## Ručna instalacija za početnike

<details>
<summary><b>Instalirate prvi put? Otvorite kratka uputstva</b></summary>

### 1. Raspakujte ZIP arhivu

Preuzmite `weig-qb-webui.zip` i raspakujte ga. Arhiva već sadrži sljedeću strukturu direktorija:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Cijeli folder `weig-qb-webui`** predstavlja osnovni direktorij web-interfejsa. Nemojte kopirati samo `public` ili `private`.

### 2. Odaberite trajnu lokaciju

Premjestite cijeli folder na mjesto gdje ga nećete slučajno obrisati, naprimjer:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Putanju do te mape zatim unesite u postavke qBittorrenta.

### 3. Uključite alternativni WebUI interfejs u qBittorrentu

Otvorite **Alati → Opcije → WebUI** u qBittorrentu. Nazivi opcija mogu se razlikovati zavisno od odabranog jezika.

1. Označite **Koristi alternativni web-interfejs** (*Use alternative WebUI*).
2. Pronađite polje **Lokacija datoteka** (*Files location*).
3. Unesite put do mape `weig-qb-webui`.

Primjer za Windows:

```text
D:\weig-qb-webui
```

Primjer za Linux:

```text
/opt/weig-qb-webui
```

4. Kliknite **OK** kako biste spremili promjene.
5. Ponovno učitajte stranicu qBittorrenta. Ako se i dalje prikazuje staro interfejs, pritisnite `Ctrl + F5` za prisilno osvježavanje.

> **Kako provjeriti putanju?** U odabranom folderu moraju se direktno nalaziti `public`, `private` i `VERSION`. Ako prvo morate otvoriti još jedan folder `weig-qb-webui`, odabrali ste pogrešan nivo direktorija.

> **Koristite Docker?** qBittorrent se pokreće **unutar kontejnera**. Zato u njegove postavke morate unijeti put koji je dostupan unutar kontejnera, a ne put koji postoji samo na računaru domaćinu. Objašnjenje slijedi u nastavku.

</details>

## Instalacija jednom naredbom

Instalacijska skripta za Linux i NAS uvijek se preuzima s niže navedene stalne adrese Dev Pages. **Adresa skripte ne određuje instalacijski kanal:** bez `-dev` instalira se posljednje provjereno stabilno izdanje s GitHub Releases; uz `-dev` instalira se razvojna verzija određena tačnim Git SHA identifikatorom. Skripta ostaje u trenutnoj mapi radi kasnijeg ažuriranja ili vraćanja prethodne instalacije.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Prikaži lokaciju skripte i podrazumijevanu instalacijsku mapu</b></summary>

Preuzeta skripta sprema se ovdje:

```text
./install.sh
```

Podrazumijevana instalacijska mapa za WebUI:

```text
~/.local/share/weig-qb-webui
```

Kada se pokreće kao korisnik `root`, to je obično:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Instalacija u Dockeru, više kontejnera i ispravni putovi</b></summary>

#### Host i kontejner

Ako koristite Docker na VPS-u, Linux serveru, Synologyju, QNAP-u ili drugom NAS uređaju:

- **Host** je Linux ili NAS sistem na kojem radi Docker. Obično mu pristupate putem SSH-a.
- **Kontejner (container)** je odvojeno okruženje u kojem radi qBittorrent. Vidi samo foldere koji su u njega mapirani.

Pretpostavimo da je konfiguracijska mapa povezana ovako:

```text
Domaćin: /root/qbittorrent/config
   ↓ povezano kao
Unutar spremnika: /config
```

U Docker Compose konfiguraciji to može izgledati ovako:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Put **lijevo od dvotočke** pripada **domaćinu**, a put **desno** označava lokaciju **unutar kontejnera**.

Ako je WeiG instaliran na domaćinu ovdje:

```text
Domaćin: /root/qbittorrent/config/weig-qb-webui
```

u polje **Files location** u qBittorrentu unesite:

```text
/config/weig-qb-webui
```

**Nemojte unositi `/root/qbittorrent/config/weig-qb-webui`**. To je put na domaćinu koji kontejner uglavnom ne može direktno vidjeti.

#### Slučaj 1: Imate samo jedan qBittorrent kontejner

Pokrenite:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Instalacijska skripta pokušat će pronaći aktivni qBittorrent kontejner, mapirani `/config` i odgovarajući folder na hostu. Ako može pouzdano prepoznati konfiguraciju, automatski će podesiti qBittorrent.

#### Slučaj 2: Ne znate naziv kontejnera

Prikažite dostupne kontejnere:

```sh
sh install.sh --list-containers
```

Ili ih provjerite direktno u Dockeru:

```sh
docker ps
```

Ako se kontejner, naprimjer, zove:

```text
qbittorrent
```

izričito ga odaberite:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Slučaj 3: Koristite više qBittorrent kontejnera

Naprimjer, jedan glavni i jedan testni:

```text
qbittorrent
qbittorrent-test
```

Najprije prikažite popis:

```sh
sh install.sh --list-containers
```

Instalacija u glavni kontejner:

```sh
sh install.sh --container=qbittorrent -configure
```

Instalacija u testni kontejner:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Ako instalacijska skripta pronađe više kontejnera, **neće nasumično odabrati nijedan**.

#### Slučaj 4: Znate lokaciju mape `/config` na domaćinu

Naprimjer:

```text
/root/qbittorrent/config
```

Možete je direktno navesti:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Na Synologyju put može izgledati ovako:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Na drugom NAS uređaju, naprimjer:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Ovo su samo primjeri. Koristite stvarni put do konfiguracije qBittorrenta na svojem domaćinu.

#### Slučaj 5: Odaberite instalacijsku mapu za WebUI

Ako ste već odabrali kontejner, možete zadati i lokaciju WebUI-ja unutar njega:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Instalacijska skripta prema Docker povezivanju `/config` pronalazi odgovarajući put na domaćinu.

#### Slučaj 6: Ažurirajte više instalacija odjednom

Ako upravljate većim brojem qBittorrent instanci, možete ponoviti parametar `-o`. Paket se preuzima i provjerava samo jednom; nijedna instalacija se ne zamjenjuje dok sve destinacije nisu pripremljene. Za svaku destinaciju odvojeno se čuvaju **tri posljednje rezervne kopije** u `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Za više destinacija nemojte koristiti `-configure`. Svaka instanca treba zadržati svoju ranije podešenu putanju do alternativnog WebUI-ja. Sve mogućnosti prikazuju se naredbom `sh install.sh -help`.

#### Provjera putova nakon instalacije

Nakon uspješne instalacije može se prikazati nešto poput ovoga:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: stvarna lokacija datoteka na domaćinu.
- `qBittorrent Root Folder`: put **unutar kontejnera** koji unosite u polje *Files location* u qBittorrentu.

Ako skriptu pokrenete uz `-configure`, ona uključuje alternativni WebUI i postavlja put ako može sigurno otkriti konfiguraciju qBittorrenta. U protivnom slijedite gornje uputstva za ručnu instalaciju.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

## Uobičajeni parametri

Osnovni parametri imaju ista imena na Linuxu i Windowsu; PowerShell ne razlikuje velika i mala slova u njihovim nazivima.

| Namjena | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Instaliraj najnoviju stabilnu verziju (`main`) | Podrazumijevano, bez parametara | Podrazumijevano, bez parametara |
| Instaliraj određenu stabilnu verziju | `-version 1.2.0` | `-version 1.2.0` |
| Instaliraj razvojnu verziju | `-dev` | `-dev` |
| Odaberi instalacijsku mapu | `-o /path` (na Linuxu se može ponoviti) | `-o D:\path` ili `-output D:\path` |
| Navedi konfiguracijsku datoteku qBittorrenta | — | `-qbconfig D:\path\qBittorrent.ini` |
| Automatski postavi qBittorrent | `-configure` | `-configure` |
| Vrati prethodnu instalaciju | `-rollback` | `-rollback` |
| Deinstaliraj i ukloni rezervne kopije | `-uninstall -purge` | `-uninstall -purge` |
| Prikaži potpunu pomoć | `-help` | `-help` |
| Odaberi Docker kontejner | `--container=NAME` | — |
| Prikaži popis kontejnera | `--list-containers` | — |
| Mapa `/config` na domaćinu | `--config-root=/path` | — |

<details>
<summary><b>Objašnjenje parametara (proširi)</b></summary>

- Bez `-dev` koristi se stabilni kanal `main`; s `-dev` razvojna verzija određena tačnim Git SHA identifikatorom.
- Slovo `o` u `-o` znači **output**. Na Linuxu se parametar može ponavljati kako biste jednim preuzimanjem ažurirali više postojećih instalacija.
- Rezervne kopije kojima upravlja instalacijska skripta nalaze se u `~/.config/weig-qb-webui/backups/`; za svako se odredište čuvaju **najviše tri najnovije rezervne kopije**.
- `-configure` uključuje *Use alternative WebUI* i postavlja *Files location*, ali samo za jedno odredište.
- `-rollback` vraća posljednju rezervnu kopiju koju je za odabrano odredište napravila instalacijska skripta. Ponavljanjem `-o` možete vratiti više izričito navedenih odredišta.
- `-uninstall -purge` uklanja rezervne kopije i stanje za povratak **samo trenutne instalacije**; ostale instalacije ostaju netaknute.
- Ako želite sačuvati kopije za kasniji `-rollback`, izostavite `-purge`.
- Parametrom `-version` instalirate određeno izdanje s GitHub Releases, naprimjer `1.2.0`. Ako ne postoji, instalacija završava pogreškom i **ne prelazi automatski** na latest ili dev.
- Za više kontejnera pokrenite `--list-containers` i odaberite `--container=NAME`; alternativno navedite mapu domaćina za `/config` preko `--config-root=/path`.

### Odabir verzije i instalacijske mape

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Povratak na prethodnu instalaciju

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Deinstalacija jednom naredbom

<details>
<summary><b>Potpuna deinstalacija na Linuxu / NAS-u, u Dockeru i Windows PowerShellu</b></summary>

Preporučujemo **ukloniti WebUI bez zadržavanja rezervnih kopija instalacijske skripte**. Naredbe u nastavku uklanjaju interfejs, isključuju alternativni WebUI odabranog odredišta, brišu rezervne kopije i stanje potrebno za povratak te na kraju uklanjaju preuzetu instalacijsku skriptu iz trenutne mape.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Ako koristite prilagođenu mapu, dodajte `-o /put/do/weig-qb-webui`.

### Docker

Jedan kontejner s automatskim otkrivanjem:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Više kontejnera:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Kada koristite `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Za prilagođenu mapu dodajte `-o D:\weig-qb-webui`.

Parametar `-purge` uklanja samo rezervne kopije instalacije koju upravo deinstalirate. Ostale instance ostaju netaknute. Ako zajednička mapa sa stanjem postane potpuno prazna, uklanja se i `~/.config/weig-qb-webui` na Linuxu (za `root`: `/root/.config/weig-qb-webui`) ili `%APPDATA%\weig-qb-webui` na Windowsima.

Ako želite zadržati rezervne kopije za kasniji `-rollback`, deinstalirajte bez `-purge`.

</details>
