## Բազմաթիվ օրինակների կողային վահանակ

qBittorrent-ի մի քանի անկախ օրինակներ կարող են օգտագործել WeiG-ի նույն պատրաստված պանակը՝ **միայն ընթերցման** ռեժիմով։ Հոսթ համակարգի պանակը տեղադրեք Docker-ի յուրաքանչյուր կոնտեյներում, օրինակ՝ `/root/weig-qb-webui:/weig-qb-webui:ro`, ապա qBittorrent-ի յուրաքանչյուր օրինակի Alternative WebUI-ի արմատը նշեք որպես `/weig-qb-webui`։ Յուրաքանչյուր օրինակ շարունակում է ունենալ իր առանձին torrent տվյալների բազան, կարգավորումները և մուտքի տվյալները։

Կողային վահանակի **Instances** բաժնում կարելի է գրանցել օրինակներ, անցնել դրանց ամբողջական էջերին և վերանվանել դրանք (աջ սեղմումով կամ տողի ընտրացանկից)։ Օրինակ՝ ընթացիկ օրինակը կարող է կոչվել `524 (current)`։ Ընթացիկ օրինակի նշումը որոշվում է իրական URL-ով, ոչ թե պահպանված անվան վերջածանցով։ Ավտոմատ ստուգման միջակայքը կարգավորվում է **Settings → WeiG WebUI → Interface** բաժնում, սկզբնական արժեքը `30 min` է, և կարելի է անջատել կամ ընտրել 5–1440 րոպե։

**Կապի առողջության ցուցիչները դիտավորյալ պահպանողական են․** նույն ծագման հաստատված WebAPI ստուգումը նշանակում է, որ qB-ն առցանց է, իսկ առանց մուտքային տվյալների միջծագումային `no-cors` պատասխանը ցույց է տալիս միայն HTTP հասցեի հասանելիությունը՝ նույնիսկ եթե վերադարձվում է 403/404։ Միջծագումային Cookie/SID ընթերցում, գաղտնաբառի կամ նիստի փոխանցում, CORS-ի շրջանցում կամ սերվերային միջնորդ չի տրամադրվում։ Նախկին qB ստուգումից հետո պահպանված ժամանակը **պատմական տվյալ** է, ոչ թե ընթացիկ առցանց լինելու ապացույց։ Դիտարկչի `127.0.0.1` հասցեն վերաբերում է դիտարկիչը գործարկող սարքին, ոչ թե հեռավոր VPS-ին։

## Տեղադրում նոր օգտվողների համար

<details>
<summary><b>Առաջին անգա՞մ եք տեղադրում։ Բացեք այս մեկ րոպեանոց ուղեցույցը</b></summary>

### 1. Ապափաթեթավորեք ZIP-ը

Ներբեռնեք `weig-qb-webui.zip` ֆայլը և ապափաթեթավորեք այն։ Արխիվն արդեն պարունակում է ստանդարտ պանակը՝

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

Ամբողջ **`weig-qb-webui` պանակը** WebUI-ի արմատն է։ Մի պատճենեք միայն `public` կամ `private` պանակը։

### 2. Տեղափոխեք մշտական վայր

Ամբողջ `weig-qb-webui` պանակը տեղադրեք այնպիսի վայրում, որտեղ հետագայում պատահմամբ չեք ջնջի այն, օրինակ՝

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Այս պանակի ուղին պետք է նշեք qBittorrent-ում։

### 3. Միացրեք այն qBittorrent-ում

Բացեք qBittorrent-ը՝

**Tools → Options... → WebUI**

Սրանք qBittorrent-ի ընթացիկ անգլերեն միջերեսի անվանումներն են։ Այնուհետև՝

1. Միացրեք **Use alternative WebUI** տարբերակը։
2. Գտեք **Files location:** դաշտը։
3. Մուտքագրեք `weig-qb-webui` պանակի ուղին։

Windows-ի օրինակ՝

```text
D:\weig-qb-webui
```

Սովորական Linux-ի օրինակ՝

```text
/opt/weig-qb-webui
```

4. Պահպանելու համար սեղմեք **OK**։
5. Թարմացրեք qBittorrent WebUI էջը։ Եթե դիտարկիչը դեռ ցույց է տալիս քեշավորված հին էջը, մեկ անգամ փորձեք `Ctrl + F5`։

> **Ինչպե՞ս ստուգել ուղու ճշտությունը։** Նշված պանակը պետք է անմիջապես պարունակի `public`, `private`, `VERSION` և WebUI-ի մյուս ֆայլերը։ Եթե դրանց հասնելու համար անհրաժեշտ է մտնել ևս մեկ `weig-qb-webui` պանակ, ուղին մեկ մակարդակով սխալ է նշված։

> **Docker-ի օգտվողներին․** qBittorrent-ը աշխատում է կոնտեյների ներսում, ուստի հոսթի ուղին սովորաբար հնարավոր չէ անմիջապես օգտագործել։ Տե՛ս ստորև բերված **Docker** ուղեցույցը՝ հոսթի և կոնտեյների ուղիների տարբերությունը հասկանալու համար։

## Տեղադրում մեկ հրամանով

Linux/NAS-ի մեկ հրամանով տեղադրիչը միշտ ներբեռնվում է ստորև նշված Dev Pages հաստատուն URL-ից։ **Սկրիպտի URL-ը չի ընտրում տեղադրման ալիքը․** առանց `-dev`-ի այն տեղադրում է վերջին ստուգված կայուն GitHub Release-ը։ `-dev` ավելացրեք միայն այն դեպքում, երբ դիտավորյալ ցանկանում եք տեղադրել ընթացիկ զարգացման տարբերակը՝ ճշգրիտ Git SHA-ով։ Ներբեռնված սկրիպտը մնում է ընթացիկ պանակում՝ հետագա թարմացման կամ հետադարձ վերականգնման համար։

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<summary><b>Ցույց տալ սկրիպտի տեղը և WebUI-ի լռելյայն տեղադրման պանակը</b></summary>

```text
./install.sh
```

```text
~/.local/share/weig-qb-webui
```

Օրինակ, `root`-ով գործարկելիս սովորաբար այստեղ՝

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker-ի տեղադրում մեկ հրամանով / բազմաթիվ կոնտեյներներ / ուղիների ուղեցույց (խորհուրդ է տրվում սկսնակներին)</b></summary>

#### Նախ հասկացեք «հոսթ» և «կոնտեյներ» հասկացությունները

Եթե qBittorrent-ը աշխատում է Docker-ում՝ VPS-ի, Linux սերվերի, Synology-ի, QNAP-ի կամ այլ NAS-ի վրա՝

- **Հոսթ**․ իրական Linux/NAS համակարգիչը, որի վրա աշխատում է Docker-ը, այսինքն՝ SSH-ով մուտք գործելիս տեսանելի համակարգը։
- **Կոնտեյներ**․ Docker-ի ստեղծած մեկուսացված միջավայրը qBittorrent-ի համար։ qBittorrent-ը անմիջապես տեսնում է կոնտեյների ուղիները, բայց ոչ հոսթի ցանկացած ուղի։

Օրինակ՝ qBittorrent-ի կոնտեյները կարող է ունենալ այս համապատասխանությունը՝

```text
Host:      /root/qbittorrent/config
   ↓ mapped to
Container: /config
```

Docker Compose-ի սովորական կարգավորումն այս տեսքն ունի՝

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Երկկետի ձախ կողմի `/root/qbittorrent/config`-ը **հոսթի ուղին** է, իսկ աջ կողմի `/config`-ը՝ **կոնտեյների ուղին**։

Եթե WeiG qB WebUI-ը ֆիզիկապես տեղադրված է այստեղ՝

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

ապա qBittorrent-ի **Files location:** դաշտում պետք է նշվի՝

```text
/config/weig-qb-webui
```

**qBittorrent-ում մի նշեք `/root/qbittorrent/config/weig-qb-webui`**, քանի որ կոնտեյները սովորաբար չի կարող անմիջապես տեսնել հոսթի այդ ուղին։

#### Դեպք 1․ աշխատում է qBittorrent-ի միայն մեկ կոնտեյներ

Օգտագործեք սովորական մեկ հրամանով տեղադրումը՝

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Տեղադրիչը կփորձի հայտնաբերել աշխատող qBittorrent կոնտեյները, նրա `/config` կապակցումը, WebUI-ը տեղադրել հոսթի համապատասխան վայրում և ավտոմատ կարգավորել qBittorrent-ը։

#### Դեպք 2․ նախ գտեք qBittorrent կոնտեյների անունը

Եթե վստահ չեք կոնտեյների անվան հարցում՝

```sh
sh install.sh --list-containers
```

Կարող եք նաև անմիջապես օգտագործել Docker-ը՝

```sh
docker ps
```

Եթե qBittorrent կոնտեյների անունն է՝

```text
qbittorrent
```

հստակ ընտրեք այն՝

```sh
sh install.sh --container=qbittorrent -configure
```

#### Դեպք 3․ qBittorrent-ի բազմաթիվ կոնտեյներներ

Օրինակ՝

```text
qbittorrent
qbittorrent-test
```

Նախ ցուցակագրեք դրանք՝

```sh
sh install.sh --list-containers
```

Տեղադրեք հիմնական `qbittorrent` կոնտեյների համար՝

```sh
sh install.sh --container=qbittorrent -configure
```

Տեղադրեք փորձնական կոնտեյների համար՝

```sh
sh install.sh --container=qbittorrent-test -configure
```

Եթե առկա են բազմաթիվ qBittorrent կոնտեյներներ, տեղադրիչը ինքնուրույն պատահական մեկը չի ընտրի։

#### Դեպք 4․ արդեն գիտեք հոսթի այն պանակը, որը միացված է որպես `/config`

Օրինակ՝

```text
/root/qbittorrent/config
```

Նշեք այն ուղղակիորեն՝

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Synology-ի ուղին կարող է լինել՝

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Այլ NAS-ում, օրինակ՝

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Սրանք միայն օրինակներ են։ **Փոխարինեք դրանք հոսթի իրական ուղով, որը qBittorrent-ում միացված է որպես `/config`։**

#### Դեպք 5․ ընտրեք WebUI-ի տեղադրման ուղին

Կոնտեյներն ընտրելուց հետո կարող եք նաև նշել կոնտեյների ներսից տեսանելի WebUI-ի ուղին՝

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Տեղադրիչը կոնտեյների `/config/...` ուղին փոխակերպում է հոսթի համապատասխան տեղադրման ուղու։

#### Դեպք 6․ մեկ ներբեռնումով թարմացրեք մի քանի WebUI պանակներ

qBittorrent-ի բազմաթիվ օրինակների համար կրկնեք `-o` տարբերակը։ Փաթեթը ներբեռնվում և ստուգվում է միայն մեկ անգամ, բոլոր թիրախները պատրաստվում են մինչև փոխարինումը, և յուրաքանչյուր թիրախ պահպանում է վերջին երեք սեփական կրկնօրինակները `~/.config/weig-qb-webui/backups/` պանակում։

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Մի ավելացրեք `-configure`-ը մի քանի թիրախի ռեժիմում. յուրաքանչյուր qBittorrent օրինակ պահպանում է իր նախորդ Alternative WebUI արմատային պանակը։ Ընթացիկ հրամանների ձևաչափը տեսնելու համար գործարկեք `sh install.sh -help`։

#### Ի՞նչ պետք է երևա տեղադրումից հետո

Հաջող տեղադրումը ցույց է տալիս մոտավորապես այսպիսի տվյալներ՝

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

Նշանակությունը՝

- `Host install path`․ ֆայլերի իրական տեղը հոսթի վրա։
- `qBittorrent Root Folder`․ **այն ուղին կոնտեյների ներսում, որը qBittorrent-ը պետք է օգտագործի Files location դաշտում**։

Եթե `-configure`-ը գտնում է qBittorrent-ի կարգավորումը, տեղադրիչն ավտոմատ միացնում է **Use alternative WebUI** և սահմանում ուղին։ Հակառակ դեպքում հետևեք վերևի **Տեղադրում նոր օգտվողների համար → Միացրեք այն qBittorrent-ում** ձեռքով քայլերին։

</details>

## Հիմնական ընտրանքներ
Linux-ը և Windows-ը հնարավորության դեպքում օգտագործում են նույն հրապարակային տարբերակների անունները։ Փաստաթղթում նշված են փոքրատառերը, իսկ PowerShell-ի պարամետրերի անուններում մեծատառերը չեն տարբերակվում։

| Նպատակ | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Կայուն main | Լռելյայն, առանց ընտրանքի | Լռելյայն, առանց ընտրանքի |
| Կոնկրետ թողարկում | `-version 1.2.0` | `-version 1.2.0` |
| Զարգացման տարբերակ | `-dev` | `-dev` |
| Տեղադրման անհատական պանակ | `-o /path` (Linux-ում կարելի է կրկնել) | `-o D:\path` կամ `-output D:\path` |
| qBittorrent-ի անհատական կարգավորումների ֆայլ | — | `-qbconfig D:\path\qBittorrent.ini` |
| qBittorrent-ի ավտոմատ կարգավորում | `-configure` | `-configure` |
| Վերադառնալ նախորդ տեղադրմանը | `-rollback` | `-rollback` |
| Ամբողջական հեռացում (առանց կրկնօրինակների պահպանման) | `-uninstall -purge` | `-uninstall -purge` |
| Ամբողջական օգնություն | `-help` | `-help` |
| Ընտրել Docker կոնտեյները | `--container=NAME` | — |
| Ցուցակել Docker կոնտեյներները | `--list-containers` | — |
| Նշել Docker-ի `/config`-ին միացված հոսթի պանակը | `--config-root=/path` | — |

<details>
<summary><b>Նշումներ (սեղմեք բացելու համար)</b></summary>

Նշումներ՝

- Առանց `-dev`-ի ընտրվում է կայուն `main` տարբերակը, իսկ `-dev`-ով՝ զարգացման ընթացիկ տարբերակի ճշգրիտ Git SHA-ն։
- `-o`-ն նշանակում է **output** և սահմանում է WeiG qB WebUI-ի տեղադրման պանակը։ Linux-ում այն կարելի է կրկնել՝ մեկ ստուգված ներբեռնումով մի քանի թիրախ թարմացնելու համար։
- Տեղադրիչի կրկնօրինակները պահվում են `~/.config/weig-qb-webui/backups/` պանակում, և **յուրաքանչյուր թիրախի համար առանձին պահվում են վերջին 3 կրկնօրինակները**։
- `-configure`-ը qBittorrent-ում միացնում է **Use alternative WebUI**-ը և տեղադրումից հետո սահմանում **Files location**-ը։ Այն նախատեսված է միայն մեկ թիրախի համար։
- `-rollback`-ը վերականգնում է ընտրված թիրախի տեղադրիչի վերջին կրկնօրինակը։ Մի քանի բացահայտ թիրախ վերադարձնելու համար կրկնեք `-o`-ն։
- `-version`-ը տեղադրում է GitHub Release-ի ճշգրիտ տարբերակը, օրինակ՝ `1.2.0`։ Եթե պահանջվող տարբերակը չկա, տեղադրումը ձախողվում է և **երբեք ինքնուրույն չի անցնում latest-ի կամ dev-ի**։
- `-help`-ը ցույց է տալիս Linux-ի ընթացիկ աջակցվող հրամանների ձևաչափը։
- Docker-ում qBittorrent-ի մի քանի կոնտեյներների դեպքում օգտագործեք `--list-containers`, ապա ընտրեք մեկը `--container=NAME`-ով։ Եթե գիտեք հոսթի կարգավորումների պանակը, կարող եք նաև օգտագործել `--config-root=/path`։

## Հեռացում մեկ հրամանով

<details>
<summary><b>Ամբողջական հեռացում Linux / NAS, Docker և Windows PowerShell համակարգերում</b></summary>

Ստորև առաջարկվող հրամանը կատարում է ամբողջական հեռացում՝ **չպահպանելով տեղադրիչի կրկնօրինակները**․ հեռացնում է WebUI-ը, անջատում համապատասխան Alternative WebUI կարգավորումը, մաքրում տվյալ թիրախի տեղադրիչին պատկանող կրկնօրինակներն ու հետադարձ վերականգնման վիճակը, ապա ընթացիկ պանակից ջնջում ներբեռնված տեղադրման սկրիպտը։

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Տեղադրման այլ պանակի համար ավելացրեք `-o /path/to/weig-qb-webui`։

### Docker

Մեկ կոնտեյներ / ավտոմատ հայտնաբերում՝

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Բազմաթիվ կոնտեյներներ՝

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

`--config-root`-ի օգտագործման դեպքում՝

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Տեղադրման այլ պանակի համար ավելացրեք `-o D:\weig-qb-webui`։

`-purge`-ը հեռացնում է միայն տվյալ թիրախին պատկանող կրկնօրինակները և չի փոխում այլ տեղադրումների կրկնօրինակները։ Երբ ընդհանուր վիճակի պանակը դատարկվում է, հեռացվում է նաև Linux-ի `~/.config/weig-qb-webui` (root-ի համար՝ `/root/.config/weig-qb-webui`) կամ Windows-ի `%APPDATA%\weig-qb-webui` պանակը։

Եթե ցանկանում եք պահպանել կրկնօրինակները հետագա `-rollback`-ի համար, պարզապես բաց թողեք `-purge`-ը։

</details>
