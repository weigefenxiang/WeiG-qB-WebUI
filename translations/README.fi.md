## Käsin asentaminen aloittelijalle

<details>
<summary><b>Asennatko ensimmäistä kertaa? Avaa minuutin pikaohje</b></summary>

### 1. Pura ZIP-paketti

Lataa `weig-qb-webui.zip` ja pura se. Paketissa on valmiina seuraava hakemistorakenne:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Koko `weig-qb-webui`-kansio** on WebUI:n juurihakemisto. Älä kopioi pelkästään `public`- tai `private`-kansiota.

### 2. Valitse pysyvä sijainti

Siirrä koko kansio paikkaan, josta sitä ei poisteta vahingossa. Esimerkiksi:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Tämä kansio valitaan myöhemmin qBittorrentin asetuksissa.

### 3. Ota vaihtoehtoinen WebUI käyttöön qBittorrentissa

Avaa qBittorrentin **Työkalut → Asetukset → Verkkokäyttöliittymä**. Valikoiden nimet voivat vaihdella qBittorrentin kieliasetuksen mukaan.

1. Ota käyttöön **Käytä vaihtoehtoista verkkokäyttöliittymää** (*Use alternative WebUI*).
2. Etsi kenttä **Tiedostojen sijainti** (*Files location*).
3. Anna `weig-qb-webui`-kansion polku.

Windows-esimerkki:

```text
D:\weig-qb-webui
```

Linux-esimerkki:

```text
/opt/weig-qb-webui
```

4. Tallenna valitsemalla **OK**.
5. Päivitä qBittorrentin verkkosivu. Jos vanha käyttöliittymä näkyy edelleen, paina `Ctrl + F5` ja pakota selaimen päivitys.

> **Mistä tiedät, että polku on oikein?** Valitusta kansiosta pitää löytyä suoraan `public`, `private` ja `VERSION`. Jos joudut ensin avaamaan vielä toisen `weig-qb-webui`-kansion, olet valinnut väärän hakemistotason.

> **Docker-käyttäjille:** qBittorrent toimii kontin sisällä. Anna polku, joka näkyy **kontissa**, ei polkua, joka on olemassa vain isäntäkoneella. Katso Docker-ohje alempaa.

</details>

## Asenna yhdellä komennolla

Linuxin ja NAS-laitteiden asennusohjelma ladataan alla olevasta pysyvästä Dev Pages -osoitteesta. **Latausosoite ei määritä asennettavaa julkaisukanavaa:** ilman `-dev`-valintaa asennetaan viimeisin tarkistettu vakaa GitHub Release, kun taas `-dev` asentaa tarkalla Git SHA:lla yksilöidyn kehitysversion. Skripti säilytetään nykyisessä hakemistossa myöhempiä päivityksiä ja palautuksia varten.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Näytä skriptin sijainti ja oletusasennushakemisto</b></summary>

Ladattu skripti on:

```text
./install.sh
```

WebUI:n oletusasennushakemisto on:

```text
~/.local/share/weig-qb-webui
```

Jos suoritat komennon `root`-käyttäjänä, se on tavallisesti:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker-asennus, useat kontit ja hakemistopolut</b></summary>

#### Isäntäkone ja kontti: mitä eroa niillä on?

Jos käytät Dockeria VPS-palvelimella, Linux-palvelimella tai Synology-, QNAP- tai muulla NAS-laitteella:

- **Isäntäkone (host)** on Linux- tai NAS-järjestelmä, jossa Docker suoritetaan. Yhdistät siihen yleensä SSH:lla.
- **Kontti (container)** on eristetty ympäristö, jossa qBittorrent toimii. Se näkee vain sille liitetyt hakemistot.

Oletetaan, että qBittorrentin asetuskansio on liitetty näin:

```text
Isäntäkone: /root/qbittorrent/config
   ↓ liitetään
Kontissa: /config
```

Docker Composessa määritys näyttää tavallisesti tältä:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Kaksoispisteen **vasemmalla puolella** on isäntäkoneen kansio ja **oikealla puolella** kontin sisäinen polku.

Jos WeiG on asennettu isäntäkoneelle tähän:

```text
Isäntäkone: /root/qbittorrent/config/weig-qb-webui
```

qBittorrentin **Files location** -kenttään pitää kirjoittaa:

```text
/config/weig-qb-webui
```

**Älä käytä polkua `/root/qbittorrent/config/weig-qb-webui`** qBittorrentin asetuksissa. Se on isäntäkoneen polku, jota kontti ei yleensä näe suoraan.

#### Tilanne 1: Vain yksi qBittorrent-kontti

Suorita:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Asennusohjelma yrittää löytää käynnissä olevan qBittorrent-kontin, sen `/config`-liitoksen ja vastaavan asennuskansion isäntäkoneelta. Jos asetukset tunnistetaan luotettavasti, qBittorrent voidaan myös määrittää automaattisesti.

#### Tilanne 2: Kontin nimi ei ole tiedossa

Listaa käytettävissä olevat kontit:

```sh
sh install.sh --list-containers
```

Tai tarkista käynnissä olevat kontit Dockerilla:

```sh
docker ps
```

Jos kontin nimi on esimerkiksi:

```text
qbittorrent
```

valitse se nimenomaisesti:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Tilanne 3: Useita qBittorrent-kontteja

Voit esimerkiksi käyttää erillistä pääinstanssia ja testikonttia:

```text
qbittorrent
qbittorrent-test
```

Tarkista ensin luettelo:

```sh
sh install.sh --list-containers
```

Asenna pääinstanssiin:

```sh
sh install.sh --container=qbittorrent -configure
```

Asenna testikonttiin:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Asennusohjelma **ei valitse konttia sattumanvaraisesti**, jos sopivia kontteja on useita.

#### Tilanne 4: Tiedät isäntäkoneen `/config`-kansion

Esimerkiksi:

```text
/root/qbittorrent/config
```

Voit antaa hakemiston suoraan:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Synology-NASissa polku voi olla:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Toisessa NAS-laitteessa esimerkiksi:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Nämä ovat esimerkkejä. Korvaa ne oman isäntäkoneesi qBittorrent-asetuskansion todellisella polulla.

#### Tilanne 5: Valitse WebUI:n asennushakemisto

Kun kontti on valittu, voit määrittää myös WebUI:n halutun sijainnin kontin sisällä:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Asennusohjelma selvittää vastaavan isäntäkoneen hakemiston Dockerin `/config`-liitoksen perusteella.

#### Tilanne 6: Päivitä useita asennuksia kerralla

Jos hallinnoit useita qBittorrent-instansseja, voit antaa `-o`-valinnan useita kertoja. Paketti ladataan ja tarkistetaan vain kerran, eikä yhtään asennusta korvata ennen kaikkien kohteiden valmistelua. Jokaiselle kohteelle säilytetään erikseen **kolme viimeisintä varmuuskopiota** hakemistossa `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Älä käytä `-configure`-valintaa usean kohteen tilassa. Jokainen instanssi säilyttää aiemmin määritetyn vaihtoehtoisen WebUI:n polkunsa. Kaikki valinnat näet komennolla `sh install.sh -help`.

#### Tarkista polut asennuksen jälkeen

Onnistuneen asennuksen tuloste voi näyttää tältä:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: tiedostojen todellinen sijainti isäntäkoneella.
- `qBittorrent Root Folder`: **kontin sisäinen polku**, joka pitää antaa qBittorrentin *Files location* -kenttään.

Kun `-configure` on käytössä ja qBittorrentin asetukset voidaan tunnistaa turvallisesti, asennusohjelma ottaa vaihtoehtoisen WebUI:n käyttöön ja asettaa oikean polun. Muussa tapauksessa noudata yllä olevia käsin tehtävän asennuksen ohjeita.

</details>

### Windows PowerShell

Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure

## Yleiset komentovalinnat

Linuxissa ja Windowsissa yleisten valintojen nimet ovat samat. PowerShell ei erottele isoja ja pieniä kirjaimia parametrien nimissä.

| Tarkoitus | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Asenna uusin vakaa versio (`main`) | Oletus, ei valintoja | Oletus, ei valintoja |
| Asenna tietty vakaa versio | `-version 1.2.0` | `-version 1.2.0` |
| Asenna kehitysversio | `-dev` | `-dev` |
| Valitse asennushakemisto | `-o /path` (toistettavissa Linuxissa) | `-o D:\path` tai `-output D:\path` |
| Määritä qBittorrentin asetustiedosto | — | `-qbconfig D:\path\qBittorrent.ini` |
| Määritä qBittorrent automaattisesti | `-configure` | `-configure` |
| Palauta edellinen asennus | `-rollback` | `-rollback` |
| Poista ohjelma ja varmuuskopiot | `-uninstall -purge` | `-uninstall -purge` |
| Näytä kaikki ohjeet | `-help` | `-help` |
| Valitse Docker-kontti | `--container=NAME` | — |
| Listaa Docker-kontit | `--list-containers` | — |
| Määritä isäntäkoneen `/config`-polku | `--config-root=/path` | — |

<details>
<summary><b>Valintojen tarkemmat selitykset (avaa)</b></summary>

- Ilman `-dev`-valintaa käytetään vakaata `main`-julkaisukanavaa; `-dev` valitsee tarkan Git SHA:n mukaisen kehitysversion.
- `-o` viittaa sanaan **output**. Linuxissa sen voi toistaa usean olemassa olevan asennuksen päivittämiseksi yhdellä latauksella.
- Asennusohjelman varmuuskopiot tallennetaan aina hakemistoon `~/.config/weig-qb-webui/backups/`. **Enintään kolme uusinta kopiota kohdetta kohti** säilytetään.
- `-configure` ottaa *Use alternative WebUI* -asetuksen käyttöön ja määrittää *Files location* -polun, mutta sitä voi käyttää vain yhdelle kohteelle.
- `-rollback` palauttaa asennusohjelman valitulle kohteelle luoman uusimman varmuuskopion. Toista `-o`, jos haluat palauttaa useita nimettyjä kohteita.
- `-uninstall -purge` poistaa **vain valitun asennuksen** varmuuskopiot ja palautustiedot, ei muiden instanssien tietoja.
- Jos haluat säilyttää kopiot myöhempää `-rollback`-toimintoa varten, jätä `-purge` pois.
- `-version` asentaa tietyn GitHub Releasen, esimerkiksi `1.2.0`. Jos versiota ei ole, asennus päättyy virheeseen eikä **vaihda automaattisesti** latest- tai dev-versioon.
- Jos Docker-kontteja on useita, voit listata ne `--list-containers`-valinnalla ja valita tietyn kontin `--container=NAME`-valinnalla tai antaa isäntäkoneen `/config`-hakemiston `--config-root=/path`-valinnalla.

### Tietty versio ja asennuskansio

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Palauttaminen

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Poista asennus yhdellä komennolla

<details>
<summary><b>Poista WebUI ja asennusohjelman varmuuskopiot Linuxissa, NASissa, Dockerissa tai Windows PowerShellissä</b></summary>

Suosittelemme yleensä **poistamaan WebUI:n säilyttämättä asennusohjelman varmuuskopioita**. Komennot poistavat käyttöliittymän, kytkevät kyseisen kohteen vaihtoehtoisen WebUI:n pois käytöstä, poistavat juuri sen asennuksen varmuuskopiot ja palautustiedot sekä poistavat ladatun asennusskriptin nykyisestä kansiosta.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Lisää `-o /polku/weig-qb-webui`, jos asennus sijaitsee muualla.

### Docker

Yksi automaattisesti tunnistettava kontti:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Useita kontteja:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Jos käytät `--config-root`-valintaa:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Lisää `-o D:\weig-qb-webui`, jos käytät muuta asennuskansiota.

`-purge` poistaa vain poistettavan asennuksen varmuuskopiot. Muiden instanssien tiedot säilyvät. Jos yhteinen tilahakemisto tyhjenee kokonaan, myös `~/.config/weig-qb-webui` (käyttäjällä `root`: `/root/.config/weig-qb-webui`) Linuxissa tai `%APPDATA%\weig-qb-webui` Windowsissa poistetaan.

Jos haluat pitää varmuuskopiot myöhempää `-rollback`-palautusta varten, poista asennus ilman `-purge`-valintaa.

</details>
