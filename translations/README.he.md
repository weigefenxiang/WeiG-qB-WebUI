## התקנה ידנית למתחילים

<details>
<summary><b>מתקינים בפעם הראשונה? פתחו את המדריך המהיר</b></summary>

### 1. חלצו את קובץ ה־ZIP

הורידו את `weig-qb-webui.zip` וחלצו אותו. הארכיון כבר מכיל תיקייה במבנה הבא:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**כל התיקייה `weig-qb-webui`** היא תיקיית השורש של ממשק האינטרנט. אל תעתיקו רק את `public` או `private`.

### 2. בחרו מיקום קבוע

העבירו את התיקייה כולה למיקום שבו לא תימחק בטעות, לדוגמה:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

זו התיקייה שתצטרכו לבחור בהמשך בהגדרות qBittorrent.

### 3. הפעילו את ממשק האינטרנט החלופי ב־qBittorrent

פתחו את qBittorrent ועברו אל **כלים ← אפשרויות ← ממשק אינטרנט**. שמות הפריטים עשויים להשתנות בהתאם לשפה שמוגדרת ב־qBittorrent.

1. סמנו **שימוש בממשק אינטרנט חלופי** (*Use alternative WebUI*).
2. אתרו את השדה **מיקום הקבצים** (*Files location*).
3. הזינו את הנתיב לתיקיית `weig-qb-webui`.

דוגמה ל־Windows:

```text
D:\weig-qb-webui
```

דוגמה ל־Linux:

```text
/opt/weig-qb-webui
```

4. לחצו על **אישור** לשמירה.
5. טענו מחדש את דף האינטרנט של qBittorrent. אם עדיין מופיע הממשק הישן, הקישו `Ctrl + F5` כדי לרענן ללא המטמון הישן.

> **איך יודעים שהנתיב נכון?** יש לראות ישירות בתיקייה שנבחרה את `public`, `private` ואת `VERSION`. אם צריך להיכנס קודם לתיקיית `weig-qb-webui` נוספת, נבחרה רמה לא נכונה בעץ התיקיות.

> **משתמשים ב־Docker?** qBittorrent פועל **בתוך קונטיינר**. יש להזין נתיב שהקונטיינר מסוגל לראות, לא נתיב שקיים רק במחשב המארח. קראו את ההסבר על Docker בהמשך.

</details>

## התקנה בפקודה אחת

סקריפט ההתקנה ל־Linux ול־NAS יורד תמיד מהכתובת הקבועה של Dev Pages שמופיעה להלן. **כתובת הורדת הסקריפט אינה קובעת איזה ערוץ יותקן:** בלי `-dev` מותקנת גרסת GitHub Release היציבה והמאומתת האחרונה; עם `-dev` מותקנת גרסת הפיתוח המזוהה באמצעות Git SHA מדויק. הסקריפט נשמר בתיקייה הנוכחית, לשימוש חוזר בעדכון או בשחזור.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<summary><b>הצגת מיקום הסקריפט ותיקיית ברירת המחדל להתקנה</b></summary>

~/.local/share/weig-qb-webui

אם מריצים בתור `root`, המיקום בדרך כלל יהיה:

/root/.local/share/weig-qb-webui

### Docker

<details>
<summary><b>התקנה ב־Docker, כמה קונטיינרים והגדרת נתיבים</b></summary>

#### מה ההבדל בין המחשב המארח לקונטיינר?

אם Docker פועל בשרת VPS, ב־Linux, ב־Synology, ב־QNAP או במכשיר NAS אחר:

- **מחשב מארח (host):** מערכת Linux או NAS שמפעילה את Docker בפועל, בדרך כלל זו שמתחברים אליה באמצעות SSH.
- **קונטיינר (container):** הסביבה המבודדת שבה פועל qBittorrent. הוא יכול לגשת רק לתיקיות שהוצגו לקונטיינר.

למשל, תיקיית התצורה יכולה להיות ממופה כך:

```text
מארח: /root/qbittorrent/config
   ↓ ממופה אל
בתוך הקונטיינר: /config
```

ב־Docker Compose זה נראה בדרך כלל כך:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

הנתיב **משמאל לנקודתיים** שייך **למארח**; הנתיב **מימין** הוא הנתיב שנראה **בתוך הקונטיינר**.

אם WeiG מותקן במארח כאן:

```text
מארח: /root/qbittorrent/config/weig-qb-webui
```

יש להזין בשדה **Files location** ב־qBittorrent:

```text
/config/weig-qb-webui
```

**אל תזינו את `/root/qbittorrent/config/weig-qb-webui`** בשדה הזה: זהו נתיב במחשב המארח, שלרוב אינו נגיש ישירות מתוך הקונטיינר.

#### מקרה 1: יש קונטיינר qBittorrent אחד בלבד

הריצו:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

תוכנית ההתקנה מנסה למצוא את קונטיינר qBittorrent הפעיל, את מיפוי `/config` ואת התיקייה המתאימה במארח. אם אפשר לזהות את ההגדרות באופן בטוח, היא גם תגדיר את qBittorrent אוטומטית.

#### מקרה 2: לא יודעים את שם הקונטיינר

הציגו את רשימת הקונטיינרים:

```sh
sh install.sh --list-containers
```

או בדקו ישירות בעזרת Docker:

```sh
docker ps
```

אם למשל שם הקונטיינר הוא:

```text
qbittorrent
```

בחרו אותו במפורש:

```sh
sh install.sh --container=qbittorrent -configure
```

#### מקרה 3: יש כמה קונטיינרים של qBittorrent

למשל, קונטיינר רגיל לצד קונטיינר לבדיקות:

```text
qbittorrent
qbittorrent-test
```

תחילה הציגו את הרשימה:

```sh
sh install.sh --list-containers
```

התקנה בקונטיינר הראשי:

```sh
sh install.sh --container=qbittorrent -configure
```

התקנה בקונטיינר הבדיקות:

```sh
sh install.sh --container=qbittorrent-test -configure
```

תוכנית ההתקנה **לא תבחר קונטיינר אקראי** אם נמצאו כמה קונטיינרים מתאימים.

#### מקרה 4: תיקיית `/config` במארח ידועה לכם

לדוגמה:

```text
/root/qbittorrent/config
```

אפשר לציין את התיקייה ישירות:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

ב־Synology הנתיב עשוי להיות:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

במכשיר NAS אחר, למשל:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

אלו דוגמאות בלבד. החליפו אותן בנתיב האמיתי של תיקיית ההגדרות של qBittorrent במארח שלכם.

#### מקרה 5: בחירת תיקיית התקנת WebUI

לאחר בחירת הקונטיינר אפשר לציין גם את המיקום הרצוי בתוך הקונטיינר:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

תוכנית ההתקנה תמיר את הנתיב למיקומו המתאים במארח על פי מיפוי `/config` של Docker.

#### מקרה 6: עדכון כמה התקנות בפעולה אחת

אם אתם מנהלים כמה מופעים של qBittorrent, אפשר לחזור על האפשרות `-o`. החבילה יורדת ונבדקת פעם אחת בלבד; ההחלפה לא מתחילה לפני הכנת כל היעדים. לכל יעד נשמרים בנפרד **שלושת הגיבויים האחרונים** ב־`~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

במצב של כמה יעדים אין להוסיף `-configure`. כל מופע ממשיך להשתמש בנתיב של ממשק האינטרנט החלופי שכבר הוגדר עבורו. כדי לראות את כל האפשרויות, הריצו `sh install.sh -help`.

#### בדיקת הנתיבים לאחר ההתקנה

לאחר התקנה מוצלחת ייתכן שתופיע תוצאה כזו:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: המיקום האמיתי של הקבצים במחשב המארח.
- `qBittorrent Root Folder`: הנתיב **בתוך הקונטיינר** שיש להזין ב־*Files location* של qBittorrent.

בשימוש ב־`-configure`, אם התוכנית מאתרת בוודאות את הגדרות qBittorrent, היא מפעילה את ממשק האינטרנט החלופי ומעדכנת את הנתיב. אם לא, בצעו את שלבי ההתקנה הידנית שלמעלה.

</details>

## פרמטרים נפוצים

ל־Linux ול־Windows אותם שמות של פרמטרים נפוצים. PowerShell אינו מבחין בין אותיות גדולות וקטנות בשמות הפרמטרים.

| פעולה | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| התקנת הגרסה היציבה האחרונה (`main`) | ברירת מחדל, ללא פרמטר | ברירת מחדל, ללא פרמטר |
| התקנת גרסה יציבה מסוימת | `-version 1.2.0` | `-version 1.2.0` |
| התקנת גרסת פיתוח | `-dev` | `-dev` |
| הגדרת תיקיית התקנה | `-o /path` (ניתן לחזור ב־Linux) | `-o D:\path` או `-output D:\path` |
| ציון קובץ התצורה של qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| הגדרת qBittorrent אוטומטית | `-configure` | `-configure` |
| שחזור התקנה קודמת | `-rollback` | `-rollback` |
| הסרה מלאה כולל הגיבויים | `-uninstall -purge` | `-uninstall -purge` |
| הצגת כל האפשרויות | `-help` | `-help` |
| בחירת קונטיינר Docker | `--container=NAME` | — |
| הצגת קונטיינרים של Docker | `--list-containers` | — |
| ציון נתיב `/config` במארח | `--config-root=/path` | — |

<details>
<summary><b>פירוט הפרמטרים (לחצו לפתיחה)</b></summary>

- בלי `-dev` נעשה שימוש בערוץ היציב `main`; עם `-dev` מותקנת גרסת הפיתוח המזוהה באמצעות Git SHA מדויק.
- האות `o` ב־`-o` היא קיצור של **output**. ב־Linux אפשר לחזור על האפשרות כדי לעדכן כמה התקנות בהורדה אחת.
- הגיבויים שתוכנית ההתקנה מנהלת נשמרים תמיד ב־`~/.config/weig-qb-webui/backups/`, עד **שלושה גיבויים אחרונים לכל יעד**.
- `-configure` מפעיל *Use alternative WebUI* ומגדיר *Files location*, אך מותר להשתמש בו עבור יעד יחיד בלבד.
- `-rollback` משחזר את הגיבוי האחרון שיצרה תוכנית ההתקנה עבור היעד הנבחר. אפשר לחזור על `-o` כדי לשחזר כמה יעדים שצוינו במפורש.
- `-uninstall -purge` מוחק את הגיבויים ואת מצב השחזור **של היעד שנבחר בלבד**, בלי לשנות התקנות אחרות.
- כדי לשמור גיבויים לשימוש עתידי ב־`-rollback`, השמיטו את `-purge`.
- `-version` מתקין GitHub Release מסוים, למשל `1.2.0`. אם הגרסה אינה קיימת, ההתקנה נכשלת **ואינה עוברת אוטומטית** אל latest או dev.
- אם יש כמה קונטיינרים, השתמשו ב־`--list-containers` להצגת הרשימה ואז ב־`--container=NAME` כדי לבחור קונטיינר מסוים, או ב־`--config-root=/path` כדי לציין את תיקיית `/config` במארח.

### גרסה מסוימת ותיקיית התקנה

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### שחזור התקנה

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

## הסרה בפקודה אחת

<details>
<summary><b>הסרה מלאה ב־Linux, ב־NAS, ב־Docker וב־Windows PowerShell</b></summary>

בדרך כלל מומלץ **להסיר את WebUI בלי לשמור את הגיבויים של תוכנית ההתקנה**. הפקודות שלהלן מסירות את הממשק, משביתות את הממשק החלופי של היעד המתאים, מוחקות את הגיבויים ואת נתוני השחזור ששייכים לו ומסירות את סקריפט ההתקנה שהורד מהתיקייה הנוכחית.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

לתיקיית התקנה מותאמת הוסיפו `-o /path/to/weig-qb-webui`.

### Docker

קונטיינר אחד עם זיהוי אוטומטי:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

כמה קונטיינרים:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

אם אתם משתמשים ב־`--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

לתיקייה מותאמת הוסיפו `-o D:\weig-qb-webui`.

`-purge` מוחק רק את הגיבויים ששייכים להתקנה המוסרת. הגיבויים של מופעים אחרים נשארים ללא שינוי. אם תיקיית המצב המשותפת מתרוקנת, תימחק גם `~/.config/weig-qb-webui` ב־Linux (עבור `root`: `/root/.config/weig-qb-webui`) או `%APPDATA%\weig-qb-webui` ב־Windows.

כדי לשמור גיבויים לשחזור עתידי בעזרת `-rollback`, בצעו את ההסרה בלי `-purge`.

</details>
