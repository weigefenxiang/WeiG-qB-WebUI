## Ручне встановлення для початківців

<details>
<summary><b>Установлюєте вперше? Відкрийте коротку інструкцію</b></summary>

### 1. Розпакуйте ZIP

Завантажте `weig-qb-webui.zip` і розпакуйте архів. Він уже містить папку такої структури:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Уся папка `weig-qb-webui`** — це кореневий каталог вебінтерфейсу. Не копіюйте лише `public` або `private`.

### 2. Виберіть постійне розташування

Перемістіть усю папку туди, звідки її випадково не видалять. Наприклад:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Саме цей каталог згодом потрібно буде вказати в qBittorrent.

### 3. Увімкніть альтернативний вебінтерфейс у qBittorrent

Відкрийте qBittorrent і перейдіть до **Інструменти → Налаштування → Вебінтерфейс**. Точні назви пунктів залежать від вибраної мови qBittorrent.

1. Увімкніть **Використовувати альтернативний вебінтерфейс** (*Use alternative WebUI*).
2. Знайдіть поле **Розташування файлів** (*Files location*).
3. Укажіть шлях до папки `weig-qb-webui`.

Приклад для Windows:

```text
D:\weig-qb-webui
```

Приклад для Linux:

```text
/opt/weig-qb-webui
```

4. Натисніть **OK**, щоб зберегти налаштування.
5. Оновіть сторінку вебінтерфейсу qBittorrent. Якщо й далі відображається стара версія, натисніть `Ctrl + F5`, щоб оновити сторінку без старого кешу.

> **Як перевірити шлях?** Усередині вибраного каталогу мають одразу бути видимі `public`, `private` та `VERSION`. Якщо спочатку доводиться відкривати ще одну папку `weig-qb-webui`, ви вибрали неправильний рівень каталогу.

> **Якщо користуєтеся Docker:** qBittorrent працює **в контейнері**, тож потрібен шлях, доступний із контейнера, а не лише з основної системи. Докладне пояснення наведено нижче.

</details>

## Встановлення однією командою

Скрипт установлення для Linux та NAS завжди завантажується за постійною адресою Dev Pages нижче. **Адреса скрипту не визначає канал установлення:** без `-dev` встановлюється останній перевірений стабільний GitHub Release, а з `-dev` — поточна версія розробки, прив’язана до точного Git SHA. Скрипт залишається в поточному каталозі для подальших оновлень або відновлення.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Показати розташування скрипту та типового каталогу встановлення</b></summary>

Завантажений скрипт:

```text
./install.sh
```

Стандартний каталог вебінтерфейсу:

```text
~/.local/share/weig-qb-webui
```

Якщо запускати від користувача `root`, зазвичай це:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker: встановлення, кілька контейнерів і правильні шляхи</b></summary>

#### Чим відрізняються основна система та контейнер?

Якщо Docker працює на VPS, Linux-сервері, Synology, QNAP або іншому NAS:

- **Основна система (host):** Linux або NAS, де запущено Docker, тобто система, до якої ви зазвичай під’єднуєтеся через SSH.
- **Контейнер (container):** ізольоване середовище, у якому працює qBittorrent. Воно бачить лише ті шляхи, до яких отримало доступ.

Припустімо, папку конфігурації змонтовано так:

```text
Хост: /root/qbittorrent/config
   ↓ змонтовано як
У контейнері: /config
```

У Docker Compose це зазвичай виглядає так:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Шлях **ліворуч** від двокрапки належить **основній системі**, а шлях **праворуч** — **контейнеру**.

Якщо WeiG встановлено в основній системі тут:

```text
Хост: /root/qbittorrent/config/weig-qb-webui
```

то в полі **Files location** у qBittorrent потрібно вказати:

```text
/config/weig-qb-webui
```

**Не вказуйте `/root/qbittorrent/config/weig-qb-webui`** у qBittorrent: контейнер зазвичай не може безпосередньо бачити такий шлях основної системи.

#### Випадок 1: лише один контейнер qBittorrent

Виконайте:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Установник спробує знайти запущений контейнер qBittorrent, монтування `/config` та відповідний каталог в основній системі. Якщо конфігурація визначена однозначно, він також автоматично налаштує qBittorrent.

#### Випадок 2: не знаєте назви контейнера

Покажіть список контейнерів:

```sh
sh install.sh --list-containers
```

Або скористайтеся Docker безпосередньо:

```sh
docker ps
```

Якщо контейнер називається, наприклад:

```text
qbittorrent
```

виберіть його явно:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Випадок 3: декілька контейнерів qBittorrent

Наприклад, є основний контейнер і тестовий:

```text
qbittorrent
qbittorrent-test
```

Спочатку перегляньте список:

```sh
sh install.sh --list-containers
```

Щоб установити в основний контейнер:

```sh
sh install.sh --container=qbittorrent -configure
```

Щоб установити в тестовий:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Установник **не вибирає випадковий контейнер**, коли знайдено декілька відповідних.

#### Випадок 4: ви знаєте каталог `/config` в основній системі

Наприклад, це:

```text
/root/qbittorrent/config
```

Можна вказати його безпосередньо:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

На Synology шлях може бути таким:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

На іншому NAS — наприклад:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Це лише приклади; замініть їх фактичним розташуванням конфігурації qBittorrent у вашій основній системі.

#### Випадок 5: виберіть каталог WebUI

Якщо контейнер уже вибрано, можна також указати бажане розташування WebUI всередині нього:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Установник переведе цей шлях у відповідний каталог основної системи через монтування Docker для `/config`.

#### Випадок 6: оновлення кількох установлених копій за один раз

Якщо ви керуєте кількома екземплярами qBittorrent, повторіть параметр `-o`. Пакет завантажується та перевіряється один раз; заміна почнеться лише після підготовки всіх призначень. Для кожного призначення окремо зберігаються **останні три резервні копії** в `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

У режимі кількох призначень не додавайте `-configure`. Кожен екземпляр продовжить використовувати раніше налаштований шлях альтернативного WebUI. Щоб переглянути всі параметри, виконайте `sh install.sh -help`.

#### Перевірка шляхів після встановлення

Після успішного встановлення можна побачити приблизно такий результат:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: де файли фактично зберігаються в основній системі.
- `qBittorrent Root Folder`: шлях **усередині контейнера**, який слід вписати в поле *Files location* у qBittorrent.

Якщо використано `-configure` і конфігурацію qBittorrent вдалося надійно визначити, установник увімкне альтернативний вебінтерфейс і встановить правильний шлях. Інакше виконайте ручне налаштування за попередньою інструкцією.

</details>

## Поширені параметри

У Linux і Windows спільні параметри мають однакові назви. У PowerShell регістр літер у назвах параметрів не має значення.

| Призначення | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Остання стабільна версія (`main`) | Типово, без параметрів | Типово, без параметрів |
| Певна стабільна версія | `-version 1.2.0` | `-version 1.2.0` |
| Версія розробки | `-dev` | `-dev` |
| Каталог установлення | `-o /path` (у Linux можна повторювати) | `-o D:\path` або `-output D:\path` |
| Файл конфігурації qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Автоматичне налаштування qBittorrent | `-configure` | `-configure` |
| Відновлення попереднього встановлення | `-rollback` | `-rollback` |
| Повне видалення з резервними копіями | `-uninstall -purge` | `-uninstall -purge` |
| Перегляд усіх параметрів | `-help` | `-help` |
| Вибір контейнера Docker | `--container=NAME` | — |
| Список контейнерів Docker | `--list-containers` | — |
| Каталог `/config` в основній системі | `--config-root=/path` | — |

<details>
<summary><b>Пояснення параметрів (розгорнути)</b></summary>

- Без `-dev` використовується стабільний канал `main`; із `-dev` — версія розробки з точним Git SHA.
- Літера `o` у `-o` означає **output**. У Linux цей параметр можна повторювати, щоб оновити кілька наявних каталогів одним завантаженням.
- Резервні копії установника завжди зберігаються в `~/.config/weig-qb-webui/backups/`: **не більше трьох останніх копій для кожного призначення**.
- `-configure` вмикає *Use alternative WebUI* і встановлює *Files location*, але працює лише для одного призначення.
- `-rollback` відновлює останню резервну копію, створену установником для вибраного призначення. Повторивши `-o`, можна відновити кілька явно зазначених призначень.
- `-uninstall -purge` видаляє резервні копії та стан відновлення **тільки вибраного встановлення**, не зачіпаючи інших екземплярів.
- Щоб зберегти копії для майбутнього `-rollback`, приберіть `-purge`.
- `-version` встановлює конкретний GitHub Release, наприклад `1.2.0`. Якщо його немає, встановлення завершиться помилкою та **не перемкнеться автоматично** на latest або dev.
- Якщо контейнерів кілька, отримайте список через `--list-containers` і виберіть потрібний за допомогою `--container=NAME`, або вкажіть каталог `/config` в основній системі через `--config-root=/path`.

## Видалення однією командою

<details>
<summary><b>Повне видалення в Linux / NAS, Docker та Windows PowerShell</b></summary>

Зазвичай радимо **повністю видаляти WebUI, не залишаючи резервних копій установника**. Команди нижче видаляють вебінтерфейс, вимикають альтернативний WebUI для відповідного призначення, прибирають його резервні копії та стан відновлення, а також видаляють завантажений скрипт з поточного каталогу.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Для власного каталогу додайте `-o /shliakh/weig-qb-webui`.

### Docker

Один контейнер з автоматичним виявленням:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Кілька контейнерів:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Якщо використовуєте `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Для власного каталогу додайте `-o D:\weig-qb-webui`.

Параметр `-purge` видаляє лише резервні копії того встановлення, яке ви зараз прибираєте; копії інших екземплярів залишаються. Якщо спільний каталог стану порожній, буде також очищено `~/.config/weig-qb-webui` (для `root`: `/root/.config/weig-qb-webui`) у Linux або `%APPDATA%\weig-qb-webui` у Windows.

Якщо хочете залишити резервні копії, щоб пізніше скористатися `-rollback`, запускайте видалення без `-purge`.

</details>
