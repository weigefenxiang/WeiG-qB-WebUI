## Installazione manuale per chi inizia

<details>
<summary><b>Prima installazione? Apri la guida rapida di un minuto</b></summary>

### 1. Estrai l'archivio

Scarica `weig-qb-webui.zip` ed estrailo: al suo interno troverai direttamente questa cartella:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

La **cartella `weig-qb-webui` completa** costituisce la directory principale dell'interfaccia. Non copiare soltanto `public` o `private`.

### 2. Scegli un percorso permanente

Sposta l'intera cartella in una posizione da cui non venga rimossa accidentalmente. Per esempio:

```text
Windows:D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

È il percorso che dovrai indicare nelle impostazioni di qBittorrent.

### 3. Attiva l'interfaccia alternativa in qBittorrent

Apri qBittorrent e vai in **Strumenti → Opzioni… → Interfaccia Web** (la dicitura può cambiare a seconda della lingua di qBittorrent).

1. Seleziona **Usa interfaccia Web alternativa** (*Use alternative WebUI*).
2. Individua il campo **Percorso dei file** (*Files location*).
3. Inserisci il percorso della cartella `weig-qb-webui`.

Esempio per Windows:

```text
D:\weig-qb-webui
```

Esempio per Linux:

```text
/opt/weig-qb-webui
```

4. Premi **OK** per salvare le impostazioni.
5. Ricarica la pagina Web di qBittorrent. Se compare ancora la vecchia interfaccia, prova `Ctrl + F5` per forzare l'aggiornamento.

> **Come verificare il percorso?** Nella cartella selezionata devono essere visibili direttamente `public`, `private` e `VERSION`. Se devi aprire un'ulteriore sottocartella `weig-qb-webui` per trovarli, hai selezionato il livello sbagliato.

> **Se usi Docker:** il percorso deve essere accessibile *all'interno del container* di qBittorrent. Quello del computer host potrebbe non esserlo; leggi la sezione Docker qui sotto.

</details>

## Installazione con un solo comando

Lo script per Linux e NAS viene scaricato dall'indirizzo fisso di Dev Pages indicato sotto. **L'indirizzo dello script non determina il canale di installazione:** senza `-dev` viene installata l'ultima Release stabile verificata, mentre `-dev` installa la versione di sviluppo corrente identificata dal Git SHA esatto. Lo script resta nella cartella corrente, così puoi riutilizzarlo per aggiornamenti e ripristini.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Mostra dove viene salvato lo script e la cartella di installazione predefinita</b></summary>

Lo script scaricato si trova in:

```text
./install.sh
```

La directory predefinita per l'interfaccia Web è:

```text
~/.local/share/weig-qb-webui
```

Se esegui l'installazione come utente `root`, normalmente sarà:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Installazione Docker, più container e scelta dei percorsi</b></summary>

#### Host e container: qual è la differenza?

Se esegui Docker su un VPS, un server Linux, Synology, QNAP o un altro NAS:

- **Host**: il sistema Linux o NAS sul quale gira Docker, ad esempio quello a cui ti colleghi via SSH.
- **Container**: l'ambiente isolato in cui gira qBittorrent, che vede solo i percorsi a cui gli viene dato accesso.

Supponiamo che il container abbia questa mappatura:

```text
Host: /root/qbittorrent/config
   ↓ montato come
Nel container: /config
```

In Docker Compose la configurazione è simile a questa:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Prima dei due punti c'è la cartella dell'**host**; dopo i due punti c'è il percorso visto **nel container**.

Se l'interfaccia è installata sull'host in:

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

nelle impostazioni di qBittorrent dovrai inserire **Files location** come segue:

```text
/config/weig-qb-webui
```

**Non usare il percorso dell'host** `/root/qbittorrent/config/weig-qb-webui` nel campo di qBittorrent: normalmente il container non può accedervi.

#### Caso 1: un solo container qBittorrent

Per iniziare, esegui:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

L'installer prova a individuare il container qBittorrent in esecuzione, la mappatura di `/config` e la cartella corretta sull'host, poi configura qBittorrent se il contesto è sufficientemente chiaro.

#### Caso 2: elencare i container

Se non conosci il nome del container:

```sh
sh install.sh --list-containers
```

Puoi anche controllare l'elenco con Docker:

```sh
docker ps
```

Se il container si chiama, per esempio:

```text
qbittorrent
```

selezionalo esplicitamente:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Caso 3: più container qBittorrent

Se hai sia un'istanza normale sia una di prova, ad esempio:

```text
qbittorrent
qbittorrent-test
```

controlla prima l'elenco:

```sh
sh install.sh --list-containers
```

Per installare nell'istanza principale:

```sh
sh install.sh --container=qbittorrent -configure
```

Per installare nell'istanza di prova:

```sh
sh install.sh --container=qbittorrent-test -configure
```

L'installer **non sceglie arbitrariamente** uno dei container quando ne rileva più di uno.

#### Caso 4: conosci già la cartella `/config` sull'host

Per esempio:

```text
/root/qbittorrent/config
```

Puoi specificarla direttamente:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Su Synology il percorso potrebbe essere:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Su altri NAS potrebbe invece essere:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Questi sono soltanto esempi: sostituiscili con il percorso reale della cartella `/config` di qBittorrent sul tuo host.

#### Caso 5: scegliere la directory dell'interfaccia Web

Dopo aver indicato il container, puoi specificare anche il percorso di destinazione visibile al container:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

L'installer ricava il corrispondente percorso sull'host dalla mappatura Docker di `/config`.

#### Caso 6: aggiornare più installazioni in una volta

Se gestisci più istanze, puoi ripetere `-o`. L'archivio viene scaricato e verificato una sola volta; la sostituzione delle installazioni inizia soltanto quando tutte le destinazioni sono state preparate. Ogni destinazione conserva fino a **tre backup separati** nella directory `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Nella modalità con più destinazioni non aggiungere `-configure`: ogni istanza continua a usare il proprio percorso dell'interfaccia alternativa già configurato. Per tutti i parametri consulta `sh install.sh -help`.

#### Controllare i percorsi dopo l'installazione

Un'installazione riuscita può mostrare:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: dove si trovano i file sul sistema host.
- `qBittorrent Root Folder`: il percorso **interno al container** da inserire nel campo *Files location* di qBittorrent.

Con `-configure`, quando la configurazione viene individuata e verificata, l'installer abilita l'interfaccia alternativa e ne imposta il percorso. Altrimenti puoi seguire i passaggi della guida manuale.

</details>

### Windows PowerShell

Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure

## Parametri più utilizzati

Linux e Windows usano gli stessi nomi per i parametri comuni. PowerShell non distingue maiuscole e minuscole nei nomi dei parametri.

| Operazione | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Installare l'ultima versione stabile (`main`) | Predefinito, nessun parametro | Predefinito, nessun parametro |
| Installare una Release specifica | `-version 1.2.0` | `-version 1.2.0` |
| Usare la versione di sviluppo | `-dev` | `-dev` |
| Scegliere il percorso di installazione | `-o /path` (ripetibile su Linux) | `-o D:\path` oppure `-output D:\path` |
| Specificare un file di configurazione qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Configurare automaticamente qBittorrent | `-configure` | `-configure` |
| Ripristinare l'installazione precedente | `-rollback` | `-rollback` |
| Disinstallare e cancellare i backup | `-uninstall -purge` | `-uninstall -purge` |
| Visualizzare la guida completa | `-help` | `-help` |
| Specificare un container Docker | `--container=NAME` | — |
| Elencare i container Docker | `--list-containers` | — |
| Specificare la directory `/config` sull'host | `--config-root=/path` | — |

<details>
<summary><b>Dettagli sui parametri (espandi)</b></summary>

- Senza `-dev`, l'installer usa il canale stabile `main`; `-dev` usa invece il Git SHA esatto del ramo di sviluppo.
- `-o` significa **output**. Su Linux puoi ripeterlo per aggiornare più installazioni esistenti con un solo download.
- I backup gestiti dall'installer si trovano sempre in `~/.config/weig-qb-webui/backups/`; vengono conservati al massimo **tre backup per ciascuna destinazione**.
- `-configure` abilita automaticamente *Use alternative WebUI* e imposta *Files location*, ma è disponibile soltanto per una singola destinazione.
- `-rollback` ripristina l'ultimo backup creato dall'installer per la destinazione selezionata. Puoi ripetere `-o` per ripristinare più destinazioni esplicite.
- `-uninstall -purge` elimina i backup e lo stato di rollback **soltanto della destinazione selezionata**, senza toccare quelli delle altre istanze.
- Se vuoi conservare i backup per un successivo `-rollback`, ometti `-purge`.
- `-version` permette di scegliere una Release GitHub, per esempio `1.2.0`. Se la versione non esiste, l'installer restituisce un errore: **non passa automaticamente a latest o dev**.
- Con più container puoi usare `--list-containers` e poi `--container=NAME`, oppure indicare direttamente la cartella `/config` sull'host con `--config-root=/path`.

### Versione specifica e cartella di installazione

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Ripristino

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Disinstallazione con un solo comando

<details>
<summary><b>Rimozione completa su Linux / NAS, Docker e Windows PowerShell</b></summary>

Per impostazione predefinita consigliamo la **rimozione senza conservare i backup dell'installer**: disinstalla l'interfaccia Web, disabilita l'interfaccia alternativa per la destinazione interessata, elimina i backup e lo stato di rollback appartenenti a quella destinazione e rimuove lo script scaricato nella directory corrente.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Per un percorso personalizzato, aggiungi `-o /percorso/weig-qb-webui`.

### Docker

Un solo container con rilevamento automatico:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Se hai più container:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Se usi `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Per una cartella personalizzata, aggiungi `-o D:\weig-qb-webui`.

`-purge` elimina soltanto i backup appartenenti alla destinazione disinstallata. Non rimuove i backup delle altre istanze. Se non rimane altro contenuto, viene cancellata anche la directory di stato condivisa `~/.config/weig-qb-webui` (per `root`: `/root/.config/weig-qb-webui`) o `%APPDATA%\weig-qb-webui` su Windows.

Se vuoi conservare i backup per usarli con `-rollback`, esegui la disinstallazione senza `-purge`.

</details>
