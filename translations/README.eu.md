## Instantzia anitzeko alboko barra

qBittorrent-en hainbat instantzia independentek WeiG karpeta bera erabil dezakete **irakurtzeko soilik**. Muntatu ostalariaren karpeta Docker edukiontzi bakoitzean, adibidez `/root/weig-qb-webui:/weig-qb-webui:ro`, eta ezarri instantzia bakoitzaren Alternative WebUI-ren erroa `/weig-qb-webui` bidean. Instantzia bakoitzak bere torrent datu-basea, ezarpenak eta saio-hasiera mantentzen ditu.

Alboko barrako **Instances** atalean instantziak erregistratu, orri osoz batetik bestera aldatu eta izena alda daiteke (eskuineko klikarekin edo errenkadako menutik). Uneko instantziari, adibidez, `524 (current)` izena jar dakioke; unekoaren adierazleak benetako URLari jarraitzen dio, ez gordetako izenaren atzizkiari. Egiaztapen automatikoaren tartea **Settings → WeiG WebUI → Interface** atalean ezartzen da: lehenetsia `30 min` da, eta desgaitu edo 5–1440 minutu artean aukeratu daiteke.

**Konexio-egoeraren frogak zuhurtziaz interpretatzen dira:** jatorri bereko WebAPI egiaztatuak qB konektatuta dagoela adierazten du; kredentzialik gabeko jatorri arteko `no-cors` erantzunak HTTP helbidea eskuragarri dela besterik ez du frogatzen, 403/404 erantzuna ere izan baitaiteke. Ez da jatorri arteko Cookie/SID irakurketarik, pasahitz edo saio-transferentziarik, CORS saihesbiderik edo backend pasabiderik eskaintzen. qB lehenago egiaztatu ondoren gordetako ordua **froga historikoa** da, ez uneko konexioaren egiaztapena. Nabigatzaileko `127.0.0.1` nabigatzailea darabilen gailuari dagokio, ez urruneko VPS bati.

## Erabiltzaile berrientzako instalazioa

<details>
<summary><b>Lehen aldiz instalatzen? Zabaldu minutu bateko gida hau</b></summary>

### 1. Deskonprimitu ZIP fitxategia

Deskargatu `weig-qb-webui.zip` eta deskonprimitu. Artxiboak dagoeneko karpeta estandarra sortzen du:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**`weig-qb-webui` karpeta osoa** da WebUI-ren erroa. Ez kopiatu `public` edo `private` bakarrik.

### 2. Eraman kokapen iraunkor batera

Jarri `weig-qb-webui` karpeta osoa gero nahi gabe ezabatuko ez duzun kokapen iraunkor batean, adibidez:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Direktorio hori adierazi beharko duzu qBittorrent-en.

### 3. Gaitu qBittorrent-en

Ireki qBittorrent:

**Tools → Options... → WebUI**

Hauek dira qBittorrent-en ingelesezko interfazeko uneko menu-izenak. Ondoren:

1. Gaitu **Use alternative WebUI**.
2. Bilatu **Files location:** eremua.
3. Sartu `weig-qb-webui` karpetarako bidea.

Windows-erako adibidea:

```text
D:\weig-qb-webui
```

Linux-erako adibide arrunta:

```text
/opt/weig-qb-webui
```

4. Sakatu **OK** gordetzeko.
5. Freskatu qBittorrent WebUI-ren orria. Nabigatzaileak aurreko bertsioa cachean badu, saiatu behin `Ctrl + F5` sakatzen.

> **Nola jakin bidea zuzena dela?** Adierazitako direktorioak zuzenean eduki behar ditu `public`, `private`, `VERSION` eta WebUI-ren gainerako fitxategiak. Horiek ikusteko beste `weig-qb-webui` karpeta batean sartu behar baduzu, bideak maila bat soberan edo faltan du.

> **Docker erabiltzaileak:** qBittorrent edukiontzi baten barruan exekutatzen da; beraz, normalean ezin da ostalariaren bidea zuzenean erabili. Ikusi beheko **Docker** gida ostalariaren eta edukiontziaren bideen arteko aldea ulertzeko.

</details>

## Komando bakarreko instalazioa

Linux/NAS sistemetarako komando bakarreko instalatzailea beheko Dev Pages URL finkotik deskargatzen da beti. **Scriptaren URLak ez du instalazio-kanala aukeratzen:** `-dev` gabe egiaztatutako azken GitHub Release egonkorra instalatzen da; gehitu `-dev` soilik Git SHA zehatzaz identifikatutako uneko garapen-bertsioa nahi baduzu. Deskargatutako scripta uneko direktorioan geratuko da, gero eguneratu edo atzera egiteko.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Erakutsi scriptaren kokapena eta WebUI instalazioaren direktorio lehenetsia</b></summary>

```text
./install.sh
```

WebUI berez honako direktorio honetan instalatzen da:

```text
~/.local/share/weig-qb-webui
```

Adibidez, `root` erabiltzaile gisa exekutatzean, normalean:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Dockerren komando bakarreko instalazioa / edukiontzi anitz / bideen gida (hasiberrientzat gomendatua)</b></summary>

#### Lehenik, ulertu «ostalaria» eta «edukiontzia»

qBittorrent Docker barruan erabiltzen baduzu VPS, Linux zerbitzari, Synology, QNAP edo beste NAS batean:

- **Ostalaria**: Docker exekutatzen duen Linux/NAS makina erreala, SSH bidez konektatzean ikusten duzun sistema.
- **Edukiontzia**: Dockerrek qBittorrent-entzat sortzen duen ingurune isolatua. qBittorrent-ek edukiontzi barruko bideak zuzenean ikus ditzake, baina ez ostalariaren edozein bide.

Adibidez, zure qBittorrent edukiontziak honako bide-mapa izan dezake:

```text
Host:      /root/qbittorrent/config
   ↓ mapped to
Container: /config
```

Docker Compose-ren ohiko konfigurazio bat honelakoa da:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Bi puntuen ezkerreko `/root/qbittorrent/config` **ostalariaren bidea** da; eskuineko `/config`, berriz, **edukiontziaren bidea**.

WeiG qB WebUI fisikoki hemen instalatuta badago:

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

orduan qBittorrent-eko **Files location:** eremuan hau jarri behar da:

```text
/config/weig-qb-webui
```

**Ez sartu `/root/qbittorrent/config/weig-qb-webui` qBittorrent-en**, edukiontziak normalean ezin duelako ostalariaren bide hori zuzenean ikusi.

#### 1. kasua: qBittorrent edukiontzi bakarra martxan

Erabili komando bakarreko ohiko agindua:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Instalatzailea martxan dagoen qBittorrent edukiontzia eta haren `/config` mapa aurkitzen saiatuko da; WebUI ostalariaren kokapen egokian instalatu eta qBittorrent automatikoki konfiguratuko du.

#### 2. kasua: lehenik, aurkitu qBittorrent edukiontziaren izena

Ez badakizu edukiontziak zer izen duen:

```sh
sh install.sh --list-containers
```

Docker zuzenean ere erabil dezakezu:

```sh
docker ps
```

qBittorrent edukiontziaren izena hau bada:

```text
qbittorrent
```

hautatu berariaz:

```sh
sh install.sh --container=qbittorrent -configure
```

#### 3. kasua: qBittorrent edukiontzi bat baino gehiago

Adibidez:

```text
qbittorrent
qbittorrent-test
```

Zerrendatu lehenik:

```sh
sh install.sh --list-containers
```

Instalatu `qbittorrent` edukiontzi nagusirako:

```sh
sh install.sh --container=qbittorrent -configure
```

Instalatu proba-edukiontzirako:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Instalatzaileak ez du qBittorrent edukiontzi bat ausaz aukeratuko hainbat daudenean.

#### 4. kasua: badakizu ostalariaren zein direktorio dagoen `/config` gisa muntatuta

Adibidez:

```text
/root/qbittorrent/config
```

Adierazi zuzenean:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Synology-n bide bat honelakoa izan daiteke:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Beste NAS batean, adibidez:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Adibideak baino ez dira. **Ordeztu qBittorrent-en `/config` gisa muntatutako ostalariaren benetako bidearekin.**

#### 5. kasua: aukeratu WebUI instalatzeko bidea

Edukiontzia aukeratu ondoren, edukiontziak ikus dezakeen WebUI-ren kokapena ere zehaztu dezakezu:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Instalatzaileak edukiontziko `/config/...` bidea ostalariaren instalazio-bide egokira bihurtzen du.

#### 6. kasua: eguneratu WebUI-ren hainbat direktorio deskarga bakar batekin

qBittorrent-en hainbat instantziatarako, errepikatu `-o`. Paketea behin bakarrik deskargatu eta egiaztatzen da, helburu guztiak prestatu egiten dira aldaketa egin aurretik, eta helburu bakoitzak bere azken hiru babeskopiak `~/.config/weig-qb-webui/backups/` azpian mantentzen ditu.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Ez gehitu `-configure` helburu anitzeko moduan; qBittorrent instantzia bakoitzak dagoeneko konfiguratuta duen Alternative WebUI-ren erro-karpeta mantentzen du. Uneko komando-aukerak ikusteko, exekutatu `sh install.sh -help`.

#### Zer agertuko da instalatu ondoren?

Instalazio arrakastatsuak honelako informazioa erakusten du:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

Esanahia:

- `Host install path`: fitxategiak ostalarian benetan gordetzen diren kokapena.
- `qBittorrent Root Folder`: **qBittorrent-ek Files location eremuan erabili behar duen edukiontzi barruko bidea**.

`-configure` aukerak qBittorrent-en konfigurazioa aurkitzen badu, instalatzaileak **Use alternative WebUI** gaitzen du eta bidea automatikoki ezartzen du. Bestela, jarraitu goiko **Erabiltzaile berrientzako instalazioa → Gaitu qBittorrent-en** ataleko eskuzko urratsei.

</details>

## Ohiko aukerak
Linuxek eta Windowsek aukera-izen publiko berak erabiltzen dituzte ahal den neurrian. Dokumentazioan letra xeheak erabiltzen dira; PowerShell parametroen izenek ez dituzte maiuskulak eta minuskulak bereizten.

| Helburua | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| main adar egonkorra | Lehenetsia, aukerarik gabe | Lehenetsia, aukerarik gabe |
| Release jakin bat | `-version 1.2.0` | `-version 1.2.0` |
| Garapen-bertsioa | `-dev` | `-dev` |
| Instalazio-direktorio pertsonalizatua | `-o /path` (Linuxen errepika daiteke) | `-o D:\path` edo `-output D:\path` |
| qBittorrent-en konfigurazio-fitxategi pertsonalizatua | — | `-qbconfig D:\path\qBittorrent.ini` |
| qBittorrent automatikoki konfiguratu | `-configure` | `-configure` |
| Aurreko instalazioa berrezarri | `-rollback` | `-rollback` |
| Desinstalazio osoa (babeskopiarik gorde gabe) | `-uninstall -purge` | `-uninstall -purge` |
| Laguntza osoa | `-help` | `-help` |
| Hautatu Docker edukiontzia | `--container=NAME` | — |
| Zerrendatu Docker edukiontziak | `--list-containers` | — |
| Adierazi Docker `/config` gisa muntatutako ostalari-direktorioa | `--config-root=/path` | — |

<details>
<summary><b>Oharrak (egin klik zabaltzeko)</b></summary>

Oharrak:

- `-dev` gabe `main` adar egonkorra erabiltzen da; `-dev` aukerak uneko garapen-bertsioaren Git SHA zehatza hautatzen du.
- `-o` aukerak **output** esan nahi du, eta WeiG qB WebUI instalatzeko direktorioa zehazten du. Linuxen hainbat helburu eguneratzeko errepika daiteke, egiaztatutako deskarga bakar batekin.
- Instalatzailearen babeskopiak `~/.config/weig-qb-webui/backups/` azpian daude eta **azken 3 babeskopiak helburu bakoitzeko bereiz gordetzen dira**.
- `-configure` aukerak qBittorrent-en **Use alternative WebUI** gaitzen du eta instalatu ondoren **Files location** ezartzen du. Helburu bakar baterako diseinatuta dago.
- `-rollback` aukerak hautatutako helburuaren instalatzaileak gordetako azken babeskopia berrezartzen du; hainbat helburu zehatz berrezartzeko, errepikatu `-o`.
- `-version` aukerak GitHub Release zehatza instalatzen du, adibidez `1.2.0`. Eskatutako bertsioa ez badago, instalazioak huts egiten du eta **ez du inoiz latest edo dev bertsiora automatikoki aldatzen**.
- `-help` aukerak Linuxerako uneko komando-sintaxi onartua erakusten du.
- Dockerreko qBittorrent edukiontzi bat baino gehiago badituzu, erabili `--list-containers` eta hautatu bat `--container=NAME` bidez. Ostalariaren konfigurazio-direktorioa badakizu, `--config-root=/path` ere erabil dezakezu.

```

```

```powershell

```

## Komando bakarreko desinstalazioa

<details>
<summary><b>Linux / NAS, Docker eta Windows PowerShell sistema guztietarako desinstalazio osoa</b></summary>

Beheko komando gomendatuak desinstalazio osoa egiten du **instalatzailearen babeskopiak gorde gabe**: WebUI ezabatzen du, dagokion ordezko WebUI konfigurazioa desgaitzen du, helburu honen babeskopiak eta atzera egiteko egoera garbitzen ditu, eta ondoren uneko direktorioan deskargatutako instalazio-scripta ezabatzen du.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Instalazio-direktorio pertsonalizatua baduzu, gehitu `-o /path/to/weig-qb-webui`.

### Docker

Edukiontzi bakarra / detekzio automatikoa:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Hainbat edukiontzi:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

`--config-root` erabiltzean:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Instalazio-direktorio pertsonalizatua baduzu, gehitu `-o D:\weig-qb-webui`.

`-purge` aukerak desinstalatutako helburuaren babeskopiak baino ez ditu kentzen, beste instalazioetakoak ukitu gabe. Partekatutako egoera-direktorioa hutsik geratzen denean, Linuxen `~/.config/weig-qb-webui` (`root` erabiltzailearentzat: `/root/.config/weig-qb-webui`) edo Windowsen `%APPDATA%\weig-qb-webui` ere ezabatuko da.

Gero `-rollback` egiteko instalatzailearen babeskopiak gorde nahi badituzu, ez jarri `-purge`.

</details>
