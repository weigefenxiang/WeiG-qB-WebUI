## แถบด้านข้างสำหรับหลายอินสแตนซ์

qBittorrent หลายอินสแตนซ์สามารถใช้โฟลเดอร์ WeiG ที่จัดเตรียมไว้ร่วมกันแบบ **อ่านอย่างเดียว** ได้ โดยเมานต์โฟลเดอร์จากโฮสต์ลงในคอนเทนเนอร์ Docker แต่ละตัว เช่น `/root/weig-qb-webui:/weig-qb-webui:ro` แล้วตั้งค่าราก Alternative WebUI ของแต่ละอินสแตนซ์เป็น `/weig-qb-webui` ทั้งนี้ฐานข้อมูลทอร์เรนต์ การตั้งค่า และการเข้าสู่ระบบของแต่ละอินสแตนซ์ยังคงแยกจากกัน

หัวข้อ **Instances** ในแถบด้านข้างใช้เพิ่มอินสแตนซ์ สลับไปยังหน้าเว็บของอินสแตนซ์อื่น และเปลี่ยนชื่อ (คลิกขวาหรือใช้เมนูในแถว) สามารถตั้งชื่ออินสแตนซ์ปัจจุบัน เช่น `524 (current)` โดยตัวบ่งชี้อินสแตนซ์ปัจจุบันอ้างอิง URL จริง ไม่ได้ยึดคำต่อท้ายชื่อที่บันทึกไว้ รอบตรวจสอบอัตโนมัติอยู่ใน **Settings → WeiG WebUI → Interface** ค่าเริ่มต้นคือ `30 min` และเลือกปิดหรือตั้งค่าได้ตั้งแต่ 5–1440 นาที

**หลักฐานสถานะการเชื่อมต่อจะแสดงอย่างระมัดระวัง:** เฉพาะ WebAPI แบบ same-origin ที่ยืนยันได้เท่านั้นจึงหมายความว่า qB ออนไลน์ การตอบสนอง `no-cors` ข้าม origin โดยไม่มีข้อมูลรับรอง หมายความเพียงว่าที่อยู่ HTTP เข้าถึงได้ ซึ่งอาจส่งสถานะ 403/404 มาก็ได้ ระบบไม่อ่าน Cookie/SID ข้าม origin ไม่ถ่ายโอนรหัสผ่านหรือเซสชัน ไม่ข้าม CORS และไม่มีเกตเวย์แบ็กเอนด์ เวลาที่เคยบันทึกหลังยืนยัน qB ครั้งก่อนเป็นเพียง **หลักฐานย้อนหลัง** ไม่ใช่ข้อพิสูจน์ว่าออนไลน์ในขณะนี้ ส่วน `127.0.0.1` ในเบราว์เซอร์หมายถึงอุปกรณ์ที่เปิดเบราว์เซอร์ ไม่ใช่ VPS ระยะไกล

## วิธีติดตั้งสำหรับผู้เริ่มต้น

<details>
<summary><b>ติดตั้งครั้งแรกใช่ไหม? เปิดคู่มือฉบับย่อนี้</b></summary>

### 1. แตกไฟล์ ZIP

ดาวน์โหลด `weig-qb-webui.zip` แล้วแตกไฟล์ ภายใน ZIP มีโฟลเดอร์มาตรฐานอยู่แล้ว:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

โฟลเดอร์ **`weig-qb-webui`** ทั้งหมดคือรากของ WebUI อย่าคัดลอกเฉพาะ `public` หรือ `private`

### 2. ย้ายไปยังตำแหน่งถาวร

วางโฟลเดอร์ `weig-qb-webui` ทั้งโฟลเดอร์ไว้ในตำแหน่งถาวรที่ไม่เผลอลบในภายหลัง เช่น:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

คุณจะต้องระบุพาธนี้ใน qBittorrent ภายหลัง

### 3. เปิดใช้งานใน qBittorrent

เปิด qBittorrent:

**Tools → Options... → WebUI**

ชื่อเมนูเหล่านี้เป็นชื่อที่ตรงกับอินเทอร์เฟซภาษาอังกฤษของ qBittorrent เวอร์ชันปัจจุบัน จากนั้น:

1. เปิด **Use alternative WebUI**
2. หาช่อง **Files location:**
3. ใส่พาธไปยังโฟลเดอร์ `weig-qb-webui`

ตัวอย่างบน Windows:

```text
D:\weig-qb-webui
```

ตัวอย่างบน Linux:

```text
/opt/weig-qb-webui
```

4. คลิก **OK** เพื่อบันทึก
5. โหลดหน้า qBittorrent WebUI ใหม่ หากเบราว์เซอร์ยังแสดงหน้าเก่าจากแคช ให้ลองกด `Ctrl + F5` หนึ่งครั้ง

> **จะทราบได้อย่างไรว่าพาธถูกต้อง?** ไดเรกทอรีที่ระบุต้องมี `public`, `private`, `VERSION` และไฟล์ WebUI อื่น ๆ อยู่ภายในโดยตรง หากต้องเข้าไปในโฟลเดอร์ `weig-qb-webui` อีกชั้นจึงเห็นไฟล์เหล่านี้ แสดงว่าระบุพาธสูงหรือลึกเกินไปหนึ่งระดับ

> **สำหรับผู้ใช้ Docker:** qBittorrent ทำงานอยู่ในคอนเทนเนอร์ จึงมักใช้พาธบนโฮสต์โดยตรงไม่ได้ โปรดอ่านหัวข้อ **Docker** ด้านล่างเพื่อทำความเข้าใจความแตกต่างของพาธบนโฮสต์และภายในคอนเทนเนอร์

</details>

## ติดตั้งด้วยคำสั่งเดียว

ตัวติดตั้งแบบคำสั่งเดียวสำหรับ Linux/NAS ดาวน์โหลดจาก URL ของ Dev Pages ที่กำหนดไว้คงที่ด้านล่างเสมอ **URL ของสคริปต์ไม่ได้เป็นตัวกำหนดช่องทางการติดตั้ง:** หากไม่ใส่ `-dev` จะติดตั้ง GitHub Release รุ่นเสถียรล่าสุดที่ผ่านการตรวจสอบแล้ว และควรใส่ `-dev` เฉพาะเมื่อตั้งใจติดตั้งรุ่นพัฒนาปัจจุบันที่ระบุด้วย Git SHA อย่างเจาะจง สคริปต์ที่ดาวน์โหลดจะอยู่ในไดเรกทอรีปัจจุบันเพื่อใช้อัปเดตหรือย้อนกลับในภายหลัง

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>แสดงตำแหน่งสคริปต์และไดเรกทอรีติดตั้ง WebUI เริ่มต้น</b></summary>

```text
./install.sh
```

โดยค่าเริ่มต้น WebUI จะติดตั้งไว้ที่:

```text
~/.local/share/weig-qb-webui
```

ตัวอย่างเช่น เมื่อเรียกใช้ด้วยผู้ใช้ `root` ตำแหน่งมักเป็น:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>คู่มือติดตั้ง Docker ด้วยคำสั่งเดียว / หลายคอนเทนเนอร์ / การกำหนดพาธ (แนะนำสำหรับผู้เริ่มต้น)</b></summary>

#### ทำความเข้าใจ “โฮสต์” และ “คอนเทนเนอร์” ก่อน

หาก qBittorrent รันใน Docker บน VPS เซิร์ฟเวอร์ Linux, Synology, QNAP หรือ NAS อื่น:

- **โฮสต์**: เครื่อง Linux/NAS จริงที่รัน Docker ซึ่งเป็นระบบที่เห็นหลังจากเข้าสู่ระบบด้วย SSH
- **คอนเทนเนอร์**: สภาพแวดล้อมแยกที่ Docker สร้างให้ qBittorrent ซึ่งมองเห็นพาธภายในคอนเทนเนอร์โดยตรง แต่ไม่สามารถเห็นพาธใด ๆ บนโฮสต์ได้โดยอัตโนมัติ

ตัวอย่างการแมปพาธของคอนเทนเนอร์ qBittorrent:

```text
Host:      /root/qbittorrent/config
   ↓ mapped to
Container: /config
```

ตัวอย่างการตั้งค่า Docker Compose โดยทั่วไป:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

ด้านซ้ายของเครื่องหมายทวิภาค `/root/qbittorrent/config` คือ **พาธบนโฮสต์** ส่วนด้านขวา `/config` คือ **พาธภายในคอนเทนเนอร์**

หากติดตั้ง WeiG qB WebUI ไว้บนโฮสต์ที่:

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

ช่อง **Files location:** ของ qBittorrent ต้องระบุว่า:

```text
/config/weig-qb-webui
```

**อย่าระบุ `/root/qbittorrent/config/weig-qb-webui` ใน qBittorrent** เพราะโดยทั่วไปคอนเทนเนอร์มองไม่เห็นพาธนั้นบนโฮสต์โดยตรง

#### กรณีที่ 1: มีคอนเทนเนอร์ qBittorrent ทำงานเพียงตัวเดียว

ใช้คำสั่งติดตั้งแบบคำสั่งเดียวตามปกติ:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

ตัวติดตั้งจะพยายามตรวจหาคอนเทนเนอร์ qBittorrent ที่กำลังทำงาน ตรวจการแมป `/config` ติดตั้ง WebUI ไปยังตำแหน่งที่สอดคล้องกันบนโฮสต์ และตั้งค่า qBittorrent โดยอัตโนมัติ

#### กรณีที่ 2: ค้นหาชื่อคอนเทนเนอร์ qBittorrent ก่อน

หากไม่แน่ใจชื่อคอนเทนเนอร์:

```sh
sh install.sh --list-containers
```

หรือเรียกใช้ Docker โดยตรง:

```sh
docker ps
```

หากคอนเทนเนอร์ qBittorrent มีชื่อว่า:

```text
qbittorrent
```

ให้ระบุคอนเทนเนอร์นั้นโดยตรง:

```sh
sh install.sh --container=qbittorrent -configure
```

#### กรณีที่ 3: มีคอนเทนเนอร์ qBittorrent หลายตัว

ตัวอย่าง:

```text
qbittorrent
qbittorrent-test
```

แสดงรายการก่อน:

```sh
sh install.sh --list-containers
```

ติดตั้งสำหรับคอนเทนเนอร์หลัก `qbittorrent`:

```sh
sh install.sh --container=qbittorrent -configure
```

ติดตั้งสำหรับคอนเทนเนอร์ทดสอบ:

```sh
sh install.sh --container=qbittorrent-test -configure
```

ตัวติดตั้งจะไม่เลือกคอนเทนเนอร์เองโดยไม่มีการแจ้งเมื่อพบ qBittorrent หลายตัว

#### กรณีที่ 4: ทราบไดเรกทอรีบนโฮสต์ที่เมานต์เป็น `/config` อยู่แล้ว

ตัวอย่าง:

```text
/root/qbittorrent/config
```

ระบุพาธนั้นโดยตรง:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

ตัวอย่างพาธบน Synology:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

ตัวอย่างพาธบน NAS อื่น:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

ตัวอย่างเหล่านี้เป็นเพียงแนวทาง **ให้เปลี่ยนเป็นพาธจริงบนโฮสต์ที่เมานต์เป็น `/config` ของ qBittorrent**

#### กรณีที่ 5: เลือกพาธติดตั้ง WebUI

หลังจากเลือกคอนเทนเนอร์แล้ว สามารถกำหนดตำแหน่ง WebUI ที่คอนเทนเนอร์มองเห็นได้:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

ตัวติดตั้งจะแปลงพาธ `/config/...` ภายในคอนเทนเนอร์เป็นพาธติดตั้งที่สอดคล้องกันบนโฮสต์

#### กรณีที่ 6: อัปเดต WebUI หลายไดเรกทอรีด้วยการดาวน์โหลดครั้งเดียว

สำหรับ qBittorrent หลายอินสแตนซ์ ให้ระบุ `-o` ซ้ำ โดยดาวน์โหลดและตรวจสอบแพ็กเกจเพียงครั้งเดียว เตรียมทุกเป้าหมายก่อนสลับเวอร์ชัน และแต่ละเป้าหมายเก็บข้อมูลสำรองล่าสุดของตนเองสามชุดใต้ `~/.config/weig-qb-webui/backups/`

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

ห้ามใส่ `-configure` ในโหมดหลายเป้าหมาย เพราะแต่ละอินสแตนซ์จะคงค่าโฟลเดอร์ราก Alternative WebUI เดิมไว้ หากต้องการดูรูปแบบคำสั่งปัจจุบัน ให้เรียก `sh install.sh -help`

#### หลังติดตั้งควรเห็นอะไร?

เมื่อติดตั้งสำเร็จจะเห็นข้อความลักษณะนี้:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

ความหมาย:

- `Host install path`: ตำแหน่งที่เก็บไฟล์จริงบนโฮสต์
- `qBittorrent Root Folder`: **พาธภายในคอนเทนเนอร์ที่ qBittorrent ควรใช้กับช่อง Files location**

หาก `-configure` พบไฟล์ตั้งค่า qBittorrent จะเปิด **Use alternative WebUI** และกำหนดพาธให้อัตโนมัติ มิฉะนั้นให้ทำตามขั้นตอนในหัวข้อ **วิธีติดตั้งสำหรับผู้เริ่มต้น → เปิดใช้งานใน qBittorrent** ด้านบน

## ตัวเลือกที่ใช้บ่อย
Linux และ Windows ใช้ชื่อตัวเลือกเดียวกันเท่าที่ทำได้ เอกสารใช้ตัวพิมพ์เล็ก ส่วนชื่อพารามิเตอร์ PowerShell ไม่แยกตัวพิมพ์เล็กและใหญ่

| วัตถุประสงค์ | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| รุ่นเสถียรจาก main | ค่าเริ่มต้น ไม่ต้องระบุ | ค่าเริ่มต้น ไม่ต้องระบุ |
| Release รุ่นที่ระบุ | `-version 1.2.0` | `-version 1.2.0` |
| รุ่นพัฒนา | `-dev` | `-dev` |
| ไดเรกทอรีติดตั้งที่กำหนดเอง | `-o /path` (ระบุซ้ำได้บน Linux) | `-o D:\path` หรือ `-output D:\path` |
| ไฟล์ตั้งค่า qBittorrent ที่กำหนดเอง | — | `-qbconfig D:\path\qBittorrent.ini` |
| ตั้งค่า qBittorrent อัตโนมัติ | `-configure` | `-configure` |
| ย้อนกลับการติดตั้งครั้งก่อน | `-rollback` | `-rollback` |
| ถอนการติดตั้งทั้งหมด (ไม่เก็บข้อมูลสำรอง) | `-uninstall -purge` | `-uninstall -purge` |
| วิธีใช้ทั้งหมด | `-help` | `-help` |
| เลือกคอนเทนเนอร์ Docker | `--container=NAME` | — |
| แสดงรายการคอนเทนเนอร์ Docker | `--list-containers` | — |
| ระบุไดเรกทอรีโฮสต์ที่เมานต์เป็น Docker `/config` | `--config-root=/path` | — |

<details>
<summary><b>หมายเหตุ (คลิกเพื่อขยาย)</b></summary>

หมายเหตุ:

- ไม่ใส่ `-dev` หมายถึงรุ่นเสถียรจาก `main` ส่วน `-dev` เลือกรุ่นพัฒนาปัจจุบันตาม Git SHA ที่เจาะจง
- `-o` หมายถึง **output** ใช้เลือกไดเรกทอรีติดตั้ง WeiG qB WebUI บน Linux สามารถระบุซ้ำเพื่ออัปเดตหลายเป้าหมายด้วยการดาวน์โหลดที่ตรวจสอบแล้วเพียงครั้งเดียว
- สำรองจากตัวติดตั้งเก็บใต้ `~/.config/weig-qb-webui/backups/` โดย **แต่ละเป้าหมายเก็บสำรองล่าสุดสามชุดแยกจากกัน**
- `-configure` เปิด **Use alternative WebUI** ของ qBittorrent และกำหนด **Files location** หลังติดตั้ง โดยใช้กับเป้าหมายเดียวเท่านั้น
- `-rollback` คืนค่าสำรองล่าสุดของตัวติดตั้งสำหรับเป้าหมายที่เลือก หากต้องการย้อนกลับหลายเป้าหมายที่ระบุชัดเจน ให้ระบุ `-o` ซ้ำ
- `-version` ติดตั้ง GitHub Release รุ่นที่ระบุ เช่น `1.2.0` หากไม่พบรุ่นที่ระบุ การติดตั้งจะล้มเหลวและ **ไม่สลับไปใช้ latest หรือ dev โดยอัตโนมัติ**
- `-help` แสดงรูปแบบคำสั่ง Linux ที่รองรับในปัจจุบัน
- หากมีคอนเทนเนอร์ qBittorrent หลายตัว ให้ใช้ `--list-containers` แล้วเลือกด้วย `--container=NAME` หรือใช้ `--config-root=/path` หากทราบไดเรกทอรีตั้งค่า qBittorrent บนโฮสต์อยู่แล้ว

### รุ่นที่ระบุและไดเรกทอรีติดตั้ง

```sh

```

```powershell

```

```sh

```

```powershell

```

</details>

## ถอนการติดตั้งด้วยคำสั่งเดียว

<details>
<summary><b>ถอนการติดตั้งทั้งหมดสำหรับ Linux / NAS, Docker และ Windows PowerShell</b></summary>

คำสั่งที่แนะนำด้านล่างถอนการติดตั้งทั้งหมด **โดยไม่เก็บข้อมูลสำรองของตัวติดตั้ง** โดยลบ WebUI ปิดการใช้ Alternative WebUI ที่ตรงกับเป้าหมาย ลบสำรองและสถานะการย้อนกลับที่ตัวติดตั้งเป็นเจ้าของเฉพาะเป้าหมายนี้ จากนั้นลบสคริปต์ติดตั้งที่ดาวน์โหลดไว้จากไดเรกทอรีปัจจุบัน

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

หากใช้ไดเรกทอรีติดตั้งที่กำหนดเอง ให้เพิ่ม `-o /path/to/weig-qb-webui`

### Docker

คอนเทนเนอร์เดียว / ตรวจหาอัตโนมัติ:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

หลายคอนเทนเนอร์:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

เมื่อใช้ `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

หากใช้ไดเรกทอรีติดตั้งที่กำหนดเอง ให้เพิ่ม `-o D:\weig-qb-webui`

`-purge` ลบเฉพาะสำรองของเป้าหมายที่ถอนการติดตั้ง ไม่กระทบสำรองของการติดตั้งอื่น เมื่อไดเรกทอรีสถานะที่ใช้ร่วมกันว่างเปล่า ไดเรกทอรี Linux `~/.config/weig-qb-webui` (สำหรับ root: `/root/.config/weig-qb-webui`) หรือ Windows `%APPDATA%\weig-qb-webui` จะถูกลบด้วย

หากต้องการเก็บข้อมูลสำรองไว้ใช้กับ `-rollback` ในภายหลัง เพียงไม่ใส่ `-purge`

</details>
