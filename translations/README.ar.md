## التثبيت اليدوي للمبتدئين

<details>
<summary><b>هل تثبّتها للمرة الأولى؟ افتح الدليل السريع</b></summary>

### 1. فك ضغط الملف

نزّل `weig-qb-webui.zip` وفك ضغطه. ستحصل مباشرة على المجلد التالي:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**مجلد `weig-qb-webui` بكامله** هو المجلد الجذر لواجهة الويب. لا تنسخ `public` أو `private` وحدهما.

### 2. اختر مكاناً ثابتاً

انقل المجلد بأكمله إلى مكان لن يُحذف عن طريق الخطأ، مثل:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

هذا هو المسار الذي ستحدّده لاحقاً في إعدادات qBittorrent.

### 3. فعّل واجهة الويب البديلة

افتح qBittorrent وانتقل إلى **الأدوات ← الخيارات ← واجهة الويب**. قد تختلف أسماء الخيارات المعروضة حسب اللغة المختارة في qBittorrent.

1. فعّل **استخدام واجهة ويب بديلة** (*Use alternative WebUI*).
2. ابحث عن حقل **موقع الملفات** (*Files location*).
3. أدخل مسار مجلد `weig-qb-webui` فيه.

مثال على Windows:

```text
D:\weig-qb-webui
```

مثال على Linux:

```text
/opt/weig-qb-webui
```

4. اضغط **موافق** لحفظ الإعدادات.
5. أعد تحميل صفحة واجهة الويب. إذا ظهرت الواجهة القديمة، اضغط `Ctrl + F5` لفرض تحديث الصفحة.

> **كيف تتأكد من صحة المسار؟** يجب أن ترى `public` و`private` و`VERSION` مباشرة داخل المجلد الذي اخترته. إذا احتجت إلى فتح مجلد `weig-qb-webui` آخر للوصول إليها، فقد اخترت مستوى غير صحيح.

> **مهم لمستخدمي Docker:** يعمل qBittorrent داخل حاوية، لذا يجب أن يكون المسار مرئياً **من داخل الحاوية**، وليس مجرد مسار على الجهاز المضيف. اقرأ توضيح Docker أدناه.

</details>

## التثبيت بأمر واحد

يُنزّل برنامج التثبيت لـ Linux وNAS من رابط Dev Pages الثابت أدناه. **عنوان تنزيل البرنامج لا يحدد قناة التثبيت:** من دون `-dev` يُثبَّت أحدث إصدار مستقر من GitHub Release بعد التحقق منه؛ ومع `-dev` يُثبَّت إصدار التطوير المحدد ببصمة Git SHA دقيقة. سيبقى ملف البرنامج في المجلد الحالي لتسهيل التحديث أو التراجع لاحقاً.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>اعرض مكان حفظ البرنامج ومجلد التثبيت الافتراضي</b></summary>

ملف التثبيت الذي نُزّل:

```text
./install.sh
```

مجلد واجهة الويب الافتراضي:

```text
~/.local/share/weig-qb-webui
```

إذا نفّذت الأمر بحساب `root`، فسيكون عادةً:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>التثبيت عبر Docker، والحاويات المتعددة، وشرح المسارات</b></summary>

#### ما الفرق بين الجهاز المضيف والحاوية؟

إذا كنت تستخدم Docker على خادم VPS أو Linux أو جهاز Synology أو QNAP أو NAS آخر:

- **الجهاز المضيف:** نظام Linux أو NAS الذي يشغّل Docker، وهو عادةً النظام الذي تدخل إليه عبر SSH.
- **الحاوية:** بيئة منفصلة يعمل بداخلها qBittorrent. ولا يمكنه الوصول إلا إلى المسارات المتاحة للحاوية.

على سبيل المثال، قد تكون مجلدات Docker مربوطة على النحو التالي:

```text
المضيف: /root/qbittorrent/config
   ↓ مربوط بـ
داخل الحاوية: /config
```

وفي Docker Compose تُكتب عادةً بهذا الشكل:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

المسار **قبل النقطتين** موجود على الجهاز المضيف، والمسار **بعدهما** هو الذي تراه الحاوية.

إذا ثبّتَّ WeiG على الجهاز المضيف في:

```text
المضيف: /root/qbittorrent/config/weig-qb-webui
```

فيجب ضبط حقل **Files location** داخل qBittorrent على:

```text
/config/weig-qb-webui
```

**لا تكتب `/root/qbittorrent/config/weig-qb-webui` في هذا الحقل**، لأن الحاوية لا ترى عادةً هذا المسار الموجود على الجهاز المضيف.

#### الحالة الأولى: لديك حاوية qBittorrent واحدة

شغّل الأمر:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

سيحاول برنامج التثبيت تحديد حاوية qBittorrent العاملة وربط `/config` ومكان التثبيت الصحيح على الجهاز المضيف. وإذا استطاع التحقق من الإعدادات، فسيضبط qBittorrent تلقائياً.

#### الحالة الثانية: لا تعرف اسم الحاوية

لعرض الحاويات المتاحة:

```sh
sh install.sh --list-containers
```

أو استخدم Docker مباشرة:

```sh
docker ps
```

إذا كان اسم الحاوية، مثلاً:

```text
qbittorrent
```

فحدّدها صراحةً:

```sh
sh install.sh --container=qbittorrent -configure
```

#### الحالة الثالثة: لديك أكثر من حاوية qBittorrent

قد تكون لديك حاوية للاستخدام اليومي وأخرى للاختبار:

```text
qbittorrent
qbittorrent-test
```

ابدأ بعرض القائمة:

```sh
sh install.sh --list-containers
```

لتثبيت الواجهة للحاوية الرئيسية:

```sh
sh install.sh --container=qbittorrent -configure
```

ولتثبيتها لحاوية الاختبار:

```sh
sh install.sh --container=qbittorrent-test -configure
```

**لن يختار برنامج التثبيت حاوية عشوائياً** إذا عثر على أكثر من حاوية مطابقة.

#### الحالة الرابعة: تعرف مجلد `/config` على الجهاز المضيف

مثلاً:

```text
/root/qbittorrent/config
```

يمكنك تحديد المجلد مباشرةً:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

قد يكون المسار على Synology هكذا:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

وعلى جهاز NAS آخر:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

هذه مسارات توضيحية فقط؛ استخدم المسار الحقيقي لمجلد إعدادات qBittorrent على جهازك.

#### الحالة الخامسة: حدّد مجلد واجهة الويب

بعد تحديد الحاوية، يمكنك أيضاً اختيار مسار تثبيت الواجهة داخلها:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

سيحوّل برنامج التثبيت هذا المسار إلى الموقع المقابل على الجهاز المضيف بالاعتماد على ربط Docker لمجلد `/config`.

#### الحالة السادسة: تحديث عدة نسخ في دفعة واحدة

إذا كنت تدير عدة مثيلات، يمكنك تكرار الخيار `-o`. سيُنزّل ملف التثبيت ويُتحقق منه مرة واحدة، ولن يبدأ استبدال أي تثبيت حتى تكتمل تهيئة جميع الوجهات. يحتفظ البرنامج بآخر **ثلاث نسخ احتياطية لكل وجهة** بصورة مستقلة في `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

لا تُضف `-configure` في وضع الوجهات المتعددة، بل اترك لكل مثيل مسار واجهة الويب البديلة الذي سبق ضبطه. لعرض الخيارات كلها شغّل `sh install.sh -help`.

#### التحقق من المسارات بعد التثبيت

قد يعرض التثبيت الناجح ناتجاً مشابهاً لما يلي:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: الموقع الفعلي للملفات على الجهاز المضيف.
- `qBittorrent Root Folder`: المسار **داخل الحاوية** الذي يجب إدخاله في حقل *Files location* في qBittorrent.

عند استخدام `-configure`، سيفعّل البرنامج واجهة الويب البديلة ويضبط مسارها إذا تعرّف على إعدادات qBittorrent بصورة مؤكدة. وإلا فاتبع خطوات التثبيت اليدوي أعلاه.

</details>

## الخيارات الشائعة

تُستخدم أسماء الخيارات الأساسية نفسها على Linux وWindows. ولا يميّز PowerShell بين الأحرف الكبيرة والصغيرة في أسماء الخيارات.

| الغرض | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| أحدث إصدار مستقر (`main`) | الخيار الافتراضي، دون معاملات | الخيار الافتراضي، دون معاملات |
| تثبيت إصدار مستقر محدد | `-version 1.2.0` | `-version 1.2.0` |
| تثبيت إصدار التطوير | `-dev` | `-dev` |
| تحديد مجلد التثبيت | `-o /path` (قابل للتكرار على Linux) | `-o D:\path` أو `-output D:\path` |
| تحديد ملف إعدادات qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| ضبط qBittorrent تلقائياً | `-configure` | `-configure` |
| استعادة التثبيت السابق | `-rollback` | `-rollback` |
| إزالة الواجهة والنسخ الاحتياطية | `-uninstall -purge` | `-uninstall -purge` |
| عرض التعليمات | `-help` | `-help` |
| تحديد حاوية Docker | `--container=NAME` | — |
| عرض حاويات Docker | `--list-containers` | — |
| تحديد مجلد `/config` على المضيف | `--config-root=/path` | — |

<details>
<summary><b>تفاصيل الخيارات (انقر للعرض)</b></summary>

- من دون `-dev` يُستخدم مسار الإصدارات المستقرة `main`. ومع `-dev` يُستخدم إصدار التطوير المحدد ببصمة Git SHA دقيقة.
- تشير `o` في `-o` إلى **output**. ويمكن تكرار هذا الخيار على Linux لتحديث عدة تثبيتات موجودة بعد تنزيل واحد.
- تُخزّن النسخ الاحتياطية التي يديرها البرنامج في `~/.config/weig-qb-webui/backups/`، مع الاحتفاظ **بثلاث نسخ حديثة لكل وجهة** كحد أقصى.
- يفعّل `-configure` واجهة *Use alternative WebUI* ويضبط *Files location*، لكنه متاح لوجهة واحدة فقط.
- يعيد `-rollback` أحدث نسخة احتياطية أنشأها البرنامج للوجهة المحددة، ويمكن تكرار `-o` لاستعادة عدة وجهات محددة.
- يحذف `-uninstall -purge` النسخ الاحتياطية وحالة الاستعادة التابعة **للوجهة الحالية فقط**، ولا يمس مثيلات أخرى.
- للاحتفاظ بالنسخ الاحتياطية واستعمال `-rollback` لاحقاً، احذف `-purge` من الأمر.
- يثبّت `-version` إصدار GitHub Release محدداً، مثل `1.2.0`. وإذا لم يكن موجوداً، يفشل التثبيت **ولا يتحول تلقائياً** إلى latest أو dev.
- مع عدة حاويات، اعرض القائمة باستخدام `--list-containers` ثم اختر حاوية بعينها عبر `--container=NAME`، أو حدّد مجلد `/config` على المضيف باستخدام `--config-root=/path`.

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### استعادة التثبيت السابق

على Linux:

```sh
sh install.sh -rollback
```

على Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## إزالة الواجهة بأمر واحد

<details>
<summary><b>الإزالة الكاملة على Linux وNAS وDocker وWindows PowerShell</b></summary>

نوصي عادةً **بإزالة الواجهة دون الاحتفاظ بنسخ برنامج التثبيت الاحتياطية**. سيزيل الأمر الواجهة، ويعطّل واجهة الويب البديلة للوجهة المحددة، ويحذف النسخ الاحتياطية وحالة الاستعادة التابعة لها، ثم يمسح ملف برنامج التثبيت من المجلد الحالي.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

لتحديد مجلد مخصص أضف `-o /path/to/weig-qb-webui`.

### Docker

حاوية واحدة مع الكشف التلقائي:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

إذا كانت لديك عدة حاويات:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

إذا كنت تستخدم `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

لإزالة تثبيت من مجلد مخصص أضف `-o D:\weig-qb-webui`.

يحذف `-purge` فقط النسخ الاحتياطية الخاصة بالتثبيت الذي تزيله، ولا يؤثر على نسخ المثيلات الأخرى. وإذا أصبح مجلد الحالة المشترك فارغاً، فسيُحذف أيضاً `~/.config/weig-qb-webui` على Linux (أو `/root/.config/weig-qb-webui` عند التشغيل بحساب `root`)، أو `%APPDATA%\weig-qb-webui` على Windows.

إذا أردت الاحتفاظ بالنسخ الاحتياطية للعودة إليها باستخدام `-rollback`، شغّل أمر الإزالة دون `-purge`.

</details>
