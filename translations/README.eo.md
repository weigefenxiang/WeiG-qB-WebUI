## Flanka breto por pluraj ekzempleroj

Pluraj sendependaj qBittorrent-ekzempleroj povas uzi la saman pretigitan dosierujon WeiG **nurlege**. Muntu la gastigantan dosierujon en ĉiu Docker-ujo, ekzemple `/root/weig-qb-webui:/weig-qb-webui:ro`, kaj agordu `/weig-qb-webui` kiel la radikon de Alternative WebUI en ĉiu qBittorrent. Ĉiu ekzemplero konservas apartajn torrentojn, agordojn kaj ensaluton.

En la sekcio **Instances** de la flanka breto eblas registri ekzemplerojn, ŝanĝi inter ili per plena paĝa navigado kaj alinomi ilin (per dekstra musbutono aŭ la vica menuo). La nuna ekzemplero estas identigita per la reala URL, ne per konservita sufikso. La intervalon de aŭtomata kontrolo oni agordas ĉe **Settings → WeiG WebUI → Interface**; defaŭlte ĝi estas `30 min`, kaj oni povas malŝalti ĝin aŭ elekti inter 5 kaj 1440 minutoj.

**La pruvoj pri la stato estas intence singardaj:** kontrolita WebAPI el la sama origino montras, ke qB estas enreta. Transorigina `no-cors`-respondo sen ensalutiloj pruvas nur, ke la HTTP-adreso estas atingebla, eĉ kiam ĝi liveras 403/404. Ne okazas transorigina legado de Cookie/SID, transdono de pasvortoj aŭ seancoj, preteriro de CORS aŭ servila peranto. Dato konservita post antaŭa sukcesa kontrolo estas **historia pruvo**, ne certigo pri nuna enreta stato. La adreso `127.0.0.1` en retumilo rilatas al la aparato, kiu rulas la retumilon, ne al fora VPS.

## Instalado por komencantoj

<details>
<summary><b>Ĉu vi instalas unuafoje? Malfermu ĉi tiun mallongan gvidilon</b></summary>

### 1. Elpaku la ZIP-arkivon

Elŝutu `weig-qb-webui.zip` kaj elpaku ĝin. La arkivo jam enhavas la norman dosierujon:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

La tuta dosierujo **`weig-qb-webui`** estas la radiko de WebUI. Ne kopiu nur `public` aŭ `private`.

### 2. Movu ĝin al konstanta loko

Ekzemple:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Tiun vojon vi poste devos enigi en qBittorrent.

### 3. Ebligu ĝin en qBittorrent

Malfermu qBittorrent:

**Tools → Options... → WebUI**

Jen la precizaj nomoj en la aktuala angla interfaco de qBittorrent. Poste:

1. Ebligu **Use alternative WebUI**.
2. Trovu la kampon **Files location:**.
3. Enigu la vojon al la dosierujo `weig-qb-webui`.

Ekzemplo por Windows:

```text
D:\weig-qb-webui
```

Ekzemplo por Linux:

```text
/opt/weig-qb-webui
```

4. Alklaku **OK** por konservi.
5. Reŝargu la paĝon de qBittorrent WebUI. Se la malnova versio restas en la kaŝmemoro, provu unufoje `Ctrl + F5`.

> **Kontrolo de la vojo:** la indikita dosierujo devas rekte enhavi `public`, `private`, `VERSION` kaj la aliajn dosierojn.

> **Por Docker-uzantoj:** qBittorrent ruliĝas en ujo, do vi ordinare devas indiki la vojon videblan interne de la ujo, ne la vojon de la gastiganto.

</details>

## Instalado per unu komando

La instalila skripto por Linux/NAS ĉiam estas elŝutata de la fiksa adreso Dev Pages ĉi-sube. **La adreso de la skripto ne elektas instalan kanalon:** sen `-dev` ĝi instalas la plej novan kontrolitan stabilan GitHub Release; `-dev` elektas la nunan evoluigan version laŭ ĝia preciza Git SHA. La elŝutita skripto restas en la aktuala dosierujo por estontaj ĝisdatigoj aŭ restaŭroj.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Montri la skriptan adreson kaj la defaŭltan instalan dosierujon</b></summary>

```text
./install.sh
```

Defaŭlte WebUI instaliĝas en:

```text
~/.local/share/weig-qb-webui
```

Kiam vi rulas kiel `root`, kutime en:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker, pluraj ujoj kaj klarigo pri vojoj</b></summary>

#### Gastiganto kaj ujo

- **Gastiganto:** la Linux/NAS-maŝino, kie ruliĝas Docker.
- **Ujo:** la izolita medio, en kiu ruliĝas qBittorrent.

Ekzemple:

```text
Хост:       /root/qbittorrent/config
   ↓ muntita kiel
Ujo:  /config
```

Ekzemplo de Docker Compose:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Se WebUI troviĝas ĉe ĉi tiu gastiganta vojo:

```text
/root/qbittorrent/config/weig-qb-webui
```

en la kampo **Files location:** de qBittorrent indiku:

```text
/config/weig-qb-webui
```

#### Unu qBittorrent-ujo

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

La instalilo provos aŭtomate trovi la ujon kaj ĝian muntitan dosierujon `/config`.

#### Trovi la ujojn

Unue montru la liston de detektitaj qBittorrent-ujoj:

```sh
sh install.sh --list-containers
```

Aŭ uzu Docker rekte:

```sh
docker ps
```

Ekzemple la ujo povas nomiĝi:

```text
qbittorrent
```

Tiam elektu ĝin eksplicite:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Se ruliĝas pluraj qBittorrent-ujoj

Ekzemple, ĉefa kaj testa ekzempleroj:

```text
qbittorrent
qbittorrent-test
```

Unue listigu ilin:

```sh
sh install.sh --list-containers
```

Por la ĉefa ekzemplero:

```sh
sh install.sh --container=qbittorrent -configure
```

Por la testa ekzemplero:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Se ekzistas pluraj ujoj, la instalilo ne elektos unu el ili arbitre.

#### Indiki la gastigantan dosierujon muntitan kiel `/config`

Se la agorda dosierujo de qBittorrent ĉe la gastiganto troviĝas ĉi tie:

```text
/root/qbittorrent/config
```

Vi povas eksplicite indiki ĝin:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Ekzemplo por Synology:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Ekzemplo por alia NAS:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Anstataŭigu la ekzemplajn vojojn per la vera gastiganta vojo muntita kiel `/config` en qBittorrent.

#### Elekti la WebUI-dosierujon

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

#### Ĝisdatigi plurajn WebUI-instalojn per unu elŝuto

En Linux/NAS vi povas ripeti la parametron `-o` kaj ĝisdatigi plurajn jam ekzistantajn instalojn post unu elŝuto. En tiu reĝimo ne uzu samtempe `-configure`, `--container` kaj `--config-root`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

#### Kontroli la vojojn post instalado

La instalilo montras la vojon ĉe la gastiganto kaj la vojon videblan al qBittorrent:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

En qBittorrent **Files location** uzu la duan vojon — tiun ene de la ujo. Se `-configure` sukcesas, la instalilo agordas ĝin aŭtomate.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

<details>
<summary><b>Montri la instalan dosierujon</b></summary>

```text
C:\Users\<uzantnomo>\AppData\Local\weig-qb-webui
```

</details>

## Oftaj parametroj
En PowerShell la uskleco de parametronomoj ne gravas.

| Celo | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Plej nova stabila eldono | Defaŭlte | Defaŭlte |
| Preciza Release | `-version 1.2.0` | `-version 1.2.0` |
| Evoluiga versio | `-dev` | `-dev` |
| Instala dosierujo | `-o /path` (ripetebla) | `-o D:\path` aŭ `-output D:\path` |
| Agorda dosiero de qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Aŭtomate agordi qBittorrent | `-configure` | `-configure` |
| Reiri al antaŭa instalo | `-rollback` | `-rollback` |
| Plena malinstalo (sen sekurkopioj) | `-uninstall -purge` | `-uninstall -purge` |
| Plena helpo | `-help` | `-help` |
| Elekti Docker-ujon | `--container=NAME` | — |
| Listigi Docker-ujojn | `--list-containers` | — |
| Gastiganta dosierujo muntita kiel Docker `/config` | `--config-root=/path` | — |

<details>
<summary><b>Notoj (alklaku por malfermi)</b></summary>

- Se la petita versio ne ekzistas, la instalilo ne aŭtomate transiras al latest aŭ dev.
- `-dev` ne uzeblas kune kun `-version`.

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

Restaŭro:

```sh

```

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Malinstalo per unu komando

<details>
<summary><b>Plena malinstalo por Linux / NAS, Docker kaj Windows PowerShell</b></summary>

La rekomendata proceduro faras **plenan malinstalon sen konservi sekurkopiojn de la instalilo**: ĝi forigas WebUI, malebligas la respondan alternativan WebUI-agordon, purigas la sekurkopiojn kaj la staton de restaŭro por tiu celo, kaj poste forigas la elŝutitan instalan skripton el la aktuala dosierujo.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Por propra instala dosierujo, aldonu `-o /path/to/weig-qb-webui`.

### Docker

Unu ujo / aŭtomata detekto:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Pluraj ujoj:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Kun `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Por propra instala dosierujo, aldonu `-o D:\weig-qb-webui`.

`-purge` forigas nur la sekurkopiojn de la nuna celo kaj ne tuŝas aliajn instalojn. Se la komuna statdosierujo malpleniĝas, ankaŭ la Linux-dosierujo `~/.config/weig-qb-webui` (por root: `/root/.config/weig-qb-webui`) aŭ la Windows-dosierujo `%APPDATA%\weig-qb-webui` estas forigita.

Por konservi sekurkopiojn por posta `-rollback`, simple ne uzu `-purge`.

</details>
