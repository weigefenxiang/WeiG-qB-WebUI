## Yeni başlayanlar için elle kurulum

<details>
<summary><b>İlk kez mi kuruyorsunuz? Bir dakikalık hızlı kılavuzu açın</b></summary>

### 1. ZIP dosyasını çıkarın

`weig-qb-webui.zip` dosyasını indirip açın. İçinden doğrudan şu klasör yapısı çıkar:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**`weig-qb-webui` klasörünün tamamı** WebUI kök dizinidir. Yalnızca `public` veya `private` klasörlerini kopyalamayın.

### 2. Kalıcı bir klasöre taşıyın

Klasörün tamamını yanlışlıkla silinmeyecek sabit bir konuma taşıyın. Örneğin:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

qBittorrent ayarlarında seçeceğiniz dizin burasıdır.

### 3. qBittorrent içinde alternatif WebUI'yi etkinleştirin

qBittorrent'i açıp **Araçlar → Seçenekler → Web Arayüzü** bölümüne gidin. Menü adları, qBittorrent'te seçili dile göre değişebilir.

1. **Alternatif Web arayüzünü kullan** (*Use alternative WebUI*) seçeneğini işaretleyin.
2. **Dosyaların konumu** (*Files location*) alanını bulun.
3. `weig-qb-webui` klasörünün yolunu girin.

Windows örneği:

```text
D:\weig-qb-webui
```

Linux örneği:

```text
/opt/weig-qb-webui
```

4. Ayarları kaydetmek için **Tamam**'a basın.
5. qBittorrent WebUI sayfasını yenileyin. Eski arayüz görünüyorsa tarayıcı önbelleğini atlamak için `Ctrl + F5` tuşlarına basın.

> **Yolun doğru olduğunu nasıl anlarsınız?** Seçtiğiniz dizinin içinde `public`, `private` ve `VERSION` öğelerini doğrudan görmelisiniz. Bunlara ulaşmak için ikinci bir `weig-qb-webui` klasörüne girmeniz gerekiyorsa bir üst düzeyi seçmelisiniz.

> **Docker kullanıyorsanız:** qBittorrent bir kapsayıcıda çalışır. Bu yüzden bilgisayarın ana sistemindeki yolu değil, **kapsayıcının içinden erişilebilen yolu** girmelisiniz. Docker bölümü aşağıda açıklanmıştır.

</details>

## Tek komutla kurulum

Linux ve NAS kurulum betiği aşağıdaki sabit Dev Pages adresinden indirilir. **Betiğin indirildiği URL, kurulacak sürümü belirlemez:** `-dev` kullanılmazsa doğrulanmış en güncel kararlı GitHub Release kurulur; `-dev` kullanılırsa tam Git SHA ile tanımlanan geliştirme sürümü yüklenir. Betik, daha sonra güncelleme ve geri alma işlemlerinde kullanılabilmesi için geçerli dizinde saklanır.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Betiğin ve varsayılan kurulum klasörünün konumunu göster</b></summary>

İndirilen betik:

```text
./install.sh
```

WebUI için varsayılan kurulum dizini:

```text
~/.local/share/weig-qb-webui
```

Komutu `root` kullanıcısı olarak çalıştırırsanız genellikle:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker kurulumu, birden fazla kapsayıcı ve dizin yolları</b></summary>

#### Ana sistem (host) ile kapsayıcı arasındaki fark

Docker'ı bir VPS, Linux sunucusu, Synology, QNAP veya başka bir NAS üzerinde çalıştırıyorsanız:

- **Ana sistem (host):** Docker'ın gerçekten çalıştığı Linux veya NAS sistemi; genellikle SSH ile bağlandığınız makine.
- **Kapsayıcı (container):** qBittorrent'in çalıştığı yalıtılmış ortam; yalnızca kapsayıcıya bağlanan dizinleri görebilir.

Örneğin qBittorrent yapılandırma klasörü şöyle eşlenmiş olsun:

```text
Ana makine: /root/qbittorrent/config
   ↓ şuraya bağlanır
Kapsayıcıda: /config
```

Docker Compose içinde genellikle şu şekilde görünür:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

İki noktanın **solundaki** dizin ana sisteme, **sağındaki** yol ise kapsayıcının içindeki konuma aittir.

WeiG ana sisteme şu konumda kuruluysa:

```text
Ana makine: /root/qbittorrent/config/weig-qb-webui
```

qBittorrent'in **Files location** alanına şu yolu yazmalısınız:

```text
/config/weig-qb-webui
```

**`/root/qbittorrent/config/weig-qb-webui` yolunu girmeyin.** Bu ana sisteme ait yoldur ve kapsayıcı genellikle burayı doğrudan göremez.

#### Durum 1: Yalnızca bir qBittorrent kapsayıcısı var

Şu komutu çalıştırın:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Kurucu, çalışan qBittorrent kapsayıcısını ve `/config` bağını bulmaya çalışır. Uygun ana sistem dizinini belirler; yapılandırmayı güvenle tespit edebilirse qBittorrent ayarlarını da otomatik olarak yapar.

#### Durum 2: Kapsayıcıların adını bilmiyorsunuz

Mevcut kapsayıcıları listeleyin:

```sh
sh install.sh --list-containers
```

Docker ile doğrudan da bakabilirsiniz:

```sh
docker ps
```

Kapsayıcının adı örneğin şöyleyse:

```text
qbittorrent
```

onu açıkça seçin:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Durum 3: Birden fazla qBittorrent kapsayıcısı var

Örneğin biri günlük kullanım, diğeri test için olsun:

```text
qbittorrent
qbittorrent-test
```

Önce listeyi kontrol edin:

```sh
sh install.sh --list-containers
```

Ana kapsayıcıya kurmak için:

```sh
sh install.sh --container=qbittorrent -configure
```

Test kapsayıcısına kurmak için:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Birden fazla eşleşme varsa kurucu **rastgele bir kapsayıcı seçmez**.

#### Durum 4: Ana sistemdeki `/config` klasörünü biliyorsunuz

Örneğin yapılandırma dizini:

```text
/root/qbittorrent/config
```

Klasörü doğrudan belirtebilirsiniz:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Synology NAS üzerinde şöyle olabilir:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Başka bir NAS üzerinde ise örneğin:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Bunlar yalnızca örnek yollardır. Kendi sisteminizdeki gerçek qBittorrent `/config` dizinini kullanın.

#### Durum 5: WebUI'nin kurulacağı dizini seçmek

Kapsayıcıyı seçtiyseniz WebUI'nin kapsayıcı içindeki konumunu da belirleyebilirsiniz:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Kurucu, Docker'ın `/config` eşlemesini kullanarak bunu ana sistemdeki karşılık gelen yola dönüştürür.

#### Durum 6: Birden fazla kurulumu tek seferde güncellemek

Birden fazla qBittorrent örneğini yönetiyorsanız `-o` seçeneğini tekrar edebilirsiniz. Paket yalnızca bir kez indirilip doğrulanır; tüm hedefler hazırlanmadan hiçbirine geçiş yapılmaz. Her hedef, `~/.config/weig-qb-webui/backups/` altında ayrı ayrı **son üç yedeğini** tutar.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Birden fazla hedef belirtildiğinde `-configure` eklemeyin. Her qBittorrent örneği önceden yapılandırılmış alternatif WebUI yolunu kullanmaya devam eder. Tüm seçenekleri görmek için `sh install.sh -help` komutunu çalıştırın.

#### Kurulumdan sonra yolları kontrol etmek

Başarılı bir kurulumda aşağıdakine benzer bir çıktı görebilirsiniz:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: dosyaların ana sistemde kaydedildiği gerçek konum.
- `qBittorrent Root Folder`: qBittorrent'in *Files location* alanına girmeniz gereken **kapsayıcı içindeki yol**.

`-configure` kullanıldığında kurucu, qBittorrent yapılandırmasını güvenle bulabilirse alternatif WebUI'yi etkinleştirip doğru dizini ayarlar. Bulamazsa yukarıdaki elle kurulum adımlarını izleyin.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

## Sık kullanılan parametreler

Linux ve Windows'ta ortak parametre adları aynıdır. PowerShell parametre adlarında büyük/küçük harf ayrımı yapmaz.

| Amaç | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| En güncel kararlı sürüm (`main`) | Varsayılan, parametre gerekmez | Varsayılan, parametre gerekmez |
| Belirli bir kararlı sürüm | `-version 1.2.0` | `-version 1.2.0` |
| Geliştirme sürümü | `-dev` | `-dev` |
| Kurulum dizini | `-o /path` (Linux'ta tekrarlanabilir) | `-o D:\path` veya `-output D:\path` |
| Özel qBittorrent yapılandırma dosyası | — | `-qbconfig D:\path\qBittorrent.ini` |
| qBittorrent'i otomatik yapılandır | `-configure` | `-configure` |
| Önceki kuruluma geri dön | `-rollback` | `-rollback` |
| Yedeklerle birlikte tamamen kaldır | `-uninstall -purge` | `-uninstall -purge` |
| Tüm yardımı göster | `-help` | `-help` |
| Docker kapsayıcısı seç | `--container=NAME` | — |
| Docker kapsayıcılarını listele | `--list-containers` | — |
| Ana sistemdeki `/config` dizini | `--config-root=/path` | — |

<details>
<summary><b>Parametre açıklamaları (genişlet)</b></summary>

- `-dev` kullanılmazsa kararlı `main` kanalı, kullanılırsa tam Git SHA ile tanımlanan geliştirme sürümü seçilir.
- `-o` içindeki `o`, **output** anlamına gelir. Linux'ta bu seçeneği tekrarlayarak tek indirmeyle birden fazla kurulu dizini güncelleyebilirsiniz.
- Kurucunun yönettiği yedekler `~/.config/weig-qb-webui/backups/` içinde saklanır; **her hedef için en fazla üç son yedek** korunur.
- `-configure`, *Use alternative WebUI* seçeneğini etkinleştirir ve *Files location* yolunu ayarlar; ancak tek hedef için kullanılabilir.
- `-rollback`, seçili hedef için kurucu tarafından oluşturulan en son yedeğe döner. Birden fazla açıkça belirlenmiş hedefi geri almak için `-o` tekrarlanabilir.
- `-uninstall -purge`, **yalnızca seçili kurulumun** yedeklerini ve geri alma durumunu siler; diğer kurulumları etkilemez.
- Yedekleri gelecekte `-rollback` ile kullanmak istiyorsanız `-purge` seçeneğini çıkartın.
- `-version` ile örneğin `1.2.0` gibi belirli bir GitHub Release yüklenir. Bu sürüm yoksa kurulum hata verir; **otomatik olarak latest veya dev'e geçmez**.
- Birden fazla kapsayıcı varsa `--list-containers` ile listeleyip `--container=NAME` ile belirli birini seçin ya da `--config-root=/path` ile ana sistemdeki `/config` dizinini belirtin.

### Belirli bir sürüm ve kurulum klasörü

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Geri alma

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Tek komutla kaldırma

<details>
<summary><b>Linux / NAS, Docker ve Windows PowerShell'de tamamen kaldırma</b></summary>

Genellikle **kurucu yedeklerini saklamadan kaldırmanızı** öneririz. Böylece WebUI kaldırılır, seçilen hedefin alternatif Web arayüzü kapatılır, o hedefe ait yedekler ve geri alma durumu temizlenir, ardından geçerli dizine indirilen kurulum betiği silinir.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Özel bir dizin kullanıyorsanız `-o /yol/weig-qb-webui` ekleyin.

### Docker

Otomatik algılanan tek kapsayıcı:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Birden fazla kapsayıcı:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

`--config-root` kullanıyorsanız:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Özel bir klasör için `-o D:\weig-qb-webui` ekleyin.

`-purge` yalnızca kaldırılan hedefin yedeklerini siler, diğer qBittorrent kurulumlarının yedeklerine dokunmaz. Paylaşılan durum dizini boş kalırsa Linux'ta `~/.config/weig-qb-webui` (`root` için `/root/.config/weig-qb-webui`) veya Windows'ta `%APPDATA%\weig-qb-webui` de temizlenir.

Yedekleri daha sonra `-rollback` için saklamak istiyorsanız kaldırma işlemini `-purge` olmadan çalıştırın.

</details>
