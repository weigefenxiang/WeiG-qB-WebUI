## نصب دستی برای کاربران تازه‌کار

<details>
<summary><b>اولین بار است که نصب می‌کنید؟ راهنمای یک‌دقیقه‌ای را باز کنید</b></summary>

### ۱. فایل ZIP را استخراج کنید

فایل `weig-qb-webui.zip` را دریافت و از حالت فشرده خارج کنید. ساختار پوشه‌ها از قبل به این صورت است:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**تمام پوشهٔ `weig-qb-webui`** ریشهٔ رابط وب است. فقط `public` یا `private` را به‌تنهایی کپی نکنید.

### ۲. یک محل دائمی انتخاب کنید

کل پوشه را به محلی منتقل کنید که تصادفی حذف نشود، برای مثال:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

بعداً همین پوشه را در تنظیمات qBittorrent مشخص خواهید کرد.

### ۳. رابط وب جایگزین را در qBittorrent فعال کنید

در qBittorrent به **ابزارها ← گزینه‌ها ← رابط وب** بروید. نام گزینه‌ها ممکن است با توجه به زبان برنامه کمی متفاوت باشد.

1. گزینهٔ **استفاده از رابط وب جایگزین** (*Use alternative WebUI*) را فعال کنید.
2. فیلد **محل فایل‌ها** (*Files location*) را پیدا کنید.
3. مسیر پوشهٔ `weig-qb-webui` را وارد کنید.

نمونهٔ Windows:

```text
D:\weig-qb-webui
```

نمونهٔ Linux:

```text
/opt/weig-qb-webui
```

4. برای ذخیره، روی **تأیید** کلیک کنید.
5. صفحهٔ وب qBittorrent را دوباره بارگذاری کنید. اگر هنوز رابط قبلی را می‌بینید، `Ctrl + F5` را بزنید تا کش مرورگر نادیده گرفته شود.

> **چطور از درستی مسیر مطمئن شویم؟** فایل `VERSION` و پوشه‌های `public` و `private` باید مستقیماً داخل پوشهٔ انتخاب‌شده دیده شوند. اگر لازم است یک پوشهٔ `weig-qb-webui` دیگر باز کنید، یک سطح اشتباه را انتخاب کرده‌اید.

> **اگر از Docker استفاده می‌کنید:** qBittorrent **داخل کانتینر** اجرا می‌شود. مسیری را وارد کنید که داخل کانتینر قابل دسترسی باشد، نه مسیری که فقط در میزبان وجود دارد. توضیحات بیشتر در بخش Docker آمده است.

</details>

## نصب با یک فرمان

اسکریپت نصب Linux و NAS همیشه از نشانی ثابت Dev Pages که در ادامه آمده دریافت می‌شود. **نشانی دانلود اسکریپت تعیین‌کنندهٔ کانال نصب نیست:** بدون `-dev` جدیدترین GitHub Release پایدار و بررسی‌شده نصب می‌شود؛ با `-dev` نسخهٔ توسعه با Git SHA دقیق نصب خواهد شد. اسکریپت در پوشهٔ جاری باقی می‌ماند تا بعداً برای به‌روزرسانی یا بازگردانی استفاده شود.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>مسیر اسکریپت و پوشهٔ پیش‌فرض نصب را ببینید</b></summary>

اسکریپت دریافت‌شده در:

```text
./install.sh
```

پوشهٔ پیش‌فرض رابط وب:

```text
~/.local/share/weig-qb-webui
```

اگر با کاربر `root` اجرا کنید، معمولاً مسیر این است:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>نصب با Docker، چند کانتینر و انتخاب درست مسیرها</b></summary>

#### تفاوت میزبان و کانتینر چیست؟

اگر Docker را روی VPS، سرور Linux، دستگاه Synology، QNAP یا NAS دیگری اجرا می‌کنید:

- **میزبان (host):** سیستم Linux یا NAS که Docker روی آن اجرا می‌شود و معمولاً از طریق SSH به آن متصل می‌شوید.
- **کانتینر (container):** محیط جداگانه‌ای که qBittorrent در آن اجرا می‌شود و فقط پوشه‌های متصل‌شده به خودش را می‌بیند.

فرض کنید پوشهٔ پیکربندی این‌گونه متصل شده است:

```text
میزبان: /root/qbittorrent/config
   ↓ متصل به
در کانتینر: /config
```

در Docker Compose معمولاً به این شکل نوشته می‌شود:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

مسیر **سمت چپ دونقطه** متعلق به **میزبان** است و مسیر **سمت راست** داخل **کانتینر** دیده می‌شود.

اگر WeiG روی میزبان در این مسیر نصب شده باشد:

```text
میزبان: /root/qbittorrent/config/weig-qb-webui
```

باید در فیلد **Files location** برنامهٔ qBittorrent این مسیر را وارد کنید:

```text
/config/weig-qb-webui
```

**مسیر `/root/qbittorrent/config/weig-qb-webui` را وارد نکنید.** این مسیر متعلق به میزبان است و کانتینر معمولاً آن را به‌طور مستقیم نمی‌بیند.

#### حالت اول: تنها یک کانتینر qBittorrent دارید

فرمان زیر را اجرا کنید:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

نصاب تلاش می‌کند کانتینر فعال qBittorrent، اتصال `/config` و پوشهٔ مربوط روی میزبان را پیدا کند. اگر پیکربندی بدون ابهام باشد، تنظیمات qBittorrent را هم به‌طور خودکار اعمال می‌کند.

#### حالت دوم: نام کانتینر را نمی‌دانید

برای دیدن فهرست کانتینرها:

```sh
sh install.sh --list-containers
```

یا از خود Docker استفاده کنید:

```sh
docker ps
```

برای مثال، اگر نام کانتینر چنین باشد:

```text
qbittorrent
```

آن را صریحاً انتخاب کنید:

```sh
sh install.sh --container=qbittorrent -configure
```

#### حالت سوم: چند کانتینر qBittorrent دارید

ممکن است یک کانتینر اصلی و یک کانتینر آزمایشی داشته باشید:

```text
qbittorrent
qbittorrent-test
```

نخست فهرست را بررسی کنید:

```sh
sh install.sh --list-containers
```

برای نصب در کانتینر اصلی:

```sh
sh install.sh --container=qbittorrent -configure
```

برای نصب در کانتینر آزمایشی:

```sh
sh install.sh --container=qbittorrent-test -configure
```

نصاب در صورت یافتن چند کانتینر **یکی را به‌صورت تصادفی انتخاب نمی‌کند**.

#### حالت چهارم: مسیر `/config` روی میزبان را می‌دانید

برای مثال:

```text
/root/qbittorrent/config
```

می‌توانید مسیر را مستقیم بدهید:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

روی Synology ممکن است مسیر چنین باشد:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

روی NAS دیگر برای مثال:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

این‌ها فقط نمونه‌اند. باید مسیر واقعی پوشهٔ پیکربندی qBittorrent روی میزبان خودتان را وارد کنید.

#### حالت پنجم: محل نصب WebUI را انتخاب کنید

پس از مشخص کردن کانتینر می‌توانید مسیر موردنظر داخل کانتینر را هم تعیین کنید:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

نصاب با توجه به اتصال Docker برای `/config`، مسیر معادل روی میزبان را پیدا می‌کند.

#### حالت ششم: چند نصب را یکجا به‌روز کنید

اگر چند نمونهٔ qBittorrent دارید، گزینهٔ `-o` را تکرار کنید. بسته تنها یک بار دانلود و اعتبارسنجی می‌شود و تا وقتی همهٔ مقصدها آماده نشده‌اند، هیچ نصبی جایگزین نمی‌شود. برای هر مقصد به‌طور مستقل **سه نسخهٔ پشتیبان آخر** در `~/.config/weig-qb-webui/backups/` نگهداری می‌شود.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

در حالت چند مقصد، `-configure` را اضافه نکنید. هر نمونه همان مسیر WebUI جایگزین قبلی را حفظ می‌کند. برای مشاهدهٔ تمام گزینه‌ها `sh install.sh -help` را اجرا کنید.

#### بررسی مسیرها پس از نصب

پس از نصب موفق ممکن است خروجی شبیه این باشد:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: محل واقعی فایل‌ها روی میزبان.
- `qBittorrent Root Folder`: مسیر **داخل کانتینر** که باید در *Files location* qBittorrent وارد شود.

با `-configure`، اگر نصاب بتواند پیکربندی qBittorrent را با اطمینان تشخیص دهد، رابط وب جایگزین را فعال و مسیر آن را تنظیم می‌کند. در غیر این صورت از مراحل نصب دستی بالا استفاده کنید.

</details>

## گزینه‌های پرکاربرد

نام گزینه‌های عمومی در Linux و Windows یکسان است. PowerShell در نام پارامترها بین حروف بزرگ و کوچک تفاوتی نمی‌گذارد.

| کاربرد | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| نصب آخرین نسخهٔ پایدار (`main`) | حالت پیش‌فرض، بدون پارامتر | حالت پیش‌فرض، بدون پارامتر |
| نصب نسخهٔ پایدار مشخص | `-version 1.2.0` | `-version 1.2.0` |
| نصب نسخهٔ توسعه | `-dev` | `-dev` |
| تعیین پوشهٔ نصب | `-o /path` (در Linux قابل تکرار) | `-o D:\path` یا `-output D:\path` |
| فایل تنظیمات qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| تنظیم خودکار qBittorrent | `-configure` | `-configure` |
| بازگردانی نسخهٔ قبلی | `-rollback` | `-rollback` |
| حذف کامل همراه پشتیبان‌ها | `-uninstall -purge` | `-uninstall -purge` |
| نمایش راهنمای کامل | `-help` | `-help` |
| انتخاب کانتینر Docker | `--container=NAME` | — |
| فهرست کانتینرهای Docker | `--list-containers` | — |
| مسیر میزبان متناظر با `/config` | `--config-root=/path` | — |

<details>
<summary><b>توضیح گزینه‌ها (برای باز کردن کلیک کنید)</b></summary>

- بدون `-dev` از کانال پایدار `main` استفاده می‌شود؛ با `-dev` نسخهٔ توسعهٔ مشخص‌شده با Git SHA دقیق نصب می‌شود.
- حرف `o` در `-o` به معنی **output** است. در Linux با تکرار این گزینه می‌توان چند نصب موجود را با یک دانلود به‌روز کرد.
- فایل‌های پشتیبان نصاب در `~/.config/weig-qb-webui/backups/` قرار می‌گیرند و **حداکثر سه پشتیبان تازه برای هر مقصد** نگهداری می‌شود.
- `-configure` گزینهٔ *Use alternative WebUI* را فعال و *Files location* را تنظیم می‌کند، ولی تنها برای یک مقصد قابل استفاده است.
- `-rollback` آخرین نسخهٔ پشتیبان ایجادشده برای مقصد انتخابی را بازیابی می‌کند. برای بازیابی چند مقصد مشخص، `-o` را تکرار کنید.
- `-uninstall -purge` فقط فایل‌های پشتیبان و وضعیت بازگردانی **همان نصب انتخاب‌شده** را حذف می‌کند و به نصب‌های دیگر کاری ندارد.
- اگر می‌خواهید بعداً از `-rollback` استفاده کنید، گزینهٔ `-purge` را حذف کنید.
- با `-version` می‌توانید یک GitHub Release مشخص، مثلاً `1.2.0`، نصب کنید. اگر وجود نداشته باشد، نصب خطا می‌دهد و **خودکار به latest یا dev برنمی‌گردد**.
- در صورت وجود چند کانتینر، ابتدا با `--list-containers` فهرست را ببینید و با `--container=NAME` موردنظر را انتخاب کنید یا مسیر میزبان `/config` را با `--config-root=/path` تعیین کنید.

### نسخه و پوشهٔ نصب مشخص

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### بازیابی نصب قبلی

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

## حذف با یک فرمان

<details>
<summary><b>حذف کامل در Linux، NAS، Docker و Windows PowerShell</b></summary>

معمولاً توصیه می‌کنیم **WebUI را بدون نگهداری پشتیبان‌های نصاب حذف کنید**. فرمان‌های زیر رابط وب را حذف می‌کنند، رابط جایگزین مقصد مربوط را غیرفعال می‌کنند، پشتیبان‌ها و وضعیت بازگردانی همان مقصد را پاک می‌کنند و اسکریپت نصب دانلودشده را از پوشهٔ جاری برمی‌دارند.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

برای پوشهٔ دلخواه، `-o /path/to/weig-qb-webui` را اضافه کنید.

### Docker

یک کانتینر با شناسایی خودکار:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

چند کانتینر:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

اگر از `--config-root` استفاده می‌کنید:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

برای پوشهٔ دلخواه، `-o D:\weig-qb-webui` را اضافه کنید.

گزینهٔ `-purge` فقط پشتیبان‌های متعلق به نصبی را که حذف می‌کنید پاک می‌کند و پشتیبان‌های دیگر را دست‌نخورده می‌گذارد. اگر پوشهٔ وضعیت مشترک خالی شود، `~/.config/weig-qb-webui` در Linux (برای `root`: `/root/.config/weig-qb-webui`) یا `%APPDATA%\weig-qb-webui` در Windows نیز پاک می‌شود.

برای نگهداری پشتیبان‌ها و استفادهٔ بعدی از `-rollback`، فرمان حذف را بدون `-purge` اجرا کنید.

</details>
