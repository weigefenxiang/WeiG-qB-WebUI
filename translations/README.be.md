## Бакавая панэль асобнікаў

Некалькі незалежных асобнікаў qBittorrent могуць выкарыстоўваць адну і тую ж падрыхтаваную папку WeiG у рэжыме **толькі для чытання**. Падключыце папку хоста да кожнага Docker-кантэйнера, напрыклад `/root/weig-qb-webui:/weig-qb-webui:ro`, пасля чаго ўкажыце шлях `/weig-qb-webui` як каранёвую папку Alternative WebUI. Базы торэнтаў, налады і ўваход у кожнага асобніка застаюцца асобнымі.

У раздзеле **Асобнікі** бакавой панэлі можна зарэгістраваць асобнікі, пераключацца паміж імі з поўнай загрузкай старонкі і пераймяноўваць іх. Пазнака бягучага асобніка залежыць ад сапраўднага URL, а не ад захаванага суфікса. Інтэрвал аўтаматычнай праверкі задаецца ў **Налады → WeiG WebUI → Інтэрфейс**: па змаўчанні 30 хвілін, можна выключыць або выбраць ад 5 да 1440 хвілін.

**Сведчанні стану наўмысна асцярожныя:** пацверджаны WebAPI таго самага паходжання азначае, што qB працуе ў сетцы. Міждаменны адказ `no-cors` без уліковых даных пацвярджае толькі даступнасць HTTP-адраса, у тым ліку пры 403/404. Няма міждаменнага чытання Cookie/SID, перадачы пароляў і сеансаў, абыходу CORS або сервернага шлюза. Час папярэдняй праверкі — **гістарычнае сведчанне**, а не доказ, што асобнік зараз анлайн. Адрас `127.0.0.1` у браўзеры адносіцца да прылады з гэтым браўзерам, а не да аддаленага VPS.

## Усталяванне для пачаткоўцаў

<details>
<summary><b>Усталёўваеце ўпершыню? Разгарніце кароткую інструкцыю</b></summary>

### 1. Распакуйце ZIP

Спампуйце `weig-qb-webui.zip` і распакуйце архіў. Ён ужо змяшчае стандартную папку:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

Уся папка **`weig-qb-webui`** — гэта корань WebUI. Не капіюйце толькі `public` або `private`.

### 2. Перамясціце ў пастаяннае месца

Напрыклад:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Затым трэба будзе ўказаць гэты шлях у qBittorrent.

### 3. Уключыце ў qBittorrent

Адкрыйце qBittorrent:

**Tools → Options... → WebUI**

Гэта актуальныя назвы пунктаў англійскага інтэрфейсу qBittorrent. Затым:

1. Уключыце **Use alternative WebUI**.
2. Знайдзіце поле **Files location:**.
3. Увядзіце шлях да папкі `weig-qb-webui`.

Прыклад для Windows:

```text
D:\weig-qb-webui
```

Прыклад для Linux:

```text
/opt/weig-qb-webui
```

4. Націсніце **OK**, каб захаваць.
5. Абнавіце старонку WebUI. Калі засталася старая версія з кэша, паспрабуйце `Ctrl + F5`.

> **Праверка шляху:** у паказанай папцы павінны непасрэдна знаходзіцца `public`, `private`, `VERSION` і іншыя файлы.

> **Docker:** qBittorrent працуе ўнутры кантэйнера, таму звычайна трэба задаваць шлях, бачны з кантэйнера, а не фактычны шлях хоста.

</details>

## Усталяванне адной камандай

Усталёўнік для Linux/NAS заўсёды спампоўваецца з пастаяннага адраса Dev Pages ніжэй. **Адрас скрыпта не выбірае канал усталявання:** без `-dev` усталёўваецца апошні правераны стабільны GitHub Release; `-dev` патрэбны толькі для бягучай распрацоўчай версіі з дакладным Git SHA. Спампаваны скрыпт застаецца ў бягучым каталогу для наступных абнаўленняў і адкатаў.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Паказаць шлях скрыпта і папку ўсталявання па змаўчанні</b></summary>

```text
./install.sh
```

Папка WebUI па змаўчанні:

```text
~/.local/share/weig-qb-webui
```

Пры запуску ад імя `root` звычайна:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker, некалькі кантэйнераў і тлумачэнне шляхоў</b></summary>

#### Хост і кантэйнер

- **Хост** — машына Linux/NAS, на якой працуе Docker.
- **Кантэйнер** — ізаляванае асяроддзе, дзе працуе qBittorrent.

Напрыклад:

```text
Хост:       /root/qbittorrent/config
   ↓ падключана як
Кантэйнер:  /config
```

Прыклад Docker Compose:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Калі WebUI на хосце знаходзіцца тут:

```text
/root/qbittorrent/config/weig-qb-webui
```

тады ў полі qBittorrent **Files location:** трэба задаць:

```text
/config/weig-qb-webui
```

#### Адзін кантэйнер qBittorrent

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Усталёўнік паспрабуе аўтаматычна выявіць кантэйнер і падключэнне `/config`.

#### Паказаць кантэйнеры

Спачатку паглядзіце спіс выяўленых кантэйнераў qBittorrent:

```sh
sh install.sh --list-containers
```

Або праверце кантэйнеры непасрэдна праз Docker:

```sh
docker ps
```

Напрыклад, кантэйнер можа называцца:

```text
qbittorrent
```

Тады выберыце яго яўна:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Калі працуе некалькі кантэйнераў qBittorrent

Напрыклад, ёсць асноўны і тэставы асобнікі:

```text
qbittorrent
qbittorrent-test
```

Спачатку атрымайце спіс:

```sh
sh install.sh --list-containers
```

Для асноўнага асобніка:

```sh
sh install.sh --container=qbittorrent -configure
```

Для тэставага асобніка:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Калі ёсць некалькі кантэйнераў, усталёўнік не выбірае адзін з іх наўздагад.

#### Указаць шлях хоста, падключаны як `/config`

Калі папка канфігурацыі qBittorrent на хосце знаходзіцца тут:

```text
/root/qbittorrent/config
```

Можна ўказаць яе непасрэдна:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Прыклад для Synology:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Прыклад для іншай NAS:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Замяніце гэтыя прыклады сапраўдным шляхам да папкі `/config` на вашым хосце.

#### Указаць шлях WebUI

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

#### Абнаўленне некалькіх папак WebUI за адзін запуск

У Linux і NAS можна паўтарыць параметр `-o` і абнавіць некалькі існых установак пасля аднаго спампоўвання. У гэтым рэжыме нельга адначасова ўжываць `-configure`, `--container` і `--config-root`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

#### Як праверыць шляхі пасля ўсталявання

Усталёўнік паказвае шлях на хосце і шлях, бачны самому qBittorrent:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

У наладзе qBittorrent **Files location** трэба задаць другі шлях — унутры кантэйнера. Калі `-configure` выкананы паспяхова, усталёўнік задае яго аўтаматычна.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

<details>
<summary><b>Паказаць папку ўсталявання</b></summary>

```text
C:\Users\<імя-карыстальніка>\AppData\Local\weig-qb-webui
```

</details>

## Асноўныя параметры
Рэгістр назваў параметраў PowerShell не мае значэння.

| Прызначэнне | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Апошні стабільны Release | Па змаўчанні | Па змаўчанні |
| Пэўны выпуск Release | `-version 1.2.0` | `-version 1.2.0` |
| Распрацоўчая версія | `-dev` | `-dev` |
| Папка ўсталявання | `-o /path` (можна паўтараць) | `-o D:\path` або `-output D:\path` |
| Файл канфігурацыі qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Аўтаматычна наладзіць qBittorrent | `-configure` | `-configure` |
| Адкаціць папярэднюю ўстаноўку | `-rollback` | `-rollback` |
| Цалкам выдаліць (без рэзервовых копій) | `-uninstall -purge` | `-uninstall -purge` |
| Даведка | `-help` | `-help` |
| Выбраць Docker-кантэйнер | `--container=NAME` | — |
| Паказаць Docker-кантэйнеры | `--list-containers` | — |
| Папка хоста, падключаная як Docker `/config` | `--config-root=/path` | — |

<details>
<summary><b>Заўвагі (націсніце, каб разгарнуць)</b></summary>

- Калі такога выпуску няма, усталёўнік не пераходзіць аўтаматычна на latest або dev.
- `-dev` нельга ўжываць разам з `-version`.

### Пэўная версія і папка ўсталявання

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Адкат

Адкат:

```sh
sh install.sh -rollback
```

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Выдаленне адной камандай

<details>
<summary><b>Поўнае выдаленне ў Linux / NAS, Docker і Windows PowerShell</b></summary>

Рэкамендуецца **поўнае выдаленне без захавання рэзервовых копій усталёўніка**: выдаліць WebUI, адключыць адпаведны альтэрнатыўны інтэрфейс, ачысціць рэзервовыя копіі і стан адкату гэтай мэты, а затым выдаліць спампаваны скрыпт з бягучага каталога.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Для ўласнай папкі ўсталявання дадайце `-o /path/to/weig-qb-webui`.

### Docker

Адзін кантэйнер / аўтаматычнае вызначэнне:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Некалькі кантэйнераў:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Пры выкарыстанні `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Для ўласнай папкі ўсталявання дадайце `-o D:\weig-qb-webui`.

`-purge` выдаляе толькі рэзервовыя копіі бягучай мэты і не закранае іншыя ўстаноўкі. Калі агульны каталог стану пусты, таксама выдаляецца Linux `~/.config/weig-qb-webui` (для root: `/root/.config/weig-qb-webui`) або Windows `%APPDATA%\weig-qb-webui`.

Каб захаваць рэзервовыя копіі для наступнага `-rollback`, проста не выкарыстоўвайце `-purge`.

</details>
