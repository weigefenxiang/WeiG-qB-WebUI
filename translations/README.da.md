## Manuel installation for begyndere

<details>
<summary><b>Er det første gang? Åbn den korte installationsvejledning</b></summary>

### 1. Pak ZIP-filen ud

Download `weig-qb-webui.zip`, og pak hele arkivet ud. Det indeholder allerede denne mappestruktur:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Hele mappen `weig-qb-webui`** er webgrænsefladens rodmappe. Kopiér ikke kun `public` eller `private`.

### 2. Vælg en fast placering

Flyt hele mappen til et sted, hvor den ikke risikerer at blive slettet ved en fejl, for eksempel:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Det er denne mappe, du senere skal vælge i qBittorrent.

### 3. Aktivér alternativ WebUI i qBittorrent

Åbn qBittorrent, og gå til **Værktøjer → Indstillinger → Webgrænseflade**. Menupunkterne kan hedde noget andet, hvis du bruger qBittorrent på et andet sprog.

1. Markér **Brug alternativ webgrænseflade** (*Use alternative WebUI*).
2. Find feltet **Filernes placering** (*Files location*).
3. Angiv stien til mappen `weig-qb-webui`.

Eksempel til Windows:

```text
D:\weig-qb-webui
```

Eksempel til Linux:

```text
/opt/weig-qb-webui
```

4. Klik på **OK** for at gemme.
5. Genindlæs qBittorrents webside. Hvis den gamle brugerflade stadig vises, kan du trykke `Ctrl + F5` for at omgå browserens gamle cache.

> **Kontrollér stien:** Du skal kunne se `public`, `private` og `VERSION` direkte i den valgte mappe. Hvis du først skal åbne endnu en `weig-qb-webui`-mappe, har du valgt et forkert mappeniveau.

> **Bruger du Docker?** qBittorrent kører inde i en container. Du skal bruge en sti, der kan tilgås **inde fra containeren**, ikke kun på værtsmaskinen. Se Docker-afsnittet nedenfor.

</details>

## Installation med én kommando

Installationsscriptet til Linux og NAS hentes altid fra den faste Dev Pages-adresse nedenfor. **Adressen på scriptet bestemmer ikke, hvilken version der installeres:** uden `-dev` installeres den seneste verificerede stabile GitHub Release; med `-dev` bruges udviklingsversionen med det præcise Git SHA. Scriptet bliver liggende i den aktuelle mappe, så du senere kan opdatere eller rulle tilbage.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Se placeringen af scriptet og standardinstallationsmappen</b></summary>

Det downloadede script findes her:

```text
./install.sh
```

WebUI installeres som standard i:

```text
~/.local/share/weig-qb-webui
```

Hvis kommandoen køres som `root`, vil placeringen normalt være:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker-installation, flere containere og stier</b></summary>

#### Forskel på værtsmaskine og container

Hvis du bruger Docker på en VPS, Linux-server, Synology, QNAP eller en anden NAS:

- **Værtsmaskine (host)** er Linux-/NAS-systemet, der kører Docker, typisk den maskine, du logger på via SSH.
- **Container** er det isolerede miljø, hvor qBittorrent kører. Det kan kun se mapper, der er gjort tilgængelige for containeren.

En typisk mapning:

```text
Vært: /root/qbittorrent/config
   ↓ monteret som
I containeren: /config
```

I Docker Compose står der ofte:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Stien **før kolon** er på **værtsmaskinen**; stien **efter kolon** er den, containeren kan se.

Hvis WeiG ligger på værtsmaskinen her:

```text
Vært: /root/qbittorrent/config/weig-qb-webui
```

skal du angive dette i feltet **Files location** i qBittorrent:

```text
/config/weig-qb-webui
```

**Skriv ikke `/root/qbittorrent/config/weig-qb-webui`** i dette felt. Containeren kan som regel ikke se denne sti på værtsmaskinen direkte.

#### Tilfælde 1: Kun én qBittorrent-container

Kør:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Installationsprogrammet forsøger at finde den aktive qBittorrent-container, `/config`-tilknytningen og den rigtige mappe på værtsmaskinen. Hvis opsætningen kan identificeres sikkert, konfigurerer det også qBittorrent.

#### Tilfælde 2: Se de tilgængelige containere

Hvis du ikke kender containerens navn:

```sh
sh install.sh --list-containers
```

Eller brug Docker direkte:

```sh
docker ps
```

Hvis containeren for eksempel hedder:

```text
qbittorrent
```

skal du vælge den eksplicit:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Tilfælde 3: Flere qBittorrent-containere

Måske har du en almindelig instans og en testinstans:

```text
qbittorrent
qbittorrent-test
```

Se først listen:

```sh
sh install.sh --list-containers
```

For at installere på hovedinstansen:

```sh
sh install.sh --container=qbittorrent -configure
```

For at installere på testinstansen:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Installationsprogrammet **vælger ikke en tilfældig container**, hvis der findes flere.

#### Tilfælde 4: Du kender værtsmaskinens `/config`-mappe

For eksempel:

```text
/root/qbittorrent/config
```

Angiv mappen direkte:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

På Synology kan stien være:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

På en anden NAS kan den eksempelvis være:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Det er kun eksempler. Brug den faktiske sti til qBittorrents konfigurationsmappe på din værtsmaskine.

#### Tilfælde 5: Vælg WebUI's installationsmappe

Når du har valgt containeren, kan du også angive den ønskede placering inde i den:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Installationsprogrammet finder den tilsvarende mappe på værtsmaskinen ud fra Dockers `/config`-tilknytning.

#### Tilfælde 6: Opdater flere installationer på én gang

Hvis du administrerer flere qBittorrent-instanser, kan du gentage `-o`. Pakken downloades og kontrolleres kun én gang; alle mål forberedes, før noget af dem udskiftes. Hvert mål beholder selvstændigt **de tre seneste sikkerhedskopier** under `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Brug ikke `-configure`, når du angiver flere mål. Hver instans fortsætter med sin tidligere konfigurerede sti til alternativ WebUI. Kør `sh install.sh -help` for at se alle indstillinger.

#### Kontrollér stierne efter installation

Efter en vellykket installation kan du se noget i retning af:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: den faktiske placering af filerne på værtsmaskinen.
- `qBittorrent Root Folder`: stien **inde i containeren**, som skal angives i *Files location* i qBittorrent.

Hvis du bruger `-configure`, aktiverer installationsprogrammet automatisk den alternative WebUI og angiver stien, hvis det sikkert kan finde qBittorrents konfiguration. Ellers følger du den manuelle vejledning ovenfor.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

<summary><b>Vis installationsmappen</b></summary>

```text
C:\Users\<brugernavn>\AppData\Local\weig-qb-webui
```

</details>

## Almindelige parametre

Linux og Windows bruger samme navne til de fælles parametre. PowerShell skelner ikke mellem store og små bogstaver i parameternavne.

| Formål | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Seneste stabile version (`main`) | Standard, ingen parameter | Standard, ingen parameter |
| En bestemt stabil version | `-version 1.2.0` | `-version 1.2.0` |
| Udviklingsversion | `-dev` | `-dev` |
| Installationsmappe | `-o /path` (kan gentages på Linux) | `-o D:\path` eller `-output D:\path` |
| Egen qBittorrent-konfigurationsfil | — | `-qbconfig D:\path\qBittorrent.ini` |
| Konfigurer qBittorrent automatisk | `-configure` | `-configure` |
| Gendan en tidligere installation | `-rollback` | `-rollback` |
| Afinstaller helt og fjern sikkerhedskopier | `-uninstall -purge` | `-uninstall -purge` |
| Vis fuld hjælp | `-help` | `-help` |
| Vælg Docker-container | `--container=NAME` | — |
| Vis Docker-containere | `--list-containers` | — |
| Værtsmaskinens `/config`-mappe | `--config-root=/path` | — |

<details>
<summary><b>Forklaring af parametrene (udvid)</b></summary>

- Uden `-dev` bruges den stabile `main`-kanal; med `-dev` bruges udviklingsversionen med det præcise Git SHA.
- `o` i `-o` står for **output**. På Linux kan den gentages, så flere installationer opdateres med én download.
- Installationsprogrammets sikkerhedskopier gemmes under `~/.config/weig-qb-webui/backups/`; **højst tre nyere kopier pr. mål** bevares.
- `-configure` aktiverer *Use alternative WebUI* og indstiller *Files location*, men kan kun bruges til ét mål.
- `-rollback` gendanner den seneste sikkerhedskopi for det valgte mål. Gentag `-o` for flere klart angivne mål.
- `-uninstall -purge` fjerner kun sikkerhedskopier og gendannelsesstatus for **det valgte mål**, ikke andre installationer.
- Undlad `-purge`, hvis du vil gemme kopierne til en senere `-rollback`.
- Med `-version` kan du vælge en bestemt GitHub Release, for eksempel `1.2.0`. Hvis den ikke findes, stopper installationen med en fejl og **skifter ikke automatisk** til latest eller dev.
- Har du flere containere, kan du bruge `--list-containers` og vælge med `--container=NAME`, eller angive værtsmaskinens `/config` via `--config-root=/path`.

### Vælg en bestemt version og installationsmappe

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Gendan en installation

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Afinstallation med én kommando

<details>
<summary><b>Fuldstændig afinstallation på Linux / NAS, Docker og Windows PowerShell</b></summary>

Vi anbefaler normalt **at fjerne WebUI uden at beholde installationsprogrammets sikkerhedskopier**. Kommandoerne afinstallerer WebUI, deaktiverer den alternative webgrænseflade for det valgte mål, fjerner målets sikkerhedskopier og gendannelsesstatus og sletter det hentede installationsscript i den aktuelle mappe.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Til en brugerdefineret installationsmappe tilføjer du `-o /sti/weig-qb-webui`.

### Docker

Én container med automatisk genkendelse:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Flere containere:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Hvis du bruger `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Til en anden installationsmappe tilføjer du `-o D:\weig-qb-webui`.

`-purge` fjerner kun de sikkerhedskopier, der hører til den installation, du er ved at afinstallere. Andre instanser berøres ikke. Hvis den fælles statusmappe bliver tom, fjernes også `~/.config/weig-qb-webui` (for `root`: `/root/.config/weig-qb-webui`) på Linux eller `%APPDATA%\weig-qb-webui` på Windows.

Vil du bevare sikkerhedskopierne til senere `-rollback`, skal du afinstallere uden `-purge`.

</details>
