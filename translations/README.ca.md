## Instal·lació manual per començar

<details>
<summary><b>És la primera vegada que la instal·les? Obre la guia d'un minut</b></summary>

### 1. Extreu el ZIP

Baixa `weig-qb-webui.zip` i extreu-lo. L'arxiu ja conté una carpeta amb aquesta estructura:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

La **carpeta `weig-qb-webui` sencera** és l'arrel de la interfície web. No copiïs només `public` o `private`.

### 2. Desa-la en una ubicació fixa

Mou tota la carpeta a un lloc on no s'esborri accidentalment. Per exemple:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Aquest és el directori que hauràs d'indicar a qBittorrent.

### 3. Activa la interfície alternativa a qBittorrent

Obre qBittorrent i ves a **Eines → Opcions… → Interfície web**. Les etiquetes exactes poden variar segons l'idioma configurat a qBittorrent.

1. Marca **Fes servir una interfície web alternativa** (*Use alternative WebUI*).
2. Cerca el camp **Ubicació dels fitxers** (*Files location*).
3. Introdueix-hi la ruta de la carpeta `weig-qb-webui`.

Exemple a Windows:

```text
D:\weig-qb-webui
```

Exemple a Linux:

```text
/opt/weig-qb-webui
```

4. Prem **D'acord** per desar la configuració.
5. Torna a carregar la pàgina web de qBittorrent. Si encara veus la interfície antiga, prova `Ctrl + F5` per forçar la recàrrega.

> **Com comproves que la ruta és correcta?** A dins hi has de trobar directament `public`, `private` i `VERSION`. Si abans has d'entrar en una altra carpeta `weig-qb-webui`, has triat el nivell equivocat.

> **Si utilitzes Docker:** qBittorrent s'executa dins d'un contenidor. Normalment has d'indicar una ruta visible *des del contenidor*, no pas la ruta de l'ordinador amfitrió. Consulta la guia de Docker de més avall.

</details>

## Instal·lació amb una sola ordre

L'script per a Linux i NAS es baixa sempre de l'adreça fixa de Dev Pages que trobaràs a continuació. **L'adreça de l'script no determina el canal d'instal·lació:** sense `-dev` s'instal·la l'última versió estable de GitHub Release, degudament verificada; amb `-dev` s'instal·la la versió de desenvolupament associada a un Git SHA exacte. L'script es desa al directori actual per facilitar futures actualitzacions i restauracions.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Mostra on es desa l'script i el directori d'instal·lació predeterminat</b></summary>

L'script descarregat és a:

```text
./install.sh
```

La interfície web s'instal·la de manera predeterminada a:

```text
~/.local/share/weig-qb-webui
```

Si executes l'ordre com a usuari `root`, habitualment serà:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Instal·lació Docker, diversos contenidors i rutes (recomanat per a principiants)</b></summary>

#### Quina diferència hi ha entre l'amfitrió i el contenidor?

Si fas servir Docker en un VPS, un servidor Linux, Synology, QNAP o un altre NAS:

- **Amfitrió**: el sistema Linux o NAS que executa Docker, on normalment et connectes per SSH.
- **Contenidor**: l'entorn aïllat on s'executa qBittorrent; només pot accedir a les rutes que té muntades.

Imaginem que la configuració de Docker inclou aquest muntatge:

```text
Amfitrió: /root/qbittorrent/config
   ↓ muntat a
Contenidor: /config
```

A Docker Compose sol aparèixer així:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

La ruta de l'esquerra dels dos punts pertany a l'**amfitrió**; la de la dreta és la que veu el **contenidor**.

Si instal·les WeiG a l'amfitrió a:

```text
Amfitrió: /root/qbittorrent/config/weig-qb-webui
```

al camp **Files location** de qBittorrent hi has d'escriure:

```text
/config/weig-qb-webui
```

**No hi indiquis `/root/qbittorrent/config/weig-qb-webui`**, perquè el contenidor normalment no pot veure aquesta ruta de l'amfitrió.

#### Cas 1: només tens un contenidor qBittorrent

Executa:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

L'instal·lador prova de detectar el contenidor qBittorrent en funcionament, el muntatge de `/config` i el directori adequat de l'amfitrió. Si la configuració està ben identificada, també configura qBittorrent automàticament.

#### Cas 2: consulta els contenidors disponibles

Si no saps com es diu el contenidor:

```sh
sh install.sh --list-containers
```

També pots consultar-los directament amb Docker:

```sh
docker ps
```

Per exemple, si el seu nom és:

```text
qbittorrent
```

selecciona'l expressament:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Cas 3: tens diversos contenidors qBittorrent

Suposa que hi ha un contenidor habitual i un de proves:

```text
qbittorrent
qbittorrent-test
```

Primer comprova'n la llista:

```sh
sh install.sh --list-containers
```

Per instal·lar la interfície a la instància principal:

```sh
sh install.sh --container=qbittorrent -configure
```

Per instal·lar-la a la instància de proves:

```sh
sh install.sh --container=qbittorrent-test -configure
```

L'instal·lador **no tria cap contenidor a l'atzar** quan en troba diversos.

#### Cas 4: coneixes la carpeta `/config` de l'amfitrió

Per exemple:

```text
/root/qbittorrent/config
```

Pots indicar-la directament:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

En un NAS Synology, la ruta podria ser:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

En altres NAS, podria ser:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Són rutes d'exemple; substitueix-les per la ubicació real de la carpeta de configuració de qBittorrent.

#### Cas 5: indica el directori de la interfície web

Si ja has indicat el contenidor, també pots triar la ruta de destinació dins seu:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

L'instal·lador la converteix en el directori corresponent de l'amfitrió fent servir el muntatge Docker de `/config`.

#### Cas 6: actualitza diverses instal·lacions alhora

Quan gestionis diverses instàncies, pots repetir `-o`. El paquet es baixa i es verifica una única vegada; no es fa cap substitució fins que totes les destinacions estan preparades. Cada destinació conserva de manera independent els **tres últims backups** a `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

No facis servir `-configure` en aquesta modalitat: cada instància ha de mantenir la ruta de WebUI alternativa que ja tingui configurada. Per veure tots els paràmetres, executa `sh install.sh -help`.

#### Comprova les rutes després de la instal·lació

Una instal·lació correcta pot mostrar una sortida semblant a aquesta:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: on s'han desat els fitxers a l'amfitrió.
- `qBittorrent Root Folder`: la ruta **dins del contenidor** que has d'escriure a *Files location* de qBittorrent.

Si fas servir `-configure` i l'instal·lador troba de manera segura la configuració de qBittorrent, activa la interfície alternativa i en desa la ruta. Si no, ho pots fer manualment tal com s'ha explicat al principi.

</details>

### Windows PowerShell

Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

```

</details>

## Paràmetres habituals

Els paràmetres compartits tenen el mateix nom a Linux i Windows; a PowerShell no distingeixen entre majúscules i minúscules.

| Finalitat | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Instal·lar l'última versió estable (`main`) | Per defecte, sense paràmetres | Per defecte, sense paràmetres |
| Instal·lar una versió estable concreta | `-version 1.2.0` | `-version 1.2.0` |
| Instal·lar la versió de desenvolupament | `-dev` | `-dev` |
| Indicar el directori de destinació | `-o /path` (repetible a Linux) | `-o D:\path` o `-output D:\path` |
| Indicar el fitxer de configuració de qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Configurar qBittorrent automàticament | `-configure` | `-configure` |
| Recuperar la instal·lació anterior | `-rollback` | `-rollback` |
| Desinstal·lar i esborrar els backups | `-uninstall -purge` | `-uninstall -purge` |
| Mostrar l'ajuda completa | `-help` | `-help` |
| Indicar un contenidor Docker | `--container=NAME` | — |
| Mostrar els contenidors Docker | `--list-containers` | — |
| Indicar la ruta de `/config` a l'amfitrió | `--config-root=/path` | — |

<details>
<summary><b>Detalls dels paràmetres (desplega)</b></summary>

- Sense `-dev`, l'instal·lador fa servir el canal estable `main`; amb `-dev`, la versió de desenvolupament associada a un Git SHA exacte.
- La `o` de `-o` vol dir **output**. A Linux pots repetir el paràmetre per actualitzar diverses instal·lacions amb una sola baixada.
- Els backups de l'instal·lador són a `~/.config/weig-qb-webui/backups/` i es conserven, com a màxim, els **tres últims per destinació**.
- `-configure` activa *Use alternative WebUI* i estableix *Files location*, però només està permès quan hi ha una sola destinació.
- `-rollback` recupera l'últim backup creat per l'instal·lador per a la destinació seleccionada; també pots repetir `-o` per restaurar diverses destinacions explícites.
- `-uninstall -purge` esborra els backups i l'estat de reversió de la destinació actual, sense tocar els de les altres.
- Si vols conservar aquests backups per poder executar `-rollback`, omet `-purge`.
- `-version` instal·la una GitHub Release concreta, per exemple `1.2.0`. Si no existeix, l'instal·lador retorna un error: **no canvia automàticament a latest o dev**.
- Si tens diversos contenidors, mostra la llista amb `--list-containers` i indica'n un amb `--container=NAME`, o bé especifica la carpeta `/config` de l'amfitrió amb `--config-root=/path`.

### Versió concreta i directori d'instal·lació

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Restauració

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Desinstal·lació amb una sola ordre

<details>
<summary><b>Desinstal·lació completa a Linux / NAS, Docker i Windows PowerShell</b></summary>

Recomanem la **desinstal·lació sense conservar els backups de l'instal·lador**: esborra la interfície web, desactiva la WebUI alternativa de la destinació corresponent, elimina els backups i l'estat de reversió que li pertanyen i suprimeix l'script que s'havia descarregat al directori actual.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Per indicar una destinació personalitzada, afegeix `-o /ruta/weig-qb-webui`.

### Docker

Un sol contenidor amb detecció automàtica:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Per a diversos contenidors:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Si fas servir `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Per indicar una carpeta personalitzada, afegeix `-o D:\weig-qb-webui`.

L'opció `-purge` només esborra els backups de la instal·lació que estàs desinstal·lant. No afecta les altres instàncies. Si no queda cap altre contingut, també s'elimina el directori d'estat compartit `~/.config/weig-qb-webui` (per a `root`: `/root/.config/weig-qb-webui`) o `%APPDATA%\weig-qb-webui` a Windows.

Per conservar els backups i poder tornar enrere amb `-rollback`, desinstal·la sense `-purge`.

</details>
