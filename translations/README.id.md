## Panduan pemasangan manual untuk pemula

<details>
<summary><b>Baru pertama kali memasang? Buka panduan singkat satu menit</b></summary>

### 1. Ekstrak berkas ZIP

Unduh `weig-qb-webui.zip`, lalu ekstrak. Di dalamnya sudah tersedia struktur folder berikut:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Seluruh folder `weig-qb-webui`** adalah direktori utama WebUI. Jangan hanya menyalin `public` atau `private`.

### 2. Simpan di lokasi tetap

Pindahkan seluruh folder ke tempat yang tidak mudah terhapus secara tidak sengaja, misalnya:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Lokasi inilah yang nanti perlu Anda pilih dalam pengaturan qBittorrent.

### 3. Aktifkan WebUI alternatif di qBittorrent

Buka qBittorrent, lalu masuk ke **Peralatan → Opsi → Antarmuka Web**. Nama menu yang tampil bisa berbeda tergantung bahasa yang dipilih di qBittorrent.

1. Centang **Gunakan antarmuka Web alternatif** (*Use alternative WebUI*).
2. Temukan kolom **Lokasi berkas** (*Files location*).
3. Isi dengan jalur ke folder `weig-qb-webui`.

Contoh untuk Windows:

```text
D:\weig-qb-webui
```

Contoh untuk Linux:

```text
/opt/weig-qb-webui
```

4. Klik **OK** untuk menyimpan pengaturan.
5. Muat ulang halaman WebUI qBittorrent. Jika tampilan lama masih muncul, tekan `Ctrl + F5` untuk memuat ulang tanpa cache lama.

> **Memastikan jalur sudah benar:** Di dalam folder yang dipilih, Anda harus langsung melihat `public`, `private`, dan `VERSION`. Jika masih harus membuka satu folder `weig-qb-webui` lagi, berarti tingkat folder yang dipilih salah.

> **Catatan untuk pengguna Docker:** qBittorrent berjalan **di dalam kontainer**. Anda harus memilih jalur yang dapat diakses dari dalam kontainer, bukan jalur yang hanya ada di komputer host. Penjelasan lengkapnya ada di bagian Docker di bawah.

</details>

## Pemasangan dengan satu perintah

Skrip pemasang untuk Linux dan NAS selalu diunduh dari alamat tetap Dev Pages berikut. **Alamat unduhan skrip tidak menentukan versi yang dipasang:** tanpa `-dev`, pemasang menggunakan GitHub Release stabil terbaru yang sudah diverifikasi; dengan `-dev`, pemasang menggunakan versi pengembangan pada Git SHA yang tepat. Skrip disimpan di direktori saat ini supaya nantinya mudah digunakan untuk memperbarui atau mengembalikan pemasangan.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Lihat lokasi skrip dan direktori pemasangan bawaan</b></summary>

Skrip yang sudah diunduh tersimpan sebagai:

```text
./install.sh
```

Lokasi bawaan pemasangan WebUI:

```text
~/.local/share/weig-qb-webui
```

Jika perintah dijalankan sebagai pengguna `root`, biasanya lokasinya adalah:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Pemasangan Docker, beberapa kontainer, dan cara menentukan jalur</b></summary>

#### Apa bedanya host dan kontainer?

Jika Anda menjalankan Docker di VPS, server Linux, Synology, QNAP, atau NAS lainnya:

- **Host**: sistem Linux atau NAS yang benar-benar menjalankan Docker, biasanya tempat Anda masuk melalui SSH.
- **Kontainer**: lingkungan terpisah tempat qBittorrent berjalan. qBittorrent hanya bisa mengakses folder yang dipetakan ke dalam kontainer.

Misalnya, folder konfigurasi Anda dipetakan seperti berikut:

```text
Host: /root/qbittorrent/config
   ↓ dipetakan ke
Di kontainer: /config
```

Di Docker Compose, biasanya ditulis seperti ini:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Bagian **di kiri** titik dua adalah jalur folder di **host**; bagian **di kanan** adalah jalur yang terlihat **dalam kontainer**.

Jika WeiG terpasang pada host di:

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

maka kolom **Files location** di qBittorrent harus diisi dengan:

```text
/config/weig-qb-webui
```

**Jangan masukkan `/root/qbittorrent/config/weig-qb-webui`** ke kolom tersebut, karena kontainer biasanya tidak dapat melihat jalur folder host itu secara langsung.

#### Situasi 1: Hanya ada satu kontainer qBittorrent

Jalankan:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Pemasang akan mencoba mencari kontainer qBittorrent yang aktif, pemetaan `/config`, dan direktori pemasangan yang sesuai di host. Bila konfigurasi dapat dikenali dengan pasti, pemasang juga akan mengatur qBittorrent.

#### Situasi 2: Melihat kontainer yang tersedia

Jika Anda belum tahu nama kontainernya:

```sh
sh install.sh --list-containers
```

Atau periksa langsung melalui Docker:

```sh
docker ps
```

Misalnya nama kontainernya adalah:

```text
qbittorrent
```

Pilih secara eksplisit:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Situasi 3: Ada beberapa kontainer qBittorrent

Misalnya Anda menjalankan kontainer utama dan kontainer untuk uji coba:

```text
qbittorrent
qbittorrent-test
```

Lihat daftarnya terlebih dahulu:

```sh
sh install.sh --list-containers
```

Untuk memasang pada kontainer utama:

```sh
sh install.sh --container=qbittorrent -configure
```

Untuk memasang pada kontainer uji coba:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Jika menemukan beberapa kontainer, pemasang **tidak akan memilih salah satu secara sembarangan**.

#### Situasi 4: Anda tahu direktori `/config` di host

Misalnya folder konfigurasinya adalah:

```text
/root/qbittorrent/config
```

Anda dapat menentukan folder tersebut secara langsung:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Di Synology, jalurnya mungkin seperti ini:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Pada NAS lain, misalnya:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Semua jalur tersebut hanya contoh. Ganti dengan direktori konfigurasi qBittorrent yang sebenarnya di host Anda.

#### Situasi 5: Menentukan folder pemasangan WebUI

Setelah memilih kontainer, Anda juga bisa menentukan lokasi WebUI yang ingin digunakan di dalamnya:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Pemasang akan mengubah jalur tersebut menjadi lokasi yang sesuai di host berdasarkan pemetaan Docker untuk `/config`.

#### Situasi 6: Memperbarui beberapa pemasangan sekaligus

Jika memiliki beberapa instans qBittorrent, Anda dapat mengulangi opsi `-o`. Berkas instalasi hanya diunduh dan diverifikasi satu kali; penggantian baru dimulai setelah semua tujuan selesai dipersiapkan. Setiap tujuan menyimpan **maksimal tiga cadangan terbaru secara terpisah** di `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Dalam mode beberapa tujuan, jangan tambahkan `-configure`. Setiap instans tetap menggunakan jalur WebUI alternatif yang telah diatur sebelumnya. Jalankan `sh install.sh -help` untuk melihat seluruh opsi.

#### Memeriksa jalur setelah pemasangan

Pemasangan yang berhasil mungkin menampilkan keluaran seperti ini:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: lokasi sebenarnya tempat berkas disimpan di host.
- `qBittorrent Root Folder`: jalur **di dalam kontainer** yang perlu dimasukkan ke kolom *Files location* qBittorrent.

Dengan `-configure`, pemasang akan mengaktifkan WebUI alternatif dan mengisi jalurnya jika konfigurasi qBittorrent dapat diidentifikasi dengan aman. Jika tidak, lakukan pengaturan manual sesuai panduan sebelumnya.

</details>

### Windows PowerShell

Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure

## Opsi yang sering digunakan

Linux dan Windows memakai nama yang sama untuk opsi umum. PowerShell tidak membedakan huruf besar dan kecil pada nama parameter.

| Keperluan | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Pasang versi stabil terbaru (`main`) | Bawaan, tanpa parameter | Bawaan, tanpa parameter |
| Pasang versi stabil tertentu | `-version 1.2.0` | `-version 1.2.0` |
| Pasang versi pengembangan | `-dev` | `-dev` |
| Tentukan direktori pemasangan | `-o /path` (bisa diulang di Linux) | `-o D:\path` atau `-output D:\path` |
| Tentukan berkas konfigurasi qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Atur qBittorrent secara otomatis | `-configure` | `-configure` |
| Kembalikan pemasangan sebelumnya | `-rollback` | `-rollback` |
| Hapus total beserta cadangan | `-uninstall -purge` | `-uninstall -purge` |
| Tampilkan bantuan lengkap | `-help` | `-help` |
| Pilih kontainer Docker | `--container=NAME` | — |
| Daftar kontainer Docker | `--list-containers` | — |
| Jalur host yang dipetakan sebagai `/config` | `--config-root=/path` | — |

<details>
<summary><b>Penjelasan opsi (klik untuk membuka)</b></summary>

- Tanpa `-dev`, pemasang menggunakan kanal stabil `main`; dengan `-dev`, pemasang menggunakan versi pengembangan dengan Git SHA yang tepat.
- Huruf `o` pada `-o` berarti **output**. Di Linux, opsi ini dapat diulang untuk memperbarui beberapa pemasangan dengan satu kali unduhan.
- Cadangan yang dikelola pemasang selalu disimpan di `~/.config/weig-qb-webui/backups/`, maksimal **tiga cadangan terbaru per tujuan**.
- `-configure` mengaktifkan *Use alternative WebUI* dan mengisi *Files location*, tetapi hanya boleh digunakan untuk satu tujuan.
- `-rollback` mengembalikan cadangan terbaru yang dibuat pemasang untuk tujuan terpilih; ulangi `-o` bila ingin memulihkan beberapa tujuan yang ditentukan.
- `-uninstall -purge` hanya menghapus cadangan dan status pemulihan **milik tujuan yang sedang dihapus**, tanpa menyentuh instalasi lain.
- Jika ingin menyimpan cadangan untuk menggunakan `-rollback` nanti, jangan gunakan `-purge`.
- Dengan `-version`, Anda dapat memasang GitHub Release tertentu, misalnya `1.2.0`. Jika versi tersebut tidak ada, pemasang akan gagal dan **tidak otomatis beralih** ke latest atau dev.
- Untuk beberapa kontainer, gunakan `--list-containers` lalu pilih dengan `--container=NAME`, atau tentukan folder `/config` di host melalui `--config-root=/path`.

### Menentukan versi dan direktori

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Mengembalikan pemasangan sebelumnya

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Menghapus WebUI dengan satu perintah

<details>
<summary><b>Penghapusan menyeluruh di Linux / NAS, Docker, dan Windows PowerShell</b></summary>

Biasanya kami menyarankan **menghapus WebUI tanpa menyimpan cadangan pemasang**. Perintah berikut akan menghapus WebUI, menonaktifkan antarmuka Web alternatif milik tujuan tersebut, membersihkan cadangan serta informasi pemulihannya, lalu menghapus skrip instalasi yang sudah diunduh di direktori saat ini.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Untuk lokasi khusus, tambahkan `-o /jalur/weig-qb-webui`.

### Docker

Satu kontainer dengan deteksi otomatis:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Jika ada beberapa kontainer:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Jika menggunakan `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Untuk direktori khusus, tambahkan `-o D:\weig-qb-webui`.

`-purge` hanya menghapus cadangan dari pemasangan yang sedang Anda hapus. Cadangan instans lainnya tetap aman. Jika direktori status bersama sudah kosong, `~/.config/weig-qb-webui` (untuk `root`: `/root/.config/weig-qb-webui`) di Linux atau `%APPDATA%\weig-qb-webui` di Windows juga akan dibersihkan.

Jika ingin menyimpan cadangan supaya nanti bisa menggunakan `-rollback`, jalankan penghapusan tanpa `-purge`.

</details>
