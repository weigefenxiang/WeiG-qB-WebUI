## Manuell installation för nybörjare

<details>
<summary><b>Installerar du för första gången? Öppna snabbguiden</b></summary>

### 1. Packa upp ZIP-filen

Ladda ned `weig-qb-webui.zip` och packa upp arkivet. Du får direkt en mapp med följande struktur:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Hela mappen `weig-qb-webui`** är webbgränssnittets rotmapp. Kopiera inte bara `public` eller `private`.

### 2. Välj en permanent plats

Flytta hela mappen till en plats där den inte riskerar att raderas av misstag, till exempel:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Det är den här mappen du sedan ska ange i qBittorrent.

### 3. Aktivera alternativt webbgränssnitt i qBittorrent

Öppna qBittorrent och gå till **Verktyg → Alternativ → Webbgränssnitt**. De exakta menytexterna kan skilja sig beroende på vilket språk qBittorrent använder.

1. Markera **Använd alternativt webbgränssnitt** (*Use alternative WebUI*).
2. Leta upp fältet **Filernas plats** (*Files location*).
3. Ange sökvägen till mappen `weig-qb-webui`.

Exempel för Windows:

```text
D:\weig-qb-webui
```

Exempel för Linux:

```text
/opt/weig-qb-webui
```

4. Klicka på **OK** för att spara.
5. Ladda om qBittorrents webbsida. Om det gamla gränssnittet fortfarande visas kan du trycka `Ctrl + F5` för att tvinga fram en ny inläsning.

> **Hur vet jag om sökvägen är rätt?** Du ska direkt kunna se `public`, `private` och `VERSION` i den valda mappen. Om du först behöver öppna ytterligare en mapp som heter `weig-qb-webui` har du valt fel nivå.

> **Om du använder Docker:** qBittorrent körs **inuti en container**. Ange därför en sökväg som är tillgänglig inifrån containern, inte bara en sökväg på värddatorn. Läs mer i Docker-avsnittet nedan.

</details>

## Installation med ett enda kommando

Installationsskriptet för Linux och NAS hämtas alltid från den fasta Dev Pages-adressen nedan. **Skriptets nedladdningsadress bestämmer inte vilken version som installeras:** utan `-dev` installeras den senast verifierade stabila GitHub-versionen; med `-dev` installeras utvecklingsversionen som identifieras med exakt Git SHA. Skriptet sparas i den aktuella mappen så att du kan återanvända det för uppdateringar och återställning.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Visa var skriptet sparas och standardmappen för installation</b></summary>

Det nedladdade skriptet ligger här:

```text
./install.sh
```

Webbgränssnittet installeras som standard i:

```text
~/.local/share/weig-qb-webui
```

Om kommandot körs som `root` blir sökvägen vanligtvis:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker-installation, flera containrar och sökvägar</b></summary>

#### Skillnaden mellan värddator och container

Om du kör Docker på en VPS, Linux-server, Synology, QNAP eller annan NAS:

- **Värddator (host):** Linux- eller NAS-systemet där Docker faktiskt körs, oftast det du ansluter till via SSH.
- **Container:** den avgränsade miljö där qBittorrent körs. Den kan bara se de kataloger som monterats in.

Anta att qBittorrents konfigurationsmapp är kopplad så här:

```text
Värd: /root/qbittorrent/config
   ↓ monteras som
I containern: /config
```

I Docker Compose brukar det se ut så här:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Sökvägen **före kolon** finns på **värddatorn**; sökvägen **efter kolon** är den som syns **inne i containern**.

Om WeiG finns installerat på värddatorn här:

```text
Värd: /root/qbittorrent/config/weig-qb-webui
```

ska du ange följande i qBittorrents fält **Files location**:

```text
/config/weig-qb-webui
```

**Ange inte `/root/qbittorrent/config/weig-qb-webui`** i qBittorrent. Den sökvägen finns på värddatorn och är normalt inte direkt tillgänglig för containern.

#### Fall 1: En enda qBittorrent-container

Kör:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Installationsprogrammet försöker hitta den aktiva qBittorrent-containern, dess `/config`-montering och motsvarande mapp på värddatorn. Om konfigurationen kan identifieras säkert ställer programmet även in qBittorrent.

#### Fall 2: Se vilka containrar som finns

Om du inte vet vad containern heter:

```sh
sh install.sh --list-containers
```

Du kan också kontrollera direkt med Docker:

```sh
docker ps
```

Om containern till exempel heter:

```text
qbittorrent
```

väljer du den uttryckligen:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Fall 3: Flera qBittorrent-containrar

Du kanske har en vanlig installation och en testinstans:

```text
qbittorrent
qbittorrent-test
```

Visa först listan:

```sh
sh install.sh --list-containers
```

Installera för den vanliga instansen:

```sh
sh install.sh --container=qbittorrent -configure
```

Installera för testinstansen:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Installationsprogrammet **väljer aldrig en slumpmässig container** när flera passar.

#### Fall 4: Du känner till värddatorns `/config`-mapp

Till exempel:

```text
/root/qbittorrent/config
```

Då kan du ange mappen direkt:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

På Synology kan sökvägen exempelvis vara:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

På en annan NAS kan den vara:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Dessa är bara exempel. Använd den verkliga sökvägen till qBittorrents konfigurationsmapp på din värddator.

#### Fall 5: Välj var WebUI ska installeras

När du har valt container kan du också ange önskad mapp inuti den:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Installationsprogrammet räknar ut motsvarande mapp på värddatorn utifrån Dockers `/config`-montering.

#### Fall 6: Uppdatera flera installationer på en gång

Om du hanterar flera qBittorrent-instanser kan du upprepa `-o`. Paketet laddas ned och verifieras bara en gång; alla mål förbereds innan något av dem byts ut. Varje mål sparar separat **sina tre senaste säkerhetskopior** under `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Lägg inte till `-configure` när du använder flera mål. Varje instans fortsätter att använda den tidigare inställda sökvägen till sitt alternativa webbgränssnitt. Kör `sh install.sh -help` för att se alla alternativ.

#### Kontrollera sökvägarna efter installation

En lyckad installation kan ge en utskrift som liknar:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: den verkliga platsen för filerna på värddatorn.
- `qBittorrent Root Folder`: sökvägen **inne i containern** som du ska skriva i qBittorrents fält *Files location*.

Med `-configure` kan installationsprogrammet aktivera det alternativa webbgränssnittet och fylla i sökvägen automatiskt, förutsatt att qBittorrent-konfigurationen kan identifieras utan tvekan. Annars gör du inställningen manuellt enligt guiden ovan.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

<summary><b>Visa installationsmappen</b></summary>

```text
C:\Users\<användarnamn>\AppData\Local\weig-qb-webui
```

</details>

## Vanliga parametrar

Linux och Windows använder samma namn på gemensamma parametrar. PowerShell skiljer inte på stora och små bokstäver i parameternamn.

| Syfte | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Senaste stabila versionen (`main`) | Standard, inga parametrar | Standard, inga parametrar |
| En viss stabil version | `-version 1.2.0` | `-version 1.2.0` |
| Utvecklingsversion | `-dev` | `-dev` |
| Välj installationsmapp | `-o /path` (kan upprepas på Linux) | `-o D:\path` eller `-output D:\path` |
| Ange qBittorrent-konfigurationsfil | — | `-qbconfig D:\path\qBittorrent.ini` |
| Konfigurera qBittorrent automatiskt | `-configure` | `-configure` |
| Återställ föregående installation | `-rollback` | `-rollback` |
| Avinstallera helt och ta bort säkerhetskopior | `-uninstall -purge` | `-uninstall -purge` |
| Visa fullständig hjälp | `-help` | `-help` |
| Välj Docker-container | `--container=NAME` | — |
| Lista Docker-containrar | `--list-containers` | — |
| Ange värddatorns `/config`-mapp | `--config-root=/path` | — |

<details>
<summary><b>Förklaring av parametrarna (visa)</b></summary>

- Utan `-dev` använder installationsprogrammet den stabila kanalen `main`; med `-dev` används utvecklingsversionen med exakt Git SHA.
- `o` i `-o` står för **output**. På Linux kan parametern upprepas för att uppdatera flera befintliga installationer med samma nedladdning.
- Installationsprogrammets säkerhetskopior lagras alltid under `~/.config/weig-qb-webui/backups/` och **högst tre senaste kopior per mål** behålls.
- `-configure` aktiverar *Use alternative WebUI* och anger *Files location*, men kan endast användas för ett enda mål.
- `-rollback` återställer den senaste säkerhetskopian som installationsprogrammet skapat för det valda målet. Upprepa `-o` för att återställa flera uttryckligen angivna mål.
- `-uninstall -purge` tar bara bort säkerhetskopior och återställningsinformation för **det aktuella målet**, inte för andra installationer.
- Vill du spara kopiorna för `-rollback` senare, utelämna `-purge`.
- Med `-version` väljer du en viss GitHub Release, till exempel `1.2.0`. Om den inte finns avbryts installationen med fel och **växlar inte automatiskt** till latest eller dev.
- Vid flera containrar kan du använda `--list-containers` och sedan `--container=NAME` för att välja en, eller ange värddatorns `/config`-mapp med `--config-root=/path`.

### Välj en särskild version och installationsmapp

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Återställning

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Avinstallation med ett enda kommando

<details>
<summary><b>Fullständig avinstallation på Linux / NAS, Docker och Windows PowerShell</b></summary>

Vi rekommenderar vanligtvis att **ta bort webbgränssnittet utan att behålla installationsprogrammets säkerhetskopior**. Kommandona avinstallerar WebUI, stänger av det alternativa webbgränssnittet för rätt mål, tar bort målets säkerhetskopior och återställningsinformation och raderar installationsskriptet från den aktuella mappen.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

För en egen installationsmapp lägger du till `-o /sokvag/weig-qb-webui`.

### Docker

En container med automatisk identifiering:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Flera containrar:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Med `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

För en egen mapp lägger du till `-o D:\weig-qb-webui`.

`-purge` tar endast bort säkerhetskopior som hör till installationen du avinstallerar. Andra instansers kopior påverkas inte. Om den gemensamma statusmappen blir tom tas även `~/.config/weig-qb-webui` på Linux (för `root`: `/root/.config/weig-qb-webui`) eller `%APPDATA%\weig-qb-webui` på Windows bort.

Om du vill behålla säkerhetskopiorna för att senare använda `-rollback`, kör du avinstallationen utan `-purge`.

</details>
