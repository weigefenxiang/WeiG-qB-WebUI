## Handmatig installeren voor beginners

<details>
<summary><b>Voor het eerst installeren? Open de handleiding van één minuut</b></summary>

### 1. Pak het ZIP-bestand uit

Download `weig-qb-webui.zip` en pak het uit. Je krijgt meteen de volgende mapstructuur:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

De **volledige map `weig-qb-webui`** is de hoofdmap van de webinterface. Kopieer niet alleen `public` of `private`.

### 2. Kies een vaste locatie

Verplaats de hele map naar een plek waar je deze niet per ongeluk verwijdert. Bijvoorbeeld:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Deze map selecteer je straks in qBittorrent.

### 3. Schakel de alternatieve webinterface in qBittorrent in

Open qBittorrent en ga naar **Extra → Opties… → Webinterface**. De precieze namen kunnen afwijken als qBittorrent in een andere taal is ingesteld.

1. Vink **Alternatieve webinterface gebruiken** (*Use alternative WebUI*) aan.
2. Zoek het veld **Bestandslocatie** (*Files location*).
3. Vul het pad naar de map `weig-qb-webui` in.

Voorbeeld voor Windows:

```text
D:\weig-qb-webui
```

Voorbeeld voor Linux:

```text
/opt/weig-qb-webui
```

4. Klik op **OK** om de instellingen op te slaan.
5. Vernieuw de webpagina van qBittorrent. Verschijnt nog de oude interface, druk dan op `Ctrl + F5` om de browsercache te omzeilen.

> **Hoe weet je of het pad klopt?** Je moet in de opgegeven map direct `public`, `private` en `VERSION` kunnen zien. Moet je eerst nog een extra map `weig-qb-webui` openen, dan heb je niet de juiste hoofdmap geselecteerd.

> **Let op bij Docker:** qBittorrent draait dan in een container. Gebruik een pad dat **binnen die container** bestaat; het pad op de hostcomputer is vaak niet rechtstreeks bereikbaar. Hieronder leggen we dit uit.

</details>

## Installeren met één opdracht

Het installatiescript voor Linux en NAS haal je altijd op via de vaste Dev Pages-link hieronder. **De URL van het script bepaalt niet welke versie wordt geïnstalleerd:** zonder `-dev` wordt de nieuwste gecontroleerde stabiele GitHub Release geïnstalleerd; met `-dev` wordt de ontwikkelversie met een exacte Git SHA gebruikt. Het script blijft in de huidige map staan, zodat je later kunt bijwerken of terugdraaien.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Bekijk waar het script staat en wat de standaardinstallatiemap is</b></summary>

Het gedownloade script heet:

```text
./install.sh
```

De webinterface wordt standaard geïnstalleerd in:

```text
~/.local/share/weig-qb-webui
```

Voer je het als `root` uit, dan is dat meestal:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker-installatie, meerdere containers en paden uitgelegd</b></summary>

#### Het verschil tussen host en container

Gebruik je Docker op een VPS, Linux-server, Synology, QNAP of een andere NAS, dan geldt:

- **Host**: het Linux- of NAS-systeem waarop Docker draait, bijvoorbeeld het systeem waarop je via SSH inlogt.
- **Container**: de afgescheiden omgeving waarin qBittorrent draait. qBittorrent ziet alleen paden die in de container beschikbaar zijn.

Stel dat je qBittorrent-container deze koppeling gebruikt:

```text
Host: /root/qbittorrent/config
   ↓ gekoppeld aan
In container: /config
```

In Docker Compose ziet dat er meestal zo uit:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Links van de dubbele punt staat de map op de **host**; rechts staat het pad **in de container**.

Als WeiG op de host is geïnstalleerd op:

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

dan vul je in qBittorrent bij **Files location** dit pad in:

```text
/config/weig-qb-webui
```

**Vul niet `/root/qbittorrent/config/weig-qb-webui` in.** Dat is het hostpad en de container kan dat meestal niet zien.

#### Situatie 1: één qBittorrent-container

Voer deze opdracht uit:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Het installatiescript probeert de actieve qBittorrent-container en diens `/config`-koppeling zelf te vinden. Als de bestemming duidelijk is, plaatst het de webinterface op de juiste hostlocatie en configureert het qBittorrent.

#### Situatie 2: bekijken welke containers er zijn

Als je niet weet hoe de container heet:

```sh
sh install.sh --list-containers
```

Je kunt ook rechtstreeks Docker gebruiken:

```sh
docker ps
```

Stel dat de container de volgende naam heeft:

```text
qbittorrent
```

Kies die dan expliciet:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Situatie 3: meerdere qBittorrent-containers

Bijvoorbeeld een gewone instantie en een testinstantie:

```text
qbittorrent
qbittorrent-test
```

Bekijk eerst de lijst:

```sh
sh install.sh --list-containers
```

Om de hoofdinstantie te installeren:

```sh
sh install.sh --container=qbittorrent -configure
```

Om de testinstantie te installeren:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Het installatiescript **kiest nooit zomaar één container** als er meerdere overeenkomen.

#### Situatie 4: je kent de hostmap van `/config`

Bijvoorbeeld:

```text
/root/qbittorrent/config
```

Dan kun je deze map rechtstreeks aangeven:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Op Synology kan het pad bijvoorbeeld zijn:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Op een andere NAS kan het pad er zo uitzien:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Dit zijn voorbeelden. Gebruik het werkelijke pad naar de qBittorrent-configuratiemap op jouw host.

#### Situatie 5: de map voor de webinterface kiezen

Heb je de container al geselecteerd, dan kun je ook de gewenste map in de container opgeven:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Het installatiescript vertaalt dit pad via de Docker-koppeling van `/config` naar de juiste map op de host.

#### Situatie 6: meerdere bestaande installaties in één keer bijwerken

Beheer je meerdere qBittorrent-instanties, dan kun je `-o` herhalen. Het pakket wordt maar één keer gedownload en gecontroleerd; pas nadat alle bestemmingen zijn voorbereid, worden ze vervangen. Per bestemming bewaart het installatiescript de **laatste drie back-ups** afzonderlijk onder `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Gebruik bij meerdere bestemmingen geen `-configure`. Elke instantie houdt het pad naar de alternatieve webinterface dat eerder is ingesteld. Alle opties vind je met `sh install.sh -help`.

#### De paden na de installatie controleren

Een geslaagde installatie kan bijvoorbeeld dit tonen:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: de werkelijke opslaglocatie op de host.
- `qBittorrent Root Folder`: het pad **in de container** dat je in qBittorrent bij *Files location* moet gebruiken.

Met `-configure` kan het installatiescript de alternatieve webinterface automatisch inschakelen en het pad instellen, maar alleen als het de juiste qBittorrent-configuratie zeker heeft gevonden. Anders kun je dit handmatig doen met de stappen bovenaan.

</details>

## Veelgebruikte parameters

Linux en Windows gebruiken dezelfde namen voor de algemene parameters. PowerShell maakt bij parameternamen geen onderscheid tussen hoofdletters en kleine letters.

| Actie | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Nieuwste stabiele versie (`main`) | Standaard, geen parameter nodig | Standaard, geen parameter nodig |
| Specifieke stabiele versie | `-version 1.2.0` | `-version 1.2.0` |
| Ontwikkelversie | `-dev` | `-dev` |
| Installatiemap kiezen | `-o /path` (herhaalbaar op Linux) | `-o D:\path` of `-output D:\path` |
| Aangepast qBittorrent-configuratiebestand | — | `-qbconfig D:\path\qBittorrent.ini` |
| qBittorrent automatisch configureren | `-configure` | `-configure` |
| Vorige installatie terugzetten | `-rollback` | `-rollback` |
| Volledig verwijderen, inclusief back-ups | `-uninstall -purge` | `-uninstall -purge` |
| Alle opties bekijken | `-help` | `-help` |
| Docker-container kiezen | `--container=NAME` | — |
| Docker-containers weergeven | `--list-containers` | — |
| Hostmap van Docker `/config` opgeven | `--config-root=/path` | — |

<details>
<summary><b>Toelichting bij de parameters (uitklappen)</b></summary>

- Zonder `-dev` gebruikt het installatiescript het stabiele kanaal `main`; met `-dev` de huidige ontwikkelversie met de exacte Git SHA.
- De `o` van `-o` staat voor **output**. Op Linux kun je die parameter herhalen om meerdere bestaande installaties met één download bij te werken.
- Back-ups van het installatiescript staan altijd onder `~/.config/weig-qb-webui/backups/`. Per doel worden maximaal **drie recente back-ups** bewaard.
- `-configure` schakelt *Use alternative WebUI* in en stelt *Files location* in, maar is alleen voor één bestemming toegestaan.
- `-rollback` herstelt de laatste back-up die het installatiescript voor het gekozen doel heeft gemaakt. Je kunt `-o` herhalen om meerdere expliciet opgegeven doelen terug te zetten.
- `-uninstall -purge` ruimt alleen de back-ups en herstelstatus van **de betreffende installatie** op; andere installaties worden niet aangeraakt.
- Wil je de back-ups bewaren voor een eventuele `-rollback`, laat `-purge` dan weg.
- Met `-version` installeer je een specifieke GitHub Release, bijvoorbeeld `1.2.0`. Bestaat die versie niet, dan stopt de installatie met een fout: er wordt **niet automatisch overgeschakeld naar latest of dev**.
- Bij meerdere Docker-containers kun je `--list-containers` gebruiken en met `--container=NAME` de juiste aanwijzen, of met `--config-root=/path` de hostmap van de configuratie opgeven.

### Een specifieke versie en installatiemap

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Een installatie terugzetten

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Verwijderen met één opdracht

<details>
<summary><b>Volledig verwijderen op Linux / NAS, Docker en Windows PowerShell</b></summary>

We raden aan om standaard **ook de back-ups van het installatiescript op te ruimen**: de webinterface wordt verwijderd, de alternatieve webinterface van het gekozen doel wordt uitgeschakeld, de bijbehorende back-ups en herstelstatus worden opgeruimd en het script in de huidige map wordt gewist.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Voor een andere installatiemap voeg je `-o /pad/weig-qb-webui` toe.

### Docker

Eén container met automatische detectie:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Meerdere containers:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Met `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Voor een aangepaste map voeg je `-o D:\weig-qb-webui` toe.

`-purge` wist uitsluitend back-ups van de installatie die je verwijdert. Back-ups van andere instanties blijven behouden. Is de gedeelde statusmap verder leeg, dan wordt ook `~/.config/weig-qb-webui` (voor `root`: `/root/.config/weig-qb-webui`) of op Windows `%APPDATA%\weig-qb-webui` opgeruimd.

Wil je de back-ups bewaren om later `-rollback` te gebruiken, verwijder de webinterface dan zonder `-purge`.

</details>
