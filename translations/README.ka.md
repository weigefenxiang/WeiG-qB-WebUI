რამდენიმე დამოუკიდებელ qBittorrent ინსტანციას შეუძლია ერთი და იგივე მომზადებული WeiG საქაღალდის **მხოლოდ წაკითხვის რეჟიმში** გამოყენება. ჰოსტის საქაღალდე მიამაგრეთ თითოეულ Docker კონტეინერს, მაგალითად `/root/weig-qb-webui:/weig-qb-webui:ro`, შემდეგ ყოველი qBittorrent ინსტანციის Alternative WebUI-ის ძირად მიუთითეთ `/weig-qb-webui`. თითოეულ ინსტანციას საკუთარი torrent მონაცემთა ბაზა, პარამეტრები და ავტორიზაცია უნარჩუნდება.

გვერდითი პანელის **Instances** სექციაში შეგიძლიათ დაამატოთ ინსტანციები, გადაერთოთ მათ სრულ გვერდებზე და გადაარქვათ სახელები (მარჯვენა ღილაკით ან სტრიქონის მენიუდან). მიმდინარე ინსტანციას შეგიძლიათ უწოდოთ, მაგალითად, `524 (current)`; მიმდინარე სტატუსის მაჩვენებელი რეალურ URL-ს ეფუძნება და არა შენახული სახელის დაბოლოებას. ავტომატური შემოწმების ინტერვალი განისაზღვრება **Settings → WeiG WebUI → Interface** განყოფილებაში; ნაგულისხმევია `30 min`, შესაძლებელი არის გამორთვა ან 5–1440 წუთის არჩევა.

### 1. ZIP ფაილის ამოღება

ჩამოტვირთეთ `weig-qb-webui.zip` და გაშალეთ. არქივი უკვე შეიცავს სტანდარტულ საქაღალდეს:

```text

├── public/
├── private/
├── VERSION
└── GIT_SHA
```

მთლიანი **`weig-qb-webui` საქაღალდე** WebUI-ის ძირია. მხოლოდ `public` ან `private` არ დააკოპიროთ.

### 2. მუდმივ ადგილას გადატანა

მთლიანი `weig-qb-webui` საქაღალდე გადაიტანეთ მუდმივ ადგილას, საიდანაც მას შემთხვევით არ წაშლით, მაგალითად:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

სწორედ ეს საქაღალდე უნდა მიუთითოთ qBittorrent-ში.

### 3. qBittorrent-ში ჩართვა

გახსენით qBittorrent:

**Tools → Options... → WebUI**

ეს qBittorrent-ის მიმდინარე ინგლისური ინტერფეისის ტერმინებია. შემდეგ:

1. ჩართეთ **Use alternative WebUI**.
2. იპოვეთ **Files location:** ველი.
3. შეიყვანეთ `weig-qb-webui` საქაღალდის გზა.

Windows-ის მაგალითი:

```text
D:\weig-qb-webui
```

Linux-ის ჩვეულებრივი მაგალითი:

```text
/opt/weig-qb-webui
```

4. შესანახად დააჭირეთ **OK**.
5. განაახლეთ qBittorrent WebUI-ის გვერდი. თუ ბრაუზერში კვლავ ქეშირებული ძველი გვერდი ჩანს, ერთხელ სცადეთ `Ctrl + F5`.

> **როგორ შევამოწმოთ გზა?** მითითებული საქაღალდე უშუალოდ უნდა შეიცავდეს `public`, `private`, `VERSION` და WebUI-ის სხვა ფაილებს. თუ მათ სანახავად კიდევ ერთ `weig-qb-webui` საქაღალდეში შესვლა გჭირდებათ, გზა ერთი დონით აცდენილია.

> **Docker-ის მომხმარებლებისთვის:** qBittorrent კონტეინერში მუშაობს, ამიტომ ჰოსტის გზას პირდაპირ ჩვეულებრივ ვერ გამოიყენებთ. ჰოსტისა და კონტეინერის გზების განსხვავების გასაგებად იხილეთ ქვემოთ მოცემული **Docker** გზამკვლევი.

### Docker

<details>
<summary><b>Docker-ის ინსტალაცია ერთი ბრძანებით / რამდენიმე კონტეინერი / გზების გზამკვლევი (რეკომენდებულია დამწყებთათვის)</b></summary>

#### ჯერ გაიგეთ „ჰოსტი“ და „კონტეინერი“

თუ qBittorrent მუშაობს Docker-ში VPS-ზე, Linux სერვერზე, Synology-ზე, QNAP-ზე ან სხვა NAS-ზე:

- **ჰოსტი**: რეალური Linux/NAS მანქანა, რომელზეც Docker მუშაობს — სისტემა, რომელსაც SSH-ით შესვლის შემდეგ ხედავთ.
- **კონტეინერი**: Docker-ის მიერ qBittorrent-ისთვის შექმნილი იზოლირებული გარემო. qBittorrent უშუალოდ ხედავს კონტეინერის გზებს და არა ჰოსტის ნებისმიერ გზას.

მაგალითად, თქვენს qBittorrent კონტეინერს შეიძლება ჰქონდეს ასეთი დაკავშირება:

```text
Host:      /root/qbittorrent/config
   ↓ mapped to
Container: /config
```

Docker Compose-ის ტიპური ჩანაწერი ასე გამოიყურება:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

ორწერტილის მარცხნივ `/root/qbittorrent/config` არის **ჰოსტის გზა**, მარჯვნივ `/config` კი **კონტეინერის გზა**.

თუ WeiG qB WebUI ფიზიკურად აქ არის დაყენებული:

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

მაშინ qBittorrent-ის **Files location:** ველში უნდა მიუთითოთ:

```text
/config/weig-qb-webui
```

**qBittorrent-ში არ შეიყვანოთ `/root/qbittorrent/config/weig-qb-webui`**, რადგან კონტეინერი ჩვეულებრივ ვერ ხედავს უშუალოდ ჰოსტის ამ გზას.

#### შემთხვევა 1: მუშაობს qBittorrent-ის ერთი კონტეინერი

გამოიყენეთ ინსტალაციის ჩვეულებრივი ერთბრძანებიანი ვარიანტი:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

ინსტალატორი შეეცდება აღმოაჩინოს გაშვებული qBittorrent კონტეინერი, მისი `/config` დამაკავშირებელი გზა, WebUI დააყენოს შესაბამის ჰოსტზე და ავტომატურად გამართოს qBittorrent.

#### შემთხვევა 2: ჯერ იპოვეთ qBittorrent კონტეინერის სახელი

თუ კონტეინერის სახელი არ იცით:

```sh
sh install.sh --list-containers
```

შეგიძლიათ Docker პირდაპირაც გამოიყენოთ:

```sh
docker ps
```

თუ qBittorrent კონტეინერის სახელია:

```text
qbittorrent
```

აირჩიეთ ის აშკარად:

```sh
sh install.sh --container=qbittorrent -configure
```

#### შემთხვევა 3: qBittorrent-ის რამდენიმე კონტეინერი

მაგალითად:

```text
qbittorrent
qbittorrent-test
```

ჯერ მიიღეთ მათი სია:

```sh
sh install.sh --list-containers
```

ძირითადი `qbittorrent` კონტეინერისთვის:

```sh
sh install.sh --container=qbittorrent -configure
```

სატესტო კონტეინერისთვის:

```sh
sh install.sh --container=qbittorrent-test -configure
```

რამდენიმე qBittorrent კონტეინერის შემთხვევაში ინსტალატორი ჩუმად შემთხვევითს არ აირჩევს.

#### შემთხვევა 4: უკვე იცით ჰოსტის საქაღალდე, რომელიც მიერთებულია როგორც `/config`

მაგალითად:

```text
/root/qbittorrent/config
```

პირდაპირ მიუთითეთ:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Synology-ის გზა შეიძლება ასე გამოიყურებოდეს:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

სხვა NAS-ზე, მაგალითად:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

ეს მხოლოდ მაგალითებია. **შეცვალეთ ისინი ჰოსტის რეალური გზით, რომელიც qBittorrent-ის `/config`-ად არის მიერთებული.**

#### შემთხვევა 5: აირჩიეთ WebUI-ის ინსტალაციის გზა

კონტეინერის არჩევის შემდეგ შეგიძლიათ მიუთითოთ WebUI-ის გზა, რომელიც თავად კონტეინერისთვის ჩანს:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

ინსტალატორი კონტეინერის `/config/...` გზას შესაბამის ჰოსტის ინსტალაციის გზად გარდაქმნის.

#### შემთხვევა 6: რამდენიმე WebUI საქაღალდის განახლება ერთი ჩამოტვირთვით

qBittorrent-ის რამდენიმე ინსტანციისთვის გაიმეორეთ `-o`. პაკეტი მხოლოდ ერთხელ იტვირთება და მოწმდება, ყველა სამიზნე მზადდება შეცვლამდე და თითოეული სამიზნე ცალკე ინახავს ბოლო სამ სარეზერვო ასლს `~/.config/weig-qb-webui/backups/` საქაღალდეში.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

მრავალსამიზნიან რეჟიმში არ დაამატოთ `-configure` — qBittorrent-ის თითოეული ინსტანცია ინარჩუნებს თავის არსებულ Alternative WebUI-ის ძირეულ საქაღალდეს. მიმდინარე ბრძანებების სინტაქსის სანახავად გაუშვით `sh install.sh -help`.

#### რა გამოჩნდება ინსტალაციის შემდეგ?

წარმატებული ინსტალაცია დაახლოებით ასეთ ინფორმაციას აჩვენებს:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

მნიშვნელობა:

- `Host install path`: ჰოსტზე ფაილების რეალური მდებარეობა;
- `qBittorrent Root Folder`: **კონტეინერის გზა, რომელიც qBittorrent-მა უნდა გამოიყენოს Files location ველში**.

თუ `-configure` წარმატებით პოულობს qBittorrent-ის კონფიგურაციას, ინსტალატორი ავტომატურად რთავს **Use alternative WebUI**-ს და უთითებს გზას. წინააღმდეგ შემთხვევაში მიჰყევით ზედა სექციას **ინსტალაცია ახალი მომხმარებლებისთვის → qBittorrent-ში ჩართვა**.

</details>

Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure

## ძირითადი პარამეტრები
Linux და Windows შეძლებისდაგვარად იყენებენ ერთსა და იმავე საჯარო პარამეტრების სახელებს. დოკუმენტაციაში გამოიყენება პატარა ასოები; PowerShell პარამეტრების სახელებში დიდი და პატარა ასოები არ განირჩევა.

| დანიშნულება | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| სტაბილური main | ნაგულისხმევი, პარამეტრის გარეშე | ნაგულისხმევი, პარამეტრის გარეშე |
| კონკრეტული გამოშვება | `-version 1.2.0` | `-version 1.2.0` |
| განვითარების ვერსია | `-dev` | `-dev` |
| ინსტალაციის საკუთარი საქაღალდე | `-o /path` (Linux-ზე შეიძლება გამეორება) | `-o D:\path` ან `-output D:\path` |
| qBittorrent-ის საკუთარი კონფიგურაციის ფაილი | — | `-qbconfig D:\path\qBittorrent.ini` |
| qBittorrent-ის ავტომატური გამართვა | `-configure` | `-configure` |
| წინა ინსტალაციაზე დაბრუნება | `-rollback` | `-rollback` |
| სრული წაშლა (სარეზერვო ასლების გარეშე) | `-uninstall -purge` | `-uninstall -purge` |
| სრული დახმარება | `-help` | `-help` |
| Docker კონტეინერის არჩევა | `--container=NAME` | — |
| Docker კონტეინერების ჩამონათვალი | `--list-containers` | — |
| Docker-ის `/config`-ად მიერთებული ჰოსტის საქაღალდე | `--config-root=/path` | — |

<details>
<summary><b>შენიშვნები (გასაშლელად დააჭირეთ)</b></summary>

შენიშვნები:

- `-dev`-ის გარეშე გამოიყენება სტაბილური `main`; `-dev` ირჩევს განვითარების მიმდინარე ვერსიის ზუსტ Git SHA-ს.
- `-o` ნიშნავს **output**-ს და განსაზღვრავს WeiG qB WebUI-ის ინსტალაციის საქაღალდეს. Linux-ზე მისი გამეორება შეიძლება რამდენიმე სამიზნის ერთი შემოწმებული ჩამოტვირთვით განახლებისთვის.
- ინსტალატორის სარეზერვო ასლები ინახება `~/.config/weig-qb-webui/backups/`-ში; ბოლო **3 ასლი თითოეული სამიზნისთვის ცალკე ინახება**.
- `-configure` qBittorrent-ში რთავს **Use alternative WebUI**-ს და ინსტალაციის შემდეგ ადგენს **Files location**-ს. ეს მხოლოდ ერთი სამიზნისთვისაა განკუთვნილი.
- `-rollback` აღადგენს არჩეული სამიზნის ინსტალატორის ბოლო სარეზერვო ასლს; რამდენიმე განსაზღვრული სამიზნის დასაბრუნებლად გაიმეორეთ `-o`.
- `-version` აყენებს GitHub Release-ის ზუსტ ვერსიას, მაგალითად `1.2.0`. თუ მოთხოვნილი ვერსია არ არსებობს, ინსტალაცია ფუჭდება და **არ გადადის ავტომატურად latest-ზე ან dev-ზე**.
- `-help` აჩვენებს Linux-ის მიმდინარე მხარდაჭერილი ბრძანებების სინტაქსს.
- Docker-ში qBittorrent-ის რამდენიმე კონტეინერისას გამოიყენეთ `--list-containers`, შემდეგ აირჩიეთ ერთი `--container=NAME`-ით. ჰოსტის კონფიგურაციის საქაღალდის ცოდნის შემთხვევაში შეგიძლიათ გამოიყენოთ `--config-root=/path`-იც.

Windows:

## წაშლა ერთი ბრძანებით

<details>
<summary><b>სრული წაშლა Linux / NAS, Docker და Windows PowerShell სისტემებისთვის</b></summary>

ქვემოთ რეკომენდებული ბრძანება სრულად შლის პროგრამას **ინსტალატორის სარეზერვო ასლების შენარჩუნების გარეშე**: შლის WebUI-ს, თიშავს შესაბამის Alternative WebUI-ის კონფიგურაციას, ასუფთავებს ამ სამიზნის ინსტალატორის სარეზერვო ასლებსა და დაბრუნების მდგომარეობას, შემდეგ მიმდინარე საქაღალდიდან შლის ჩამოტვირთულ ინსტალაციის სკრიპტს.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

ინსტალაციის განსხვავებული საქაღალდისთვის დაამატეთ `-o /path/to/weig-qb-webui`.

### Docker

ერთი კონტეინერი / ავტომატური აღმოჩენა:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

რამდენიმე კონტეინერი:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

`--config-root`-ის გამოყენებისას:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

ინსტალაციის განსხვავებული საქაღალდისთვის დაამატეთ `-o D:\weig-qb-webui`.

`-purge` შლის მხოლოდ მიმდინარე სამიზნის სარეზერვო ასლებს და არ ეხება სხვა ინსტალაციებს. როდესაც საერთო მდგომარეობის საქაღალდე ცარიელდება, Linux-ის `~/.config/weig-qb-webui` (root-ისთვის: `/root/.config/weig-qb-webui`) ან Windows-ის `%APPDATA%\weig-qb-webui` საქაღალდეც იშლება.

თუ მომავალში `-rollback`-ისთვის გსურთ სარეზერვო ასლების შენარჩუნება, უბრალოდ გამოტოვეთ `-purge`.

</details>
