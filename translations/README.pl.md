## Ręczna instalacja dla początkujących

<details>
<summary><b>Instalujesz po raz pierwszy? Rozwiń krótką instrukcję</b></summary>

### 1. Rozpakuj archiwum ZIP

Pobierz `weig-qb-webui.zip` i rozpakuj je. W środku znajduje się folder o następującej strukturze:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Cały folder `weig-qb-webui`** jest katalogiem głównym interfejsu. Nie kopiuj oddzielnie samych folderów `public` ani `private`.

### 2. Wybierz stałą lokalizację

Przenieś cały folder do miejsca, z którego nie zostanie przypadkowo usunięty, na przykład:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

To właśnie ten katalog wskażesz później w ustawieniach qBittorrent.

### 3. Włącz alternatywny interfejs WWW w qBittorrent

Otwórz **Narzędzia → Opcje → Interfejs WWW**. Nazwy opcji mogą się nieco różnić w zależności od języka ustawionego w qBittorrent.

1. Zaznacz **Użyj alternatywnego interfejsu WWW** (*Use alternative WebUI*).
2. Znajdź pole **Lokalizacja plików** (*Files location*).
3. Wpisz ścieżkę do folderu `weig-qb-webui`.

Przykład dla Windows:

```text
D:\weig-qb-webui
```

Przykład dla Linux:

```text
/opt/weig-qb-webui
```

4. Kliknij **OK**, aby zapisać ustawienia.
5. Odśwież stronę qBittorrent. Jeśli nadal widzisz poprzedni interfejs, naciśnij `Ctrl + F5`, aby wymusić ponowne pobranie strony.

> **Jak sprawdzić ścieżkę?** W wybranym katalogu muszą znajdować się bezpośrednio `public`, `private` i `VERSION`. Jeśli trzeba wejść jeszcze do kolejnego folderu `weig-qb-webui`, wybrany katalog jest o jeden poziom za wysoko.

> **Uwaga dla użytkowników Docker:** qBittorrent działa **wewnątrz kontenera**. W ustawieniach podaj ścieżkę widoczną z kontenera, a nie ścieżkę dostępną wyłącznie na hoście. Szczegóły znajdziesz poniżej.

</details>

## Instalacja jednym poleceniem

Skrypt instalacyjny dla Linux i NAS jest zawsze pobierany ze stałego adresu Dev Pages podanego niżej. **Sam adres skryptu nie decyduje o kanale instalacji:** bez `-dev` instalowana jest najnowsza zweryfikowana stabilna wersja z GitHub Releases; z `-dev` instalowana jest wersja rozwojowa wskazana dokładnym Git SHA. Skrypt pozostaje w bieżącym katalogu, więc można go użyć do aktualizacji i przywracania wcześniejszej wersji.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Sprawdź lokalizację skryptu i domyślny katalog instalacji</b></summary>

Pobrany skrypt znajduje się tutaj:

```text
./install.sh
```

Domyślny katalog instalacji interfejsu:

```text
~/.local/share/weig-qb-webui
```

Przy uruchomieniu jako `root` jest to zwykle:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Instalacja w Dockerze, wiele kontenerów i ścieżki</b></summary>

#### Host a kontener — na czym polega różnica?

Jeśli używasz Dockera na VPS, serwerze Linux, Synology, QNAP lub innym NAS:

- **Host** to system Linux lub NAS, na którym działa Docker; zwykle właśnie do niego łączysz się przez SSH.
- **Kontener** to odizolowane środowisko uruchamiające qBittorrent. Widzi tylko katalogi, które zostały do niego podłączone.

Przykładowo katalog konfiguracji może być podłączony w następujący sposób:

```text
Host: /root/qbittorrent/config
   ↓ mapowanie na
W kontenerze: /config
```

W Docker Compose zwykle zapisuje się to tak:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Ścieżka **przed dwukropkiem** należy do **hosta**, a ścieżka **po dwukropku** jest widoczna **wewnątrz kontenera**.

Jeżeli WeiG jest zainstalowany na hoście tutaj:

```text
Host: /root/qbittorrent/config/weig-qb-webui
```

to w polu **Files location** w qBittorrent należy wpisać:

```text
/config/weig-qb-webui
```

**Nie wpisuj `/root/qbittorrent/config/weig-qb-webui`** — to ścieżka na hoście, której kontener zazwyczaj nie widzi bezpośrednio.

#### Przypadek 1: Jeden kontener qBittorrent

Uruchom:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Instalator spróbuje wykryć działający kontener qBittorrent, jego mapowanie `/config` i odpowiednią lokalizację na hoście. Jeśli uda się jednoznacznie rozpoznać konfigurację, może również automatycznie skonfigurować qBittorrent.

#### Przypadek 2: Nie znasz nazwy kontenera

Wyświetl listę dostępnych kontenerów:

```sh
sh install.sh --list-containers
```

Możesz też skorzystać bezpośrednio z Dockera:

```sh
docker ps
```

Jeśli kontener nazywa się na przykład:

```text
qbittorrent
```

wybierz go jawnie:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Przypadek 3: Masz kilka kontenerów qBittorrent

Załóżmy, że korzystasz z instancji głównej i testowej:

```text
qbittorrent
qbittorrent-test
```

Najpierw sprawdź listę:

```sh
sh install.sh --list-containers
```

Aby zainstalować interfejs w instancji głównej:

```sh
sh install.sh --container=qbittorrent -configure
```

Aby zainstalować go w instancji testowej:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Instalator **nie wybiera losowego kontenera**, jeśli znajdzie więcej niż jeden pasujący.

#### Przypadek 4: Znasz katalog `/config` na hoście

Na przykład:

```text
/root/qbittorrent/config
```

Możesz podać go bezpośrednio:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Na serwerze Synology ścieżka może wyglądać tak:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Na innym NAS może to być:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

To jedynie przykłady. Podstaw rzeczywistą ścieżkę do katalogu konfiguracji qBittorrent na swoim hoście.

#### Przypadek 5: Wybierz katalog dla WebUI

Po wskazaniu kontenera możesz również określić docelową ścieżkę w jego wnętrzu:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Instalator przeliczy ją na właściwą lokalizację na hoście za pomocą mapowania `/config` w Dockerze.

#### Przypadek 6: Aktualizacja kilku instalacji jednocześnie

Jeżeli zarządzasz kilkoma instancjami qBittorrent, możesz powtórzyć opcję `-o`. Pakiet jest pobierany i weryfikowany tylko raz. Żadna instalacja nie zostanie zastąpiona, zanim wszystkie miejsca docelowe nie będą gotowe. Dla każdego celu przechowywane są osobno **trzy ostatnie kopie zapasowe** w `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Nie używaj opcji `-configure` przy wielu miejscach docelowych. Każda instancja powinna zachować wcześniej ustawioną ścieżkę alternatywnego WebUI. Pełną pomoc wyświetlisz poleceniem `sh install.sh -help`.

#### Sprawdzanie ścieżek po instalacji

Poprawna instalacja może zwrócić wynik podobny do poniższego:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: rzeczywisty katalog plików na hoście.
- `qBittorrent Root Folder`: ścieżka **wewnątrz kontenera**, którą należy wpisać w pole *Files location* w qBittorrent.

Z opcją `-configure` instalator włączy alternatywny interfejs i ustawi jego ścieżkę, jeśli potrafi bezpiecznie zidentyfikować konfigurację qBittorrent. W przeciwnym razie wykonaj opisane wyżej kroki ręczne.

</details>

## Najczęściej używane opcje

Ogólne nazwy opcji są takie same na Linux i Windows; PowerShell nie rozróżnia wielkich i małych liter w nazwach parametrów.

| Działanie | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Instalacja najnowszej wersji stabilnej (`main`) | Domyślnie, bez parametrów | Domyślnie, bez parametrów |
| Instalacja określonej wersji stabilnej | `-version 1.2.0` | `-version 1.2.0` |
| Instalacja wersji rozwojowej | `-dev` | `-dev` |
| Określenie katalogu instalacji | `-o /path` (można powtarzać w Linux) | `-o D:\path` lub `-output D:\path` |
| Wskazanie konfiguracji qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Automatyczna konfiguracja qBittorrent | `-configure` | `-configure` |
| Przywrócenie poprzedniej instalacji | `-rollback` | `-rollback` |
| Odinstalowanie wraz z kopiami zapasowymi | `-uninstall -purge` | `-uninstall -purge` |
| Wyświetlenie pełnej pomocy | `-help` | `-help` |
| Wybór kontenera Docker | `--container=NAME` | — |
| Lista kontenerów Docker | `--list-containers` | — |
| Podanie katalogu `/config` na hoście | `--config-root=/path` | — |

<details>
<summary><b>Objaśnienie opcji (rozwiń)</b></summary>

- Bez `-dev` instalator korzysta z kanału stabilnego `main`; z `-dev` z wersji rozwojowej o dokładnym Git SHA.
- Litera `o` w `-o` oznacza **output**. W Linux można powtórzyć tę opcję, aby jedną pobraną paczką zaktualizować kilka istniejących instalacji.
- Kopie zapasowe instalatora znajdują się w `~/.config/weig-qb-webui/backups/`. Dla każdego miejsca docelowego przechowywane są **maksymalnie trzy najnowsze kopie**.
- `-configure` włącza *Use alternative WebUI* i ustawia *Files location*, ale można jej używać tylko dla jednego miejsca docelowego.
- `-rollback` przywraca ostatnią kopię zapasową utworzoną przez instalator dla wybranego celu; powtórzenie `-o` umożliwia przywracanie kilku jawnie wskazanych miejsc.
- `-uninstall -purge` usuwa kopie zapasowe i informacje przywracania **wyłącznie danego celu**, nie ruszając innych instalacji.
- Aby zachować kopie na wypadek przyszłego użycia `-rollback`, pomiń `-purge`.
- `-version` instaluje określoną wersję z GitHub Releases, na przykład `1.2.0`. Jeśli taka wersja nie istnieje, instalacja kończy się błędem — **bez automatycznego przełączenia** na latest lub dev.
- Przy kilku kontenerach wyświetl listę przez `--list-containers` i wybierz odpowiedni przez `--container=NAME` albo wskaż katalog hosta `/config` za pomocą `--config-root=/path`.

### Określenie wersji i katalogu instalacji

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Przywrócenie poprzedniej instalacji

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Odinstalowanie jednym poleceniem

<details>
<summary><b>Pełne odinstalowanie na Linux, NAS, Dockerze i Windows PowerShell</b></summary>

Zwykle zalecamy **usunięcie interfejsu bez zachowywania kopii zapasowych instalatora**. Polecenia poniżej usuwają WebUI, wyłączają alternatywny interfejs dla wskazanego celu, usuwają jego kopie zapasowe i informacje o przywracaniu, a także kasują pobrany skrypt instalacyjny z bieżącego katalogu.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Dla niestandardowego katalogu dodaj `-o /sciezka/weig-qb-webui`.

### Docker

Jeden kontener, wykrywanie automatyczne:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Kilka kontenerów:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Z opcją `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Dla niestandardowego katalogu dodaj `-o D:\weig-qb-webui`.

Opcja `-purge` usuwa tylko kopie zapasowe tej instalacji, którą odinstalowujesz. Nie wpływa na inne instancje. Jeśli wspólny katalog danych instalatora stanie się pusty, usuwany jest również `~/.config/weig-qb-webui` na Linux (dla `root`: `/root/.config/weig-qb-webui`) albo `%APPDATA%\weig-qb-webui` na Windows.

Aby zachować kopie zapasowe na potrzeby przyszłego `-rollback`, odinstaluj bez `-purge`.

</details>
