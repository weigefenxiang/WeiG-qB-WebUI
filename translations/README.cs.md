## Ruční instalace pro začátečníky

<details>
<summary><b>Instalujete poprvé? Otevřete krátký návod</b></summary>

### 1. Rozbalte ZIP archiv

Stáhněte `weig-qb-webui.zip` a rozbalte jej. Archiv již obsahuje následující strukturu složek:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Celá složka `weig-qb-webui`** je kořenovým adresářem webového rozhraní. Nekopírujte pouze `public` nebo `private`.

### 2. Vyberte trvalé umístění

Přesuňte celou složku na místo, odkud ji omylem nesmažete, například:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Právě tuto složku následně zadáte do nastavení qBittorrent.

### 3. Aktivujte alternativní WebUI v qBittorrent

Otevřete **Nástroje → Možnosti → Webové rozhraní**. Názvy položek se mohou mírně lišit podle jazyka nastaveného v qBittorrent.

1. Zaškrtněte **Použít alternativní webové rozhraní** (*Use alternative WebUI*).
2. Najděte pole **Umístění souborů** (*Files location*).
3. Zadejte cestu ke složce `weig-qb-webui`.

Příklad pro Windows:

```text
D:\weig-qb-webui
```

Příklad pro Linux:

```text
/opt/weig-qb-webui
```

4. Kliknutím na **OK** uložte změny.
5. Znovu načtěte webovou stránku qBittorrent. Pokud se stále zobrazuje původní vzhled, použijte `Ctrl + F5` pro vynucené obnovení.

> **Jak ověřit správnost cesty?** Ve zvolené složce musí být přímo vidět `public`, `private` a `VERSION`. Pokud musíte nejprve otevřít ještě jednu složku `weig-qb-webui`, vybrali jste nesprávnou úroveň adresáře.

> **Používáte Docker?** qBittorrent běží **uvnitř kontejneru**. Do jeho nastavení proto musíte zadat cestu dostupnou v kontejneru, nikoli cestu platnou jen na hostitelském systému. Vysvětlení je níže.

</details>

## Instalace jediným příkazem

Instalační skript pro Linux a NAS se vždy stahuje z pevné adresy Dev Pages níže. **Adresa skriptu neurčuje instalační kanál:** bez `-dev` se nainstaluje poslední ověřené stabilní vydání GitHub Release; s `-dev` se použije vývojová verze určená přesným Git SHA. Skript zůstává v aktuální složce pro pozdější aktualizaci nebo návrat k předchozí instalaci.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Zobrazit umístění skriptu a výchozí instalační složky</b></summary>

Stažený skript je uložen zde:

```text
./install.sh
```

Výchozí instalační adresář WebUI:

```text
~/.local/share/weig-qb-webui
```

Při spuštění pod uživatelem `root` to obvykle bývá:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Instalace v Dockeru, více kontejnerů a správné cesty</b></summary>

#### Hostitelský systém versus kontejner

Pokud používáte Docker na VPS, serveru Linux, Synology, QNAP nebo jiném NAS:

- **Hostitel (host)** je systém Linux nebo NAS, na němž běží Docker. Obvykle se na něj přihlašujete přes SSH.
- **Kontejner (container)** je oddělené prostředí, v němž běží qBittorrent. Vidí jen adresáře, které jsou do něj připojené.

Představme si toto připojení konfigurační složky:

```text
Hostitel: /root/qbittorrent/config
   ↓ připojeno jako
Uvnitř kontejneru: /config
```

V Docker Compose bývá zapsáno takto:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Cesta **vlevo od dvojtečky** patří **hostiteli**; cesta **vpravo** označuje umístění **uvnitř kontejneru**.

Pokud je WeiG na hostiteli nainstalován zde:

```text
Hostitel: /root/qbittorrent/config/weig-qb-webui
```

do pole **Files location** v qBittorrent zadejte:

```text
/config/weig-qb-webui
```

**Nezadávejte `/root/qbittorrent/config/weig-qb-webui`**. To je cesta na hostiteli, kterou kontejner obvykle přímo nevidí.

#### Případ 1: Máte pouze jeden kontejner qBittorrent

Spusťte:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Instalátor se pokusí najít běžící kontejner qBittorrent, připojení `/config` a odpovídající adresář na hostiteli. Pokud konfiguraci bezpečně rozpozná, nastaví qBittorrent automaticky.

#### Případ 2: Neznáte název kontejneru

Vypište dostupné kontejnery:

```sh
sh install.sh --list-containers
```

Nebo je zkontrolujte přímo přes Docker:

```sh
docker ps
```

Pokud se kontejner jmenuje například:

```text
qbittorrent
```

vyberte jej výslovně:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Případ 3: Provozujete více kontejnerů qBittorrent

Například jeden hlavní a jeden testovací:

```text
qbittorrent
qbittorrent-test
```

Nejprve si zobrazte seznam:

```sh
sh install.sh --list-containers
```

Instalace do hlavního kontejneru:

```sh
sh install.sh --container=qbittorrent -configure
```

Instalace do testovacího kontejneru:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Pokud se najde více kontejnerů, instalátor **nevybere žádný náhodně**.

#### Případ 4: Znáte složku `/config` na hostiteli

Například:

```text
/root/qbittorrent/config
```

Můžete ji zadat přímo:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Na Synology může cesta vypadat takto:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Na jiném NAS například takto:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Jde pouze o příklady. Použijte skutečnou cestu ke konfiguraci qBittorrent na svém hostiteli.

#### Případ 5: Vyberte instalační adresář WebUI

Pokud jste již vybrali kontejner, můžete určit také umístění WebUI uvnitř něj:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Instalátor podle připojení Docker `/config` zjistí odpovídající cestu na hostitelském systému.

#### Případ 6: Aktualizace několika instalací najednou

Pokud spravujete více instancí qBittorrent, můžete parametr `-o` opakovat. Balíček se stáhne a ověří pouze jednou; žádný cíl se nenahradí, dokud nejsou připravené všechny. Každý cíl uchovává nezávisle **poslední tři zálohy** v `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Při více cílech nepoužívejte `-configure`. Každá instance má zachovat dříve nastavenou cestu ke svému alternativnímu WebUI. Všechny možnosti zobrazíte příkazem `sh install.sh -help`.

#### Kontrola cest po instalaci

Úspěšná instalace může vypsat něco podobného:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: skutečné umístění souborů na hostiteli.
- `qBittorrent Root Folder`: cesta **uvnitř kontejneru**, kterou zadáte do *Files location* v qBittorrent.

Při použití `-configure` instalátor aktivuje alternativní WebUI a nastaví cestu, pokud bezpečně zjistí konfiguraci qBittorrent. Jinak postupujte podle návodu pro ruční instalaci výše.

</details>

## Běžné parametry

Základní parametry mají stejné názvy na Linuxu i Windows; PowerShell u jejich názvů nerozlišuje velikost písmen.

| Účel | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Nainstalovat nejnovější stabilní verzi (`main`) | Výchozí stav, bez parametrů | Výchozí stav, bez parametrů |
| Nainstalovat konkrétní stabilní verzi | `-version 1.2.0` | `-version 1.2.0` |
| Nainstalovat vývojovou verzi | `-dev` | `-dev` |
| Zvolit instalační složku | `-o /path` (na Linuxu lze opakovat) | `-o D:\path` nebo `-output D:\path` |
| Zadání konfiguračního souboru qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Automaticky nastavit qBittorrent | `-configure` | `-configure` |
| Obnovit předchozí instalaci | `-rollback` | `-rollback` |
| Odinstalovat včetně záloh | `-uninstall -purge` | `-uninstall -purge` |
| Zobrazit kompletní nápovědu | `-help` | `-help` |
| Vybrat kontejner Docker | `--container=NAME` | — |
| Zobrazit seznam kontejnerů | `--list-containers` | — |
| Složka `/config` na hostiteli | `--config-root=/path` | — |

<details>
<summary><b>Vysvětlení parametrů (rozbalit)</b></summary>

- Bez `-dev` se používá stabilní kanál `main`; s `-dev` vývojová verze určená přesným Git SHA.
- Písmeno `o` v `-o` znamená **output**. Na Linuxu lze parametr opakovat a jedním stažením aktualizovat více již existujících instalací.
- Zálohy spravované instalátorem jsou v `~/.config/weig-qb-webui/backups/`; uchovávají se **nejvýše tři nejnovější zálohy pro každý cíl**.
- `-configure` aktivuje *Use alternative WebUI* a nastaví *Files location*, ale pouze pro jeden cíl.
- `-rollback` obnoví poslední zálohu vytvořenou instalátorem pro zvolený cíl. Opakováním `-o` můžete obnovit několik výslovně uvedených cílů.
- `-uninstall -purge` odstraní zálohy a stav obnovení **pouze aktuální instalace**, ostatní instalace neovlivní.
- Pokud chcete zálohy zachovat pro pozdější `-rollback`, vynechte `-purge`.
- Parametrem `-version` nainstalujete určitou verzi z GitHub Releases, například `1.2.0`. Pokud neexistuje, instalace skončí chybou a **nepřepne se automaticky** na latest nebo dev.
- U více kontejnerů použijte `--list-containers` a vyberte `--container=NAME`, případně zadejte složku hostitele `/config` pomocí `--config-root=/path`.

### Určení verze a instalačního adresáře

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Obnovení předchozí instalace

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Odinstalace jedním příkazem

<details>
<summary><b>Úplné odinstalování na Linuxu / NAS, Dockeru i Windows PowerShell</b></summary>

Obvykle doporučujeme **odstranit WebUI bez ponechání záloh instalátoru**. Příkazy níže odstraní rozhraní, vypnou alternativní WebUI daného cíle, smažou jeho zálohy a stav pro případné obnovení a nakonec odstraní stažený instalační skript z aktuálního adresáře.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Pokud používáte vlastní adresář, přidejte `-o /cesta/weig-qb-webui`.

### Docker

Jeden kontejner s automatickou detekcí:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Více kontejnerů:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Při použití `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Pro vlastní adresář přidejte `-o D:\weig-qb-webui`.

Parametr `-purge` odstraní pouze zálohy instalace, kterou právě odinstalováváte. Ostatní instance zůstanou nedotčené. Pokud se společný stavový adresář zcela vyprázdní, odstraní se také `~/.config/weig-qb-webui` na Linuxu (pro `root`: `/root/.config/weig-qb-webui`) nebo `%APPDATA%\weig-qb-webui` ve Windows.

Chcete-li zálohy zachovat pro pozdější `-rollback`, odinstalujte bez `-purge`.

</details>
