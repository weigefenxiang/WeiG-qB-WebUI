## Странична лента с множество екземпляри

Няколко независими екземпляра на qBittorrent могат да използват една и съща подготвена папка WeiG **само за четене**. Монтирайте папката на хоста във всеки Docker контейнер, например `/root/weig-qb-webui:/weig-qb-webui:ro`, и задайте `/weig-qb-webui` като коренова папка на Alternative WebUI. Всеки екземпляр запазва собствените си торенти, настройки и данни за вход.

Разделът **Instances** в страничната лента позволява регистриране на екземпляри, превключване чрез пълно презареждане и преименуване (с десния бутон или от менюто на реда). Маркерът за текущия екземпляр следва действителния URL, а не запазен суфикс. Интервалът за автоматична проверка се намира в **Settings → WeiG WebUI → Interface** и по подразбиране е `30 min`; може да бъде изключен или зададен между 5 и 1440 минути.

**Доказателствата за състоянието са умишлено предпазливи:** проверен WebAPI от същия произход означава, че qB е онлайн. Отговор на междудоменна заявка `no-cors` без идентификационни данни доказва само, че HTTP адресът е достижим — възможно е дори да връща 403/404. Не се четат Cookie/SID от друг произход, не се прехвърлят пароли или сесии и няма заобикаляне на CORS или междинен сървърен шлюз. Запазен час от предишна успешна проверка е **историческо доказателство**, а не потвърждение за текущо онлайн състояние. Адресът `127.0.0.1` в браузъра е самото устройство с браузъра, а не отдалечен VPS.

## Инсталиране за начинаещи

<details>
<summary><b>Инсталирате за първи път? Отворете краткото ръководство</b></summary>

### 1. Разархивирайте ZIP файла

Изтеглете `weig-qb-webui.zip` и го разархивирайте. Архивът вече съдържа стандартната папка:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

Цялата папка **`weig-qb-webui`** е кореновата директория на WebUI. Не копирайте само `public` или `private`.

### 2. Преместете го на постоянно място

Например:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Това е пътят, който след това трябва да зададете в qBittorrent.

### 3. Активирайте го в qBittorrent

Отворете qBittorrent:

**Tools → Options... → WebUI**

Това са точните названия в английския интерфейс на qBittorrent. След това:

1. Активирайте **Use alternative WebUI**.
2. Намерете полето **Files location:**.
3. Въведете пътя до папката `weig-qb-webui`.

Пример за Windows:

```text
D:\weig-qb-webui
```

Пример за Linux:

```text
/opt/weig-qb-webui
```

4. Натиснете **OK**, за да запазите.
5. Опреснете страницата на qBittorrent WebUI. Ако все още виждате кеширания стар интерфейс, опитайте веднъж `Ctrl + F5`.

> **Проверка на пътя:** в посочената директория трябва да виждате директно `public`, `private`, `VERSION` и останалите файлове.

> **За Docker:** qBittorrent работи в контейнер, затова обикновено трябва да посочите пътя, видим в контейнера, а не пътя в хост системата.

</details>

## Инсталиране с една команда

Инсталационният скрипт за Linux/NAS винаги се изтегля от постоянния адрес на Dev Pages по-долу. **Адресът на скрипта не избира канала за инсталиране:** без `-dev` се инсталира последната проверена стабилна версия от GitHub Release; `-dev` избира текущата разработвана версия по нейния точен Git SHA. Изтегленият скрипт остава в текущата папка за следващи актуализации или връщане към предишна версия.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Покажи адреса на скрипта и папката по подразбиране</b></summary>

```text
./install.sh
```

Папката за инсталиране на WebUI по подразбиране е:

```text
~/.local/share/weig-qb-webui
```

При изпълнение като `root` обикновено е:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker, множество контейнери и разяснение на пътищата</b></summary>

#### Хост и контейнер

- **Хост:** Linux/NAS машината, на която работи Docker.
- **Контейнер:** изолираната среда, в която работи qBittorrent.

Например:

```text
Хост:       /root/qbittorrent/config
   ↓ монтирано като
Контейнер:  /config
```

Пример с Docker Compose:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Ако WebUI се намира на хоста тук:

```text
/root/qbittorrent/config/weig-qb-webui
```

в полето на qBittorrent **Files location:** трябва да посочите:

```text
/config/weig-qb-webui
```

#### Един контейнер с qBittorrent

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Инсталаторът ще се опита автоматично да открие контейнера и монтираната директория `/config`.

#### Откриване на контейнерите

Първо вижте списъка на откритите контейнери с qBittorrent:

```sh
sh install.sh --list-containers
```

Или използвайте Docker директно:

```sh
docker ps
```

Например контейнерът може да се нарича:

```text
qbittorrent
```

Тогава го посочете изрично:

```sh
sh install.sh --container=qbittorrent -configure
```

#### При множество контейнери с qBittorrent

Например основен и тестов екземпляр:

```text
qbittorrent
qbittorrent-test
```

Първо ги избройте:

```sh
sh install.sh --list-containers
```

За основния екземпляр:

```sh
sh install.sh --container=qbittorrent -configure
```

За тестовия екземпляр:

```sh
sh install.sh --container=qbittorrent-test -configure
```

При повече от един контейнер инсталаторът няма да избира произволно.

#### Посочване на хост папката, монтирана като `/config`

Ако конфигурационната директория на qBittorrent на хоста е:

```text
/root/qbittorrent/config
```

Можете да я посочите директно:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Пример за Synology:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Пример за друга NAS система:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Заменете примерите с действителния хост път, монтиран в qBittorrent като `/config`.

#### Посочване на папката за WebUI

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

#### Обновяване на няколко WebUI инсталации с едно изтегляне

В Linux/NAS можете да повторите параметъра `-o` и да актуализирате няколко съществуващи инсталации след едно изтегляне. В този режим не използвайте едновременно `-configure`, `--container` и `--config-root`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

#### Проверка на пътищата след инсталиране

Инсталаторът показва хост пътя и пътя, който вижда qBittorrent:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

В настройката **Files location** на qBittorrent използвайте втория път — този в контейнера. При успешно `-configure` инсталаторът го задава автоматично.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

<details>
<summary><b>Покажи папката за инсталиране</b></summary>

```text
C:\Users\<потребителско-име>\AppData\Local\weig-qb-webui
```

</details>

## Основни параметри
Имената на параметрите в PowerShell не зависят от регистъра.

| Предназначение | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Последна стабилна версия | По подразбиране | По подразбиране |
| Конкретен Release | `-version 1.2.0` | `-version 1.2.0` |
| Разработвана версия | `-dev` | `-dev` |
| Директория за инсталиране | `-o /path` (може да се повтаря) | `-o D:\path` или `-output D:\path` |
| Конфигурационен файл на qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Автоматична настройка на qBittorrent | `-configure` | `-configure` |
| Връщане към предишна версия | `-rollback` | `-rollback` |
| Пълно деинсталиране (без резервни копия) | `-uninstall -purge` | `-uninstall -purge` |
| Помощ | `-help` | `-help` |
| Избор на Docker контейнер | `--container=NAME` | — |
| Списък с Docker контейнерите | `--list-containers` | — |
| Хост път, монтиран като Docker `/config` | `--config-root=/path` | — |

<details>
<summary><b>Бележки (натиснете за разгъване)</b></summary>

- Ако посочената версия не съществува, инсталаторът не преминава автоматично към latest или dev.
- `-dev` не може да се комбинира с `-version`.

### Конкретна версия и директория за инсталиране

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Връщане към предишна версия

Връщане:

```sh
sh install.sh -rollback
```

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Деинсталиране с една команда

<details>
<summary><b>Пълно деинсталиране за Linux / NAS, Docker и Windows PowerShell</b></summary>

Препоръчва се **пълно деинсталиране без запазване на резервните копия на инсталатора**: премахват се WebUI, съответната настройка за алтернативен интерфейс и резервните копия/състоянието за връщане към предишна версия, а после изтегленият инсталационен скрипт се изтрива от текущата папка.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

За собствена директория добавете `-o /path/to/weig-qb-webui`.

### Docker

Един контейнер / автоматично откриване:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Множество контейнери:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

При използване на `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

За собствена директория добавете `-o D:\weig-qb-webui`.

`-purge` премахва само резервните копия на текущата цел и не засяга останалите инсталации. Ако общата папка за състояние се изпразни, се изтрива и Linux `~/.config/weig-qb-webui` (за root: `/root/.config/weig-qb-webui`) или Windows `%APPDATA%\weig-qb-webui`.

За да запазите резервните копия за по-късен `-rollback`, просто не използвайте `-purge`.

</details>
