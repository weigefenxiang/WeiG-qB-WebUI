## Χειροκίνητη εγκατάσταση για αρχάριους

<details>
<summary><b>Πρώτη εγκατάσταση; Ανοίξτε τον γρήγορο οδηγό ενός λεπτού</b></summary>

### 1. Αποσυμπιέστε το ZIP

Κατεβάστε και αποσυμπιέστε το `weig-qb-webui.zip`. Περιλαμβάνει ήδη την παρακάτω δομή φακέλων:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Ολόκληρος ο φάκελος `weig-qb-webui`** είναι ο ριζικός φάκελος του WebUI. Μην αντιγράψετε μόνο τους `public` ή `private`.

### 2. Επιλέξτε μόνιμη θέση

Μετακινήστε ολόκληρο τον φάκελο σε θέση όπου δεν κινδυνεύει να διαγραφεί κατά λάθος. Για παράδειγμα:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Αυτόν τον φάκελο θα επιλέξετε αργότερα στις ρυθμίσεις του qBittorrent.

### 3. Ενεργοποιήστε το εναλλακτικό WebUI στο qBittorrent

Ανοίξτε το qBittorrent και μεταβείτε στα **Εργαλεία → Επιλογές → Περιβάλλον ιστού**. Οι ονομασίες ενδέχεται να διαφέρουν ανάλογα με τη γλώσσα του qBittorrent.

1. Ενεργοποιήστε την **Χρήση εναλλακτικού περιβάλλοντος ιστού** (*Use alternative WebUI*).
2. Βρείτε το πεδίο **Θέση αρχείων** (*Files location*).
3. Συμπληρώστε τη διαδρομή του φακέλου `weig-qb-webui`.

Παράδειγμα σε Windows:

```text
D:\weig-qb-webui
```

Παράδειγμα σε Linux:

```text
/opt/weig-qb-webui
```

4. Πατήστε **OK** για αποθήκευση.
5. Ανανεώστε τη σελίδα του qBittorrent. Αν εμφανίζεται ακόμα το παλιό περιβάλλον, πατήστε `Ctrl + F5` για ανανέωση χωρίς την παλιά προσωρινή μνήμη.

> **Πώς ελέγχετε τη διαδρομή;** Στον φάκελο που επιλέξατε πρέπει να φαίνονται απευθείας οι `public`, `private` και `VERSION`. Αν πρέπει πρώτα να ανοίξετε έναν δεύτερο φάκελο `weig-qb-webui`, έχετε επιλέξει λάθος επίπεδο καταλόγου.

> **Χρησιμοποιείτε Docker;** Το qBittorrent εκτελείται **μέσα σε περιέκτη**. Πρέπει να δώσετε διαδρομή ορατή **από τον περιέκτη**, όχι μόνο από τον κεντρικό υπολογιστή. Δείτε την ενότητα Docker παρακάτω.

</details>

## Εγκατάσταση με μία εντολή

Το σενάριο εγκατάστασης για Linux και NAS λαμβάνεται πάντα από τη σταθερή διεύθυνση Dev Pages παρακάτω. **Η διεύθυνση του σεναρίου δεν καθορίζει ποια έκδοση εγκαθίσταται:** χωρίς `-dev` εγκαθίσταται η τελευταία ελεγμένη σταθερή έκδοση GitHub Release, ενώ με `-dev` εγκαθίσταται η έκδοση ανάπτυξης που ορίζεται από συγκεκριμένο Git SHA. Το σενάριο διατηρείται στον τρέχοντα κατάλογο για μελλοντικές ενημερώσεις και επαναφορές.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Δείτε τη θέση του σεναρίου και τον προεπιλεγμένο φάκελο εγκατάστασης</b></summary>

Το αρχείο του σεναρίου βρίσκεται εδώ:

```text
./install.sh
```

Προεπιλεγμένος κατάλογος του WebUI:

```text
~/.local/share/weig-qb-webui
```

Αν εκτελείτε ως `root`, η θέση είναι συνήθως:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Εγκατάσταση Docker, πολλοί περιέκτες και διαδρομές</b></summary>

#### Ποια είναι η διαφορά μεταξύ κεντρικού υπολογιστή και περιέκτη;

Αν χρησιμοποιείτε Docker σε VPS, διακομιστή Linux, Synology, QNAP ή άλλο NAS:

- **Κεντρικός υπολογιστής (host)** είναι το Linux ή NAS που εκτελεί το Docker και στο οποίο συνήθως συνδέεστε με SSH.
- **Περιέκτης (container)** είναι το απομονωμένο περιβάλλον όπου εκτελείται το qBittorrent. Βλέπει μόνο τους καταλόγους που του έχουν προσαρτηθεί.

Ας υποθέσουμε ότι ο φάκελος ρυθμίσεων αντιστοιχίζεται ως εξής:

```text
Κεντρικός υπολογιστής: /root/qbittorrent/config
   ↓ προσαρτάται ως
Μέσα στον περιέκτη: /config
```

Στο Docker Compose αυτό γράφεται συνήθως έτσι:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Η διαδρομή **αριστερά από την άνω-κάτω τελεία** ανήκει στον **κεντρικό υπολογιστή**· εκείνη **δεξιά** είναι η θέση **μέσα στον περιέκτη**.

Αν το WeiG έχει εγκατασταθεί στον κεντρικό υπολογιστή εδώ:

```text
Κεντρικός υπολογιστής: /root/qbittorrent/config/weig-qb-webui
```

τότε στο πεδίο **Files location** του qBittorrent πρέπει να βάλετε:

```text
/config/weig-qb-webui
```

**Μην βάλετε το `/root/qbittorrent/config/weig-qb-webui`** στο qBittorrent: είναι διαδρομή του κεντρικού υπολογιστή την οποία ο περιέκτης συνήθως δεν μπορεί να δει απευθείας.

#### Περίπτωση 1: Ένας περιέκτης qBittorrent

Εκτελέστε:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Το πρόγραμμα εγκατάστασης προσπαθεί να βρει τον ενεργό περιέκτη qBittorrent, την προσάρτηση `/config` και τον σωστό φάκελο στον κεντρικό υπολογιστή. Αν εντοπίσει με βεβαιότητα τις ρυθμίσεις, διαμορφώνει και το qBittorrent αυτόματα.

#### Περίπτωση 2: Δεν γνωρίζετε το όνομα του περιέκτη

Εμφανίστε τους διαθέσιμους περιέκτες:

```sh
sh install.sh --list-containers
```

Ή ελέγξτε τους με το Docker:

```sh
docker ps
```

Αν για παράδειγμα ο περιέκτης ονομάζεται:

```text
qbittorrent
```

επιλέξτε τον ρητά:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Περίπτωση 3: Πολλοί περιέκτες qBittorrent

Ίσως έχετε έναν κύριο περιέκτη και έναν για δοκιμές:

```text
qbittorrent
qbittorrent-test
```

Δείτε πρώτα τη λίστα:

```sh
sh install.sh --list-containers
```

Για εγκατάσταση στον κύριο περιέκτη:

```sh
sh install.sh --container=qbittorrent -configure
```

Για εγκατάσταση στον δοκιμαστικό:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Το πρόγραμμα εγκατάστασης **δεν επιλέγει τυχαίο περιέκτη** όταν υπάρχουν πολλοί υποψήφιοι.

#### Περίπτωση 4: Γνωρίζετε τον φάκελο `/config` του κεντρικού υπολογιστή

Για παράδειγμα:

```text
/root/qbittorrent/config
```

Μπορείτε να δηλώσετε τον φάκελο απευθείας:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Σε Synology NAS η διαδρομή μπορεί να είναι:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Σε άλλο NAS, για παράδειγμα:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Αυτές είναι ενδεικτικές διαδρομές. Χρησιμοποιήστε την πραγματική θέση του φακέλου ρυθμίσεων qBittorrent στο σύστημά σας.

#### Περίπτωση 5: Επιλογή φακέλου εγκατάστασης του WebUI

Αφού επιλέξετε περιέκτη, μπορείτε να καθορίσετε και τον φάκελο εγκατάστασης μέσα σε αυτόν:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Το πρόγραμμα εγκατάστασης βρίσκει τον αντίστοιχο φάκελο στον κεντρικό υπολογιστή μέσω της προσάρτησης Docker για το `/config`.

#### Περίπτωση 6: Ενημέρωση πολλών εγκαταστάσεων μαζί

Αν διαχειρίζεστε πολλά qBittorrent, μπορείτε να επαναλάβετε την επιλογή `-o`. Το πακέτο λαμβάνεται και επαληθεύεται μία φορά, ενώ καμία εγκατάσταση δεν αντικαθίσταται πριν ετοιμαστούν όλοι οι προορισμοί. Για κάθε προορισμό τηρούνται ανεξάρτητα **τα τρία πιο πρόσφατα αντίγραφα ασφαλείας** στο `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Μην προσθέτετε `-configure` όταν ορίζετε πολλούς προορισμούς. Κάθε qBittorrent συνεχίζει να χρησιμοποιεί τη διαδρομή του εναλλακτικού WebUI που είχε ήδη ρυθμιστεί. Εκτελέστε `sh install.sh -help` για όλες τις διαθέσιμες επιλογές.

#### Έλεγχος των διαδρομών μετά την εγκατάσταση

Μια επιτυχημένη εγκατάσταση μπορεί να εμφανίσει:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: η πραγματική θέση των αρχείων στον κεντρικό υπολογιστή.
- `qBittorrent Root Folder`: η διαδρομή **μέσα στον περιέκτη** που πρέπει να δηλωθεί στο *Files location* του qBittorrent.

Με την επιλογή `-configure`, όταν το πρόγραμμα αναγνωρίσει με ασφάλεια τις ρυθμίσεις του qBittorrent, ενεργοποιεί το εναλλακτικό WebUI και ορίζει τη διαδρομή του. Διαφορετικά, ακολουθήστε τα χειροκίνητα βήματα παραπάνω.

</details>

## Συνηθισμένες παράμετροι

Linux και Windows χρησιμοποιούν τα ίδια ονόματα για τις κοινές παραμέτρους. Το PowerShell δεν ξεχωρίζει πεζά και κεφαλαία στα ονόματα παραμέτρων.

| Σκοπός | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Τελευταία σταθερή έκδοση (`main`) | Προεπιλογή, χωρίς παράμετρο | Προεπιλογή, χωρίς παράμετρο |
| Συγκεκριμένη σταθερή έκδοση | `-version 1.2.0` | `-version 1.2.0` |
| Έκδοση ανάπτυξης | `-dev` | `-dev` |
| Φάκελος εγκατάστασης | `-o /path` (επαναλαμβάνεται στο Linux) | `-o D:\path` ή `-output D:\path` |
| Αρχείο ρυθμίσεων qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Αυτόματη ρύθμιση qBittorrent | `-configure` | `-configure` |
| Επαναφορά προηγούμενης εγκατάστασης | `-rollback` | `-rollback` |
| Πλήρης απεγκατάσταση με αντίγραφα ασφαλείας | `-uninstall -purge` | `-uninstall -purge` |
| Πλήρης βοήθεια | `-help` | `-help` |
| Επιλογή περιέκτη Docker | `--container=NAME` | — |
| Λίστα περιεκτών Docker | `--list-containers` | — |
| Φάκελος `/config` στον κεντρικό υπολογιστή | `--config-root=/path` | — |

<details>
<summary><b>Λεπτομέρειες παραμέτρων (άνοιγμα)</b></summary>

- Χωρίς `-dev` χρησιμοποιείται το σταθερό κανάλι `main`. Με `-dev` χρησιμοποιείται η έκδοση ανάπτυξης με ακριβές Git SHA.
- Το `o` στο `-o` σημαίνει **output**. Στο Linux επαναλάβετε αυτή την παράμετρο για να ενημερώσετε πολλούς προϋπάρχοντες φακέλους με μία λήψη.
- Τα αντίγραφα ασφαλείας φυλάσσονται στο `~/.config/weig-qb-webui/backups/`, το πολύ **τρία πρόσφατα αντίγραφα ανά προορισμό**.
- Το `-configure` ενεργοποιεί το *Use alternative WebUI* και ορίζει το *Files location*, αλλά επιτρέπεται μόνο για έναν προορισμό.
- Το `-rollback` επαναφέρει το τελευταίο αντίγραφο ασφαλείας που δημιούργησε το πρόγραμμα για τον επιλεγμένο προορισμό. Επαναλάβετε το `-o` για περισσότερους ρητούς προορισμούς.
- Το `-uninstall -purge` διαγράφει αντίγραφα ασφαλείας και δεδομένα επαναφοράς **μόνο του επιλεγμένου προορισμού**, χωρίς να επηρεάζει άλλες εγκαταστάσεις.
- Για να διατηρήσετε αντίγραφα ασφαλείας για μελλοντικό `-rollback`, παραλείψτε το `-purge`.
- Με `-version` εγκαθίσταται μια συγκεκριμένη GitHub Release, όπως `1.2.0`. Αν δεν υπάρχει, η εγκατάσταση αποτυγχάνει και **δεν μεταβαίνει αυτόματα** σε latest ή dev.
- Για πολλούς περιέκτες, χρησιμοποιήστε `--list-containers` για τη λίστα και `--container=NAME` για την επιλογή ή δηλώστε τον φάκελο `/config` του κεντρικού υπολογιστή με `--config-root=/path`.

### Συγκεκριμένη έκδοση και φάκελος εγκατάστασης

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Επαναφορά

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Απεγκατάσταση με μία εντολή

<details>
<summary><b>Πλήρης απεγκατάσταση σε Linux / NAS, Docker και Windows PowerShell</b></summary>

Συνήθως προτείνουμε **να αφαιρέσετε το WebUI χωρίς να κρατήσετε τα αντίγραφα ασφαλείας του προγράμματος εγκατάστασης**. Οι παρακάτω εντολές αφαιρούν το WebUI, απενεργοποιούν το εναλλακτικό περιβάλλον του συγκεκριμένου προορισμού, διαγράφουν τα αντίγραφα και τα δεδομένα επαναφοράς που ανήκουν σε αυτόν και αφαιρούν το σενάριο εγκατάστασης από τον τρέχοντα φάκελο.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Για προσαρμοσμένο φάκελο προσθέστε `-o /path/to/weig-qb-webui`.

### Docker

Ένας περιέκτης με αυτόματη αναγνώριση:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Πολλοί περιέκτες:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Με `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Για διαφορετικό φάκελο προσθέστε `-o D:\weig-qb-webui`.

Το `-purge` διαγράφει μόνο τα αντίγραφα ασφαλείας του προορισμού που απεγκαθιστάτε. Τα αντίγραφα άλλων εγκαταστάσεων διατηρούνται. Αν αδειάσει πλήρως ο κοινός κατάλογος κατάστασης, αφαιρείται επίσης το `~/.config/weig-qb-webui` στο Linux (για `root`: `/root/.config/weig-qb-webui`) ή το `%APPDATA%\weig-qb-webui` στα Windows.

Αν θέλετε να κρατήσετε τα αντίγραφα για μελλοντική επαναφορά με `-rollback`, εκτελέστε την απεγκατάσταση χωρίς `-purge`.

</details>
