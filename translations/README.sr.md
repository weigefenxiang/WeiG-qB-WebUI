## Ручна инсталација за почетнике

<details>
<summary><b>Први пут инсталирате? Отворите кратко упутство</b></summary>

### 1. Распакујте ZIP архиву

Преузмите `weig-qb-webui.zip` и распакујте архиву. Она већ садржи следећу структуру директоријума:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Цела фасцикла `weig-qb-webui`** представља основни директоријум веб-интерфејса. Немојте копирати само `public` или `private`.

### 2. Изаберите сталну локацију

Преместите целу фасциклу на место где је нећете случајно обрисати, на пример:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Затим унесите путању до те фасцикле у подешавањима qБитторрента.

### 3. Укључите алтернативни WebUI интерфејс у qБитторренту

Отворите **Алати → Опције → WebUI** у qБитторренту. Називи опција могу да се разликују у зависности од изабраног језика.

1. Означите **Користи алтернативни веб-интерфејс** (*Усе алтернативе WebUI*).
2. Пронађите поље **Локација датотека** (*Files location*).
3. Унесите путању до фасцикле `weig-qb-webui`.

Примјер за Windows:

```text
D:\weig-qb-webui
```

Примјер за Linux:

```text
/opt/weig-qb-webui
```

4. Кликните на **ОК** да сачувате измене.
5. Поново учитајте страницу qБитторрента. Ако се и даље приказује стари интерфејс, притисните `Ctrl + F5` да је освежите без кеша.

> **Како проверити путању?** У изабраној фасцикли морају директно да се налазе `public`, `private` и `VERSION`. Ако прво морате да отворите још једну фасциклу `weig-qb-webui`, изабрали сте погрешан ниво директоријума.

> **Користите Docker?** qBittorrent ради **унутар контејнера**. Зато у подешавањима наведите путању која је доступна контејнеру, а не само путању на хост рачунару. Објашњење следи у наставку.

</details>

## Инсталација једном командом

Инсталациона скрипта за Linux и NAS увек се преузима са сталне адресе Dev Пагес наведене испод. **Адреса скрипте не одређује канал инсталације:** без `-dev` инсталира се последња проверена стабилна верзија са GitHub Релеасес, а са `-dev` развојна верзија везана за тачан Гит СХА. Скрипта остаје у тренутној фасцикли ради каснијег ажурирања или враћања претходне верзије.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Прикажи локацију скрипте и подразумевану инсталациону фасциклу</b></summary>

Преузета скрипта спрема се овде:

```text
./install.sh
```

Подразумевана инсталациона фасцикла за WebUI:

```text
~/.local/share/weig-qb-webui
```

Када се покреће као корисник `root`, то је обично:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Инсталација у Доцкеру, више контејнера и исправни путање</b></summary>

#### Host и контејнер

Ако користите Docker на VPS-у, Linux серверу, Сyнологyју, QNAP-у или другом NAS уређају:

- **Host** је Linux или NAS систем на ком ради Docker. Обично му приступате преко SSH-а.
- **Контејнер (цонтаинер)** је издвојено окружење у ком ради qBittorrent. Види само фасцикле које су у њега мапиране.

Претпоставимо да је конфигурацијска фасцикла повезана овако:

```text
Domaćin: /root/qbittorrent/config
   ↓ povezano kao
Unutar spremnika: /config
```

У Docker Цомпосе конфигурацији то може изгледати овако:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Путања **лево од двотачке** припада **хосту**, а путања **десно** означава локацију **унутар контејнера**.

Ако је WeiG инсталиран на хосту овде:

```text
Domaćin: /root/qbittorrent/config/weig-qb-webui
```

у поље **Files location** у qБитторренту унесите:

```text
/config/weig-qb-webui
```

**Немојте уносити `/root/qbittorrent/config/weig-qb-webui`**. То је путања на хосту коју контејнер обично не може директно да види.

#### Случај 1: Имате само један qBittorrent контејнер

Покрените:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Инсталациона скрипта ће покушати да пронађе активни qBittorrent контејнер, мапирање `/config` и одговарајућу фасциклу на хосту. Ако може поуздано да препозна конфигурацију, аутоматски ће подесити qBittorrent.

#### Случај 2: Не знате назив контејнера

Прикажите доступне контејнере:

```sh
sh install.sh --list-containers
```

Или их проверите директно у Доцкеру:

```sh
docker ps
```

Ако се контејнер, на пример, зове:

```text
qbittorrent
```

изричито га изаберите:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Случај 3: Користите више qBittorrent контејнера

На пример, један главни и један тестни:

```text
qbittorrent
qbittorrent-test
```

Најпре прикажите попис:

```sh
sh install.sh --list-containers
```

Инсталација у главни контејнер:

```sh
sh install.sh --container=qbittorrent -configure
```

Инсталација у тестни контејнер:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Ако инсталациона скрипта пронађе више контејнера, **неће насумично изабрати ниједан**.

#### Случај 4: Знате локацију фасцикле `/config` на хосту

На пример:

```text
/root/qbittorrent/config
```

Можете је директно навести:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

На Сyнологyју пут може изгледати овако:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

На другом NAS уређају, на пример:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Ово су само примјери. Користите стварни пут до конфигурације qБитторрента на својем хосту.

#### Случај 5: Изаберите инсталациону фасциклу за WebUI

Ако сте већ изабрали контејнер, можете задати и локацију WebUI-ја унутар њега:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Инсталациона скрипта према Docker повезивању `/config` проналази одговарајући пут на хосту.

#### Случај 6: Ажурирајте више инсталација одједном

Ако управљате већим бројем qBittorrent инстанци, можете да поновите параметар `-o`. Пакет се преузима и проверава само једном; ниједна инсталација се не замењује док сви циљеви нису припремљени. За сваки циљ засебно се чувају **три последње резервне копије** у `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

За више циљева немојте користити `-configure`. Свака инстанца задржава раније подешену путању до алтернативног WebUI-ја. Све опције можете видети командом `sh install.sh -help`.

#### Провера путања после инсталације

Након успешне инсталације може се приказати нешто попут овога:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: стварна локација датотека на хосту.
- `qBittorrent Root Folder`: пут **унутар контејнера** који уносите у поље *Files location* у qБитторренту.

Ако скрипту покренете уз `-configure`, она укључује алтернативни WebUI и подешава пут ако може сигурно открити конфигурацију qБитторрента. У противном слиједите горње упутства за ручну инсталацију.

</details>

## Уобичајени параметри

Основни параметри се исто зову на Линуxу и Wиндоwсу; PowerShell не разликује велика и мала слова у њиховим називима.

| Намјена | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Инсталирај најновију стабилну верзију (`main`) | Подразумијевано, без параметара | Подразумијевано, без параметара |
| Инсталирај одређену стабилну верзију | `-version 1.2.0` | `-version 1.2.0` |
| Инсталирај развојну верзију | `-dev` | `-dev` |
| Изабери инсталациону фасциклу | `-o /path` (на Линуxу се може поновити) | `-o D:\path` или `-output D:\path` |
| Наведи конфигурацијску датотеку qБитторрента | — | `-qbconfig D:\path\qBittorrent.ini` |
| Аутоматски постави qBittorrent | `-configure` | `-configure` |
| Врати претходну инсталацију | `-rollback` | `-rollback` |
| Деинсталирај и уклони резервне копије | `-uninstall -purge` | `-uninstall -purge` |
| Прикажи потпуну помоћ | `-help` | `-help` |
| Изабери Docker контејнер | `--container=NAME` | — |
| Прикажи попис контејнера | `--list-containers` | — |
| Мапа `/config` на хосту | `--config-root=/path` | — |

<details>
<summary><b>Објашњење параметара (прошири)</b></summary>

- Без `-dev` користи се стабилни канал `main`; с `-dev` развојна верзија одређена тачним Гит СХА идентификатором.
- Слово `o` у `-o` значи **оутпут**. На Линуxу се параметар може понављати како бисте једним преузимањем ажурирали више постојећих инсталација.
- Резервне копије којима управља инсталациона скрипта налазе се у `~/.config/weig-qb-webui/backups/`; за свако се одредиште чувају **највише три најновије резервне копије**.
- `-configure` укључује *Усе алтернативе WebUI* и подешава *Files location*, али само за једно одредиште.
- `-rollback` враћа последњу резервну копију коју је за изабрано одредиште направила инсталациона скрипта. Понављањем `-o` можете вратити више изричито наведених одредишта.
- `-uninstall -purge` уклања резервне копије и стање за повратак **само тренутне инсталације**; остале инсталације остају нетакнуте.
- Ако желите сачувати копије за каснији `-rollback`, изоставите `-purge`.
- Параметром `-version` инсталирате одређено издање с GitHub Релеасес, на пример `1.2.0`. Ако не постоји, инсталација завршава погрешком и **не прелази аутоматски** на латест или дев.
- За више контејнера покрените `--list-containers` и изаберите `--container=NAME`; алтернативно наведите фасциклу хоста за `/config` преко `--config-root=/path`.

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Деинсталација једном командом

<details>
<summary><b>Потпуна деинсталација на Линуxу / NAS-у, у Доцкеру и Windows ПоwерСхеллу</b></summary>

Препоручујемо **уклањање WebUI-ја без чувања резервних копија инсталационе скрипте**. Следеће команде уклањају интерфејс, искључују алтернативни WebUI за изабрани циљ, бришу његове резервне копије и стање за повратак и на крају уклањају преузету инсталациону скрипту из тренутне фасцикле.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Ако користите прилагођену фасциклу, додајте `-o /put/do/weig-qb-webui`.

### Docker

Један контејнер с аутоматским откривањем:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Више контејнера:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Када користите `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

За прилагођену фасциклу додајте `-o D:\weig-qb-webui`.

Параметар `-purge` уклања само резервне копије инсталације коју управо деинсталирате. Остале инстанце остају нетакнуте. Ако заједничка фасцикла са стањем постане потпуно празна, уклања се и `~/.config/weig-qb-webui` на Линуxу (за `root`: `/root/.config/weig-qb-webui`) или `%APPDATA%\weig-qb-webui` на Wиндоwсима.

Ако желите задржати резервне копије за каснији `-rollback`, деинсталирајте без `-purge`.

</details>
