## Manuell installasjon for nybegynnere

<details>
<summary><b>Første gang? Åpne den korte installasjonsveiledningen</b></summary>

### 1. Pakk ut filen

Last ned `weig-qb-webui.zip` og pakk ut hele arkivet. Mappestrukturen ser slik ut:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Hele mappen `weig-qb-webui`** er roten til WebUI. Ikke kopier bare `public` eller `private`.

### 2. Velg en fast plassering

Legg mappen et sted den ikke blir slettet ved en feil, for eksempel:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Denne katalogen skal senere oppgis i qBittorrent.

### 3. Aktiver alternativ WebUI

Åpne **Verktøy → Alternativer → Webgrensesnitt** i qBittorrent. Menynavnene varierer med valgt språk.

1. Aktiver **Bruk alternativt webgrensesnitt** (*Use alternative WebUI*).
2. Finn **Filplassering** (*Files location*).
3. Skriv inn banen til `weig-qb-webui`.

På Windows:

```text
D:\weig-qb-webui
```

På Linux:

```text
/opt/weig-qb-webui
```

4. Klikk **OK**.
5. Last inn qBittorrent-siden på nytt. Prøv `Ctrl + F5` hvis den gamle siden fortsatt vises.

> **Sjekk banen:** Inne i den valgte katalogen må du umiddelbart se `public`, `private` og `VERSION`. Hvis du må åpne enda en `weig-qb-webui`-mappe, er mappenivået feil.

> **Docker:** qBittorrent kjører inne i en container. Bruk derfor banen som er synlig **fra containeren**, ikke bare banen på vertsmaskinen.

</details>

## Installer med én kommando

Installasjonsskriptet for Linux og NAS hentes fra den faste Dev Pages-adressen nedenfor. **Skriptadressen bestemmer ikke installasjonskanalen:** uten `-dev` installeres siste verifiserte stabile GitHub Release, mens `-dev` bruker utviklingsversjonen med en eksakt Git SHA. Skriptet lagres i gjeldende katalog, slik at det også kan brukes til oppdatering og tilbakerulling.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Se plasseringen av skriptet og standard installasjonskatalog</b></summary>

Skriptet finnes her:

```text
./install.sh
```

Standardplassering for WebUI:

```text
~/.local/share/weig-qb-webui
```

For brukeren `root` er dette vanligvis:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Docker-installasjon, flere containere og katalogbaner</b></summary>

#### Forskjellen på vertsmaskin og container

På VPS, Linux-server, Synology, QNAP og andre NAS-systemer:

- **Vertsmaskin (host)** er Linux-/NAS-systemet som faktisk kjører Docker, ofte maskinen du logger inn på med SSH.
- **Container** er det isolerte miljøet som kjører qBittorrent og bare kan se katalogene som er gjort tilgjengelige der.

En typisk kobling:

```text
Vertsmaskin: /root/qbittorrent/config
   ↓ monteres som
I containeren: /config
```

I Docker Compose ser den slik ut:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Før kolon står banen på **vertsmaskinen**. Etter kolon står banen **inne i containeren**.

Hvis WeiG ligger på vertsmaskinen her:

```text
Vertsmaskin: /root/qbittorrent/config/weig-qb-webui
```

skal feltet **Files location** i qBittorrent inneholde:

```text
/config/weig-qb-webui
```

**Ikke skriv `/root/qbittorrent/config/weig-qb-webui`** i dette feltet; containeren ser normalt ikke vertsmaskinens bane direkte.

#### Tilfelle 1: Én qBittorrent-container

Kjør:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Installasjonsprogrammet prøver å finne qBittorrent-containeren, `/config`-koblingen og riktig vertskatalog. Hvis konfigurasjonen er entydig, kan det også sette opp qBittorrent automatisk.

#### Tilfelle 2: Se hvilke containere som finnes

Hvis du ikke kjenner navnet:

```sh
sh install.sh --list-containers
```

Du kan også bruke Docker:

```sh
docker ps
```

Hvis navnet er:

```text
qbittorrent
```

velger du den eksplisitt:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Tilfelle 3: Flere qBittorrent-containere

For eksempel en hovedinstans og en testinstans:

```text
qbittorrent
qbittorrent-test
```

List dem først:

```sh
sh install.sh --list-containers
```

For hovedinstansen:

```sh
sh install.sh --container=qbittorrent -configure
```

For testinstansen:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Installasjonsprogrammet **velger aldri en tilfeldig container** når flere stemmer.

#### Tilfelle 4: Du kjenner vertens `/config`-mappe

Eksempel på en konfigurasjonsmappe:

```text
/root/qbittorrent/config
```

Angi mappen direkte:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

På Synology kan banen være:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

På en annen NAS, for eksempel:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Bytt ut eksempelbanene med den faktiske `/config`-katalogen til qBittorrent på vertsmaskinen.

#### Tilfelle 5: Velg hvor WebUI skal installeres

Når containeren er angitt, kan du også velge banen inne i containeren:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Programmet finner den tilsvarende katalogen på vertsmaskinen ved hjelp av Dockers `/config`-kobling.

#### Tilfelle 6: Oppdater flere installasjoner i samme kjøring

Gjenta `-o` når du har flere qBittorrent-instanser. Pakken lastes ned og kontrolleres én gang, og ingen installasjon byttes ut før alle målkataloger er klargjort. Hvert mål beholder **de tre nyeste sikkerhetskopiene separat** under `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Ikke bruk `-configure` med flere mål. Hver instans skal fortsette å bruke sin allerede konfigurerte WebUI-bane. Alle valg vises med `sh install.sh -help`.

#### Kontroller banene etter installasjonen

En vellykket installasjon kan vise:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path` er der filene faktisk ligger på vertsmaskinen.
- `qBittorrent Root Folder` er banen **inne i containeren** som skal brukes i *Files location* i qBittorrent.

Med `-configure` aktiveres alternativ WebUI automatisk hvis programmet sikkert finner qBittorrent-oppsettet. Ellers bruker du den manuelle veiledningen over.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

<summary><b>Vis installasjonskatalogen</b></summary>

```text
C:\Users\<brukernavn>\AppData\Local\weig-qb-webui
```

</details>

## Vanlige parametere

Linux og Windows bruker samme navn på felles parametere. PowerShell skiller ikke mellom store og små bokstaver.

| Formål | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Nyeste stabile versjon (`main`) | Standard, ingen parameter | Standard, ingen parameter |
| Bestemt stabil versjon | `-version 1.2.0` | `-version 1.2.0` |
| Utviklingsversjon | `-dev` | `-dev` |
| Installasjonsmappe | `-o /path` (kan gjentas på Linux) | `-o D:\path` eller `-output D:\path` |
| Egen konfigurasjonsfil for qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Konfigurer qBittorrent automatisk | `-configure` | `-configure` |
| Gjenopprett forrige installasjon | `-rollback` | `-rollback` |
| Avinstaller helt med sikkerhetskopier | `-uninstall -purge` | `-uninstall -purge` |
| Vis fullstendig hjelp | `-help` | `-help` |
| Velg Docker-container | `--container=NAME` | — |
| List Docker-containere | `--list-containers` | — |
| Vertsmaskinens `/config`-mappe | `--config-root=/path` | — |

<details>
<summary><b>Parameterforklaringer (vis)</b></summary>

- Uten `-dev` brukes stabil `main`. Med `-dev` brukes utviklingsversjonen med eksakt Git SHA.
- `-o` betyr **output** og kan gjentas på Linux for å oppdatere flere mål etter én nedlasting.
- Sikkerhetskopier lagres under `~/.config/weig-qb-webui/backups/`; **de tre nyeste per mål** beholdes.
- `-configure` aktiverer *Use alternative WebUI* og setter *Files location*, men kan bare brukes med ett mål.
- `-rollback` gjenoppretter siste sikkerhetskopi for valgt mål. Gjenta `-o` for flere eksplisitte mål.
- `-uninstall -purge` fjerner bare sikkerhetskopiene og gjenopprettingsstatusen til **målet som avinstalleres**, ikke til andre installasjoner.
- Utelat `-purge` dersom du vil beholde sikkerhetskopiene til senere `-rollback`.
- `-version` installerer en bestemt GitHub Release, for eksempel `1.2.0`. Finnes den ikke, stopper installasjonen med feil og **bytter ikke automatisk** til latest eller dev.
- Ved flere containere kan du bruke `--list-containers`, velge med `--container=NAME`, eller oppgi vertsmaskinens `/config` med `--config-root=/path`.

### Bestemt versjon og installasjonsmappe

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Gjenoppretting

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Avinstaller med én kommando

<details>
<summary><b>Fullstendig avinstallasjon på Linux / NAS, Docker og Windows PowerShell</b></summary>

Vi anbefaler normalt **å fjerne WebUI uten å beholde installasjonsprogrammets sikkerhetskopier**. Kommandoene fjerner WebUI, deaktiverer alternativt grensesnitt for riktig mål, sletter målets sikkerhetskopier og gjenopprettingsstatus, og fjerner det nedlastede installasjonsskriptet fra gjeldende mappe.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Legg til `-o /bane/weig-qb-webui` hvis du bruker en egen installasjonsmappe.

### Docker

Én container med automatisk gjenkjenning:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Flere containere:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Med `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Legg til `-o D:\weig-qb-webui` for en egen mappe.

`-purge` sletter bare sikkerhetskopiene som tilhører installasjonen du avinstallerer. Andre instanser påvirkes ikke. Hvis den delte statusmappen blir tom, fjernes også `~/.config/weig-qb-webui` på Linux (`/root/.config/weig-qb-webui` for `root`) eller `%APPDATA%\weig-qb-webui` på Windows.

For å beholde sikkerhetskopiene til `-rollback` kan du avinstallere uten `-purge`.

</details>
