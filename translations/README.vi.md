## Cài đặt thủ công cho người mới

<details>
<summary><b>Lần đầu cài đặt? Mở hướng dẫn nhanh trong một phút</b></summary>

### 1. Giải nén

Tải `weig-qb-webui.zip` rồi giải nén. Trong đó đã có sẵn thư mục với cấu trúc:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Toàn bộ thư mục `weig-qb-webui`** chính là thư mục gốc của WebUI. Không chỉ sao chép riêng `public` hoặc `private`.

### 2. Chọn nơi lưu cố định

Chuyển cả thư mục đến vị trí không dễ bị xóa nhầm, chẳng hạn:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Đây là đường dẫn bạn sẽ chọn trong phần cài đặt của qBittorrent.

### 3. Bật WebUI thay thế trong qBittorrent

Mở qBittorrent và vào **Công cụ → Tùy chọn → Giao diện Web**. Tên mục có thể hơi khác tùy ngôn ngữ đang dùng trong qBittorrent.

1. Bật **Sử dụng giao diện Web thay thế** (*Use alternative WebUI*).
2. Tìm mục **Vị trí tệp** (*Files location*).
3. Nhập đường dẫn đến thư mục `weig-qb-webui`.

Ví dụ trên Windows:

```text
D:\weig-qb-webui
```

Ví dụ trên Linux:

```text
/opt/weig-qb-webui
```

4. Nhấn **OK** để lưu.
5. Tải lại trang WebUI của qBittorrent. Nếu giao diện cũ vẫn xuất hiện, hãy nhấn `Ctrl + F5` để làm mới bộ nhớ đệm trình duyệt.

> **Kiểm tra đường dẫn:** Mở thư mục bạn đã chọn; bên trong phải thấy ngay `public`, `private` và `VERSION`. Nếu còn phải mở thêm một thư mục `weig-qb-webui` nữa thì bạn đã chọn sai cấp thư mục.

> **Lưu ý khi dùng Docker:** qBittorrent chạy **bên trong container**, nên bạn phải nhập đường dẫn mà container nhìn thấy, không phải đường dẫn chỉ tồn tại trên máy chủ. Xem giải thích chi tiết ở phần Docker bên dưới.

</details>

## Cài đặt bằng một lệnh

Script dành cho Linux và NAS được tải qua liên kết Dev Pages cố định dưới đây. **Địa chỉ tải script không quyết định kênh cài đặt:** không có `-dev` sẽ cài bản ổn định mới nhất đã được kiểm tra trên GitHub Release; thêm `-dev` mới cài bản phát triển tại Git SHA chính xác. Script được giữ trong thư mục hiện tại để tiện cập nhật hoặc khôi phục về sau.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Xem nơi lưu script và thư mục cài đặt mặc định</b></summary>

Script vừa tải nằm tại:

```text
./install.sh
```

WebUI mặc định được cài vào:

```text
~/.local/share/weig-qb-webui
```

Nếu chạy bằng tài khoản `root`, vị trí thông thường là:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Cài đặt trên Docker, nhiều container và cách chọn đường dẫn</b></summary>

#### Phân biệt máy chủ và container

Nếu Docker đang chạy trên VPS, máy chủ Linux, Synology, QNAP hoặc NAS khác:

- **Máy chủ (host):** hệ thống Linux/NAS thực sự chạy Docker, thường là nơi bạn đăng nhập bằng SSH.
- **Container:** môi trường độc lập chạy qBittorrent; ứng dụng chỉ nhìn thấy những đường dẫn đã được ánh xạ vào container.

Giả sử bạn ánh xạ thư mục cấu hình như sau:

```text
Máy chủ: /root/qbittorrent/config
   ↓ ánh xạ tới
Trong container: /config
```

Trong Docker Compose, cấu hình thường có dạng:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Đường dẫn **bên trái** dấu hai chấm thuộc máy chủ; đường dẫn **bên phải** là vị trí bên trong container.

Nếu WebUI nằm trên máy chủ tại:

```text
Máy chủ: /root/qbittorrent/config/weig-qb-webui
```

thì trong qBittorrent, mục **Files location** phải là:

```text
/config/weig-qb-webui
```

**Không nhập `/root/qbittorrent/config/weig-qb-webui`** vào qBittorrent; container thường không thể truy cập trực tiếp đường dẫn trên máy chủ này.

#### Trường hợp 1: Chỉ có một container qBittorrent

Chạy:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Trình cài đặt sẽ thử tìm container qBittorrent đang hoạt động và thư mục `/config` được ánh xạ, rồi đặt WebUI vào đúng vị trí trên máy chủ. Nếu xác định chắc chắn cấu hình, trình cài đặt cũng sẽ cấu hình qBittorrent.

#### Trường hợp 2: Xem các container hiện có

Nếu bạn chưa biết tên container:

```sh
sh install.sh --list-containers
```

Hoặc xem trực tiếp bằng Docker:

```sh
docker ps
```

Ví dụ bạn thấy container tên là:

```text
qbittorrent
```

Hãy chỉ định rõ container đó:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Trường hợp 3: Có nhiều container qBittorrent

Ví dụ có một container sử dụng chính và một container thử nghiệm:

```text
qbittorrent
qbittorrent-test
```

Trước tiên hãy xem danh sách:

```sh
sh install.sh --list-containers
```

Cài cho container chính:

```sh
sh install.sh --container=qbittorrent -configure
```

Cài cho container thử nghiệm:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Khi tìm thấy nhiều container, trình cài đặt **không tự ý chọn đại một cái**.

#### Trường hợp 4: Bạn biết thư mục `/config` trên máy chủ

Ví dụ thư mục cấu hình là:

```text
/root/qbittorrent/config
```

Bạn có thể nhập trực tiếp:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Trên Synology, đường dẫn có thể là:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Trên một NAS khác, có thể là:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Đây chỉ là các ví dụ. Hãy thay bằng đường dẫn `/config` thực tế của qBittorrent trên máy chủ của bạn.

#### Trường hợp 5: Chọn thư mục cài WebUI

Nếu đã chỉ định container, bạn cũng có thể chọn đường dẫn WebUI muốn sử dụng bên trong container:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Trình cài đặt sẽ dựa vào ánh xạ Docker của `/config` để tìm vị trí tương ứng trên máy chủ.

#### Trường hợp 6: Cập nhật nhiều bản cài trong một lần

Nếu đang vận hành nhiều qBittorrent, bạn có thể lặp lại tùy chọn `-o`. Gói cài đặt chỉ được tải và xác minh một lần; mọi thư mục đích đều phải được chuẩn bị xong trước khi bắt đầu thay thế. Mỗi đích lưu độc lập tối đa **ba bản sao lưu gần nhất** tại `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Trong chế độ nhiều đích, đừng dùng `-configure`; mỗi qBittorrent tiếp tục sử dụng đường dẫn WebUI thay thế đã được thiết lập trước đó. Chạy `sh install.sh -help` để xem đầy đủ tùy chọn.

#### Kiểm tra đường dẫn sau khi cài

Một lần cài đặt thành công có thể hiển thị:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: vị trí các tệp thực sự được lưu trên máy chủ.
- `qBittorrent Root Folder`: đường dẫn **bên trong container** cần nhập vào mục *Files location* của qBittorrent.

Khi có `-configure` và trình cài đặt xác định được đúng cấu hình qBittorrent, WebUI thay thế sẽ được bật và đường dẫn sẽ được cập nhật tự động. Nếu không, bạn hãy làm theo hướng dẫn cài thủ công ở trên.

</details>

## Các tùy chọn thường dùng

Linux và Windows sử dụng cùng tên cho các tùy chọn chung; PowerShell không phân biệt chữ hoa và chữ thường trong tên tham số.

| Mục đích | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Cài bản ổn định mới nhất (`main`) | Mặc định, không cần tham số | Mặc định, không cần tham số |
| Chọn bản ổn định cụ thể | `-version 1.2.0` | `-version 1.2.0` |
| Cài bản phát triển | `-dev` | `-dev` |
| Chỉ định thư mục cài đặt | `-o /path` (có thể lặp trên Linux) | `-o D:\path` hoặc `-output D:\path` |
| Chỉ định tệp cấu hình qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Tự cấu hình qBittorrent | `-configure` | `-configure` |
| Khôi phục lần cài trước | `-rollback` | `-rollback` |
| Gỡ cài đặt và xóa bản sao lưu | `-uninstall -purge` | `-uninstall -purge` |
| Xem toàn bộ trợ giúp | `-help` | `-help` |
| Chỉ định container Docker | `--container=NAME` | — |
| Liệt kê container Docker | `--list-containers` | — |
| Chỉ định đường dẫn host được ánh xạ tới `/config` | `--config-root=/path` | — |

<details>
<summary><b>Giải thích các tùy chọn (bấm để mở)</b></summary>

- Không có `-dev` nghĩa là sử dụng kênh ổn định `main`; có `-dev` nghĩa là sử dụng bản phát triển gắn với Git SHA chính xác.
- Chữ `o` trong `-o` viết tắt của **output**. Trên Linux, bạn có thể dùng tùy chọn này nhiều lần để cập nhật các bản cài hiện có chỉ bằng một lần tải.
- Bản sao lưu do trình cài đặt quản lý luôn ở `~/.config/weig-qb-webui/backups/`, giữ tối đa **ba bản gần nhất cho từng đích**.
- `-configure` tự bật *Use alternative WebUI* và cập nhật *Files location*, nhưng chỉ được dùng khi cài vào một đích.
- `-rollback` khôi phục bản sao lưu mới nhất do trình cài đặt tạo cho đích đã chọn; cũng có thể lặp `-o` để khôi phục nhiều đích xác định.
- `-uninstall -purge` chỉ xóa bản sao lưu và thông tin khôi phục của **đích đang được gỡ**, không đụng đến các bản cài khác.
- Muốn giữ bản sao lưu để dùng `-rollback` sau này thì bỏ `-purge`.
- `-version` cài một bản GitHub Release cụ thể, ví dụ `1.2.0`. Nếu bản đó không tồn tại, quá trình cài đặt sẽ báo lỗi, **không tự chuyển sang latest hoặc dev**.
- Nếu có nhiều container, dùng `--list-containers` rồi chọn chính xác bằng `--container=NAME`, hoặc chỉ định thư mục cấu hình trên máy chủ bằng `--config-root=/path`.

## Gỡ cài đặt bằng một lệnh

<details>
<summary><b>Gỡ bỏ hoàn toàn trên Linux / NAS, Docker và Windows PowerShell</b></summary>

Thông thường, nên **gỡ WebUI mà không giữ bản sao lưu của trình cài đặt**. Lệnh bên dưới sẽ gỡ giao diện, tắt WebUI thay thế của đúng đích cài, xóa bản sao lưu và trạng thái khôi phục thuộc đích đó, rồi xóa script đã tải trong thư mục hiện tại.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Để sử dụng đường dẫn tùy chỉnh, thêm `-o /duong-dan/weig-qb-webui`.

### Docker

Một container, tự động nhận diện:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Nếu có nhiều container:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Khi dùng `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Nếu cài ở thư mục tùy chỉnh, thêm `-o D:\weig-qb-webui`.

`-purge` chỉ xóa những bản sao lưu thuộc bản cài bạn đang gỡ; bản sao lưu của các qBittorrent khác vẫn được giữ nguyên. Nếu thư mục trạng thái dùng chung không còn dữ liệu, `~/.config/weig-qb-webui` (với `root`: `/root/.config/weig-qb-webui`) trên Linux hoặc `%APPDATA%\weig-qb-webui` trên Windows cũng sẽ được dọn dẹp.

Nếu muốn giữ bản sao lưu để sau này `-rollback`, hãy chạy lệnh gỡ mà không có `-purge`.

</details>
