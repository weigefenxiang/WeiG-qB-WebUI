## Instalare manuală pentru începători

<details>
<summary><b>Instalezi pentru prima dată? Deschide ghidul rapid</b></summary>

### 1. Dezarhivează fișierul ZIP

Descarcă `weig-qb-webui.zip` și extrage-l. Arhiva conține deja următoarea structură de directoare:

```text
weig-qb-webui/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

**Întregul director `weig-qb-webui`** reprezintă rădăcina interfeței web. Nu copia doar `public` sau `private`.

### 2. Alege un loc permanent

Mută întregul director într-un loc de unde nu poate fi șters din greșeală, de exemplu:

```text
Windows: D:\weig-qb-webui
Linux:   /opt/weig-qb-webui
```

Aceasta este calea pe care o vei introduce apoi în setările qBittorrent.

### 3. Activează interfața WebUI alternativă în qBittorrent

Deschide **Instrumente → Opțiuni → Interfață web**. Denumirile exacte pot varia în funcție de limba selectată în qBittorrent.

1. Bifează **Folosește interfața web alternativă** (*Use alternative WebUI*).
2. Găsește câmpul **Locația fișierelor** (*Files location*).
3. Introdu calea către directorul `weig-qb-webui`.

Exemplu pentru Windows:

```text
D:\weig-qb-webui
```

Exemplu pentru Linux:

```text
/opt/weig-qb-webui
```

4. Apasă **OK** pentru a salva modificările.
5. Reîncarcă pagina qBittorrent. Dacă apare în continuare interfața veche, apasă `Ctrl + F5` pentru o reîncărcare forțată.

> **Cum verifici calea?** Directorul selectat trebuie să conțină direct `public`, `private` și `VERSION`. Dacă mai trebuie să intri într-un director `weig-qb-webui`, ai selectat nivelul greșit.

> **Folosești Docker?** qBittorrent rulează **într-un container**. În setări trebuie, așadar, să introduci calea disponibilă în container, nu una existentă doar pe sistemul gazdă. Explicațiile sunt mai jos.

</details>

## Instalare printr-o singură comandă

Scriptul de instalare pentru Linux și NAS se descarcă întotdeauna de la adresa fixă Dev Pages de mai jos. **Adresa scriptului nu determină canalul de instalare:** fără `-dev` se instalează ultima versiune stabilă verificată din GitHub Releases, iar cu `-dev` se folosește versiunea de dezvoltare identificată printr-un Git SHA exact. Scriptul rămâne în directorul curent pentru actualizări sau revenirea la o instalare anterioară.

### Linux / NAS

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

<details>
<summary><b>Arată locația scriptului și directorul de instalare implicit</b></summary>

Scriptul descărcat se salvează aici:

```text
./install.sh
```

Directorul implicit de instalare WebUI:

```text
~/.local/share/weig-qb-webui
```

Atunci când rulezi ca utilizator `root`, acesta este de obicei:

```text
/root/.local/share/weig-qb-webui
```

</details>

### Docker

<details>
<summary><b>Instalare Docker, mai multe containere și căi corecte</b></summary>

#### Sistem gazdă și container

Dacă folosești Docker pe un VPS, un server Linux, Synology, QNAP sau alt NAS:

- **Gazda (host)** este sistemul Linux sau NAS pe care rulează Docker. De obicei te conectezi la acesta prin SSH.
- **Containerul (container)** este un mediu separat în care rulează qBittorrent. Poate accesa doar directoarele montate în el.

Să presupunem că directorul de configurare este montat astfel:

```text
Gazdă: /root/qbittorrent/config
   ↓ montat ca
În container: /config
```

În Docker Compose, această montare poate arăta astfel:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

Calea **din stânga semnului două puncte** aparține **gazdei**, iar cea **din dreapta** este calea **din container**.

Dacă WeiG este instalat pe gazdă aici:

```text
Gazdă: /root/qbittorrent/config/weig-qb-webui
```

în câmpul **Files location** din qBittorrent trebuie introdus:

```text
/config/weig-qb-webui
```

**Nu introduce `/root/qbittorrent/config/weig-qb-webui`**. Aceasta este o cale de pe gazdă, pe care containerul nu o poate vedea de regulă direct.

#### Cazul 1: Ai un singur container qBittorrent

Execută:

```sh
curl -fsSL https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.sh -o install.sh && sh install.sh -configure
```

Scriptul va încerca să găsească un container qBittorrent pornit, montarea `/config` și directorul corespunzător de pe gazdă. Dacă poate identifica în siguranță configurația, va configura automat qBittorrent.

#### Cazul 2: Nu știi numele containerului

Afișează containerele disponibile:

```sh
sh install.sh --list-containers
```

Sau verifică-le direct prin Docker:

```sh
docker ps
```

Dacă un container se numește, de exemplu:

```text
qbittorrent
```

selectează-l explicit:

```sh
sh install.sh --container=qbittorrent -configure
```

#### Cazul 3: Folosești mai multe containere qBittorrent

De exemplu, unul principal și unul de test:

```text
qbittorrent
qbittorrent-test
```

Mai întâi, afișează lista:

```sh
sh install.sh --list-containers
```

Instalare în containerul principal:

```sh
sh install.sh --container=qbittorrent -configure
```

Instalare în containerul de test:

```sh
sh install.sh --container=qbittorrent-test -configure
```

Dacă scriptul găsește mai multe containere, **nu va alege unul la întâmplare**.

#### Cazul 4: Cunoști directorul `/config` de pe gazdă

De exemplu:

```text
/root/qbittorrent/config
```

Îl poți specifica direct:

```sh
sh install.sh --config-root=/root/qbittorrent/config -configure
```

Pe Synology, calea poate arăta astfel:

```sh
sh install.sh --config-root=/volume1/docker/qbittorrent -configure
```

Pe un alt NAS, de exemplu:

```sh
sh install.sh --config-root=/share/Container/qbittorrent -configure
```

Acestea sunt doar exemple. Folosește calea reală către configurația qBittorrent de pe gazda ta.

#### Cazul 5: Alege directorul de instalare WebUI

Dacă ai selectat deja un container, poți indica și locația WebUI în interiorul lui:

```sh
sh install.sh --container=qbittorrent -o /config/weig-qb-webui -configure
```

Scriptul identifică directorul corespunzător de pe gazdă folosind montarea Docker `/config`.

#### Cazul 6: Actualizează mai multe instalări odată

Dacă administrezi mai multe instanțe qBittorrent, poți repeta parametrul `-o`. Pachetul se descarcă și se verifică o singură dată; nicio destinație nu este înlocuită până când toate nu sunt pregătite. Fiecare destinație păstrează independent **cele mai recente trei copii de rezervă** în `~/.config/weig-qb-webui/backups/`.

```sh
sh install.sh -dev \
  -o /root/qbittorrent/config/weig-qb-webui \
  -o /root/qbittorrent3/config/weig-qb-webui
```

Pentru mai multe destinații, nu folosi `-configure`. Fiecare instanță trebuie să păstreze calea deja configurată pentru WebUI alternativ. Toate opțiunile sunt afișate de `sh install.sh -help`.

#### Verificarea căilor după instalare

După o instalare reușită, poți vedea un rezultat de forma:

```text
Host install path: /root/qbittorrent/config/weig-qb-webui
qBittorrent Root Folder: /config/weig-qb-webui
```

- `Host install path`: locația reală a fișierelor pe gazdă.
- `qBittorrent Root Folder`: calea **din container** care trebuie introdusă în câmpul *Files location* din qBittorrent.

Cu `-configure`, scriptul activează WebUI alternativ și setează calea dacă poate identifica sigur configurația qBittorrent. Altfel, urmează instrucțiunile de instalare manuală de mai sus.

</details>

### Windows PowerShell

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\install.ps1; powershell -ExecutionPolicy Bypass -File .\install.ps1 -configure
```

<details>
<summary><b>Arată directorul de instalare</b></summary>

```text
C:\Users\<nume_utilizator>\AppData\Local\weig-qb-webui
```

</details>

## Parametri uzuali

Parametrii de bază au aceleași denumiri pe Linux și Windows; în PowerShell, numele lor nu țin cont de literele mari sau mici.

| Scop | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| Instalează ultima versiune stabilă (`main`) | Implicit, fără parametri | Implicit, fără parametri |
| Instalează o anumită versiune stabilă | `-version 1.2.0` | `-version 1.2.0` |
| Instalează versiunea de dezvoltare | `-dev` | `-dev` |
| Alege directorul de instalare | `-o /path` (se poate repeta pe Linux) | `-o D:\path` sau `-output D:\path` |
| Specifică fișierul de configurare qBittorrent | — | `-qbconfig D:\path\qBittorrent.ini` |
| Configurează automat qBittorrent | `-configure` | `-configure` |
| Revino la instalarea anterioară | `-rollback` | `-rollback` |
| Dezinstalează inclusiv copiile de rezervă | `-uninstall -purge` | `-uninstall -purge` |
| Afișează ajutorul complet | `-help` | `-help` |
| Selectează un container Docker | `--container=NAME` | — |
| Afișează lista containerelor | `--list-containers` | — |
| Directorul `/config` de pe gazdă | `--config-root=/path` | — |

<details>
<summary><b>Explicația parametrilor (extinde)</b></summary>

- Fără `-dev` se folosește canalul stabil `main`; cu `-dev`, versiunea de dezvoltare identificată prin Git SHA exact.
- Litera `o` din `-o` înseamnă **output**. Pe Linux poți repeta parametrul și actualiza mai multe instalări existente printr-o singură descărcare.
- Copiile de rezervă administrate de script sunt stocate în `~/.config/weig-qb-webui/backups/`; se păstrează **cel mult ultimele trei copii pentru fiecare destinație**.
- `-configure` activează *Use alternative WebUI* și setează *Files location*, dar numai pentru o singură destinație.
- `-rollback` restaurează ultima copie de rezervă creată de script pentru destinația aleasă. Repetând `-o`, poți restaura mai multe destinații precizate explicit.
- `-uninstall -purge` șterge copiile de rezervă și starea necesară revenirii **numai pentru instalarea curentă**, fără a afecta alte instalări.
- Dacă vrei să păstrezi copiile pentru un `-rollback` ulterior, omite `-purge`.
- Parametrul `-version` instalează o versiune anume din GitHub Releases, de exemplu `1.2.0`. Dacă nu există, instalarea eșuează și **nu trece automat** la latest sau dev.
- Pentru mai multe containere, folosește `--list-containers` și selectează `--container=NAME`; alternativ, specifică directorul gazdei pentru `/config` prin `--config-root=/path`.

### Alegerea versiunii și a directorului de instalare

Linux:

```sh
sh install.sh -version 1.2.0 -o /opt/weig-qb-webui -configure
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -version 1.2.0 -o D:\weig-qb-webui -configure
```

### Revenirea la instalarea anterioară

Linux:

```sh
sh install.sh -rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -rollback
```

</details>

## Dezinstalare printr-o singură comandă

<details>
<summary><b>Dezinstalare completă pe Linux / NAS, în Docker și în Windows PowerShell</b></summary>

Recomandăm în general **eliminarea WebUI fără păstrarea copiilor de rezervă create de script**. Comenzile de mai jos elimină interfața, dezactivează WebUI alternativ pentru destinația aleasă, șterg copiile și starea de restaurare și, la final, elimină scriptul de instalare descărcat din directorul curent.

### Linux / NAS

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Dacă folosești un director personalizat, adaugă `-o /cale/catre/weig-qb-webui`.

### Docker

Un singur container cu detectare automată:

```sh
sh install.sh -uninstall -configure -purge && rm -f -- ./install.sh
```

Mai multe containere:

```sh
sh install.sh -uninstall -configure -purge --container=qbittorrent && rm -f -- ./install.sh
```

Când folosești `--config-root`:

```sh
sh install.sh -uninstall -configure -purge --config-root=/path/to/qbittorrent/config && rm -f -- ./install.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -uninstall -configure -purge; if ($LASTEXITCODE -eq 0) { Remove-Item .\install.ps1 -Force }
```

Pentru un director personalizat, adaugă `-o D:\weig-qb-webui`.

Parametrul `-purge` elimină doar copiile de rezervă ale instalării pe care o dezinstalezi. Celelalte instanțe rămân neatinse. Dacă directorul comun pentru stare rămâne complet gol, se elimină și `~/.config/weig-qb-webui` pe Linux (pentru `root`: `/root/.config/weig-qb-webui`) sau `%APPDATA%\weig-qb-webui` pe Windows.

Dacă vrei să păstrezi copiile pentru un `-rollback` ulterior, dezinstalează fără `-purge`.

</details>
