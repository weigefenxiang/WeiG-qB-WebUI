### 1.1 正式 compatibility scope anchors

正式兼容优先级始终是 `qB 4.1.0+ official stable -> current stable -> 未来 official stable / future new major`。Future stable/new-major compatibility 必须继续由 **source-derived / 上游源码生成** 的 exact release facts、bounded inheritance 与 fail-closed UNKNOWN 驱动，不能因为 major 更高就整体拒绝，也不能盲继承 current latest 的危险写语义。

`qB 4.0.x` **不是当前实现/CI scope**；未来可选扩展只能经用户明确扩大范围，并通过集中 Legacy Adapter 进入 canonical WeiG semantics，禁止把 WebAPI v1/v2 patch 分支散落到 UI/caller。

验证职责继续分开：`Linux browser candidate` 与 `Windows browser candidate` 提供代表性跨平台浏览器证据；`Full qB Release compatibility audit` / all stable upstream source audit 证明完整 admitted stable source/product compatibility；需要真实 runtime/hosting 的行为还必须由 real-qB evidence 证明。任何一层 PASS 都不能自动替代另一层。

## 2. 0.3.75 已建立的 source / recovery / write-gate 基线

0.3.75 已把 0.3.74 source groundwork 闭合到 build/product packaging：

```text
exact qB source / official TS
-> per-shard source + recovery evidence
-> deterministic merge
-> Settings/source LKG v2
-> native bundle / catalog materialization
-> bounded runtime profile + exact bridge shards
```

### 2.1 Deterministic native-QM recovery

`tools/qb-native-qm-recovery.mjs` 是 canonical recovery owner。候选译文 winner 固定为：occurrence count 最大；同票时 newest exact qB stable 更新者优先；再同票按 lexical/codepoint translation order。并行 shard merge 必须 order-independent / associative；malformed/conflicting evidence fail closed。

完整 official recovery translation bodies 是 build-only 证据，只用于 materialize `translations/webui_<locale>.qm`；不得重新进入 browser release profile JSON，也不得把 exact Settings shard 膨胀成全历史翻译数据库。

### 2.2 Settings/source LKG v2

LKG v2 继续绑定：

```text
exact qbVersion
exact sourceSha
exact torrentTableColumns
exact source/translation bridge facts
canonical deterministic recovery union hash
```

Candidate source shards/LKG/package chain仍消费 exact-SHA certified artifact；0.3.77 没有改变 source parser 或 LKG owner。

### 2.3 0.3.75 write gates

Torrent File Priority 继续由 exact `torrentscontroller.h:filePrioAction` source ownership 决定；INHERITED/FALLBACK/UNKNOWN 或 source 未证明时 HTTP 前 fail closed。

Transfer normal/global rate-limit write 继续要求 `setDownloadLimitAction + setUploadLimitAction + toggleSpeedLimitsModeAction`；Alternative 模式继续要求 `appcontroller.h:setPreferencesAction + toggleSpeedLimitsModeAction`。`W.CapabilityRegistry` 的 strict `allActions` 与 `applyLimits()` preflight 保持不变。

## 3. 0.3.76 DataGrid 原生列正式消费

### 3.1 Source truth 不再停留在 evidence 层

此前 exact source/LKG 已经生成并保留 `torrentTableColumns`，字段包括：

```text
key
source order
caption / translation source
source defaultWidth
defaultVisible
dataProperties
```

0.3.76 不新增第二 parser，而是让正式产品 `W.TorrentFieldRegistry` 消费 `W.ReleaseProfile.torrentTableColumns`。对 exact/certified profile，这份 source schema 现在是 Desktop DataGrid column set/defaults 的 authoritative input；旧 17-field registry 保持 semantic/fallback owner，而不再限制 exact release 的原生列集合。

### 3.2 User override v2 / 非破坏迁移

`cfg.columns` 在 exact native schema 下升级为 full-schema user override：

```text
key
width
visible
layoutVersion: 2
```

迁移规则：

- 旧用户已有显示/隐藏、宽度与可识别顺序尽量保留；
- `state/status` 等通过已证明的 `dataProperties` 做 canonical mapping，而不是按版本猜；
- qB 新增 exact native column 自动按 source-relative 位置合入；
- 无用户 override 的新列使用 upstream `defaultVisible/defaultWidth`；
- 暂时不存在的 saved preference 不因 effective view 被删除；
- FALLBACK/UNKNOWN profile 不宣称 native column parity，继续安全回退到现有 legacy behavior。

Source-only native column 使用现有 torrentInfo object 的 source/dataProperty 值渲染，不再因为不在旧 17-field list 就只显示 `—`。这只是 presentation projection，不新增 API 请求。

### 3.3 Sort / interaction 边界

Field presence 不等于 server-sort proof。Source-only column 默认没有 sort；只有 direct canonical semantic 或 `dataProperties` 已映射到 canonical WeiG sort semantic 时才可复用该 sort key。

Columns interaction 仍由 `app.js -> openColumns()` 单一 owner 负责：

```text
checkbox visibility
↑ / ↓ reorder
Desktop drag reorder
Android 360 ms long-press drag reorder
```

Android 长按激活前移动超过阈值会取消 drag，普通纵向滚动继续由浏览器处理；没有 `MutationObserver`、monkey patch、post-render repair 或第二 layout owner。

## 4. Transfer / Locale / Tracker 的 0.3.77 current product semantics

### 4.1 Transfer data owner 不变

现有 `app.js` transfer cycle 仍通过同一个 `transfer/info` 请求取得：

```text
dl_info_data / up_info_data        session cumulative totals
dl_info_speed / up_info_speed      realtime rates
connection_status                  connection state
```

`W.TransferRuntime` 继续只保存 bounded realtime samples/history 与现有 metadata snapshot，不新增请求、timer、poll owner 或第二 state store。

### 4.2 Transfer presentation：单一 chart-bottom Download/Upload pair

Canonical compact transfer capsule 仍只显示本次 qB session cumulative totals：

```text
↓ 下载 <session downloaded>
↑ 上传 <session uploaded>
```

Drawer compact chart legend 同样 totals-only，不复制 realtime speed text。

0.3.77 删除 canonical Transfer statistics dialog 图表上方重复的 Download/Upload summary strip。完整 dialog 的唯一 Download/Upload summary 位于 chart 下方：

```text
left:  ↓ <realtime download> | 下载 <session downloaded>
right: 上传 <session uploaded> | ↑ <realtime upload>
```

Desktop/Mobile 复用同一组节点；窄屏只自适应换行/收缩，不恢复旧 2x2 owner。Chart averaging 是 display-only，默认 `10 s`，选项为 `Raw / 3 / 5 / 10 / 15 / 20 / 30 s`；长窗口继续使用 bounded minute buckets，不增加 poll/history。

### 4.3 Native WebUI return locale/root handoff

Persisted language truth 仍只有 `qB app/preferences.locale`。当同一次 verified Settings save 把 `alternative_webui_enabled` 切为 false 时，`W.SessionController.planNativeWebUiReturn / prepareNativeWebUiReturn / completeNativeWebUiReturn` 可在 Alternative WebUI root 仍 active 时先写/验证临时 locale，完成 root switch 后再写/验证最终目标 locale。

这个 transaction 不保存 `previousLocale`，不做 exit restore，不创建第二 language owner。若用户在同一次 save 明确选择 locale，该 locale 必须保持 final target。最终 Settings verification reread 仍决定 shared prefs 与 `W.I18n.applyLocale()`。

### 4.4 Tracker detail exact URL

qB upstream `TorrentsController::trackersAction()` 对正常 Tracker 直接把 `tracker.url` 放进 API JSON；`** [DHT] **`、`** [PeX] **`、`** [LSD] **` 是单独构造的特殊 entries。

因此 Torrent detail 的 Tracker display/edit 现在直接消费 exact API `url`，不再通过 `U.normalizeTracker()`。长 URL 使用 variable-height + wrap，编辑 prompt 以 exact URL 为初值。该变化只修正 presentation truth，不新增 endpoint 或 compatibility owner。

## 9. Truth hierarchy

发生冲突时：

```text
qB official source / exact runtime identity
-> admitted release profile
-> canonical WeiG product owner
-> real-qB evidence where applicable
-> browser / Virtual qB / Pages evidence
-> docs/tests/fixtures
```

Stale test、Simulator、old checkpoint 或旧 docs 必须跟随正确 source/runtime truth 更新；不得为旧结论降低安全边界。
