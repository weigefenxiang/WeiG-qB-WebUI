# 002. qBittorrent 兼容与实现状态

更新时间：2026-09-01  
当前产品版本：**0.3.6-dev**

## 1. 支持边界与判定原则

WeiG qB WebUI 的兼容目标不是“只支持几个写死版本”，而是：

```text
qBittorrent 4.1.9.1
→ 当前稳定版 5.2.3
→ 当前 upstream / next
```

兼容判定遵循 **COMPAT-001**：优先检测 WebAPI、endpoint、Preference key、response field 与 capability，禁止仅凭 qB major version 开关功能。

截至 2026-09-01，官方稳定版仍属于 5.x；仓库 `master` WebAPI 已进入 2.16.x 的下一开发线。官方尚无 6.x 正式版。因此 6.x 只能作为 **synthetic forward-major sentinel**，用于验证前端没有 `major > 5 => unsupported` 一类硬编码，不能宣称“已支持 qB 6.x”。

## 2. Release-blocking 实机环境

仓库只定义 release-blocking 的版本/能力目标：

```text
Legacy LIVE target
qBittorrent 4.1.9.1
WebAPI 2.2.1

Modern LIVE target
qBittorrent 5.2.x
WebAPI 2.15.x
```

具体 URL、IP、凭据、容器名、Host path 与 qB-visible path 均由测试操作者在运行时提供，不写入开源仓库。

自动 API fixture、Chromium browser fixture、静态 CI、源码分析都不能替代真实实例回归。

## 7. FLOATING-001：统一浮动层

所有 Select / Dropdown / Action Menu / Context Menu / Popover / Tooltip / Timezone picker 最终必须归一到同一个 Floating Layer contract：

```text
trigger.getBoundingClientRect()
        ↓
#weigg-floating-layer (document.body)
        ↓
position: fixed
        ↓
flip / shift / max-height / internal scroll
```

浮层不允许留在 `overflow:hidden/auto` 的业务容器中，也不允许以不断提高 `z-index` 作为裁切问题的修复方式。

## 8. TIME-002：Display Time Zone

时区属于 WeiG 前端显示层：

```text
qB timestamp
→ normalized epoch
→ W.Time
→ Intl.DateTimeFormat(timeZone)
```

UTC offset 根据当前日期与 IANA zone 实时计算，必须支持 `+05:30`、`+05:45` 和 DST。当前选择保存在 `localStorage: weigg.timeZone`，不会调用 `setPreferences()`，不会修改 qBittorrent daemon、Docker 或宿主机系统时区。

## 9. SETTING-UNIT-001：Advanced Unit / Enum Schema

Advanced 页面不能长期展示无法解释的裸数字。经过官方源码/API 验证的字段应提供 unit、API unit、display unit、enum 与 special value。涉及单位转换的字段必须先完成跨版本 read → display → write round-trip；未经验证禁止猜单位或自动换算。

## 13. LIVE regression

真实 LIVE 环境由操作者显式提供，不存放在仓库。至少覆盖：

```text
qB 4.1.9.1 / WebAPI 2.2.1
qB 5.2.x   / WebAPI 2.15.x
```

测试内容包括 Logs、全局时区、Settings/Advanced、Torrent Detail 返回、Alternative WebUI、Search/RSS、Desktop/Mobile/i18n 与 browser console。

Production cache header 也只针对操作者传入的实际 URL 检查，例如：

```sh
curl -I "$QB_URL"
```

HTML 目标仍是 `Cache-Control: no-store`。
