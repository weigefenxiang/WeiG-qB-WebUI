# 002. 兼容与实现状态

> 本文件只记录**当前仍有效的产品兼容事实与最新验证状态**。不维护 Phase A–G 历史里程碑。

`webui/**` 是正式产品；source catalog、real-qB、Virtual qB、browser 与 Pages 是发现/证明层，不替代正式产品语义。

## 2. Compatibility states

统一状态：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

优先级：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY when applicable
-> UNAVAILABLE
```

`UNKNOWN` 表示当前无法证明，不等于 supported，也不等于 permanently unsupported。危险写操作在 `UNKNOWN` 时必须 HTTP 前 fail closed。

禁止用：

```text
major/version-only final truth
blind nearest-version inheritance
404/501 after user click as feature detection
fake empty list masking error/unsupported
manual compatibility mode
```

## 3. Release profile resolution 当前实现

Runtime resolution 已从旧的 `exact || fallback` 改为：

```text
EXACT
EQUIVALENT
INHERITED
FALLBACK
```

语义：

```text
EXACT       exact canonical official stable profile
EQUIVALENT  canonical suffix equivalent, e.g. 5.2.3-r1 -> 5.2.3
INHERITED   same major.minor nearest lower certified profile if runtime/API relation remains valid
FALLBACK    no safe profile relation
```

典型期望：

```text
5.2.3-r1 -> 5.2.3 EQUIVALENT
5.2.3.1  -> 5.2.3 INHERITED
5.2.4    -> 5.2.3 INHERITED temporarily
```

但 inheritance 不授权新的危险能力；action/parameter/Preference write 仍由 source facts 证明。不能跨 hard translator/API boundary 盲继承，例如 `4.6.4 -> 4.6.5` 的 Alternative WebUI translation behavior 边界。

Runtime diagnostics 保留：

```text
detectedVersion
resolvedFrom
resolutionMode
```

## 4. Runtime release catalog 当前实现

真实 qB 4.6.7 验证发现：把 65 个 full release profiles 全部塞入单个 runtime `qb-releases.json` 会让文件接近 qB Alternative WebUI 静态资源的实用大小边界，并且旧 loader 会把 load failure 误吞成空 catalog/fallback。

当前生产 runtime 已改为 sharded：

```text
private/data/qb-releases.json                     # compact index
private/data/qb-release-profiles/<sourceSha>.json # one profile per shard
```

只加载当前 exact/equivalent/inherited profile shard。HTTP/index/profile load failure 应显式暴露，不允许静默转成“当前版本没有 source proof”。

在 `c1823...` materialized artifact 中曾实测：

```text
index ~14.6 KiB
65 profile shards
qB 4.6.7 profile shard ~183 KiB
qB 4.6.7 Settings bridge shard <1 MiB
96 minimal official QM files
```

Full 65-profile evidence 仍保留在 build/audit 层，不回到 runtime 单体文件。

## 6. 已验证的主要兼容语义

### 6.1 Torrent states / filters

旧 qB 与新 qB 状态名通过 canonical Torrent semantics 归一化；产品不把 qB4/qB5 major 当最终状态行为 oracle。

可靠旧 API 组合允许生成 `DERIVED` filter；无法可靠证明时降级或隐藏，不能伪造能力。

### 6.2 Categories / Tags

读、列举、创建/删除、分配等能力独立判定：

```text
read/filter != list != create/delete != assign
```

不同历史 API response shape 在 QBClient/正式 owner 中 normalize，不把 shape 差异泄漏到 presentation。

### 6.3 Settings

Settings 写入要求双重证明：

```text
app/setPreferences endpoint/action proven
AND
per-Preference descriptor proves writable/type agreement
```

Getter-only、missing setter、unknown endpoint、type mismatch、无法证明的 structured editor 都不得 blind write。

### 6.4 Locale / translation

Locale persisted owner：

```text
qB preferences.locale
-> shared preferences snapshot
-> W.I18n.applyLocale()
```

WeiG Language 与 Advanced Locale 两个入口共享同一个 `draft.locale`、同一 exact-release options、同一保存/回读确认事务。

qB-owned Settings 文案当前为 native-first：

```text
qB official source/context
-> QBT_TR
-> qB translator
-> official minimal QM
```

只有 source-proven gap 使用 exact official-TS bridge。

全 65 stable translator behavior audit 已完成：

```text
4.1.0-4.1.3  qapp-native
4.1.4        dedicated-native-no-explicit-fallback
4.1.5-4.4.5  dedicated-native-explicit-fallback
4.5.0-4.6.4  dedicated-alt-disabled
4.6.5-5.2.3  dedicated-native-explicit-fallback
```

当前 frozen routing evidence：

```text

1234 deduplicated official translation sets
2908 native-capable locale routes
616 mandatory exact-TS bridge routes
11 Alternative WebUI translation-gap releases
```

详细见 `docs/012.qB原生翻译与国际化复盘.md`。

### 6.5 Search / RSS / Logs

当前 admitted source facts 证明：

```text
RSS core: qB 4.1.0+
Logs main/peers: qB 4.1.0+
Search core: qB 4.1.4+
```

这些边界来自 source/action provenance，不应退化为简单版本阈值判断。

### 6.6 Torrent Details / actions

Properties、Files、Trackers、Peers、WebSeeds 的读取能力独立；File priority、Tracker mutations、Peer Ban 等写操作也独立。

Action form 必须由 exact action parameter facts 证明。参数不明时不发送 HTTP。

### 6.7 Torrent Creator

Torrent Creator 只在 exact source facts 证明相关 actions/parameters 时暴露。不能因为 qB major >= 5 就自动假设 creator capability 存在。

## 7. Windows qB config safety 当前状态

真实 Windows qB 4.6.7 事故证明，旧 PowerShell 5.1 whole-file config rewrite 会把 UTF-8 no-BOM 中文/日文转成 mojibake，并污染：

```text
Session\DefaultSavePath
Session\TempPath
SavePathHistory
Session\Tags
```

当前 `dev/installers/install.ps1` 已有 encoding-preserving strict read/write 和 byte round-trip check；`tests/windows-config-encoding.ps1` 已在 Windows PowerShell 5.1 下通过。

但以下 fail-closed 保护仍未完成：

```text
qB running detection
qBittorrent_new.ini conflict detection
zero/invalid config rejection
temp write + strict verify + atomic replace
portable/custom/multiple-config ambiguity handling
```

用户本机最终已恢复并在 qB 启动后验证 `MojibakeMatches=0`。完整事故复盘见 `docs/013.Windows配置编码事故复盘.md`。

## 11. Future stable 原则

发现新的 official stable 时：

```text
verify current Frozen LKG
-> discover new official stable
-> extract exact source facts
-> preserve historical prefix
-> run source/product contracts
-> review compatibility diff
-> admit into Frozen LKG
```

在 admission 前 runtime 可以使用受约束的 same-series `INHERITED` profile 作为临时兼容，但不能凭继承 invent capabilities。source facts 不足或 hard boundary 不明时保持 fail closed。

## 13. Truth hierarchy

发生冲突时优先级：

```text
qB official source / exact runtime identity
-> admitted release profile
-> canonical WeiG product owner
-> real-qB evidence
-> browser / Virtual qB / Pages evidence
-> docs/tests fixtures
```

Stale test、Simulator 或 docs 应跟随正确 source/runtime truth 更新。
