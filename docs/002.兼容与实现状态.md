# 002. qBittorrent 兼容与实现状态

更新时间：2026-09-02  
当前产品版本：**0.3.7 dev candidate**

## 1. 支持边界与判定原则

WeiG qB WebUI 当前兼容目标：

```text
qBittorrent 4.1.9.1 / WebAPI 2.2.1
→ 后续官方正式 4.x / 5.x
→ 当前稳定线 5.2.x
→ current upstream WebAPI monotonic sentinel
```

兼容判定遵循 **COMPAT-001**：优先检测 WebAPI、endpoint、Preference key、response field 与 capability，禁止仅凭 qB major version决定功能。

Synthetic future-major fixture 只用于验证没有 `major > 5 => unsupported` 一类硬编码，不代表正式宣称支持尚未发布的 qB major version。

## 2. 验证分层：日常双基准，Release 才跑全量

日常开发与正式 Release 使用不同成本的证据链，不能混为一谈。

### 2.1 dev 日常 upstream audit

`.github/workflows/upstream-compat.yml` 在每次 `dev` push 上只浅拉取两个明确 release tags：

```text
release-4.1.9.1
release-5.2.0
```

然后运行：

```text
node tests/upstream-release-audit-v037.mjs upstream-qb \
  --refs=release-4.1.9.1,release-5.2.0
```

这两个节点分别代表最低 legacy 边界和现代 5.2 线。脚本同时读取 `origin/master` 的 WebAPI 版本，作为“upstream WebAPI 不应倒退到已审计稳定版之前”的轻量 sentinel；日常 dev **不会**遍历全部 stable tags。

目的：普通开发快速发现最关键的老/新 API bridge 回归，而不是每次提交都消耗完整仓库历史和全版本矩阵。

### 2.2 dev focused UI gate

当提交信息包含 `[ui]`，或从 `dev` 手动选择 `validation_mode=ui`，只增加一个 Linux Chromium focused gate。

当前 focused browser 同一次 Chromium 运行固定覆盖：

```text
qB 4.1.9.1 / WebAPI 2.2.1  -> mobile 390×844
qB 5.2.0   / WebAPI 2.15.1 -> desktop 1440×900
```

主要锁定 Settings 母版、About/Brand、StatusDock、Transfer editor、Advanced scroll 和共享响应式 ownership。它不是 Release 全矩阵。

### 2.3 main Release candidate 全 stable-tag 源码/API 审计

只有 `main` 上手动运行：

```text
workflow_dispatch
validation_mode=candidate
```

才执行 `Full qB Release compatibility audit`：

```text
checkout qbittorrent/qBittorrent with full history/tags
→ 枚举 release-4.1.9.1 起全部官方正式 4.x/5.x tags
→ 从每个 tag 官方源码读取 API_VERSION
→ 验证 WeiG QBClient capability/API bridge
→ 再核对 current origin/master WebAPI
```

最近一次完整审计基线记录为：

```text
55 official stable tags
40 qB 4.x releases
15 qB 5.x releases
floor: 4.1.9.1 / WebAPI 2.2.1
latest audited stable: 5.2.3 / WebAPI 2.15.1
master WebAPI at that audit: 2.16.2
```

这些数字属于 Release 全量证据，不代表每次 dev 都重新跑 55 个 tags。

## 3. LIVE gate

Fixture/browser success 不能替代真实 qB daemon。晋级 `main` 前，当前 exact `dev` SHA 至少需要两个真实边界：

```text
Legacy LIVE
qBittorrent 4.1.9.1
WebAPI 2.2.1

Modern LIVE
qBittorrent 5.2.x
WebAPI 2.15.x
```

真实 URL、凭据、Docker container、Host path、qB-visible path 只作为 runtime input，不写入公开仓库。任何代码变化都会产生新 SHA，旧 SHA 的 LIVE PASS 不自动继承。

## 4. 关键 API bridge

WeiG `QBClient` 负责跨版本语义归一：

```text
qB 4.x resume/pause
        ↕
WeiG semantic resume/pause
        ↕
qB 5.x start/stop
```

同样处理：

```text
paused / stopped filter vocabulary
editTracker origUrl / url parameter migration
legacy/modern auth response
WebAPI capability thresholds
structured torrents/add
exact private field availability
```

Release compatibility contract 会逐 representative release 验证这些 bridge，避免“页面能打开，但操作 endpoint 已变”的假兼容。

## 5. Alternate WebUI entry contract

qB Alternate WebUI package 必须同时存在：

```text
public/index.html
public/login.html
private/index.html
```

Linux/Windows installer、platform contract、Release candidate 都强制检查这三个入口。

登录兼容覆盖：

```text
legacy qB 4.x: HTTP 200 + "Ok."
modern qB 5.x: HTTP 204
invalid credentials
HTTP 403 temporary ban
```

## 9. Display Time Zone

时区属于 WeiG 前端显示层：

```text
qB timestamp
→ normalized epoch
→ W.Time
→ Intl.DateTimeFormat(timeZone)
```

唯一控制入口是 `Settings → WeiG WebUI → Display Time Zone`。状态栏不复制第二个 timezone control；选择保存在浏览器 local state，不修改 qB daemon、Docker 或宿主机时区。

## 10. Storage telemetry

数据源：

```text
sync/maindata
→ server_state.free_space_on_disk
```

表示 qBittorrent 默认保存路径所在文件系统可用空间，不等于通用 VPS `/` 剩余空间。显示使用 IEC 自动单位 `B/KiB/MiB/GiB/TiB`。

## 11. Installer compatibility contract

安装器有两个显式频道：

```text
release  -> 默认，latest GitHub Release + SHA256SUMS + exact GIT_SHA
dev      -> 当前 dev exact SHA source archive，明确标记 development channel
```

Release 频道 fail closed，绝不会因为 Release 不存在而偷偷退回 branch archive。dev 频道必须由用户显式选择。

Linux downloader/extractor/checksum 允许多实现 fallback，以兼容 NAS/BusyBox 等环境；最终 payload 仍强制检查三个 Alternate WebUI 入口与 40 位 exact Git SHA。

## 12. Release 判定

最终发布 SHA 必须满足：

```text
dev smoke/static/platform                    PASS
dev qB 4.1.9.1 + 5.2.0 upstream audit       PASS
focused [ui] when UI changed                 PASS
Legacy 4.1.9.1 LIVE                          PASS
Modern 5.2.x LIVE                            PASS
operator explicit LIVE-PASS                  PASS
main full official stable-tag audit           PASS
main full fixture compatibility matrix        PASS
Linux browser matrix                          PASS
Windows browser matrix                        PASS
exact-SHA release candidate artifact          PASS
```

Fixture/CI PASS 不冒充实机 PASS；synthetic future-major sentinel 不冒充正式版本支持。
