# 002. 兼容与实现状态

> 当前兼容状态与剩余工作。Structural truth 以 upstream source-derived stable catalog 为准；semantic evolution 的后续路线以 003/009 定义的 Endpoint Contract + WebAPI Evolution Audit 为准；旧实现由 Git history 保存。

## 1. 正式支持范围

- WebAPI v2 主线正式下限：**qBittorrent 4.1.0**；
- 上限：**当前上游最新官方 stable**，不硬编码最新 patch 或 stable 数量；
- Alpha / Beta / RC / master 不进入正式 stable matrix；
- qB 4.0.x 属于旧 WebAPI v1，当前不在主线支持范围。未来如支持，使用独立 Legacy WebAPI v1 Adapter，不污染 v2 router/contract owner；
- `tools/qb-release-catalog.mjs` 从 official stable tag/source 生成 matrix；
- `tests/upstream-release-audit.mjs` 从 4.1.0 到 latest stable 做完整 source audit；
- `4.6.1 -> WebAPI 2.9.3` 是 contract 保护的历史事实。

## 2. Structural compatibility truth — 已建立

```text
qB upstream stable source
-> source parsers
-> qb-release-catalog
-> qb-releases.json
-> W.ReleaseProfile
```

每个 exact profile 至少包含：

- qB version / WebAPI version / tag / source SHA；
- Preferences getter/setter descriptors；
- `apiActions`；
- Torrent filter surface；
- `torrents/info` parameter surface。

Structural truth 回答：

```text
endpoint 有没有？
Preference 有没有 getter/setter？
Torrent filter / info parameter 有没有？
```

这部分已经是当前正式 owner，不再由 caller 手写 patch allowlist。

## 3. Product runtime compatibility — 已建立

### Capability

`W.ReleaseProfile` 提供 exact source facts，`W.CapabilityRegistry` 负责 user-visible policy。Source-bound feature 不在 exact upstream surface 时正常 UI **隐藏**，不保留 disabled + badge clutter；unknown capability id fail closed。

### Torrent

`W.TorrentSemantics` 是 status/filter semantic owner：

- qB4 source `paused/resumed` <-> canonical `stopped/running`；
- qB5 使用 `stopped/running`；
- unknown/retired filter fail closed；
- Completed != Seeding；
- Private authoritative metadata 与 PT domain classification 分开处理。

### Settings

`W.SettingsSchema + exact Preference descriptors` 决定 route/type/editability。Setter missing/unresolved/type mismatch/missing descriptor 均 read-only；structured value 仍 read-only，直到有专用 editor contract。

## 4. Semantic evolution — 当前主要剩余工作

`apiActions` 只能回答 endpoint existence，不能表达同一个 endpoint 在不同 WebAPI revision 中的参数、response、status code、no-op、mutation 变化。

当前 simulator 已通过历史 contracts 修正多项真实差异，例如 tracker/editCategory/response projection 等；但这些 semantic version facts 仍有一部分直接存在于 protocol router/core caller 中。

因此当前阶段不再继续随机增加 router version branches。批准的下一步是：

```text
Approved Target Owner:
simulator/protocol/endpoint-contracts.js

stable caller interface:
resolveEndpointContract(profile, path)
```

该 owner 尚未完成 runtime cutover，所以现在仍是 **planned/approved architecture**，不是 Current Owner。

## 5. OWNER-CUTOVER 状态

后续 migration 必须两步完成：

1. **Dormant validation**：新 Endpoint Contract owner 先独立存在，由 direct contracts 验证；正式 runtime 仍只有旧路径。
2. **Atomic cutover**：验证成功后下一变更立即迁移全部 caller，并删除 superseded router version branches/helpers/tests/files/docs；禁止 long-lived new/old dual-active fallback。

只有职责被替代的代码删除；`apiActions/upstream-gates` 等 endpoint-existence owner 与 Endpoint Contract 职责正交，继续保留。

## 6. Full WebAPI Evolution Audit — 尚未开始系统化扫描

Audit 将按 upstream WebAPI release chronology 从 2.0.x 到 latest stable 扫描，不再按 endpoint 随机发现。

每条 change 必须分类为：

```text
NEW_ENDPOINT / REMOVED_ENDPOINT
PREFERENCE / TORRENT_SURFACE
PARAMETER_CHANGE / RESPONSE_CHANGE
STATUS_CHANGE / MUTATION_CHANGE
TRANSPORT_CHANGE / NOT_APPLICABLE
```

目标 ledger 状态：

```text
SOURCE_DERIVED
CONTRACT_COVERED
NOT_APPLICABLE
MISSING
UNCLASSIFIED
```

`UNCLASSIFIED` 未来必须 fail closed；先完成完整 ledger，再集中修 `MISSING`。

## 7. Future stable strategy

新 stable release 自动进入 structural catalog；若 WebAPI semantic revision 已知或可证明安全继承，则自动继续验证；若出现未分类 semantic delta，CI/Audit 失败，禁止按“更高版本应该兼容”推断通过。

未来 Endpoint Contract 的公共接口必须隐藏内部数据来源，允许后续从 audited table 升级为 generated semantic catalog/source parser，而 router caller 无需改变。
