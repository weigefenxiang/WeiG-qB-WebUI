## 3. Settings 当前实现

Current value/presence owner仍是真实 qB WebAPI：

```text
W.QBClient.getPreferences()
-> app/preferences actual keys + values
-> W.SettingsSchema semantic grouping/control
-> W.ReleaseProfile exact setter/type/action provenance
-> W.SettingsRenderer
```

Write 仍要求 source-proven writable/type + `setPreferences` action，并在 POST 后 `getPreferences()` verification reread。Unknown returned Preference 没有 exact setter/type proof 时只读。

Native Settings topology 由一个 canonical tab reconciler统一暴露 Behavior / Downloads / Connection / Speed / BitTorrent / RSS / Web UI / Advanced 等 source-proven surface；不恢复独立 Speed/tab patch owner。

## 7. Generic Detail action contract

Toolbar、blank-area context menu 与 row context menu必须消费同一 canonical action chain：

```text
source/menu or exact local source fact
-> source availability / selection context
-> W.ReleaseProfile.actionDescriptor(sourceAction) when transport is required
-> endpoint agreement
-> required/optional parameters + source-proven options
-> generic context binding
-> W.QBClient.request(exact endpoint)
```

本地 presentation-only source action（例如 Copy）不能伪装成 WebAPI write；transport action缺少 exact proof时必须在 HTTP 前 fail closed。

Files hierarchy中的 synthetic folder row只是 presentation projection，不自动获得真实 file mutation capability。file write继续绑定 exact qB source file index/path；folder Rename与file Rename分别消费各自 exact source action provenance，不能用 folder DOM顺序、child row或 file write address互相推导。

## 8. Transfer / capability / shared owner

Transfer继续使用 existing `transfer/info` + `W.TransferRuntime`；没有第二 polling owner。Desktop sidebar / mobile / full chart只消费同一个 realtime/session owner。短高度桌面布局可改变空间优先级，但不得复制 timer/history/request state。

Read/write/action/field/parameter capability继续分离证明；dangerous `UNKNOWN` 必须 transport前阻断。

一个 semantic purpose只有一个 Current Owner；禁止 runtime alias、monkey patch、MutationObserver repair、post-render repair、第二业务状态或重复 polling。

## 9. Installer / Universal Portable / distribution

Stable installer消费 immutable Release + checksum/identity；Dev installer只消费 Pages exact-SHA materialized distribution，禁止 raw-source fallback。

Dev channel继续区分 installer bootstrap identity 与 WebUI payload identity：当前 dev 测试 bootstrap 来自 `dev/installers/*`；正式 WebUI payload仍只能来自 `downloads/dev` materialized distribution。

Universal Portable要求继续成立：同一 materialized `WeiG-qB-WebUI/` 可离线复制到受支持 qB 主机并直接作为 Alternative WebUI 使用。

Materialized runtime保留 release/profile/translation compact IR、local qB Peer flags、VERSION/GIT_SHA 等必要资产，并继续拒绝旧全量 Settings runtime shards 与外部 flag CDN truth回流。
