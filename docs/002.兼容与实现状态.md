# 002. qBittorrent 兼容与实现状态

更新时间：2026-09-04  
当前产品版本：见仓库根 `VERSION`（Canonical）

## 1. 支持边界

兼容目标：qBittorrent 4.1.9.1 floor -> 官方 4.x/5.x -> 当前稳定 5.2.3。前端只有一套；technical endpoint facts 留在 `QBClient`，用户可见的版本门槛、badge、禁用态与解释统一归 `W.CapabilityRegistry + data/capabilities.json`。

### COMPAT-DEGRADE
旧版缺 authoritative/低成本能力时默认明确降级，不做昂贵模拟。

### PERF-COMPAT
Collection/List 禁止默认 `N items -> N API requests` fallback。

### CAPABILITY-RANGE
Capability 以 semantic range 判断，不依赖精确 release 枚举。`>=5.0.0`、`<5.0.0`、上下界和 exception 都可表达；任意 patch 字符串按范围比较。

## 2. Current-only boundary

WeiG 自身旧 release runtime/tests/deploy scripts 不保留兼容副本。历史恢复使用 Git history / tags / Releases。

当前 qB/WebAPI facts 必须保留：

```text
Minimum qBittorrent: 4.1.9.1
Current stable qBittorrent: 5.2.3
Private/PT exact metadata: qBittorrent 5.0.0+
Tags: WebAPI 2.3.0+
Known qB-facing Tags boundary: qBittorrent 4.2+
Representative browser/audit generations: qB 4.1.9.1 + 5.2.0
```

**此功能需要 qBittorrent 5.0.0+** 和 **WebAPI 2.3.0+** 都是当前 upstream capability facts，不属于 WeiG 历史兼容包袱。

## 3. Capability Registry

运行时只检测一次当前：

```text
qbVersion
webApiVersion
```

随后 Registry 在本地 JSON 中判断：

```text
supported / disabled / degraded / hidden
```

默认 user-facing unsupported policy：

```text
visible + aria-disabled + qB-facing badge + Tooltip + shared Dialog
```

不会为每个功能单独请求 API。

WebAPI requirement 的主界面 badge 优先映射成用户理解的 qBittorrent 版本；例如 `WebAPI >=2.3.0` 显示 `4.2+`。Dialog 同时显示原始 WebAPI requirement 与当前 qB/WebAPI。如果没有可靠 qB milestone，则显示 `需升级 / Upgrade`，禁止猜测。

## 4. Private / PT

qB5：authoritative Private metadata -> `TorrentSemantics` -> filter/badge/detail。

qB4：`Private / PT  5+` 保持可见但不可执行；Hover 给简要原因；Click -> canonical Capability Dialog -> filter unchanged。

Current guarantee：

```text
0 legacy Private tracker scan
0 resolveMany
0 per-torrent privacy queue
0 DHT/PeX/LSD inference
```

## 5. Tags / Search / RSS / Logs

Tags boundary = **WebAPI 2.3.0+**。已知 qB-facing milestone = **4.2+**。

Unsupported Tags：

```text
全部标签  4.2+
visible
aria-disabled
click -> shared Capability Dialog
0 Tags endpoint request caused by the click
0 filter state mutation
```

Search / RSS / Logs 也由同一个 Registry 决定是否可用，不再由 `app.js` 单独隐藏。

## 6. Range 与 exception

Registry 支持：

```text
eq / gt / gte / lt / lte
all / any / not
```

例如：

```text
qB >=5.0.0
qB <5.0.0
qB >=4.2.0 AND qB <5.0.0
WebAPI >=2.3.0
qB ==4.3.3 OR WebAPI >=2.8.0
```

`4.9.2 / 4.9.3` 可作为 synthetic boundary inputs 验证 `<5.0.0` range engine；这不表示 upstream 一定发布过这些具体版本。

## 8. Validation coverage matrix

“支持多少版本”“fixture 有多少节点”“Linux/Windows Browser 跑多少版本”“LIVE 跑多少实例”是四个不同问题，必须分开记录：

| Validation layer | Coverage | Purpose |
| --- | ---: | --- |
| Supported stable range | 55 real stable releases | 产品支持声明：4.1.9.1 -> 5.2.3 |
| Fast/representative generation gate | 2 versions | 4.1.9.1 + 5.2.0，覆盖 legacy/modern 主路径 |
| Fixture release matrix | 20 nodes | 18 real releases + upstream master + 6.0 synthetic sentinel |
| Full upstream stable-tag audit | 55 real stable tags | 逐 tag 读取 upstream WebAPI facts 并验证 compatibility bridges |
| Linux Hosted Chrome browser | 2 representative generations | qB4 floor + qB5 modern semantic/browser path，不启动 55 个 qB binary |
| Windows Hosted Chrome browser | 2 representative generations | 与 Linux 相同的 qB4/qB5 semantic/browser path，验证 Windows platform/browser runtime |
| Real LIVE | 2 real endpoints | qB 4.1.9.1 + current qB 5.2.x exact-SHA deployment/API truth |

## 9. Rate / Transfer

Canonical rate = B/s；NORMAL endpoint B/s；ALT preference KiB/s；QBClient read ×1024 / write ÷1024。

Transfer windows `1m/5m/15m/30m/1h/3h/6h/12h`；raw max 900；minute buckets max 720；long window 不增加 polling。

## 11. Fixture / forward sentinel

Representative fixture/browser generation 固定 `4.1.9.1 + 5.2.0`。Release fixture matrix 含 **5.2.3**；full upstream stable-tag audit 当前覆盖全部 55 个 supported releases。

未来 major 只允许明确标记的 **synthetic / 哨兵 / sentinel** fixture 做前向检查；synthetic 不构成实际支持声明。

## 12. LIVE gate

Current exact `dev` SHA 必须在 qB 4.1.9.1 与 current qB 5.2.x 两个真实实例验证：qB4 capability degradation、qB5 native path、Tags range、Connection single rendered marker/help、Header end anchor、route/settings、desktop/mobile、Light/Dark、Transfer units/history。

任何 code/test/docs 变化产生新 candidate，旧 SHA 证据不继承。

## 13. Release 判定

最终发布要求：current contracts PASS；representative upstream PASS；full stable-tag audit PASS；focused Hosted Chrome PASS；qB4 LIVE PASS；qB5 LIVE PASS；explicit LIVE-PASS；Linux+Windows browser gates；exact-SHA artifact/SHA256SUMS。`main` 未经明确授权不移动。
