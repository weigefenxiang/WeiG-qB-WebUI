## 2. 0.3.75 已完成的 source / recovery / LKG 链

0.3.74 的 source groundwork 已真正闭合到 build/product packaging：

```text
exact qB source / official TS
-> per-shard source + recovery evidence
-> deterministic merge
-> Settings/source LKG v2
-> native bundle / catalog materialization
-> bounded runtime profile + exact bridge shards
```

### 2.1 Deterministic native-QM recovery

`tools/qb-native-qm-recovery.mjs` 是 canonical recovery owner。候选译文 winner 固定为：

```text
1. occurrence count 最大
2. 同票时，支持该候选的 newest exact qB stable 更新者优先
3. 再同票时，按 lexical/codepoint translation order
```

因此并行 shard 的合并必须 order-independent / associative； malformed/conflicting evidence 必须 fail closed。

完整 official recovery translation bodies 是 **build-only** 证据，只用于 materialize `translations/webui_<locale>.qm`。它们不得重新进入 browser release profile JSON，也不得把 `private/data/qb-settings/<sourceSha>.json` 膨胀成全版本翻译数据库。

### 2.2 Settings/source LKG v2

LKG v2 绑定并冻结：

```text
exact qbVersion
exact sourceSha
exact torrentTableColumns
exact source/translation bridge facts
canonical deterministic recovery union hash
```

Candidate CI 的 source shards 会上传 `.recovery.json`；merge 生成 deterministic recovery sidecar；LKG job 生成 exact-SHA certified artifact；release candidate packaging 必须消费该 exact-SHA LKG，而不是临时/隐式 fallback。

### 2.3 Native bundle / exact bridge

Native-capable exact routes使用 certified full deterministic recovery union生成 QBT_TR/QM；qApp native 保持 native。`4.5.0 -> 4.6.4` 因 upstream Alternative WebUI document translation 被 exact source 证明为不可执行，仍必须走 narrow exact official-TS browser bridge。

这个 gap 是 hard boundary，不能因为 recovery QM 更完整就错误改成 native。

### 2.4 Legacy dynamicTable parser 修复

qB 4.1.0 的真实 `dynamicTable.js` 含类似：

```text
//Don't round up
```

旧 block scanner 不理解 JS 注释，误把注释内 apostrophe 当 string 起点，导致 `TorrentsTable Class: unterminated block`。当前 scanner 已明确区分：

```text
code
line-comment
block-comment
string
```

并有 quote / brace-in-comment regression contract。后续 parser 不能恢复跨 comment/statement 的宽松猜测。

## 3. 0.3.75 产品写能力已完成的 fail-closed 收口

### 3.1 Torrent File Priority

File Priority 动态 UI 与 transport 共用 exact `torrentscontroller.h:filePrioAction` source ownership。EXACT/EQUIVALENT 可写；INHERITED/FALLBACK、action 缺失或 source 未证明时必须在 HTTP 前 fail closed，zero request。

### 3.2 Transfer global / alternative rate limits

Transfer Apply 不再只靠“版本看起来支持”或单个 action。

Normal/global 模式要求全部：

```text
transfercontroller.h:setDownloadLimitAction
transfercontroller.h:setUploadLimitAction
transfercontroller.h:toggleSpeedLimitsModeAction
```

Alternative 模式要求全部：

```text
appcontroller.h:setPreferencesAction
transfercontroller.h:toggleSpeedLimitsModeAction
```

`W.CapabilityRegistry` 支持 strict `allActions`：必须 `every()` 成立。Transfer dialog 会按当前 normal/alt 模式动态绑定对应 capability，真正执行 `applyLimits()` 前再次 preflight，避免 `Promise.all()` 出现只写成功一部分的半事务风险。

qB 4.1.0 与当前 5.2.3 upstream source均存在这些 endpoint actions；但正式 runtime 仍按 exact release source facts 判断，不因版本号猜写能力。

这次没有更换 Current Owner：source facts仍由 `W.ReleaseProfile`，user-visible capability strategy仍由 `W.CapabilityRegistry`，transport仍由 `W.QBClient`。因此 `DESIGN.md` / `docs/003` 不需要为了 `allActions` 新造第二 owner。
