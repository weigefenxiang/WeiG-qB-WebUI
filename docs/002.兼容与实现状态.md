# 002. qBittorrent 兼容与实现状态

更新时间：2026-08-31

## 目标范围

- Compatibility floor: qBittorrent 4.1.9
- 4.x target: 4.1.9 → 4.6.x
- 5.x target: 5.0.x → 当前稳定 5.2.x
- Future: 未验证的新版本进入 capability-based compatibility mode，不允许 UI 直接绑定版本号。

## 已实现差异

### Torrent start/stop

```text
qBittorrent 4.x
resume / pause

qBittorrent 5.x
start / stop
```

`QBClient` 根据检测到的 qB 主版本选择首选 endpoint；若返回 404/405，会自动尝试另一套 endpoint。

### Torrent stopped filter

```text
qBittorrent 4.x: paused
qBittorrent 5.x: stopped
```

UI 始终使用统一的“已暂停”语义，由兼容层转换。

### Version parsing

不得使用 `parseFloat(WebAPIVersion)`。

例如：

```text
2.11.3 > 2.8.0
```

但 `parseFloat("2.11.3")` 会错误得到 `2.11`。

当前实现使用点分段整数比较。

qB 应用版本允许带 `v` 前缀，例如 `v5.2.3`，检测时会先标准化再提取 major。

### Historical capability exceptions

qBittorrent 4.3.3 的 WebAPI version reporting 存在已知历史异常，因此兼容判断不能只依赖报告版本；当前对已知能力保留显式补偿入口。

### Legacy filter capabilities

`stalled` 系列过滤不是所有早期 4.x WebAPI 都具备。UI 会根据 WebAPI capability 隐藏不支持的筛选，而不是向旧版发送已知不支持的请求。

## 性能实现

Torrent 主列表固定默认：

```text
limit = 50
offset = page * 50
```

因此主 Torrent DOM 默认不超过当前批次规模。

Files / Trackers / Peers 使用统一 `VirtualList`：

```text
Data array
  ↓
Viewport + overscan
  ↓
Mounted DOM rows
```

数据项数量不会直接等于 DOM 节点数量。

- JS syntax
- 关键导航恢复入口存在
- 50 条分页入口存在
