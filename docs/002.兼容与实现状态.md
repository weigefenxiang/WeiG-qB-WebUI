# 002. 兼容与实现状态

> 当前产品兼容状态。最高目标是让同一份 `webui/**` 在真实 qBittorrent 4.x / 5.x stable 上自动适配；source catalog / ledger / Virtual qB 用于证明和辅助实现这一目标，不再把 simulator fidelity 当产品主进度。

## 1. 正式支持范围

- 长期产品目标：**qBittorrent 4.x / 5.x official stable**；
- 当前 WebAPI v2 正式支持策略：**qBittorrent 4.1.0 -> latest official stable**；
- 当前完整 source-derived stable matrix 已验证：**qB 4.1.0 -> 5.2.3，共 65 个官方 stable profile**；
- 当前 audited semantic ceiling：**WebAPI 2.15.1**；
- qB 4.0.x 属于 WebAPI v1，当前仍是明确产品缺口；若要覆盖全部 qB4 stable，需要独立 Legacy WebAPI v1 Adapter；
- Alpha / Beta / RC / master 不进入正式 stable matrix；未来未知 semantic revision 不自动继承最后已知行为；
- stable tag 枚举不再使用 `4|5` major 上限，未来 official stable major 只要满足支持 floor，就会进入 source audit，而不是被正则静默漏掉。

## 3. 产品主线 — `webui/**`

`webui/**` 是唯一正式产品。兼容工作优先修改/验证：

```text
W.QBClient
W.ReleaseProfile
W.CapabilityRegistry
W.SettingsSchema
W.TorrentSemantics
以及直接消费这些 canonical owners 的正式 UI/runtime
```

目标是让 UI 只消费统一 WeiG semantics，把 qB4/qB5 差异尽量在 compatibility owner 截止。

已有产品兼容基础包括：

- qB4 `resume/pause` 与 qB5 `start/stop` 的 Torrent action 映射；
- qB4 `paused` 与 qB5 `stopped` filter 映射；
- `editTracker` legacy `origUrl` / modern `url`；
- legacy `torrents/add` 文本结果与 modern structured result normalization；
- source-derived release/action/filter/parameter facts；
- exact Preference getter/setter/type provenance；
- Settings/Torrent/Capability current owners。

这些是 Phase B 的起点，不代表整个 `webui/**` 已完成 qB4/qB5 全功能兼容。

## 4. 自动适配策略

每项产品功能依次尝试：

```text
1. 原生等价 API 映射
2. request/response normalization
3. 可靠的旧 API 组合/emulation
4. 从 canonical 已有数据本地推导
5. 真正无法实现时才 hide/read-only/capability notice
```

“隐藏”不是默认策略。功能在稳定 qB4/qB5 上应尽可能都能实现。

同时禁止：

- 伪造真实 qB 根本没有的数据；
- 用高成本 N items -> N requests 作为默认兼容；
- 在 presentation 中散落版本判断；
- 点击后才出现 404/501 才叫“适配”。

## 7. 已确认的正式产品缺口

Phase E 产品审计已确认以下问题，不再把它们当 simulator-only backlog：

1. **qB 4.0.x WebAPI v1 transport adapter 缺失**：当前 `QBClient` 使用 `/api/v2/`；这是独立 P0 轨道，但不混入 Phase B。
2. **状态筛选本地推导未接入**：`TorrentSemantics` 已能可靠判断多种状态，但 UI 支持面仍主要跟随 native filters。
3. **旧版 Category facet 可从 torrent catalog 推导但未使用**：早期 qB 已返回 `category` 字段，即使 categories taxonomy endpoint 尚未出现。
4. **Tags read/filter 与 Tags write/list capability 错误耦合**：早期 qB 已返回 `tags` 字段；读/筛选能力应与修改 Tags 分开。
5. **Reannounce 在不具备 upstream action 的 release 上仍可暴露**：应在点击前 source-derived gate。
6. **Remove Tracker 在缺少 endpoint 的 release 上仍可暴露**：应精确 gate/normalize，不允许 click-to-404。

补充结论：

- 当前 17 个正式 Torrent columns 所需字段在 qB 4.1.0 已基本存在，因此 Columns 暂无同等级 runtime blocker；后续做 field provenance registry 硬化。
- Settings 当前 exact Preference provenance / fail-closed 设计较强，Phase B 不重写。
- Search / RSS / Logs 现有 capability guard 未发现同等级 qB4.1+ blocker，Phase B 不改。

## 8. Phase B — qB4.1+ Product Compatibility Core — NEXT

Phase B 只解决 qB 4.1.0+ WebAPI v2 的三组已确认产品问题：

### B1. Filters

目标：

```text
native upstream filter
-> otherwise reliable local TorrentSemantics derivation over canonical catalog
-> otherwise unavailable/hide
```

优先覆盖：downloading / seeding / completed / stopped / running / active / inactive / stalled / stalledUP / stalledDL / checking / moving / errored。

Private/PT 只有在语义完整、证据可靠时才开放 fallback，不能把 PT tracker heuristic 冒充完整 authoritative private flag。

### B2. Category / Tags facets

目标：

```text
native taxonomy endpoint when available
-> otherwise derive distinct values from already-fetched canonical Torrent catalog
```

必须把：

```text
read/filter Category/Tags
```

与：

```text
create/edit/remove Category/Tags
```

分开 gate。

### B3. Torrent Action availability / normalization

建立单一正式 action resolver：

```text
WeiG semantic action
-> exact ReleaseProfile source action
-> parameter normalization / reliable emulation
-> unsupported before click
```

第一批必须消除 Reannounce / Remove Tracker 的 click-to-404。
