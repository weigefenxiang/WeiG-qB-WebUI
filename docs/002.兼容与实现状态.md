## 2. 正式支持范围与 future stable/new-major 原则

当前正式实现/CI floor 是 **qB 4.1.0 official stable**。`qB 4.0.x / WebAPI v1` **不是当前实现/CI 范围，属于 future optional**。

未来 stable / new-major 兼容优先依赖 **source-derived / 上游源码生成的 release truth**，而不是硬编码 major/version 阈值。Synthetic forward-major sentinel 只用于证明“不要按 major 硬拒绝”，不能把未发布版本声明为 supported。

发现 future stable 时应：

```text
verify Frozen LKG
-> discover official stable
-> derive source truth from upstream source
-> preserve historical prefix
-> run source/product contracts
-> review compatibility diff
-> admit into Frozen LKG
```

在正式 admission 前，只允许受约束的 same-series `INHERITED` profile；source facts 不足或 hard boundary 不明时保持 fail closed。

## 3. 当前已完成的 P0/P1

### 3.1 Release exact identity

Linux/Windows stable installer 当前都执行：

```text
resolve Release tag metadata
-> resolve tag to exact commit SHA
-> pin asset URL to resolved tag
-> verify SHA256SUMS
-> require package VERSION == tag version
-> require package GIT_SHA == tag commit SHA
```

成功时 source identity 明确输出：

```text
Source: Release v<VERSION> at <40-char SHA> (checksum and Release identity verified)
```

指定版本不存在、tag/version/SHA 不一致或 checksum 不一致时全部 fail closed；不得 fallback 到 latest/dev。

### 3.2 Dev materialized-only distribution

Linux 和 Windows Dev 都必须消费 Virtual qB Pages 发布的 exact-SHA materialized payload，不允许 raw source fallback。

Dev identity 必须满足：

```text
current dev HEAD
== downloads/dev/GIT_SHA
== downloaded package GIT_SHA
```

Materialized payload 至少包含：

```text
private/data/qb-releases.json
private/data/qb-release-profiles/
private/data/qb-settings-native.txt
translations/webui_*.qm
```

### 3.3 Windows qB config safety

`installers/install.ps1` 的 `-configure` 已完成 fail-closed hardening：

```text
qBittorrent running -> refuse
non-empty qBittorrent_new.ini/recovery file -> refuse
zero/obviously invalid INI -> refuse
multiple config candidates -> refuse to guess
exactly one [Preferences] section required
managed WebUI keys must be unique and inside [Preferences]
encoding/BOM preserving read/write
byte-identical safety backup
temp write -> strict reread/invariant verify -> atomic replace
post-replace byte/text verify
failure rollback without overwriting unexpected concurrent changes
```

`tests/windows-config-encoding.ps1` 在 Windows PowerShell 5.1 contract 中覆盖 UTF-8 no-BOM/BOM、UTF-16 LE/BE 和上述负例。

### 3.4 Pages race / duplicate owner

Pages 现在只有：

```text
Virtual qB Pages Source
-> ref-bound workflow_dispatch
-> Virtual qB Pages
```

旧 default-branch `workflow_run` owner 已退役；final validated SHA 上 `event=workflow_run` 应为 0。

Pages deployment 使用串行 concurrency，且 deploy 前重新确认 current branch HEAD / allowed docs-only freshness。旧 runtime-relevant run 在 branch 前进后必须在 deploy 前 fail closed。

Live catalog readiness 等待稳定条件：

```text
catalogError || (catalogReady && !catalogBusy)
```

不通过删除 busy 断言或修改产品生命周期伪造通过。

### 3.5 Release-grade compatibility evidence owner

当前 promotion/release 已统一通过：

```text
tests/release-compat-evidence.mjs
```

重新验证 exact release candidate SHA 的：

```text
Real qB Full Frozen Matrix aggregate
Current Stable Locale Matrix aggregate
Frozen catalog identity
WeiG VERSION / exact SHA
65/65 exact qB runtime identity
immutable runtime image digest identity
current-stable all-locale PASS
```

`tests/release-compat-evidence-contract.mjs` 已加入普通 `npm test`，使用完全离线合成 evidence 验证正例，并证明以下篡改会 fail closed：

```text
wrong WeiG SHA
wrong qB runtime identity
mutable runtime image tag
incomplete Locale aggregate
wrong Locale SHA
```

它不启动真实 qB，也不替代最终 real-qB evidence。

## 6. Compatibility states / runtime owners

统一兼容状态：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

危险写操作在 `UNKNOWN` 时必须 HTTP 前 fail closed。

Release profile resolution：

```text
EXACT
EQUIVALENT
INHERITED
FALLBACK
```

Inheritance 只用于 source-backed 的安全关系，不授权新的危险能力，也不能跨 hard translator/API boundary 盲继承。

Runtime catalog 采用 sharded 结构：

```text
private/data/qb-releases.json
private/data/qb-release-profiles/<sourceSha>.json
```

禁止恢复 65 full profiles 的 monolithic runtime catalog。

主要 owners：

```text
Exact release/source facts             W.ReleaseProfile
HTTP endpoint/transport invocation     W.QBClient
User-visible capability policy         W.CapabilityRegistry
Torrent status/filter semantics        W.TorrentSemantics
Torrent field/column provenance        W.TorrentFieldRegistry
Settings Preference semantics          W.SettingsSchema
Persisted language truth               qB app/preferences.locale
WeiG translation/presentation runtime  W.I18n
```

最终 authority 见 `DESIGN.md`。

## 7. 发布前仍需要的正式门禁

### 7.1 开发过程中不要频繁跑 Full Frozen Matrix

`Real qB Full Frozen Matrix` 是**最终发布级重型门禁**，不是日常反馈环：

```text
ordinary dev push          -> do not run
normal fixes/tests/docs    -> do not run
intermediate checkpoint    -> do not run
before final SHA freeze    -> do not run
final validation/release   -> manual workflow_dispatch
```

只有 final dev exact SHA 已冻结，或明确需要全支持区间重新认证时才运行。

### 7.2 Final exact-SHA release evidence

准备 release 时，同一个 final dev exact SHA 必须满足：

```text
normal CI PASS
CI candidate PASS
Dev Pages exact-SHA PASS
Current Stable Locale Matrix manual PASS
  -> current qB 5.2.3 locale surface currently 61/61
Real qB Full Frozen Matrix manual PASS
  -> 65/65 exact stable runtimes
release-compat-evidence central verifier PASS
Promote validated dev to main PASS
main == dev == final exact SHA
main Pages exact reuse/live identity PASS
```

之后才允许创建 `v<VERSION>` tag。

Promotion 与 Release 都会重新下载、解析并验证同 SHA 的 G-FM + Locale aggregate；**Actions UI 显示绿色本身不够**，旧 SHA、Fast aggregate、普通 push/skipped Locale run 都不能替代正式 evidence。

Release 复用 exact candidate artifact，不重新 build 产品。

## 9. Truth hierarchy

发生冲突时优先级：

```text
qB official source / exact runtime identity
-> admitted release profile
-> canonical WeiG product owner
-> real-qB evidence
-> browser / Virtual qB / Pages evidence
-> docs/tests fixtures
```

Stale test、Simulator 或 docs 应跟随正确 source/runtime truth 更新；不得为旧测试结论降低产品安全边界。
