# 002. 兼容与实现状态

> 当前产品兼容状态。最高目标是让同一份 `webui/**` 在真实 qBittorrent 4.x / 5.x stable 上自动适配；source catalog / ledger / Virtual qB 用于证明和辅助实现这一目标，不再把 simulator fidelity 当产品主进度。

## 1. 正式支持范围

- 长期产品目标：**qBittorrent 4.x / 5.x official stable**；
- 当前 WebAPI v2 正式支持策略：**qBittorrent 4.1.0 -> latest official stable**；
- 当前完整 source-derived stable matrix 已验证：**qB 4.1.0 -> 5.2.3，共 65 个官方 stable profile**；
- 当前 audited semantic ceiling：**WebAPI 2.15.1**；
- qB 4.0.x 属于 WebAPI v1，当前仍是明确产品缺口；若要覆盖全部 qB4 stable，需要独立 Legacy WebAPI v1 Adapter；
- Alpha / Beta / RC / master 不进入正式 stable matrix；未来未知 semantic revision 不自动继承最后已知行为。

## 2. 产品主线 — `webui/**`

`webui/**` 是唯一正式产品。兼容工作优先修改/验证：

```text
W.QBClient
W.ReleaseProfile
W.CapabilityRegistry
W.SettingsSchema
W.TorrentSemantics
以及直接消费这些 canonical owners 的正式 UI/runtime
```

目标是让 UI 只消费统一 WeiG semantics，把 qB4/qB5 差异尽量在 compatibility owner 截止。

已有产品兼容基础包括：

- qB4 `resume/pause` 与 qB5 `start/stop` 的 Torrent action 映射；
- qB4 `paused` 与 qB5 `stopped` filter 映射；
- `editTracker` legacy `origUrl` / modern `url`；
- legacy `torrents/add` 文本结果与 modern structured result normalization；
- source-derived release/action/filter/parameter facts；
- exact Preference getter/setter/type provenance；
- Settings/Torrent/Capability current owners。

这些是 Phase E 的起点，不代表整个 `webui/**` 已完成 qB4/qB5 全功能兼容。

## 3. 自动适配策略

每项产品功能依次尝试：

```text
1. 原生等价 API 映射
2. request/response normalization
3. 可靠的旧 API 组合/emulation
4. 从 canonical 已有数据本地推导
5. 真正无法实现时才 hide/read-only/capability notice
```

“隐藏”不是默认策略。用户已经明确要求：**功能在稳定 qB4/qB5 上应尽可能都能实现。**

同时禁止：

- 伪造真实 qB 根本没有的数据；
- 用高成本 N items -> N requests 作为默认兼容；
- 在 presentation 中散落版本判断；
- 点击后才出现 404/501 才叫“适配”。

## 4. Phase E — Real qB Product Compatibility — ACTIVE

当前主阶段改为系统审计 `webui/**`。

建立矩阵：

```text
WeiG Feature
-> UI entry
-> product owner / QBClient method
-> upstream endpoint(s)
-> qB4/qB5 behavior
-> historical request/response difference
-> normalization status
-> emulation possibility
-> unavoidable gap
-> virtual test
-> real-qB evidence
```

第一批优先：

### Torrent filters

包括全部、下载中、做种中、已完成、已停止、运行中、活动、非活动、停滞、上传停滞、下载停滞、校验中、移动中、错误、Private/PT。

### Facets

Tracker / 路径 / 分类 / 标签。

### Columns

Name / Size / Progress / Download / Upload / ETA / Status / Ratio / Tracker 以及其它正式列。

### Torrent actions

Add/Delete/Start/Stop/Force Start/Recheck/Reannounce、Files priorities、Trackers/WebSeeds、Peers、Categories/Tags 等。

### Settings

下载 / 连接 / 速度 / BitTorrent / Web UI / 高级。Preference surface、setter、type、旧版等价设置都要逐 release 审计。

### Search / RSS / Logs

入口本身和后续 API flow 都应自动适配真实 release。

## 8. 当前真实证明边界

```text

```

## 9. qB4.0.x 明确缺口

当前 catalog/evolution floor 是 qB 4.1.0 / WebAPI v2。

用户最新目标是 qB4/qB5 stable 尽可能全部支持，因此 qB 4.0.x 不能长期被文档悄悄排除。后续应单独评估：

```text
Legacy WebAPI v1 Adapter
-> canonical W.QBClient/product semantics
-> same WeiG UI
```

如果技术上无法做到某功能，必须逐项给出真实原因，而不是笼统宣布整个 qB4.0.x 不支持。

## 10. Validation layers

```text
Level 1: upstream source/evolution evidence
Level 2: webui/** product compatibility contracts
Level 3: Virtual qB multi-profile real Chrome
Level 4: representative real qB4/qB5 browser/API tests
Level 5: promotion-time frozen real-qB LIVE
```

Simulator PASS != real-qB PASS。

Docs 必须继续明确区分 browser evidence 与 **Upstream Compatibility Audit / full stable source audit**。

## 12. 工作纪律

- `dev` 正式开发；未经用户明确授权不动 `main`；
- 写前/ref update 前 fresh-read exact dev；
- 只 `force:false` fast-forward；
- 每完成一个大阶段停下复盘；
- upstream/real runtime truth 优先于 stale test；
- 不为了 simulator ledger 数字漂亮而偏离产品；
- 新增兼容逻辑优先进入 canonical product owner，不散落 UI caller。
