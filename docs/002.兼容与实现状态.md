# 002. 兼容与实现状态

> 本文件只记录**当前仍有效的产品兼容事实**。不再维护 Phase A–G 历史里程碑。

`webui/**` 是正式产品；source catalog、real-qB、Virtual qB、browser 与 Pages 是发现/证明层，不替代正式产品语义。

## 1. 当前正式支持范围

截至 2026-09-11：

```text
latest stable WeiG release on main: v0.3.61
current dev product VERSION: 0.3.69
qB support floor: 4.1.0 official stable
latest admitted stable: 5.2.3
Frozen stable profiles: 65
Frozen catalog: tests/fixtures/qb-release-catalog.lkg.json
manifest: tools/data/qb-stable-lkg.json
```

`dev` 的 0.3.69 尚未 promotion 到 `main`。当前 `main` 仍保持稳定发布线。

qB 4.0.x / WebAPI v1 **不是当前正式实现/CI 范围，属于未来可选（future optional）**。

Frozen LKG 是已经验收的历史事实集合：新增 official stable 时可以扩展，但不能静默改写旧 profile；历史修正必须有上游源码 evidence、明确 review 和重新验证。

正式 release profile truth 必须由 qB 上游源码生成（source-derived），不能由 UI 版本条件手工猜测。

## 2. Compatibility states

统一状态：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

优先级：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY when applicable
-> UNAVAILABLE
```

`UNKNOWN` 表示当前无法证明，不等于 supported，也不等于 permanently unsupported。危险写操作在 `UNKNOWN` 时必须 HTTP 前 fail closed。

禁止用：

```text
major/version-only final truth
higher-version auto inheritance
404/501 after user click as feature detection
fake empty list masking error/unsupported
manual compatibility mode
```

未来 stable / future major 优先保持能力级 forward compatibility，不按 major 整体拒绝。

## 4. 已验证的主要兼容语义

### 4.1 Torrent states / filters

旧 qB 与新 qB 状态名通过 canonical Torrent semantics 归一化；产品不把 qB4/qB5 major 作为最终状态行为 oracle。

可靠的旧 API 组合允许生成 `DERIVED` filter；无法可靠证明时降级或隐藏，不能伪造能力。

### 4.2 Categories / Tags

读、列举、创建/删除、分配等能力独立判定：

```text
read/filter != list != create/delete != assign
```

不同历史 API response shape 在 QBClient/正式 owner 中 normalize，不把 shape 差异泄漏到 presentation。

### 4.3 Settings

Settings 写入要求双重证明：

```text
app/setPreferences endpoint/action proven
AND
per-Preference descriptor proves writable/type agreement
```

Getter-only、missing setter、unknown endpoint、type mismatch、无法证明的 structured editor 都不得 blind write。

### 4.4 Locale / translation

Locale persisted-owner cutover 已完成：

```text
qB preferences.locale
-> shared preferences snapshot
-> W.I18n.applyLocale()
```

WeiG Language 与 Advanced Locale 两个入口共享同一个 `draft.locale`、同一 exact-release options、同一保存/回读确认事务。

当前 0.3.69 的 qB-owned Settings 文案仍使用 exact qB upstream official TS 的 bounded per-release shard；这不是人工翻译，也不是长期目标。长期 translation owner 应优先回到 qB WebApplication 的 `QBT_TR`/QTranslator，并让 `qb-releases.json` 退出翻译职责。

已经源码确认：qB 4.1.0 的 `QBT_TR` 路径使用 `qApp->translate()`；qB 4.6.4 和 5.2.3 会从 active WebUI root 加载 `translations/webui_<locale>`。中间 release 的 translator 行为边界仍需 source audit，不能猜 patch 版本。

### 4.5 Search / RSS / Logs

当前 admitted source facts证明：

```text
RSS core: qB 4.1.0+
Logs main/peers: qB 4.1.0+
Search core: qB 4.1.4+
```

这些边界来自 source/action provenance，不应重新退化为简单版本阈值判断。

### 4.6 Torrent Details / actions

Properties、Files、Trackers、Peers、WebSeeds 的读取能力独立；File priority、Tracker mutations、Peer Ban 等写操作也独立。

Action form 必须由 exact action parameter facts 证明。参数不明时不发送 HTTP。

### 4.7 Torrent Creator

Torrent Creator 只在 exact source facts 证明相关 actions/parameters 时暴露。不能因为 qB major >= 5 就自动假设所有 creator capability 存在。

## 5. Formal product matrix

正式兼容矩阵执行 canonical owners，而不是只对 JSON 做 presence compare：

```text
W.ReleaseProfile
W.CapabilityRegistry
W.TorrentSemantics
W.TorrentFieldRegistry
W.SettingsSchema
W.QBClient
```

65/65 PASS 的含义是：

```text
same webui tree
-> each exact stable consumes its own admitted source facts
-> supported capability follows canonical owner
-> unsupported capability hides/disables/degrades correctly
-> unknown dangerous write sends zero HTTP
```

它不表示早期 qB 被赋予后期 API。

## 6. Browser / full-stable / real-qB evidence 分层

发布 candidate 明确区分不同证明层：

```text
Linux browser / Hosted Chrome
Windows browser / Hosted Chrome
all stable source audit / Full qB Release compatibility audit
full stable PRODUCT compatibility matrix
Real qB Full Frozen Matrix
```

Linux/Windows browser evidence 证明跨平台浏览器与用户交互；**all stable source audit** 证明整个 admitted stable 区间的上游源码 facts；二者不能互相替代。

Real qB Full Frozen Matrix 再把同一 exact SHA 放到真实 qB runtime 上验证。

截至本文更新时，dev 0.3.69 的 candidate 链已经通过 smoke、Linux browser、Windows browser、Full qB Release compatibility audit、release candidate packaging 与 deployment acceptance。该 evidence 证明当前 shard 过渡实现可工作，但不把它升级为长期 translation architecture。

## 7. Real-qB 验证状态

全支持区间真实 qB 验证由 `.github/workflows/real-qb-full.yml` 执行：

```text
65 exact stable versions
1 real qB version per job
fail-fast: false
max-parallel: 16
per-version evidence
aggregate exact-SHA evidence
```

该矩阵不是普通 dev push gate，只在发布前/需要重新建立全版本真实 evidence 时手动运行。

正式 promotion 必须要求当前 dev exact SHA 的成功 G-FM aggregate，且 aggregate 必须证明：

```text
expected = 65
executed = 65
PASS = 65
FAIL = 0
BLOCKED = 0
missing/duplicate/unexpected runtime = 0
```

## 8. Future stable 原则

发现新的 official stable 时：

```text
verify current Frozen LKG
-> discover new official stable
-> extract source facts for new profile
-> ensure historical prefix unchanged
-> run source/product contracts
-> review compatibility diff
-> admit into Frozen LKG
-> rerun release-required evidence on final exact SHA
```

如果 source facts 不足、runtime identity 无法确认或兼容行为未知，则保持 `PENDING_REVIEW` / fail closed，不得为了“支持最新版本”而猜语义。

Locale/translation 相关的新 stable 还需确认 translator behavior / locale surface 是否发生变化；不要默认沿用上一版本实现。

## 9. Truth hierarchy

发生冲突时优先级：

```text
qB official source / exact runtime identity
-> admitted release profile
-> canonical WeiG product owner
-> real-qB evidence
-> browser / Virtual qB / Pages evidence
-> docs/tests fixtures
```

Stale test、Simulator 或 docs 应跟随正确 source/runtime truth 更新。
