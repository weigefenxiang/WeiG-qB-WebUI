### 1.1 正式 compatibility scope anchors

正式兼容优先级始终是：

```text
qB 4.1.0+ official stable
-> current stable
-> future official stable / future new major
```

Future stable/new-major compatibility继续由 source-derived exact release facts、bounded inheritance与fail-closed UNKNOWN驱动，不能因为 major 更高就整体拒绝，也不能盲继承 current latest 的危险写语义。

`qB 4.0.x` 不是当前实现/CI scope；未来可选扩展只能经用户明确扩大范围，并通过集中 Legacy Adapter 进入 canonical WeiG semantics，禁止把 WebAPI v1/v2 patch分支散落到 UI/caller。

验证职责继续分开：**Linux browser candidate** 与 **Windows browser candidate** 提供代表性跨平台浏览器证据；**Full qB Release compatibility audit / all-stable upstream source audit** 证明完整 admitted stable source/product compatibility；需要真实 runtime/hosting 的行为还必须由 real-qB evidence 证明。任何一层 PASS 都不能自动替代另一层。

## 2. 0.3.75 source / recovery / write-gate 基线

0.3.75 已闭合：

```text

-> per-shard source + recovery evidence
-> deterministic merge
-> Settings/source LKG v2

-> bounded runtime profile + exact bridge shards
```

Canonical recovery winner：

```text

```

Merge必须order-independent / associative；malformed/conflicting evidence fail closed。Full official recovery translation bodies只能进入 build-time QM materialization，不能重新进入 browser release profile JSON。

```text

```

## 3. DataGrid native schema 与 0.3.78 交互收口

### 3.1 Source truth

Exact source/LKG生成并保留 `torrentTableColumns`：

```text
key
source order
caption / translation source
defaultWidth
defaultVisible
dataProperties
```

正式产品链：

```text
W.ReleaseProfile.torrentTableColumns
-> W.TorrentFieldRegistry
-> W.DataGrid / Columns UI / Torrent rows
```

对 exact/certified profile，这份 source schema 是 Desktop DataGrid column set/defaults 的 authoritative input。旧 legacy registry只保留 semantic/fallback职责，不再限制 exact release 的原生列集合。

### 3.2 User override / 非破坏迁移

用户状态是 override：

```text
key
width
visible
layoutVersion: 2
```

规则：

- 旧用户显示/隐藏、宽度与可识别顺序尽量保留；
- `state/status` 等通过已证明的 `dataProperties` 做 canonical mapping；
- qB 新增 exact native column按source-relative位置合入；
- 无用户override的新列使用 upstream `defaultVisible/defaultWidth`；
- 暂时不存在的saved preference不因effective view被删除；
- FALLBACK/UNKNOWN不宣称native column parity；
- source-only native column使用现有 torrentInfo object 的source/dataProperty值渲染，不因为不在旧固定字段表就只显示 `—`。

### 3.3 0.3.78 column interaction / resize

0.3.78没有建立第二份 column state。`W.TorrentFieldRegistry` 继续拥有 canonical schema projection 与用户 visibility/order/width override；所有入口写回同一份 override。

Columns dialog仍由：

```text
app.js -> openColumns()
```

负责 checkbox、↑/↓、Desktop dialog drag 与 Android 360ms long-press drag。Android长按激活前移动超过阈值会取消drag，普通纵向滚动仍交给浏览器。

Desktop主表现在增加直接 header drag reorder。该手势由 `W.DataGrid` 的表头几何交互处理，但最终仍修改同一个 `app.columns -> W.TorrentFieldRegistry.saveEffectiveDesktopColumns()` 状态链；不存在第二排序/布局持久状态。resize handle与header reorder分区，普通header click仍保留server sort语义。

用户列宽的产品级 resize floor 现在为 `24 px`，因此 `#`、名称、大小等列可以像 qB 原版一样主动压得很窄；upstream `defaultWidth` 仍只是新用户/新列默认宽度，不是强制最小宽度。

Resize的 pointermove 只即时更新当前 header + 已挂载 Torrent rows 的 grid template，不再每帧重建 VirtualList；pointerup 后才执行一次 canonical persistence/reconciliation。因此横向 table width / scrollbar在拖动期间即时跟手，同时避免每个 pointermove 的整表 VirtualList 重建。

Field presence不等于server-sort proof；source-only column默认不得发明server sort。

## 4. Transfer / Locale / Tracker 当前产品语义

### 4.1 Transfer owner不变

现有 app transfer cycle仍通过同一个 `transfer/info`取得：

```text
dl_info_data / up_info_data        session cumulative totals
dl_info_speed / up_info_speed      realtime rates
connection_status                  connection state
```

`W.TransferRuntime`继续只保存bounded realtime samples/history与现有metadata snapshot；0.3.78没有新增request、timer、poll owner或第二业务history store。

### 4.2 0.3.78 compact realtime presentation

Desktop Statusbar 与 Mobile Drawer 中 chart 下方的 canonical compact capsule现在显示**箭头 + realtime rate**：

```text
↓ <dl_info_speed>   ↑ <up_info_speed>
```

不显示“下载 / 上传”文字，也不再把这两个 compact values 用作 session cumulative totals。Mobile compact speed typography与右侧连接状态使用同一 responsive font scale，优先保持完整单位和值在一行内。

Drawer compact chart自己的 dot legend 仍显示 session cumulative totals；它与下方 realtime arrow capsule职责不同，不建立第二 transfer state owner。

完整 Transfer statistics dialog继续没有图表上方重复 summary strip；唯一 Download/Upload summary位于 chart 下方：

```text
left:  ↓ <realtime download> | 下载 <session downloaded>
right: 上传 <session uploaded> | ↑ <realtime upload>
```

Desktop/Mobile复用同一组节点；窄屏只自适应换行/收缩，不恢复旧第二summary owner。

### 4.3 0.3.78 incremental display smoothing

Display smoothing仍是：

```text
default: 10 s
choices: Raw / 3 / 5 / 10 / 15 / 20 / 30 s
```

但短窗口不再在每次 redraw 时从“当前滚动 cutoff 后的全部 raw samples”重新分桶。当前选中的 smoothing window 使用**单一 bounded display aggregation cache**：

```text
absolute-time bucket
-> 当前 active bucket 只累计新 sample
-> bucket 完成后 freeze 到 completed
-> 后续 sample 不再重算 completed bucket
```

切换 smoothing 选项时允许从 canonical bounded raw history 一次性重建所选 window；之后正常 poll 只增量更新 active bucket。长窗口仍消费已有 bounded minute buckets。该设计不新增网络 polling、timer、第二 canonical history owner或unbounded raw retention，同时避免已完成历史桶随每秒 cutoff 反复重新计算。

### 4.4 Native WebUI return locale/root handoff

Persisted language truth仍只有：

```text
qB app/preferences.locale
```

当同一次verified Settings save把 `alternative_webui_enabled`切为false时，`W.SessionController`可在Alternative root仍active时先写/验证临时locale，完成root switch后再写/验证最终目标locale。

该transaction不保存 `previousLocale`，不做exit restore，不创建第二language owner。若用户同一次save明确选择locale，该locale必须保持final target。

### 4.5 Tracker detail exact URL

qB upstream `TorrentsController::trackersAction()` 对普通Tracker直接把 `tracker.url`放进API JSON；`[DHT] / [PeX] / [LSD]`为特殊entries。

Torrent detail的Tracker display/edit直接消费 exact API `url`，不再通过 `U.normalizeTracker()`。长URL使用variable-height + wrap，编辑prompt以exact URL为初值。Facet/domain分类可继续使用归一化，但不得覆盖详情exact URL truth。

## 6. Pages / installer current rule

Dev installer只消费Pages materialized distribution，不允许raw-source fallback。Pages Source不能只检查“本次push before -> current”，对dev还必须在需要时比较：

```text
published downloads/dev/GIT_SHA
-> current dev SHA
```

若这整段历史存在Pages-relevant变化，必须dispatch当前exact dev Pages owner；公开SHA读取失败、格式非法、无法证明为current dev祖先时也要fail closed重新materialize。

`pages-source.yml`中的materialization relevance matcher只有一个canonical owner；不要复制第二套 matcher。

Docs-only/public-payload-irrelevant follow-up可以由classifier证明无需重新生成产品bytes，但它不能把旧SHA Pages evidence改写为新SHA release-grade evidence。准备promotion/release时，final dev exact SHA仍必须拥有流程要求的exact Pages identity。

## 10. Truth hierarchy

发生冲突时：

```text
qB official source / exact runtime identity
-> admitted release profile
-> canonical WeiG product owner
-> real-qB evidence where applicable
-> browser / Virtual qB / Pages evidence
-> docs/tests/fixtures
```

Stale test、Simulator、old checkpoint或旧docs必须跟随正确source/runtime truth更新；不得为旧结论降低安全边界。
