### 1.1 正式 compatibility scope anchors

正式兼容优先级始终是：

```text
qB 4.1.0+ official stable
-> current stable
-> future official stable / future new major
```

Future stable/new-major compatibility继续由 source-derived exact release facts、bounded inheritance与 fail-closed UNKNOWN 驱动，不能因为 major 更高就整体拒绝，也不能盲继承 current latest 的危险写语义。

`qB 4.0.x` 不是当前实现/CI scope；未来可选扩展只能经用户明确扩大范围，并通过集中 Legacy Adapter 进入 canonical WeiG semantics，禁止把 WebAPI v1/v2 patch 分支散落到 UI/caller。

验证职责严格分开：Linux/Windows browser candidate、all-stable source/product audit、Pages、real-qB evidence各自证明不同层，任何一层 PASS 都不能自动替代另一层。

## 2. Source / recovery / write-gate 基线

当前 certified source chain：

```text
exact qB source / official TS
-> per-release source facts + recovery evidence
-> deterministic merge
-> Settings/source LKG v2
-> native bundle / catalog materialization
-> bounded runtime profile + exact bridge shards
```

Canonical recovery winner：

```text
highest occurrence count
-> newest exact stable supporting candidate
-> lexical/codepoint order
```

Merge 必须 order-independent / associative；malformed/conflicting evidence fail closed。Full official recovery translation bodies只能进入 build-time QM materialization，不能重新进入 browser release profile JSON。

Settings/source LKG v2继续 exact-source 绑定：

```text
exact qbVersion
exact sourceSha
exact torrentTableColumns
exact torrentDetailUi
exact source/translation bridge facts
canonical deterministic recovery union hash
```

`4.5.0 -> 4.6.4` Alternative WebUI document-translation gap仍是 source-proven hard boundary，必须保留 exact official-TS bridge。

File Priority继续由 exact `filePrioAction` source ownership决定；Transfer normal/global rate-limit Apply继续要求 `setDownloadLimitAction + setUploadLimitAction + toggleSpeedLimitsModeAction` 全部 proven，Alternative继续要求 `setPreferencesAction + toggleSpeedLimitsModeAction` 全部 proven。`W.CapabilityRegistry.allActions` 为 strict `every()`，transport前仍重复 fail-closed preflight。

## 3. DataGrid / Torrent Detail 当前交互语义

Exact source/LKG生成并保留 `torrentTableColumns`：

```text
key
source order
caption / translation source
defaultWidth
defaultVisible
dataProperties
```

正式产品链：

```text
W.ReleaseProfile.torrentTableColumns
-> W.TorrentFieldRegistry
-> W.DataGrid / Columns UI / Torrent rows
```

对 exact/certified profile，这份 source schema 是 Desktop DataGrid column set/defaults 的 authoritative input。旧 legacy registry只保留 semantic/fallback职责；用户 visibility/order/width 是 override，不是第二份固定列清单；saved preference不能因为当前effective view缺列就被删除。

主表与详情表都遵守同一交互纪律：

```text
resize handle -> resize only
header drag threshold -> reorder
ordinary header click -> existing sort
product resize floor -> 24 px
pointermove -> only live width/grid-template paint
pointerup -> one canonical persistence/reconciliation
```

Detail table在 0.3.79-0.3.82 完成两处产品收口：

```text
Detail ctx.apply -> applyDetailColumns(ctx,rebuild)
Detail resize handle -> 完整位于当前 header cell 可命中区域（right:0）
```

Resize lifecycle使用 pointerId 过滤并在拖动期间由 window 级 pointermove/up/cancel 接管；没有第二 column owner、MutationObserver 或 post-render repair。

Field presence不等于 server-sort proof；source-only column默认不得发明 server sort。

## 4. Transfer / Locale / Tracker 当前产品语义

### 4.1 Transfer owner与 compact realtime

现有 app transfer cycle仍通过同一个 `transfer/info` 取得：

```text
dl_info_data / up_info_data        session cumulative totals
dl_info_speed / up_info_speed      realtime rates
connection_status                  connection state
```

`W.TransferRuntime`继续只保存 bounded realtime samples/history 与现有 metadata snapshot；没有新增 request、timer、poll owner 或第二业务 history store。

Desktop Statusbar 与 Mobile Drawer chart下方 compact capsule显示：

```text
↓ <dl_info_speed>   ↑ <up_info_speed>
```

完整 Transfer statistics dialog继续保留 realtime + session totals 语义。

Display smoothing继续使用 absolute-time bucket；active bucket只累计新 sample，completed bucket冻结，切换 smoothing 时才允许从 canonical bounded raw history一次性重建。

### 4.2 Native WebUI return locale/root handoff

Persisted language truth仍只有：

```text
qB app/preferences.locale
```

关闭 Alternative WebUI时，`W.SessionController`可在 Alternative root仍active时先写/验证临时locale，完成 root switch后再写/验证最终目标locale。该transaction不保存 `previousLocale`，不做 exit restore，不创建第二language owner。

### 4.3 Tracker detail exact URL

qB upstream `TorrentsController::trackersAction()` 对普通Tracker直接把 `tracker.url` 放进 API JSON；`[DHT] / [PeX] / [LSD]` 为特殊entries。

Torrent detail 的 Tracker display/edit直接消费 exact API `url`，不再通过 `U.normalizeTracker()`。Facet/domain分类可以继续归一化，但不得覆盖详情 exact URL truth。

### 5.1 Tracker row projection

旧 qB 4.1.x既可能使用 indexed row，也可能使用 `var row=[...]`，并可通过 `switch(tracker.status)` 派生 bare local。现代 qB还可能使用 `rows.push({...})`、nested `tracker.endpoints` 和 helper-derived fields。

Parser只在能从 source证明 relation 时接受：direct object field、source-proven bare local、helper dependency、nested top-level root；未知形态继续 fail closed。

UI key不得冒充 API field，例如：

```text
peers      -> num_peers
seeds      -> num_seeds
leeches    -> num_leeches
downloaded -> num_downloaded
message    -> msg
```

### 5.2 Properties shared serializer keys

qB 4.4-4.6 的 `propertiesAction()` 不只写 `KEY_PROP_*`，也会写 shared `serialize_torrent.h` 中定义的 `KEY_TORRENT_*`，包括 infohash fields。

Properties source surface必须依据：

```text
propertiesAction() 实际赋值
+ shared serializer key definitions
```

解析，不能按前缀猜测允许字段。

### 5.3 qB 5.2 Content derived facts

现代 qB 5.2 的 Content truth分散在：

```text
prop-files.js
torrent-content.js
file-tree.js
```

当前 proven relation：

```text
checked   -> priority
remaining -> size + progress + priority
```

正式语义：

```text
priority == 0 -> checked=false, remaining=0
else remaining = size * (1 - progress)
```

Browser evidence可以消费 current exact-source overlay，但不能因此私自晋级 Frozen LKG。

## 7. Pages / installer current rule

Dev installer只消费 Pages materialized distribution，不允许 raw-source fallback。

Pages Source对 `dev` 必须在需要时比较：

```text
published downloads/dev/GIT_SHA
-> current dev SHA
```

若整段历史存在 Pages-relevant变化，必须 dispatch当前 exact dev Pages owner；公开SHA读取失败、格式非法、无法证明为 current dev祖先时也要 fail closed重新 materialize。

`pages-source.yml`中的 materialization relevance matcher只有一个 canonical owner；不要复制第二套 matcher。

Docs/tests/browser-gate-only follow-up可以由 classifier证明不需要重新生成产品bytes；这种 representability必须由 workflow输出证明，不能人工猜。
