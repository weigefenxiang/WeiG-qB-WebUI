## 1. 正式支持范围与优先级

正式支持 floor：

```text

-> 每一个 4.x official stable
-> 每一个 5.x official stable
-> 当前最新 official stable
-> 未来 5.x / 6.x / 7.x / x.x.x official stable
```

当前 source-derived stable matrix 已验证：

```text

65 个 official stable profiles
50 个 qB 4.x stable + 15 个 qB 5.x stable
当前 audited WebAPI ceiling: 2.15.1

```

优先级固定为：

```text
P0 当前最新 stable 正确可用
P0 未来新 stable / 新 major 能自动进入发现、事实提取和产品验证
P1 qB 4.1.0 起所有历史 stable 保持兼容
P2 representative real-qB / promotion hardening
```

### qB 4.0.x

qB4.0.x / WebAPI v1 **不是当前实现、测试、CI 或阶段目标**。

只保留未来可选扩展原则：

```text
Legacy WebAPI v1 Adapter
-> canonical WeiG semantics
-> same UI
```

只有未来明确决定支持 qB4.0.x 时才实现。禁止为了这个低使用率旧版本牺牲当前/未来 stable 的开发优先级，也禁止把 v1/v2 分支散落到 UI、Settings、Torrent View。

### 4.1 Filters

产品 filter 按以下优先级解析：

```text
native upstream filter
-> normalized alias
-> reliable local derivation from source-proven Torrent fields/states
-> unavailable
```

qB4 的 `paused/resumed` 与 WeiG canonical `stopped/running` 统一；缺少 native filter、但 source facts 足够可靠时从既有 bulk Torrent catalog 本地推导。

### 4.2 Category / Tags read 与 write 分离

```text
Category/Tags read + facet + filter
!=
Category/Tags taxonomy endpoint / mutation actions
```

例如 qB4.1.0 的 `torrents/info.category/tags` 足以支持 read/facet；native taxonomy/mutation endpoint 不存在时只关闭对应写能力。

### 4.3 Torrent Actions

ReleaseProfile / Selection / QBClient 使用 exact source action facts。Reannounce / Remove Tracker 等缺少 upstream action 的 release：UI 不暴露动作，QBClient 再 fail closed，不发送必然 404 的请求。

### 4.4 Performance

本地 derivation 复用批量 `torrents/info` catalog，没有加入 `N torrents -> N requests`。

## 7. 兼容规则

每项产品能力按顺序处理：

```text
1. NATIVE
2. NORMALIZED / ADAPTER
3. reliable old-API composition
4. reliable DERIVED
5. READ_ONLY
6. UNAVAILABLE
7. future UNKNOWN -> only that unproven capability fails closed
```

禁止：

- presentation 中散落 qB version `if`；
- 因为 major 变成 6/7 就自动拒绝；
- 因为版本更高就自动继承 current latest semantics；
- 用版本号猜 source facts；
- 把 read capability 和 write capability 合并成一个 `true/false`；
- 点击后 404/501 才算“检测不支持”；
- 用 Simulator PASS 代替正式产品/real-qB evidence。

```text
ReleaseProfile exact source facts
-> TorrentFieldRegistry single semantic field/provenance owner

-> DataGrid layout + persisted geometry only

```

必要时允许 `READ_ONLY`，但 Torrent list field 本阶段以 read/display provenance 为主，不为了状态枚举而制造无语义的状态。

首批只覆盖当前正式 17 个 fields，不凭空扩列：

```text
name size progress dlspeed upspeed eta state ratio tracker
category tags num_seeds num_leechs save_path added_on completion_on priority
```

对 frozen 65 stable，当前事实预期这 17 项全部为 `NATIVE`；Phase E matrix 必须由正式 runtime owner 解析并证明，而不再仅做 JSON `includes()` prerequisites。

Synthetic contract 用于证明 `NORMALIZED / DERIVED / UNAVAILABLE / UNKNOWN` 的通用规则，但不得把 synthetic profile 冒充真实 qB historical fact。DERIVED 只能消费已有 canonical bulk data，禁止新增 `N items -> N requests` 或额外 polling。

用户保存的 column preference 与当前 release effective availability 必须分离：字段暂时 unavailable/unknown 时不破坏性删除 preference；未来 capability 恢复后可重新显示。字段 presence 也不自动证明 server-side sort semantics，Sort capability 必须有独立可靠证据。

```text

```

预计正式 owner cutover 才同步 `DESIGN.md`；planned/dormant `torrent-fields.js` 在 cutover 前不得提前登记为 Current Owner。
