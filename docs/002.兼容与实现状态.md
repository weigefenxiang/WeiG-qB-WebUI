# 002. qBittorrent 兼容与实现状态

更新时间：2026-09-03  
当前产品版本：**0.3.7 dev candidate**

## 1. 支持边界

WeiG qB WebUI 的兼容目标仍为：

```text
qBittorrent 4.1.9.1 / legacy WebAPI floor
→ 后续官方正式 4.x / 5.x
→ 当前稳定 5.2.x
```

兼容首先判断官方 WebAPI capability、endpoint、Preference key 与 response field。前端只有一套；版本差异集中在 `QBClient` 与明确 capability boundary。

兼容不等于“所有旧版必须模拟所有新版功能”。从本轮 LIVE 起正式执行：

```text
COMPAT-DEGRADE-001
旧版缺少某项官方低成本能力时，默认明确降级，不进行复杂模拟。

PERF-COMPAT-001
Collection/List 功能禁止默认使用 N items -> N API requests 的兼容方式。
```

只有开发者明确确认旧版功能确实必要并完成性能评估后，才允许增加 fallback。

## 3. Private / PT 能力边界

### qBittorrent 5.0+

现代 qB 提供适合 collection 使用的 authoritative Private metadata。WeiG 直接消费该字段：

```text
torrents/info private metadata
→ TorrentSemantics
→ Private / PT filter
→ PRIVATE / PT badge / detail semantics
```

此路径不产生逐 Torrent tracker 请求。

PT Tracker 域名规则只作为 PT 补充分类，Private 状态仍以 qB authoritative metadata 为准。

### qBittorrent 4.x

左侧 `私有 / PT` 入口仍显示，并带轻量 `5+` 标记。点击后显示 capability dialog：

```text
此功能需要 qBittorrent 5.0.0+
当前版本：x.x.x
如需使用可考虑升级
升级前请备份 qBittorrent 配置、Torrent 任务及重要数据
```

产品提示保持中立，不向普通用户解释 WebAPI 实现、逐项请求或内部性能机制。

运行时行为：

```text
0 legacy Private tracker scan
0 resolveMany
0 per-torrent privacy request queue
0 DHT/PeX/LSD message inference
```

点击 capability entry 不改变当前 Torrent filter。

## 4. Capability Matrix

| 能力 | qB 4.1.9.1 / 4.x | qB 5.0+ | 实现方式 |
| --- | --- | --- | --- |
| Torrent Resume/Pause semantic bridge | ✓ | ✓ | QBClient endpoint bridge |
| Global DL/UL limits | ✓ | ✓ | Native |
| Alternative speed mode | ✓ | ✓ | Native + unit normalization |
| Logs | ✓ | ✓ | Native + normalization |
| Settings / responsive shell | ✓ | ✓ | Shared frontend |
| Private/PT filter | capability notice `5+` | ✓ | direct Private metadata + PT rules |
| Private badge/detail | unavailable when authoritative metadata absent | ✓ | TorrentSemantics |
| Tags | visible capability entry when WebAPI < 2.3.0 | ✓ when WebAPI >= 2.3.0 | QBClient capability + canonical Select/open guard |

Tags 的能力边界是 **WebAPI 2.3.0+**，不是 qB 5-only。旧版仍显示 `全部标签` 控件；点击只打开共享 capability dialog，不改变 `tag` filter，不调用不支持的 Tags endpoint，也不增加兼容扫描。

## 5. Rate-limit unit normalization

这一轮 LIVE 审计发现 NORMAL 与 ALT 的 qB native unit 不能直接混用。

Canonical boundary：

```text
WeiG Transfer internal state = bytes/second
```

`QBClient` 负责：

```text
Normal transfer/downloadLimit + uploadLimit
qB native: B/s
WeiG:      B/s

ALT preferences alt_dl_limit + alt_up_limit
qB native: KiB/s
WeiG:      B/s
```

因此：

```text
read ALT: KiB/s × 1024 -> B/s
write ALT: B/s ÷ 1024 -> KiB/s
```

Transfer UI 不直接读取/写入 `alt_dl_limit`/`alt_up_limit`，避免单位语义泄漏到 presentation。

## 6. Large-library progressive data

大量 Torrent 时，当前页是 primary content；总数量、Tracker/保存路径 index 等是后台 enrichment。

```text
第一页数据到达
→ 立即 render
→ 页码左侧显示小 CSS loading ring
→ 后台 index/count 完成
→ 页码更新为精确总页数
```

未知总数不再显示 `?`：

```text
◌ 第 1 页 · 每页 50
→ 第 1 / 30 页 · 每页 50
```

若 aggregate 失败：

```text
! 第 1 页 · 每页 50
```

当前页仍可浏览。Native page 请求使用 `pageSize + 1` 的 bounded look-ahead 判断“下一页”是否可用，不需要等完整 index。

## 7. Transfer history

Transfer 不增加 speed polling。现有 `getTransferInfo()` 调用被单一 `TransferRuntime` 捕获。

窗口：

```text
1m / 5m / 15m / 30m / 1h / 3h / 6h / 12h
```

保留策略：

```text
raw samples: max 900
minute buckets: max 720
```

History 仅存在当前浏览器页面内存；刷新即重新开始，不写 qB daemon/VPS/localStorage。

## 8. Modal Select compatibility

浏览器 native `<dialog>` 位于 top layer。为了避免 modal trigger 与 body floating portal 跨层导致“看得到、点不了”，统一 `Components.selectControl()` 支持显式 `native:true` presentation mode。

```text
普通页面 -> floating mode
modal 中需要浏览器原生 top-layer dropdown -> native mode
```

这不是第二个 Select owner。Transfer 时间窗口与 rate unit 使用同一个 canonical Select contract 的 native mode。

Torrent Facet 同样只使用该 canonical Select；旧 `facet-trigger/facet-popover/facet-search` 已退出 runtime。

## 9. Route Frame / Torrent workspace compatibility

Route presentation 只有 `app.js` 一个 Current Owner：

```text
active view
Top Nav active
Mobile Nav active
Torrent Sidebar visibility
workspace route scope
Back button
Drawer close
```

`ux.js` 只处理 route-dependent text/translation；`spatial.js` 只组合 Facet，不再修改 route shell，也不再拥有 Connection/Footer presentation。

Torrent workspace 新边界：

```text
Facet state          app.js / W.LibraryController
Facet presentation   W.SpatialRuntime
Select primitive     W.Components.selectControl()
Mobile placement     W.MobileAdaptive
DHT/Peers source     W.TransferRuntime / sync/maindata
Network paint        app.js, idempotent
Footer durable state Torrent count + storage + Transfer only
```

桌面和手机移动的是同一个 Facet/Selection DOM，不复制第二套业务控件。

## 12. Fixture / forward-sentinel policy

Daily fast gate 固定为 `4.1.9.1 + 5.2.0`，避免普通 dev 重复消耗完整矩阵资源；Release fixture matrix 继续包含较新的 5.x 代表节点，例如 `5.2.3`。

未来大版本只允许用明确标记的 **synthetic / 哨兵 (sentinel)** fixture 做“不要硬编码拒绝未知 major”的前向兼容检查。当前 `6.0.0-synthetic` 不是实际支持声明，也不能替代未来真实 qB release 的 source/API audit。

Torrent workspace 的系统性失败模式、`FACET-OWNER-001 / PRESENTATION-STATE-001 / TELEMETRY-PAINT-001 / STATUS-NOISE-001 / STATUS-DEDUP-001` 详见 `008.Torrent工作区与状态所有权.md`；其能力边界不得与本文件冲突。
