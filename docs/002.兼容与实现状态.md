## 3. Main Torrent table 当前实现

Exact/certified release 的主表链：

```text

```

Source schema拥有 native key/order/defaultVisible/defaultWidth/dataProperties；用户 visibility/order/width 是 override，不是第二固定列清单。暂时 unavailable 的 saved preference 不得破坏性删除。

```text

```

Field presence不等于 server sort proof。

### 3.1 当前主列表横向滚动优化

`#torrent-list` 的 native scroll container / `W.VirtualList` 仍是唯一横向滚动 owner。当前行为：

```text
horizontal motion期间 polling继续
polling得到的新 items只保留最新 snapshot
horizontal motion期间不 repaint 主 VirtualList
连续横移重启同一个 bounded idle timer
140 ms horizontal idle后只 flush 最新 snapshot 一次
非主列表 VirtualList保持即时 setItems/render
```

该优化没有新增第二 scroll/poll/state owner，没有通过 transform 同步 `scrollLeft`，也没有 MutationObserver、monkey patch 或 post-render repair。

## 4. Torrent Detail 当前实现

Current source/data/runtime chain：

```text
exact qB properties markup / detail scripts / menu markup / controller actions
-> Detail source parsers
-> W.ReleaseProfile.torrentDetailUi + actionDescriptor
-> W.QbUiEvidence / canonical detail projection
-> generic app Detail runtime
-> W.SharedColumns / W.ColumnInteraction
-> W.QBClient transport
-> detail DOM
```

### 4.1 Tabs / General / tables 已完成数据驱动收口

HTML只保留空的 `#detail-tabs` host；tab order与 existence来自 certified `torrentDetailUi.tabOrder/tabs`。默认 tab是 source order第一个，不再假定固定五个 tab。

`app.js`只保留 General/Properties 作为不同 source-layout surface；Files / Trackers / Peers / Web Seeds 等 table surface通过 `torrentDetailUi.tables`判定并统一进入 generic `renderDetailTable()`。已退休 fixed `detailActions`、per-surface renderer与手写 tab dispatch。

General当前行为：

```text
one torrents/properties request
-> source-generated propertyLayout
-> source-proven dataProperties bindings
-> ReleaseProfile per-field provenance gate
-> existing formatters/helpers
-> qB-owned group/field translation refs
```

没有 source-generated propertyLayout 或某字段 binding无法 exact证明时 fail closed / omission，不维护第二手写 General field list，也不造假值。

### 4.2 Tracker / Peer 原版语义已收口

Tracker source projection保持：

```text
peers      -> num_peers
seeds      -> num_seeds
leeches    -> num_leeches
downloaded -> num_downloaded
message    -> msg
```

Tracker Detail display/edit使用 `torrents/trackers` exact `url`。Generic row-address owner不调用 `normalizeTracker()`；presentation只做 single-line `nowrap + overflow:hidden + text-overflow:ellipsis`，完整 exact value保留在 tooltip/title。主 Torrent 列表的 Tracker facet仍可合法使用自己的 normalization，不能用 Detail contract误伤它。

Peers country presentation使用 shared ISO alpha-2 `U.countryFlag()`，消费 source/API `country_code`；Detail UI不维护第二 country mapping。

Tracker/Peer永久 inline Edit/Delete/`×` mutation affordance已退休。Row actions统一来自 source-generated `contextMenus`；selection/static-row availability、qB menu wording、sourceAction与 endpoint都来自 exact source facts。

### 4.3 Generic Detail action runtime

Detail mutation统一链：

```text
source-generated contextMenus
-> detailMenuAvailable(...)
-> W.ReleaseProfile.actionDescriptor(sourceAction)
-> exact endpoint agreement
-> generated required/optional parameters + parameterOptions
-> generic row/torrent parameter binding
-> W.QBClient.request(exact endpoint)
```

Torrent identity、Tracker exact URL、Peer address、新值参数与 source-proven options由通用 parameter binder处理；runtime不再按 `editTracker/removeTrackers/banPeers` 等已知 endpoint名字分支。

无法证明 source action、required parameter、row binding或 endpoint一致性时，操作在 HTTP 前 fail closed。Context menu只是 presentation；真实 write support仍由 exact source/capability + QBClient transport边界决定。

Zero-selection source actions可通过同一 `detailActionItems()`路径进入表格首行 toolbar；row context actions也复用同一 action executor，不创建第二 action owner。

## 6. Installer / distribution 当前实现

Stable installer消费 immutable Release + checksum/identity；Dev installer只消费 Pages materialized distribution，禁止 raw-source fallback。

Windows external qB config mutation当前安全边界：

```text
qB running / recovery file / ambiguous config -> fail closed
strict decode + byte round-trip
byte-identical backup
exact [Preferences] ownership check
temp write + strict reread
encoding/BOM/invariant verification
target unchanged recheck
safe replace + post-verify
safe rollback when applicable
```

Installer backup retention：成功建立新 backup 后**先写 `state/last-backup`**，再 prune；只删除名称严格为 timestamp 且同时含 `had-webui` + `dest-path` markers 的 installer-owned backup，最多保留最新 3 份。用户普通目录/文件不属于删除边界。
