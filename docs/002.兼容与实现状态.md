## 3. Cross-version Logs 状态

### 3.1 4.1.9 日志能力

旧 capability 曾错误使用：

```text
logs = WebAPI >= 2.3.0
```

v0.3.2 起在 WeiG 支持范围内使用：

```text
qB >= 4.1.0 → logs=true
```

因此 4.1.9、成熟 4.x、5.x 都显示 Logs。

### 3.2 timestamp normalization

`QBClient.logs()` / `peerLogs()` 统一输出秒：

```text
legacy milliseconds >= 1e12 → /1000
modern seconds               → unchanged
```

UI 只消费稳定时间 contract。

### 3.3 Adaptive DataPanel

```text
Auto    fill remaining workspace
Compact intentionally smaller panel
Max     maximize log workspace
```

并提供 VirtualList、增量 `last_known_id`、搜索、级别过滤、Follow latest 和 5000 条 bounded buffer。

## 6. v0.3.5 Cache Contract

源 payload 使用部署占位符：

```text
__WEIGG_GIT_SHA__
```

安装/Release 时替换为精确 40 位 Git commit SHA。

部署后必须有：

```text
VERSION
GIT_SHA
private/weigg-install.json
```

HTML：

```text
Cache-Control meta: no-store, no-cache, must-revalidate
Pragma: no-cache
Expires: 0
<meta name="weigg-build-sha" content="<SHA>">
```

本地静态资源：

```text
css/app.css?v=<SHA>
scripts/app.js?v=<SHA>
...
```

动态 runtime layer 同样通过 `buildAssetUrl()` 读取该 SHA，不再使用 `?v=0.3.x`。

`tests/cache-contract-v035.mjs` 检查：

```text
HTML no-store metadata
single build SHA metadata
所有 direct CSS/JS 使用 Git SHA placeholder
禁止 semver query cache buster
lazy runtime 使用 buildAssetUrl()
Linux installer SHA 注入
Windows installer SHA 注入
Release workflow GITHUB_SHA 注入
不同 SHA 必须生成不同 asset URL
```

注意：HTML meta 是浏览器侧防御。线上 `qb.weigshare.com` / `q.weigshare.com` 的最终 HTTP Header 仍必须用 `curl -I` 验证，防止 Cloudflare/Nginx 把 HTML 改成可缓存响应。
