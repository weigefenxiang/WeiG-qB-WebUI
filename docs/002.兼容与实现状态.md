## 3. Runtime compatibility truth

浏览器总控制面是 `W.CapabilityRegistry + webui/private/data/capabilities.json`，但 `capabilities.json` 不是所有版本事实的总表。完整 admitted release source truth 属于 build/CI Frozen catalog/LKG；browser 只按 domain lazy-load compact facts：

```text
capabilities.json      release identity / high-level gates / compatFiles
torrent-compat.json    Torrent filters/status/fields/columns and planned native facets
detail-compat.json     Torrent Detail source projection
settings-compat.json   Settings/Options compact facts
source-actions.json    exact action/parameter provenance
rss-compat.json        planned RSS native surface/rule facts
qB-owned copy artifact source/context + official locale route
```

现有 `capabilities.json` 已拥有 release identity 与 torrent/detail/actions/settings domain index；RSS domain 尚未独立 compact 化，属于当前 D 阶段工作。正式 runtime 不得重新加载 65-release full catalog。

危险 write 继续 fine-grained fail closed：certified exact/equivalent identity、source action/endpoint、required parameter、payload semantics缺一不可；Settings另要求 exact Preference setter/type agreement。UNKNOWN/future 不允许用 major/nearest-version猜写能力。

## 4. Settings / Options 当前事实

已完成：固定 `QB_TAB_ORDER`、静态 qB native tabs 与 `ensureQbTabs()` 已退休；native tab presence/order来自 upstream `preferencesToolbar.html` source extraction → `settings-compat.nativeTabs` → `W.SettingsSchema.nativeSurfaces()`。

历史差异必须保留：4.2.x 不存在 Behavior/RSS；4.3.x 出现 RSS；4.6+ 出现 Behavior。不得为了“看齐最新版”补不存在的 native tab。

仍需当前方案收口：Preference native section/order/source-context/control/enum/unit/dependency 仍有大量手工 truth 在 `settings-schema.js`；固定八 tab extractor/runtime白名单必须被 generic source inventory替换，避免未来 native tab静默遗漏。最终 Options UI应为：

```text
exact source Preference manifest
∩ GET /api/v2/app/preferences
= current instance native Options projection
```

## 5. Torrent Sidebar / Detail 当前事实

已完成：Status filter semantics走 `W.CapabilityRegistry + W.TorrentSemantics`；Categories/Tags/Trackers 文案可走 qB-owned source/context；Path 是 WeiG extension；Torrent Detail 已有成熟的 `torrentDetailUi() -> detail-compat.json -> generic renderer` 链。

仍需当前方案收口：Sidebar composition仍固定知道 category/tag/tracker/savePath，未来 native facet无法仅靠 source admission generic 接入；应生成 native facet manifest并由 generic renderer消费，最后 append WeiG Path。Detail 不另造第二套系统，只补 source/copy/generic coverage缺口。

## 6. RSS 当前事实

RSS transport 已统一归 `W.QBClient`，`setRule / renameRule / removeRule / matchingArticles / markAsRead` 等 mutation/read能力继续由 exact `source-actions.json` gate。编辑 existing rule 必须以 qB 返回的完整 object 为 draft base并保留未知字段。

本轮 fresh upstream核查发现 0.3.105 的实际 rule fidelity bug：

- qB 4.3.0 原生 Downloader 已读写 `smartFilter`；0.3.105 UI漏渲染/写回。
- qB 4.6+/5.x 使用 `torrentParams.stopped`；0.3.105 错查 `torrentParams.paused`。
- 原生 stopped/addPaused、historical createSubfolder、contentLayout具有 default/null tri-state；不得压成 boolean checkbox后改写语义。

当前 D 阶段先修这些真实问题，再把 RSS fields/order/controls/source-context 编译进独立 compact contract，并删除手工 rule-field owner；不能保留 generic manifest + legacy renderer 双轨。

## 7. Translation / copy

`W.I18n` 已具备 exact release official translation 主链，但 qB-owned surface仍残留手工英文→中文 fallback。当前方案要求最终 qB-owned copy只以 upstream source/context为身份；目标 locale从 exact release official translation facts解析，缺失时只安全回退 upstream English source。WeiG-owned copy继续 WeiG i18n。

外层与 qB native Options 对应的 surface必须使用 upstream `Options` 身份及官方翻译，而不是继续由 WeiG维护“Settings/设置”冒充 qB native wording。

## 8. 验证边界

Source audit、focused unit/browser、65-profile offline/Virtual matrix、Pages、real-qB 分属不同 evidence 层。阶段开发中只跑 focused/change-point；每个 A/B/C/D/E/F 阶段完成后最多一次 admitted-stable full offline/Virtual matrix。所有阶段集成完成、final dev SHA冻结后，才按 `docs/011` 运行一次昂贵 real-qB Full Frozen Matrix。

Full-stage coverage必须从 Frozen catalog派生 expected version set并满足：executed==expected、missing/duplicate/unexpected为空；source inventory必须满足 `inventory = mapped + explicit exclusions` 且 `unaccounted = 0`，避免 extractor与产品一起静默漏项。
