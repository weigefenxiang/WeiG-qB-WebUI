## v0.2.3 登录兼容热修

`public/login.html` 现在严格区分 qB 登录结果：

```text
Ok.        → 登录成功
Fails.     → 用户名/密码错误
HTTP 403   → qB 临时封禁客户端/IP
其它 HTTP  → 反代 / Host / Origin / WebUI 安全设置或服务器拒绝
网络异常   → 无法连接 qB
```

qBittorrent 4.1.9 的认证实现会累计失败次数，第 5 次失败后对当前 client/IP 建立内存封禁；因此登录页不得把 403 继续误报为“用户名或密码错误”。4.1.x 重启进程会清空这一内存状态，但重试前仍应先确认真正原因。

登录 POST 采用 qB 4.1.x 官方兼容的 `application/x-www-form-urlencoded`，字段保持 `username` / `password`，成功响应仍以精确 `Ok.` 为准。

### Lab A 当前实机结果

通过独立 `curl` 直接请求 qB 4.1.9.1：

```text

```

这证明请求已正常到达 qBittorrent，当前登录失败不是 WeiG 登录页、反向代理或请求格式导致，而是 qB 4.1.9.1 本身认为提交的凭据与当前 `Preferences/WebUI/Username` + `Password_ha1` 不匹配。下一步应先校正/重置该实例的 WebUI 凭据，再继续 UI 回归。

## 已实现兼容桥

### Start / Stop

```text
qB 4.x
resume / pause

qB 5.x
start / stop
```

`QBClient` 选择首选 endpoint；必要时对 404/405 使用兼容 fallback。

### Paused / Stopped filter

```text
qB 4.x: paused
qB 5.x: stopped
```

UI 使用统一语义，兼容层负责转换。

### Version parsing

- qB 应用版本允许 `v5.2.3` 等前缀；先 normalize 再取 major。
- WebAPI 使用点分整数比较，禁止 `parseFloat()`。

```text
2.11.3 > 2.8.0
```

### Historical exceptions

qB 4.3.3 存在 WebAPI version reporting 历史异常，因此 Capability 不能只依赖报告版本；已保留已知例外和 endpoint fallback 入口。

### Legacy filters / capabilities

老 4.x 不支持的筛选、Tags、Private flag 或新操作按 Capability 隐藏，不向旧实例暴露已知不可用控件。

## 性能实现

Torrent 主列表：

```text
pageSize = 20 / 50 / 100 / 200
limit = pageSize
offset = page * pageSize
```

DOM：

```text
Data page/cache
↓
Virtual Window
↓
Viewport + overscan rows
```

当前页 200 条数据不代表 200 个挂载 Torrent Row。

Tracker / SavePath / PT 全库索引按有限批次构建，只生成 Data Catalog，不生成隐藏 DOM。
