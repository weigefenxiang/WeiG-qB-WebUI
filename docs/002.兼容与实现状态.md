## 2. Runtime compatibility truth

当前浏览器 compatibility owner 为 `W.CapabilityRegistry`。它消费 checked-in compact contracts，并结合 `W.QBClient` 检测的 qB/WebAPI identity 解析 exact/equivalent/bounded inherited/fallback 状态。`W.QBClient` 只拥有 transport 与运行实例版本检测，不重新拥有 capability/version policy。

运行时 compact contracts 是 **source-derived / 上游源码生成** 的兼容真值。正式 runtime 不包含旧 release-profile owner、`qb-releases.json` 或 per-release profile shards；qB official source、65-release catalog、完整 translation/source evidence 只留在 tools/tests/CI/simulator，用来生成或审计 compact contracts。

危险 write 继续遵循 fine-grained provenance 与 fail-closed：endpoint proof、required parameter proof、具体 Preference/action proof 缺一不可。future UNKNOWN 不得通过 nearest-version/major guessing 放开写操作。

Settings compound controls（例如 Listen port + Random、schedule From/To）是**单个 canonical SettingRow 内的组合控件**。一个 DOM row 可以合法表示多个 upstream Preferences；测试必须按 Settings layout contract 验证 source Preference -> canonical row projection，不能强迫“一 Preference = 一 DOM row”。组合 row 也不自动意味着顶层 SettingsGrid full-span。

Locale bootstrap 必须同时尊重 browser locale、qB persisted `app/preferences.locale`、source-proven writable proof 与 `W.I18n` presentation 边界；只改 DOM 文字、W.I18n active locale 或 localStorage 都不能替代 qB persisted truth。

`W.TorrentSemantics`、`W.TorrentFieldRegistry`、`W.Selection/ActionRegistry`、`W.QbUiEvidence`、`W.SharedColumns`、`W.ColumnInteraction`、`W.VirtualList` 等既有唯一 owner 不变。Files 必须保持 qB response order 与 exact source file index；synthetic folder != qB source file；file/folder Rename provenance 独立；Tracker 使用 exact URL；Peer flags 本地 source-pinned；Copy browser-local；transport mutation 只经 QBClient；checked Tag removal 必须 exact `removeTagsAction`；unknown dangerous write 零 HTTP。

## 6. RSS Downloader protected state

RSS feed/item 与 RSS auto-download rule 是同一 RSS product surface 下的不同 source-proven action contract。0.3.103 新增 rule UI 时继续遵守：

- `rss/rules` 只负责读取 current qB rules truth。
- `rss/setRule`、`rss/renameRule`、`rss/removeRule` 必须分别通过对应 source action descriptor，不能因为 route 可用就整体放开写权限。
- 编辑已有 rule 时以 qB 返回 object 为 draft base，只修改 UI 实际拥有的字段；未知/未来字段继续保留。
- release 未证明某字段/动作时 UI 不得凭版本号猜测。
- RSS route module lazy-load 不得形成第二 navigation/state owner。

## 7. Evidence boundary

**Linux/Windows browser evidence** 证明真实浏览器产品行为；**Virtual qB Pages live evidence** 证明部署后 simulator + product + live browser 链；**Full qB stable WebAPI evolution audit** 证明 all-stable 上游源码/API 演进。Ordinary CI、Virtual qB、Pages/browser、real-qB 与 release-grade matrix 各自证明不同层级，不能互相冒充。

- `SKIPPED != PASS`。
- classifier 明确判定“不适用”时，不应为了制造绿灯而手工触发无关 heavy lane。
- Pages `build` / `deploy` SUCCESS 不等于 Pages 全链 SUCCESS；required live verify lanes必须全部闭环。
- 旧 SHA PASS 不自动证明新 SHA；反之，仅 tests/docs-only change 也不使未改变的 product bytes 自动变成新 Product VERSION。
- docs-only final handoff SHA 可引用其父 product exact SHA 的已验证 product bytes，但必须明确 identity，不得把 docs-only SHA 冒充新的 product validation checkpoint。
- Promotion/main/tag/Release 仍需用户明确授权；当前用户明确禁止本轮碰 `main` 或创建/使用 `[candidate]`。
