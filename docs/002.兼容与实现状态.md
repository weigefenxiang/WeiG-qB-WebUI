### 1.1 正式 compatibility scope anchors

正式兼容优先级始终是：

```text
qB 4.1.0+ official stable
-> current stable
-> future official stable / future new major
```

Future stable/new-major compatibility继续由 source-derived exact release facts、bounded inheritance与fail-closed UNKNOWN驱动，不能因为 major 更高就整体拒绝，也不能盲继承 current latest 的危险写语义。

`qB 4.0.x` 不是当前实现/CI scope；未来可选扩展只能经用户明确扩大范围，并通过集中 Legacy Adapter 进入 canonical WeiG semantics，禁止把 WebAPI v1/v2 patch分支散落到 UI/caller。

验证职责严格分开：**Linux browser candidate** 与 **Windows browser candidate** 提供代表性跨平台浏览器证据；**Full qB Release compatibility audit / all-stable upstream source audit** 证明完整 admitted stable source/product compatibility；需要真实 runtime/hosting 的行为还必须由 real-qB evidence 证明。任何一层 PASS 都不能自动替代另一层。

## 2. Source / recovery / write-gate 基线

当前 certified source chain：

```text
exact qB source / official TS
-> per-release source facts + recovery evidence
-> deterministic merge
-> Settings/source LKG v2
-> native bundle / catalog materialization
-> bounded runtime profile + exact bridge shards
```

Canonical recovery winner：

```text
highest occurrence count
-> newest exact stable supporting candidate
-> lexical/codepoint order
```

Merge必须order-independent / associative；malformed/conflicting evidence fail closed。Full official recovery translation bodies只能进入 build-time QM materialization，不能重新进入 browser release profile JSON。

Settings/source LKG v2继续 exact-source 绑定：

```text
exact qbVersion
exact sourceSha
exact torrentTableColumns
exact torrentDetailUi
exact source/translation bridge facts
canonical deterministic recovery union hash
```

`4.5.0 -> 4.6.4` Alternative WebUI document-translation gap仍是source-proven hard boundary，必须保留 exact official-TS bridge。

File Priority继续由 exact `filePrioAction` source ownership决定；Transfer normal/global rate-limit Apply继续要求 `setDownloadLimitAction + setUploadLimitAction + toggleSpeedLimitsModeAction` 全部 proven，Alternative继续要求 `setPreferencesAction + toggleSpeedLimitsModeAction`全部 proven。`W.CapabilityRegistry.allActions`为strict `every()`，transport前仍重复fail-closed preflight。

## 3. DataGrid native schema 与 0.3.78 交互收口

Exact source/LKG生成并保留 `torrentTableColumns`：

```text
key
source order
caption / translation source
defaultWidth
defaultVisible
dataProperties
```

正式产品链：

```text
W.ReleaseProfile.torrentTableColumns
-> W.TorrentFieldRegistry
-> W.DataGrid / Columns UI / Torrent rows
```

对 exact/certified profile，这份 source schema 是 Desktop DataGrid column set/defaults 的 authoritative input。旧 legacy registry只保留 semantic/fallback职责，不再限制 exact release 的原生列集合。用户 visibility/order/width 是 override，不是第二份固定列清单；saved preference不能因为当前effective view缺列就被删除。

0.3.78没有建立第二份 column state。Columns dialog仍由 `app.js -> openColumns()` 负责 checkbox、↑/↓、Desktop dialog drag 与 Android 360ms long-press drag；Desktop主表增加直接 header drag reorder，但最终仍写回同一个 `app.columns -> W.TorrentFieldRegistry.saveEffectiveDesktopColumns()` 状态链。

主表交互规则：

```text
resize handle -> resize only
header drag threshold -> reorder
ordinary header click -> existing sort
product resize floor -> 24 px
pointermove -> immediate mounted header/row grid-template update
pointerup -> one canonical persistence/reconciliation
```

因此横向 table width / scrollbar在拖动期间即时跟手，同时避免每个 pointermove 重建整个 VirtualList。

Field presence不等于server-sort proof；source-only column默认不得发明server sort。

## 4. Transfer / Locale / Tracker 当前产品语义

### 4.1 Transfer owner与compact realtime

现有 app transfer cycle仍通过同一个 `transfer/info`取得：

```text
dl_info_data / up_info_data        session cumulative totals
dl_info_speed / up_info_speed      realtime rates
connection_status                  connection state
```

`W.TransferRuntime`继续只保存bounded realtime samples/history与现有metadata snapshot；0.3.78没有新增request、timer、poll owner或第二业务history store。

Desktop Statusbar 与 Mobile Drawer chart 下方 canonical compact capsule现在显示：

```text
↓ <dl_info_speed>   ↑ <up_info_speed>
```

不再把这两个 compact values 用作 session cumulative totals。完整 Transfer statistics dialog继续只保留 chart-bottom 一组 realtime + session totals 语义：

```text
left:  ↓ <realtime download> | 下载 <session downloaded>
right: 上传 <session uploaded> | ↑ <realtime upload>
```

### 4.2 Incremental display smoothing

Display smoothing仍是：

```text
default: 10 s
choices: Raw / 3 / 5 / 10 / 15 / 20 / 30 s
```

短窗口不再每次 redraw 从滚动 cutoff 后的全部 raw samples重新分桶。当前选中的 smoothing window使用单一 bounded display aggregation cache：

```text
absolute-time bucket
-> active bucket只累计新 sample
-> bucket完成后freeze到completed
-> 后续sample不再重算completed bucket
```

切换 smoothing 时允许从 canonical bounded raw history 一次性重建所选 window；正常 poll 之后只增量更新 active bucket。它不是第二 canonical history owner。

### 4.3 Native WebUI return locale/root handoff

Persisted language truth仍只有：

```text
qB app/preferences.locale
```

关闭 Alternative WebUI 时，`W.SessionController`可在Alternative root仍active时先写/验证临时locale，完成root switch后再写/验证最终目标locale。该transaction不保存 `previousLocale`，不做exit restore，不创建第二language owner。

### 4.4 Tracker detail exact URL

qB upstream `TorrentsController::trackersAction()` 对普通Tracker直接把 `tracker.url`放进API JSON；`[DHT] / [PeX] / [LSD]`为特殊entries。

Torrent detail的Tracker display/edit直接消费 exact API `url`，不再通过 `U.normalizeTracker()`。Facet/domain分类可以继续归一化，但不得覆盖详情exact URL truth。

## 5. Torrent detail source facts

被冻结的 source facts包括：


## 7. Pages / installer current rule

Dev installer只消费Pages materialized distribution，不允许raw-source fallback。Pages Source不能只检查“本次push before -> current”，对dev还必须在需要时比较：

```text
published downloads/dev/GIT_SHA
-> current dev SHA
```

若这整段历史存在Pages-relevant变化，必须dispatch当前exact dev Pages owner；公开SHA读取失败、格式非法、无法证明为current dev祖先时也要fail closed重新materialize。

`pages-source.yml`中的materialization relevance matcher只有一个canonical owner；不要复制第二套 matcher。

Docs-only/public-payload-irrelevant follow-up可以由classifier证明无需重新生成产品bytes，但它不能把旧SHA Pages evidence改写为新SHA release-grade evidence。
