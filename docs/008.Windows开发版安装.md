# Windows 开发版安装与排障

本文只用于测试 `dev` 分支。稳定版用户继续使用正式 GitHub Release。2026-09-13 已按本轮 installer / Pages 事故复盘更新。

## 1. Dev bootstrap authority

Windows Dev 推荐始终从 Virtual qB Pages 获取与当前 materialized distribution 同步发布的 installer：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure
```

指定目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure -o "D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
```

如果只更新 WebUI 文件、不希望 installer 修改 qBittorrent 配置，直接省略 `-configure`：

```powershell
Invoke-WebRequest "https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1" -OutFile ".\weigg-install-dev.ps1"; powershell.exe -ExecutionPolicy Bypass -File ".\weigg-install-dev.ps1" -dev -o "D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
```

历史旧 installer 的 `-dev` 曾直接下载 GitHub raw source archive，导致 runtime catalog/profile/QM/Settings translation materialization 缺失。当前 installer 已修为 Pages materialized distribution，**禁止恢复 raw-source fallback**。

## 2. 当前 public payload classifier

当前 Dev installer 与 `.github/workflows/pages-source.yml` 使用同一个 public payload allowlist：

```text
webui/**
simulator/**
installers/**
VERSION
tools/data/qb-stable-lkg.json
tools/data/qb-locale-lkg.json
tests/fixtures/qb-release-catalog.lkg.json
```

判断规则不是“只允许 docs-only 领先”，而是：

```text
current dev HEAD == materialized SHA
-> 直接使用

current dev HEAD > materialized SHA
-> GitHub compare
-> 如果 intervening changes 全部不属于上述 public payload allowlist
   -> 允许复用最后一个已验证 materialized payload
-> 只要有任意 public payload path
   -> fail closed，等待新的 Pages build
```

因此普通：

```text
docs/**
tests/**
.github/workflows/**
其它 tooling / repository-only files
```

本身不会让 Windows/Linux installer 把已验证 payload 判成过期。

空/未知 compare 状态、compare 不是 `ahead`、文件列表可能被截断等情况仍必须 fail closed；不能为了方便把 source guard 放宽。

## 3. Pages exact-SHA identity 与已知 workflow debt

Materialized payload 自身仍保持严格 identity：

```text
Pages downloads/dev/GIT_SHA
== downloaded package GIT_SHA
== package manifest gitSha
```

当前 reviewed payload：

```text
materialized SHA: e72824b096d253a07c030248be9b451f3f009b8b
product VERSION: 0.3.72
profiles: 65
QM assets: 96
native registry: true
```

对应 Virtual qB Pages run：

```text
#625 / run 34708177147
build PASS
deploy PASS
core/services/mobile/release-profile/preferences live browser verifies PASS
```

当前 `dev` 在复盘时为：

```text
81c1bf42b315d9c1b49a39cd5f7cf8baeec7519b
```

它只比上述 materialized SHA 多删除一次临时 maintenance workflow，因此 installer 可以通过 compare 复用该 payload。

### 尚未收口：`pages.yml` stale-deploy gate

`.github/workflows/pages-source.yml` 与 Windows/Linux installer 已经采用 public payload allowlist；但 `.github/workflows/pages.yml` 的 `Refuse stale dev Pages deployment` 当前仍使用较旧的 explicit exception list。

这意味着：

```text
installer/source relay classification  已修
Pages owner stale-deploy classification 仍待对齐
```

后续 dev 应把 `pages.yml` stale gate 改成同一个 allowlist，并恢复对应 contract。不要用删除 guard、接受 unknown path 或 raw-source fallback 来“修”这个差异。

## 4. Materialized payload 必需内容

至少要有：

```text
private/data/qb-releases.json
private/data/qb-release-profiles/
private/data/qb-settings-native.txt
private/data/qb-settings/<sourceSha>.json   # only source-proven bridge routes
translations/webui_*.qm
GIT_SHA
VERSION
manifest.json
```

当前 qB-owned copy pipeline 还会把 Settings tabs、Torrent status filters 与 Transfer rate mode 的 exact official source/context refs 放进同一 native registry / bridge transport。

如果存在尚未发布的 public payload 变化，必须：

```text
wait for exact Pages build and retry
```

## 5. 为什么 raw source 不够

Dev runtime 依赖构建期 materialized：

```text
compact release index
exact/inherited release profile shards
source-proven Settings facts
source-proven qB-owned UI refs
native QBT_TR registry
official minimal webui_*.qm
exact official-TS bridge shards
```

缺失时真实 qB 可能表现为：

```text
This API action is not source-proven for the current qBittorrent release.
This qBittorrent version returned no settings in this group.
qB-owned Settings/filter/tab copy unexpectedly falls back to English.
```

遇到这些错误先核对 GIT_SHA/materialized files，不要放宽 source guard。

## 6. Windows `-configure` 安全链

2026-09-11 编码事故暴露了 Windows PowerShell 5.1 whole-file transcode 风险。当前 installer 已完成 fail-closed hardening：

```text
qBittorrent running -> refuse
non-empty qBittorrent_new.ini/recovery file -> refuse
zero/obviously invalid config -> refuse
multiple discovered configs -> refuse to guess
exactly one [Preferences] required
managed WebUI keys must be unique and inside [Preferences]
strict encoding decode + byte round-trip
byte-identical safety backup
temp write -> reread/invariant verify
encoding/BOM preserve verification
target unchanged recheck
atomic replace
post-replace verification
safe rollback when mutation itself replaced the target
```

支持保留：

```text
UTF-8 BOM
UTF-8 no BOM
UTF-16 LE BOM
UTF-16 BE BOM
```

不要重新引入：

```powershell
Get-Content $cfg -Raw
Set-Content -Encoding UTF8 $cfg
```

省略 `-configure` 时 installer 只更新目标 WebUI 文件，不应关闭/重启 qB，也不应改写 qBittorrent.ini。

## 7. Config discovery

标准 profile 会自动发现常见路径；multiple candidates、portable/custom profile 或明确知道配置位置时使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure -qbconfig "D:\path\qBittorrent.ini"
```

多个候选时脚本必须拒绝猜测。人工运行前仍建议完全退出 qBittorrent；没退出时当前 installer 会 fail closed。

## 8. 安装后快速验证

```powershell
$root="D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
Get-Content "$root\GIT_SHA"
Get-Content "$root\VERSION"
Get-Item "$root\private\data\qb-releases.json" | Select-Object Length
(Get-ChildItem "$root\private\data\qb-release-profiles" -Filter '*.json').Count
Test-Path "$root\private\data\qb-settings-native.txt"
Test-Path "$root\translations\webui_zh_CN.qm"
```

应满足：

```text
installed GIT_SHA == Pages published materialized GIT_SHA
current dev HEAD == installed GIT_SHA
OR
all commits after installed GIT_SHA are compare-proven non-public-payload changes
qb-releases.json 是 compact index
profile shard directory exists
qb-settings-native.txt exists
webui_zh_CN.qm exists
```

## 9. 本轮事故复盘结论

本轮 Windows Dev 安装器误报的根因不是 qB、PowerShell 下载或用户目录，而是 classifier 语义错误：旧实现把“允许复用 payload”写成了一个很窄的 docs/workflow exception list，导致普通 repository-only 变更也被误判为 Pages-relevant。

修复后的原则是：

```text
问“什么会改变公开 materialized payload？”
而不是问“哪些仓库文件我愿意例外放行？”
```

因此 public payload allowlist 是正向 truth，未知 repository-only path 默认可复用；真正 public payload path 才阻止复用。compare 本身异常时仍 fail closed。

临时用于落地修复的 maintenance workflow/tool 已删除，不应重新引入长期自修改 workflow。
