# Windows 开发版安装与排障

本文只用于测试 `dev` 分支。稳定版用户继续使用 `main` 分支的一键安装器和 GitHub Release。

> 2026-09-11 真实 Windows qBittorrent 4.6.7 排障已证明：**Windows Dev 不能复用旧的 `main/installers/install.ps1 -dev` raw-source 路径。** 同时，旧版 PowerShell 5.1 配置写入方式曾把 UTF-8 no-BOM 的 `qBittorrent.ini` 按 ANSI/GBK 误解码后再写回 UTF-8，导致中文/日文配置值乱码。完整事故复盘见 `docs/013.Windows配置编码事故复盘.md`。

## 为什么开发版不能复用旧的 main 安装器

WeiG qB WebUI 的开发版运行时不是仓库 `webui/` 原始目录的简单拷贝。CI/Pages 会把 qBittorrent stable release catalog、exact/inherited release profile、Settings 翻译路由、native QBT_TR registry、官方 `webui_*.qm` 与必要的 exact translation bridge materialize 后，再发布到 Virtual qB Pages 的 `downloads/dev/`。

旧版 `main/installers/install.ps1` 的 `-dev` 路径会直接下载 GitHub source archive。该 raw source 不包含完整 materialized runtime data，会导致真实 qBittorrent 出现：

- `This API action is not source-proven for the current qBittorrent release.`
- Settings 显示 `This qBittorrent version returned no settings in this group.`
- 切换 `zh_CN` 后 qBittorrent-owned Settings 标题大量回退为英文。

因此开发版测试必须使用和 dev materialized payload 同时发布的安装器。

## Windows PowerShell：正确的 dev 安装命令

先下载当前 Pages 发布的 dev 安装器，再执行 `-dev`：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure
```

如果要安装到指定目录，例如本轮真实环境：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure -o "D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
```

**不要使用：**

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -dev ...
```

旧 `main` installer 只代表当前稳定发布线，不是当前 Dev bootstrap authority。

## exact-SHA / materialized payload 规则

Dev 安装器会先解析当前 `dev` exact Git SHA，然后检查：

```text
current dev HEAD
== Pages downloads/dev/GIT_SHA
== downloaded package embedded GIT_SHA
```

并验证 materialized payload 至少包含：

```text
private/data/qb-releases.json                # compact release index
private/data/qb-release-profiles/            # exact profile shards
private/data/qb-settings-native.txt
translations/webui_*.qm
```

如果 Pages 还没有追上当前 `dev` SHA，安装器必须直接失败，不允许退回 raw source。

## 安装前 Windows 配置安全规则

当前 `dev` 已修复 PowerShell 5.1 的 UTF-8/UTF-16 编码保留问题，并有 `powershell.exe` regression。但下一轮还要继续把 qB config write 收紧为完全 fail-closed。

**在 guardrails 全部落地前，测试 `-configure` 时请先完全退出 qBittorrent。**

人工测试前至少确认：

```powershell
[bool](Get-Process qbittorrent -ErrorAction SilentlyContinue)
Test-Path "$env:APPDATA\qBittorrent\qBittorrent_new.ini"
```

期望：

```text
False
False
```

如果 qB 仍在运行，或存在非空 `qBittorrent_new.ini`，不要让外部脚本继续修改正式配置。

## qB 配置编码要求

Windows qB 配置可能是：

```text
UTF-8 BOM
UTF-8 no BOM
UTF-16 LE BOM
UTF-16 BE BOM
```

`installers/install.ps1` 当前已经通过 `Read-QBConfigText` / `Write-QBConfigText` 做严格解码和 byte round-trip check，避免 Windows PowerShell 5.1 默认 `Get-Content` 把 UTF-8 no-BOM 当 ANSI/GBK。

禁止重新引入：

```powershell
Get-Content $cfg -Raw
# mutate whole text
Set-Content -Encoding UTF8 $cfg
```

这种 whole-file transcode 会污染与 WebUI 配置完全无关的中文/日文值，例如：

```text
Session\DefaultSavePath
Session\TempPath
SavePathHistory
Session\Tags
```

## 尚未落地的 installer guardrails

当前必须继续实现并测试：

```text
1. qBittorrent.exe 正在运行 + -configure -> fail closed
2. 非空 qBittorrent_new.ini -> fail closed
3. 0 byte / obviously invalid config -> fail closed
4. write temp config -> strict reread -> invariant checks -> atomic replace
5. original config safety backup + replace failure restore
6. portable/custom-profile/multiple-config detection must avoid guessing wrong file
7. PowerShell 5.1 regression covers all negative cases
```

这些项完成前，不能把“编码保留已经通过”误写成“Windows 配置修改链已经完全安全”。

## 安装后快速验证

假设安装到：

```text
D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI
```

可检查：

```powershell
$root="D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
Get-Content "$root\GIT_SHA"
Get-Item "$root\private\data\qb-releases.json" | Select-Object Length
(Get-ChildItem "$root\private\data\qb-release-profiles" -Filter '*.json').Count
Test-Path "$root\private\data\qb-settings-native.txt"
Test-Path "$root\translations\webui_zh_CN.qm"
```

正常 materialized dev 安装应满足：

- `GIT_SHA` 是当前 `dev` 的 40 位 exact SHA；
- `qb-releases.json` 是 compact index，不应再是 65 full profiles 的超大单文件；
- exact profile shard 目录存在；
- `qb-settings-native.txt` 存在；
- `webui_zh_CN.qm` 存在。

qBittorrent 4.6.7 还可以检查 exact profile 与 Settings translation bridge shard：

```powershell
Test-Path "$root\private\data\qb-release-profiles\839bc696d066aca34ebd994ee1673c4b2d5afd7b.json"
Test-Path "$root\private\data\qb-settings\839bc696d066aca34ebd994ee1673c4b2d5afd7b.json"
```

两项都应为 `True`。

## qB 4.6.7 本地配置正常基线

本轮事故恢复完成后的已验证关键值：

```text
General\Locale=zh_CN
Session\DefaultSavePath=D:\\clash\\u\\下载
Session\TempPath=D:\\clash\\其他文件\\下载临时文件夹
```

最终启动 qB 后再次读取：

```text
MojibakeMatches      = 0
QbittorrentNewExists = False
```

如果“更改保存位置”里的已有 torrent 路径正常，而“默认保存路径”乱码，应优先检查全局 `qBittorrent.ini` Preferences，而不是去修改 torrent 自己的保存位置。

## 浏览器仍显示旧错误时

先确认 qBittorrent Alternative WebUI `文件位置` 指向刚安装的目录，然后：

```text
Ctrl + F5
```

如果仍然出现 source-proven 错误，先检查本地 `GIT_SHA` 和 materialized profile shard，不要通过放宽 source guard 解决。
