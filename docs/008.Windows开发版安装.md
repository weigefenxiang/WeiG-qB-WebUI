# Windows 开发版安装与排障

本文只用于测试 `dev` 分支。稳定版用户继续使用 `main` 分支的一键安装器和 GitHub Release。

## 为什么开发版不能复用旧的 main 安装器

WeiG qB WebUI 的开发版运行时不是仓库 `webui/` 原始目录的简单拷贝。CI 会把 qBittorrent stable release catalog、exact release profile、Settings 翻译映射、native QBT_TR registry 和官方 `webui_*.qm` 资源 materialize 后，再发布到 Virtual qB Pages 的 `downloads/dev/`。

旧版 `main/installers/install.ps1` 的 `-dev` 路径会直接下载 GitHub source archive。该 raw source 不包含完整 materialized runtime data，会导致真实 qBittorrent 出现：

- `This API action is not source-proven for the current qBittorrent release.`
- Settings 显示 `This qBittorrent version returned no settings in this group.`
- 切换 `zh_CN` 后 qBittorrent-owned Settings 标题仍大量回退为英文。

因此开发版测试必须使用和 dev materialized payload 同时发布的安装器。

## Windows PowerShell：正确的 dev 安装命令

先下载当前 Pages 发布的 dev 安装器，再执行 `-dev`：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure
```

如果要安装到指定目录，例如 `D:\WeiG-qB-WebUI`：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -o D:\WeiG-qB-WebUI -configure
```

安装器会先解析当前 `dev` exact Git SHA，然后检查 Pages `downloads/dev/GIT_SHA` 是否已经追上该 SHA；如果 Pages 还在构建，它会拒绝使用旧 payload，也不会退回 raw source。等 Virtual qB Pages 完成后重试即可。

## 安装后快速验证

默认安装目录下运行：

```powershell
$root="$env:LOCALAPPDATA\WeiG-qB-WebUI"
Get-Content "$root\GIT_SHA"
(Get-Content "$root\private\data\qb-releases.json" -Raw | ConvertFrom-Json).Count
Test-Path "$root\private\data\qb-settings-native.txt"
Test-Path "$root\translations\webui_zh_CN.qm"
```

正常的 materialized dev 安装应满足：

- `GIT_SHA` 是当前 `dev` 的 40 位 exact SHA；
- release index 不是空数组；
- `qb-settings-native.txt` 存在；
- `webui_zh_CN.qm` 存在。

qBittorrent 4.6.7 还可以检查 exact profile 与 Settings translation shard：

```powershell
Test-Path "$root\private\data\qb-release-profiles\839bc696d066aca34ebd994ee1673c4b2d5afd7b.json"
Test-Path "$root\private\data\qb-settings\839bc696d066aca34ebd994ee1673c4b2d5afd7b.json"
```

两项都应为 `True`。

## 浏览器仍显示旧错误时

确认 qBittorrent 的 Alternative WebUI `Files location` 指向刚安装的目录，然后完全刷新浏览器缓存（`Ctrl+F5`）。如果 qBittorrent 进程在安装期间一直运行，建议重启 qBittorrent 一次，确保它重新读取 Alternate WebUI 静态文件。
