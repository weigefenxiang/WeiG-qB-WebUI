# 008. Torrent 工作区与状态所有权

Status: **current Torrent workspace authority**

## 1. Information architecture

```text
Topbar    -> identity / navigation / adaptive Search / global action rail
Sidebar   -> Torrent state filters + canonical Tracker/Path/Category/Tag facets
Workspace -> Torrent DataGrid + compact controls + pager
Statusbar -> Desktop Torrent count + storage + Transfer + Connection + actionable message
```

Desktop 与 Mobile **都不再保留** Download / Upload / Network / Torrent 四张 Summary 卡。持久 telemetry 使用已有 Transfer / Status surface；主工作区只保留筛选、数据和操作。

Mobile Drawer 与 Desktop Sidebar 使用同一 `#filter-nav` 和同一 `#facet-controls`：四个 Facet 永久位于 Torrent 状态筛选之后，不再移动到工作区横向 shelf。

`W.MobileAdaptive` owns only adaptive placement/geometry。它拥有 no qB client、polling、Torrent state map、VirtualList implementation 或 second filter/sort state。

## 3. Desktop workspace

Desktop Topbar remains one row and keeps the right-edge action rail。Sidebar order is stable：

```text
Torrent state filters
  ↓
Tracker
Path
Category
Tag
```

The four summary cards are deleted, not hidden。TorrentPanel flex-fills the workspace。Desktop action order remains `Start -> Pause -> More -> Delete`；Pager remains below the DataGrid。

### TORRENT-FOCUS-RETIRE
Torrent list expand/focus mode is retired on Desktop and Mobile。There is no `torrent-focus-slot`, `data-viewport-focus`, `is-data-focus`, `registerDataViewport()` or `setDataViewportFocus()` runtime/CSS/test contract。The normal workspace already owns the available data viewport。Desktop 和 Mobile 的 canonical Selection toolbar 都只能包含 `Start / Pause / More / Delete` 四个动作；`⤢ / ⤡` 或任何等价 expand/focus control 都属于 regression。

## 4. Mobile library IA — MOBILE-LIBRARY-IA

Mobile is the same library state with different placement：

```text
Topbar
  same Search input, revealed below header

Drawer
  Torrent state filters
  Tracker / Path / Category / Tag

Workspace toolbar
  Select | Per page | Columns | Sort

Torrent card
  row 1: selection | torrent name | More
  row 2: configured metrics + overflow count, including progress % / rates / status as selected
  bottom: canonical real progress rail

Pager
  compact page navigation | same Selection action toolbar
```

No `mobile-command-slot`, no `mobile-facet-slot`, no Mobile Summary, no second Selection toolbar。

## 5. Mobile control density — MOBILE-CONTROL-DENSITY

Toolbar controls retain an approximately 44px interaction height while their visible control surface is inset and visually compact。Select / Columns / Sort / page-size reuse canonical Button/Select skin and one geometry rule；feature-local Select or button skin is prohibited。

Compact presentation must not reduce keyboard focus visibility, accessible labels or touch usability。Light/Dark consume the same shared semantic tokens。

## 6. Mobile actions — MOBILE-ACTION-PLACEMENT

`#torrent-selection-toolbar` has one DOM owner。Responsive presentation moves that same node：

```text
Desktop -> #torrent-action-slot
Mobile  -> #mobile-pager-actions-slot
```

No duplicate Start/Pause/More/Delete buttons, no mirrored enabled state, no second event handlers。

### MOBILE-PAGER-DENSITY
On Mobile the page navigation is content-sized and yields horizontal space to `Start / Pause / More / Delete`。Canonical compact copy removes redundant words/spaces，例如 `← 第1/30页·50 →`，而不是 Desktop 的 `第 1 / 30 页 · 每页 50`。Buttons keep a usable interaction height；only very narrow widths may fall back to horizontal action overflow。

## 7. Mobile card composition — MOBILE-CARD-COMPOSITION

`W.Components.mobileTorrentCard()` is the single Mobile Torrent card renderer。First-line information is intentionally minimal so the title is not squeezed by status/metrics。Every configured field and the `+N` overflow summary live on the second rail；configured fields still come from `W.TorrentFieldRegistry`。

The card has one explicit grid column；row 1 and row 2 are both locked to that same column, so configured status/Tracker/category/tags/progress/rates and `+N` cannot escape beside `More`。Browser acceptance checks final bounding boxes rather than trusting DOM child order alone。

When Progress is enabled, the card calls the same canonical progress helper and places the resulting rail at the bottom edge。The rail never adds another API request or state projection。

## 8. Sort ownership — SORT-OWNER

Sort truth is `app.sort + app.reverse`, exposed by `W.LibraryController.state()` and changed through `W.LibraryController.setSort()`。

Desktop header cells and Mobile Sort Select are callers of the same semantic owner。The retired Mobile bridge is forbidden：

```text
open hidden Columns dialog
-> temporarily add a column
-> programmatically click hidden desktop header
-> restore column
```

There is no `weigg.mobileSort` second persistence/state and no `mobile-sort-bridge` presentation database。

## 9. Renderer ownership — TORRENT-RENDERER-OWNER

`W.Components` owns `torrentRow()` and `mobileTorrentCard()` directly。`ui.js` may provide `W.TorrentFieldRegistry` and Mobile field controls but must not replace renderer functions after load。

Likewise, `W.MobileAdaptive` must not replace `W.VirtualList` or `W.Components.state`；`W.LayoutRuntime` must not monkey-patch `W.DataGrid.template/addResizeHandles`。

## 10. Search / Header utilities

### HEADER-SEARCH
Torrent Search has one `#search-input` and one `app.search`。On Mobile, `W.HeaderUtilities` owns the reveal trigger/presentation。The search layer is anchored below Topbar and must not change Topbar height or push Menu/Add/Theme/utility actions outside the viewport。

### HEADER-END-ANCHOR
Desktop Add/Theme/GitHub/WeiG Share/Logout remains one right-edge action rail。Search collapses before this rail loses its anchor。

Theme/GitHub/WeiG Share/Logout use the same visible utility geometry：one square control surface, same width/height, border, radius, hover/focus state and icon optical box。Theme mode/options still belong to canonical `W.Theme + W.Components.selectControl()`，but the Header trigger exposes only the `◐` prefix；visible Select value/chevron placeholder leaves are removed from the Header trigger rather than reserving phantom width。

Mobile Menu/Drawer presentation belongs only to `W.HeaderUtilities`。`setDrawer(open)` changes the existing Sidebar/Scrim classes and `aria-expanded` together；`toggleDrawer()` makes the same Menu button open on the first click and close on the second。Scrim and route/filter close operations call the same setter。`app.js` must not bind another `menu-btn.onclick` / `drawer-scrim.onclick` owner。

## 11. Facets

### FACET-OWNER
Facet state = `W.LibraryController`；composition = `W.SpatialRuntime`；Select behavior = canonical `W.Components.selectControl()`；DOM location = `#sidebar-facet-slot` for both Desktop and Mobile。

`W.SpatialRuntime` does not relocate Facet DOM by viewport and never owns compatibility thresholds or qB requests。

Capability name/trigger and its badge use one shared inline adjacency contract。State-filter badges and Tag Select badges use the same 7px presentation gap；remaining Sidebar width must never push `全部标签` 的 badge 到最右侧。

## 12. Presentation state

### PRESENTATION-STATE
DOM is not a business-state database。Selection matching count reads `W.LibraryController.total()` rather than parsing a retired `#torrent-count` element。Mobile Sort reads semantic sort state rather than desktop table DOM。

### TELEMETRY-PAINT
Telemetry facts enter through the existing Transfer/MainData lifecycle。Connection help reads `W.TransferRuntime.snapshot()`；deleting the Network Summary does not create a replacement polling path。

### STATUS-NOISE
Routine polling success stays silent。

### STATUS-DEDUP
Durable connection state is not duplicated in primary workspace。Desktop renders Connection in Statusbar。Mobile does not recreate a Network Summary；the same semantic state remains available to canonical help/status owners without spending workspace height。

### STATUS-PLACEMENT
Persistent telemetry uses the lowest-cost existing surface。

### ADAPTIVE-STATUS
Adaptive placement never forks state, qB client, timer or poller。

## 13. Connection

### LIVE-INDICATOR
Connection motion consumes existing `connection_status` only。

### STATUS-SIGNAL
One Connection semantic state renders one marker。

### RENDERED-SIGNAL
Final visible rendering is the acceptance boundary；pseudo-elements/rings cannot create a second marker。

### MOTION-STATUS
System Reduced Motion and WeiG Reduced Motion make the same marker static。

### STATUS-EXPLAIN
Tooltip/Dialog help consumes existing qB/WebAPI/DHT/Peers state and performs zero extra request, polling or port scan。

## 14. Capability Registry

### CAPABILITY-OWNER
User-facing compatibility policy belongs only to `W.CapabilityRegistry + data/capabilities.json`。

### CAPABILITY-RANGE
Support uses semantic ranges, not exact patch allowlists。Declarative JSON stores complete upstream version facts；user-facing capability versions use full segments and `+`，例如 `5.0.0+ / 4.2.0+ / 4.2.5+`。`5+ / 4.2+` 这类省略写法禁止进入 badge、tooltip 或 capability requirement presentation。

### CAPABILITY-BADGE
Primary compatibility badges use the complete qB-facing presentation milestone when trustworthy。`presentation.requirements` may describe a conservative qB-facing milestone, but `rule` remains the sole support predicate and presentation data must never become a second support owner。

### CAPABILITY-DIALOG
All capabilities reuse one shared dialog renderer。The requirement block always uses the same three-row template and full `X.X.X+` presentation：

```text
qBittorrent 要求：X.X.X+
WebAPI 要求：X.X.X+
已知对应 qBittorrent：X.X.X+
```

If one fact is not known, the same row remains and displays `—` rather than changing template shape。The dialog then renders the same current-environment block (`当前 qBittorrent / 当前 WebAPI`) beneath it。

### CAPABILITY-COST
Capability evaluation uses detected versions + local data；no N controls -> N requests。

### CAPABILITY-VISIBLE
Unsupported actionable controls normally stay visible/explainable。

### CAPABILITY-EXCEPTION
Upstream quirks are declarative data rules, not feature-local version branches。

Current presentation facts：

```text
Private/PT badge                  qBittorrent 5.0.0+
Tags badge                        qBittorrent 4.2.0+
Stalled badge                     qBittorrent 4.2.5+ (conservative qB-facing presentation)
Stalled support predicate         WebAPI 2.4.1+
Official milestone database fact  qBittorrent 4.2.2 -> WebAPI 2.4.1
```

The last two lines intentionally coexist：qB 4.2.2 / WebAPI 2.4.1 still satisfies the semantic support rule；the `4.2.5+` badge is a conservative user-facing qB milestone requested by the current product presentation contract, not a rewritten support boundary。

Current support is semantic-range based。The supported stable range is qBittorrent 4.1.9.1 -> 5.2.3（55 official stable releases）。Linux/Windows Browser acceptance uses representative qB4 floor + qB5 modern generations；the 55-tag full compatibility audit is owned separately by `tests/upstream-release-audit.mjs`。

## 15. Torrent progress

### TORRENT-PROGRESS-OWNER
One canonical `W.Components` projection/DOM chain owns Torrent progress。Desktop/Mobile reuse it。

### TORRENT-PROGRESS-TRUTH
Fill width is only real qBittorrent `torrent.progress`。

### TORRENT-PROGRESS-STATE
Completed 100% torrents use one completed green family across completed / paused seeding / stalled seeding / queued seeding states; active seeding uses the related active green family。Incomplete non-error states use one cool incomplete family while Status Pill keeps paused/stalled/checking meaning。Error remains a danger exception。

### TORRENT-PROGRESS-MOTION
Only active download/seed/checking states use slow decorative flow/sheen。Completed/paused/queued/stalled/error remain static；both Reduced Motion authorities disable decorative movement。The track/fill uses a rounded cylindrical highlight + lower inner shadow rather than a flat bar。

## 16. Canonical Select / interaction

### SELECT-SCROLL
Select option-list scrolling is separate from floating-anchor placement。

### OWNER-RETIRE
When an owner changes, old caller/state/event/CSS/test expectation leaves in the same change。

### SEMANTIC-NAMING
Current semantic rule names are stable responsibilities。`-001/-002/...` revision suffixes are prohibited；Git history/tags own revisions。qB/WebAPI/dependency version facts are not semantic identifier revisions and remain explicit where required。

## 17. Protected baselines

This Mobile/Sidebar change explicitly changes Desktop Facet location semantics only by making it permanent and explicitly removes Desktop summary leaves。The following Desktop behavior remains protected：

```text
Topbar one-row / end rail
Desktop Search full -> compact -> icon
DataGrid rows/columns/resize
Selection + ActionRegistry
Desktop toolbar action order
Pager semantics
Statusbar / Transfer / Connection
Light / Dark semantic surfaces
Reduced Motion final state
```

Mobile must also be validated in Dark/Light and Reduced Motion。“Covered” does not mean every surface needs a different style；shared tokens are preferred。

## 19. Systemic failure summary

Forbidden regressions include restoring Summary cards, restoring Torrent focus/expand mode, adding a Mobile Facet shelf, rebuilding a second Mobile filter, giving `app.js` a second Drawer click owner, reserving hidden Theme Select value/chevron width, parsing hidden DOM as count/sort state, using a hidden desktop dialog to implement Mobile Sort, replacing canonical renderer/VirtualList/DataGrid functions at runtime, creating another telemetry poller, clipping Search inside Topbar, or adding `*-fix.css` / MutationObserver / compatibility repair layers。
