# 008. Torrent 工作区与状态所有权

> Torrent workspace 当前语义所有权。目标是把 qB release source facts、Torrent semantic state、HTTP transport 与 Desktop/Mobile presentation 分层，不增加第二套兼容实现。

## 1. Product owner chain

```text
qB stable source facts
-> W.ReleaseProfile
-> W.TorrentSemantics
-> W.TorrentFilterView / W.LibraryController / W.Selection
-> W.QBClient HTTP boundary
```

### TORRENT-FILTER-OWNER

`W.TorrentSemantics` 是 status/filter evaluation 的唯一 owner；`app.js` 与 `selection.js` 不得维护自己的 state regex/version table。

## 2. Release-specific filter names

qB4 与 qB5 的 HTTP filter 命名不同，但 UI semantic state 不复制：

```text
qB4 paused  -> canonical stopped
qB4 resumed -> canonical running
qB5 stopped/running stay canonical
```

HTTP 请求时由 `W.ReleaseProfile.upstreamTorrentFilter()` 映射回 exact upstream name。

Filter 不在 exact release source surface 时 fail closed，不退化为 All。

## 3. Status truth

`W.TorrentSemantics.matchesStatus()` 消费当前 torrent object，统一判断：

```text
Downloading
Seeding
Completed
Stopped
Running
Active
Inactive
Stalled
Checking
Moving
Errored
```

**Completed 与 Seeding 不同。** `progress >= 1` 只证明完成，不单独证明正在做种。

## 4. Filter presentation

`W.TorrentFilterView` 只渲染 `W.ReleaseProfile/W.TorrentSemantics` 返回的 supported filters。

Private 以 exact `torrents/info` `private` parameter presence 为 authority；Tags/Stalled 等 source-bound feature 由对应 source facts决定。

不支持的 normal UI隐藏；Desktop Sidebar 与 Mobile Drawer 使用同一 filter DOM/state。

## 5. Private / PT

`W.TorrentSemantics` 统一负责 Private authoritative metadata、unknown state 与可选 PT tracker-domain classification。

PT rule 不能伪造 Private metadata。

## 6. Selection parity

`W.Selection.selectAllMatching()` / `invertAllMatching()` 必须使用与页面 filter 相同的 canonical matcher。

Selection 负责 selection set/actions，不拥有 Torrent taxonomy。

## 7. QBClient boundary

`W.QBClient` 负责真实 qB transport，不拥有 compatibility policy：

```text
detect() 读取版本/identity
getTorrents() 使用 ReleaseProfile exact filter mapping
start/resume、stop/pause 使用 exact action surface
write/action 在参数未知时 fail closed
```

禁止通过“先请求失败再试另一个 endpoint”来探测 capability；caller 不复制 qB patch/WebAPI version policy。

## 8. Virtual protocol boundary

Virtual Lab 位于 QBClient 后方。

```text
source apiActions / upstream gates
-> endpoint exists?

simulator Endpoint Contract
-> historical request/response/status/mutation semantics

simulator Transport Contract
-> auth/header/proxy semantics

router/engine
-> execute resolved contract
```

这些 simulator owners 不进入 `W.TorrentSemantics`、`W.ReleaseProfile` 或 `W.QBClient`，也不改变正式产品 Torrent owner chain。

职责正交的 source catalog、ReleaseProfile、TorrentSemantics、Endpoint Contract 可以同时存在，因为它们回答不同问题；禁止两个 Torrent semantic engines 同时活跃。

## 9. Owner cutover

未来若 Torrent/HTTP semantic owner 真正被新 owner替代，必须：

```text
new owner isolated validation
-> atomic cutover callers/contracts/DESIGN
-> remove superseded branch/helper/test
```

禁止 runtime alias、shim 或长期双活。

## 10. Performance

兼容不能通过 N Torrent -> N requests 实现。

Filter、selection、Private/PT、protocol semantic resolution 都应使用已有 list/catalog/profile/state；不新增 per-Torrent probe 或 capability polling。

## 11. Acceptance

至少验证：

```text
qB4 paused/resumed canonical alias
qB5 stopped/running
unsupported filters fail closed
Completed != Seeding
app/selection share one owner
floor profile unsupported source-bound UI hidden
modern exact profile matches source catalog
Desktop/Mobile no second filter state
Virtual protocol history does not leak into product callers
```

发布前真实 runtime 兼容由 `docs/011.全版本真实qB验证规则.md` 定义。
