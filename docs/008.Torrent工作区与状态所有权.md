## 5. Torrent progress

Real width is always derived from qBittorrent `torrent.progress`. Motion never advances width and never fabricates completion.

Current visual projection:

```text
downloading / metaDL / forcedDL        download   active blue/cyan
uploading / forcedUP                   seed       active success/teal
pausedUP / stoppedUP                   complete   static success
pausedDL / stoppedDL                   paused     static muted warm
checking* / allocating / moving        checking   active warning
queuedDL / queuedUP                    queued     static muted violet
stalledDL / stalledUP                  stalled    static warning/muted
error / missingFiles                   error      static danger
unknown completed                      complete   static success
unknown incomplete                     idle       static neutral
```

Active motion is presentation only: subtle flow/sheen inside the already-filled region. Paused/completed/queued/stalled/error do not run active progress motion. System and WeiG Reduced Motion disable the sheen while retaining real width and semantic color.

Mobile two-line cards reuse the same canonical progress track as Desktop and place a thin rail along the card bottom when Progress is enabled. No second Mobile state mapping exists.

## 6. Capability Registry

Private/PT exact metadata boundary = **qBittorrent 5.0.0+**. Tags boundary = **WebAPI 2.3.0+**, known qB-facing milestone = **4.2+**.

User-facing unsupported default:

```text
visible
aria-disabled
qB-facing badge
hover explanation
click -> shared Capability Dialog
state unchanged
```

Version support uses `eq / gt / gte / lt / lte / all / any / not`; arbitrary patch versions are evaluated by range. Synthetic `4.9.2 / 4.9.3` are boundary-test strings, not release claims.

Registry consumes already detected qB/WebAPI versions and local JSON only. No `N controls -> N requests` capability probing.

## 7. Transfer / DHT / Peers

`sync/maindata -> existing runtime -> weigg:maindata -> app renderer`. Same formatted DHT/Peers value -> zero DOM mutation. Transfer history remains bounded through 12 h without extra polling.

## 8. Connection

```text

-> css/layout.css one rendered marker
```

Desktop areas: `"torrent storage transfer connection message"`.

```text
connected     success   Connected / 已连接          one gentle animated dot
firewalled    warning   Network limited / 网络受限   one slower animated dot
disconnected  danger    Disconnected / 未连接       one static dot

Hover -> short reason. Click -> canonical Connection Dialog with existing qBittorrent/WebAPI/DHT/Peers state and troubleshooting. No request/poll/port scan.

`polish.js/css` is explicitly not a Connection owner and cannot draw `::before/::after` markers/rings. Reduced Motion makes the same single marker static.

```

- `FACET-OWNER-001`: Facet state/composition/control/skin each has one canonical owner.
- `PRESENTATION-STATE-001`: UI nodes are not business-state databases.
- `TELEMETRY-PAINT-001`: one telemetry input, idempotent paint.
- `STATUS-NOISE-001`: routine polling success is silent.
- `STATUS-DEDUP-001`: one durable status is not repeated in one viewport.
- `STATUS-PLACEMENT-001`: durable status uses the lowest-cost surface.
- `ADAPTIVE-STATUS-001`: Desktop/Mobile placement does not create second state or polling.
- `LIVE-INDICATOR-001`: Connection motion consumes existing semantic state only.
- `STATUS-SIGNAL-001`: one Connection semantic state has one marker.
- `RENDERED-SIGNAL-001`: final rendered marker count is the acceptance boundary, not DOM count alone.
- `MOTION-STATUS-001`: status motion respects Reduced Motion.
- `STATUS-EXPLAIN-001`: hover/click explanation consumes existing state and zero extra network work.
- `HEADER-UTILITY-001`: passive identity/manual refresh do not occupy permanent Topbar space.
- `HEADER-SEARCH-001`: same Search DOM/state adapts Full -> Compact -> Icon.
- `HEADER-END-ANCHOR-001`: one global action rail stays anchored to the Desktop right edge.
- `SELECT-SCROLL-001`: Select internal option scroll cannot trigger anchor re-placement.
- `CAPABILITY-OWNER-001`: one Registry owns user-facing compatibility policy.
- `CAPABILITY-RANGE-001`: support is semantic-range driven.
- `CAPABILITY-BADGE-001`: primary badge is qB-facing when known.
- `CAPABILITY-DIALOG-001`: all unsupported-feature details use one template.
- `CAPABILITY-COST-001`: capability evaluation adds no per-feature API work.
- `CAPABILITY-VISIBLE-001`: unsupported user-facing controls normally remain visible/explainable.
- `CAPABILITY-EXCEPTION-001`: quirks are declarative data rules, not feature-local version branches.
- `OWNER-RETIRE-001`: old caller/CSS/test leaves with replaced owner.
- `TORRENT-PROGRESS-OWNER`: one canonical projection/DOM chain owns Torrent progress; Mobile reuses it instead of implementing another renderer policy.
- `TORRENT-PROGRESS-TRUTH`: fill width is only real qBittorrent progress; timers, sheen and CSS animation never fabricate business progress.
- `TORRENT-PROGRESS-STATE`: semantic state chooses color/activity locally from the torrent object already being rendered and adds zero network work.
- `TORRENT-PROGRESS-MOTION`: only genuinely active states use flow/sheen; completed/paused/queued/stalled/error remain static and both Reduced Motion authorities disable decorative movement.

## 11. Systemic failure summary

Forbidden regressions include adding a **new UI wrapper** while the old owner remains, replacing a **shared component** with a feature-local copy, spending **primary workspace height** on duplicate telemetry, restoring a permanent **manual refresh**, treating Select internal scroll as page scroll, creating a second Search input, rendering one Connection state as two circles, copying capability thresholds into feature code, deriving progress from DOM state, or using animated width to simulate download completion.
