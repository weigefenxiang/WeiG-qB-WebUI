# 008. Torrent 工作区与状态所有权

> Torrent workspace 当前语义所有权。目标不是增加兼容分支，而是把 qB release source facts、Torrent semantic state、HTTP transport 与 Desktop/Mobile presentation 分层。

## 1. Product owner chain

```text
qB stable source facts
-> W.ReleaseProfile
-> W.TorrentSemantics
-> W.TorrentFilterView / W.LibraryController / W.Selection
-> W.QBClient HTTP boundary
```

`W.TorrentSemantics` 是 status/filter evaluation 的唯一 owner；`app.js` 与 `selection.js` 不得维护自己的 state regex/version table。

## 2. Release-specific filter names

qB4 与 qB5 的 HTTP filter 命名不同，但 UI semantic state 不复制：

- qB4 source `paused` -> canonical `stopped`；
- qB4 source `resumed` -> canonical `running`；
- HTTP 请求时由 `W.ReleaseProfile.upstreamTorrentFilter()` 映射回 exact upstream name；
- qB5 exact source 使用 `stopped/running`。

Filter 不在 exact release source surface 时 fail closed，不退化为 All。

## 3. Status truth

`W.TorrentSemantics.matchesStatus()` 消费当前 torrent object：Downloading / Seeding / Completed / Stopped / Running / Active / Inactive / Stalled / Checking / Moving / Errored。

**Completed 与 Seeding 不同。** `progress >= 1` 只证明完成，不单独证明正在做种。

## 4. Filter presentation

`W.TorrentFilterView` 只渲染 `W.ReleaseProfile/W.TorrentSemantics` 返回的 supported filters。Private 以 exact `torrents/info` `private` parameter presence 为 authority；Tags/Stalled 等 source-bound feature 由对应 source facts 决定。

不支持的 normal UI **隐藏**；Desktop Sidebar 与 Mobile Drawer 使用同一 `#filter-nav` 与 Library state。

## 5. Private / PT

`W.TorrentSemantics` 统一负责 Private authoritative metadata、unknown state 与可选 PT tracker-domain classification。PT rule 不伪造 Private metadata。

## 6. Selection parity

`W.Selection.selectAllMatching()` / `invertAllMatching()` 必须使用与页面 filter 相同的 canonical matcher。Selection 负责 selection set/actions，不拥有 Torrent taxonomy。

## 7. QBClient boundary

`W.QBClient` 负责真实 qB transport，不拥有 compatibility policy：

- `detect()` 读取版本，不提前 certified；
- `getTorrents()` 使用 ReleaseProfile exact filter mapping；
- start/resume、stop/pause 使用 exact action surface；
- 不通过 404/405 后再试另一个 endpoint 来探测能力；
- caller 不复制 qB patch/WebAPI version policy。

## 8. Virtual protocol semantic boundary

Virtual Lab 位于 QBClient 后方。Endpoint existence 与同 endpoint historical semantics 必须分开：

```text
apiActions / upstream-gates
  -> endpoint exists?

Approved Endpoint Contract target owner
  -> request/response/status/mutation behaves how?

router
  -> execute resolved contract
```

这个 Virtual Endpoint Contract 不进入 `W.TorrentSemantics`、`W.ReleaseProfile` 或 `W.QBClient`，也不改变产品 Torrent owner chain。

当前该 owner 尚未完成 cutover；详见 003/009。

## 9. OWNER-CUTOVER

未来若 Torrent/HTTP semantic owner 真正被新 owner替代，新接口先 isolated test；验证成功后必须 atomic cutover 并删除 superseded old branch/helper/test。禁止为了 qB4/qB5 保留两个 Torrent semantic engines。

职责正交的 source catalog、ReleaseProfile、TorrentSemantics、Endpoint Contract 可以同时存在，因为它们回答不同问题。

## 10. Performance

兼容不能通过 N Torrent -> N requests 实现。Filter、selection、Private/PT、protocol semantic resolution 都使用已有 list/catalog/profile/state；不新增 per-Torrent probe 或 capability polling。

## 11. Acceptance

至少验证：

- qB4 paused/resumed canonical alias；
- qB5 stopped/running；
- unsupported filters fail closed；
- Completed != Seeding；
- app/selection 同 owner；
- floor qB 4.1.0 unsupported source-bound UI 隐藏；
- modern exact profile filter/capability 与 source catalog 一致；
- Desktop/Mobile 无第二 filter state；
- Virtual protocol history 不泄漏回 product Torrent callers。
