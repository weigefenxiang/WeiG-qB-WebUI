# 008. Torrent 工作区与状态所有权

Status: **current Torrent workspace authority**

## 1. Information architecture

```text
Topbar    -> identity / navigation / adaptive Search / global action rail
Sidebar   -> Torrent state filters + canonical Tracker/Path/Category/Tag facets
Workspace -> Torrent DataGrid + compact controls + pager
Statusbar -> Desktop Torrent count + storage + Transfer + Connection + actionable message
```

Desktop 与 Mobile **都不再保留** Download / Upload / Network / Torrent 四张 Summary 卡。持久 telemetry 使用已有 Transfer / Status surface；主工作区只保留筛选、数据和操作。

Mobile Drawer 与 Desktop Sidebar 使用同一 `#filter-nav` 和同一 `#facet-controls`：四个 Facet 永久位于 Torrent 状态筛选之后，不再移动到工作区横向 shelf。

`W.MobileAdaptive` owns only adaptive placement/geometry. It owns no qB client, polling, Torrent state map, VirtualList implementation or second filter/sort state.

## 3. Desktop workspace

Desktop Topbar remains one row and keeps the right-edge action rail. Sidebar order is stable:

```text
Torrent state filters
  ↓
Tracker
Path
Category
Tag
```

The four summary cards are deleted, not hidden. TorrentPanel flex-fills the workspace. Desktop action order remains `Start -> Pause -> More -> Delete -> Expand`; Pager remains below the DataGrid.

## 4. Mobile library IA — MOBILE-LIBRARY-IA

Mobile is the same library state with different placement:

```text
Topbar
  same Search input, revealed below header

Drawer
  Torrent state filters
  Tracker / Path / Category / Tag

Workspace toolbar
  Select | Per page | Columns | Sort

Torrent card
  row 1: selection | torrent name | More
  row 2: configured metrics, including progress % / rates / status as selected
  bottom: canonical real progress rail

Pager
  page navigation | same Selection action toolbar
```

No `mobile-command-slot`, no `mobile-facet-slot`, no Mobile Summary, no second Selection toolbar.

## 5. Mobile control density — MOBILE-CONTROL-DENSITY

Toolbar controls retain an approximately 44px interaction box while their visible control surface is inset and visually compact. Select / Columns / Sort / page-size reuse canonical Button/Select skin and one geometry rule; feature-local Select or button skin is prohibited.

Compact presentation must not reduce keyboard focus visibility, accessible labels or touch usability. Light/Dark consume the same shared semantic tokens.

## 6. Mobile actions — MOBILE-ACTION-PLACEMENT

`#torrent-selection-toolbar` has one DOM owner. Responsive presentation moves that same node:

```text
Desktop -> #torrent-action-slot
Mobile  -> #mobile-pager-actions-slot
```

No duplicate Start/Pause/More/Delete buttons, no mirrored enabled state, no second event handlers.

## 7. Mobile card composition — MOBILE-CARD-COMPOSITION

`W.Components.mobileTorrentCard()` is the single Mobile Torrent card renderer. First-line information is intentionally minimal so the title is not squeezed by status/metrics. Metrics live on the second rail; configured fields still come from `W.TorrentFieldRegistry`.

When Progress is enabled, the card calls the same canonical progress helper and places the resulting rail at the bottom edge. The rail never adds another API request or state projection.

## 8. Sort ownership — SORT-OWNER

Sort truth is `app.sort + app.reverse`, exposed by `W.LibraryController.state()` and changed through `W.LibraryController.setSort()`.

Desktop header cells and Mobile Sort Select are callers of the same semantic owner. The retired Mobile bridge is forbidden:

```text
open hidden Columns dialog
-> temporarily add a column
-> programmatically click hidden desktop header
-> restore column
```

There is no `weigg.mobileSort` second persistence/state and no `mobile-sort-bridge` presentation database.

## 9. Renderer ownership — TORRENT-RENDERER-OWNER

`W.Components` owns `torrentRow()` and `mobileTorrentCard()` directly. `ui.js` may provide `W.TorrentFieldRegistry` and Mobile field controls but must not replace renderer functions after load.

Likewise, `W.MobileAdaptive` must not replace `W.VirtualList` or `W.Components.state`; `W.LayoutRuntime` must not monkey-patch `W.DataGrid.template/addResizeHandles`.

## 10. Search

### HEADER-SEARCH-001
Torrent Search has one `#search-input` and one `app.search`. On Mobile, `W.HeaderUtilities` owns the reveal trigger/presentation. The search layer is anchored below Topbar and must not change Topbar height or push Menu/Add/Theme/utility actions outside the viewport.

### HEADER-END-ANCHOR-001
Desktop Add/Theme/GitHub/WeiG Share/Logout remains one right-edge action rail. Search collapses before this rail loses its anchor.

## 11. Facets

### FACET-OWNER-001
Facet state = `W.LibraryController`; composition = `W.SpatialRuntime`; Select behavior = canonical `W.Components.selectControl()`; DOM location = `#sidebar-facet-slot` for both Desktop and Mobile.

`W.SpatialRuntime` does not relocate Facet DOM by viewport and never owns compatibility thresholds or qB requests.

## 12. Presentation state

### PRESENTATION-STATE-001
DOM is not a business-state database. Selection matching count reads `W.LibraryController.total()` rather than parsing a retired `#torrent-count` element. Mobile Sort reads semantic sort state rather than desktop table DOM.

### TELEMETRY-PAINT-001
Telemetry facts enter through the existing Transfer/MainData lifecycle. Connection help reads `W.TransferRuntime.snapshot()`; deleting the Network Summary does not create a replacement polling path.

### STATUS-NOISE-001
Routine polling success stays silent.

### STATUS-DEDUP-001
Durable connection state is not duplicated in primary workspace. Desktop renders Connection in Statusbar. Mobile does not recreate a Network Summary; the same semantic state remains available to canonical help/status owners without spending workspace height.

### STATUS-PLACEMENT-001
Persistent telemetry uses the lowest-cost existing surface.

### ADAPTIVE-STATUS-001
Adaptive placement never forks state, qB client, timer or poller.

## 13. Connection

### LIVE-INDICATOR-001
Connection motion consumes existing `connection_status` only.

### STATUS-SIGNAL-001
One Connection semantic state renders one marker.

### RENDERED-SIGNAL-001
Final visible rendering is the acceptance boundary; pseudo-elements/rings cannot create a second marker.

### MOTION-STATUS-001
System Reduced Motion and WeiG Reduced Motion make the same marker static.

### STATUS-EXPLAIN-001
Tooltip/Dialog help consumes existing qB/WebAPI/DHT/Peers state and performs zero extra request, polling or port scan.

## 14. Capability Registry

### CAPABILITY-OWNER-001
User-facing compatibility policy belongs only to `W.CapabilityRegistry + data/capabilities.json`.

### CAPABILITY-RANGE-001
Support uses semantic ranges, not exact patch allowlists.

### CAPABILITY-BADGE-001
Primary compatibility badges use qB-facing ranges when trustworthy.

### CAPABILITY-DIALOG-001
One shared dialog template explains unsupported capabilities.

### CAPABILITY-COST-001
Capability evaluation uses detected versions + local data; no N controls -> N requests.

### CAPABILITY-VISIBLE-001
Unsupported actionable controls normally stay visible/explainable.

### CAPABILITY-EXCEPTION-001
Upstream quirks are declarative data rules, not feature-local version branches.

Private/PT exact metadata boundary = qBittorrent 5.0.0+. Tags boundary = WebAPI 2.3.0+, known qB-facing milestone = 4.2+.

## 15. Torrent progress

### TORRENT-PROGRESS-OWNER
One canonical `W.Components` projection/DOM chain owns Torrent progress. Desktop/Mobile reuse it.

### TORRENT-PROGRESS-TRUTH
Fill width is only real qBittorrent `torrent.progress`.

### TORRENT-PROGRESS-STATE
Semantic Torrent state selects progress color/activity locally from the already-rendered torrent object.

### TORRENT-PROGRESS-MOTION
Only active download/seed/checking states use decorative flow/sheen. Completed/paused/queued/stalled/error remain static; both Reduced Motion authorities disable decorative movement.

## 16. Canonical Select / interaction

### SELECT-SCROLL-001
Select option-list scrolling is separate from floating-anchor placement.

### OWNER-RETIRE-001
When an owner changes, old caller/state/event/CSS/test expectation leaves in the same change.

## 17. Protected baselines

This Mobile/Sidebar change explicitly changes Desktop Facet location semantics only by making it permanent and explicitly removes Desktop summary leaves. The following Desktop behavior remains protected:

```text
Topbar one-row / end rail
Desktop Search full -> compact -> icon
DataGrid rows/columns/resize
Selection + ActionRegistry
Desktop toolbar action order
Pager semantics
Statusbar / Transfer / Connection
Light / Dark semantic surfaces
Reduced Motion final state
```

Mobile must also be validated in Dark/Light and Reduced Motion. “Covered” does not mean every surface needs a different style; shared tokens are preferred.

## 18. Validation

Browser acceptance performs real interaction and final-state checks:

```text
Desktop and Mobile: one Facet DOM, always under Sidebar filter nav
Desktop and Mobile: no Download/Upload/Network/Torrent Summary leaves
Mobile Drawer: four Facets below state filters
Selection matching count comes from LibraryController total
Desktop header sort -> semantic state
Mobile Sort Select -> same semantic state, no hidden Columns bridge
Mobile toolbar touch target remains usable with compact visible surface
same Selection toolbar moves to right side of Mobile pager
Mobile card: selection + title + More first line; metrics second line; real progress rail
Mobile Search opens below Topbar; header action rects remain inside viewport
qB4 Private/Tags degradation and qB5 native state
Connection help reads existing TransferRuntime snapshot
Torrent semantic progress + real width + Dark/Light + Reduced Motion
```

## 19. Systemic failure summary

Forbidden regressions include restoring Summary cards, adding a Mobile Facet shelf, rebuilding a second Mobile filter, parsing hidden DOM as count/sort state, using a hidden desktop dialog to implement Mobile Sort, replacing canonical renderer/VirtualList/DataGrid functions at runtime, creating another telemetry poller, clipping Search inside Topbar, or adding `*-fix.css` / MutationObserver / compatibility repair layers.
