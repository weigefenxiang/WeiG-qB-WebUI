# 008. Torrent 工作区与状态所有权

Status: **current Torrent main/detail ownership authority**

本文件维护 Torrent workspace 的当前 semantic ownership、source provenance 与交互边界，不记录按 WeiG VERSION 切片的开发历史。当前尚未完成的产品事项统一放在 `docs/014`。

## 1. Product owner chain

```text
qB stable source facts
-> W.ReleaseProfile
-> W.TorrentSemantics / W.TorrentFieldRegistry / detail source projection
-> W.TorrentFilterView / W.LibraryController / W.Selection / W.SharedColumns
-> W.QBClient HTTP boundary
-> canonical presentation
```

### TORRENT-FILTER-OWNER

`W.TorrentSemantics` 是 status/filter evaluation 的唯一 owner；`app.js` 与 `selection.js` 不得维护自己的 state regex/version table。

### TORRENT-COLUMN-LAYOUT

对 exact/certified qB release：

```text
W.ReleaseProfile.torrentTableColumns
-> W.TorrentFieldRegistry
-> W.DataGrid
-> row/card presentation
```

`torrentTableColumns` 提供 native key、source order、defaultVisible/defaultWidth与 `dataProperties`；用户 visibility/order/width只是 override。Saved preference与 current effective availability分离；暂时缺失的列不得破坏性删除用户设置。

Main Columns dialog仍由 `app.js -> openColumns()` 进入同一 persisted owner；Desktop header resize/reorder由 `W.DataGrid`负责。约束：

```text
resize hitbox -> resize only
header drag threshold -> reorder
ordinary header click -> sort
pointermove -> live width/grid-template only
pointerup -> one canonical save/reconciliation
user resize floor -> 24 px
```

列存在本身不证明 server sort；未知 source-only column不能发明 sort semantics。

禁止 MutationObserver、post-render repair、第二 layout state或第二 persisted column owner。

## 2. Main VirtualList / horizontal scroll

`#torrent-list` native scroll container + `W.VirtualList` 是主表唯一 virtual/scroll projection owner。

当前 polling/scroll contract：

```text
horizontal motion does not trigger row render
horizontal motion期间 polling仍继续
new polling items只保留 latest pending snapshot
while horizontally active -> no main-list repaint
continued horizontal motion -> restart same bounded idle timer
140 ms idle -> flush latest snapshot once
other VirtualLists -> immediate setItems behavior
```

这条优化不允许被改造成：

```text
第二 app-level scroll state
scrollLeft transform同步header/body
停止所有后台 polling
MutationObserver/post-render scroll repair
每次poll重建新的 scroll owner
```

Main row/header的横向位置由浏览器 native scrollLeft直接驱动；轮询/重建不得无故把用户位置重置为0。

## 3. Torrent Detail source schema

Detail source facts链：

```text
exact qB properties markup + detail scripts
-> extractTorrentDetailUi()
-> W.ReleaseProfile.torrentDetailUi
-> W.QbUiEvidence / canonical detail projection
```

Source surface包括：

```text
detail tabs + official translation refs
property groups / property field labels / dataProperties
Files / Trackers / Peers / Web Seeds columns
column source order/caption/source-context
response/derived source relation
```

UI key不自动等于 API field；每个 relation必须 exact-source proven。

## 4. Detail shared columns

```text
W.ReleaseProfile.torrentDetailUi.tables
-> canonical detail projection
-> W.SharedColumns user visibility/order/width
-> W.ColumnInteraction pointer/touch lifecycle
-> shared detail table DOM
```

Owner边界：

```text
source schema/default/provenance -> W.ReleaseProfile.torrentDetailUi
user visibility/order/width     -> W.SharedColumns
resize/reorder lifecycle        -> W.ColumnInteraction
horizontal scroll               -> .shared-table__viewport
```

Detail Columns checkbox必须 live-apply同一个 canonical state。Resize lifecycle必须 pointerId-filtered；pointermove只 paint，pointerup再 persist。普通 mobile touch scroll不得误触 reorder；long-press才进入 intentional reorder。

Header与body必须消费同一 column definition、width/padding/alignment projection。禁止为了“修表头位置”增加第二段同步 JS。

## 5. Tracker source provenance / exact URL

Tracker row source relation当前必须支持并 source-prove：

```text
peers      -> num_peers
seeds      -> num_seeds
leeches    -> num_leeches
downloaded -> num_downloaded
message    -> msg
```

Parser要覆盖 legacy indexed assignment、`row=[...]`、source-proven bare local/helper dependency、modern `rows.push({...})` 与 nested `tracker.endpoints` dependency；未知 upstream形态继续 fail closed。

Torrent Detail Tracker URL的 business truth是 `torrents/trackers` 返回的 exact `url`。Display/edit初始值不得通过 `normalizeTracker()` 丢失 hostname/path/query。

Presentation可以对长 URL做 ellipsis/tooltip/accessibility处理，但**显示层的截断不能改变 exact value truth**。

Tracker edit/remove/reannounce等 action必须各自按 current exact source/capability证明；不能用一个粗粒度 `trackerWritable` boolean替代。

## 6. Peer provenance / actions

Peers table普通数据字段与 mutation actions必须分层：

```text
peer data / source relation -> exact upstream/profile
row/cell rendering          -> shared detail projection
peer mutation action        -> exact source-proven capability + QBClient
```

Country/region icon若展示，应复用 qB/项目已有 country code / GeoIP / icon renderer，不维护手写国家名称->国旗 mapping。

Peer操作不得依赖“单元格里永久塞一个按钮”作为 capability owner。若产品采用原版式 context menu，该菜单只是 action presentation caller；真正支持与 transport仍由 canonical capability/QBClient owner决定。

## 7. Properties / General provenance

Properties source surface不能只扫描 `KEY_PROP_*`。qB部分版本的 `propertiesAction()` 还会使用 shared serializer中的 `KEY_TORRENT_*`；因此允许字段必须来自：

```text
propertiesAction() actual assignments
+ shared serializer key definitions
```

General/property UI 应由 exact `propertyLayout + dataProperties + certified profile` 驱动，并复用已有 formatters/helpers。不同版本没有的字段要按 source/API能力安全缺省，不得造假值。

当前用户要求将 General恢复到 qB原版信息完整度；这属于尚未完成产品工作，详细 acceptance见 `docs/014`。

## 8. qB 5.2 Content derived facts

当前 proven relation：

```text
checked   -> priority
remaining -> size + progress + priority
```

正式语义：

```text
priority == 0 -> checked=false, remaining=0
else remaining = size * (1 - progress)
```

Browser fixture可以消费 current exact-source overlay，但不能因此私自晋级 Frozen LKG。

## 9. Filter / selection parity

qB historical/current upstream filter名称差异由 `W.ReleaseProfile + W.TorrentSemantics` canonicalize；caller不维护 patch-version判断。

Completed与Seeding必须区分；`progress >= 1`只证明完成，不单独证明正在做种。

`Private / PT` 属于 capability-gated Tracker facet，不属于 status filter。Page rendering与 `W.Selection.selectAllMatching()/invertAllMatching()` 必须消费同一个 `LibraryController.matchesTorrent()` matcher。

## 10. Transfer ownership

Existing app transfer cycle仍是 `transfer/info` poll publisher；`W.TransferRuntime` 是唯一 bounded realtime history owner。Desktop/Mobile只做 adaptive presentation，不增加第二 request/timer/history owner。

## 11. QBClient / simulator boundary

`W.QBClient`负责真实 transport，不拥有 patch-version compatibility policy；Source profile/capability owner决定 endpoint/action/parameter是否合法。

Virtual qB 位于 QBClient后方，用于验证 historical request/response/status/mutation semantics；Simulator/Pages PASS不能反向定义正式 Torrent product truth。
