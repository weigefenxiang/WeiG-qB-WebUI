# 008. Torrent 工作区与状态所有权

> Torrent workspace 当前语义所有权。目标是把 qB release source facts、Torrent semantic state、HTTP transport 与 Desktop/Mobile presentation 分层，不增加第二套兼容实现。

## 1. Product owner chain

```text
qB stable source facts
-> W.ReleaseProfile
-> W.TorrentSemantics / W.TorrentFieldRegistry / detail source projection
-> W.TorrentFilterView / W.LibraryController / W.Selection / W.SharedColumns
-> W.QBClient HTTP boundary
```

### TORRENT-FILTER-OWNER

`W.TorrentSemantics` 是 status/filter evaluation 的唯一 owner；`app.js` 与 `selection.js` 不得维护自己的 state regex/version table。

### TORRENT-COLUMN-LAYOUT

对 exact/certified qB release，`W.ReleaseProfile.torrentTableColumns` 是 Desktop Torrent 原生列 key、源码顺序、默认显示、默认宽度与 `dataProperties` 的 source truth。`W.TorrentFieldRegistry` 负责把这份 exact schema 投影为 WeiG 可显示字段，并持久化用户的 visibility/order/width override；不得维护第二份 patch-version column table。

旧 `cfg.columns` 必须非破坏迁移：已有显示/隐藏、顺序与宽度尽量保留；exact qB 新增列按 upstream source-relative 位置自动合入，并使用 upstream `defaultVisible/defaultWidth`。暂时缺失或未来重新出现的 preference 不得因一次 effective view 被删除。FALLBACK/UNKNOWN profile 不得宣称 native column parity。

0.3.78 将用户可调整列宽的产品级 floor 收敛为 `24 px`。这只放宽用户 override 的最小宽度，不改变 exact qB `defaultWidth` source truth；因此 `#`、名称、大小等列可以主动压到接近 qB 原版的窄宽度。

Columns dialog 仍由 `app.js -> openColumns()` 负责 checkbox、↑/↓、Desktop dialog drag 与 Android 360ms long-press drag，并全部进入同一保存路径。Android长按激活前的正常纵向滑动继续交给浏览器。

Desktop Torrent 主表的 header geometry 由 `W.DataGrid` 处理：resize handle 负责宽度，header body 达到拖拽阈值后可直接 reorder，普通点击仍执行现有 sort。Header reorder不是第二份 order state；它修改同一个 `app.columns`，并通过 `W.TorrentFieldRegistry.saveEffectiveDesktopColumns()` 持久化同一 user override。

Resize pointermove 只即时 paint 当前 header 与已挂载 `.torrent-row` 的 grid template；不在每帧重建 VirtualList，也不在每帧持久化。Pointerup 后才做一次 canonical save/reconciliation，因此列边界与横向 table width/scrollbar实时跟手，同时避免 resize 的高频整表 rebuild。

禁止 `MutationObserver`、post-render repair、第二个 layout state或第二个 persisted column owner。

列存在本身不证明 server sort。只有已经由 canonical WeiG field semantic 证明的 sort key，或经 `dataProperties` 映射到该 canonical semantic 的 native column，才可复用排序；source-only column 默认不得推断 server sort。

### TORRENT-DETAIL-COLUMN-OWNER

Torrent Detail shared tables使用 exact release source facts，而不是 WeiG 固定列清单：

```text
W.ReleaseProfile.torrentDetailUi.tables
-> canonical detail projection / W.QbUiEvidence.detailColumns(surface)
-> W.SharedColumns user visibility/order/width override
-> W.ColumnInteraction pointer/touch lifecycle
-> shared detail table DOM
```

Owner 边界：

```text
source column set/default/order/provenance -> W.ReleaseProfile.torrentDetailUi
user visibility/order/width               -> W.SharedColumns
resize/reorder pointer/touch lifecycle    -> W.ColumnInteraction
horizontal scroll                         -> .shared-table__viewport
```

`W.SharedColumns` 不是第二 source schema owner；`W.ColumnInteraction` 也不保存第二份 column state。

Detail Columns checkbox必须 live-apply同一个 canonical state：

```text
checkbox change
-> W.SharedColumns.commit(...)
-> ctx.apply(true)
-> applyDetailColumns(ctx,true)
```

禁止 canonical state 已更新后再依靠 MutationObserver/post-render repair 修 DOM。

Resize interaction：

```text
pointerdown on dedicated .col-resize hitbox
-> one active pointerId
-> window pointermove/up/cancel lifecycle
-> pointermove only paints width/grid-template
-> pointerup commits/persists once
```

Resize handle必须完整位于当前 header cell 的可命中区域，不能把主要 hitbox放在 `overflow:hidden` 会裁掉的位置。

Header body drag负责 reorder；普通 vertical touch scroll必须保持浏览器滚动，不能误重排。只有 intentional long-press 才能捕获移动端手势进入 reorder，最终顺序仍写回 `W.SharedColumns`。

Detail shared viewport拥有横向滚动。Header与row可以存在固定布局 offset，但二者在 horizontal scroll 时必须移动相同 `scrollLeft`，且相对 offset保持不变；外层 `#detail-content` 不能抢走横向 scroll ownership。

### TORRENT-DETAIL-SOURCE-PROVENANCE

Detail UI key 不自动等于 qB response field。必须从 exact upstream source证明 relation，例如 Tracker：

```text
peers      -> num_peers
seeds      -> num_seeds
leeches    -> num_leeches
downloaded -> num_downloaded
message    -> msg
```

Parser必须支持旧版 indexed assignment / `row=[...]`、source-proven bare local、helper-derived fields、现代 `rows.push({...})` 与 nested `tracker.endpoints` top-level dependency；无法证明 relation 时 fail closed。

Properties source surface既可能来自 `KEY_PROP_*`，也可能来自 shared serializer 的 `KEY_TORRENT_*`；必须依据 `propertiesAction()` 实际赋值与 shared key definitions恢复，不能按前缀猜。

qB 5.2 Content当前 proven derived relation：

```text
checked   -> priority
remaining -> size + progress + priority
```

正式语义：

```text
priority == 0 -> checked=false, remaining=0
else remaining = size * (1 - progress)
```

这些 relation属于 source/runtime truth；browser fixture可以消费 exact-source overlay，但不能因此私自晋级 Frozen LKG。

## 2. Release-specific filter names

qB4 与 qB5 的 HTTP filter 命名不同，但 UI semantic state 不复制：

```text
qB4 paused  -> canonical stopped
qB4 resumed -> canonical running
qB5 stopped/running stay canonical
```

HTTP 请求时由 `W.ReleaseProfile.upstreamTorrentFilter()` 映射回 exact upstream name。

Filter 不在 exact release source surface 时 fail closed，不退化为 All。

## 3. Status truth

`W.TorrentSemantics.matchesStatus()` 消费当前 torrent object，统一判断：

```text
Downloading
Seeding
Completed
Stopped
Running
Active
Inactive
Stalled
Checking
Moving
Errored
```

**Completed 与 Seeding 不同。** `progress >= 1` 只证明完成，不单独证明正在做种。

`Private / PT` 不属于 status/filter 控件；它属于 Tracker facet 的 capability-gated 特殊条件，不能重新追加到 `W.TorrentFilterView`。

## 4. Filter presentation

`W.TorrentFilterView` 只渲染 `W.ReleaseProfile/W.TorrentSemantics` 返回的 supported **status filters**。

Tags/Stalled 等 source-bound feature 由对应 source facts 决定。不支持的 normal UI 隐藏；Desktop Sidebar 与 Mobile Drawer 使用同一 filter DOM/state。

Private 的权威可见性仍以 `W.CapabilityRegistry` 的 `privateFilter` 为准：该 capability 必须通过 exact release/source 证明 `torrents/info` 的 `private` metadata surface。Capability 不成立或 UNKNOWN 时，产品不得显示 `Private / PT` 入口，也不得只凭 PT 域名规则伪造该能力。

## 5. Private / PT：Tracker facet 特殊条件

`W.TorrentSemantics` 继续唯一负责 Private authoritative metadata、unknown state 与可选 PT tracker-domain classification；PT rule 不能伪造 Private metadata。

Presentation/state 归入现有 canonical facet chain：

```text
W.CapabilityRegistry.supports('privateFilter')
-> W.LibraryController.facetOptions('tracker')
-> All Trackers
-> Private / PT
-> real tracker values
-> W.SpatialRuntime canonical Select
```

规则：

- `Private / PT` 只在 `privateFilter` exact/source capability 成立时出现；旧 qB 或无法证明的 future release 直接隐藏。
- 它固定排在 `All Trackers` 后、真实 Tracker 项之前。
- 选择它只改变 `LibraryController.tracker` 条件，不改变 `LibraryController.filter`。
- 因此可与 `All / Downloading / Seeding / Completed / ...` 任一 status filter 做交集筛选。
- 页面列表与 `W.Selection.selectAllMatching()/invertAllMatching()` 必须消费同一个 `LibraryController.matchesTorrent()` matcher，禁止 selection 再维护第二套 Tracker/Private 判断。

## 6. Selection parity

`W.Selection.selectAllMatching()` / `invertAllMatching()` 必须使用与页面 filter/facet 相同的 canonical matcher。

Selection 负责 selection set/actions，不拥有 Torrent taxonomy。

## 7. Transfer session telemetry

`app.js` 的 existing transfer cycle 继续是 `transfer/info` 的 poll owner；`W.TransferRuntime` 继续拥有 canonical bounded realtime samples/history 与现有 metadata snapshot，不新增请求或第二 timer。

Desktop Statusbar 与 Mobile Drawer chart 下方的 canonical compact transfer capsule显示 realtime rate：

```text
↓ <dl_info_speed>   ↑ <up_info_speed>
```

Compact capsule不显示“下载 / 上传”文字，也不把这两个位置用于 session cumulative totals。Mobile compact speed与右侧 connection status使用同一 responsive字体尺度，窄屏优先完整保留箭头、数值与单位。

Drawer compact chart复用同一 bounded history；其 dot legend继续显示 session cumulative totals：

```text
Download <dl_info_data>
Upload   <up_info_data>
```

因此 mini-chart totals legend 与 compact realtime arrow capsule是两个不同 presentation语义，但都消费同一 canonical `transfer/info` / `W.TransferRuntime` state；不得为任一 surface增加第二 poll、第二 request或 reconciliation owner。

Canonical Transfer statistics dialog继续没有图表上方重复 Download/Upload summary strip。完整 dialog 只保留一组 Download/Upload 语义，位于 chart 下方：左侧为 `↓ <realtime download> | 下载 <session downloaded>`，右侧为 `上传 <session uploaded> | ↑ <realtime upload>`。Desktop 与窄屏/Mobile 都消费同一组节点；窄屏只允许自适应换行/收缩，不恢复旧的独立 2x2 summary owner。

图表 window继续复用同一 canonical history；display smoothing默认 `10 s`，可选 `Raw / 3 / 5 / 10 / 15 / 20 / 30 s`。

短窗口 smoothing使用一个**当前选中窗口的 bounded derived aggregation cache**。每个 absolute-time bucket在完成时 freeze；后续 poll只累计新的 active bucket，不再每秒按滚动 cutoff对已经完成的历史桶重新分组/平均。用户切换 smoothing value时允许从既有 bounded raw samples一次性重建该显示 cache；之后继续增量推进。长窗口仍使用 bounded minute buckets。

这个 display cache不是第二业务 history truth：它不新增网络 polling、timer、长期 raw retention或新的 transfer state owner，且只服务当前 display aggregation。

Global/alternative rate-limit write gate、单位选择与 `transfer/info` publisher均不因此次 presentation/aggregation调改变。

## 8. Tracker detail URL truth

Torrent 详情页的 Tracker URL 直接消费 qB `torrents/trackers` API 返回的 `url`。对正常 HTTP(S) Tracker，WeiG 必须显示并把编辑初始值设为 exact API URL，不得再通过 `normalizeTracker()` 隐去 hostname、path 或参数。

qB upstream 自己构造的 `** [DHT] **`、`** [PeX] **`、`** [LSD] **` 等特殊条目仍按 upstream 原值展示；它们不证明普通 Tracker URL 应被 WeiG 归一化。长 URL 使用 variable-height/wrap presentation，不能为了固定行高截断 source truth。

## 9. QBClient boundary

`W.QBClient` 负责真实 qB transport，不拥有 compatibility policy：

```text
detect() 读取版本/identity
getTorrents() 使用 ReleaseProfile exact filter mapping
start/resume、stop/pause 使用 exact action surface
write/action 在参数未知时 fail closed
```

禁止通过“先请求失败再试另一个 endpoint”来探测 capability；caller 不复制 qB patch/WebAPI version policy。

## 10. Virtual protocol boundary

Virtual Lab 位于 QBClient 后方。

```text
source apiActions / upstream gates
-> endpoint exists?

simulator Endpoint Contract
-> historical request/response/status/mutation semantics

simulator Transport Contract
-> auth/header/proxy semantics

router/engine
-> execute resolved contract
```

这些 simulator owners 不进入 `W.TorrentSemantics`、`W.ReleaseProfile` 或 `W.QBClient`，也不改变正式产品 Torrent owner chain。

职责正交的 source catalog、ReleaseProfile、TorrentSemantics、Endpoint Contract 可以同时存在，因为它们回答不同问题；禁止两个 Torrent semantic engines 同时活跃。

## 11. Owner cutover

未来若 Torrent/HTTP semantic owner 真正被新 owner替代，必须：

```text
new owner isolated validation
-> atomic cutover callers/contracts/DESIGN
-> remove superseded branch/helper/test
```

禁止 runtime alias、shim 或长期双活。

## 12. Performance / scrolling

兼容不能通过 N Torrent -> N requests 实现。

Filter、selection、Private/PT、column projection、protocol semantic resolution 都应使用已有 list/catalog/profile/state；不新增 per-Torrent probe 或 capability polling。

Torrent DataGrid 横向位置属于承载 row 的 canonical `W.VirtualList` container state。普通轮询、row reconstruction、resize persistence不得把用户的 `scrollLeft` 重置为 0；只有用户主动横向滚动或真正改变横向布局几何时才改变该位置。禁止用 post-render timer 反复回写滚动条位置。

Detail table横向位置属于 `.shared-table__viewport`；`#detail-content` 只负责详情 workspace 布局，不能成为第二 horizontal scroll owner。

Resize期间直接修改当前已挂载 header/rows 的 grid geometry是 canonical interaction paint，不是第二 renderer；松手后的正式重建仍由现有 canonical rendering链完成。
