# 008. Torrent 工作区与状态所有权

> Torrent workspace 当前语义所有权。目标不是增加兼容分支，而是把 qB release source facts、Torrent semantic state 与 Desktop/Mobile presentation 分层。

## 1. Owner chain

```text
qB stable source facts
 -> W.ReleaseProfile
 -> W.TorrentSemantics
 -> W.TorrentFilterView / W.LibraryController / W.Selection
 -> W.QBClient HTTP boundary
```

`W.TorrentSemantics` 是 status/filter evaluation 的唯一 owner。`app.js` 与 `selection.js` 不得维护自己的 state regex 表。

## 2. Release-specific upstream filter names

qB4 与 qB5 的 HTTP filter 命名不同，但 UI semantic state 不复制：

- qB4 source `paused` -> canonical `stopped`；
- qB4 source `resumed` -> canonical `running`；
- HTTP 请求时再由 `W.ReleaseProfile.upstreamTorrentFilter()` 映射回 exact source name；
- qB5 exact source 直接使用 `stopped/running`。

某个 filter 不在该 release 的 source surface 中时 fail closed；不再让 unknown filter 退化为 All。

## 3. Status truth

`W.TorrentSemantics.matchesStatus()` 消费当前 torrent object：

- Downloading：下载/meta/forced/stalled/queued download states；
- Seeding：uploading/stalledUP/queuedUP/forcedUP states；
- Completed：`progress >= 1`；
- Stopped/Running：paused/stopped state complement；
- Active/Inactive：当前上下行速度；
- Stalled / checking / moving / errored：对应 upstream state families。

**Completed 与 Seeding 是不同语义。** 100% 完成不能单独把任务归入 Seeding。

## 4. Filter presentation

`W.TorrentFilterView` 只渲染 `W.ReleaseProfile`/`W.TorrentSemantics` 返回的 supported filters。Private / PT 只在 `W.CapabilityRegistry.supports('privateFilter')` 为真时加入。

因此：

- qB 4.1.0 不展示不存在的 Stalled/Private filter；
- 当前 release source 中存在 Stalled 才展示；
- Private 以 `torrents/info` 的 `private` 参数 presence 为 authority；
- Desktop Sidebar 与 Mobile Drawer 使用同一 `#filter-nav` 与同一 Library state。

## 5. Private / PT

`W.TorrentSemantics` 同时负责：

- qB authoritative Private metadata；
- metadata pending/unsupported 的 unknown 状态；
- 可选 PT tracker-domain rules。

PT tracker 规则只补充 PT 分类，不伪造 qB Private metadata。Private/UNKNOWN/PUBLIC 与 PT 可以组合为 `PRIVATE_PT / PRIVATE / PT / PUBLIC / UNKNOWN` presentation facts。

## 6. Selection parity

`W.Selection.selectAllMatching()` / `invertAllMatching()` 必须调用与页面 filter 相同的 semantic matcher。禁止出现页面显示一组 Torrent，而“选择全部匹配”按另一套规则选择的情况。

Selection 仍负责 selection set、range、page/all matching 与 actions；它不拥有 Torrent status taxonomy。

## 7. QBClient boundary

`W.QBClient` 负责 transport，不拥有 compatibility policy：

- `getTorrents()` 使用 `ReleaseProfile.upstreamTorrentFilter()`；
- start/resume 与 stop/pause 使用 exact API action surface 解析；
- 不再通过先请求一个 endpoint、收到 404/405 再试另一个 endpoint 来探测能力；
- capability flags 在 ReleaseProfile/CapabilityRegistry bind 后写入 client 供现有 callers 消费。

## 8. Performance

兼容不能通过 N Torrent -> N requests 实现。Filter、selection matching、Private/PT 等使用已有 list/catalog 数据和 source facts；不新增 per-Torrent probe 或能力轮询。

## 9. Acceptance

Contracts/Browser/LIVE 至少验证：

- qB4 paused/resumed canonical alias；
- qB5 stopped/running；
- retired/unsupported filters fail closed；
- Completed != Seeding；
- `app.js` 与 `selection.js` 同 owner；
- qB 4.1.0 unsupported Tags/Stalled/Private 正常 UI 隐藏；
- modern exact profile capability/filter set 与 source catalog 一致；
- Desktop/Mobile 不产生第二份 filter state。
