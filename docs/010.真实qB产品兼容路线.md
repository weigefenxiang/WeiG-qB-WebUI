# 010. 真实 qB 产品兼容路线

Status: **P0 product roadmap / Phase A DONE / Phase B DONE / Phase C NEXT**

> `webui/**` 是唯一正式产品。目标不是把 Simulator 做得更像 qB，而是让同一份 WeiG WebUI 在 qBittorrent 4.1.0 起的所有 official stable，以及未来新 stable / 新 major 上自动适配并保持正确产品语义。

## 1. 长期产品目标

同一份：

```text
webui/**
```

应能够：

```text
安装到 qB 4.1.0 起任意受支持 official stable
-> 自动识别真实 release / WebAPI / source capabilities
-> 自动选择 native / normalized / derived 实现
-> UI 只消费 canonical WeiG semantics
-> 不要求用户选择 qB4/qB5/qB6 专用包
-> 不要求手工选择 WebAPI 版本
```

正式兼容链：

```text
qB 4.1.0
-> all 4.x stable
-> all 5.x stable
-> current stable
-> future stable
-> qB 6.x / 7.x / future x.x.x
```

## 2. 优先级

当前工程优先级固定为：

```text
P0 当前最新 official stable
P0 未来 official stable / future major
P1 qB 4.1.0 起所有历史 stable
P2 representative real-qB / release hardening
P3 supporting simulator fidelity
```

核心思想：

> 不为了极少使用的老版本占用当前/未来版本适配资源。

### qB4.0.x / WebAPI v1

qB4.0.x 只保留 **Future Optional** 架构位：

```text
Legacy WebAPI v1 Adapter
```

当前：

```text
不实现
不进 CI
不进 full-stable matrix
不占 Phase 编号
不影响当前/未来 stable roadmap
```

若以后明确要求支持，再通过独立 Transport/Adapter 接入 canonical WeiG semantics。禁止把 v1/v2 判断散落进 UI、Settings、Torrent workspace。

## 3. 兼容架构原则

长期结构：


### 禁止 scattered version-if

业务层不要写：

```text
if qB4 ...
if qB5 ...
if major >= 5 ...
if version startsWith('5.') ...
```

优先判断：

```text
source action exists?
source field exists?
source filter exists?
required parameters exist?
reliable local derivation available?
```

只有无法通过 API/source facts 判断的极少数历史异常，才允许进入集中 exception manifest。

## 4. Product capability 状态

长期统一为：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

含义：

- `NATIVE`：上游直接提供；
- `NORMALIZED`：上游名称/参数不同，由兼容层归一化；
- `DERIVED`：从 source-proven canonical data 可靠本地实现；
- `READ_ONLY`：读取有证据，但写能力无证据；
- `UNAVAILABLE`：无法可靠实现；
- `UNKNOWN`：未来未知 surface，危险写操作 fail closed。

解析优先级：

```text
native
-> normalized / adapter
-> reliable local derivation
-> read-only when applicable
-> unavailable
```

## 5. Read / Write 必须分离

禁止：

```text
tags = true / false
```

应该拆成：

```text
tags.read
tags.list/facet
tags.filter
tags.assign
tags.create
tags.delete
```

同理：

```text
Category read/filter != Category mutation
Tracker read/add/remove/edit/reannounce 彼此独立
```

Phase B 已正式证明这个设计是必要的：qB4.1.0 `torrents/info` 已有 `category` / `tags`，因此 read/filter facet 可用；native taxonomy / mutation endpoint 不存在时只关闭对应写能力。

## 6. 性能规则

兼容不能以暴力请求换功能。

禁止：

```text
N torrents -> N extra API requests
```

优先复用：

```text
bulk torrents/info catalog
-> Filters
-> Facets
-> Search/local projection
-> Columns
-> derived capabilities
```

同一份 canonical data 尽量多处复用。

### Phase B 完成的核心产品变化

#### Filters

```text
native filter
-> normalized alias
-> source-proven local derivation
-> unavailable
```

qB4 `paused/resumed` 归一到 WeiG `stopped/running`；缺少 native stalled/checking filter 时，只要 source states 足够可靠就本地推导。

#### Category / Tags facets

```text
Category Select -> categoryFacet
Tags Select     -> tagFacet
```

read/facet/filter 不再错误依赖 native taxonomy API。

#### Torrent actions

Reannounce / Remove Tracker 等操作使用 exact source action gate；缺失时在 UI 前就不可用，QBClient 再做 fail-closed，消灭 click-to-404。

## 10. Phase C — Full Stable Product Compatibility Matrix — NEXT

Phase A 已经让每个 stable 都有真实 source facts；现有 `tests/upstream-release-audit.mjs` 也已经遍历所有 stable。

Phase C 不再重新造 stable tag 枚举器，而是在现有基础上增加正式 **product-level matrix**。

目标：

```text
for every official stable >= 4.1.0:
    source facts
       -> ReleaseProfile
       -> product capability resolution
       -> assert product invariants
```

### Phase C 预计修改文件

```text
NEW（优先）
tests/full-stable-product-compat.mjs

MODIFY
tests/upstream-release-audit.mjs
tests/release-compat.mjs
tests/compat-matrix.mjs
.github/workflows/ci.yml
package.json            # 仅需要统一 script 入口时
```

如果 source facts 已足够，Phase C 不修改 `tools/*`。

原则上 Phase C 也不修改 `webui/**`；只有矩阵找到真实产品 bug，才回到对应 owner 修复。

### Phase C 每个 stable 必须验证

```text
Filters
  native / normalized / derived / unavailable

Facets
  Tracker / Path / Category / Tags
  read 与 write 分离

Torrent Actions
  action 是否有 exact source / adapter 证据
  不允许 exposed-but-404

Torrent Fields
  当前正式 columns 所需字段是否存在/可 normalized/derived

Settings
  Preference getter/setter/type provenance

Search / RSS / Logs
  入口与真实 capability 一致
```

### Phase C 必须守住的 invariant

```text
1. 每个 exposed write action 必须有可证明实现
2. derived filter 必须有可靠 source fields/states
3. Category/Tags read 与 write 永远分开
4. source-required capability 无 exact facts 时 fail closed
5. 不允许 major upper bound
6. 不允许 major>=5 作为产品事实替代品
7. future unknown dangerous writes fail closed
8. qB4.0.x 不进入矩阵
```

现有 `release-compat.mjs` 中的 `major>=5 ? ... : ...` 测试 stub 将在 Phase C 移除，改为 ReleaseProfile/source facts 驱动。
