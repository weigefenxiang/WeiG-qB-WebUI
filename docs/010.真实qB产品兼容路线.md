# 010. 真实 qB 产品兼容策略

Status: **current compatibility strategy**

## 1. 长期目标

qB 4.1.0 official stable -> all admitted stable -> current latest -> future stable/major。`UNKNOWN` 表示无法证明；危险 write必须 fail closed。

当前 operational admitted window是 4.1.0 -> 5.2.3，共 65 stable；数量与 latest是当前事实，不是永久硬编码。Expected set始终由 target exact-SHA Frozen catalog定义。

## 2. Source truth first，runtime compact

```text
qB official exact source / official TS
-> semantic extractors + independent inventories/census
-> admitted Frozen LKG/catalog
-> common catalog identity
-> compact domain compilers
-> capabilities / torrent / detail / settings / rss / actions / qB-owned copy
-> W.CapabilityRegistry / canonical semantic owners / W.I18n
-> W.QBClient
-> product UI
```

Browser不加载 release catalog或 per-release profile shards。Version只用于 detected identity、exact/equivalent/bounded inherited resolution、diagnostics/evidence；禁止 `major >= N => feature=true` 或 future自动继承 dangerous writes。

`capabilities.json` 是轻量 control plane，不是全部版本事实总表。领域事实分别进入 bounded compact contracts；浏览器按需 lazy-load active domain。

## 3. Domain contract 与 ownership

```text
capabilities.json      release identity / high-level gates / compatFiles
torrent-compat.json    filters/status/fields/columns + B target native facets
detail-compat.json     Detail tabs/layout/tables/menus/actions
settings-compat.json   current legacy runtime facts + A target source-native controls/sections/order/value projection
rss-compat.json        RSS Downloader/rule native-surface facts
source-actions.json    action + required/optional parameters
qB-owned copy artifact exact {source,context} + official locale route
```

一个 domain只能有一个 active runtime owner。Source/admission IR可以先存在于 tools/CI，但正式 cutover时必须原子替换 superseded runtime truth；禁止长期 `legacy/new`、`v1/v2` product path。

## 4. Independent inventory / census：防静默遗漏

仅验证 extractor返回的数据内部一致，不足以证明 upstream没有被漏掉。每个 source-driven domain的正式 completion必须引入尽量独立的 census：

```text
raw upstream source
  ├─ semantic extractor -> mapped product facts
  └─ independent inventory/census -> upstream exposed inventory

inventory = mapped + explicit reviewed exclusions
unaccounted = 0
duplicates = 0
```

典型 accounting：

```text
Settings   native tabs/controls + read/write Preference identities + source-bound bindings
Torrent    statuses/filters/facets + filter/value bindings
RSS        feeds/downloader/rule fields/actions/read-state
Detail     tabs/general properties/table columns/context menus/actions
Copy       every runtime qB-owned {source,context}
Writes     every product mutation action/required parameter
```

`explicit exclusions` 必须说明为什么该 upstream item不属于 formal product surface/不安全/不可表达，不能拿 exclusion当“解析失败垃圾桶”。如果 upstream语法变化导致 census看到新 item而 extractor不认识，admission必须 fail/PENDING_REVIEW；不能静默丢掉后继续绿色。

Preferences source层已经实现 independent census：`tabs / preferences / bindings` 对全部 admitted release逐项 account，full-stable contract要求 census complete，并在 unaccounted/overlap/escaped/duplicate时失败。Mapping ratio仍保留为 parser健康度 signal，但**已经不再承担 completeness proof职责**。因此 A剩余 blocker不是“再做一套 Preferences census”，而是把已经证明的 source-native IR正式切入 runtime并退休旧手工 Settings owner。

## 5. Source-derived value projection / Settings write safety

Preferences UI不是简单的 raw API value == DOM value。Exact source可能存在：

```text
identity
raw bytes/s <-> UI KiB/s scale
raw bytes <-> UI MiB scale
historical switch/composite read mapping
future or unknown transformations
```

当前 source pipeline已把这些事实提取成 Preference-level `projection`：`identity / scale / switch-map / unproven`，并携带 `safeWrite`。已证明的 scale可由 canonical product mapping安全转换；只有 read-side switch-map而没有 source-proven inverse时必须 `safeWrite:false`。

A runtime cutover后，Settings dangerous write要求：

```text
certified exact/equivalent release identity
AND setPreferences action proven
AND specific Preference setter/type proven
AND source value projection.safeWrite == true
AND current app/preferences actually exposes the Preference
```

任何一项缺失都在 HTTP前 fail closed。不得继续依赖手工 `META.scale` 或版本条件猜 raw/UI转换。

## 6. Cross-domain catalog identity

`tools/qb-catalog-identity.mjs` 已建立 common Frozen catalog identity helper。当前 compact compiler已经把同一 identity注入 capabilities/torrent/detail/actions/settings outputs，Preferences keyed native IR也携带它。这是 F foundation的一部分，但不是 integrated closure。

最终所有 compact contracts与 qB-owned copy必须来自同一个 Frozen admitted catalog并携带可比较 identity，至少等价于：

```text
supportFloor
latestAdmittedStable
releaseCount
releaseSetSha256
sourceCatalogSha256
```

仍需完成：RSS进入相同 compiler/identity链；runtime/distribution在加载/打包时校验所有 domain identity一致；mixed/stale domain bytes必须 fail closed。不能只因为每个 JSON单独合法就接受 mixed-generation runtime。

## 7. Capability granularity / fail-closed writes

Category/Tags/Tracker/Settings/RSS/Detail等 read/write/action/field/parameter独立证明。一个 mutation需要多个 action/parameter时必须 all-required proven。可靠 historical shape差异可 NORMALIZED/DERIVED，但必须 deterministic、bounded、无 N->N requests、无第二 state；否则 READ_ONLY/UNAVAILABLE/UNKNOWN。

Transport前必须证明 certified current identity、source action/endpoint、required parameters与 payload semantics。Settings另要求 Preference setter/type agreement + source value projection。Unknown action/parameter、missing setter、type mismatch、unproven structured value、unsafe projection、unsafe inherited/future write均零 HTTP。

## 8. Frozen LKG / new stable admission

Frozen LKG是离线验证基线，不是 browser runtime。新 stable admission固定顺序：

```text
verify Frozen prefix identity
-> discover exact official stable tag/source SHA
-> run independent inventory + semantic extraction for new stable
-> compare against previous admitted stable
-> identify new/removed/moved tabs/fields/actions/source-context/value projections
-> focused parser/product/change-point validation
-> explicit review of every unaccounted item
-> regenerate common-identity compact contracts
-> one phase/admission aggregate as required
-> append to Frozen admitted set only after PASS
```

旧 verified release facts默认不因 extractor重构而无理由重写。无法证明的新语义保持 `PENDING_REVIEW/UNKNOWN`；不能因为“最新版必须支持”猜 semantics或放宽 gate。

## 9. Translation / evidence layers

qB-owned wording遵循 exact source/context + translator behavior -> native official QM或 source-proven exact bridge；4.5.0 -> 4.6.4 hard gap不得 nearest inheritance。WeiG-owned wording不进入 qB source inventory。

Source audit、phase-end offline/Virtual 65、browser/Pages、focused real-qB、release-grade real-qB Full Frozen Matrix是不同证据层，不能互相替代。`SKIPPED != PASS`，旧 SHA evidence不能证明新 SHA，被 supersede/cancel的 source run也不能证明后续 SHA。

## 10. Validation cadence

开发阶段不每一步跑65：

```text
inside phase -> focused/source-diff change points
phase complete -> at most one admitted-stable offline/Virtual full matrix
all A–F complete + final dev SHA frozen -> one release-grade real-qB Full Frozen Matrix
```

Source extractor的性能本身也是工程约束：不要把每个 Preference/field都实现成重新扫描整份历史 source的 O(N×source)路径。可索引的 release source应每个 release预索引一次，再做 bounded lookup；性能回归不能靠“CI多等一会”掩盖。

如果 final product SHA在 release-grade matrix后发生变化，则旧 matrix仍只证明旧 SHA，真正发布前需要按 `docs/011` 重新建立新 final SHA所需 evidence。
