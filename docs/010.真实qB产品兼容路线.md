# 010. 真实 qB 产品兼容策略

Status: **current compatibility strategy**

本文件描述 WeiG qB WebUI 如何长期兼容真实 qBittorrent，不维护 Phase/patch-version历史路线图。`webui/**` 是唯一正式产品；当前实现事实见 `docs/002`，Current Owner见 `docs/003` / `DESIGN.md`。

## 1. 长期兼容目标

```text
qB 4.1.0 official stable
-> all admitted official stable releases
-> current latest official stable
-> future official stable / future major
```

能力解析优先级：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY when applicable
-> UNAVAILABLE
-> UNKNOWN
```

`UNKNOWN` 表示无法证明；危险 write必须 fail closed。

## 2. Source truth first

兼容行为必须从 qB official source与 exact release facts推导，而不是从版本号猜。

```text
qB official source
-> generated exact stable facts
-> admitted Frozen LKG
-> W.ReleaseProfile
-> canonical product owners
-> W.QBClient
-> product UI
```

Formal facts包括：

```text
qB/WebAPI/source identity
actions + required/optional parameters
Torrent states / filters / info fields
main/detail source schema
Preference getter/setter/type provenance
translator behavior / locale routes
release evolution facts
```

## 3. Version 信息的正确用途

允许：

```text
select exact/equivalent/inherited profile
source catalog indexing
diagnostics/evidence
runtime identity verification
```

禁止：

```text
if major >= 5 then feature=true
if version >= x then blindly send write
nearest-version-wins across hard boundary
future version automatically gains latest dangerous capability
```

Historical API shape transition应在 source-backed normalize/adapter层解决，不把 patch-version条件散落到 presentation。

## 4. Release profile resolution

```text
EXACT
-> EQUIVALENT
-> bounded INHERITED
-> FALLBACK
```

- **EXACT**：exact admitted official stable profile。
- **EQUIVALENT**：只有 source/API identity可证明语义等价的 suffix/packaging variation。
- **INHERITED**：只在明确边界内临时复用较低已认证 profile；默认不得跨 major.minor或 source-proven hard boundary。
- **FALLBACK**：不存在安全 relation时，危险能力保持 UNKNOWN/fail closed。

Inheritance只能复用 base已证明事实，不能为新版本 invent endpoint、parameter、field、Preference或write能力。

## 5. Capability 粒度

兼容按能力而不是页面粗粒度判断：

```text
Category: read/filter/list/create/delete/assign independent
Tags: read/filter/list/create/delete/assign independent
Tracker: read/add/remove/edit/reannounce independent
Settings: endpoint read/write + per-Preference writable independent
Details: properties/files/trackers/peers/webseeds independent
```

一个 UI mutation依赖多个 upstream actions/parameters时，必须全部 source-proven；不能部分发送或先发后探测。

## 6. Normalize / Derived 原则

当历史版本返回不同 shape但语义可可靠归一化时允许 `NORMALIZED`；当新能力可由旧 API稳定组合可靠推导时允许 `DERIVED`。

必须满足：

```text
semantics deterministic
cost bounded
no N->N compatibility requests
no hidden second state
no fake data
errors/unsupported remain distinguishable
```

否则降级为 READ_ONLY / UNAVAILABLE / UNKNOWN。

## 7. Fail-closed write

任何 destructive/mutating action在 transport前必须证明：

```text
endpoint/action exists
required parameter contract known
current capability owner allows it
payload semantics validated
```

Settings还要求 specific Preference setter/type agreement。

以下情况不得发送 HTTP：

```text
unknown action
unknown required parameter
missing setter
type mismatch
unproven structured value
inherited/future profile without write provenance
```

## 8. Frozen LKG / new stable admission

Frozen LKG代表已经验收的 historical source facts；future parser/UI改造不得无理由重写 verified prefix。

发现新 official stable时：

```text
discover official release/source identity
-> verify existing Frozen prefix
-> extract only new stable facts
-> diff against previous admitted stable
-> focused source/product review
-> admit only after evidence PASS
```

无法证明时标记 pending/fail closed，LKG不变。

当前 operational范围是 qB 4.1.0 -> 5.2.3；具体 stable数量由 target exact-SHA LKG派生，不写成永久架构常量。

## 9. Translation compatibility boundary

qB-owned wording同样是 compatibility surface：

```text
exact source/context
+ exact translator behavior
-> native QBT_TR/QM where source-proven
-> exact official-TS bridge only for proven Alternative-WebUI gap
```

`4.5.0 -> 4.6.4` Alternative WebUI document translation disabled是当前已证明 hard boundary，不能用 nearest-version inheritance或“有 QM 文件”跨越。

具体 locale/i18n contract见 `docs/005`。

## 10. Product / simulator / evidence 分离

```text
formal product compatibility -> webui canonical owners
Virtual qB               -> deterministic validation infrastructure
Pages/browser             -> hosted product/materialization evidence
real-qB harness           -> real runtime evidence
```

Simulator/Pages PASS不能代替 formal product matrix或 real-qB evidence。

正式全版本验证规则见 `docs/011`；发布晋级见 `docs/006`。

## 11. 文档维护

兼容策略发生长期改变时更新本文件；当前 exact实现/验证事实更新 `docs/002`；当前未完成工作更新 `docs/014`。

不再创建按 WeiG patch version命名的 compatibility复盘/路线图文件；Git history保存历史演进。
