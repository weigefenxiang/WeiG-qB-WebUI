# 010. 真实 qB 产品兼容路线

Status: **P0 product roadmap / Phase A–F DONE / Phase G PLANNED / STOP**

> `webui/**` 是唯一正式产品。目标不是把 Simulator 做得更像 qB，而是让同一份 WeiG WebUI 在 qBittorrent 4.1.0 起的全部 verified official stable、当前 latest stable，以及未来 stable / new major 上自动适配并保持正确产品语义。

## 1. 长期目标

```text
qB 4.1.0
-> all verified 4.x official stable
-> all verified 5.x official stable
-> current latest official stable
-> future official stable
-> qB6.x / qB7.x / future x.x.x
```

能力解析：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY
-> UNAVAILABLE
```

future `UNKNOWN` 只关闭无法证明的具体 capability；尤其危险写操作 fail closed。禁止手动 compatibility mode、按 major 整体拒绝或自动继承 current latest semantics。

## 9. Phase F compatibility semantics — 复盘后的正式解释

**“qB 4.1.0 -> 5.2.3，65/65 compatible”不等于“65 个版本都拥有全部新功能”。**

正式含义是：

```text
同一份 webui/**
-> 识别当前 exact release/source facts
-> 该版本真实存在的 capability 正常开放
-> 该版本不存在的 capability 正确隐藏/禁用/降级
-> UNKNOWN / 未证明危险写在 HTTP 前 fail closed
-> 不用用户选择 4.x/5.x compatibility mode
```

代表性边界：

```text
Settings preferences endpoint          qB 4.1.0+
Settings setPreferences endpoint       qB 4.1.0+，但具体 Preference writable 仍逐项判断
RSS core                               qB 4.1.0+
Logs main/peers                        qB 4.1.0+
Properties/Files/Trackers/Peers/
WebSeeds + filePrio + addTrackers      qB 4.1.0+
Search core                            qB 4.1.4+
remove/edit Tracker                    qB 4.1.5+
Peer Ban                               qB 4.2.0+
Tags capability                        qB 4.2.0+ source truth
Torrent Creator                        qB 5.0.0+
```

因此把当前 `weig-qb-webui/webui` 放到任一 **已验证官方 stable qB 4.1.0 -> 5.2.3** 上，目标行为是“自动正确适配”；不是把后期 qB API 回填到早期 qB。

Phase F 已用 65-profile formal Product Matrix + Linux/Windows Hosted Chrome + Virtual qB + all-stable source audit 证明这一层。**真实 qB binary/server、不同设备/部署环境的端到端证明属于 Phase G。**

## 14. Phase G — Real-qB / Release Hardening — PLANNED

Phase G 的目标不是重新做 Phase F，而是把“source/profile/browser 已证明”升级为“真实 qB binary/server + 真实部署已证明”。

### G1 — Representative real-qB matrix

```text

modern qB4 representative             -> 从 verified qB4 stable 中选定

latest official stable                -> Phase G 开始时 fresh-resolve
```

每个真实 qB 都使用同一份正式 `webui/**`，禁止专门为测试版本做手动 compatibility mode。

### G2 — Real WebAPI semantic flows

```text

```

禁止用“真实 server 能返回 404”作为 feature detection 机制替代 Phase F owner。

### G3 — Deployment / operator hardening
