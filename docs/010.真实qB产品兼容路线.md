# 010. 真实 qB 产品兼容路线

Status: **P0 product roadmap / Phase A DONE / Phase B DONE / Phase C DONE / Phase D DONE / Phase E DONE / Phase F NEXT**

> `webui/**` 是唯一正式产品。目标不是把 Simulator 做得更像 qB，而是让同一份 WeiG WebUI 在 qBittorrent 4.1.0 起的全部已验证 official stable、当前 latest stable，以及未来新 stable / new major 上自动适配并保持正确产品语义。

## 1. 长期目标

同一份：

```text
webui/**
```

应能够：

```text
qB 4.1.0
-> all verified 4.x official stable
-> all verified 5.x official stable
-> current latest stable
-> future official stable
-> qB6.x / qB7.x / future x.x.x
```

自动识别真实 release/WebAPI/source capability，按证据选择：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY
-> UNAVAILABLE
```

future `UNKNOWN` 只关闭无法证明的具体 capability，尤其危险写操作；不要求用户选择 qB4/qB5/qB6 专用包，也不要求手动 compatibility mode。

## 2. 优先级

```text
P0 current latest official stable
P0 future official stable / future major
P1 every verified stable >= qB 4.1.0
P2 representative real-qB / release hardening
P3 supporting simulator fidelity
```

核心思想：不为了极少使用的旧版本占用当前/未来 stable 适配资源。

### qB4.0.x / WebAPI v1

```text
Legacy WebAPI v1 Adapter = FUTURE OPTIONAL
```

当前不实现、不进 CI、不进 full-stable matrix、不占 Phase。未来若明确批准，只通过集中 Adapter 接入 canonical WeiG semantics，禁止把 v1/v2 判断散落到 UI、Settings、Torrent workspace。

## 5. Read / Write / Performance rules

Read/write 必须分离，例如：

```text
Tags read/facet/filter != list/assign/create/delete
Category read/filter != mutation
Tracker read/add/remove/edit/reannounce independent
Settings getter-only != editable
```

兼容不能靠暴力请求：

```text
no N items -> N extra compatibility requests
no high-cost compatibility polling
no presentation caller self-probe
no second business state / owner
```

优先复用 canonical bulk data，例如 `torrents/info` catalog。
