# 010. 真实 qB 产品兼容路线

Status: **P0 product roadmap / Phase A DONE / Phase B DONE / Phase C DONE / Phase D DONE / Phase E NEXT**

> `webui/**` 是唯一正式产品。目标不是把 Simulator 做得更像 qB，而是让同一份 WeiG WebUI 在 qBittorrent 4.1.0 起的所有已验证 official stable、当前 latest stable，以及未来新 stable / new major 上自动适配并保持正确产品语义。

## 1. 长期产品目标

同一份：

```text
webui/**
```

应能够：

```text
安装到 qB 4.1.0 起任意受支持 official stable
-> 自动识别真实 release / WebAPI / source capabilities
-> 自动选择 native / normalized / adapter / composition / derived
-> read-only / unavailable only when evidence requires
-> UI 只消费 canonical WeiG semantics
-> 不要求用户选择 qB4/qB5/qB6 专用包
-> 不要求手工选择 WebAPI compatibility mode
```

正式兼容链：

```text
qB 4.1.0
-> all verified 4.x stable
-> all verified 5.x stable
-> current stable
-> future stable
-> qB 6.x / 7.x / future x.x.x
```

## 2. 优先级

当前工程优先级固定为：

```text
P0 当前 latest official stable
P0 未来 official stable / future major
P1 qB 4.1.0 起所有历史 verified stable
P2 representative real-qB / release hardening
P3 supporting simulator fidelity
```

核心思想：不为了极少使用的老版本占用当前/未来版本适配资源。

### qB4.0.x / WebAPI v1

qB4.0.x 只保留 **FUTURE OPTIONAL** 架构位：

```text
Legacy WebAPI v1 Adapter
-> canonical WeiG semantics
```

当前不实现、不进 CI、不进 full-stable matrix、不占 Phase。若以后明确批准支持，只能通过独立集中 Adapter 接入，禁止把 v1/v2 判断散落进 UI、Settings、Torrent workspace。

## 3. Authority / 兼容架构原则

Authority：

```text

```

实际行为最终以当前 exact-SHA canonical runtime + upstream/source/real-qB evidence 为准。

长期结构：

```text
qB upstream official stable source
          |
          v
Source Extractors / generated stable facts
          |
          v
W.ReleaseProfile
          |
          +--> W.TorrentSemantics
          +--> W.CapabilityRegistry
          +--> W.SettingsSchema
          +--> W.QBClient
          |
          v
Canonical WeiG semantics
          |
          v

```

业务层不得保存 patch/major version table。优先判断：

```text
source action exists?
source field exists?
source filter exists?
required parameters exist?
Preference getter/setter/type provenance?
reliable old-API composition available?
reliable local derivation available?
```

只有无法通过 source/API facts 证明的极少数历史异常，才允许进入集中 exception owner。

## 4. Product capability 状态

长期统一为：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

解析优先级：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY
-> UNAVAILABLE
```

future `UNKNOWN` 只对无法证明的具体 capability fail closed，尤其危险写操作；future version 本身不能因为 major/version number 被自动拒绝，也不能因为版本更高就自动继承 current latest semantics。

## 5. Read / Write 必须分离

禁止：

```text
tags = true / false
```

应该拆成：

```text
tags.read
tags.list/facet
tags.filter
tags.assign
tags.create
tags.delete
```

同理：

```text
Category read/filter != Category mutation
Tracker read/add/remove/edit/reannounce 彼此独立
Settings getter-only -> read-only
a getter + trustworthy setter/type -> editable
```

Phase B 与 Phase C 已证明 read/write 分离是长期兼容模型，而不是旧版本特例补丁。

## 6. 性能规则

兼容不能以暴力请求换功能。

禁止：

```text
N items -> N extra compatibility requests
high-cost compatibility polling
presentation caller self-probe
second business state / owner
```

优先复用 canonical bulk data，例如 `torrents/info` catalog，再供 Filters、Facets、Search/local projection、Columns、derived capabilities 多处消费。

### 11.2 Tag-first discovery

Future Stable Watch 首先只比较官方 stable tag 名称：

```text
verify LKG
-> git ls-remote release-* tag names
-> stableAdmissionDelta
```

无新 stable：

```text
immediate exit
no upstream source checkout
no frozen-history product replay
no source extraction
no repository write
```

有新 stable 才进入：

```text
upstream source checkout
-> source-extract only newly discovered stable profiles
-> assert frozen prefix unchanged
-> diff from previous admitted stable
-> source audit support floor + new refs
-> focused product gate:
   support floor + previous admitted stable + new profiles
-> repository contracts / architecture guard
-> upstream + product capability diff
-> prepare next manifest
-> fresh exact dev race check
-> safe fast-forward catalog + manifest only
```

### 11.3 Admission failure

以下任一出现：

```text
parser failure
unknown API/response semantics
unknown or unsafe write semantics
product owner gap
product regression
history drift / frozen profile mutation
repository contract failure
```

必须：

```text
PENDING_REVIEW
candidate not admitted
Last Known Good unchanged
formal release baseline unaffected
```

禁止为了“最新版必须自动支持”放宽 parser、猜 response/write semantics、改旧 profile 或硬把 CI 变绿。

### 11.4 Historical product regression

只有通用 formal product compatibility code / matrix contract 变化时才跑历史 frozen product regression，例如：

```text
ReleaseProfile
QBClient
TorrentSemantics
CapabilityRegistry
SettingsSchema
full-stable product matrix / architecture guard
```

该 regression 直接消费 frozen profiles，不重新 source-extract old stable。仅新增 verified stable profile或 LKG/manifest/admission-only 变化不触发全部 historical product replay。

### 11.5 Heavy source/evolution audit

Stable discovery、source parser、source extraction、evolution ledger/tooling 变化触发：

```text
Full qB stable WebAPI evolution audit
```

`tools/qb-stable-admission.mjs` 已纳入该 trigger。普通 docs/UI/CSS/图片/翻译/VERSION-only/installer/test-only 不触发；heavy audit 不重复 npm test。

### 11.6 Architecture / proof guard

`tests/compat-architecture-contract.mjs` 在 exact checkout 上递归读取 `webui/private/scripts/**` 全部 `.js` 完整内容，阻止新增 scattered qB version-if；集中版本知识保留在 canonical resolver/adapter/exception owner。

Repo-wide ownership/absence/proof 固定要求：

```text
target exact SHA
+ complete tree identity
+ complete blob/file contents for semantic inspection
```

Code search/snippet 只可 discovery；旧 SHA、截断结果、局部片段和推测不能作为 repo-wide final proof。
