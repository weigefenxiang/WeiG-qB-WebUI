# Settings 语义与未来兼容

当前 Settings 的 qBittorrent Preference 语义由 `W.SettingsSchema` 唯一负责。`W.QBClient` 只负责 `app/preferences` / `app/setPreferences` HTTP 传输；Settings presentation 复用现有 section/grid、canonical Select、Switch 与 Input。

Locale persisted-owner cutover 与 qB-owned Settings native-first translation cutover 都已经完成。当前不是“JSON bridge 等待未来被 native path 替换”的状态；正式产品已经优先使用 qB 原生 `QBT_TR` / translator / official QM，仅对 upstream Alternative WebUI 明确无法执行 document translation 的 exact stable family 保留 source-proven official-TS narrow bridge。详细复盘见 `docs/012.qB原生翻译与国际化复盘.md`。

## 1. 与 Virtual qB 的职责边界

正式产品：

```text
Real/Virtual app/preferences HTTP transport
-> W.QBClient

Product Settings schema / routing / editability
-> W.SettingsSchema + W.SettingsRenderer / W.SettingsState

Persisted locale truth
-> qB app/preferences.locale

WeiG-owned UI translation runtime
-> W.I18n

qB-owned wording: native-first
-> exact qB source/context
-> QBT_TR
-> source-SHA-bound translator behavior
-> qB native translator / official minimal QM where required
-> W.I18n.qbSetting() consumption

qB-owned wording: source-proven compatibility gap only
-> exact qB source/context + official TS
-> exact qbVersion + sourceSha + locale route
-> private/data/qb-settings/<sourceSha>.json
-> W.I18n.qbSetting() consumption

Virtual qB preference storage / modeled side effect
-> Virtual qB Engine
```

Simulator 可以知道某个 preference key 存在，但不能因此自行发明正式 WeiG 的 label、unit、enum、help 或复杂写回 contract。

## 2. 信息架构

qBittorrent Settings 主 surface：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema
-> semantic family rule
-> canonical surface
-> Advanced / Upstream fallback
```

Desktop/Mobile 共享同一 Settings semantic state，不建立第二套 schema 或业务状态。

## 3. Exact Preference provenance

每个 admitted official stable profile 从 qB upstream getter/setter source 生成 descriptor，包括：

```text
getter/read type/kind/confidence
setter/write type/kind/confidence
getter/setter agreement
writable
enum fallback provenance
```

Setter-only key 不得逃出 `app/preferences` surface。

## 4. Locale 当前 Owner

唯一持久语言真值：

```text
qB app/preferences.locale
```

当前启动链已经是：

```text
QBClient.detect()
-> ReleaseProfile / capability ready
-> QBClient.getPreferences()
-> shared AppState / SettingsState preferences snapshot
-> W.I18n.applyLocale(prefs.locale)
-> W.I18n.ready()
```

没有独立 `weigg-language` persistence。

两个 Locale presentation entry point：

```text
WeiG WebUI -> Interface -> Language
qB Settings -> Advanced -> Locale
```

共享：

```text
same draft.locale
same exact-release options
same writable provenance
same setPreferences transaction
same verification reread
```

## 5. Locale Save contract

```text
shared locale draft
-> SettingsSchema writable check
-> QBClient.setPreferences(pending)
-> QBClient.getPreferences() verification reread
-> update shared prefs snapshot
-> W.I18n.applyLocale(returned locale)
-> rerender shared DOM
```

写入失败：不切视觉语言。

写入成功但 verification read 失败：明确显示“已写入但无法确认”，仍不把未确认 draft 提升为 rendered truth。

## 6. Locale option source truth

真实 qB：

```text
private/views/preferences.html
-> qB WebApplication injects ${LANGUAGE_OPTIONS}
-> runtime exact locale codes + localized labels
```

Virtual qB / historical profile：

```text
source-SHA-bound frozen locale overlay
-> W.ReleaseProfile exact webuiLocales
```

当前 admitted latest qB 5.2.3 的 WebUI locale set 为 61 项。旧 release 可能使用不同历史代码/子集，例如 `de_DE`、`ja_JP`、`ko_KR`、`zh`。

禁止在 Settings/App caller 中写 patch-version Locale 表。

## 7. qB-owned Settings 文案：当前 native-first 实现

当前 0.3.72 正式链：

```text
exact release Preferences UI
-> control relation
-> official QBT_TR source/context
-> exact sourceSha translator behavior family
-> native Settings registry
-> qB server-side QBT_TR
-> official minimal webui_<locale>.qm where exact family requires active-root QM
-> W.I18n.qbSetting()
```

Native registry：

```text
private/data/qb-settings-native.txt
```

它保存 QBT_TR source/context 与 exact routing/reference facts，不拥有第二份人工翻译数据库。

qB-owned 译文来源仍是 upstream qB official translation facts；魏G presentation 只消费翻译结果。

## 8. Source-proven narrow compatibility bridge

并非所有 admitted stable 都能让 Alternative WebUI 执行 document translation。

Exact source audit 已证明：

```text
qB 4.5.0 -> 4.6.4
Alternative WebUI document QBT_TR: disabled / not executed
```

因此这些明确 family 需要窄 bridge：

```text
private/data/qb-settings/<sourceSha>.json
```

约束：

```text
exact qbVersion + sourceSha + locale route
translation body comes only from exact official qB TS
only source-derived translator behavior may enable bridge
profile/source/locale mismatch -> reject/fail closed
```

这条 JSON path 是 upstream gap 的 compatibility transport，不是待迁移的主翻译 owner，也不能扩回所有 stable/all locales 的浏览器 translation database。

只要正式支持范围仍包含这些 source-proven gap releases，就不能因为“native-first 已完成”而误删这条必要 bridge。

## 9. `qb-releases.json` / runtime profile 的边界

`qb-releases.json` 与 exact profile shards 继续拥有 compatibility/source facts：

```text
exact qB/WebAPI/source identity
actions + parameters
Torrent fields/filters
Preference provenance
translator behavior / routing facts
compatibility facts consumed by W.ReleaseProfile
```

它们**不拥有全量翻译正文**。

Runtime 当前采用 compact index + exact profile shard：

```text
private/data/qb-releases.json
private/data/qb-release-profiles/<sourceSha>.json
```

`settingsTranslationPath` 现在只允许是 source-proven gap route 的窄 pointer。它不是 0.3.69 临时债，也不应被“一刀切删除”；是否存在由 exact translator behavior/source facts 决定。

禁止重新把 all-release / all-locale Settings translation bodies 塞回 runtime release catalog。

## 10. WeiG-owned translation

以下语义仍属于 WeiG：

```text
WeiG Interface / Theme / Starfield / Motion
WeiG diagnostics / custom notices
WeiG-specific interactions/help
About / Brand / project identity
```

这些由 `W.I18n` 拥有。

如果上游存在完全对应的 qB source/context，则应评估改用 qB owner；如果没有，就必须明确保持 WeiG-owned，不能借 qB translation 名义制造“官方译文”。

## 11. Editability

Exact stable profile 只有同时满足：

```text
write endpoint/action proven
setter exists
write type understood
getter/setter type agrees
descriptor writable == true
```

才可编辑。

否则保持 read-only/unavailable。`onDraft` 不接受 non-writable key，保存前 `writableDraft()` 再做 defense-in-depth 过滤。

Locale 也受此 contract 约束。

## 12. Unknown / future Preferences

未来 stable 新 key 不静默丢失：

```text
exact schema if known
-> semantic family rule
-> Advanced / Upstream fallback
```

未知 scalar 在没有 exact setter provenance 时只读；未知 array/object 可见但只读，以结构化 JSON 展示。

禁止猜 unit、enum、range、startup default，也禁止 blind write。

## 13. Endpoint / Preference 两层证明

Settings write 不是一个粗粒度 boolean：

```text
app/setPreferences source action proven
AND
Preference descriptor proves setter/type/editability
-> write allowed
```

任一层 unknown/unproven，都不得发送对应 payload。

CapabilityRegistry 不决定 Preference writable；SettingsSchema 也不维护 endpoint historical response policy。

## 14. Translator behavior / native path acceptance

Native-first 当前架构必须持续证明：

```text
translator behavior matrix covers every admitted stable
QBT_TR parsing/served-file behavior is source-derived
required official QM provisioning is deterministic
historical locale identity is handled without caller version branches
qB-owned source/context comes from exact upstream release
missing/unfinished translation fallback remains truthful
source-proven Alternative WebUI gap remains bridge-routed
Pages validation does not leak unresolved QBT_TR markers
Virtual qB does not invent native capability for gap releases
```

新增 stable 或 translator behavior 变化时，先更新 exact source facts，再决定 native/bridge route；禁止按 semver 猜 family。

完整 source audit 与历史边界见 `docs/012.qB原生翻译与国际化复盘.md`。

## 15. Pages / simulator boundary

GitHub Pages 不经过 qB WebApplication，因此 Pages 使用 validation-only preprocessing/emulation 模拟 native-capable profile 的 qB server replacement。

这种 fixture 只能来自 frozen/source-derived official translation evidence，不得重新进入正式 `webui/**` runtime translation owner。

对于 source-proven Alternative WebUI translation gap，emulator 不得伪造 native capability，仍应表现为 bridge route。

Pages 仍禁止每次 deploy 重新 parse 全部 qB 历史。

## 16. Real-qB Locale / release acceptance

日常 Settings/Locale 开发通过 contracts、Virtual qB、browser/candidate representative real-qB acceptance 快速反馈。

最终 release-grade Locale evidence 单独由：

```text
Real qB Current Stable Locale Matrix
-> final dev exact SHA
-> manual workflow_dispatch
-> current admitted stable exact locale set
-> each locale write/read/reload/restore
-> exact-SHA aggregate all PASS
```

当前 operational surface 是 qB 5.2.3 的 61 locales；数量由 exact LKG 派生，不提升为永久常量。

它与 `Real qB Full Frozen Matrix` 互补：Locale Matrix 证明 current-stable 全语言 Settings/handoff 行为；G-FM 证明 Frozen 全版本 real runtime semantics。

Promotion / Release 必须消费同一 final SHA 的 manual Locale + manual G-FM aggregate，并通过 `tests/release-compat-evidence.mjs` fail closed 验证。普通 push skipped Locale run、旧 SHA evidence、Fast G-FM utility 都不能替代正式 release evidence。

Full Frozen Matrix 只在 final SHA 最终验证 / 准备发布时手工执行，不作为日常 Settings/Locale 开发反馈环。

## 17. 变更纪律

语言/翻译 owner 改造必须回答：

```text
persisted locale truth? -> qB preferences.locale
allowed Locale? -> running qB / exact source facts
qB-owned wording? -> native QBT_TR/translator first; exact official-TS bridge only for source-proven gaps
WeiG-only wording? -> W.I18n
bridge existence? -> exact translator behavior/source route only
future/unknown release? -> source-derived + fail closed
```

不要创建 `I18nV2`、第二 locale store、第二 Settings renderer、全版本浏览器翻译数据库或新的长期 bridge owner。

完整发布规则见 `docs/006.发布与晋级流程.md`。
