# Settings 语义与未来兼容

当前 Settings 的 qBittorrent preference 语义由 `W.SettingsSchema` 唯一负责。`W.QBClient` 只负责 `app/preferences` / `app/setPreferences` 的 HTTP 传输，`settings.js` 只负责使用现有 Settings section/grid、canonical Select、Switch 和 Input 渲染；全局与备用上传/下载限速继续由 `W.Transfer` 底部栏唯一负责。

## 与 Virtual qB 的职责边界

本文件只描述 **正式 WeiG 产品 Settings UI/schema 与 forward compatibility**。Virtual qB 后端如何发现、保存、读取并执行 preference behavior，由 [`docs/009.Virtual-qB-Lab.md`](./009.Virtual-qB-Lab.md) 的 Simulator policy 负责。

两者不要合并成第二套 Settings owner：

```text
Real/Virtual app/preferences HTTP transport
→ W.QBClient

Product Settings schema / label / unit / enum / control
→ W.SettingsSchema + W.SettingsRenderer / W.SettingsState

Virtual qB preference storage / MODELED side effect / Scheduler behavior
→ Virtual qB Engine (docs/009)
```

Virtual Lab 中的 `MODELED / STATEFUL / READ_ONLY / UNKNOWN` 是**后端模拟覆盖等级**，不是产品 UI schema 等级。Simulator 可以知道某个 preference key 存在，却不能因此自行发明正式 WeiG 的 label、unit、enum、help 或复杂写回 contract。

## 信息架构

qBittorrent Settings 主入口为 Downloads、Connection、BitTorrent、Web UI、Advanced。Speed 主标签已退休：`dl_limit`、`up_limit`、`alt_dl_limit`、`alt_up_limit` 不再在 Settings 重复呈现；调度、uTP/TCP/LAN 等不属于底部限速面板的传输策略进入 Advanced / Bandwidth。

- Downloads：添加 Torrent、路径与保存、自动管理、文件规则、自动任务。
- Connection：监听、连接限制、Proxy、I2P、IP Filter、网络底层。
- BitTorrent：协议与隐私、Queue、Seeding、Tracker / Announce、Peer / Transport。
- Web UI：服务器/HTTPS、认证、安全、Reverse Proxy、Custom HTTP Headers、Alternative WebUI。
- Advanced：带宽策略、Disk / I/O、libtorrent、RSS、Dynamic DNS、Mail、Logging、System/Security，以及未分类的 upstream preference。

只有当前 qBittorrent 实例实际从 `app/preferences` 返回的 key 才显示。

## Forward compatibility

Preference 解析优先级固定为：exact schema → semantic family rule → Advanced / Upstream fallback。禁止为 qB 5.2/5.3/5.4 各复制一套运行时实现或 exact-version allowlist。

未来未知 boolean/number/string preference 会按实际 JSON 标量类型生成现有 Switch/Number/Text 控件；未知 array/object 必须可见但只读并以结构化 JSON 展示，禁止退化为 `[object Object]`，也禁止在未知 upstream contract 时盲目写回。

新的 WebAPI endpoint 不具备可安全推导完整 UI 的 schema，因此不会由旧客户端猜测参数或自动生成页面。Upstream compatibility audit 负责比较 qB API action surface，并报告新增 surface 供 capability owner 后续映射。

Virtual qB catalog 可以自动发现新的 preference key/getter/setter provenance；这只能帮助验证“upstream 有什么”，不能替代 `W.SettingsSchema` 对产品名称、单位、枚举、帮助文案和复杂交互的正式建模。

## Latest generation audit

`Upstream Compatibility Audit` 每次从 qBittorrent 官方 tags 动态解析最新 `release-5.*.0` generation，并同时保留 4.1.9.1 compatibility floor；若存在前一代 `5.x.0`，同时比较前一代与最新 generation 的 Preference/API surface delta。完整 stable-tag audit 与 representative generation audit 仍是两个不同验证层级。

Catalog quality 对 upstream-derived profile fail closed：缺失/空/重复/非法 `apiActions`、preference descriptor/surface drift、writable preference 缺少可信 setter/write type 等不能被当作有效 catalog 继续传播。

## Visual / responsive contract

Settings 不建立第二套视觉系统。必须复用项目已有 `settings-section`、`settings-grid`、`setting-row`、`field-input setting-input`、`switch-control` 和 `W.Components.selectControl()`；本架构不新增 feature-local CSS、Dialog/Select/Input skin 或 Mobile 专用业务 state。

Desktop/Mobile 共享同一 Settings semantic state；Light/Dark 继续使用现有 Theme token；Reduced Motion 不改变 preference 语义和可见状态。
