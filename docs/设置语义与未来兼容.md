# Settings 语义与未来兼容

当前 Settings 的 qBittorrent Preference 语义由 `W.SettingsSchema` 唯一负责。`W.QBClient` 只负责 `app/preferences` / `app/setPreferences` HTTP 传输；Settings presentation 复用现有 section/grid、canonical Select、Switch 与 Input。

本文同时记录已经复盘确认、**待下一次产品原子切换实施**的 Locale/i18n contract。因为代码尚未完成 owner cutover，`DESIGN.md` 仍是当前运行时 Current Owner authority；本文的“目标”不能被当作已上线行为。

## 1. 与 Virtual qB 的职责边界

本文只描述**正式 WeiG 产品 Settings UI/schema 与 forward compatibility**。Virtual qB 后端如何保存、读取并执行 preference behavior，由 `docs/009.Virtual-qB-Lab.md` 的 simulator policy负责。

```text
Real/Virtual app/preferences HTTP transport
-> W.QBClient

Product Settings schema / routing / editability
-> W.SettingsSchema + W.SettingsRenderer / W.SettingsState

Exact qB Locale + official Settings strings
-> qB upstream source facts -> W.ReleaseProfile -> W.SettingsSchema

WeiG-owned UI translation runtime
-> W.I18n

Virtual qB preference storage / modeled side effect
-> Virtual qB Engine
```

Simulator 可以知道某个 preference key 存在，但不能因此自行发明正式 WeiG 的 label、unit、enum、help 或复杂写回 contract。

## 2. 信息架构

qBittorrent Settings 主 surface：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema
-> semantic family rule
-> canonical surface
-> Advanced / Upstream fallback
```

Desktop/Mobile 共享同一 Settings semantic state，不建立第二套 schema 或业务状态。

## 3. Exact Preference provenance

每个 admitted official stable profile 从 qB upstream getter/setter source 生成 descriptor，包括：

```text
getter/read type/kind/confidence
setter/write type/kind/confidence
getter/setter agreement
writable
enum fallback provenance
```

Setter-only key 不得逃出 `app/preferences` surface。

## 4. Locale 当前问题与目标 Owner

### 当前问题

当前 dev 的语言链仍然是双真值：

```text
qB locale -> SettingsState / app/setPreferences

weigg-language localStorage -> W.I18n
```

这会造成：

- qB Locale 保存成功，但 WeiG 界面不跟随；
- `W.I18n` 仅支持 `en / zh-CN / zh-TW / ja / ko`，其余 qB 官方 Locale 回退 English；
- Settings 自身部分文案仍使用 `zh-CN : English` 二选一；
- current bridge 是 WeiG -> qB 单向同步，不是 shared owner；
- App bootstrap 不读取 `app/preferences`，启动后不能从 qB 恢复语言。

### 目标：一个持久语言真值

待原子切换后，唯一持久语言真值为：

```text
qB app/preferences.locale
```

`W.I18n` 仍是 WeiG-owned translation/render runtime，但不再拥有独立语言 persistence。

Settings 的 qB Locale control 与 WeiG WebUI / Interface Language control 都绑定：

```text
W.SettingsSchema.meta.locale.enum
+ SettingsState.draft.locale
```

它们是同一 preference 的两个 presentation entry point，不是两套状态。

`localStorage['weigg-language']`、自有 `auto` 语言状态、五语言手写 enum 与双向 bridge 都在 cutover 同提交退休。

## 5. 启动与保存数据流

### Bootstrap

为了让刷新/重新登录后 WeiG 自动跟随 qB 已保存 Locale，应用在现有 client detection / ReleaseProfile bind 之后进行一次共享读取：

```text
QBClient.detect()
-> ReleaseProfile / capability ready
-> QBClient.getPreferences() once
-> shared current preference snapshot
-> W.I18n apply prefs.locale
```

不得增加 Locale polling；Settings 打开时应复用该 snapshot，避免同一时点的重复 preferences request。

### Save

```text
shared locale draft
-> SettingsSchema writable check
-> QBClient.setPreferences({locale})
-> QBClient.getPreferences() verification reread
-> returned locale verified
-> update shared snapshot
-> W.I18n apply returned locale
-> rerender shared DOM
```

写入成功但 verification read 失败时，沿用现有“写入完成但无法确认”语义；不能先改变 WeiG UI 再假装 qB 已验证成功。

## 6. qB 5.2.3 Locale coverage baseline

当前 admitted latest qBittorrent **5.2.3** 的官方 WebUI translation resources 对应 **61** 个 Locale code。WeiG-owned translation coverage 以这 61 个为基线：

```text
ar, az@latin, be, bg, bs, ca, cs, da, de, el,
en, en_AU, en_GB, eo, es, et, eu, fa, fi, fr,
gl, he, hi_IN, hr, hu, hy, id, is, it, ja,
ka, kk, ko, lt, ltg, lv_LV, mn_MN, ms_MY, nb, ne_NP,
nl, oc, pl, pt_BR, pt_PT, ro, ru, sk, sl, sq,
sr, sr@latin, sv, th, tr, uk, uz@Latn, vi, zh_CN, zh_HK, zh_TW
```

`tools/data/qb-locale-lkg.json` 保存 4.1.0 -> 5.2.3 的 source-SHA-bound exact Locale sets；它证明不同 stable 的 code/subset 会变化，例如旧版可出现 `zh / ja_JP / ko_KR`，现代版使用 `zh_CN / ja / ko`。

因此：

- 5.2.3：两个语言入口都显示相同 61 个官方 Locale；
- 旧 stable：两个入口都显示该 exact release 实际支持的 subset/code；
- WeiG 自有字典覆盖 5.2.3 的 61 种语言，因此旧 release 的 subset 也有对应显示资源；
- 历史 alias 通过 locale normalization/source fact 解析，不允许在 Settings/App caller 中写 patch-version 分支。

## 7. qB-owned Settings 文案必须来自官方 WebUI

Locale 不仅决定选择器，还决定 qB Settings 的显示文字。

qB-owned Settings title、enum label、官方 tooltip/help 的来源：

```text
exact release src/webui/www/private/views/preferences.html
-> official source strings / translation context / enum values

exact release src/webui/www/translations/webui_<locale>.ts
-> official translated strings

-> generated release source facts
-> ReleaseProfile
-> SettingsSchema presentation metadata
-> renderer
```

规则：

1. qB 5.2.3 显示 5.2.3 官方 Settings 翻译；qB 4.x 显示对应旧 release 的官方文字，不拿最新版强盖历史 UI 语义。
2. 官方某条翻译为空/unfinished 时，回退该 exact release 的官方 English source text。
3. 禁止 `zhHumanize()`、token guessing、机器猜 label 或人工写“像官方”的 qB Settings 翻译。
4. `capabilities.json` 只拥有 capability policy，不存语言和翻译。
5. 当前通用描述 **`qBittorrent preference.` 保持不变**，语言改造不顺手处理它。

## 8. WeiG-owned 文案与 About

qB 官方翻译只能拥有 qB-owned 文案。以下仍属于 WeiG，不能删除：

- WeiG WebUI 自有 Interface settings；
- About / Brand / License / GitHub / Blog identity；
- WeiG 特有的 layout、responsive、selection、feedback、辅助日志/Transfer 等文案；
- 其它没有 qB 官方 source/context 对应的 WeiG feature text。

这些 WeiG-owned key 必须补齐 qB 5.2.3 的 61 Locale coverage。

如果某个 WeiG 显示字符串与 qB 官方 source/context 完全一致，可以复用 qB 官方译文；否则翻译必须明确归属 WeiG，不能标成“qB 官方”。

## 9. i18n runtime 清理纪律

当前实际文件是 `webui/private/scripts/i18n*.js` 平铺文件，而不是 `scripts/i18n/` 目录。

当前 `private/index.html` 会加载：

```text
i18n.js
i18n-time.js
i18n-alternative-webui.js
i18n-interface.js
i18n-transfer.js
```

且 callers 仍使用 `W.RuntimeI18n / W.AlternativeWebUIText / W.InterfaceText / W.TransferText`，所以现状不能直接删。

目标 cutover：

```text
W.I18n
<- 所有仍属 WeiG 的 translation keys

qB official Settings catalog
<- 所有 qB-owned Settings strings

然后删除 sidecar runtime：
i18n-time.js
i18n-alternative-webui.js
i18n-interface.js
i18n-transfer.js
```

同时删除旧 namespace、script tags 与动态注入 bridge；不得留下兼容 alias 长期双活。

优先改造现有 `i18n.js` 成唯一 WeiG translation runtime，不创建 `i18n-v2.js` / `translation-manager.js` 等平行系统。

`settings-translations.js` 只有在 exact official qB Settings catalog 已覆盖正式 caller 后才能与其 hand-authored qB label/humanize 一起原子退休；不能先删除导致 Settings 无文字，也不能把新官方层叠在旧层上长期共存。

## 10. Editability

Exact stable profile 只有同时满足以下条件才可编辑：

```text
write endpoint/action proven
setter exists
write type is understood
getter/setter type does not conflict
descriptor writable == true
```

否则保持 read-only 或 unavailable。

`onDraft` 不接受 non-writable key；保存前 `writableDraft()` 再做 defense-in-depth 过滤。

Locale 同样受这一 contract 约束；不能因为 WeiG UI 需要语言切换而 bypass exact setter provenance。

## 11. Unknown / future Preferences

未来 stable 新 key 不静默丢失：

```text
exact schema if known
-> semantic family rule
-> Advanced / Upstream fallback
```

未知 scalar 可以按实际 JSON 类型展示，但在没有 exact setter provenance 时保持只读。

未知 array/object 必须可见但只读，以结构化 JSON 展示；禁止退化为 `[object Object]`，也禁止在未知 contract 时盲目写回。

不要猜 unit、enum、range、startup default。

## 12. Endpoint / Preference 两层证明

Settings write 不是一个粗粒度 boolean。

```text
app/setPreferences source action proven
AND
Preference descriptor proves setter/type/editability
-> write allowed
```

任一层 unknown/unproven，都不得发送对应 payload。

CapabilityRegistry 不决定 Preference writable；SettingsSchema 也不维护 endpoint historical response policy。

## 13. Source / release validation

发布级 source/product audit 由 `CI` 的 `candidate` 模式完成：

```text
exact stable source catalog
-> exact Locale/source translation extraction
-> all admitted stable source audit
-> full stable PRODUCT compatibility matrix
```

真实 qB runtime 证明由手动 `Real qB Full Frozen Matrix` 完成。

Locale/i18n cutover 后必须额外证明：

```text
5.2.3 locale count = 61
WeiG Language enum == qB Locale enum on 5.2.3
old release enums == exact old-release Locale set
qB Locale save/read round-trip drives WeiG UI after verification
reload restores qB locale with no weigg-language state
qB Settings labels match exact official translation/source
About/WeiG custom catalog has 61/61 coverage
retired sidecar namespaces/files are absent
```

## 14. Visual / responsive contract

Settings 不建立第二套视觉系统。复用现有：

```text
settings-section
settings-grid
setting-row
field-input setting-input
switch-control
W.Components.selectControl()
```

Language/Locale 的 Desktop/Mobile 差异只能是字体、可用宽度、菜单几何等 presentation 差异；选项集合、value、draft、save 和 translation state 必须是同一份。

Light/Dark 使用现有 Theme token；Reduced Motion 不改变 Locale 或 Preference 语义。

## 15. 变更纪律

语言 owner 实施必须作为一个 coherent cutover 回答并满足：

```text
谁是 persisted language truth？ -> qB preferences.locale
谁拥有 allowed Locale？ -> exact qB source / ReleaseProfile / SettingsSchema
谁拥有 qB Settings 翻译？ -> exact qB official WebUI source facts
谁拥有 WeiG-only 翻译？ -> W.I18n
旧 weigg-language / sidecar i18n / bridge 怎么退出？ -> 同提交删除
UNKNOWN / old release 怎么办？ -> exact set + fail closed
```

完整发布规则见 `docs/006.发布与晋级流程.md`。
