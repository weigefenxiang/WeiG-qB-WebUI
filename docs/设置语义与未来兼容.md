# Settings 语义与未来兼容

当前 Settings 的 qBittorrent Preference 语义由 `W.SettingsSchema` 唯一负责。`W.QBClient` 只负责 `app/preferences` / `app/setPreferences` HTTP 传输；Settings presentation 复用现有 section/grid、canonical Select、Switch 与 Input。

> Locale / i18n 单一 owner cutover 已完成设计复盘，但在对应产品代码原子切换前仍属于实施方案，不提前修改 `DESIGN.md` 的 Current Owner 声明。

## 1. 与 Virtual qB 的职责边界

本文只描述**正式 WeiG 产品 Settings UI/schema 与 forward compatibility**。Virtual qB 后端如何保存、读取并执行 preference behavior，由 `docs/009.Virtual-qB-Lab.md` 的 simulator policy 负责。

```text
Real/Virtual app/preferences HTTP transport
-> W.QBClient

Product Settings schema / key / type / unit / enum / control
-> W.SettingsSchema + W.SettingsRenderer / W.SettingsState

Product presentation locale
-> qB preferences.locale authoritative value
-> W.I18n presentation API

Virtual qB preference storage / modeled side effect
-> Virtual qB Engine
```

Simulator 可以知道某个 preference key 存在，但不能因此自行发明正式 WeiG 的 label、unit、enum、help 或复杂写回 contract。

## 2. 信息架构

qBittorrent Settings 主 surface：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema
-> semantic family rule
-> canonical surface
-> Advanced / Upstream fallback
```

Desktop/Mobile 共享同一 Settings semantic state，不建立第二套 schema、业务状态或 locale 状态。

## 3. Exact Preference provenance

每个 admitted official stable profile 从 qB upstream getter/setter source 生成 descriptor，包括：

```text
getter/read type/kind/confidence
setter/write type/kind/confidence
getter/setter agreement
writable
enum fallback provenance
```

Setter-only key 不得逃出 `app/preferences` surface。

## 4. Locale 单一 owner cutover

### 4.1 当前问题

当前代码把 WeiG Language 和 qB `preferences.locale` 分成两套状态。WeiG Language 保存后会通过语言事件再尝试同步 qB；反过来在 qB Settings 修改 `Locale` 时，`saveQb()` 只执行 qB write + verification reread，不会把回读后的 Locale 应用到 `W.I18n`。

结果是：**Locale 保存成功后，Settings/WebUI 仍可保持英文或原 WeiG 语言。**

禁止通过新增“qB -> WeiG”监听器与现有“WeiG -> qB”监听器并存来解决；那会形成双 owner / 双向写回风险。

### 4.2 目标 owner

下一次产品改动后，唯一持久 owner 为：

```text
qBittorrent preferences.locale
```

目标数据流：

```text
initial app/preferences.locale
              |
              v
      SettingsState.prefs.locale
              |
              v
          W.I18n locale
              |
       +------+------+
       |             |
WeiG Interface    qB Settings / About / rest of UI
Language view
```

`WeiG WebUI -> Interface -> Language` 不再有独立 `weigg-language` localStorage，也不再写 `weiggDraft.language`。它只是 `preferences.locale` 的第二个 UI 入口，与 Advanced/Locale 使用同一个 `draft.locale`、同一组选项、同一 writable provenance、同一次 save。

保存成功必须按此顺序：

```text
setPreferences({locale})
-> getPreferences() verification reread
-> accept verified locale
-> W.I18n apply locale
-> repaint current shared DOM
```

不得在 verification 前先切 WeiG UI；也不得因 UI 切换再发第二次 `setPreferences()`。

### 4.3 Locale 选项与版本差异

实际 qB Locale control 的 options 仍以**当前 exact qB release** 为准：

```text
real qB runtime
-> qB WebApplication ${LANGUAGE_OPTIONS}

Virtual / historical qB
-> ReleaseProfile.webuiLocales
-> source-SHA-bound frozen locale source facts
```

`capabilities.json` 继续只描述 capability，不保存翻译表或语言版本表。

WeiG 的 translation coverage 使用最新 admitted stable **qB 5.2.3** 的完整 WebUI locale superset：**61 locales**。因此连接 5.2.3 时，WeiG Language 和 qB Locale 两个入口都必须出现相同的 61 个选项；连接旧 qB 时，两个入口共同收窄到该 release 实际支持的 Locale 集合。

5.2.3 source-derived locale codes：

```text
ar, az@latin, be, bg, bs, ca, cs, da, de, el,
en, en_AU, en_GB, eo, es, et, eu, fa, fi, fr,
gl, he, hi_IN, hr, hu, hy, id, is, it, ja,
ka, kk, ko, lt, ltg, lv_LV, mn_MN, ms_MY, nb, ne_NP,
nl, oc, pl, pt_BR, pt_PT, ro, ru, sk, sl, sq,
sr, sr@latin, sv, th, tr, uk, uz@Latn, vi, zh_CN, zh_HK, zh_TW
```

历史 release 中同一语言使用不同 code 时（如 `de_DE -> de`、`ja_JP -> ja`、`zh -> zh_CN`），由 locale identity / language-script-region normalization 处理；不允许用 qB 版本号分支硬编码迁移。

## 5. 翻译 source policy

### 5.1 qB-owned strings

能对应 qBittorrent 官方 WebUI 的 Settings/通用文案，必须从 **qB 5.2.3 官方 `webui_*.ts` / official WebUI source** 生成或提取，不能自行翻译，也不能维护另一份手写 61-language qB 字典。

qB 运行时会从自身 WebUI translation resources 生成 `${LANGUAGE_OPTIONS}`，这可以作为真实实例的 Locale code / language-name source truth。

但是 Alternate WebUI 下，qB WebApplication 的 translation file path 会切到 Alternate WebUI root 的 `translations/webui_<locale>`；因此不能假设系统内置 qB `.qm` 会自动翻译 WeiG 自定义字符串。需要的 qB-owned translation facts 应在构建/生成阶段从官方 5.2.3 source 提取并随 WeiG 产品提供。

### 5.2 WeiG-owned strings

以下仍属于 WeiG 自有 presentation，不能因为清理旧翻译层而删除：

```text
WeiG WebUI interface-only settings
WeiG-specific actions/diagnostics/help
About / brand / build metadata labels
```

这些内容保留一个最小 WeiG-owned translation namespace，并补齐同一 61-locale coverage。缺译必须在 contract 中暴露，不通过 silent handcrafted qB text 或第二套 fallback owner 掩盖。

当前通用描述 **`qBittorrent preference.`** 按已确认范围保持不变，不纳入这次清理。

## 6. i18n 旧层清理纪律

当前源码中不存在 `private/scripts/i18n/` 子目录；实际是 `private/scripts/i18n*.js` 多文件层。下一次产品实现必须完整 audit caller 后原子切换，不保留旧层当 compatibility wrapper。

目标清理：

```text
i18n-interface.js
-> qb-locale-bridge 显式进入 canonical script order
-> 迁移实际 caller
-> 删除

i18n-time.js
-> RuntimeI18n caller（Logs 等）迁到 W.I18n
-> 删除

i18n-transfer.js
-> 若完整 tree audit 仍无 caller，删除

i18n-alternative-webui.js
-> 若完整 tree audit 仍无 caller，删除

i18n.js
-> 保留统一 W.I18n API
-> 删除 weigg-language persistent owner
-> 删除固定 ['en','zh-CN','zh-TW','ja','ko'] supported 表
-> 改为 5.2.3 61-locale coverage + exact current-qB option projection
```

同时清除 `settings.js` 的 `text(en, cn)`、`transfer.js` 的 `label(en, cn)` 等只支持 EN/ZH 的动态 presentation 分支。静态 `data-i18n` 和动态 JS 字符串必须消费同一 canonical i18n owner。

## 7. Editability

Exact stable profile 只有同时满足以下条件才可编辑：

```text
write endpoint/action proven
setter exists
write type is understood
getter/setter type does not conflict
descriptor writable == true
```

否则保持 read-only 或 unavailable。

`onDraft` 不接受 non-writable key；保存前 `writableDraft()` 再做 defense-in-depth 过滤。

Locale 也不例外。没有 exact safe setter provenance 时，WeiG Language 的镜像入口同样必须 read-only；不能绕过 `SettingsSchema` 直接写 qB。

## 8. Unknown / future Preferences

未来 stable 新 key 不静默丢失：

```text
exact schema if known
-> semantic family rule
-> Advanced / Upstream fallback
```

未知 scalar 可以按实际 JSON 类型展示，但在没有 exact setter provenance 时保持只读。

未知 array/object 必须可见但只读，以结构化 JSON 展示；禁止退化为 `[object Object]`，也禁止在未知 contract 时盲目写回。

不要猜 unit、enum、range、startup default。

## 9. Endpoint / Preference 两层证明

Settings write 不是一个粗粒度 boolean。

```text
app/setPreferences source action proven
AND
Preference descriptor proves setter/type/editability
-> write allowed
```

任一层 unknown/unproven，都不得发送对应 payload。

CapabilityRegistry 不决定 Preference writable；SettingsSchema 也不维护 endpoint historical response policy。

## 10. 保存流程

普通 Preference：

```text
user interaction
-> canonical control
-> SettingsState.draft
-> writableDraft()
-> validateBeforeSave()
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> canonical feedback
```

Locale verification 成功后再把回读 locale 应用到唯一 `W.I18n` presentation state。写成功但 verification read 失败时，必须明确显示“写入完成但无法确认”，不能伪装成完整验证成功，也不能提前切换界面语言。

## 11. Source / release validation

仓库不再使用独立 `Upstream Compatibility Audit` workflow。

发布级 source/product audit 由 `CI` 的 `candidate` 模式完成：

```text
exact stable source catalog
-> source-derived locale facts
-> all admitted stable source audit
-> full stable PRODUCT compatibility matrix
```

真实 qB runtime 证明由手动 `Real qB Full Frozen Matrix` 完成。

因此 Settings/Locale 改动应同时保证：

```text
source descriptor correct
exact release locale set correct
product schema/owner correct
candidate product matrix correct
real-qB behavior correct when release evidence is rebuilt
```

## 12. Catalog quality

Upstream-derived profile 必须 fail closed：

```text
missing/empty/duplicate/invalid apiActions
Preference descriptor drift
Locale source-fact/source-SHA mismatch
surface drift
writable Preference without trustworthy setter/write type
```

这些情况不能被当作有效 catalog 继续传播。

## 13. Visual / responsive contract

Settings 不建立第二套视觉系统。复用：

```text
settings-section
settings-grid
setting-row
field-input setting-input
switch-control
W.Components.selectControl()
```

Light/Dark、Desktop/Mobile 和字体大小只改变 presentation，不改变 active Locale、Locale options、draft 或保存语义。

## 14. Locale acceptance contract

产品 cutover 至少验证：

```text
Locale save + verification -> current WeiG UI immediately changes language
WeiG Language and Advanced Locale show the same exact options/value/draft
qB 5.2.3 exact set contains 61 options
all 61 locales have required qB-derived and WeiG/About text coverage
old locale codes normalize without qB-version branching
no weigg-language localStorage owner
no fixed five-language supported list
no reverse languagechange -> qB duplicate write
no superseded i18n owner/wrapper remains
qBittorrent preference. remains unchanged
Desktop/Mobile use the same locale state
```

## 15. 变更纪律

Locale/i18n 产品 cutover 必须和 callers、contracts、script loading、`DESIGN.md` Current Owner 更新一起原子完成：

```text
new canonical locale flow
+ migrated callers
+ source-derived 5.2.3 translations
+ WeiG/About 61-locale coverage
+ tests
+ remove superseded i18n files/state
+ DESIGN owner update
```

不能先加新翻译 runtime，再把旧 `W.I18n` / RuntimeI18n / InterfaceText 留着慢慢迁移。

完整发布规则见 `docs/006.发布与晋级流程.md`。
