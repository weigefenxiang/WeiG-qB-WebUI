# 004. UI 与缓存契约

版本：0.3.5

## 1. 目标

本文件定义两个必须长期稳定的工程契约：

1. 同一种 UI 语义只能有一个 canonical component，不允许功能版本文件重新发明 Card / Grid / Modal。
2. HTML 是 no-store 启动入口；CSS/JS 的资源身份由部署 Git SHA 决定，不再由人工维护的产品版本 query 决定。

### 2.1 Settings 强规则

所有 Settings 卡片必须满足：

```text
Title
Description
Control / readonly value
```

桌面普通宽度使用两列；宽屏使用三张卡的视觉列；移动端使用一列。卡片的边框、圆角、阴影、hover、focus、输入框与开关全部复用现有 Token/Component。

禁止：

```text
feature-x__head
feature-x__control
feature-x__meta-grid
feature-x__info-card
```

如果这些结构只是重复 SettingCard 的视觉职责，应删除并回到 canonical component。

### 2.2 Alternative WebUI

`alternative_webui_enabled` 与 `alternative_webui_path` 仍由专用兼容/安全逻辑负责保存，因为关闭 Alternative WebUI 与修改 Root Folder 都可能让当前页面失效；但视觉层必须使用 `W.Components.preferenceField()`。

安装器元信息使用 `W.Components.readonlySettingField()`，因此 Host path、VERSION、Git SHA、Container、Installed At 与普通设置卡共享同一布局。

## 3. Cache Contract

### CACHE-001 — HTML no-store

`private/index.html` 与 `public/login.html` 必须声明：

```text
Cache-Control: no-store, no-cache, must-revalidate
Pragma: no-cache
Expires: 0
```

这些 meta 是浏览器侧防御；生产环境仍必须确认 qBittorrent/反代/CDN 的最终 HTTP Header 没有把 HTML 改成可缓存响应。

### CACHE-002 — 一个 Build SHA

部署后的 HTML 必须包含：

```html
<meta name="weigg-build-sha" content="<git-sha>">
```

其中 `<git-sha>` 为部署源码的 40 位 Git commit SHA。

### CACHE-003 — 所有本地 CSS/JS 使用 Git SHA

```text
css/app.css?v=<git-sha>
scripts/app.js?v=<git-sha>
```

禁止重新引入：

```text
?v=0.3.5
?v=0.3.6
```

产品版本与资源身份是两个不同概念。

### CACHE-004 — Lazy runtime 使用同一 SHA

`components.js` 中的动态 CSS/JS loader 必须通过 `buildAssetUrl()` 读取 `weigg-build-sha`，不能自己维护第二份版本号。

### CACHE-005 — 部署身份

安装后的目录必须包含：

```text
VERSION
GIT_SHA
private/weigg-install.json
```

`weigg-install.json` 至少包含：

```json
{
  "version": "0.3.5",
  "gitSha": "<40-char SHA>",
  "qbPath": "/config/weigg-qb-webui",
  "hostPath": "/host/.../weigg-qb-webui"
}
```

### CACHE-006 — Release 与 main

- GitHub Release 打包时使用 `${GITHUB_SHA}` 固化资源身份。
- main 安装器通过 GitHub commits API 解析当前 main SHA，再注入下载的 main payload。
- Release 缺少有效 `GIT_SHA` 时拒绝部署，避免给旧代码伪造一个新 SHA。

## 4. 自动测试

`tests/cache-contract-v035.mjs` 检查：

- HTML no-store meta；
- HTML build SHA meta；
- 本地 CSS/JS 不存在 semver query；
- direct assets 都使用 `__WEIGG_GIT_SHA__` source placeholder；
- lazy assets 使用 `buildAssetUrl()`；
- Linux/Windows installer 与 Release workflow 均有 SHA 注入契约；
- 两个不同 SHA 注入后产生不同资源 URL。

`tests/browser-settings-v034.mjs` 从 v0.3.5 起同时承担 UI primitive gate：

```text
qB 4.1.9.1
qB 4.6.7
qB 5.2.0
×
390×844
1366×768
1920×1080
```

检查 Alternative WebUI 卡片必须使用 canonical `setting-card/settings-row`，不能出现旧 `alt-webui-v034__*` 视觉类，也不能出现横向 overflow。

## 5. 线上验收

两个实际站点部署后都应检查：

```sh
cat /host/config/weigg-qb-webui/VERSION
cat /host/config/weigg-qb-webui/GIT_SHA
cat /host/config/weigg-qb-webui/private/weigg-install.json
```

并检查最终 HTML Header：

```sh
curl -I https://qb.weigshare.com/
curl -I https://q.weigshare.com/
```

HTML 应保持 no-store。CSS/JS 可以缓存，因为 URL 已由 Git SHA 唯一标识。

## 6. 结论

v0.3.5 的规则不是“Alternative WebUI 看起来像其它卡片”，而是更严格的结构约束：**Settings 只有一种卡片系统；HTML 只有一种启动缓存策略；本地资源只有一种版本身份来源。**
