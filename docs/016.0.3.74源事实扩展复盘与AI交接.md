## 3. 本轮已经完成什么

### 3.1 Native Torrent table column source facts

`tools/qb-torrent-fields-parser.mjs` 新增 `extractTorrentTableColumns()`，从 exact qB upstream：

```text
src/webui/www/private/scripts/dynamicTable.js
```

直接提取 TorrentsTable 的：

```text
key
caption
defaultWidth
defaultVisible
QBT_TR source/context（存在时）
dataProperties
```

同时兼容：

```text
旧 qB: const TorrentsTable = new Class({ initColumns:function(){...} })
新 qB: class TorrentsTable extends DynamicTable { initColumns(){...} }
```

解析不到 TorrentsTable / initColumns / native columns 时 fail closed。

`tools/qb-release-catalog-shard.mjs` 已开始把 `torrentTableColumns` 放入 raw exact-release source profile。目标是让 qB 自己的列菜单/defaultVisible/defaultWidth/source caption 成为 source truth，而不是在 WeiG runtime 手维护一份“看起来像 qB”的列清单。

### 3.2 qB-owned UI ref 扩展

`tools/qb-owned-ui-source.mjs` 现在可以在收到 `dynamicTableSource` 时复用同一个 Torrent column parser，生成：

```text
column.<key> -> exact QBT_TR source/context
state.<state> -> exact TransferListDelegate source/context
filter.moving -> 若 sidebar 没有 moving_filter，则复用 exact Moving state ref
```

不要再新增第二个 `qb-torrent-columns-source.mjs` owner。native column source extraction 已归入现有 `qb-torrent-fields-parser.mjs`。

### 3.3 Settings label source relation 更完整

`tools/qb-settings-translation-source.mjs` 除了原有：

```text
<label for=...>
aria-labelledby
```

现在还支持：

```text
同一 <tr> 内只有一个 official QBT_TR label
+ preference 的真实 value control 位于该 row
-> 可把该 official label 作为 source-proven title
```

前提必须是**唯一 label**。同一 row 多个不同 QBT_TR ref 时不能猜，必须保持 unresolved/fail closed。

### 3.4 Parser 事故复盘

早期 native-column parser 曾使用过宽的 lazy regex，可能让 `dataProperties` 匹配跨越相邻 JS statement，造成一个 column 吞到另一个 column 的 key/value。

已修正为 quote-bounded 解析，并用 qB4/qB5 synthetic TorrentsTable contract 覆盖。后续不要恢复 `.*?` 跨 statement 抓 quoted ID 的做法。

## 4. 总方案：下一阶段要完成的链路

最终目标不是只“能提取 columns”，而是让 source facts 真正走到正式 runtime，同时保持 translation payload 与 Frozen LKG 的架构边界。

目标链：

```text
exact qB source
  -> raw release shard: torrentTableColumns
  -> locale/source enrichment: qB-owned column/state refs + official TS
  -> deterministic merged source evidence
  -> Settings/source LKG v2 freezes:
       exact per-release torrentTableColumns
       small exact Settings/qB-owned bridge data
       one full official recovery-QM union
  -> apply LKG to Frozen release catalog
  -> runtime exact profile keeps torrentTableColumns
  -> W.TorrentFieldRegistry consumes exact native columns
  -> W.I18n.qbText('column.<key>', sourceCaption)
  -> Columns / DataGrid / Mobile field presentation
```

完整 official recovery-QM 必须只作为 qB native translator 恢复资产进入：

```text
translations/webui_<locale>.qm
```

不能把完整 recovery translations 塞进 browser release profile JSON 或把 `qb-settings/<sourceSha>.json` 重新膨胀成全版本翻译数据库。

## 5. 尚未完成：不要误报为已落地

以下代码/架构**尚未进入当前 dev**：

### 5.1 Deterministic full recovery-QM union

需要新增/接入一个 canonical recovery owner，完成：

```text
每 exact release / locale 收集 official TS votes
-> 跨并行 shard 合并
-> winner = highest occurrence count
          -> tie: newest exact qB release
          -> tie: lexical translation
-> materialize one deterministic locale recovery union
```

原因：source extraction 是并行 shard；“哪个 shard 先到就用哪个 set”是 order-dependent，不能作为发布事实。

### 5.2 Settings/source LKG schema v2

当前正式 `tools/qb-settings-translation-lkg.mjs` 仍是 schema v1。下一阶段应升级为 v2，并同时冻结：

```text
exact profile Settings UI refs
qB-owned UI refs
exact torrentTableColumns
small exact official-TS bridge sets
full native recovery-QM route + payload union
```

关键点：`torrentTableColumns` 不能只存在于临时 source-enriched catalog。实际 Pages/product build 常走 `Frozen catalog + Settings/source LKG`；如果不冻结，source evidence 跑完后 columns 会在 packaging 前丢失。

### 5.3 Source overlay / parallel merge 全链闭合

升级 LKG 前必须同步修改：

```text
tools/qb-settings-translation-overlay.mjs
tools/qb-locale-source.mjs
tools/qb-release-catalog-shard-merge.mjs
```

使它们传递 `dynamicTableSource`、完整 official TS recovery vote evidence，并在 merge 时调用同一个 deterministic recovery owner。

禁止只改 LKG consumer 而不改 producer/merge；否则 65-release pipeline 会因缺少 recovery evidence 直接失败。

### 5.4 Native bundle / packer

随后更新：

```text
tools/qb-settings-native-bundle.mjs
tools/qb-webui-catalog.mjs
```

规则：

```text
native/bridge eligibility 仍按 exact profile + translator-family evidence 判断
browser compatibility shard 保持小而 exact
full recovery QM 只打包到 translations/
runtime profile保留 torrentTableColumns
build-only Settings/translation/recovery payload从 browser profile剥离
```

`4.5.0 -> 4.6.4` Alternative WebUI translation gap 仍必须走 exact official-TS bridge；不能因为 recovery QM 更完整就错误改成 native。

### 5.5 Formal runtime column cutover

最后才修改 `webui/**`，让 `W.TorrentFieldRegistry` 正式消费 exact `torrentTableColumns`：

```text
native source columns define available column menu/default order
known fields reuse canonical formatters
unknown/future native fields use bounded generic formatter
column label -> W.I18n.qbText('column.<key>', source caption)
saved old WeiG aliases migrate safely
saved-but-currently-unavailable preference不得破坏性删除
```

Columns dialog可以增加 drag/drop reorder，但不能创造第二 DataGrid owner；箭头 fallback 可保留。

这一步一旦修改正式 `webui/**`，才形成新的 Product VERSION；届时按规则做一次 deliberate patch bump（预期下一版本为 0.3.75），并一次性同步 root `VERSION`、`webui/VERSION`、`package.json`、`package-lock.json`。不要提前 bump，也不要只改一个 version source。

### 5.6 Tracker raw URL

Torrent Details 的 Tracker display/edit 仍应复核：编辑时必须保留 qB 返回的 exact raw URL。`normalizeTracker()` 可以用于 facet/label 语义，但不能在编辑 owner 中先丢掉 path/query 后再提交 edit。
