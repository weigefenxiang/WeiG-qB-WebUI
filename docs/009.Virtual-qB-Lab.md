# 009. Virtual qB Lab

> Virtual qB Lab 是 WeiG qB WebUI 的非产品后端模拟器与 GitHub Pages 验收环境。它模拟 qB WebAPI，不替换产品 `W.QBClient`、不建立第二份产品业务 state。

Status: **current Virtual Lab architecture + Current Endpoint Contract + Current Transport Contract + completed Phase C WebAPI evolution ledger + active Phase D backlog remediation**

## 1. 目标

Virtual qB Lab 用于：

- 在真实浏览器中验证 formal `webui/**`；
- 覆盖 qBittorrent **4.1.0 -> 最新官方 stable** 的 WebAPI v2 主线；
- 对每个 stable release 使用 upstream source-derived Preference / API / Torrent structural facts；
- 提供 deterministic Torrent/peer/network/disk world；
- 将 Pages LIVE evidence 绑定 exact source SHA；
- 系统验证同一个 WebAPI endpoint 在不同 revision 中的 observable semantic evolution；
- 对 WebAPI/qB patch 的 HTTP transport evolution 建立独立、可审计的 Current Owner。

qB 4.0.x 属于上一代 WebAPI v1，不属于当前主线。未来如支持，必须通过独立 Legacy WebAPI v1 Adapter 接入 canonical semantics；禁止在 v2 router 中保留 silent v1 fallback。

## 3. Stable release catalog — Current Owner

`tools/qb-release-catalog.mjs` 对 numeric official stable tags 逐个读取源码并生成 profile：

```text

```

起点固定 `release-4.1.0`；Alpha/Beta/RC/master 不进入正式 stable matrix。Latest stable 与 profile 数量动态发现，不硬编码到 runtime。

当前完整验证覆盖：

```text

65 official stable profiles
5.2.3 -> WebAPI 2.15.1
```

Upstream master 可以领先于 stable，因此 master 新 revision 不会自动扩张正式 semantic ceiling。

## 5. Runtime boundary

```text
formal W.QBClient
-> Native Service Worker / transport adapter
-> Transport Contract
-> structural upstream gate
-> protocol router + Endpoint Contract
-> QBSimulatorEngine / Scheduler / Policy / services

```

禁止：

- monkey-patch `W.QBClient`；
- 在 Pages 建第二份产品 state；
- fixture DOM 伪装真实 UI transition；
- presentation 直接轮询 simulator state；
- new/old protocol owner 长期双活；
- transport 版本策略散落在 Service Worker/router/core；
- endpoint semantic 版本策略重新散落到 caller。

### `transport-contract.js`

Current Owner 已覆盖：

```text
WebAPI 2.15.0 Basic Auth acceptance
qB 5.2.2 X-Forwarded-Host trust only with reverse-proxy support enabled
```

第二条是 qB patch-level supplement：qB 5.2.0/5.2.1/5.2.2 都是 WebAPI 2.15.1，所以不能用 WebAPI revision 冒充 patch boundary。

Ledger 的 `CONTRACT_COVERED` 默认 owner 仍可为 Endpoint Contract，但 transport change 可以显式指定 `simulator/protocol/transport-contract.js`。

### `router.js / auxiliary-router.js`

负责 request parse、route dispatch、core invocation、Response construction。对 canonical contract 已接管的事实，只消费 resolved contract，不再保存 historical policy。

### simulator core

负责 deterministic domain mutation/state projection，不感知 UI owner。若 endpoint projection 需要 semantic contract，router 显式传入；core 不建立“缺 contract 就自己按版本猜”的第二 owner。

## 7. Endpoint Contract interface

公共接口保持窄：

```text
resolveEndpointContract(profile, path)
```

可返回例如：

```text
hashSelection = single | multi-or-all
missingResourceStatus = 404 | 409
noOp = success | conflict
trackerTimingFields = true | false
trackerStatusMode = legacy | extended
parseMetadataResponseShape = object | ordered-array
addResponseMode = legacy-text | structured
useSubcategoriesField = true | false
peerHostNameField = true | false
requiredParameters = [...]
```

它只返回 semantic facts，不执行 route dispatch、实际 mutation、Preference schema、UI capability 或 Torrent filter taxonomy。

接口允许未来把内部 audited table 升级成 generated semantic catalog/source parser，而 caller 不改变。

## 14. Preference fidelity — 独立 Current Owner

## 15. Torrent fidelity — 独立 Current Owner
