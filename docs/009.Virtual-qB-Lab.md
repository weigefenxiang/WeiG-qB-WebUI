# 009. Virtual qB Lab

> Virtual qB Lab 是 WeiG qB WebUI 的非产品后端模拟器与 GitHub Pages 验收环境。它模拟 qB WebAPI，不替换产品 `W.QBClient`、不建立第二份产品业务 state。

Status: **current Virtual Lab architecture + current Endpoint Contract owner + completed Phase C WebAPI evolution ledger + active Phase D backlog remediation**

## 1. 目标

Virtual qB Lab 用于：

- 在真实浏览器中验证 formal `webui/**`；
- 覆盖 qBittorrent **4.1.0 -> 最新官方 stable** 的 WebAPI v2 主线；
- 对每个 stable release 使用 upstream source-derived Preference / API / Torrent structural facts；
- 提供 deterministic Torrent/peer/network/disk world；
- 将 Pages LIVE evidence 绑定 exact source SHA；
- 系统验证同一个 WebAPI endpoint 在不同 revision 中的 observable semantic evolution。

qB 4.0.x 属于上一代 WebAPI v1，不属于当前主线。未来如支持，必须通过独立 Legacy WebAPI v1 Adapter 接入 canonical semantics；禁止在 v2 router 中保留 silent v1 fallback。

## 2. Compatibility truth hierarchy

Virtual Lab 必须把兼容 truth 分成两层。

### 2.1 Structural truth — Current Owner

回答“有没有”：

```text

Preference getter/setter exists?
Torrent filter exists?

```

来源：

```text

-> source parsers
-> qb-release-catalog.mjs
-> qb-releases.json
-> ReleaseProfile
```

Exact supported-stable source facts 优先于 version heuristic。

### 2.2 Semantic evolution truth — Current Owner

回答“同一个 endpoint 在这个 WebAPI revision 怎么表现”：

- required/renamed parameter；
- selector syntax；
- request type；
- response field/shape；
- HTTP status；
- no-op behavior；
- mutation semantics；
- conditional projection。

Current Owner：

```text
simulator/protocol/endpoint-contracts.js
resolveEndpointContract(profile, path)
```

B1 已完成 dormant interface + direct isolated contracts；B2 已完成第一批 atomic runtime cutover；Phase C 已建立完整 evolution chronology/classification ledger；Phase D 按 ledger 的 `MISSING` 项逐批补齐 runtime fidelity。已迁移的 semantic facts 不再由 router/core caller 自行保存历史版本判断。

## 3. Stable release catalog — Current Owner

`tools/qb-release-catalog.mjs` 对 numeric official stable tags 逐个读取源码并生成 profile：

```text
qbVersion
webApiVersion
tag
sourceSha
preferenceKeys / preferenceDescriptors
apiActions
torrentFilters
torrentInfoParameters
```

起点固定 `release-4.1.0`；Alpha/Beta/RC/master 不进入正式 stable matrix。Latest stable 与 profile 数量动态发现，不硬编码。

当前已验证 stable 基线覆盖 qB 4.1.0 -> 5.2.3；5.2.3 使用 WebAPI 2.15.1。Upstream master 可以领先于 stable，因此 master 新 revision 不会自动扩张正式语义 ceiling。

## 4. Source parsers — Current Owners

- `qb-source-parsers.mjs`：Preferences getter/setter；
- Preference semantic enrichment：getter/setter type/provenance；
- `qb-torrent-surface-parsers.mjs`：Torrent filters + `torrents/info` params；
- `qb-release-catalog.mjs`：stable profile assembly；
- catalog quality/evolution contracts：source evidence/shape consistency。

Parser 无法隔离关键 source surface 时 fail closed，不输出“猜到”的 exact capability。

## 5. Runtime boundary

```text
formal W.QBClient
-> Native Service Worker
-> protocol router
-> QBSimulatorEngine / Scheduler / Policy / services
-> canonical IndexedDB world
```

禁止：

- monkey-patch `W.QBClient`；
- 在 Pages 建第二份产品 state；
- fixture DOM 伪装真实 UI transition；
- presentation 直接轮询 simulator state；
- new/old protocol owner 长期双活。

## 6. Current protocol responsibilities

### `upstream-gates.js`

只负责 structural endpoint existence：

```text
apiActions contains actionRef?
```

它与 Endpoint Contract 是职责正交关系，**不会因 Endpoint Contract 上线而删除**。

### `endpoint-contracts.js`

负责已审计的 endpoint semantic evolution facts。Current Owner 已覆盖的第一批路径包括：

```text
torrents/addTrackers
torrents/removeTrackers
torrents/trackers
torrents/properties
sync/maindata
torrents/editCategory
torrents/editTracker
```

Unknown/unclassified semantic revision fail closed；caller 不得自行“版本更高就沿用最后一个行为”。

Phase D 扩展某一条已有 contract 时，必须补全完整 lifecycle，而不是只记录“删除点”或“最新状态”。例如 `sync/maindata.use_subcategories` 的 contract 同时记录 2.9.2 introduction 与 2.15.0 removal；projection value 来自 canonical Preference state，不允许硬编码。

### `router.js / auxiliary-router.js`

负责 request parse、route dispatch、core invocation、Response construction。对已经由 Endpoint Contract 接管的事实，router/core caller 只消费 contract，不再保存对应 historical version policy。

### simulator core

负责 deterministic domain mutation/state projection，不感知 UI owner。若 endpoint projection 需要 semantic contract，router 显式传入；core 不建立“缺 contract 就自己按版本猜”的第二 owner。

## 7. Endpoint Contract interface

公共接口保持窄：

```text
resolveEndpointContract(profile, path)
```

可返回例如：

```text
hashSelection = single | multi-or-all
missingResourceStatus = 404 | 409
noOp = success | conflict
trackerTimingFields = true | false
useSubcategoriesField = true | false
useSubcategoriesPreference = use_subcategories
requiredParameters = [...]
```

它只返回 semantic facts，不执行：

- route dispatch；
- `split('|')` 等具体 request work；
- torrent/category/tracker mutation；
- HTTP `Response` 构造；
- Preference schema；
- UI capability；
- Torrent status taxonomy。

第一代内部是 audited canonical table。接口允许未来替换成 generated semantic catalog/source parser，而 caller 不改变。

## 11. Phase D — MISSING backlog remediation

Phase D 只消费 Phase C 已证明的 `MISSING`，每批保持小而原子：

```text
upstream evidence
-> owner classification
-> one canonical implementation
-> direct contract tests
-> ledger MISSING -> SOURCE_DERIVED / CONTRACT_COVERED / NOT_APPLICABLE
-> exact-SHA CI + Upstream + Pages
```

第一批处理 `sync/maindata.server_state.use_subcategories` 完整生命周期：

- qB 4.5.x / WebAPI 2.8.19 及以前：字段不存在；
- qB 4.6.0 / WebAPI 2.9.2：Preference `use_subcategories` 与 sync 字段出现；
- 2.9.2 <= WebAPI < 2.15.0：sync 字段值镜像 canonical Preference state；
- WebAPI 2.15.0 起：sync 字段删除，subcategories 变为 always enabled。

Ownership 保持分离：`app/preferences.use_subcategories` getter/setter/surface 仍由 source-derived Preference pipeline 拥有；Endpoint Contract 只拥有 `sync/maindata` 的 conditional projection lifecycle。

剩余 backlog 必须继续显式保留为 `MISSING`，不能因为相邻版本已有 contract 就自动继承。

## 13. Preference fidelity — 独立 Current Owner

每个 profile 的 `app/preferences` surface 由 upstream descriptor catalog 驱动。Virtual runtime 保持 value/type fidelity；modelled Preferences 真正影响 simulator behavior。

产品 Settings writable truth 仍归 `W.SettingsSchema + W.ReleaseProfile`。Endpoint Contract 不复制 Preference getter/setter/type/editability；只可引用 preference state 处理真正 conditional endpoint projection。

## 14. Torrent fidelity — 独立 Current Owner

Simulator Torrent query 消费 exact `torrentFilters/torrentInfoParameters`：

- qB4 source `paused/resumed`；
- qB5 source `stopped/running`；
- unsupported filter fail closed；
- Private query 只有 exact profile 含 `private` 时生效；
- selection/pagination/sort/BadParams 由 current contracts 保护。

Endpoint Contract 不重新定义 Torrent status/filter taxonomy。
