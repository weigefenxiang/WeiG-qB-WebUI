# WeiG Virtual qB Lab

> 状态：**已进入持续实现与线上验收阶段。GitHub Pages、每周 stable 发现、dev/main exact snapshot、Service Worker + IndexedDB、5000 Torrent 世界与主要 qB WebAPI 模拟能力均已上线。**
>
> Pages：`https://weigefenxiang.github.io/WeiG-qB-WebUI/`
>
> 目标：在 **不修改 `webui/**` 产品源码** 的前提下，为 GitHub Pages 提供一个尽可能接近真实 qBittorrent 的浏览器内虚拟服务端，使原始 WeiG WebUI 通过原始 `W.QBClient` 直接连接并操作它。

---

## 1. 项目定位

WeiG Virtual qB Lab 不是截图 Demo，也不是固定 JSON fixture，而是一台运行在浏览器中的 **Virtual qBittorrent daemon**。

```text
Real deployment:
WeiG WebUI -> W.QBClient -> qBittorrent WebAPI

Virtual Lab:
WeiG WebUI -> W.QBClient -> Native Service Worker -> QBSimulatorEngine -> IndexedDB
```

核心原则：

- `webui/**` 始终是产品源码，Simulator 不在其中加入 mock 开关、fetch monkey patch、MutationObserver、第二 QBClient 或版本专用运行时。
- Virtual Lab 位于产品 HTTP 边界之下，模拟 qBittorrent，而不是要求 WeiG WebUI 为 Demo 特判。
- Clean Validation Mode 使用分支 `webui/**` 的 exact snapshot，不注入 Lab DOM，用于回归、截图与兼容验收。
- 所有 BitTorrent、Tracker、Peer、Proxy、磁盘与文件系统副作用均为虚拟状态，不产生真实 P2P 流量或本地文件操作。

## 2. 当前线上架构

当前实现固定采用：

- Native Service Worker：接管 Pages scope 下 `api/v2/*`。
- IndexedDB：持久化每个 Virtual Session 的世界状态。
- Service Worker resident world cache：热请求在内存推进，写操作立即持久化，读请求按节流 checkpoint，SW 被回收后可由 IndexedDB 恢复。
- Seeded deterministic RNG：相同 seed/profile/scenario 可重现。
- Request-driven Virtual Clock：不依赖永久 `setInterval`。
- Canonical torrent state + qB version codec：内部状态与 qB4/qB5 外部字符串分离。
- Upstream action/preference catalog：优先按 exact qB stable tag 的真实 WebAPI action surface 门禁；无 exact catalog 时才使用保守 fallback。
- GitHub Pages Actions：构建 exact `dev` / `main` WebUI snapshot，并部署同一站点。

当前主要代码边界：

```text
simulator/
  core/
    engine.js                 # world / scheduler / canonical torrent semantics
    torrent-actions.js        # qB torrent actions
    torrent-content.js        # files / pieces / share limits
    torrent-metadata.js       # properties / tracker projections
    torrent-auxiliary.js      # modern torrent metadata, peers, SSL, clientdata helpers
    virtual-services.js       # RSS / Search / Torrent Creator / WebSeeds
    app-services.js           # virtual filesystem / API key / interfaces / shutdown
    scenarios.js
    profiles.js
    random.js
  protocol/
    router.js
    auxiliary-router.js
    upstream-gates.js
  service-worker/
  storage/
  lab/
  build/
  versions/

tools/
  qb-release-catalog.mjs

tests/
  simulator-*.mjs
  pages-live-acceptance.mjs
  pages-live-services.mjs
```

Service Worker 只是 transport adapter；业务语义必须保持单一 owner。

## 3. qBittorrent 稳定版本范围

Virtual Lab 从 qBittorrent **4.1.0** 开始，自动发现后续官方纯数字稳定版：

```text
4.1.0 -> 4.1.x -> 4.2.x -> ... -> 4.6.x
5.0.x -> 5.1.x -> 5.2.x -> 未来 5.3.x / 5.x.x
```

普通选择器必须排除：

- alpha
- beta
- rc
- nightly
- master
- synthetic

稳定 tag 只接受纯数字 release 形态。Lab coverage 与 WeiG 产品正式 support floor 是两个概念；低于产品正式 floor 的 qB 版本只能视为 Lab/兼容实验 profile。

## 4. Upstream Truth

唯一 stable-release truth owner 是 `QBStableReleaseCatalog` / `tools/qb-release-catalog.mjs` 所代表的 upstream 解析链。

构建时读取 qBittorrent 官方 stable tags，并从 exact tag 源码提取：

```text
qB version
WebAPI API_VERSION
controller *Action endpoints
app/preferences keys
upstream tag SHA / provenance
```

Simulator profile 优先使用生成的 `apiActions` 做 exact endpoint gating。未知 endpoint 不得因为“看起来像 qB”而被自动放行。

## 5. 每周自动发现新稳定版（已上线）

Pages workflow 已启用定时构建：

```text
.github/workflows/pages.yml
cron: 17 4 * * 1
```

即每周一由 GitHub Actions 重新拉取 qB upstream stable tags，生成最新 stable catalog 并重建 Pages。

当未来出现：

```text
5.2.4
5.3.0
5.3.1
...
```

只要是符合规则的官方稳定版，它会自动进入 Pages 构建期 catalog 和版本选择器。

约束：

- weekly rebuild **不自动 commit dev/main**；
- 不自动修改 `webui/**`；
- 不自动 bump WeiG 产品 VERSION；
- 不自动猜未知设置的 label/unit/enum/业务语义；
- upstream 解析失败必须 fail closed。

## 6. 新 qB Settings 策略

新 stable qB 版本新增 Preferences 后：

1. catalog 自动发现 preference key；
2. Virtual qB 的 `app/preferences` 按该 profile 的 upstream key surface 返回；
3. 已建模 preference 可以真正影响 Scheduler/Policy/Environment；
4. 未建模但安全的 scalar 可先作为 stateful/fallback 数据存在；
5. 正式 WeiG Settings 的名称、单位、枚举、帮助文本和复杂交互仍由 `webui/**` 后续产品开发完善。

Simulation coverage 概念：

```text
MODELED    读写 + 有真实虚拟副作用
STATEFUL   可保存/读取，暂未完整模拟现实副作用
READ_ONLY  只读安全展示
UNKNOWN    不猜语义
```

## 7. 登录 / 退出

公开 Lab 保留真实 auth 流程。

Lab Mode 默认预填：

```text
username = demo
password = demo
```

用户只需点击登录；同时任意用户名/密码都可以登录成功。它们只是 Virtual Lab 体验凭据，不代表真实 qB 默认安全配置。

成功：

```text
POST auth/login -> Virtual Session active -> private APIs available
```

退出：

```text
POST auth/logout
-> Virtual Session invalid
-> app/preferences 等 protected API 返回 403
-> 原始 WeiG SessionController 完成退出闭环
```

Clean Mode 不为了预填便利修改 `webui/**`。

## 9. 默认 5000 Torrent 世界

典型 Lab 参数：

```text
count = 5000
scenario = mixed
seed = 可重现值
```

5000 Torrent 不等于 5000 个高速活动任务。真实感来自：

- 大量 completed / stalledUP / idle seeding；
- 少量 downloading/uploading；
- queued / paused / checking / metadata / error 混合；
- 活动数量受 queue、active limits、连接数、peer 供应、网络和磁盘共同约束。

同一 seed/profile/scenario 的初始世界必须可重现。

## 10. Scheduler / Policy / Resource Model

速度不是独立随机数，而是资源分配结果。

```text
effective download rate = min(
  swarm potential,
  per-torrent limit,
  global / alternate allocation,
  queue eligibility,
  connection budget,
  network budget,
  disk write budget,
  peer supply
)
```

上传同理。

已经建模的重要约束包括：

- Global Download / Upload Limit
- Alternate Speed
- Per-Torrent DL/UL Limit
- Maximum Active Downloads / Uploads / Torrents
- Queueing
- Force Start
- Connection / per-torrent connection limit
- Upload slots
- Ratio / Seeding Time / inactive seeding limits
- Share Limit Action（Stop / Remove / RemoveWithContent / EnableSuperSeeding）
- DHT / PeX / LSD
- Virtual Network / Disk / Free Space
- Offline / poor network / disk bottleneck / tracker failure 等场景

重要不变量：`torrents/info`、`transfer/info` 与 `sync/maindata.server_state` 必须来自同一世界快照。

## 16. IndexedDB 与多 Session


## 22. 安全与真实性边界

Virtual Lab 的“真实”是协议和状态因果真实，不是现实副作用真实。

例如：

- Proxy preference 可以影响虚拟连接条件，但不会建立真实 SOCKS 连接；
- Virtual path 可以移动和列目录，但不会写宿主机文件；
- Search/RSS 可以新增 Virtual Torrent，但不会访问真实 Tracker/资源站；
- Shutdown 会使 Virtual daemon offline，但不会关闭页面或机器；
- Test Email 只产生虚拟日志；
- API key 只属于 Virtual Session。

页面必须明确说明它是模拟环境。

## 23. Definition of Done

最终硬性标准：

- `webui/**` 为 0 个 Simulator 产品侵入改动。
- qB 4.1.0 -> 最新 stable 自动进入 Lab catalog。
- alpha/beta/rc/master 不进入普通选择器。
- profile 有 upstream WebAPI/action/preference provenance。
- 5000 Torrent 可稳定运行且 same seed 可重现。
- 任意凭据可登录；默认 `demo/demo` 可一键登录；logout 后 protected API 403。
- Global/per-torrent/alternate limits 真正限制 Scheduler。
- Active limits / Queue / Force Start / Ratio / Seeding Time 真正执行。
- Seeds/Peers/Tracker/Connections/Rate/Progress/ETA/Ratio 互相解释。
- Add/Delete/Rename/Pause/Start/Settings/RSS/Search 等状态刷新后仍持久化。
- 多 Virtual Session 可同时运行不同 qB profile 且互不串状态。
- 未实现或该版本不存在的 API fail closed。
- Clean Mode 无 Simulator DOM 污染。
- weekly stable discovery 不自动修改产品源码或 VERSION。
- Pages 每次部署都执行 exact-SHA 公网 Chrome 验收。

## 24. 核心原则

> **不要让 WeiG WebUI 配合 Simulator 演戏；应模拟一个足够接近真实 qBittorrent 的后端，让同一份 WeiG WebUI 自己去适配它。**

因此 WeiG Virtual qB Lab 同时承担：

1. 公开可交互 qBittorrent/WeiG WebUI 体验环境；
2. 多 qB/WebAPI generation 高保真回归环境；
3. qB stable release / Preferences / API surface 自动变化探测器。
