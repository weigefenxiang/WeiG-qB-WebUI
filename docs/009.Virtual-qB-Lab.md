# 009. Virtual qB Lab

> Virtual qB Lab 是 WeiG qB WebUI 的非产品后端模拟器与 GitHub Pages 验收环境。它模拟 qB WebAPI，不替换产品 `W.QBClient`、不建立第二份产品业务 state。

Status: **current Virtual Lab architecture + approved next-stage evolution plan + AI handoff truth**

## 1. 目标

Virtual qB Lab 用于：

- 在真实浏览器中验证 formal `webui/**`；
- 覆盖 qBittorrent **4.1.0 -> 最新官方 stable** 的 WebAPI v2 主线；
- 对每个 stable release 使用 upstream source-derived Preference / API / Torrent structural facts；
- 提供 deterministic Torrent/peer/network/disk world；
- 将 Pages LIVE evidence 绑定 exact source SHA；
- 系统验证同一个 WebAPI endpoint 在不同 revision 中的 observable semantic evolution。

qB 4.0.x 属于上一代 WebAPI v1，不属于当前主线。未来如支持，必须通过独立 Legacy WebAPI v1 Adapter 接入 canonical semantics；禁止在 v2 router 中保留 silent v1 fallback。

## 2. Compatibility truth hierarchy

Virtual Lab 必须把兼容 truth 分成两层。

### 2.1 Structural truth — Current Owner

回答“有没有”：

```text
endpoint exists?
Preference getter/setter exists?
Torrent filter exists?
torrents/info parameter exists?
```

来源：

```text
qB upstream official stable source
-> source parsers
-> qb-release-catalog.mjs
-> qb-releases.json
-> ReleaseProfile
```

Exact supported-stable source facts优先于 version heuristic。

### 2.2 Semantic evolution truth — Approved Target Owner

回答“同一个 endpoint 在这个 WebAPI revision 怎么表现”：

- required/renamed parameter；
- selector syntax；
- request type；
- response field/shape；
- HTTP status；
- no-op behavior；
- mutation semantics；
- conditional projection。

批准新增：

```text
simulator/protocol/endpoint-contracts.js
resolveEndpointContract(profile, path)
```

**该 owner 当前尚未完成 runtime cutover。** 当前 router 中仍存在已验证但分散的 historical WebAPI branches；下一阶段先建立新接口，再原子迁移并删除旧政策代码。

## 3. Stable release catalog — Current Owner

`tools/qb-release-catalog.mjs` 对 numeric official stable tags 逐个读取源码并生成 profile：

```text
qbVersion
webApiVersion
tag
sourceSha
preferenceKeys / preferenceDescriptors
apiActions
torrentFilters
torrentInfoParameters
```

起点固定 `release-4.1.0`；Alpha/Beta/RC/master 不进入正式 stable matrix。Latest stable 与 profile 数量动态发现，不硬编码。

`4.6.1 -> WebAPI 2.9.3` 是受 contract 保护的历史事实。

## 4. Source parsers — Current Owners

- `qb-source-parsers.mjs`：Preferences getter/setter；
- Preference semantic enrichment：getter/setter type/provenance；
- `qb-torrent-surface-parsers.mjs`：Torrent filters + `torrents/info` params；
- `qb-release-catalog.mjs`：stable profile assembly；
- catalog quality/evolution contracts：source evidence/shape consistency。

Parser 无法隔离关键 source surface 时 fail closed，不输出“猜到”的 exact capability。

## 5. Runtime boundary

```text
formal W.QBClient
-> Native Service Worker
-> protocol router
-> QBSimulatorEngine / Scheduler / Policy / services
-> canonical IndexedDB world
```

禁止：

- monkey-patch `W.QBClient`；
- 在 Pages 建第二份产品 state；
- fixture DOM 伪装真实 UI transition；
- presentation 直接轮询 simulator state；
- new/old protocol owner 长期双活。

## 6. Current protocol responsibilities

### `upstream-gates.js`

只负责 structural endpoint existence：

```text
apiActions contains actionRef?
```

它与未来 Endpoint Contract 是职责正交关系，**不会因 Endpoint Contract 上线而删除**。

### `router.js / auxiliary-router.js`

当前负责 request parse、route dispatch、core invocation、Response construction，同时仍包含若干 historical WebAPI semantic version branches。

目标状态：router 继续拥有执行流程，但不拥有历史版本政策。

### simulator core

负责 deterministic domain mutation/state projection，不感知 UI owner；只有确实属于 domain state 的逻辑才进入 core。

## 7. Planned Endpoint Contract interface

目标公共接口保持窄：

```text
resolveEndpointContract(profile, path)
```

可返回例如：

```text
hashSelection = single | multi-or-all
missingResourceStatus = 404 | 409
noOp = success | conflict
trackerTimingFields = true | false
requiredParameters = [...]
```

它只返回 semantic facts，不执行：

- route dispatch；
- `split('|')` 等具体 request work；
- torrent/category/tracker mutation；
- HTTP `Response` 构造；
- Preference schema；
- UI capability；
- Torrent status taxonomy。

第一代内部可以是 audited canonical table。接口必须允许未来替换成 generated semantic catalog/source parser，而 caller 不改变。

## 8. OWNER-CUTOVER — 强制迁移规则

新 owner 可以先写、先测，但不能和旧 owner 长期混用。

### Phase B1 — Dormant interface validation

```text
endpoint-contracts.js exists
-> direct isolated contract tests
-> production router still uses exactly one old active path
```

此阶段新 owner不是 Current Owner。

### Phase B2 — Atomic cutover

B1 一旦成功，下一变更立即：

```text
all affected router/auxiliary callers -> resolveEndpointContract()
remove superseded apiAtLeast/version policy branches
remove obsolete helpers/files/tests/docs expectations
repo-wide search confirms zero stale ownership references
update DESIGN.md: Endpoint Contract becomes Current Owner
CI / Upstream / Pages exact-SHA validation
```

禁止：

```text
feature flag switching old/new
new fails -> call old
compatibility shim
runtime alias
legacy/vNext files长期并存
```

只有“被替代”的旧代码删除。Source parsers、release catalog、upstream-gates、Settings/Torrent owners 等正交职责不得误删。

## 9. Full WebAPI Evolution Audit — 下一主任务

不再随机扫 endpoint。按 upstream WebAPI release chronology 从 **2.0.x -> latest stable WebAPI** 顺序审计。

每条 changelog/source delta 分类：

```text
NEW_ENDPOINT
REMOVED_ENDPOINT
PREFERENCE
TORRENT_SURFACE
PARAMETER_CHANGE
RESPONSE_CHANGE
STATUS_CHANGE
MUTATION_CHANGE
TRANSPORT_CHANGE
NOT_APPLICABLE
```

Owner mapping：

```text
NEW/REMOVED endpoint -> apiActions/source catalog
PREFERENCE          -> Preference source pipeline
TORRENT_SURFACE     -> Torrent surface parser/catalog
PARAM/RESPONSE/
STATUS/MUTATION     -> Endpoint Contract
TRANSPORT           -> protocol transport contract
NOT_APPLICABLE      -> audited ledger only
```

Audit 必须先完成完整 classification ledger，再集中处理 `MISSING`。禁止边审计边随机把新 `apiAtLeast()` 塞回 router。

## 10. Planned evolution audit tool

计划新增：

```text
tools/qb-webapi-evolution-audit.mjs
```

目标消费：

```text
upstream WebAPI changelog
+ official stable release catalog
+ structural source catalogs
+ Endpoint Contract owner
```

输出：

```text
SOURCE_DERIVED
CONTRACT_COVERED
NOT_APPLICABLE
MISSING
UNCLASSIFIED
```

最终规则：`UNCLASSIFIED` = hard failure。新 stable/WebAPI revision 不能因为“版本更高”就默认继承未知 semantics。

## 11. Future stable release adaptation

未来 qB stable：

```text
new tag discovered
-> exact structural catalog generated
-> WebAPI revision compared
-> evolution audit
```

### 已知 semantic revision / 可证明无相关 delta

继续自动验证。

### 未分类 semantic delta

Fail closed，并输出 endpoint/change/evidence requirement。修复完成并建立 Current Owner 后才恢复 PASS。

`resolveEndpointContract(profile,path)` 隐藏数据来源，因此未来 audited table 可以无 caller 变更地升级成 generated semantic truth。

## 12. Preference fidelity — 独立 Current Owner

每个 profile 的 `app/preferences` surface 由 upstream descriptor catalog 驱动。Virtual runtime 保持 value/type fidelity；modelled Preferences 真正影响 simulator behavior。

产品 Settings writable truth 仍归 `W.SettingsSchema + W.ReleaseProfile`。Endpoint Contract 不复制 Preference getter/setter/type/editability；只可读取 preference state 处理真正 conditional endpoint projection。

## 13. Torrent fidelity — 独立 Current Owner

Simulator Torrent query 消费 exact `torrentFilters/torrentInfoParameters`：

- qB4 source `paused/resumed`；
- qB5 source `stopped/running`；
- unsupported filter fail closed；
- Private query 只有 exact profile含 `private` 时生效；
- selection/pagination/sort/BadParams 由 current contracts 保护。

Endpoint Contract 不重新定义 Torrent status/filter taxonomy。

## 14. Pages / evidence

Pages build 把 generated release catalog写入：

```text
metadata/qb-releases.json
<branch>/app/__source/private/data/qb-releases.json
```

Formal Pages：

```text
source signal
-> exact source checkout
-> simulator contracts
-> qB upstream catalog generation
-> exact dev/main build
-> deploy
-> Hosted Chrome LIVE verify
```

Workflow UI 的 main `head_sha` 不是 source identity；必须以 triggering source SHA、exact checkout、`WEIGG_PAGES_SOURCE_SHA`、`WEIGG_EXPECTED_SIMULATOR_SHA`、deployed metadata为准。

## 17. Next AI — 开工顺序

## 18. Definition of Done

Virtual qB Lab 的目标不是重写 qB/libtorrent 内核，而是达到 **WebUI-observable fidelity**。

完成标准：

```text
every official supported stable release
-> exact structural profile known
-> endpoint existence known
-> every WebAPI evolution item classified
-> every WeiG-consumed semantic delta has one Current Owner
-> no unclassified delta
-> no superseded legacy owner/runtime path
-> deterministic state mutation
-> representative real browser interaction correct
-> exact-SHA Pages validation green
```

只有达到以上条件，WebAPI evolution 阶段才可以宣布完成。
