# 009. Virtual qB Lab

> Virtual qB Lab 是 WeiG qB WebUI 的非产品后端模拟器与 GitHub Pages 验收环境。它必须模拟 qB WebAPI，而不是替换产品 `W.QBClient` 或修改产品业务 state。

## 1. 目标

Virtual qB Lab 用于：

- 在真实浏览器中验证 formal `webui/**`；
- 覆盖 qBittorrent **4.1.0 → 最新官方 stable**；
- 对每个 stable release 使用从 upstream source 派生的 Preference / API / Torrent surface；
- 提供 deterministic Torrent/peer/network/disk world；
- 将 Pages LIVE evidence 绑定 exact source SHA。

## 2. Stable release catalog

`tools/qb-release-catalog.mjs` 对 numeric official stable tags 逐个读取源码并生成 profile：

```text
qbVersion
webApiVersion
tag
sourceSha
preferenceKeys / preferenceDescriptors
apiActions
torrentFilters
torrentInfoParameters
```

起点固定为 **release-4.1.0**。Alpha/Beta/RC/master 不进入正式 stable matrix。Latest stable 与 profile 数量运行时发现，不在文档中硬编码。

`4.6.1 -> WebAPI 2.9.3` 是受 contract 保护的历史事实。

## 3. Source parsers

- `qb-source-parsers.mjs`：Preferences getter/setter；
- `qb-preference-semantics.mjs`：C++ getter semantic enrichment；
- `qb-torrent-surface-parsers.mjs`：Torrent filter 与 `torrents/info` 参数；
- catalog quality/evolution tools：验证每个 profile 的 source evidence 与演化一致性。

Parser 无法隔离关键 upstream action/surface 时 fail closed，不能输出“猜到”的能力。

## 4. Product runtime catalog injection

Pages build 会把 generated catalog 写入两个位置：

- `metadata/qb-releases.json`：Lab/验收 metadata；
- `<branch>/app/__source/private/data/qb-releases.json`：formal product runtime 的 `W.ReleaseProfile` 输入。

因此 Pages 产品代码使用的 compatibility truth 与 simulator 选择的 release profile 是同一 source artifact。

正式 Release candidate 也必须嵌入同 shape catalog 到 `private/data/qb-releases.json`，避免 Pages 与用户下载包出现不同兼容模式。

## 5. Runtime boundary

```text
formal W.QBClient
 -> Native Service Worker
 -> protocol router
 -> QBSimulatorEngine
 -> Scheduler / Policy / services
 -> IndexedDB world
```

禁止：

- monkey-patch `W.QBClient`；
- 在 Pages 建第二份产品 state；
- 为浏览器测试另写一套 Torrent semantic engine；
- 用 fixture DOM 伪装真实 UI transition。

## 6. Preference fidelity

每个 profile 的 `app/preferences` surface 由 upstream descriptor catalog 驱动。Virtual runtime 必须保持 value/type fidelity；modelled Preferences 要真正影响 simulator behavior。

产品 Settings 的 writable truth 仍归 `W.SettingsSchema + W.ReleaseProfile`，Lab 不替产品猜 unit/enum/range/default。

## 7. Torrent query fidelity

Simulator `torrent-query.js` 消费 profile 的 exact `torrentFilters` 与 `torrentInfoParameters`：

- qB4 使用 source `paused/resumed`；
- qB5 使用 source `stopped/running`；
- 不存在的 filter 返回空匹配/fail closed，而不是 All；
- Private query 只有 profile source 明确包含 `private` 参数时生效；
- historical pagination/sort/BadParams 行为由 contract 单独保护。

## 8. Pages workflow

`Virtual qB Pages Source` 只发送 source signal；默认分支拥有 deployment workflow。Source relay watch：

- `webui/**`；
- `simulator/**`；
- `tools/qb-*.mjs`；
- relevant tests/package/workflow inputs。

Build：

1. checkout exact source SHA；
2. checkout qB upstream stable tags；
3. `npm test`；
4. generate exact stable catalog；
5. build dev/main product source + simulator；
6. inject catalog；
7. deploy Pages。

Verify 使用 hosted Google Chrome，对 deployed URL 做 LIVE 验收。

## 9. LIVE gates

当前 LIVE 层包括：

- base acceptance / exact SHA；
- all-stable Preferences matrix；
- exact release-profile capability/Torrent filter gate；
- services；
- Mobile layout。

Release-profile gate 特别验证：

- qB 4.1.0 exact profile 能绑定并 certified；
- qB 4.1.0 不展示 source 不支持的 Tags/Stalled/Private；
- 六个 qB Settings surfaces 使用 canonical renderer；
- latest stable UI filter/capability 与其 exact source profile 一致；
- qB 4.6.1 / WebAPI 2.9.3 catalog fact。

## 10. Performance / determinism

Synthetic world 必须 seeded、可重放、bounded。大库测试可用 5000 Torrent，但 UI virtualization、catalog indexing 与 polling 仍遵守产品性能 contract。兼容验证不通过每个 Torrent 单独请求实现。
