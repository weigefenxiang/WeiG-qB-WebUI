# 009. Virtual qB Lab



> **Current-work routing**：mutable phase / exact-SHA / TODO只看 `docs/014` STOP 前；当前 A4 Settings 专项见 `docs/017`；A1–A3 历史在 `docs/016`，默认不要读。

> Virtual qB Lab 是 WeiG qB WebUI 的**辅助验证基础设施**。它模拟 qB WebAPI，帮助同一份正式 `webui/**` 在多个历史/未来 profile 下跑可重复浏览器测试；它不替换 `W.QBClient`，不建立第二份产品业务 state，也不定义正式产品语义。

## 1. 正确定位

Virtual qB 用来：

```text
reproduce historical request/response/status differences
exercise the same formal webui/** under multiple profiles
validate normalization / fail-closed behavior
provide deterministic torrent/peer/network/disk worlds
support exact-SHA browser/Pages evidence
```

Virtual qB 不用于：

```text
代替修改正式 webui/**
让产品依赖 simulator-only endpoint/data
把 simulator coverage 当产品主进度
声称 simulator PASS == all real qB runtimes PASS
```

如果 simulator 与 qB official source / real-qB behavior 冲突，以正确 source/runtime truth 为准，修 simulator/fixture。

## 2. Product-first workflow

发现历史差异时先确认正式 `webui/**` 是否消费该差异。若消费：确认 qB source truth -> 确认 canonical product owner -> 修正式 compatibility semantics -> 再补 Virtual qB profile/contract/browser evidence。若不消费：只记录 evolution/ledger facts并按需要维护 simulator fidelity。

不要因为 simulator 出现 `MISSING` 就默认先补模拟器。

## 3. Structural truth

```text
qB official stable source
-> source parsers
-> admitted Frozen catalog/LKG
-> compact domain contracts
```

这些 facts 同时服务正式产品与 simulator，包括 endpoint/action/parameters、Preference getter/setter/type、native Settings/RSS/Torrent/Detail surfaces、Torrent filters/fields 与 WebUI locale facts。它们不是 Virtual Lab 私有 truth。

Locale 在 Virtual qB 中使用独立的 hash/source-SHA-bound frozen overlay；它补充已 admitted Frozen LKG，不改写原始 LKG bytes，也不要求 Pages 每次重新 clone/parse qB 历史。

## 4. Simulator protocol architecture

```text
formal W.QBClient
-> Native Service Worker / transport adapter
-> Transport Contract
-> upstream structural gate
-> Endpoint Contract / router
-> QBSimulatorEngine / Scheduler / Policy / services
-> IndexedDB world
```

职责：upstream structural gate判 endpoint/action 是否存在；Endpoint Contract复现历史 request/response/status/mutation；Transport Contract复现 auth/header/proxy；simulator engine提供 deterministic world。它们都属于 validation infrastructure，不得复制正式产品 compatibility owner。

## 5. Stable profile scope

当前 admitted WebAPI v2 matrix：

```text
qB 4.1.0 -> 5.2.3
65 official stable profiles
```

qB 4.0.x / WebAPI v1 当前不在正式范围。未来如实现 legacy adapter，产品设计和 canonical owner 先完成，Virtual qB 随后增加对应验证。

## 6. A–F 阶段验证节奏

用户明确要求避免每一步都跑全部 65 版本。开发节奏固定为：

```text
阶段内部
  unit/parser/source contracts
  + source-diff-driven change-point releases
  + focused browser/Virtual cases
  -> 不重复跑全 65

阶段完整收口
  -> 该领域只跑一次 admitted-stable 65-release offline/Virtual full matrix

A–F 全部完成并冻结 final dev exact SHA
  -> 再按 docs/011 跑一次 real-qB Full Frozen Matrix
```

change-point应由 source diff/manifest timeline选择，而不是永久手写“代表版本”。例如 Settings 已知边界可覆盖 4.2.x / 4.3.x / 4.6+ / latest，但最终 selection应由当前 exact source changes驱动。

一次 phase full matrix之后如果只是 docs-only变化，不应为了形式重复昂贵矩阵；如果该领域产品/source truth之后又发生实质改变，则旧矩阵只证明旧 SHA/旧内容，阶段 completion需要重新判断。

## 7. Independent inventory / census

为了避免“extractor自己漏了，测试又只验证 extractor输出”这种共同盲点，每个 source-driven domain完成前必须有独立 inventory/census：

```text
raw exact upstream source
  ├─ semantic extractor -> product compact facts
  └─ independent census -> upstream exposed controls/actions/facets/tabs/fields

upstream inventory
= mapped facts + explicit reviewed exclusions
unaccounted = 0
duplicates = 0
```

至少分别审计：

```text
A Settings: tabs + sections + bound controls + app/preferences descriptors
B Torrent: statuses/filters/native facets + value/filter bindings
C Copy: every runtime qB-owned {source,context} route
D RSS: feeds/downloader/rule fields/actions/read-state surface
E Detail: tabs/general fields/table columns/context menus/actions
F Actions/contracts: every formal write is subset of exact source proof
```

independent census不要只是把 semantic extractor返回的数组再 count一遍。Unknown upstream syntax应使 admission fail/PENDING_REVIEW，而不是静默减少 mapped count。

## 8. Full phase aggregate contract

每次阶段末 65-release offline/Virtual matrix的 expected set必须直接来自 target exact-SHA Frozen admitted catalog：

```text
executed_versions == expected_versions
missing_versions == []
duplicate_versions == []
unexpected_versions == []
```

每个版本至少绑定 `qbVersion + sourceSha`，并验证该领域 source inventory、mapped/excluded accounting、compact contract resolution、formal runtime projection与 relevant fail-closed writes。阶段 artifact可以保存 coverage evidence，但它只是 evidence，不能成为新的 runtime compatibility owner。

## 9. Pages exact-SHA evidence

Pages 链：

```text
Virtual qB Pages Source
-> verify source signal is still current branch HEAD
-> workflow_dispatch Virtual qB Pages on that same dev/main ref
-> GITHUB_SHA == dispatched ref SHA
```

对 dev：exact dev checkout/archive -> Frozen LKG + frozen Locale overlay -> Virtual qB Pages dev build -> exact-SHA artifact -> deploy -> Hosted Chrome live exact-SHA verify。

对 main：不重新 build；只复用同 SHA 已成功 dev artifact并重新验证 main alias/live identity。

不要使用 `workflow_run` 顶层 `GITHUB_SHA` 作为 Pages deployment identity；真实 identity必须同时检查 dispatched ref、exact checkout/archive SHA、artifact名、site/build metadata与 live expected SHA。

Pages green 只证明 formal `webui/**` + modeled profiles + hosted Chrome；它不能替代 real-qB full matrix。

## 10. Simulator realism / performance boundary

Synthetic runtime data必须 seeded/deterministic/internally consistent，response shape/status遵循 audited contract，modeled settings必须影响 modeled behavior。不得制造 impossible fake data 只为了让测试变绿。

Virtual qB 或正式产品都不能通过高成本 self-probing实现兼容。禁止 N torrents -> N compatibility requests、per-row endpoint probes、duplicate polling、second capability state或 presentation-owned compatibility checks。

## 11. Future stable

新的 official stable：

```text
discover exact tag/source identity
-> verify Frozen prefix
-> run source inventory + semantic extraction for the new stable
-> diff against previous admitted stable
-> focused product/admission gate
-> regenerate compact contracts only after review
-> update simulator profile only where product/evidence needs it
-> browser/Pages evidence
```

产品影响判断先于 simulator fidelity扩展；Unknown语义不能猜。

## 12. Definition of Done

Virtual qB 不需要完整重写 qB daemon。完成标准是：product-consumed historical semantics准确、multi-profile flows deterministic、差异能暴露真实产品兼容 bug、formal product没有 simulator dependency、phase/full evidence可追到 exact source/SHA、Pages deployment identity不混淆。

相关正式兼容原则见 `docs/010.真实qB产品兼容路线.md`；真实全版本验证见 `docs/011.全版本真实qB验证规则.md`。
