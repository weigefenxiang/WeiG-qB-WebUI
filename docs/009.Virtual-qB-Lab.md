# 009. Virtual qB Lab

> Virtual qB Lab 是 WeiG qB WebUI 的**辅助验证基础设施**。它模拟 qB WebAPI，帮助同一份正式 `webui/**` 在多个历史/未来 profile 下跑可重复浏览器测试；它不替换 `W.QBClient`，不建立第二份产品业务 state，也不定义正式产品语义。

## 1. 正确定位

Virtual qB 用来：

```text
reproduce historical request/response/status differences
exercise the same formal webui/** under multiple profiles
validate normalization / fail-closed behavior
provide deterministic torrent/peer/network/disk worlds
support exact-SHA browser/Pages evidence
```

Virtual qB 不用于：

```text
代替修改正式 webui/**
让产品依赖 simulator-only endpoint/data
把 simulator coverage 当产品主进度
声称 simulator PASS == all real qB runtimes PASS
```

如果 simulator 与 qB official source / real-qB behavior 冲突，以正确 source/runtime truth 为准，修 simulator/fixture。

## 2. Product-first workflow

发现历史差异时先问：

```text
正式 webui/** 是否消费这个差异？
```

如果 YES：

```text
确认 qB source truth
-> 确认 canonical product owner
-> 修正式 compatibility semantics
-> 再补 Virtual qB profile/contract/browser evidence
```

如果 NO：

```text
记录 evolution/ledger facts
-> simulator fidelity 按需要维护
```

不要因为 simulator 出现 `MISSING` 就默认先补模拟器。

## 3. Structural truth

```text
qB official stable source
-> source parsers
-> qb-release-catalog.mjs
-> admitted release facts
```

这些 facts 同时服务正式产品与 simulator，包括：

```text
endpoint/action existence
parameters
Preference getter/setter/type
Torrent filters/fields
Details response fields
WebUI locale source facts
```

它们不是 Virtual Lab 私有 truth。

Locale 在 Virtual qB 中使用独立的 hash/source-SHA-bound frozen overlay；它补充已 admitted Frozen LKG，不改写原始 LKG bytes，也不要求 Pages 每次重新 clone/parse qB 历史。

## 4. Simulator protocol architecture

```text
formal W.QBClient
-> Native Service Worker / transport adapter
-> Transport Contract
-> upstream structural gate
-> Endpoint Contract / router
-> QBSimulatorEngine / Scheduler / Policy / services
-> IndexedDB world
```

职责：

```text
upstream structural gate  -> endpoint/action exists?
Endpoint Contract          -> historical request/response/status/mutation semantics
Transport Contract         -> auth/header/proxy transport semantics
simulator engine           -> deterministic runtime world
```

这些 owner 都属于 validation infrastructure，不得复制正式产品 compatibility owner。

## 5. Stable profile scope

当前 admitted WebAPI v2 matrix：

```text
qB 4.1.0 -> 5.2.3
65 official stable profiles
```

qB 4.0.x / WebAPI v1 当前不在正式范围。未来如实现 legacy adapter，产品设计和 canonical owner 先完成，Virtual qB 随后增加对应验证。

## 6. 重点验证内容

Virtual qB 优先覆盖用户可见正式 surface：

```text
Torrent filters / states
facets: tracker/path/category/tag
columns / field availability
Settings getter/setter/type/editability
qB Locale exact options / WeiG language bridge
Search / RSS / Logs
Torrent Details / actions
Categories / Tags
Torrent Creator where supported
future UNKNOWN fail-close
```

测试应验证真实 interaction + final semantic/rendered state，而不是只检查 DOM 是否存在。

## 7. Pages exact-SHA evidence

Pages 链：

```text
Virtual qB Pages Source
-> verify source signal is still current branch HEAD
-> workflow_dispatch Virtual qB Pages on that same dev/main ref
-> GITHUB_SHA == dispatched ref SHA
```

对 dev：

```text
exact dev checkout/archive
-> Frozen LKG + frozen Locale overlay
-> Virtual qB Pages dev build
-> virtual-qb-pages-site-<SHA>
-> github-pages artifact
-> deploy
-> Hosted Chrome live exact-SHA verify
```

对 main：

```text
no rebuild
-> find successful same-SHA dev workflow_dispatch artifact
-> repackage only main alias
-> deploy
-> live metadata + main build identity verify
```

main 不重新 build；main path 必须复用相同 SHA 的已成功 dev artifact。

不要使用 `workflow_run` 顶层 `GITHUB_SHA` 作为 Pages deployment identity。该事件的 workflow context 可能把默认分支 SHA 暴露为 `GITHUB_SHA`，而 `actions/deploy-pages` 又使用它作为 `pages_build_version`；这样不同 dev artifact 会共享同一个 deployment ID。Pages Source 因此只持有 `actions: write` 来 dispatch 真正 owner，本身不持有 `pages: write` / `id-token: write`。

真实 identity 应同时检查：

```text
dispatched ref + GITHUB_SHA
exact checkout/archive SHA
virtual-qb-pages-site-<SHA>
github-pages artifact content
metadata/site.json simulatorSha / branch exactSha
virtual-qb-build.json exactSha / simulatorSha
live expected simulator SHA
```

Pages green 只证明：

```text
formal webui/** + modeled profiles + hosted Chrome
```

它不能替代 real-qB full matrix。

## 8. Simulator realism boundary

Synthetic runtime data必须：

```text
seeded / deterministic
internally consistent
response shape/status follows audited contract
modeled settings actually affect modeled behavior
no impossible fake data just to make tests green
```

## 9. Performance boundary

Virtual qB 或正式产品都不应通过高成本 self-probing 实现兼容。

禁止：

```text
N torrents -> N compatibility requests
per-row endpoint probes
duplicate polling
second capability state
presentation-owned compatibility checks
```

## 10. Future stable

新 official stable 的顺序：

```text
discover source facts
-> product compatibility impact check
-> update/admit release profile after review
-> refresh frozen Locale facts when source locale surface changed
-> update simulator contract/profile only where needed
-> browser/Pages evidence
```

产品影响判断必须先于 simulator fidelity 扩展。

## 11. Definition of Done

Virtual qB 不需要完整重写 qB daemon。完成标准是：

```text
product-consumed historical semantics are accurate
multi-profile browser flows are deterministic
differences can expose real product compatibility bugs
formal product has no simulator dependency
exact-SHA evidence is traceable
Pages deployment build identity cannot alias an unrelated default-branch SHA
```

相关正式兼容原则见 `docs/010.真实qB产品兼容路线.md`；真实全版本验证见 `docs/011.全版本真实qB验证规则.md`。
