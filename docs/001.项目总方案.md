# 001. 项目总方案

Status: **current project plan / AI handoff entry**

WeiG qB WebUI 是 qBittorrent Alternate WebUI。当前 `dev` 只维护一套现行架构；WeiG 自身旧 runtime、tests、tools、deploy scripts 由 Git history / tags / Releases 保存，不在工作树长期共存。

Virtual qB 的总体方案、当前实现进度、验证边界、WebAPI Evolution Audit 与 Definition of Done 统一由 [`docs/009.Virtual-qB-Lab.md`](./009.Virtual-qB-Lab.md) 维护。不得另建第二份 Virtual Engine 总方案或 AI handoff truth。

## 1. Identity

```text
Product version  -> VERSION / webui/VERSION / package.json.version / package-lock.json root version
Code identity     -> exact Git SHA / GIT_SHA
Distribution      -> Git tag / GitHub Release
```

产品 VERSION 的唯一 bump trigger 是正式 `webui/**` 产品内容变化。仅修改 simulator、tests、tools、workflow、docs、DESIGN、installer 或 CI/gate 时保持当前产品 VERSION；任何新 commit 都产生新的 exact SHA，旧 SHA 的 CI/LIVE/Pages/candidate/artifact 证据不继承。

First-party 文件名与 semantic identifier 使用稳定职责名；numeric revision suffix 由 Git history 取代。

## 2. Compatibility scope

当前 WebAPI v2 主线正式支持：**qBittorrent 4.1.0 -> 最新官方 stable**。

- `release-4.1.0` 是正式 stable matrix 起点；
- 上界与 stable 数量运行时从 qB upstream 发现，不在文档硬编码；
- Alpha / Beta / RC / master 不进入正式 stable matrix；
- qB 4.0.x 属于上一代 WebAPI v1，不塞入当前 v2 evolution owner。未来若明确要求支持，必须通过独立 Legacy WebAPI v1 Adapter 接入 canonical semantics，不能在当前 router 中混入 v1/v2 双路 fallback。

兼容必须区分两种 truth：

```text
Structural truth
  endpoint / Preference / Torrent surface 有没有

Semantic evolution truth
  同一个 endpoint 在不同 WebAPI revision 中参数、response、status、mutation 怎么变化
```

Structural truth 已由 upstream source-derived catalog 管理；semantic evolution 将升级为单一 canonical owner，详见 003/009。

## 4. Single Owner + cutover discipline

### OWNER-CUTOVER

新 owner / 新工具允许先以 **dormant / isolated** 形式存在并直接测试，但不能与旧 owner 同时承担正式 runtime responsibility。

允许：

```text
new-owner.js exists
old owner remains the only active runtime path
new owner is exercised only by isolated contracts
```

禁止：

```text
if (useNew) newOwner()
else oldOwner()

new + old dual-active fallback
compatibility shim / runtime alias / long-lived bridge
```

新接口 direct contract 验证成功后，下一步必须立即做 atomic cutover：

```text
all callers -> new owner
+ delete superseded old helpers/branches/files/tests/docs
+ repo-wide zero-reference audit
+ DESIGN/docs ownership sync
```

被新 owner **取代** 的旧工具要删除；职责正交的 owner 不得误删。例如 endpoint existence owner 与 endpoint semantic-evolution owner 是互补关系，不是新旧关系。

## 5. WebAPI semantic-evolution target

批准的目标责任链：

```text
qB upstream source / stable catalog
        |
        +-> apiActions / upstream gates
        |      responsibility: endpoint exists?
        |
        +-> Endpoint Contract owner
               responsibility: endpoint behaves how at this WebAPI revision?

router
  responsibility: parse request + execute resolved contract + form HTTP response
```

目标稳定接口：

```text
resolveEndpointContract(profile, path)
```

Router 不应长期拥有历史 `apiAtLeast()` policy。Endpoint Contract 只返回 semantic facts，不执行 state mutation，也不复制 Preferences/Torrent capability truth。

当前 runtime 尚未完成该 owner cutover；在实现前它是 **approved target architecture**，不是已经存在的 Current Owner。

## 6. Full WebAPI Evolution Audit

后续停止随机扫 endpoint，改为按 upstream WebAPI release chronology 从 2.0.x 扫到 latest stable WebAPI。

每条 upstream delta 必须分类：

```text
NEW_ENDPOINT / REMOVED_ENDPOINT
PREFERENCE
TORRENT_SURFACE
PARAMETER_CHANGE
RESPONSE_CHANGE
STATUS_CHANGE
MUTATION_CHANGE
TRANSPORT_CHANGE
NOT_APPLICABLE
```

归属规则：

- endpoint existence -> source-derived `apiActions`；
- Preference -> Preference source pipeline；
- Torrent filter/info parameter -> Torrent surface catalog；
- parameter/response/status/mutation semantic evolution -> Endpoint Contract；
- WeiG 不消费 -> audited `NOT_APPLICABLE`。

Audit 必须先完成 classification ledger，再集中处理 `MISSING`；不得回到“发现一条、router 加一个 if、继续随机找下一条”的工作方式。

## 7. Future stable adaptation

未来 stable release 的原则不是“版本更高就猜兼容”，而是：

```text
new stable discovered
-> structural source catalog generated
-> WebAPI evolution audit
-> known semantic revision / provably safe inheritance -> PASS
-> unclassified semantic delta -> FAIL CLOSED
```

`resolveEndpointContract(profile, path)` 隐藏内部 truth 来源，未来可以从 audited table 演进到 generated semantic catalog，而 caller 不需要改接口。

## 8. UI / Settings / Torrent boundaries

- UI compatibility/presentation policy：`W.CapabilityRegistry + W.ReleaseProfile`；
- Settings semantics/writability：`W.SettingsSchema + exact Preference descriptors`；
- Torrent status/filter：`W.TorrentSemantics + W.ReleaseProfile`；
- HTTP transport：`W.QBClient`；
- Virtual protocol semantics：未来 Endpoint Contract owner。

这些 owner 不得互相复制版本表。
