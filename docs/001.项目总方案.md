# 001. WeiG qB WebUI 项目总方案

Status: **v0.2.1 integrated baseline**  
Primary repository: `weigefenxiang/WeiG-qB-WebUI`  
Compatibility floor: **qBittorrent 4.1.9**  
Current product version: **0.2.1**

## 0. 启动原则

新 AI、新开发者或新会话不得根据聊天记忆猜项目。修改前至少：

```text
1. 读取本文件
2. UI/视觉/布局/i18n/Settings 任务读取根目录 DESIGN.md
3. 查看 README.md 与 VERSION
4. 查看真实 Git main / HEAD / CI
5. 搜索已有 Component / API Client / Capability / VirtualList / i18n / SettingsSchema / Installer
6. 明确 4.1.9、5.x、Desktop、Mobile、语言、性能和回归影响
7. Reuse → Extend → New
8. 修改后跑 CI，并同步必要文档
```

## 1. 产品定位

WeiG qB WebUI 是 qBittorrent Alternate WebUI，目标不是单纯换皮，而是同时做到：

- Nebula Noir 高品质视觉；
- 原生 qB 核心管理能力完整；
- 参考 VueTorrent 的功能覆盖和移动端思路，但保持独立视觉/架构；
- qB 4.1.9 强兼容，并延伸到当前 5.x；
- capability-based progressive enhancement；
- English canonical + 多语言翻译层；
- Desktop 应用导航与 Torrent 数据筛选职责清晰；
- 20 / 50 / 100 / 200 服务端分页；
- 数千 Torrent 时 DOM 保持窗口化；
- Desktop 可配置 DataGrid；
- Mobile 独立 Torrent Card + Drawer + Bottom Navigation；
- Tracker/Announce 隐私脱敏；
- Metadata-driven Settings，不把 `/app/preferences` 直接做成 JSON 编辑器；
- GitHub 一键部署、备份和回滚；
- 永不出现无返回路径的死路。

## 3. 核心硬规则

### COMPAT-001

4.1.9 核心回归失败，禁止发布。

### COMPAT-002

Feature/UI 不直接判断 qB 主版本。版本/WebAPI 信息只用于生成 Capability Profile。

### UI-001

所有视觉、布局、导航、i18n 和 Settings UX 修改以根目录 `DESIGN.md` 为唯一权威。

### TYPO-001

所有文字必须属于 Semantic Typography Role；Feature 不得自行硬编码字号。

### TYPO-002

整体阅读尺寸不足时通过全局 `--font-scale-offset` 一次增加 2–3px，不逐组件打补丁。

### TYPO-003

字体大小与 UI Density 独立。

### I18N-001

**English 是 canonical source language。** Feature 不允许维护中英两套业务逻辑。

### I18N-002

语言解析：

```text
用户手动选择
→ navigator.languages / 浏览器语言
→ English fallback
```

不支持的 Locale 必须回退英文，不能显示翻译 key。

### I18N-003

qBittorrent 术语优先参考官方 WebUI translation resources；WeiG 独有术语由本项目维护。

### SETTINGS-001

Settings 必须通过 metadata/schema 呈现 human-readable title / description / control type / section。普通用户界面不得把 `auto_tmm_enabled` 等 raw API key 当主标签。

### NAV-001 — No Dead-End Navigation

非首页必须有 Back。错误状态保留 Back/Home/Reload。

### IA-001

Topbar 负责应用级导航；Sidebar 只负责 Torrent 数据集筛选。

### MOBILE-001

Mobile 是一等平台，不是 Desktop Table 缩小版。

### PERF-001

Torrent API 默认 `PAGE_SIZE=50`，允许 20 / 50 / 100 / 200。

### PERF-002

```text
Data Count != DOM Count
```

200 个当前页模型不代表 200 个挂载 DOM Row。

### PERF-003

Torrent、Files、Peers、Trackers、Logs、Search Results 等大型列表使用 Virtual Window + overscan。

### PRIVACY-001

任何 Tracker/Announce URL 在显示、筛选 key、UI 本地状态中必须先脱敏 query/fragment credential/passkey/token。

### DEPLOY-001

自动安装/升级必须可备份、可验证、可回滚；多 qB Docker 实例不得猜目标。

## 7. Contextual Search

Topbar Search 根据 Route 工作：

```text
/#/          Torrent name/library search
/#/settings Settings search
/#/search   Search Engine query
/#/rss      RSS filter/search
/#/logs     Log filter/search
```

不同 Feature 的 search controller 必须隔离。不能在 Settings 页面输入搜索词时同时触发后台 Torrent 搜索/分页。

## 8. i18n Architecture

运行时：

```text
English canonical dictionary
        ↓
Locale overlay
        ↓
Missing key?
        ↓ yes
English fallback
```

当前目标 Locale：

```text
en
zh-CN
zh-TW
ja
ko
```

关键文件：

```text
webui/private/scripts/i18n.js
webui/private/scripts/settings-schema.js
webui/private/scripts/settings-translations.js
```

登录页也必须根据浏览器语言自动选择，不允许登录页和登录后界面使用完全不同的语言策略。

### qB 翻译来源

qB 已有术语优先参考官方仓库：

```text
qBittorrent/qBittorrent
src/webui/www/translations/
```

例如简体中文：

```text
webui_zh_CN.ts
```

WeiG 独有词条，例如 Nebula Noir、Starfield、Density、Performance Diagnostics，由项目自身 translation layer 维护。

### Raw key policy

```text
auto_tmm_enabled
web_ui_port
web_ui_csrf_protection_enabled
```

可以用于 API/schema/search metadata，但普通 Settings 卡片必须显示人类可读名称和说明。

## 9. Torrent 分页与 LargeList

用户可以选择：

```text
20
50 (default)
100
200
```

普通列表优先直接使用 qB：

```text
filter
category
tag
sort
reverse
limit
offset
```

需要全库名称/Tracker/SavePath/PT 过滤时，在后台以有限批次建立 Data Catalog；Catalog 仅保存数据，不映射为隐藏 DOM。

VirtualList 只渲染 viewport + overscan。

目标：

```text
Desktop Torrent DOM 通常约 20–60，prefer <100
Mobile Torrent DOM prefer <=50
```

主界面只显示产品信息；DOM/Cache/Render 等进入 Settings → Performance。

## 12. Tracker / PT / Private

Normalizer：

```text
https://tracker.m-team.cc/announce?credential=SECRET
→
https://tracker.m-team.cc/announce
```

## 15. Settings Architecture

### 15.1 Metadata-driven Settings

数据流：

```text
/app/preferences
↓
actual returned keys/types
↓
SettingsSchema metadata
↓
localized title + description
↓
canonical control
↓
responsive Setting Card
```

Settings 不是原始 API Object Editor。

Known metadata 可定义：

```text
canonical English title
description
section
kind/control
units/options
capability constraints
translation
```

未知 key 使用 humanized English fallback；不得因为新 qB 增加 Preference 就让整个 Settings 崩溃。

### 15.2 Settings layout

Desktop：

```text
Normal desktop → 2 columns
Very wide desktop → up to 3 columns
Tablet / Mobile → 1 column
```

每个 Card 内部优先紧凑，不让一个普通 Toggle 浪费整行宽屏空间。

### 15.3 Canonical controls

```text
boolean → Switch
text/path → Input
enum → Select
number → numeric Input/control
```

### 15.4 Settings Search

搜索可以匹配：

```text
current locale title
canonical English title
description
internal key
```

但 internal key 不必在正常 Card 中可见。

### 15.5 WeiG Settings

```text
Language: Automatic / en / zh-CN / zh-TW / ja / ko
Theme: System / Dark / Light
Font: Standard / Large(+2px) / XLarge(+3px)
Density: Compact / Standard / Comfortable
Starfield: Off / Subtle / Full
Motion
Page Size: 20 / 50 / 100 / 200
Refresh: 1 / 2 / 5 / 10s
Column layout
PT Tracker rules
Performance diagnostics
```

### 15.6 qB Settings

主分组：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

只显示当前 qB `/app/preferences` 实际返回/允许编辑的设置。

## 16. Search / RSS / Logs

入口 capability-aware：

- Search API 不支持 → 应用导航入口隐藏；
- RSS 不支持 → 入口隐藏；
- Logs 不支持 → 入口隐藏。

Topbar 与 Mobile Bottom Nav 的重复入口必须共享同一个 capability state。

## 17. Refresh Engine

```text
Visible Torrent dynamic data: default ~2s
Transfer info: ~2s
Static Preferences: on demand
Detail lists: view/tab active 时
Background browser tab: ~10s or lower priority
```

失败不得毫秒级死循环。

## 19. Installer

Linux installer：

```text
--list-containers
--container=NAME
--config-root=/host/config/root
--dir=/container/or/local/path
--configure
--rollback
```

多 qB Docker 实例必须显式选目标。识别 `/config` bind mount 后，在宿主机真实目录部署，而向 qB 输出容器可见 Root Folder。

必须排除 Docker overlay/rootfs 模板配置。

安装成功前验证：

```text
public/login.html
private/index.html
```

Windows 保持对应安装/备份/回滚能力。
