# 001. 项目总方案

Status: **current project plan**

WeiG qB WebUI 是 qBittorrent Alternate WebUI。当前 `dev` 只维护一套现行架构，不在工作树中保存 WeiG 自身旧版本 runtime、tests 或 deploy scripts；历史实现由 Git history / tags / Releases 保存。

## 1. Identity

```text
Product version  -> VERSION / webui/VERSION / package.json.version
Code identity     -> exact Git SHA / GIT_SHA
Distribution      -> Git tag / GitHub Release
```

产品 VERSION 的唯一 bump trigger 是正式 `webui/**` 产品内容变化。仅修改 tests、fixtures、workflow、docs、DESIGN、installer、CI/gate、package test tooling、test dependency 或 lockfile 时保持当前产品 VERSION；一旦 `webui/**` 变化，三个 version source 必须在同一最终 tree 中同步递增。无论 VERSION 是否变化，每个新 commit 都有新的 exact SHA，旧 SHA 的 CI/LIVE/candidate/artifact 证据不继承。

文件名不承担版本身份；Current semantic identifier 也不承担 revision identity。First-party 名称使用稳定职责名，numeric revision suffix 由 Git history 取代。

## 2. Compatibility

当前支持从 qBittorrent 4.1.9.1 起覆盖官方 4.x / 5.x，并以 capability-driven 方式处理差异。当前稳定上界 5.2.3；supported stable range 共 **55 个官方稳定 release = 40 qB 4.x + 15 qB 5.x**。

必须保留当前兼容事实：

```text
Private/PT: 此功能需要 qBittorrent 5.0.0+
Tags: WebAPI 2.3.0+
Representative CI/browser generations: qB 4.1.9.1 + 5.2.0
Full stable-tag compatibility audit: all supported releases from 4.1.9.1
```

## 3. Architecture

```text
qB WebAPI
→ W.QBClient
→ canonical business owner
→ semantic lifecycle / source DOM
→ canonical component/presentation owner
→ layout / responsive / theme
```

One semantic purpose = one Current Owner。禁止 compatibility shim、second owner、MutationObserver repair、presentation API polling、N items -> N API fallback。

## 4. UI

Desktop Torrent 是数据工作台：Topbar actions；Sidebar filters/facets；Workspace DataGrid；Statusbar Torrent/storage/Transfer/Connection。

Mobile 复用同一 business state / canonical controls，只改变 adaptive placement；Desktop/Mobile 都不建立第二套 Summary、filter、sort、polling 或业务状态 owner。

## 5. Browser CI runtime

Browser automation dependency 由 repository 固定：

```text
package.json + package-lock.json
→ Playwright 1.62.1 exact pin
```

Browser launch policy 只有一个 Current Owner：

```text
tests/browser-driver.mjs
```

Linux routine UI、Linux candidate、Windows candidate 都复用 GitHub-hosted runner 已提供的 Google Chrome Stable。六套 `browser-*.mjs` 只是 semantic/visible-state callers，不直接 import Playwright、不选择 channel/executablePath，也不实现 fallback。

Linux/Windows Browser coverage 是 qB4 floor + qB5 modern 的 representative semantic generations；它不等于在两个 OS 上分别启动 55 个 qB binary。完整 supported stable-tag compatibility 由 Full qB Release compatibility audit 负责。

CI browser path 禁止：

```text
npm install --no-save playwright@...
playwright install / install-deps
manual Chromium download
browser-specific apt provisioning
silent fallback
```

Hosted Chrome 缺失时 fail closed。每次 browser evidence 记录 exact Git SHA、package-lock、runner image、Playwright version 和实际 Chrome version；Hosted Chrome 可以随 runner image 更新，因此这是可追溯 evidence，不声称同一 SHA 永远重放同一 browser binary。

## 6. Release

```text
dev exact SHA
→ current contracts/naming/syntax
→ representative upstream audit
→ focused Hosted Chrome browser gate when UI-affecting
→ real qB4 + qB5 LIVE
→ explicit maintainer authorization
→ fast-forward main same SHA
→ main-only full 55-stable-tag candidate + Linux/Windows representative Hosted Chrome matrices
→ tag same SHA
→ verify + publish same artifact
```

任何 tree change 都产生新 SHA，旧证据不继承；只有 `webui/**` 产品变化才同时递增产品 VERSION。

## 7. Current-only repository

禁止为新版创建 `foo-vNext.js`、`browser-vNext.mjs`、`live-vNext.sh`、`live-qbNN.sh`、version-labelled docs。无 current owner/caller 的旧文件直接删除；Git history 是 archive。

`tests/naming-contract.mjs` 是 stable filename / semantic naming policy 的唯一 gate；`tests/syntax-contract.mjs` 只负责 JavaScript syntax。
