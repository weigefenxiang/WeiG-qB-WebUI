# 001. 项目总方案

Status: **current product plan / AI handoff entry**

WeiG qB WebUI 是 qBittorrent Alternative WebUI。**`webui/**` 是唯一正式产品；真实 qBittorrent 4.x / 5.x 稳定版兼容是最高目标。** Simulator、source catalog、WebAPI evolution ledger、Endpoint/Transport Contract 都是辅助发现与验证工具，不是产品本身。

详细产品兼容路线统一见 [`010.真实qB产品兼容路线.md`](./010.真实qB产品兼容路线.md)。Virtual qB 的辅助验证边界见 [`009.Virtual-qB-Lab.md`](./009.Virtual-qB-Lab.md)。

## 1. 产品目标

同一份：

```text
weig-qb-webui/webui/*
```

放到受支持的真实 qBittorrent 4.x / 5.x stable 上，应自动识别 qB/WebAPI/capability 并正常工作。用户不需要手工选择版本、切换另一套 WebUI 或维护 patch-specific 配置。

兼容策略不是“旧版没有同名新 API 就隐藏”。正确优先级：

```text
原生等价 API
-> request/response normalization
-> 可靠的旧 API 组合/emulation
-> 基于已有 canonical data 的本地推导
-> 真正无法实现时才 capability gap/hide/read-only
```

不允许伪造真实 qB 无法提供的数据，也不允许为了兼容制造不可控的 N->N 网络放大。

## 2. 当前范围与目标范围

长期产品目标：**qBittorrent 4.x / 5.x official stable**。

当前已经建立的 WebAPI v2 structural/evolution matrix：

```text
qB 4.1.0 -> latest official stable
current tested latest: qB 5.2.3
current audited WebAPI ceiling: 2.15.1
65 official stable profiles
```

qB 4.0.x 属于旧 WebAPI v1，当前未被主线覆盖。如果“所有 qB4 stable”作为最终要求，则需要独立 Legacy WebAPI v1 Adapter，把 v1 映射到同一 WeiG canonical semantics；禁止把 v1/v2 判断散落到 UI caller。

## 3. Identity / VERSION

```text
Product version  -> VERSION / webui/VERSION / package.json.version / package-lock.json root version
Code identity     -> exact Git SHA
Distribution      -> Git tag / GitHub Release
```

只有正式 `webui/**` 产品内容变化才 bump 产品 VERSION。Simulator/tests/tools/workflow/docs/DESIGN-only 改动保持 VERSION；但任何新 commit 都产生新的 exact SHA，旧 SHA 证据不继承。

## 4. 产品架构主链

```text
UI / presentation
-> canonical WeiG state/semantics
-> W.QBClient + product compatibility normalization
-> W.ReleaseProfile / W.CapabilityRegistry / W.SettingsSchema / W.TorrentSemantics
-> real qB WebAPI
```

UI/presentation 不应到处判断具体 qB/WebAPI patch。版本差异尽可能在产品 compatibility owner 截止。

已有代表性产品兼容逻辑包括：

```text
qB4 resume/pause <-> WeiG start/stop <-> qB5 start/stop
qB4 paused filter <-> canonical stopped <-> qB5 stopped filter
editTracker legacy origUrl <-> modern url
legacy torrents/add Ok./Fails. <-> modern structured result normalization
```

后续工作的中心是系统审计整个 `webui/**`，不是只继续增强 simulator。

## 5. Phase E — Real qB Product Compatibility — ACTIVE

Phase E 是当前主阶段。

第一步建立完整产品功能矩阵：

```text
WeiG feature
-> UI entry
-> product owner / QBClient call
-> upstream endpoint(s)
-> qB4 behavior
-> qB5 behavior
-> request/response differences
-> normalization exists?
-> reliable emulation possible?
-> unavoidable gap?
-> virtual test?
-> real-qB evidence?
```

第一批优先审计：

1. Torrent 状态筛选；
2. Tracker / 路径 / 分类 / 标签 facets；
3. Columns / field availability；
4. Torrent actions；
5. Settings：下载 / 连接 / 速度 / BitTorrent / Web UI / 高级；
6. Search / RSS / Logs。

完成一个大批次后必须停下复盘，由用户拍板下一方向。

## 6. Structural/evolution infrastructure — 辅助层

现有基础设施仍然有价值：

```text
qB upstream source
-> source parsers
-> qb-release-catalog
-> qb-releases.json
-> W.ReleaseProfile
```

回答 endpoint/Preference/Torrent surface “有没有”。

WebAPI evolution ledger 回答历史上“怎么变过”。Simulator Endpoint/Transport Contract 用于准确模拟这些历史差异。

但新优先级是：

```text
发现 upstream 差异
-> 先判断是否影响 webui/**
-> 影响产品：优先修改/验证 webui/** compatibility
-> 产品不消费：可留作低优先级 simulator fidelity
```

不能再以 simulator `MISSING` 数字下降作为产品主进度。

## 7. Virtual qB 的正确位置

```text
real product webui/**
        ^
        | validate
Virtual qB / source catalog / ledger
```

Simulator 必须在 `W.QBClient` 后面模拟 qB，不得 monkey-patch 产品 client、增加 Demo-only 产品 state 或让产品依赖 simulator-only API。

Simulator PASS 是辅助证据，不能替代真实 qB PASS。

## 8. UI 自动适配范围

截图/正式产品中的以下 UI 都属于 Phase E：

- Torrent filters：全部、下载中、做种中、已完成、已停止、运行中、活动、非活动、停滞、上传停滞、下载停滞、校验中、移动中、错误、Private/PT；
- facets：Tracker、路径、分类、标签；
- Columns：Name、Size、Progress、Download、Upload、ETA、Status、Ratio、Tracker 等；
- Settings：下载、连接、速度、BitTorrent、Web UI、高级；
- Search、RSS、Logs；
- Add/Delete/Start/Stop/Force Start/Recheck/Reannounce；
- Files/priorities、Trackers/WebSeeds、Peers、Categories/Tags、Metadata/Torrent Creator、Transfer 等。

它们都应该跟随真实 release 自动适配，而不是用户手工选 qB4/qB5。

## 9. Validation

开发验证按层次：

```text
source/evolution evidence
-> product compatibility contracts
-> Virtual qB multi-profile browser tests
-> representative real qB4/qB5 tests
-> promotion-time frozen real-qB LIVE
```

Virtual Pages 证明同一正式 `webui/**` 在模拟历史 profile 下工作，但不能冒充真实 qB binary LIVE。

## 10. Git discipline

- 正式开发分支 `dev`；未经用户明确授权不动 `main`；
- 写前和 ref 更新前 fresh-read exact `dev`；
- 只允许 `force:false` fast-forward；
- 新 SHA 重新验证；
- product truth 与 stale test 冲突时先确认 upstream/real runtime truth；
- 不为了测试变绿回退正确产品行为。
