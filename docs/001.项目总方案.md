# 001. 项目总方案

Status: **current project authority / stable project overview**

WeiG qB WebUI 是 qBittorrent Alternative WebUI。`webui/**` 是唯一正式产品；source catalog、真实 qB harness、Virtual qB、browser/Pages 与 CI 都是发现、验证和发布设施，不能反过来定义产品语义。

本文件只维护长期目标、正式边界、authority 与当前高层状态。**Git history 是版本历史档案；docs 不再按 WeiG 版本号新增“复盘/下一 AI 交接”文件。** 已完成工作形成长期规则时写回对应 authority；当前未完成事项只维护在 `docs/014.AI协作与分支纪律.md`。

## 1. 长期目标

同一份正式 `webui/**` 应覆盖：

```text
qBittorrent 4.1.0 official stable
-> all admitted official stable releases
-> current latest official stable
-> future official stable / future major
```

兼容策略优先级：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY when applicable
-> UNAVAILABLE
-> UNKNOWN when facts are not provable
```

未来或未收录版本不能因为版本号更高就自动继承 current latest 全部语义，也不能按 major 整体拒绝。`UNKNOWN` 只关闭无法证明的具体能力；危险写操作必须在 HTTP 前 fail closed。

qB 4.0.x / WebAPI v1 不在当前正式支持范围。若未来用户明确扩大范围，只允许通过集中 Legacy Adapter 映射到 canonical WeiG semantics，禁止在 UI/caller 散落 v1/v2 分支。

### 1.1 Universal Portable 是正式产品形态

正式 WeiG WebUI 必须长期保持：

```text
同一份 materialized WeiG-qB-WebUI/
-> 可复制到任意受支持 qB 主机
-> qB 指向该 Alternative WebUI 目录即可运行
-> 正常运行不依赖 tools/**、simulator/**、CI、GitHub 或在线服务
-> 离线时仍保留已声明的正式产品能力
```

完整 upstream source、历史 release catalog、Settings/translation LKG、recovery bodies 与验证数据可以很大，但它们属于 build/source/evidence。最终用户 runtime 只应携带浏览器和 qB WebApplication 真正消费的最小 runtime IR/asset。

## 4. Truth hierarchy

行为真值优先级：

```text
qB official source + exact admitted profile
-> canonical WeiG runtime owner
-> real qB evidence where runtime/hosting behavior requires it
-> browser / Virtual qB / Pages evidence
-> docs / tests / fixtures
```

旧 prompt、stale test、Simulator 或旧 docs 与已确认 source/runtime truth 冲突时，应更新旧内容，不能为了旧断言恢复错误 owner、错误 capability 或不安全写行为。Source parser 遇到未知 upstream 结构必须 fail closed。

## 5. Current Owner 与产品实现原则

一个 semantic purpose 只能有一个 Current Owner。正式 owner 切换必须 atomic cutover：

```text
new owner proven
+ callers switched
+ tests/contracts updated
+ docs/DESIGN updated when needed
+ superseded owner/state/event/polling/helper retired
```

禁止 old/new 双 active、MutationObserver repair、monkey patch、post-render repair、第二 polling/state/layout/language owner，以及 feature-local 重造 canonical UI 工具。Desktop/Mobile 是同一业务 state 的 adaptive presentation，不是两套应用。

## 6. 分支与 exact-SHA 纪律

长期 canonical branches：

```text
dev   normal development / fix / docs / validation
main  validated promotion result
```

所有修改先进入 `dev`。每个 mutation batch 前 fresh-read 当前 `dev`；更新 ref 前再次 fresh-read 做 race check；只允许 safe fast-forward，禁止 force push。

未经用户明确授权不得移动 `main`、formal promotion、tag、GitHub Release、手动触发 Candidate、Current Stable Locale Matrix 或 Real qB Full Frozen Matrix。

Exact Git SHA 是 code、CI、Pages、candidate、matrix、promotion 与 Release evidence 的身份。旧 SHA 的 PASS 不自动证明新 SHA；`SKIPPED != PASS`。

## 7. Locale / translation 原则

唯一 persisted language truth：`qB app/preferences.locale`。qB-owned wording采用 native-first exact source/context → source-bound translator behavior → official QM where source-proven → exact official-TS bridge only for proven Alternative WebUI gap。

`4.5.0 -> 4.6.4` Alternative WebUI document-translation gap 是 source-proven hard boundary，必须保留 exact bridge。WeiG 自有功能文案由 WeiG 自己负责；qB upstream 已拥有并有 exact source/context 的文案不得再维护第二套手写翻译表。

## 8. Distribution / Windows 安全原则

Dev installer只消费 Pages materialized distribution，不允许 raw-source fallback。Stable installer只消费 immutable GitHub Release identity与checksum。Universal Portable 继续要求同一 materialized WebUI 目录可离线复制到受支持 qB 主机直接使用。

`qb-release-profiles` 当前仍承担 exact source/capability/write safety，不得在没有用户新授权时继续做 Batch B profile runtime-IR dedupe或其它重构。

Windows qB config 外部修改必须 strict decode/round-trip、byte-identical backup、temp write、invariant reread、target-unchanged check、safe replace、post-write verify；禁止 PowerShell whole-file `Get-Content/Set-Content` 转码路径。
