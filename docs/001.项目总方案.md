# 001. WeiG qB WebUI 项目总方案

Status: Project baseline  
Primary repository: `weigefenxiang/WeiG-qB-WebUI`  
Compatibility floor: qBittorrent 4.1.9

## 0. 启动原则

新 AI、新开发者或新会话不要根据聊天记忆猜项目。正式提出实现方案或修改代码前，至少完成：

```text
1. 读取本文件
2. 读取根目录 DESIGN.md（仅 UI/视觉相关任务必须详细读取）
3. 查看 README.md
4. 查看真实 Git branch / HEAD / working state
5. 查找已有组件、API helper、Adapter、LargeList、Router、Installer 能力
6. 明确本次改动影响的兼容版本、Desktop/Mobile、DOM/性能与回归范围
7. 优先复用或扩展已有能力，最后才新建
8. 实施后完成对应测试与文档收尾
```

## 1. 项目定位

WeiG qB WebUI 是一个面向 qBittorrent 的高品质 Alternate WebUI，目标是同时做到：

- 界面漂亮、统一、现代；
- qBittorrent 4.1.9 强兼容；
- 4.2.x–4.6.x 渐进增强，并为后续版本保留适配层；
- Desktop 与 Mobile 同等重要；
- 数千甚至更多 Torrent 时仍保持稳定 DOM 与流畅交互；
- GitHub Release 可直接部署，并提供 Linux / Windows 安装、更新、备份与回滚；
- 所有页面都有明确返回路径，任何 Feature 错误都不能把用户困住。

## 2. 核心硬规则

### COMPAT-001 — qBittorrent 4.1.9 是硬基线

任何 Release 如果 qBittorrent 4.1.9 核心回归失败，即使 4.6.x 正常，也禁止发布。

兼容等级：

```text
Tier 0  qBittorrent 4.1.9   Release blocking
Tier 1  qBittorrent 4.2.x   Supported
Tier 1  qBittorrent 4.3.x   Supported
Tier 1  qBittorrent 4.4.x   Supported
Tier 1  qBittorrent 4.5.x   Supported
Tier 1  qBittorrent 4.6.x   Supported
Tier 2  qBittorrent 5.x+    Future adapter / progressive support
```

### UI-001 — 设计只有一个权威

任何 UI、主题、动画、卡片、按钮、Tooltip、移动端视觉或布局设计修改，都必须先读取并遵循根目录 `DESIGN.md`。

### NAV-001 — No Dead-End Navigation

任何非首页视图必须存在可靠 Back；错误状态至少保留 Retry / Back / Home 中的恢复路径。

### MOBILE-001 — Mobile 是一等平台

手机不是 Desktop 缩小版，允许使用独立 Shell、Torrent Card、Drawer、Action Sheet 和触控交互，但必须复用同一 API、Domain、Store 与标准组件能力。

### PERF-001 — Torrent 默认每批 50

Torrent 列表默认 API Batch：

```text
PAGE_SIZE = 50
```

优先使用 qBittorrent API 的 `limit` / `offset` 做服务端分批，而不是先拉取全部 Torrent 再前端隐藏。

### PERF-002 — Data Count != DOM Count

加载、缓存的数据数量与 DOM 节点数量必须解耦。

```text
5000 Torrent models
!=
5000 Torrent DOM rows
```

所有大型列表必须进入统一 LargeList / Virtual Window 能力。

### PERF-003 — 大列表窗口化

Torrent、Files、Peers、Trackers、Logs、Search Results、RSS Items 等大列表必须根据 API 能力采用：

```text
Server Pagination + Virtual Window
```

或在 API 无法分页时采用：

```text
Data Cache + Virtual Window
```

### DEPLOY-001 — 安装必须可逆

任何自动安装、自动配置或升级都必须先备份，并提供明确 Rollback。

## 3. 技术路线

生产运行时保持轻量：

```text
HTML
CSS
JavaScript Modules
SVG
JSON
```

开发阶段可使用 Node.js、bundler、lint、unit/e2e/visual tooling；正式 Dist 不要求用户安装 Node.js，也不依赖 Vue、React、大型 UI Runtime 或远程 CDN。

目标：最终 Alternate WebUI 目录可被 qBittorrent 直接作为静态 `WebUI\RootFolder` 使用。

## 4. 总体架构

严格数据流：

```text
UI Components
      ↓
Feature Controller
      ↓
Store
      ↓
Domain Model
      ↓
Normalizer
      ↓
Compatibility Adapter
      ↓
qB API Client
      ↓
qBittorrent WebAPI
```

禁止 Feature/UI 直接散落调用 `/api/v2/*`。

## 5. qB Compatibility Layer

建议：

```text
src/qb/
├─ client.js
├─ auth.js
├─ bootstrap.js
├─ version.js
├─ capabilities.js
├─ endpoints/
├─ normalizers/
└─ adapters/
   ├─ base.js
   ├─ qb-4.1.js
   ├─ qb-4.2.js
   ├─ qb-4.3.js
   ├─ qb-4.4.js
   ├─ qb-4.5.js
   ├─ qb-4.6.js
   └─ qb-future.js
```

业务 UI 不直接判断：

```text
qBVersion === 4.6
```

而查询：

```text
capabilities.renameFolder
capabilities.tags
capabilities.search
...
```

Capabilities 可由以下信息综合生成：

```text
qBittorrent Version
+
WebAPI Version
+
Known Compatibility Matrix
+
必要时 Endpoint/Behavior Probe
```

版本探测用于建立能力，不把版本分支扩散到 UI。

## 6. Domain Model

UI 面对稳定 Domain Model，不直接消费不同 qB 版本的原始 JSON 差异。

首批 Model：

```text
Torrent
TorrentFile
Peer
Tracker
Category
Tag
TransferInfo
ApplicationInfo
Preference
```

例如旧版本没有某字段时，由 Normalizer 统一给出明确的 `null` / capability state，而不是让多个页面自行判断 `undefined`。

## 7. Store 与渲染

建议：

```text
src/store/
├─ app-store.js
├─ torrent-store.js
├─ transfer-store.js
├─ preference-store.js
└─ ui-store.js
```

不引入大型状态管理 Runtime。

Torrent 使用 `hash` 作为稳定 Key。

动态刷新：

```text
API response
→ Normalize
→ Store diff
→ Single render schedule
→ Patch changed visible rows only
```

禁止每次轮询 `innerHTML` 重建整个 Torrent 列表。

## 8. LargeList Engine

建立项目级通用 LargeList，不允许各 Feature 自建分页/虚拟列表逻辑。

职责：

```text
Server pagination
Virtual window
Overscan
Scroll position
Stable keys
Page cache
Cache eviction
Load more
Classic page fallback
Loading / Empty / Error state
```

### 8.1 Torrent API 分批

默认：

```text
limit=50&offset=0
limit=50&offset=50
limit=50&offset=100
...
```

允许用户后续选择 25 / 50 / 100；默认推荐 50。

筛选、排序或分类变化时重置 offset，从第一页重新获取，避免只对当前已加载小样本做“假全局排序”。

### 8.2 无限滚动

可以支持 Infinite Scroll，但其含义必须是：

```text
Infinite Data Navigation
!=
Infinite DOM Growth
```

数据缓存可以累积有限页，DOM 只保留 viewport + 少量 overscan。

### 8.3 DOM Budget

目标值：

```text
Desktop Torrent DOM:
通常约 20–60 visible/overscan rows，建议保持 <100

Mobile Torrent DOM:
建议 <=50
```

最终预算通过真实设备和浏览器测试调整，但绝不允许 DOM 与 Torrent 总数线性增长。

### 8.4 Cache

允许缓存多个 Torrent Page，例如 150–250 个 Model；手机可以更小。滚动极远时允许淘汰远端页，再返回时重新获取。

## 9. Refresh / Polling

初始建议值不是永久常量，必须以真实性能和 qB 行为测试调整：

```text
Visible Torrent dynamic data   ~2s
Transfer status                ~1–2s
Preferences/static config      on demand
Detail-only data               when detail view/tab is active
```

使用 Page Visibility API：

- 前台正常刷新；
- 后台 Tab 大幅降频或暂停非必要请求；
- 网络错误采用 progressive backoff；
- 不允许错误后毫秒级重复请求。

## 10. Desktop / Mobile 架构

共享：

```text

```


## 11. Mobile 专项要求

至少覆盖：

```text

430px
768px
```

- Portrait / Landscape；
- Drawer；
- Torrent List；
- Torrent Detail；
- Add Torrent；
- Dialog；
- More Menu / Action Sheet；
- 软件键盘弹出；

- 1000+ / 5000+ 模拟 Torrent 数据源；
- 非活动 Detail Tab 是否正确释放重 DOM。

## 12. Navigation

默认使用 Hash Router，避免依赖 qB 静态服务器提供 SPA history fallback：

```text
/#/
/#/torrent/HASH
/#/torrent/HASH/files
/#/torrent/HASH/peers
/#/settings
/#/search
/#/rss
/#/logs
```

统一 `NavigationService`。

Back 顺序：

```text
Internal App History
→ valid Browser History
→ Home fallback
```

Feature 不自行散落调用 `history.back()`。

## 13. Error Boundary / Safe Recovery

Feature JS/API 错误只影响当前 Feature，App Shell 尽量继续存在。

最低恢复能力：

```text
Back
Home
Reload
```

无法加载 Torrent 时不能出现完全空白、乱码后无按钮或不可操作页面。

## 14. UTF-8 与文本安全

所有源码：

```text
UTF-8
LF
```

HTML 必须明确 UTF-8 charset。

禁止遗留式 `escape` / `unescape` / 错误二次 decode。

测试 Torrent 名称：

```text
中文
日本語
한국어
Русский
Emoji 😀
特殊符号
超长文件名
```

DOM 文本默认使用安全文本写入，避免无必要 `innerHTML`。

## 18. GitHub 发布与部署

GitHub 负责：

```text
Source
CI
Release
```

Release 目标产物：

```text
weigg-qb-webui-vX.Y.Z.zip
install.sh
install.ps1
SHA256SUMS
```

正式 qB Alternate WebUI 使用的是本地目录，不是 GitHub URL：

```text
GitHub Release
→ Installer / manual extraction
→ Local WebUI folder
→ qBittorrent WebUI\RootFolder
```

## 19. Linux Installer

`install.sh` 目标能力：

```text
Detect OS
Detect qB installation/config where possible
Search common paths
Detect existing Alternate WebUI
Allow manual target path
Download Release
Verify checksum
Backup old WebUI/config
Deploy dist
Optionally configure qB
Print final RootFolder
Rollback
Update
```

路径搜索不能只写死一个目录；需兼顾常规 Linux、Docker bind mount、自定义 `/config/...` 等实际部署。

## 20. Windows Installer

`install.ps1` 目标能力相同，重点检测：

```text
%APPDATA%\qBittorrent
Portable/custom layouts
Existing qB config
Existing Alternate WebUI root
Manual destination
```

自动改配置必须是可选项，并在修改前备份。

## 21. Manual Install 永远保留

即使自动安装器成熟，也永远提供：

```text
Download ZIP
→ Extract
→ Copy folder
→ User pastes local folder into qBittorrent Alternate WebUI setting
```

安装器应明确输出可复制的最终目录。

## 22. Backup / Rollback / Update

必须支持：

```text
install.sh --rollback
install.ps1 -Rollback
```

回退至少恢复：

- 旧 WebUI 文件；
- 原 RootFolder；
- 原 AlternativeUIEnabled 状态（如果安装器曾修改）；
- 安装前配置备份。

升级流程：

```text
Check Release
→ Download
→ Verify
→ Backup
→ Atomic-ish replace
→ Health check where possible
→ Rollback on failure
```

## 26. 收尾原则

任何重要架构或长期规则改变：

- 更新本方案或新增 ADR；
- UI/视觉规则变化更新 `DESIGN.md`；
- 不把临时 Bug、一次性环境信息伪装成长期规则；
- 完成任务前明确说明修改范围、测试结果、兼容影响和是否存在遗留风险。

## 27. 项目完成定义

第一代 WeiG qB WebUI 不是只做到“比现有 WebUI 更漂亮”，而是同时达到：

```text
Premium UI
+
qBittorrent 4.1.9 stable
+
4.2–4.6 progressive compatibility
+
first-class mobile
+
50-item server batching
+
bounded virtualized DOM
+
one-click/manual deployment
+
backup and rollback
+
no dead-end navigation
```

其中任意关键项缺失，都不视为第一代架构完成。
