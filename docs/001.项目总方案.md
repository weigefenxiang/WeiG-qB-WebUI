# 001. 项目总方案

Status: **current product plan / AI handoff entry**

WeiG qB WebUI 是 qBittorrent Alternative WebUI。**`webui/**` 是唯一正式产品；核心目标是从 qBittorrent 4.1.0 起覆盖全部 official stable，并优先保证当前 stable 与未来 stable/new major 自动适配。** Simulator、source catalog、WebAPI evolution ledger、Endpoint/Transport Contract 都是辅助发现与验证工具，不是产品本身。

详细产品兼容路线见 [`010.真实qB产品兼容路线.md`](./010.真实qB产品兼容路线.md)；当前兼容事实见 [`002.兼容与实现状态.md`](./002.兼容与实现状态.md)；发布/CI 分层见 [`006.发布与晋级流程.md`](./006.发布与晋级流程.md)。

## 1. 产品目标

同一份：

```text
webui/**
```

应能够：

```text
qB 4.1.0
-> all 4.x official stable
-> all 5.x official stable
-> current latest stable
-> future stable / qB6.x / qB7.x / future x.x.x
```

自动识别真实 release/WebAPI/source capability，自动选择 native / normalized / adapter / reliable old-API composition / derived / read-only / unavailable；用户不需要手工选择 qB4/qB5/qB6 专用包，也不维护 patch-specific 配置。

兼容优先级：

```text
native equivalent API
-> adapter / request-response normalization
-> reliable old-API composition
-> reliable local derivation from canonical data
-> read-only when applicable
-> truly unavailable only then hide/disable
```

禁止伪造真实 qB 无法提供的数据，也禁止为了兼容制造不可控的 N->N 网络放大。

## 7. Phase D — Incremental Future Stable Admission / Last Known Good — DONE

Phase D 将 Phase C 已验证的 65-profile catalog 固化为 Last Known Good，并建立未来 official stable 的增量接纳链。

Frozen LKG：

```text
tests/fixtures/qb-release-catalog.lkg.json
qB 4.1.0 -> 5.2.3
65 profiles
SHA-256 8b91742ac8eee276b7994c84445c681913430f220325a10afc8c931c89645ddb
```

正式流程：

```text
verify frozen LKG
-> lightweight compare official stable tag names
-> no new stable: exit immediately
-> new stable: checkout upstream source only then
-> source-extract only new stable profiles onto frozen prefix
-> diff against previous admitted stable
-> source audit support floor + new refs
-> product gate on support floor + previous LKG + new profiles
-> repository contracts / architecture guard
-> upstream + product capability diff
-> all gates PASS
-> fresh-check dev exact SHA
-> safe fast-forward catalog + manifest admission only
```

如果 parser、新 API/response/write semantics、产品 owner 或 regression 无法证明，状态为 `PENDING_REVIEW` / fail closed，candidate 不进入正式 LKG，旧 LKG 不变。

历史 65-profile product regression 只在通用 product compatibility owner / product-matrix contract 变化时运行，并直接消费 frozen profiles；不会因此重新 source-extract 旧 stable。

Architecture guard scoped 到 `webui/private/scripts/**`，在 exact checkout 上读取全部 `.js` 完整文件内容，阻止新增 scattered qB version-if。Repo-wide ownership/absence/proof 的最终结论必须绑定目标 exact SHA，并基于该 SHA 的完整 tree/blob/file；code search/snippet 只能用于发现候选。

## 9. Git discipline

- 正式开发分支 `dev`；未经用户明确授权不动 `main`；
- 每轮写入前 fresh-read exact `dev`，candidate 只以该 SHA 为 parent；
- ref update 前再次 fresh-read；若移动则 candidate 作废重建；
- ref 更新只允许 `force:false` safe fast-forward，禁止 force push；
- repo-wide proof 只认目标 exact SHA 的完整 tree/blob/file；
- product truth 与 stale test 冲突时先确认 upstream/real runtime truth；
- 不为了测试变绿回退正确产品行为。
