# 001. WeiG qB WebUI 项目总方案

Status: **v0.3.7 / Responsive UI System 3.3**  
Repository: `weigefenxiang/WeiG-qB-WebUI`  
Compatibility floor: **qBittorrent 4.1.9.1 / WebAPI 2.2.1**  
Current product version: **0.3.7**

## 1. 产品定位

WeiG qB WebUI 是长期维护的 qBittorrent Alternate WebUI。目标不是针对截图持续补丁，而是建立可复用、可测试、可迁移的 UI / interaction / compatibility system。

长期原则：

```text
一个业务模型
一套组件语义
一个语义一个 owner
桌面 / 手机响应式呈现
高信息密度但不牺牲可读性
qB 老版本可用，新能力渐进增强
精确 Git SHA 身份
Release 作为稳定分发事实源
真实环境可验证、可回滚
```

设计方法参考 `VoltAgent/awesome-design-md` 的 DESIGN.md 体系：把视觉氛围、颜色角色、Typography、Component、Layout/Spacing、Depth、Do/Don't 与 Responsive Behavior 写成代码代理可直接执行的规则。参考的是方法，不复制其它品牌界面。

## 2. 分支与验证

```text
dev   开发、smoke、4.1.9.1 + 5.2.0 日常兼容、必要时一个 focused Linux UI gate
main  Release 准备线；全 qB stable tags、Linux/Windows、多 viewport 只在手动 candidate 运行
```

Canonical Release chain：

```text

→ dev implementation

→ exact-SHA LIVE: qB 4.1.9.1 + 5.2.x
→ fast-forward main to same SHA
→ main validation_mode=candidate

→ reusable exact-SHA artifact
→ tag same SHA
→ GitHub Release publishes the same artifact
```

## 3. 应用架构

```text

  ↓
QBClient + capability normalization
  ↓
Shared application state / models
  ↓
PreferenceSchema / semantic registries
  ↓
Canonical components and layout owners
```

禁止 desktop/mobile 两套业务应用。手机 adaptive layer 只负责 layout、density、touch interaction 和 presentation。

## 4. Responsive UI System 3.3 重点

### 4.1 Settings

所有设置页面统一：

```text
SettingsPageShell
→ SettingsViewportLayout
→ SettingsSectionPanel
→ SettingsGrid
→ SettingRow
→ SettingCopy + SettingControlSlot
```

适用于：

```text
WeiG WebUI
下载
连接
速度
BitTorrent
Web UI
高级
```

桌面默认两列；窄屏一列。每个普通 SettingRow 内部始终：

```text
文字 / 描述左对齐                    控件 / 值右对齐
```

普通字段默认 `span=1`。不再根据 `path/url/host/username/password` 等字段名猜 full-span。只有明确的多行/复合编辑器才允许 schema 显式 `span=full`。

### 4.2 Header utilities

Desktop/tablet 右上角统一：

```text
[+ Add Torrent] [GitHub] [Blog] [↻] [◐]
```

GitHub：`https://github.com/weigefenxiang/WeiG-qB-WebUI`  
Blog：`https://www.weigshare.com/`

GitHub / Blog / Refresh / Theme 共用一个 `HeaderUtilityAction` 模板和现有 `icon-btn` 状态系统，不增加 `.github-btn` / `.blog-btn` 特例。

### 4.3 Brand

Header 图标与 `WeiG qB` 是两个独立 Home target；About 使用同一个 BrandMark 和同一个 AmbientMark controller，只改变尺寸/profile。

## 5. 本轮截图暴露的系统性问题

这不是三个孤立样式 bug，而是以下架构问题叠加：

```text
双 Row DOM 结构
+ 旧 FormRail 与新 SettingsGrid 两套 layout owner
+ 根据字段名猜 full-span
+ observer 后处理 DOM
+ browser gate 只看列数、没看每行对齐
```

结果就是：同一个页面中可能同时出现左对齐、居中、单列整行、两列半宽等视觉语言。

修复原则：**修 owner / schema / primitive，不再给某一个页面加 CSS 特例。**

## 6. Settings 硬规则

```text
SETTINGS-STRUCTURE-002
所有普通 editable setting 渲染成同一种 SettingRow DOM。

SETTINGS-ALIGN-002
SettingCopy 永远左对齐；SettingControlSlot 永远靠 cell 右边缘。

SETTINGS-GRID-002
宽桌面默认两列；普通 row 默认占一个 cell。

SETTINGS-SPAN-002
full-span 必须由 schema 显式声明；字段名/描述文字不能决定 span。

SETTINGS-OWNER-002
旧 820px FormRail 不得继续影响已迁移 SettingsGrid。

SETTINGS-BUSINESS-001
UI 重构不改变 QBClient、Preference key、单位换算或保存语义。
```

奇数个普通设置时，最后一项留在左 cell；不自动拉满整行。

## 7. Header 硬规则

```text
HEADER-UTILITY-001
GitHub / Blog / Refresh / Theme 使用一个 icon-action presentation owner。

HEADER-LINK-001
外链使用语义 anchor + target=_blank + rel=noopener noreferrer。

HEADER-A11Y-001
所有 icon-only action 必须有 aria-label / Tooltip / focus-visible。

HEADER-MOBILE-001
窄手机空间不足时 GitHub/Blog 移入 ContextDrawer Links，不挤压主导航。
```

## 11. 开发禁区

禁止：

```text
页面各造一套 SettingRow / Select / Dialog / IconButton
用字段名字猜设置布局
同时维护 FormRail 和 SettingsGrid 两套 geometry
靠 MutationObserver / timeout 长期修核心 Settings DOM
用 !important 让两套 owner 互相覆盖
为 GitHub/Blog 单独造视觉按钮
为了测试通过降低真实 alignment/span 标准
普通 dev push 启动 full Linux/Windows matrix
```
