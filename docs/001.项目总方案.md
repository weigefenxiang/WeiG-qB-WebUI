# 001. 项目总方案

Status: **current project authority / AI handoff entry**

WeiG qB WebUI 是 qBittorrent Alternative WebUI。**`webui/**` 是唯一正式产品**；source catalog、真实 qB harness、Virtual qB、browser/Pages 与 CI 都是发现、验证和发布工具，不能反过来定义产品语义。

本文档不维护历史 Phase A–G，也不保存某次临时排障流水账。长期维护只记录当前目标、正式边界、authority、执行原则与不可破坏的规则；当前 operational 事实以 `docs/002` 为准，专项复盘可放在 bounded 文档中。

## 1. 长期目标

同一份正式 `webui/**` 应覆盖：

```text
qB 4.1.0
-> all admitted official stable releases
-> current latest official stable
-> future official stable / future major
```

兼容策略优先级：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY when applicable
-> UNAVAILABLE
-> UNKNOWN when facts are not provable
```

未来或未收录版本不能因为版本号更高就自动继承 current latest 全部语义，也不能按 major 整体拒绝。`UNKNOWN` 只关闭无法证明的具体能力；危险写操作必须在 HTTP 前 fail closed。

## 4. 分支与 exact-SHA 原则

长期只保留：

```text
dev   normal development / repair / docs / validation branch
main  stable promoted result
```

普通开发只进 `dev`。未经用户明确授权，不修改 `main`、promotion、tag、GitHub Release；禁止 force push。

Exact Git SHA 是以下证据共同 identity：

```text
source checkout
normal CI / candidate
source/LKG artifacts
real-qB Full Frozen Matrix
real-qB Current Stable Locale Matrix
Pages site artifact/live verify
promotion
release candidate package
release tag/assets
```

任何新 commit 都产生新的 evidence identity。旧 SHA 的 candidate/G-FM/Locale/Pages/browser/runtime evidence 不能自动证明新 SHA。docs-only commit 可以按 public-payload classifier 复用已 materialized Dev payload，但**release-grade evidence 仍必须绑定准备 promotion 的 final dev exact SHA**。

## 5. 兼容实现原则

正式兼容由 machine-readable source facts 与 canonical product owners 驱动。禁止：

```text
业务层 patch-version compatibility table
major>=5 作为最终产品 oracle
404/501 after click 才判断 capability
manual compatibility mode
fake empty data 掩盖 unsupported/error
N items -> N compatibility fallback requests
presentation self-probe
第二套 capability/state/polling owner
MutationObserver / monkey patch / post-render repair 维持双架构
```

Release profile resolution 固定区分：

```text
EXACT -> EQUIVALENT -> bounded INHERITED -> FALLBACK
```

危险写操作不能靠版本猜测。需要多个 upstream action 才能完成的一次 UI 写操作，必须证明**全部** required actions/parameters，而不是只证明任意一个。

生产 runtime catalog 必须保持 bounded/sharded；完整历史 source/recovery evidence 可存在 build/audit 层，但不能重新塞回一个随历史线性膨胀的浏览器 monolith。

## 6. Locale / translation 当前原则

Persisted language truth 只有：

```text
qB app/preferences.locale
```

qB-owned wording 采用 native-first：

```text
exact qB source/context
-> source-bound translator behavior
-> QBT_TR / qB native translator
-> deterministic official QM recovery where native path is source-proven
-> exact official-TS bridge only for proven native gap
```

完整 recovery translation bodies 是 build-only QM materialization evidence，不进入 browser release profile JSON。`4.5.0 -> 4.6.4` Alternative WebUI document-translation gap 仍是 source-proven hard boundary，必须保留 exact bridge。

browser/OS locale 只作为 bootstrap/environment input；若产品在第一次进入时采用浏览器 locale，也只能通过 canonical `setPreferences(locale)` + verified reread 把结果变成 qB persisted truth，不能恢复 previousLocale/退出恢复或第二语言 state。

## 7. Windows 配置与 distribution 安全

Windows 外部配置修改必须保持 encoding/BOM/newline/无关 Unicode，使用 fail-closed、backup、temp、strict reread、target-unchanged check 与 atomic/equivalently safe replace。禁止 PowerShell 5.1 whole-file `Get-Content/Set-Content` 路径重新引入 mojibake 风险。完整规则见 `docs/007`、`docs/008.Windows开发版安装.md`、`docs/013`。

任何可运行 Dev/preview distribution 必须是 target exact-SHA materialized artifact，并验证 embedded `GIT_SHA`；禁止 raw source fallback。

## 8. 验证与发布原则

长期发布顺序：

```text
finish planned changes on dev
-> freeze final dev exact SHA
-> normal CI PASS
-> CI candidate PASS on the same SHA
-> exact-SHA Dev Pages artifact/live verify PASS
-> manual Current Stable Locale Matrix PASS on the same SHA
-> manual Real qB Full Frozen Matrix PASS on the same SHA
-> central release-compat-evidence verifier PASS
-> formal Promote validated dev to main, safe fast-forward only
-> main Pages reuses the same validated artifact
-> tag exact main SHA as v<VERSION>
-> Release reuses validated candidate bytes
```

Candidate 是 source/product/browser/package/real-qB rehearsal gate，不等于 Full Frozen Matrix。Full Frozen Matrix 是 final/release-stage heavy validation，不随普通 dev push 自动运行。

当前 Frozen operational facts 是 65 stable profiles 与 qB 5.2.3 的 61-locale surface；这些数量由 target exact-SHA LKG 派生，不提升为永久常量。

## 9. 当前下一优先级

在用户尚未明确授权 promotion/release 的前提下：

```text
1. 保持 current dev docs/tests/workflows 与 0.3.75 canonical runtime/source truth 一致。
2. 对准备交接的 current dev exact SHA 完成 candidate 级 source/product/browser/package/deployment validation。
3. 不把 skipped job 写成 PASS，不把旧 SHA evidence写成新 SHA evidence。
4. 若只是 docs-only finalization，Product VERSION 保持 0.3.75。
5. promotion/main/tag/Release 前仍必须取得同 final SHA 的 exact Pages、manual Locale、manual G-FM 与 central evidence。
6. 未经用户明确授权，不执行 promotion、main fast-forward、tag 或 GitHub Release。
```

任何 gate 变红时先读完整日志并按 root cause 修复；source/canonical runtime truth 高于 stale test/fixture/docs/Simulator expectation。
