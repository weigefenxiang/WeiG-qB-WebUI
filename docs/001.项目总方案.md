# 001. 项目总方案

Status: **current project authority / AI handoff entry**

WeiG qB WebUI 是 qBittorrent Alternative WebUI。**`webui/**` 是唯一正式产品**；source catalog、真实 qB harness、Virtual qB、browser/Pages 与 CI 都是发现、验证和发布工具，不能反过来定义产品语义。

本文档不再维护 Phase A–G 等历史阶段。长期维护只记录当前目标、正式边界、执行流程与不可破坏的规则。

## 1. 长期目标

同一份正式 `webui/**` 应覆盖：

```text
qB 4.1.0
-> all admitted official stable releases
-> current latest official stable
-> future official stable / future major
```

兼容策略优先级：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY when applicable
-> UNAVAILABLE
```

对未来或未收录版本，无法证明的具体能力标记为 `UNKNOWN`。`UNKNOWN` 只关闭无法证明的能力，尤其危险写操作必须在 HTTP 前 fail closed；不能因为 major/version 更高就自动继承当前 latest 的全部语义，也不能按 major 整体拒绝。

## 4. 分支规则

长期只保留：

```text
main   stable / promoted branch
dev    normal development branch
```

普通开发在 `dev`。`main` 只接受已经验证的 exact SHA 的 safe fast-forward promotion。

禁止：

```text
force push main
merge commit 代替 exact-SHA promotion
在 main 单独修改产品再发布
未经用户明确授权移动 tag / GitHub Release
长期保留 fix/tmp/phase 工作分支
```

当前 0.3.72 开发/收口阶段明确要求：**只动 `dev`，不动 `main`、tag、GitHub Release。**

## 5. Exact-SHA 原则

Git SHA 是以下证据的共同 identity：

```text
source checkout
CI / candidate
real-qB Full Frozen Matrix
real-qB Current Stable Locale Matrix
Pages site artifact
promotion
release package
release tag
```

**任何新 commit 都产生新的 candidate identity。旧 SHA 的 candidate/G-FM/Locale/Pages evidence 不自动证明新 SHA。**

纯 docs commit 不要求机械跑重型 G-FM/candidate/Locale，但一旦准备 promotion/release，必须在当时 final `dev` exact SHA 重新取得发布所需证据。

日常 dev materialized payload 允许因为明确 Pages-irrelevant docs commit 暂时落后 current dev HEAD；这是安装/Pages runtime identity 规则，不是 release evidence 继承规则。

## 6. 兼容实现规则

正式兼容必须由 machine-readable source facts 与 canonical owners 驱动。

禁止：

```text
业务层手写 patch-version compatibility table
major>=5 之类作为最终产品行为 oracle
404/501 after click 作为 capability owner
manual compatibility mode
fake empty data 掩盖 unsupported/error
N items -> N compatibility requests
presentation self-probe
第二套 capability owner
第二套业务状态 / duplicate polling
runtime monkey patch / MutationObserver bridge 修复架构问题
```

允许 version 信息参与 source profile 选择、诊断和 evidence；最终 feature truth 仍来自 exact actions / parameters / fields / Preference provenance 等事实。

### 6.1 Release profile resolution

当前 runtime resolution：

```text
EXACT       exact admitted official stable
EQUIVALENT  canonical suffix equivalence, e.g. 5.2.3-r1 -> 5.2.3
INHERITED   same major.minor nearest lower certified profile when source/runtime contract permits
FALLBACK    no safe relation
```

目标允许例如：

```text
5.2.4   -> temporarily resolve from 5.2.3
5.2.3.1 -> resolve from 5.2.3
```

但不是“nearest wins”。不能跨 hard source boundary 盲继承；危险写操作仍必须 source/range proven。

### 6.2 Runtime catalog 必须 sharded

真实 qB 4.6.7 已证明接近 10 MiB 的单体 runtime `qb-releases.json` 不是可接受设计。当前生产 runtime 使用：

```text
private/data/qb-releases.json                     # compact index
private/data/qb-release-profiles/<sourceSha>.json # exact profile shard
```

只加载当前 profile shard；load failure 必须暴露具体错误，不能吞成空 catalog/fallback。完整 65-profile source evidence 仍可存在于构建/审计层，不应重新塞回真实 qB runtime 单文件。

### 6.3 Language / translation 当前原则

Persisted language truth：

```text
qB app/preferences.locale
```

qB-owned wording 已采用 native-first：

```text
qB official source/context
-> QBT_TR
-> qB translator
-> official minimal QM
```

WeiG-only wording继续由 `W.I18n` 拥有。

全 65 stable translator audit 已完成；`4.5.0 -> 4.6.4` 因 upstream Alternative WebUI 不执行 document translation，保留 exact official-TS compatibility bridge。详细见 `docs/012.qB原生翻译与国际化复盘.md`。

## 7. Windows 配置安全规则

2026-09-11 真实 Windows 事故证明：外部安装器不能把整个 `qBittorrent.ini` 当普通文本“读出再 Set-Content 写回”。PowerShell 5.1 的 UTF-8 no-BOM / ANSI 行为曾造成中文、日文配置全局 mojibake。

当前 `dev` 已完成完整 fail-closed / encoding-preserving / atomic config mutation 安全链：

```text
qB running + -configure -> fail closed
non-empty qBittorrent_new.ini / recovery file -> fail closed
zero/invalid config -> fail closed
multiple config candidates -> fail closed; do not guess
exactly one [Preferences] -> required
managed WebUI keys unique and inside [Preferences] -> required
strict decode + byte round-trip
byte-identical safety backup
temp write -> strict reread + invariant/encoding verification
target unchanged recheck
atomic replace
post-replace verification
safe rollback when the mutation itself replaced the target
```

支持保留 UTF-8 BOM/no-BOM、UTF-16 LE/BE BOM，并由 Windows PowerShell 5.1 contract 覆盖。不要重新引入 `Get-Content -Raw` + `Set-Content -Encoding UTF8` whole-file rewrite。

完整复盘见 `docs/013.Windows配置编码事故复盘.md`。

Windows Dev bootstrap authority：

```text
https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1
```

Dev installer 只消费 Pages materialized distribution；禁止 raw-source fallback。

## 9. 发布规则摘要

完整 authority 见 `docs/006.发布与晋级流程.md`。长期顺序：

```text
finish all planned changes on dev
-> do not run Full Frozen Matrix during ordinary development
-> freeze final dev exact SHA
-> normal CI PASS
-> run CI candidate on the same exact SHA
-> ensure exact-SHA Pages dev artifact/live verify PASS
-> manually run Current Stable Locale Matrix on the same SHA
-> as the final heavyweight validation, manually run Real qB Full Frozen Matrix 65/65 on the same SHA
-> central release-compat-evidence verifier PASS
-> Promote validated dev to main, fast-forward only
-> verify main Pages reuses same exact dev artifact
-> tag current main exact SHA as v<VERSION>
-> Release workflow re-resolves candidate + G-FM + Locale and reuses validated candidate artifact
```

Normal CI、candidate、dev Pages、Locale 与 G-FM 必须以同一个 final dev exact SHA 为发布证据。

**G-FM 是最终发布前重型门禁，不跟随普通 dev push 自动运行，也不应在每个中间 commit 上反复运行。** 只有 final SHA 已冻结、准备最终验证/发布时才支付 65-version runtime 成本；如果之后又产生新的发布 commit，旧 aggregate 只证明旧 SHA，发布时再对新的 final SHA 做最后一次即可。

当前 Locale operational fact 是 qB 5.2.3 的 61-locale surface，因此当前 release gate 表现为 `65/65 G-FM + 61/61 Locale`；Locale 数量由 exact LKG 派生，不提升为永久常量。

## 10. Version / Release 规则

只有正式 `webui/**` 产品行为变化才需要考虑产品版本 bump。纯 docs/tests/tools/workflow/Simulator 维护不应机械 bump 产品 VERSION。

正式 release tag 必须满足：

```text
tag == v<VERSION>
tag SHA == current main SHA == validated release candidate SHA
```

Release workflow 不得重新构建产品；应发布已验证 candidate 中的：

```text
WeiG-qB-WebUI.zip
weigg-install.sh
weigg-install.ps1
SHA256SUMS
```

Promotion 与 Release 都必须重新验证 same-SHA manual G-FM + Locale aggregate，不能只依赖 Actions 顶层绿色状态，也不能用 Fast、旧 SHA 或 skipped push run 代替 release-grade evidence。

## 11. 当前下一优先级

在只允许修改 `dev` 的前提下：

```text
1. 保持 docs / tests / workflow authority 与当前实现事实一致。
2. 所有后续产品、installer、workflow、test 修复继续只进 dev。
3. 日常开发不运行 Real qB Full Frozen Matrix。
4. 所有计划修改完成、用户明确进入最终验证/准备发布后，冻结新的 final dev exact SHA。
5. 对该 exact SHA 建 normal CI + candidate + explicit Pages + manual Locale evidence。
6. 最后只对该 exact SHA 手动跑一次 G-FM 65/65。
7. promotion / main / tag / Release 只有在用户明确授权发布流程后执行；不能在 dev-only 维护阶段提前做。
```

修改 workflow、验证 contract、release choreography 时必须同步检查依赖。任何 gate 变红时先按日志分类根因，不降低断言、不放宽 exact-SHA identity、不用重跑掩盖确定性 bug。
