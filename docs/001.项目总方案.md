# 001. WeiG qB WebUI 项目总方案

Status: **v0.3.7 Release Candidate / Responsive UI System 3.1 planning**  
Repository: `weigefenxiang/WeiG-qB-WebUI`  
Compatibility floor: **qBittorrent 4.1.9.1 / WebAPI 2.2.1**  
Current product version: **0.3.7**

## 1. 产品定位

WeiG qB WebUI 是长期维护的 qBittorrent Alternate WebUI。目标不是针对某张截图不断补 CSS，而是建立可复用、可测试、可迁移的 UI / interaction / compatibility system。

长期原则：

```text
一个业务模型
一套组件语义
桌面 / 手机响应式呈现
高信息密度但不牺牲可读性
qB 老版本可用，新能力渐进增强
精确 Git SHA 身份
Release 作为稳定分发事实源
真实环境可验证、可回滚
```

设计方法参考 `VoltAgent/awesome-design-md` 中的 DESIGN.md 体系，重点吸收 token、spacing、component、responsive、interaction、depth 与 Do/Don't，而不是复制某个网站外观。

当前视觉方向：

```text
Linear     深色层级、hairline、克制高端
IBM Carbon 设置/表单的结构化密度
Raycast    command / popover / keyboard interaction
Apple      motion rhythm / reduced visual noise
WeiG       蓝紫 + cyan + 低频随机 AmbientMark
```

## 2. 分支、验证与稳定分发

长期分支：

```text
dev   开发 / Release Candidate
main  已通过真实环境 gate 的稳定代码
```

稳定发布链：

```text
需求
→ docs / DESIGN contract
→ dev implementation
→ full dev CI once
→ exact-SHA reusable artifact
→ real qB live validation
→ fast-forward main to same SHA
→ tag same SHA
→ publish the same artifact as GitHub Release
```

普通用户稳定安装入口只认：

```text
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest
```

`dev` / `main` 源码压缩包不是普通用户稳定安装包。没有 GitHub Release 时，代表当前还没有稳定版。

## 3. 应用架构

```text
qB WebAPI
  ↓
QBClient + capabilities + normalization
  ↓
Shared application state / models
  ↓
Canonical components
  ↓
Responsive presentation
      ├─ Desktop DataGrid
      └─ Mobile two-line Torrent row
```

禁止发展成两个独立应用：

```text
desktop-app.js
mobile-app.js
```

手机端可以有 adaptive presentation layer，但过滤、排序、选择、字段定义、设置 schema、限速模型、Dialog 规则、API 与状态必须共享。

## 4. Responsive UI System 3.1

本轮 UI 重构按以下 owner 推进：

```text
Intrinsic Select
  内容决定宽度，取消无意义右侧空白；不依赖 ▾ 识别控件

Dismiss Policy
  Popover 外部单击关闭；普通 Dialog 背景双击关闭；危险 Dialog 明确确认

TorrentFieldRegistry
  桌面列、手机字段、排序字段、格式化和 label 共用一份定义

Mobile two-line row
  每个种子最多两行；不足空间时按优先级折叠为 +N，不把字体压到不可读

Settings Section / Row
  一组设置一个 Surface；一项设置一行，不再一项一张大卡

About Surface
  一个完整板块，清楚区分 qBittorrent upstream 与 WeiG qB WebUI

AmbientMark
  hover / click / idle-random / reduced-motion 模块化，可迁移到其它 WeiG 项目

Transfer Capsule
  桌面底部下载+上传合并；点击统一调整全局上下行限速、单位与 ALT 模式

Display Time Zone
  Settings 为唯一配置入口；底部状态栏不再重复放时区 Select
```

详细 contract 见 `005.v0.3.7统一交互与设置系统.md`。

## 5. 手机端硬规则

```text
MOBILE-ROW-001
每个 Torrent 最多两行。

MOBILE-COMMAND-001
每页 / 选择 / 列设置 / 排序工具条最多一行，不换行。

MOBILE-FIELD-001
手机可使用桌面同一 TorrentFieldRegistry 的 Size / Progress / DL / UL / ETA /
Status / Ratio / Tracker / Category / Tags / time / peers 等受支持字段。

MOBILE-READABILITY-001
空间不足时优先缩短格式、缩 gap、折叠低优先级字段为 +N；禁止靠极小字体硬塞。

MOBILE-SHELL-001
页面消费动态 viewport 剩余空间，不使用固定 `100vh - 魔法像素`。
```

## 6. Settings 硬规则

```text
SETTINGS-ROW-001
一项 setting = 一行，不等于一张大卡。

CONTROL-WIDTH-001
数字/枚举/端口等短值使用 intrinsic/semantic width；路径和长字符串才允许较宽输入。

CONTROL-ALIGN-001
同组右侧 controls 共用对齐轴；Boolean Switch、Select、Input 高度遵循统一 Control Height。

TIME-003
显示时区只在 Settings 配置；其它页面消费同一个状态。
```

## 7. 兼容策略

兼容判断以 WebAPI 字段与 capability 为主，不按 qB major version 硬编码。代表矩阵与当前实现状态见 `002.兼容与实现状态.md`。

原则：

```text
旧版本缺 API → 隐藏/降级该能力
新版本多 API → progressive enhancement
fixture PASS ≠ LIVE PASS
```

## 8. 缓存、安装与身份

```text
VERSION                 产品版本
GIT_SHA                 精确代码身份
CSS/JS ?v=<Git SHA>     静态资源 cache identity
weigg-install.json      部署 metadata
SHA256SUMS              Release 包完整性
```

稳定安装器只是 bootstrap；最终部署 payload 以 GitHub Release 资产为准。安装、Docker path、Windows、NAS、更新与回滚见 `007.安装升级与手动部署.md`。

## 9. 开发禁区

禁止：

```text
为桌面/手机复制业务逻辑
页面各自造 Select / Dialog / Popover
设置项一项一大卡并用 min-height 强行等高
为了塞手机数据把字号压到不可读
用随机动画制造持续视觉噪声
把 deployment URL / credential / host path 写死进源码
用 main/tag Release 阶段重新构建未经 dev candidate 验证的 payload
```

## 10. Gate

自动 gate 至少覆盖：

```text
syntax / smoke
compatibility matrix
cache / exact-SHA contract
canonical component contract
mobile responsive contract
settings schema round-trip
selection / context actions
DataGrid resize
AdaptiveDialog
Logs / Search / RSS / Settings browser regressions
release candidate packaging
```

真实服务器 gate 通过前不得 promote `main`、不得打稳定 tag、不得发布 GitHub Release。
