# 001. 项目总方案

Status: **current product plan / AI handoff entry**

WeiG qB WebUI 是 qBittorrent Alternative WebUI。**`webui/**` 是唯一正式产品；正式 support floor 为 qBittorrent 4.1.0，核心目标是覆盖全部已验证 official stable，并让未来 stable / new major 自动进入 source facts、产品兼容和 fail-closed admission 链。** Simulator、source catalog、WebAPI evolution ledger、Endpoint/Transport Contract 都是辅助发现与验证工具，不是产品本身。

详细产品路线见 [`010.真实qB产品兼容路线.md`](./010.真实qB产品兼容路线.md)；当前事实见 [`002.兼容与实现状态.md`](./002.兼容与实现状态.md)；架构见 [`003.项目架构.md`](./003.项目架构.md)；发布/CI 分层见 [`006.发布与晋级流程.md`](./006.发布与晋级流程.md)。

## 1. 产品目标

同一份：

```text
webui/**
```

应能够：

```text
qB 4.1.0
-> all verified 4.x official stable
-> all verified 5.x official stable
-> current latest stable
-> future stable / qB6.x / qB7.x / future x.x.x
```

自动识别真实 release / WebAPI / source capability，按以下优先级得到 canonical WeiG semantics：

```text
NATIVE
-> NORMALIZED / ADAPTER
-> reliable old-API composition
-> reliable DERIVED
-> READ_ONLY when applicable
-> UNAVAILABLE
```

future `UNKNOWN` 只对无法证明的具体 capability fail closed，尤其危险写操作；不能因为 major/version 变大就整体拒绝，也不能因为版本更高就自动继承 current latest semantics。

禁止伪造真实 qB 无法提供的数据，禁止为了兼容制造 N->N 网络放大、额外高成本 polling、presentation self-probe 或第二套业务状态。

## 8. Git / proof discipline

- 正式开发分支 `dev`；未经用户明确授权不动 `main`；
- 每轮写入前 fresh-read exact `dev`；candidate 只以该 SHA 为 parent；
- ref update 前再次 fresh-read；如果移动，candidate 作废并基于新 HEAD 重建；
- ref 更新只允许 `force:false` safe fast-forward；禁止 force push；
- repo-wide ownership/absence/proof 只认目标 exact SHA 的完整 tree/blob/file；code search/snippet 只能 discovery；
- product truth 与 stale test 冲突时先确认 exact runtime/upstream/source truth；禁止为了测试变绿回退正确产品行为。
