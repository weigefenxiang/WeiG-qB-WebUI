## 2. 0.3.79：Detail Columns live-apply owner 补齐

Hosted Chrome 首次真正执行 Torrent Detail Columns DOM gate 后暴露产品缺口：

```text
renderSharedColumnDialog()
-> checkbox onchange
-> SharedColumns.commit(...)
-> ctx.apply(true)
```

主表 context 有 apply owner，但 Detail 的 `prepareDetailVirtual()` 当时没有绑定 `ctx.apply`，导致 visibility state 已写入 canonical SharedColumns/localStorage 后，UI 没有立即重建，并产生异常。

修复保持单一 owner：

```text
Detail ctx.apply
-> applyDetailColumns(ctx, rebuild)
```

没有新增第二列状态、MutationObserver、post-render repair 或 polling owner。

产品因此从 `0.3.78` 升到 `0.3.79`。

## 3. 0.3.80 / 0.3.81：Detail resize pointer lifecycle 收口

下一层 browser evidence 暴露 Detail resize 在真实 hosted Chrome 中无法稳定完成拖动。

最终保留的交互纪律是：

```text
resize handle pointerdown
-> 建立单一 active pointer state
-> window 级 pointermove/up/cancel lifecycle
-> pointerId 过滤
-> pointermove 只更新 width + grid template
-> pointerup 才 canonical commit/persist
```

中间 `0.3.80` 的一次实现因为 pointermove 多做了副作用，被现有 hot-path contract 正确拒绝；`0.3.81` 收窄到原有纪律后 semantic contracts 全绿。

这一步没有改变 `W.TorrentFieldRegistry / W.SharedColumns / W.DataGrid` 的 owner 边界。

## 4. 0.3.82：真正根因是 resize hitbox 被裁剪

`0.3.81` 的 global pointer lifecycle 仍然得到 `300 -> 300`，说明问题不在 pointermove 离开 10px handle。

进一步读取实际 CSS 后确认：

```text
.grid-head-cell { overflow: hidden; }
.col-resize { right: -6px; width: 10px; }
```

Detail header 把 handle 的大部分几何放到了父单元格外，而父单元格又裁剪 overflow；Playwright/真实鼠标取 handle 中点时可能落在被裁掉或下一列区域，pointerdown 根本没有命中 resize handle。

最终产品修复是把 Detail 专用 resize handle 完整放回当前 header cell 的可命中区域：

```text
right: 0
```

不需要改 JS owner，也不改变 header 文本 overflow/ellipsis 语义。产品因此升到 `0.3.82`。

## 5. Torrent Detail source provenance 的后续修复

在修 browser evidence 之前，Virtual qB Pages / Settings source evidence 连续暴露了几类真实 upstream 差异。

### 5.1 Legacy/modern Tracker row projection

旧 qB DynamicTable/row UI key（例如 `peers`）不能直接当 API response field。正确 relation 必须从 source row projection恢复：

```text
peers      -> tracker.num_peers
seeds      -> tracker.num_seeds
leeches    -> tracker.num_leeches
downloaded -> tracker.num_downloaded
message    -> tracker.msg
```

现代 qB 5.x 还存在 `rows.push({...})`、nested `tracker.endpoints` 与 helper-derived status。parser 现在从实际 source relation 恢复 direct field、bare derived local、helper call dependency 与 nested top-level root；无法证明继续 fail closed。

### 5.2 Properties shared serializer keys

qB 4.4-4.6 的 `propertiesAction()` 不只写 `KEY_PROP_*`，还会写 shared serializer 中定义的 `KEY_TORRENT_*`，例如 infohash 字段。

因此 Properties source surface 现在按：

```text
propertiesAction() 实际赋值
+ shared serialize_torrent.h key definitions
```

解析，而不是按前缀猜测允许字段。

### 5.3 qB 5.2 Content checked / remaining

现代 qB 5.2 的 Content source truth分散在：

```text
prop-files.js
+ torrent-content.js
+ file-tree.js
```

其中：

```text
checked   -> priority
remaining -> size + progress + priority
```

正式语义仍是：

```text
priority == 0 -> checked=false, remaining=0
else remaining = size * (1 - progress)
```

browser fixture通过 current exact-source overlay消费这些 source facts；Frozen LKG 没有被 browser test私自晋级。

## 7. Horizontal-scroll gate 修正不是产品回退

最后两次 browser red 属于 gate 构造问题：

1. 默认列总宽小于 1366px viewport，固定只放大 Name 360px并不能保证 overflow；gate改为按当前 viewport与列总宽动态计算 resize delta，主动制造真实 overflow。
2. header cell 与 row cell 在滚动前本来就有固定约 10px布局偏移；正确同步条件是二者都移动同一 `scrollLeft` 且相对偏移前后保持不变，而不是强迫绝对 left相等。

这两处修正加强了“必须真实 overflow、必须同步移动”的证据，没有降低产品标准。
