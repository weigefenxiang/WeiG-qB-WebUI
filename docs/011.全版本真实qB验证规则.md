# 011. 全版本真实 qB 验证规则

Status: **current full real-qB validation authority**

> 本文件定义发布前全支持区间真实 qB 验证规则。它不是日常开发矩阵，也不是新的 compatibility owner。

## 1. 目的

对 Frozen LKG 中的每一个 admitted official stable，使用同一份正式 `webui/**` 与同一套 capability-driven real-qB harness，在真实 qB runtime 上建立 exact-SHA evidence。

当前基线：

```text
qB 4.1.0 -> 5.2.3
65 stable versions
```

## 2. 触发策略

正式 workflow：

```text
.github/workflows/real-qb-full.yml
name: Real qB Full Frozen Matrix
```

触发：

```text
workflow_dispatch only
```

不跟随普通 `dev` push 自动运行。

### 2.1 成本纪律

Full Frozen Matrix 是发布级重型验证，不是开发反馈环。

永久规则：

```text
日常 dev push                   -> 不跑
普通修复 / tests / docs         -> 不跑
中间 checkpoint                 -> 不跑
final dev exact SHA 尚未冻结     -> 不跑
准备最终验证 / 准备发布         -> 手动跑
Frozen/runtime/harness 重大变化且明确要求全量重新认证 -> 手动跑
```

优先用 normal CI、source/product contracts、focused real-qB acceptance 收敛问题。只有已经准备作为最终候选的 exact SHA 才运行 65-version Full Matrix，避免在不断变化的中间 SHA 上重复消耗 runner 时间。

Full Matrix 完成后如果又产生新的最终发布 commit，旧 aggregate 仍只证明旧 SHA；真正发布时必须对新的 final exact SHA 再做最后一次验证。

适合运行的时机：

```text
final dev SHA 已冻结，准备正式发布
compatibility owner / real-qB harness / runtime resolver 有重大变化且需要全量重新认证
Frozen LKG 扩展后需要重新建立全版本证据
明确要求重新确认全支持区间
```

### 2.2 手工启动防误触 gate

为了避免误点一次就展开 65 个真实 runtime jobs，`workflow_dispatch` 必须同时填写：

```text
branch/ref: dev
candidate_sha: <当前 frozen final dev 的 40 位 exact SHA>
confirmation: RUN-FULL-FROZEN-65
```

Plan job 在生成 matrix 前先 fail closed 检查：

```text
GITHUB_EVENT_NAME == workflow_dispatch
GITHUB_REF == refs/heads/dev
candidate_sha 是 40 位 hex
candidate_sha == GITHUB_SHA
confirmation == RUN-FULL-FROZEN-65
```

任一不满足都只消耗 plan 的轻量前置检查，不允许展开 65-version matrix。

这不是“允许提前跑”的快捷按钮；`candidate_sha` 应当只填写已经冻结并准备最终验证/发布的 final dev SHA。

## 3. 调度模型

当前 workflow：

```text
1 plan job
65 independent real-qB jobs
1 aggregate job
fail-fast: false
max-parallel: 16
```

每个 qB stable 独立 job，避免固定 shard 导致慢 shard 尾部拖延，也便于单版本定位与 evidence 审计。

如果未来 Frozen LKG profile 数变化，matrix count、aggregate contract、promotion/release gate 中的 expected count 必须同批更新；禁止只改其中一处。

## 4. Exact identity

每个 job 必须证明：

```text
WeiG checkout SHA == workflow GITHUB_SHA
requested qB version == runtime self-reported qB version
release/source profile identity is exact
runtime image/source-build identity is auditable
```

旧 SHA 的 G-FM evidence 不能证明新 SHA。

## 5. Runtime resolver

每个 admitted stable 都必须映射到可审计真实 runtime。

优先级：

```text
immutable historical runtime image/digest
-> verified historical wrapper + exact qB self-reported identity
-> deterministic source build from exact official tag/commit
-> unresolved => BLOCKED/FAIL
```

第三方 runtime wrapper只能作为 packaging/runtime evidence，不能冒充 qB 官方镜像。

## 6. Harness 原则

所有版本使用同一套 capability-driven harness，不允许为某个 patch 维护单独 compatibility truth。

Expectation 来自：

```text
Frozen LKG
-> exact ReleaseProfile/source provenance
-> canonical product owners
```

禁止：

```text
if qB major == 4/5 then guess API
manual compatibility mode
404 probing as feature owner
fake empty result
silently weaken one historical version assertions
```

Fast capability planning/aggregate 代码可以作为离线 contract、调试与实现验证工具存在，但**不是正式 release workflow evidence**，不得替代手工 Exhaustive 65/65 aggregate。

## 7. 测试范围

真实语义至少覆盖适用的：

```text
auth/session
app / WebAPI identity
transfer/torrent list
Torrent lifecycle and details
Settings read + approved safe write + reread
Logs
RSS
Categories
Tags
Search where source-supported
Torrent Creator / other actions where source-supported and harness-owned
cleanup
```

具体 scenario 可以随正式产品能力演进，但必须由 source/capability truth 驱动。

## 8. Safe write / isolation

全部真实 qB job 必须隔离：

```text
no user production qB
no user torrents
no production credentials
no public inbound service
unique temporary test objects
approved safe/no-op Settings writes only
cleanup required
```

历史 qB runtime 优先使用 runner-only/internal network。

## 9. PASS / FAIL / BLOCKED

版本级最终状态：

```text
PASS
FAIL
BLOCKED
```

Scenario 级可使用 `SKIP`，仅当：

```text
exact source profile proves capability unavailable
or
明确可选 runtime prerequisite 缺失且 evidence 记录原因
```

以下不能伪装成 SKIP/PASS：

```text
runtime 找不到
container/source build 启动失败
qB/WebAPI identity mismatch
harness crash
cleanup failure
infrastructure failure after retry policy exhausted
```

## 10. Per-version evidence

每个 stable version 必须有独立 artifact，至少能审计：

```text
weig_sha
webui_version
qB_version
WebAPI_version
source/runtime identity
runtime digest or deterministic build identity
platform / architecture
deployment mode
scenario results
capability expectation/source provenance
cleanup result
final status
```

禁止写入 password、cookie/token、真实用户 torrent 内容或其它敏感凭据。

Artifact 名称必须包含 qB version + WeiG exact SHA。

## 11. Aggregate gate

所有版本执行完后聚合 exact-SHA evidence。

当前 65-version contract 必须满足：

```text
expected_stable_count = 65
executed_runtime_count = 65
PASS = 65
FAIL = 0
BLOCKED = 0
missing_versions = []
duplicate_versions = []
unexpected_runtime_versions = []
results.length = 65
each qb_version == runtime_version
each status == PASS
each runtime image identity is immutable/auditable
```

最终 artifact：

```text
real-qb-full-aggregate-<SHA>
```

Promotion 与 Release 都必须重新下载并通过中央 `tests/release-compat-evidence.mjs` 验证这个 aggregate，不能只看 workflow UI 显示绿色，也不能接受旧 SHA、Fast aggregate 或普通 push run 替代。

## 12. 与 Locale / 发布流程关系

G-FM PASS 本身不移动 main、不创建 tag、不发布 Release。

最终 release-grade compatibility evidence 是同一 final dev exact SHA 上的两部分：

```text
Real qB Full Frozen Matrix
-> manual workflow_dispatch
-> final-dev SHA + RUN-FULL-FROZEN-65 intent guard
-> real-qb-full-aggregate-<SHA>
-> 65/65 PASS

Real qB Current Stable Locale Matrix
-> manual workflow_dispatch
-> real-qb-current-locale-aggregate-<SHA>
-> current stable all locales PASS
```

当前 Frozen latest stable 为 qB 5.2.3，当前 locale surface 为 61，因此当前发布门禁表现为 `65/65 + 61/61`；未来 Locale 数量由 exact LKG 派生，不把 61 写成永久产品常量。

发布链：

```text
all dev changes complete
-> freeze final dev exact SHA
-> normal CI / candidate / dev Pages PASS
-> manual Current Stable Locale Matrix PASS
-> 最后 manual G-FM（粘贴 final SHA + RUN-FULL-FROZEN-65）65/65 PASS
-> Promote validated dev to main
-> main Pages exact reuse PASS
-> tag v<VERSION>
-> Release re-resolves and revalidates candidate + G-FM + Locale exact-SHA evidence
```

Candidate、dev Pages、Locale 与 G-FM 可以在 final SHA 已冻结之后并行；但 Full Matrix 应尽量留到最后一次重型验证，避免开发过程中频繁重复运行。

## 13. 失败处理

失败先判断：

```text
product semantic bug
source/profile bug
historical runtime resolver bug
harness bug
transient infrastructure problem
```

只有明确的瞬时基础设施故障才适合同 SHA rerun。

确定性错误必须修复后产生新 SHA；在真正准备发布时，对新的 final exact SHA 重新取得完整 release-grade G-FM/Locale evidence，而不是复用旧 SHA 的绿色结果。
