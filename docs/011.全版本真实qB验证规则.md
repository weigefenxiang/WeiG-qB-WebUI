# 011. 全版本真实 qB 验证规则

Status: **current full real-qB validation authority**

> 本文件定义发布前全支持区间真实 qB 验证规则。它不是日常开发矩阵，也不是新的 compatibility owner。

## 1. 目的

对 Frozen LKG 中的每一个 admitted official stable，使用同一份正式 `webui/**` 与同一套 capability-driven real-qB harness，在真实 qB runtime 上建立 exact-SHA evidence。

当前基线：

```text
qB 4.1.0 -> 5.2.3
65 stable versions
```

## 2. 触发策略

正式 workflow：

```text
.github/workflows/real-qb-full.yml
name: Real qB Full Frozen Matrix
```

触发：

```text
workflow_dispatch only
```

不跟随普通 `dev` push 自动运行。

适合运行的时机：

```text
准备正式发布
compatibility owner / real-qB harness / runtime resolver 有重大变化
Frozen LKG 扩展后需要重新建立全版本证据
明确要求重新确认全支持区间
```

## 3. 调度模型

当前 workflow：

```text
1 plan job
65 independent real-qB jobs
1 aggregate job
fail-fast: false
max-parallel: 16
```

每个 qB stable 独立 job，避免固定 shard 导致慢 shard 尾部拖延，也便于单版本定位与 evidence 审计。

如果未来 Frozen LKG profile 数变化，matrix count、aggregate contract、promotion gate 中的 expected count 必须同批更新；禁止只改其中一处。

## 4. Exact identity

每个 job 必须证明：

```text
WeiG checkout SHA == workflow GITHUB_SHA
requested qB version == runtime self-reported qB version
release/source profile identity is exact
runtime image/source-build identity is auditable
```

旧 SHA 的 G-FM evidence 不能证明新 SHA。

## 5. Runtime resolver

每个 admitted stable 都必须映射到可审计真实 runtime。

优先级：

```text
immutable historical runtime image/digest
-> verified historical wrapper + exact qB self-reported identity
-> deterministic source build from exact official tag/commit
-> unresolved => BLOCKED/FAIL
```

第三方 runtime wrapper只能作为 packaging/runtime evidence，不能冒充 qB 官方镜像。

## 6. Harness 原则

所有版本使用同一套 capability-driven harness，不允许为某个 patch 维护单独 compatibility truth。

Expectation 来自：

```text
Frozen LKG
-> exact ReleaseProfile/source provenance
-> canonical product owners
```

禁止：

```text
if qB major == 4/5 then guess API
manual compatibility mode
404 probing as feature owner
fake empty result
silently weaken one historical version assertions
```

## 7. 测试范围

真实语义至少覆盖适用的：

```text
auth/session
app / WebAPI identity
transfer/torrent list
Torrent lifecycle and details
Settings read + approved safe write + reread
Logs
RSS
Categories
Tags
Search where source-supported
Torrent Creator / other actions where source-supported and harness-owned
cleanup
```

具体 scenario 可以随正式产品能力演进，但必须由 source/capability truth 驱动。

## 8. Safe write / isolation

全部真实 qB job 必须隔离：

```text
no user production qB
no user torrents
no production credentials
no public inbound service
unique temporary test objects
approved safe/no-op Settings writes only
cleanup required
```

历史 qB runtime 优先使用 runner-only/internal network。

## 9. PASS / FAIL / BLOCKED

版本级最终状态：

```text
PASS
FAIL
BLOCKED
```

Scenario 级可使用 `SKIP`，仅当：

```text
exact source profile proves capability unavailable
or
明确可选 runtime prerequisite 缺失且 evidence 记录原因
```

以下不能伪装成 SKIP/PASS：

```text
runtime 找不到
container/source build 启动失败
qB/WebAPI identity mismatch
harness crash
cleanup failure
infrastructure failure after retry policy exhausted
```

## 10. Per-version evidence

每个 stable version 必须有独立 artifact，至少能审计：

```text
weig_sha
webui_version
qB_version
WebAPI_version
source/runtime identity
runtime digest or deterministic build identity
platform / architecture
deployment mode
scenario results
capability expectation/source provenance
cleanup result
final status
```

禁止写入 password、cookie/token、真实用户 torrent 内容或其它敏感凭据。

Artifact 名称必须包含 qB version + WeiG exact SHA。

## 11. Aggregate gate

所有版本执行完后聚合 exact-SHA evidence。

当前 65-version contract 必须满足：

```text
expected_stable_count = 65
executed_runtime_count = 65
PASS = 65
FAIL = 0
BLOCKED = 0
missing_versions = []
duplicate_versions = []
unexpected_runtime_versions = []
results.length = 65
each qb_version == runtime_version
each status == PASS
```

最终 artifact：

```text
real-qb-full-aggregate-<SHA>
```

Promotion 必须重新下载并验证这个 aggregate，不能只看 workflow UI 显示绿色。

## 12. 与发布流程关系

G-FM PASS 本身不移动 main、不创建 tag、不发布 Release。

发布链：

```text
final dev exact SHA
-> G-FM 65/65 PASS
-> CI candidate PASS
-> exact Pages dev artifact PASS
-> Promote validated dev to main
-> main Pages exact reuse PASS
-> tag v<VERSION>
-> Release
```

G-FM、candidate、dev Pages 可以在同一 final SHA 上并行。

## 13. 失败处理

失败先判断：

```text
product semantic bug
source/profile bug
historical runtime resolver bug
harness bug
transient infrastructure problem
```

只有明确的瞬时基础设施故障才适合同 SHA rerun。

确定性错误必须修复后产生新 SHA，并重新取得该 SHA 的完整 G-FM evidence。
