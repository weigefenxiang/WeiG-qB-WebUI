# 011. 全版本真实 qB 验证规则

Status: **current full real-qB validation authority**


> **Current-work routing**：mutable phase / exact-SHA / TODO只看 `docs/014` STOP 前；当前 A5 Settings 全版本系统闭环见 `docs/018`；A4历史证据见 `docs/017`；A1–A3历史在 `docs/016`，默认不要读。

> 本文件定义发布前全支持区间真实 qB 验证规则。它不是日常开发矩阵，也不是新的 compatibility owner。

## 1. 目的

对 Frozen LKG 中的每一个 admitted official stable，使用同一份正式 `webui/**` 与同一套 capability-driven real-qB harness，在真实 qB runtime 上建立 exact-SHA evidence。

当前基线：

```text
qB 4.1.0 -> 5.2.3
65 stable versions
```

## 2. 触发策略

正式 workflow：

```text
.github/workflows/real-qb-full.yml
name: Real qB Full Frozen Matrix
```

触发：`workflow_dispatch only`，不跟随普通 `dev` push自动运行。

### 2.1 成本纪律

Full Frozen Matrix 是发布级重型验证，不是开发反馈环。

```text
日常 dev push                   -> 不跑
普通修复 / tests / docs         -> 不跑
中间 checkpoint                 -> 不跑
A/B/C/D/E/F 单阶段开发过程       -> 不跑
final dev exact SHA 尚未冻结     -> 不跑
准备最终验证 / 准备发布         -> 手动跑
Frozen/runtime/harness 重大变化且明确要求全量重新认证 -> 手动跑
```

优先用 normal CI、source/product contracts、focused real-qB acceptance与阶段 offline/Virtual evidence收敛问题。只有已经准备作为最终候选的 exact SHA 才运行 65-version Full Matrix，避免在不断变化的中间 SHA 上重复消耗 runner 时间。

Full Matrix完成后如果又产生新的最终产品 commit，旧 aggregate仍只证明旧 SHA；真正发布时必须对新的 final exact SHA重新满足所需 release-grade evidence。

### 2.2 手工启动防误触 gate

为了避免误点一次就展开 65 个真实 runtime jobs，`workflow_dispatch` 必须同时填写：

```text
branch/ref: dev
candidate_sha: <当前 frozen final dev 的 40 位 exact SHA>
confirmation: RUN-FULL-FROZEN-65
```

Plan job 在生成 matrix 前先 fail closed检查：

```text
GITHUB_EVENT_NAME == workflow_dispatch
GITHUB_REF == refs/heads/dev
candidate_sha 是 40 位 hex
candidate_sha == GITHUB_SHA
confirmation == RUN-FULL-FROZEN-65
```

任一不满足都只消耗 plan轻量前置检查，不允许展开 65-version matrix。该输入不是“允许提前跑”的快捷按钮。

### 2.3 A–F 阶段 65 != 本文件的真实 65

`docs/009` / `docs/010` 定义的阶段末 65-release offline/Virtual/source-contract matrix与本文件的 Real qB Full Frozen Matrix是两种不同 evidence：

```text
phase-end offline/Virtual 65
  exact source + compact/runtime projection + modeled semantics
  每个完整阶段最多一次
  不启动 65 个真实 qB runtime

Real qB Full Frozen Matrix
  65 个真实 qB runtime
  全 A–F 完成、final dev SHA冻结后才运行
  release-grade evidence
```

阶段 offline/Virtual 65 PASS不能冒充 real-qB 65/65；real-qB 也不能替代 source census/compact completeness。当前用户明确禁止创建/使用 `[candidate]`，因此在本轮开发未另行授权前更不能因为某个阶段完成就触发 Candidate/Promotion/Release。

## 3. 调度模型

当前 workflow：

```text
1 plan job
65 independent real-qB jobs
1 aggregate job
fail-fast: false
max-parallel: 16
```

每个 qB stable独立 job，避免固定 shard导致慢 shard尾部拖延，也便于单版本定位与 evidence审计。

如果未来 Frozen LKG profile数变化，matrix count、aggregate contract、promotion/release gate中的 expected count必须同批更新；禁止只改其中一处。

## 4. Exact identity

每个 job 必须证明：

```text
WeiG checkout SHA == workflow GITHUB_SHA
requested qB version == runtime self-reported qB version
release/source profile identity is exact
runtime image/source-build identity is auditable
```

旧 SHA 的 G-FM evidence不能证明新 SHA。

## 5. Runtime resolver

每个 admitted stable都必须映射到可审计真实 runtime。

优先级：

```text
immutable historical runtime image/digest
-> verified historical wrapper + exact qB self-reported identity
-> deterministic source build from exact official tag/commit
-> unresolved => BLOCKED/FAIL
```

第三方 runtime wrapper只能作为 packaging/runtime evidence，不能冒充 qB官方镜像。

## 6. Harness 原则

所有版本使用同一套 capability-driven harness，不允许为某个 patch维护单独 compatibility truth。

Expectation来自：

```text
Frozen LKG
-> exact ReleaseProfile/source provenance
-> canonical product owners
```

禁止 major-version guessing、manual compatibility mode、404 probing as feature owner、fake empty result或 silently weaken historical assertions。Fast capability planning/aggregate可以作为离线 contract、调试与实现验证工具存在，但不是正式 release workflow evidence。

## 7. 测试范围

真实语义至少覆盖适用的：

```text
auth/session
app / WebAPI identity
transfer/torrent list
Torrent lifecycle and details
Settings read + approved safe write + reread
Logs
RSS
Categories
Tags
Search where source-supported
Torrent Creator / other actions where source-supported and harness-owned
cleanup
```

具体 scenario可随正式产品能力演进，但必须由 source/capability truth驱动。

## 8. Safe write / isolation

全部真实 qB job必须隔离：no user production qB、no user torrents、no production credentials、no public inbound service、unique temporary test objects、approved safe/no-op Settings writes only、cleanup required。历史 qB runtime优先使用 runner-only/internal network。

## 9. PASS / FAIL / BLOCKED

版本级最终状态：`PASS / FAIL / BLOCKED`。

Scenario级可使用 `SKIP`，仅当 exact source profile证明 capability unavailable，或明确可选 runtime prerequisite缺失且 evidence记录原因。

以下不能伪装成 SKIP/PASS：runtime找不到、container/source build启动失败、qB/WebAPI identity mismatch、harness crash、cleanup failure、infrastructure failure after retry exhausted。

## 10. Per-version evidence

每个 stable version必须有独立 artifact，至少能审计：

```text
weig_sha
webui_version
qB_version
WebAPI_version
source/runtime identity
runtime digest or deterministic build identity
platform / architecture
deployment mode
scenario results
capability expectation/source provenance
cleanup result
final status
```

禁止写入 password、cookie/token、真实用户 torrent内容或其它敏感凭据。Artifact名称必须包含 qB version + WeiG exact SHA。

## 11. Aggregate gate

当前 65-version contract必须满足：

```text
expected_stable_count = 65
executed_runtime_count = 65
PASS = 65
FAIL = 0
BLOCKED = 0
missing_versions = []
duplicate_versions = []
unexpected_runtime_versions = []
results.length = 65
each qb_version == runtime_version
each status == PASS
each runtime image identity is immutable/auditable
```

最终 artifact：`real-qb-full-aggregate-<SHA>`。

Promotion 与 Release都必须重新下载并通过中央 `tests/release-compat-evidence.mjs` 验证这个 aggregate，不能只看 workflow UI绿色，也不能接受旧 SHA、Fast aggregate或普通 push run替代。

## 12. 与 Locale / 发布流程关系

G-FM PASS本身不移动 main、不创建 tag、不发布 Release。

最终 release-grade compatibility evidence是同一 final dev exact SHA上的两部分：

```text
Real qB Full Frozen Matrix
-> manual workflow_dispatch
-> final-dev SHA + RUN-FULL-FROZEN-65 intent guard
-> real-qb-full-aggregate-<SHA>
-> 65/65 PASS

Real qB Current Stable Locale Matrix
-> manual workflow_dispatch
-> real-qb-current-locale-aggregate-<SHA>
-> current stable all locales PASS
```

当前 Frozen latest stable为 qB 5.2.3，当前 locale surface为61，因此当前发布门禁表现为 `65/65 + 61/61`；未来 Locale数量由 exact LKG派生，不把61写成永久产品常量。

发布链继续由 `docs/006` 负责，并且只有用户明确授权后才能进入 Candidate/Promotion/Release。本轮当前指令是 dev-only、不要创建/使用 `[candidate]`。

## 13. 失败处理

失败先判断 product semantic bug、source/profile bug、historical runtime resolver bug、harness bug还是 transient infrastructure problem。只有明确瞬时基础设施故障才适合同 SHA rerun。

确定性错误必须修复后产生新 SHA；真正准备发布时，对新的 final exact SHA重新取得完整 release-grade G-FM/Locale evidence，而不是复用旧 SHA绿色结果。


## 10. A5 phase matrix 与本文件 Full Frozen Matrix 的边界

A5 会新增/扩展 **all-admitted Settings source/Virtual/browser matrix**，expected set同样来自target exact-SHA Frozen catalog，但它属于A阶段开发验收，不是本文件定义的release-grade真实qB Full Frozen Matrix。

两层证据必须分开：

~~~text
A5 phase gate
  exact source ownership/writeability census
  + compact semantic round-trip
  + all-admitted Settings browser matrix
  + focused real-qB sixth review

docs/011 release gate
  A–F全部完成
  + final dev SHA冻结
  + 每个admitted official stable真实qB runtime
  + release-grade aggregate
~~~

A5 phase gate必须在进入B前通过；但不能因为A5 browser matrix 65/65 PASS就声称真实qB 65/65已完成。反过来，也不得提前启动昂贵Full Frozen Matrix来绕过A5 source ownership/projection缺口。

最终真实qB Full Frozen Matrix中的Settings acceptance应继续验证read + approved safe write + reread；A5形成的ownership/projection contracts将成为其前置产品事实，但release harness不应重新实现第二套Settings semantics。
