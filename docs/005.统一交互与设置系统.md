# 005. 统一交互与设置系统

> 当前 Settings / Locale / interaction contract。Current Owner 最终以 `DESIGN.md` 为准；qB 原生翻译当前实现与历史兼容边界见 `docs/012.qB原生翻译与国际化复盘.md`。

## 1. Canonical controls

Settings 复用统一组件：

```text
W.Components.selectControl()
switch-control
field-input setting-input
canonical Dialog / Feedback
shared section/grid/row layout
```

不为 qB4/qB5、Desktop/Mobile 或某个 tab 建第二套控件系统。

## 2. 六个 qB Settings surfaces

Canonical surfaces：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

## 3. Exact Preference provenance

每个 admitted official stable profile 从 qB upstream getter/setter source 生成 descriptor：

```text
getter/read type/kind/confidence
setter/write type/kind/confidence
getter/setter agreement
writable
enum fallback provenance
```

Setter-only key 不得逃出 `app/preferences` surface。未知/无法证明的写操作必须 fail closed。

## 4. Locale 当前架构：单一 persisted owner 已完成

Locale owner cutover 已经在正式 `webui/**` 完成。当前不再是“双语言真值”状态。

唯一持久语言真值：

```text
qB app/preferences.locale
```

启动链：

```text
QBClient.detect()
-> ReleaseProfile / capabilities ready
-> QBClient.getPreferences()
-> W.AppState.preferences / W.SettingsState.prefs
-> W.I18n.applyLocale(prefs.locale)
-> W.I18n.ready()
-> normal render
```

WeiG 不再保存第二份 `weigg-language`，也不通过 `languagechange` 反向写 qB。

两个显示入口继续保留：

```text
WeiG WebUI -> Interface -> Language
qB Settings -> Advanced -> Locale
```

它们共享：

```text
same SettingsState.draft.locale
same exact-release locale options
same SettingsSchema writable provenance
same QBClient.setPreferences() transaction
same verification reread
```

这两个入口是同一 Preference 的两个 presentation caller，不是两套状态。

## 5. Locale 保存必须 verification-first

Locale 与其它 qB Preference 共用 canonical 保存事务：

```text
user edits locale
-> SettingsState.draft.locale
-> SettingsSchema writable check
-> QBClient.setPreferences(pending)
-> QBClient.getPreferences() verification reread
-> shared prefs snapshot updated
-> W.I18n.applyLocale(verified prefs.locale)
-> rerender existing shared DOM
```

如果 write 失败，不切视觉语言。

如果 write 已成功但 verification reread 失败，明确反馈“已写入但无法确认”，仍不能把未确认 draft 提升为 rendered truth。

## 6. Locale options 的 source truth

语言选项不允许写成 UI 侧版本表。

真实 qB：

```text
private/views/preferences.html
-> qB WebApplication replaces ${LANGUAGE_OPTIONS}
-> current runtime locale code + localized language name
```

Virtual qB / historical exact profile：

```text
source-SHA-bound frozen locale facts
-> W.ReleaseProfile exact webuiLocales
```

因此两个语言入口必须始终显示同一个 exact-release set。连接 qB 5.2.3 时当前 source facts 为 61 项；旧 release 使用自己的历史 code/subset，例如可能出现 `de_DE`、`ja_JP`、`ko_KR`、`zh` 等。

历史 alias/identity 只能在 canonical locale normalization/source layer 处理，禁止在 Settings caller 中写 patch-version 分支。

## 7. qB-owned Settings 文案：当前 native-first + source-proven narrow bridge

### 7.1 当前 0.3.71 的实际实现

qB-owned Settings title/description 并非 WeiG 人工翻译。正式链先从 exact qB upstream 证明：

```text
Preferences UI control relation
-> QBT_TR source/context
-> exact sourceSha translator behavior family
-> official qB translation facts
```

native-capable profile/locale 使用：

```text
private/data/qb-settings-native.txt
-> QBT_TR marker/source/context
-> qB WebApplication translator
-> official minimal webui_<locale>.qm where the exact family requires active-root QM
-> W.I18n.qbSetting()
```

浏览器不拥有第二份完整 qB Settings translation database。

### 7.2 Source-proven compatibility bridge

`4.5.0 -> 4.6.4` 的 qB Alternative WebUI 不执行 document translation。这个上游行为已经由 exact sourceSha audit 证明，不能靠“多放一个 QM”修掉。

因此这些明确 route 可以使用：

```text
private/data/qb-settings/<sourceSha>.json
```

约束：

```text
exact qbVersion + sourceSha + locale route
translation body must come from exact official qB TS
only when source-derived translator behavior requires the bridge
mismatch -> reject/fail closed
```

JSON 在这里是窄化 compatibility transport，不是主翻译 owner。

## 8. `qb-releases.json` 与翻译必须解耦

`qb-releases.json` 的长期职责是 compatibility/source facts：

```text
qB/WebAPI version
source SHA
actions / parameters
Torrent fields / filters
Preference provenance
translator behavior / routing facts
other source-derived capability facts
```

它不是 translation database。

禁止再次把：

```text
all-release Settings translation bodies
all-locale translation sets
```

塞回 runtime `qb-releases.json`。

当前 `settingsTranslationPath` 只允许作为 source-proven bridge route 的 pointer；不要把它扩回所有版本，也不要在仍支持 `4.5.0 -> 4.6.4` 时误删这条必要 compatibility path。

## 9. WeiG-owned 文案边界

qB upstream 没有对应语义的内容仍由 WeiG 自己拥有，例如：

```text
WeiG Interface / Theme / Starfield / Motion
WeiG diagnostics / compatibility notices
WeiG-specific layout/help/feedback
About / Brand / project identity
```

这些不能伪装成 qB 官方翻译。

反过来，如果一个显示语义在 qB upstream 已经有明确 source/context，优先复用 qB owner，不再手写一份“看起来一样”的中文/英文。

## 10. Current i18n owner 状态

旧 runtime owners 已退出：

```text
W.RuntimeI18n
W.InterfaceText
W.TransferText
W.AlternativeWebUIText
W.QBLocaleBridge
settings-translations.js
legacy i18n sidecar modules
```

当前 presentation API 是 `W.I18n`。

它当前职责是：

```text
WeiG-owned wording
locale normalization/options/presentation helpers
consume qB native QBT_TR output
consume exact official-TS bridge only when source-proven route requires it
```

不要再建立 `I18nV2`、第二 persisted language state 或全版本浏览器翻译数据库。

## 11. Editability

Exact stable profile 只有同时满足以下条件才可编辑：

```text
setPreferences action proven
setter exists
write type understood
getter/setter type agrees
descriptor writable == true
```

否则可见但 read-only，或按 capability policy 隐藏。

Boolean/Enum/Input/Structured control 都消费同一事实；`onDraft` 拒绝 non-writable，保存时 `writableDraft()` 再过滤。

Locale 也不得绕过这一 contract。

## 12. Unknown / future Preferences

未来 stable 新 key 不静默丢失：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

未知 scalar 在没有 exact setter provenance 时只读；未知 array/object 可见但只读，以结构化 JSON 展示。

禁止猜 unit / enum / range / startup default，也禁止 blind write。

## 13. 与 simulator Endpoint/Transport Contract 的边界

```text
W.SettingsSchema + Preference descriptors
-> key/type/getter/setter/editability

simulator Endpoint Contract
-> historical request/response/status/mutation semantics

simulator Transport Contract
-> auth/header/proxy transport semantics
```

这些职责不能合并成第二套 Settings owner。

当前 native-first 产品在 Pages/Virtual qB 中使用 validation-only server-translation emulation；该 fixture 不得进入正式 product runtime，也不得为 upstream 明确禁用 Alternative WebUI QBT_TR 的版本伪造 native capability。

## 14. Mobile / acceptance

Mobile 使用同一 Settings DOM/state/controls/save flow，不建立第二套语言状态。

当前 contract 至少覆盖：

```text
qB Locale save -> verified reread -> WeiG UI locale applies
WeiG Language and Advanced Locale share draft/value/options
exact release locale set is used
no weigg-language persistent state
no duplicate setPreferences after locale save
Desktop/Mobile consume same active locale
QBT_TR source/context provenance
translator behavior across admitted release families
official QM provisioning where required
qB-owned bridge rejects mismatched qbVersion/sourceSha
Virtual qB does not leak unresolved QBT_TR markers
```

发布前 real-qB evidence 还必须继续证明 representative locale/Settings behavior 与实际 runtime identity；这属于 evidence gate，不是再做一轮 translation architecture cutover。

## 15. 变更纪律

Settings/Locale/i18n owner 被替换时必须 atomic cutover：

```text
new proven production path
+ callers
+ contracts
+ DESIGN/docs
+ remove superseded runtime owner
```

禁止新旧 qB translation runtime 长期双活。

普通 docs/tests/tools 维护不 bump 产品 VERSION；任何 `webui/**` 产品修改按仓库规则同步 patch VERSION。
