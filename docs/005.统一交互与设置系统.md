# 005. 统一交互、Settings 与 Locale 系统

Status: **current Settings / Locale / qB-owned copy / shared interaction contract**

## 1. Settings 当前 owner 与 A 阶段目标

当前业务值的唯一 truth始终是 `GET /api/v2/app/preferences`。现行正式写入链固定为：

```text
user edit
-> current Preference exists
-> exact descriptor proves writable/type
-> certified setPreferences write provenance
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> verified value becomes truth
```

Unknown/unproven values只读，危险 write fail closed。

当前 runtime仍由 `W.SettingsSchema + private/data/settings-compat.json` 投影 Settings；这条链已经 source-drive native tab presence/order，但 `settings-schema.js` 仍手工维护大量 qB-owned section/control/unit/enum/family truth，因此 **A 尚未完成**。

A source/admission层现在已经额外证明 native raw/UI value projection：

```text
identity
scale                 # e.g. raw bytes/s <-> native KiB/s
switch-map            # historical composite read projection
unproven              # no safe write claim
```

每个 projection带 `safeWrite`。正式 A cutover后，Settings write条件要升级为：

```text
setPreferences endpoint proven writable
AND specific Preference setter/type proven
AND source value projection proves safe inverse/write
```

`switch-map`/composite只有 read map、没有 source-proven inverse时必须保持 read-only/fail closed，不能靠旧 `META/toRaw()` 手工猜写回。

A目标不是再加一套 renderer，而是把 exact-source Preferences native IR原子接入 canonical Settings owner：

```text
exact qB Preferences source
+ exact preferenceDescriptors / app/preferences keys
  ├─ semantic manifest
  │    native tabs / sections / order / source-context copy
  │    control semantic / attributes / options / unit / dependency
  │    raw/UI value projection
  │    getter / setter / readType / writeType agreement
  │
  └─ independent inventory/census
       tabs / preferences / bindings
       mapped + explicit reviewed exclusions
       unaccounted=0 / duplicates=0

-> compact Settings contract
∩ runtime app/preferences
-> W.SettingsSchema / W.SettingsRenderer generic projection
```

新 source-native contract proven后，必须同批删除被替代的 qB-owned `SURFACES/SECTION_ORDER/SECTION_TITLES/META/FAMILY_RULES/add()` 等手工 truth；禁止 “source schema + legacy schema” 双 active。WeiG自己的 layout tokens、canonical components与 presentation rules可以保留，但不能重新定义 qB native semantics。

## 2. Settings layout / compound controls

Settings顶层布局只有一个 owner：canonical SettingsGrid + `W.SettingsRenderer`。Source/schema决定 SettingRow是否存在、属于哪个 section、control semantics与是否 writable；presentation只能投影这些 facts。

一个 SettingRow内部允许把语义紧密关联的控件组合在一起，例如历史上已有：

```text
Listen port + Random
schedule From + To
```

但这些旧 compound helpers本身不是上游 source truth。A cutover必须逐项证明其 source semantics：能由 exact native source/manifest表达则generic compose；不能证明时不得为了保留旧外观恢复 patch-version rule，也不能制造危险写回。可以安全退回source-proven单控件/read-only表现，直到结构性 inverse/dependency得到证明。

**compound control只说明 row内部有多个控件，不代表整个 row必须 full-span**。顶层 row默认仍占一个标准 grid cell；只有独立 source/layout contract明确证明需要时才跨两列。

测试必须优先绑定稳定 semantic owner（例如 `data-setting-key` / canonical control role），同时考虑 compound row真实 DOM层级。若 browser test找不到 input，先核对 current renderer输出和 readiness，再判断 selector stale、surface未 ready还是产品确实没渲染；禁止只加 timeout、删断言或恢复旧 DOM来让测试变绿。

## 3. Native Options identity

WeiG外层不应把 qB native Preferences surface重新命名成一套独立“Settings”产品语义。qB-owned native surface identity必须来自对应 exact release upstream source；例如 toolbar/title/source里是 `Options` 时，显示文本由 official qB translation解析。

固定八 native-tab whitelist已从 compact tooling退休；当前按 exact `qbOwnedUi` 的 `settings.tab.*` source facts动态提取 native tab集合/顺序。历史已知 change point只作为 evidence，不应再变成固定 allowlist或未来版本 if/else。

## 4. Preferences independent census

A source layer现在有独立于 semantic extractor 的 census：

```text
raw Preferences source
-> independent tab inventory
-> independent read/write app/preferences references
-> independent source-bound control bindings
-> account against semantic manifest + explicit reviewed exclusions
```

Full-stable Preferences source contract要求每个 admitted release的 `tabs / preferences / bindings` census均 complete；出现 `unaccounted / overlap / escaped / duplicate` 直接 FAIL。Raw helper/client-only controls可以保留为 diagnostics，但不能假装成 app/preferences completeness blocker。

因此“Preferences census 尚未实现”已不是 TODO；A当前 blocker是**正式 runtime cutover**。Mapping ratio仍可保留为 parser健康度信号，但不能代替 census，也不能因为 ratio达到某阈值就忽略新语法。

## 5. Locale / qB-owned copy

唯一 persisted language truth是 `qB app/preferences.locale`。qB-owned wording不维护第二手写翻译表，统一走 `W.I18n`：exact `{source, context}` + exact-release official translation facts；只有 source-proven Alternative WebUI hard gap才使用 compact official-TS bridge。官方目标 locale缺失时允许回退 **upstream English source**，不允许回退 WeiG手写“官方中文”。

当前 runtime仍使用 Settings-focused `qb-settings-native.txt` + minimal official QM。C阶段若把它泛化为 domain-neutral qB-owned copy artifact，必须一次切换 generator、runtime loader、callers、tests、distribution contract并删除旧 artifact；不得保留 `qb-settings-native.txt` 和新文件两套 active registry。

`4.5.0 -> 4.6.4` document-translation hard gap继续保留。完整 TS/recovery/source evidence只在 tools/CI，最终 runtime只携带实际引用的 compact registry与 minimal QM。

Locale bootstrap正确链路：

```text
browser/session locale intent
-> canonical bootstrap decision
-> qB app/preferences.locale persisted truth
-> reread/observed locale
-> W.I18n presentation
```

`W.I18n` 只负责 presentation，不得偷偷成为第二 persisted language owner。出现 `zh-CN browser -> qB locale en` 时，不能用前端强制中文显示掩盖；必须检查 bootstrap初始化顺序、session/reset、simulator Preferences truth与真实 qB write/reread contract。

## 6. qB-owned copy coverage

C阶段要求所有正式 qB-owned runtime text都能追到 `{source, context}`，至少包括：

```text
Options tabs / sections / controls / options / units
Torrent Status / Categories / Tags / Trackers
RSS Downloader/rule fields/actions where upstream owns wording
Torrent Detail tabs/labels/menu actions
```

WeiG-owned Path、Private/PT、WeiG WebUI、About、WeiG diagnostics继续用 WeiG i18n。不能为了“统一翻译”把 WeiG extension伪装成 qB source string，也不能把 qB native text重新放入 WeiG EN/ZH dictionary。

## 7. Self-contained runtime

```text
capabilities.json
torrent-compat.json
detail-compat.json
settings-compat.json
rss-compat.json
source-actions.json
qb-settings-native.txt          # current artifact until an atomic C cutover replaces it

```

`release-profile.js`、`qb-releases.json`、`qb-release-profiles/`、旧 per-release Settings/translation shards已退休，不得回流。完整 Preferences native source catalog/census/IR属于 tools/CI/admission input；只有最终 compact runtime projection进入 `webui/**`。

## 8. Shared interaction

Settings/Detail复用 canonical `W.Components` 与 shared Input/Button/Dialog/Select；Detail tables复用 `W.SharedColumns / W.ColumnInteraction`。Desktop/Mobile只是同一 state 的 adaptive presentation，不建立第二控件、action、language、scroll或polling owner。

Torrent/Detail虚拟滚动交互继续由 canonical `W.VirtualList`拥有。滚动或 scrollbar drag期间可以继续获取 polling数据，但 DOM replacement必须延后，只保留 latest pending snapshot并在 bounded idle后一次提交。

## 9. Validation

A阶段内部使用 source parser/unit/change-point/focused browser tests；A完整收口后最多一次65-release offline/Virtual Settings matrix。Independent census已经是 source gate基础，不应重复造第二 census；下一步重点是让 formal runtime真正消费 source-native IR/projection并删除旧 owner。

C阶段应对所有 admitted release/runtime qB-owned `{source,context}` route做解析检查：official translation存在则 exact resolve；允许 hard gap时回 upstream English；不得落入 WeiG手写 qB copy。

Pages build/deploy成功不自动证明 locale/settings live acceptance；required live lane的 timeout/assertion failure仍然是 FAIL。Promotion/main/tag/Release另需用户授权。
