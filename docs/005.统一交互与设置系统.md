# 005. 统一交互与设置系统

> 当前 Settings / Locale / qB-owned copy / interaction contract。2026-09-13 复盘后更新。Current Owner 最终以 `DESIGN.md` 为准；qB 原生翻译历史边界与 source-derived 证据见 `docs/012.qB原生翻译与国际化复盘.md`。

## 1. Canonical controls

Settings 复用统一组件：

```text
W.Components.selectControl()
switch-control
field-input setting-input
canonical Dialog / Feedback
shared section/grid/row layout
```

不为 qB4/qB5、Desktop/Mobile 或某个 tab 建第二套控件系统。

## 2. 六个 qB Settings surfaces

Canonical surfaces：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

## 3. Exact Preference provenance

每个 admitted official stable profile 从 qB upstream getter/setter source 生成 descriptor：

```text
getter/read type/kind/confidence
setter/write type/kind/confidence
getter/setter agreement
writable
enum fallback provenance
```

Setter-only key 不得逃出 `app/preferences` surface。未知/无法证明的写操作必须 fail closed。

Preference UI source 解析除 `<label for=...>` 外，还必须支持 qB 使用的 `aria-labelledby` 控件关系；否则像 file log age/max size 这类设置会错误退回 humanized English。

## 4. Locale 当前架构：单一 persisted owner

唯一持久语言真值：

```text
qB app/preferences.locale
```

启动链：

```text
QBClient.detect()
-> ReleaseProfile / capabilities ready
-> QBClient.getPreferences()
-> W.AppState.preferences / W.SettingsState.prefs
-> W.I18n.applyLocale(prefs.locale)
-> W.I18n.ready()
-> normal render
```

WeiG 不保存第二份 `weigg-language`，也不通过 `languagechange` 反向写 qB。

两个显示入口继续保留：

```text
WeiG WebUI -> Interface -> Language
qB Settings -> Advanced -> Locale
```

它们共享同一个 `SettingsState.draft.locale`、exact-release locale options、`SettingsSchema` writable provenance、`QBClient.setPreferences()` transaction 与 verification reread。

## 5. Locale 保存必须 verification-first

```text
user edits locale
-> SettingsState.draft.locale
-> SettingsSchema writable check
-> QBClient.setPreferences(pending)
-> QBClient.getPreferences() verification reread
-> shared prefs snapshot updated
-> W.I18n.applyLocale(verified prefs.locale)
-> rerender existing shared DOM
```

write 失败时不切视觉语言。write 已成功但 verification reread 失败时，明确反馈“已写入但无法确认”，仍不能把未确认 draft 提升为 rendered truth。

## 6. Locale options 的 source truth

真实 qB：

```text
private/views/preferences.html
-> qB WebApplication replaces ${LANGUAGE_OPTIONS}
-> current runtime locale code + localized language name
```

Virtual qB / historical exact profile：

```text
source-SHA-bound frozen locale facts
-> W.ReleaseProfile exact webuiLocales
```

连接 qB 5.2.3 时当前 source facts 为 61 项；旧 release 使用自己的历史 code/subset。历史 alias/identity 只在 canonical locale normalization/source layer 处理，禁止在 Settings caller 中写 patch-version 分支。

## 7. qB-owned copy：Settings + shared qB UI 已统一进入 official source/context pipeline

### 7.1 source-derived semantic refs

qB-owned 文案不再只覆盖 Preference title/description。当前 source parser `tools/qb-owned-ui-source.mjs` 还从 exact upstream WebUI markup 证明并绑定：

```text
Settings tabs
  settings.tab.downloads
  settings.tab.connection
  settings.tab.speed
  settings.tab.bittorrent
  settings.tab.webui
  settings.tab.advanced

Transfer rate modes
  transfer.rate.global          -> Global Rate Limits
  transfer.rate.alternative     -> Alternative Rate Limits

Torrent status filters
  filter.all / downloading / seeding / completed
  filter.resumed / paused / running / stopped
  filter.active / inactive
  filter.stalled / stalled_uploading / stalled_downloading
  filter.checking / moving / errored
```

这些 semantic key 只是 WeiG 内部稳定引用，译文 owner 仍是 qB official source/context + official translation facts。

历史 qB filter 名称不同，例如旧版本使用 `Resumed/Paused`，新版本使用 `Running/Stopped`。产品 canonical state 仍由 `W.TorrentSemantics` 统一，显示文案通过 `W.ReleaseProfile.upstreamTorrentFilter()` 回到 exact upstream 名称，不能在 UI caller 中自己猜版本。

`Private / PT` 是 WeiG-specific filter，不存在对应 qB upstream source/context，因此明确保持 **English only**，不能伪装成 qB 官方翻译。

### 7.2 native-first + exact official-TS bridge

正式 source/data 链：

```text
exact qB Preferences/toolbar/filters source
-> QBT_TR source/context refs
-> exact sourceSha translator behavior family
-> official qB TS facts
-> enriched Settings translation overlay
-> native registry / minimal official QM
-> exact bridge shard only where required
```

Native registry `private/data/qb-settings-native.txt` 当前同时包含：

```text
@@WEIGG_PROFILE   # Settings preference refs
@@WEIGG_UI        # qB-owned shared UI refs
@@WEIGG_TEXT      # QBT_TR source/context body
```

`tools/qb-settings-native-bundle.mjs` 把 Settings refs 与 qB-owned UI refs 放进同一个 translator-family routing 与 canonical minimal QM union；没有第二套翻译数据库。

`4.5.0 -> 4.6.4` 的 Alternative WebUI 不执行 document translation，所以 exact sourceSha bridge `private/data/qb-settings/<sourceSha>.json` 继续允许携带同一批 source-proven `preferences` + `ui` official-TS facts。这个 JSON 是窄 transport，不是翻译 owner。

### 7.3 Current runtime owner 已收口到 `W.I18n`

qB-owned shared UI runtime resolver 现在由 canonical：

```text
webui/private/scripts/i18n.js
```

统一负责：

```text
parse @@WEIGG_UI from the existing native registry
reuse the same exact native / bridge routing as Settings copy
W.I18n.qbText()
W.I18n.loadQbOwnedText()
```

Presentation 模块只做 caller：

```text
torrent-filter-view.js -> filter semantic key -> W.I18n.qbText()
settings.js            -> settings.tab.* -> W.I18n.qbText()
transfer.js            -> transfer.rate.* -> W.I18n.qbText()
```

不再由 Torrent presentation 模块给 `W.I18n` 动态挂 API；也不再通过 Settings render 后或 Transfer dialog 创建后的 post-render repair 来补官方文案。owner cutover、callers、contracts 与旧 owner 删除在同一轮完成，禁止恢复双活。

## 8. `qb-releases.json` 与翻译必须解耦

`qb-releases.json` 的长期职责是 compatibility/source facts：

```text
qB/WebAPI version
source SHA
actions / parameters
Torrent fields / filters
Preference provenance
translator behavior / routing facts
other source-derived capability facts
```

它不是 translation database。

禁止再次把 all-release Settings/qB-owned UI translation bodies 或 all-locale translation sets 塞回 runtime `qb-releases.json`。

Build-only `qbOwnedUi*` / Settings UI translation facts必须在构建阶段用于 routing/artifact 生成后从 runtime profile 移除；exact bridge shard只保留 source-proven gap 所需内容。

## 9. WeiG-owned 文案边界

qB upstream 没有对应语义的内容仍由 WeiG 自己拥有，例如：

```text
WeiG Interface / Theme / Starfield / Motion
WeiG diagnostics / compatibility notices
WeiG-specific layout/help/feedback
About / Brand / project identity
Private / PT
```

这些不能伪装成 qB 官方翻译。

反过来，如果一个显示语义在 qB upstream 已有明确 source/context，优先复用 qB owner，不再手写一份“看起来一样”的中文/英文。

## 11. Editability

Exact stable profile 只有同时满足以下条件才可编辑：

```text
setPreferences action proven
setter exists
write type understood
getter/setter type agrees
descriptor writable == true
```

否则可见但 read-only，或按 capability policy 隐藏。Locale 也不得绕过这一 contract。

## 12. Unknown / future Preferences

未来 stable 新 key 不静默丢失：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

未知 scalar 在没有 exact setter provenance 时只读；未知 array/object 可见但只读。禁止猜 unit / enum / range / startup default，也禁止 blind write。

## 13. 与 simulator Endpoint/Transport Contract 的边界

```text
W.SettingsSchema + Preference descriptors
-> key/type/getter/setter/editability

simulator Endpoint Contract
-> historical request/response/status/mutation semantics

simulator Transport Contract
-> auth/header/proxy transport semantics
```

Pages/Virtual qB 使用 validation-only server-translation emulation；fixture 不得进入正式 product runtime，也不得为 upstream 明确禁用 Alternative WebUI QBT_TR 的版本伪造 native capability。

## 14. Mobile / acceptance

Mobile 使用同一 Settings DOM/state/controls/save flow，不建立第二套语言状态。

当前 product/contract 至少覆盖：

```text
qB Locale save -> verified reread -> WeiG UI locale applies
WeiG Language and Advanced Locale share draft/value/options
exact release locale set is used
no weigg-language persistent state
no duplicate setPreferences after locale save
Desktop/Mobile consume same active locale
QBT_TR source/context provenance
translator behavior across admitted release families
official QM provisioning where required
qB-owned bridge rejects mismatched qbVersion/sourceSha
Virtual qB does not leak unresolved QBT_TR markers
qB-owned Settings + shared UI refs share one source/translator pipeline
qB-owned shared copy APIs are owned only by W.I18n
presentation callers do not keep post-render repair owners
```

## 15. 发布证据纪律

candidate deployment acceptance、Current Stable Locale Matrix 与 `Real qB Full Frozen Matrix` 职责互补。正式 promotion/release 必须消费同一 final SHA 的 release-grade evidence；普通 push 的 skipped job、旧 SHA aggregate 或 Fast utility 不能代替。

Full Frozen Matrix 只在 final SHA 的最终验证/准备发布阶段手工运行，不用于日常 Settings/i18n 开发反馈。

## 16. Dev materialized distribution / installer classifier

Windows/Linux Dev installer 只消费 Pages `downloads/dev` materialized payload，不允许 raw-source fallback。

installer、`pages-source.yml` 与 `pages.yml` stale-deploy gate 现在使用同一个**public payload allowlist**：

```text
webui/**
simulator/**
installers/**
VERSION
tools/data/qb-stable-lkg.json
tools/data/qb-locale-lkg.json
tests/fixtures/qb-release-catalog.lkg.json
```

只有这些路径变化才意味着旧 materialized payload 不能代表当前 dev；其它 docs/tests/workflows/tooling/repository-only 变化可在 GitHub compare 证明后复用已验证 payload。

stale gate 仍保持 fail-closed：compare 必须证明 current HEAD `ahead`，文件列表必须非空且小于 300，文件名按 NUL-safe 方式处理；unknown/truncated/异常状态不得放行。
