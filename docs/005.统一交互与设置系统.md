# 005. 统一交互、Settings 与 Locale 系统

Status: **current Settings / Locale / qB-owned copy / shared interaction contract**

## 1. Settings owner

当前 Preference presence/value 只来自 `GET /api/v2/app/preferences`。`W.SettingsSchema + private/data/settings-compat.json` 拥有 Preference surface/type/unit/enum/getter/setter descriptor；当前 release certified/write provenance gate来自 runtime compatibility identity；`W.QBClient` 只 transport。

```text
user edit
-> current Preference exists
-> SettingsSchema exact descriptor proves writable/type
-> certified write provenance
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> verified value becomes truth
```

Unknown/unproven values只读，危险 write fail closed。

## 2. Settings layout / compound controls

Settings 顶层布局只有一个 owner：canonical SettingsGrid + `W.SettingsRenderer`。Source/schema 决定 SettingRow 是否存在、属于哪个 section、是否 writable；presentation 只能投影这些 facts。

一个 SettingRow 内允许把语义紧密关联的控件组合在一起，例如：

```text
Listen port + Random
schedule From + To
```

但 **compound control 只说明 row 内部有多个控件，不代表整个 row 必须 full-span**。顶层 row 默认仍占一个标准 grid cell；只有独立 source/layout contract 明确证明需要时才跨两列。不得用 `.setting-row--compound { grid-column: 1/-1 }` 这类全局规则把所有组合项强制拉满。

测试必须优先绑定稳定 semantic owner（例如 `data-setting-key` / canonical control role），同时考虑 compound row 的真实 DOM 层级。若 browser test 找不到 input，先核对当前 renderer 输出和 readiness，再判断是 selector stale、surface 未 ready，还是产品确实没渲染；禁止只加 timeout、删断言或恢复旧 DOM 来让测试变绿。

## 3. Locale / qB-owned copy

唯一 persisted language truth是 `qB app/preferences.locale`。qB-owned wording不维护第二手写翻译表，统一走 `W.I18n`：exact source/context + `qb-settings-native.txt` + source-proven official QM；只有 source-proven Alternative WebUI hard gap才使用 compact official-TS bridge。

`4.5.0 -> 4.6.4` 的 document-translation gap继续保留。完整 TS/recovery/source evidence只在 tools/CI，最终 runtime只携带实际引用的 compact registry与 minimal QM。

Locale bootstrap 的正确链路是：

```text
browser/session locale intent
-> canonical bootstrap decision
-> qB app/preferences.locale persisted truth
-> reread/observed locale
-> W.I18n presentation
```

`W.I18n` 只负责 presentation，不得偷偷成为第二 persisted language owner。出现 `zh-CN browser -> qB locale en` 时，不能用前端强制中文显示来掩盖；必须检查 bootstrap 初始化顺序、session/reset、simulator Preferences truth 与真实 qB write/reread contract。

## 4. Self-contained runtime

```text
capabilities.json / torrent-compat.json / detail-compat.json / source-actions.json
settings-compat.json
qb-settings-native.txt
translations/webui_*.qm
```

`release-profile.js`、`qb-releases.json`、`qb-release-profiles/`、旧 per-release Settings/translation shards 已退休，不得回流。

历史 connector bootstrap payload/workflow 不是产品 runtime，也不是 distribution asset；最终产品树必须不包含 `.weigg-bootstrap/**` 或一次性 `dev-bootstrap-*.yml`。

## 5. Shared interaction

Settings/Detail复用 canonical `W.Components` 与 shared Input/Button/Dialog/Select；Detail tables复用 `W.SharedColumns / W.ColumnInteraction`。Desktop/Mobile只是同一 state 的 adaptive presentation，不建立第二控件、action、language、scroll或polling owner。

Torrent/Detail 的虚拟滚动交互继续由 canonical `W.VirtualList` 拥有。滚动或 scrollbar drag 期间可以继续获取 polling 数据，但 DOM replacement 必须延后，只保留 latest pending snapshot并在 bounded idle 后一次提交。

## 6. Detail copy/action chain

```text
W.CapabilityRegistry.torrentDetailUi()
-> W.QbUiEvidence
-> generic Detail runtime
-> W.CapabilityRegistry.actionDescriptor()
-> W.QBClient for transport
```

Copy等 source-proven local action继续 browser-local。真实 file row 的本地 Copy surface可以提供文件路径和所在文件夹路径，但路径分隔符/形态来自 qB 返回 host path，不从浏览器 OS 猜；synthetic folder 不伪装成 qB file。无法证明 required parameter/endpoint/action时零 HTTP。

## 7. Validation

必须持续证明 app/preferences truth、setter/type safety、locale verification、4.5.0-4.6.4 hard gap、minimal QM、old runtime absence与 Universal Portable self-contained。Settings browser evidence需要验证用户动作 + semantic state + visible final state，而不是只验证 DOM 存在。

Pages build/deploy 成功不自动证明 locale/settings live acceptance；required live lane 的 timeout/assertion failure仍然是 FAIL。Promotion/main/tag/Release另需用户授权。
