## 2. A3 real-interaction / dynamic-options / presentation closure

A2证明“source node/accounting完整、DOM存在、synthetic browser路径能Save/reread”仍不足以等价于真实Options可用。A3的验收单位扩展为**真实用户交互链**：

~~~text
visible control
-> real pointer/click/keyboard interaction
-> canonical component callback
-> Settings draft mutation
-> live predicate/dependency recompute
-> dependent control/action presentation
-> Save/setPreferences/reread OR exact source action/dialog
~~~

### 2.1 Canonical Select必须证明真实可操作

所有 Settings Select 都复用 `W.Components.selectControl()`；不得建立Settings专用第二Select。A3必须验证：

- visible option可由真实pointer/click/keyboard选中；
- option value进入同一个Settings draft；
- setValue/setOptions等presentation同步不能吞掉用户callback；
- re-render后选择值不被旧draft/current prefs覆盖；
- dependent controls基于**新draft**立即重算；
- browser acceptance不得只靠直接赋值、synthetic `change` 或调用内部callback证明“可选”。

Downloads content-layout/stop-condition、BitTorrent encryption/seed-limit action、Advanced dynamic choices只是代表性复现点；修复必须属于shared Select/Settings owner。

### 2.2 Dependency、helper/action与disabled feedback

Preference dependency和source action是不同语义，但都必须由exact source facts驱动。A3要区分：

- parent draft改变后predicate graph是否即时重算；
- child Select本身是否可写；
- helper/action是否有source identity、enable condition与canonical click owner；
- disabled source action若qB原生要求feedback/dialog，不能被简单隐藏。

RSS auto-download + Edit auto downloading rules是本轮代表案例。不得写 `if(tab==='rss')` 或指定key组合来复制qB逻辑。

### 2.3 Static options、runtime dynamic options、API-omitted/write-only controls

Select option来源必须可证明，至少分：

~~~text
exact source static options
source-proven runtime/API dynamic options
current value only (not an option inventory)
~~~

Network interface / optional IP address这类control不能把“当前字符串值”误当完整option list，也不能凭空构造选项。

Web UI Password已证明属于setter-only/write-only：source control存在、GET current value缺省、setter direct identity与omit-empty语义均有exact source证据。正式runtime使用generic `writeOnly` metadata，不以Password key特判；普通Preference仍不放宽current-key门禁。

### 2.4 Generic long-copy layout

Settings row不得假设label/description固定单行。Long label、description、switch/input、inline cluster需要intrinsic height / wrap / min-width规则，避免文本和control重叠。布局仍只根据row shape/content class/responsive width决定，不按Preference key或具体中文字符串决定。

### 2.5 Time composite presentation

Scheduler等time-composite的raw numeric value与display text分离。若source UI语义是时:分，minute display需要统一的time formatter（例如0显示为00）；不得改变raw Preference类型，也不得给 `schedule_from_min` 等key写专用formatter。

### 2.6 Exact locale/context closure

所有runtime显示的 qB-owned graph refs继续走 exact `{source,context}` + exact-release official translation。A3第三轮人工复核新增 I2P quantity/length 等英文fallback证据；必须先验证source/context identity和official zh_CN是否存在。官方有翻译却fallback English是closure bug；官方本来无翻译时才允许 upstream English。

## 8. Shared interaction

Settings/Detail继续复用canonical `W.Components` 与 shared Input/Button/Dialog/Select；Desktop/Mobile只是同一semantic state的adaptive presentation。

A2新增两条shared interaction contract：

1. **Canonical Select real interaction**：Settings Select必须通过shared `W.Components.selectControl()`完成真实用户option选择并回写同一draft；synthetic value/change不能代替此验收。
2. **Settings row intrinsic layout**：由row shape/semantic/content length/width class决定wrap与packing；长label/description必须增长行高，禁止key/string特判。
3. **Expandable textarea**：inline textarea与expanded Dialog必须共享同一个draft value；Dialog不是第二editor owner、第二save path或第二persistent state。
4. **Time composite formatting**：时/分等显示由generic formatter负责，presentation zero-padding不改变raw value。
5. **Dynamic/write-only controls**：option inventory与current value分离；source control存在性与API是否返回current value分离。

Torrent/Detail现有VirtualList/scroll contract不变。

## A3：source-proven write-only 与 presentation

Settings 允许一种严格受限的 setter-only/write-only 控件：只有 exact source 同时证明 Options 控件、`setPreferencesAction` 写键/类型、direct write 与 `omitEmpty` 语义时，才可在当前 key 不出现在 `GET /app/preferences` 的情况下进入同一 Settings draft/save owner。此类值永不预填、永不缓存旧值；保存后立即清空，只验证请求成功与普通 preferences 可继续回读，不把“读不到 secret”误判为失败。

显示值与 raw preference 分离：若 exact Options source 明确通过纯 presentation helper（例如单字符前补 `0`）显示数值，Control Graph 应携带通用 `displayFormat`；renderer 只格式化显示，不改变 raw value / projection / write safety。RSS Downloader 的禁用提示同样必须来自 exact source/context copy，不能在 WeiG 里另写一份 qB 文案。
