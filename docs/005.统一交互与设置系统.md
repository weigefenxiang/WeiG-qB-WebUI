# 005. 统一交互、Settings 与 Locale 系统

Status: **current Settings / Locale / qB-owned copy / shared interaction contract + approved runtime-convergence target**

本文件合并维护 Settings、Locale、qB-owned translation 与 shared interaction 的当前长期契约，并记录用户已批准、尚未实现的 Runtime Distribution / Settings / Translation 轻量化收口目标。历史翻译事故/版本复盘不再单独成文；Git history负责历史，当前 source/runtime contract以本文件、`docs/003` 与 `DESIGN.md` 为准。

凡本文写明 **current** 的内容是现行行为；写明 **approved target / planned** 的内容是下一阶段目标，在对应 `webui/**` / tools 代码提交并通过 exact-SHA 验证前不得误报为已实现。

## 1. Canonical controls

Settings 与详情工具优先复用：

```text
W.Components.selectControl()
switch-control
canonical Input / Button / Dialog / Feedback
shared section/grid/row layout
W.SharedColumns / W.ColumnInteraction where table semantics match
```

不为 qB4/qB5、Desktop/Mobile、某个 tab 或某个语言建立第二套控件系统。

## 2. Settings owner 与 WebAPI truth

Canonical Settings surfaces：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing由 `W.SettingsSchema` 唯一负责：

```text
exact descriptor
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

每个 admitted exact release的 Preference descriptor来自 upstream getter/setter source，并区分：

```text
read/getter provenance
write/setter provenance
type/kind confidence
getter/setter agreement
writable
enum/value provenance
```

未知 scalar在没有 exact setter provenance时只读；未知 array/object可见但只读。禁止猜 unit、enum、range、startup default或 blind write。

### 2.1 Current API capability

`W.QBClient` 已有 canonical：

```text
GET  api/v2/app/preferences
POST api/v2/app/setPreferences
```

因此当前 qB 实例的 **Preference presence + current value** 可以直接由 `app/preferences` 获得；Settings 页面不需要一份 61-release runtime database 才能知道“当前 qB 返回了什么值”。

但必须严格区分：

```text
GET app/preferences 返回 key
!=
证明该 key 可以安全写回
```

例如 write-only / intentionally omitted values、historical setter differences、type mismatch 都要求 exact source provenance。下一阶段删除 runtime `qb-settings` 时，**只能删除大体积 Settings UI/translation runtime data，不能删除 Preference getter/setter/type/write provenance**。

### 2.2 Approved target: Settings runtime chain

下一阶段正式目标：

```text
QBClient.getPreferences()
  -> current qB actual keys + values
  -> W.SettingsSchema canonical grouping/control semantics
  -> W.ReleaseProfile preference descriptor exact provenance
  -> W.SettingsRenderer
```

Write仍固定为：

```text
user edit
-> specific Preference writable/type proof
-> setPreferences action proof
-> W.QBClient.setPreferences()
-> W.QBClient.getPreferences() verification reread
-> only verified value becomes truth
```

因此 planned runtime不再需要：

```text
private/data/qb-settings/<sourceSha>.json   # all-release Settings UI/translation shards
qb-settings-native.txt                     # large generated native registry, if no remaining runtime consumer
```

是否删除 `qb-settings-native.txt` 必须先做 complete caller audit；没有 remaining runtime consumer 后才退休，不能只因为文件大就删。

Full Settings/source LKG、official TS extraction 与 historical evidence仍保留在 `tools/**`、CI/artifacts/source pipeline，作为 build-time proof，而不是每个用户都必须携带的 runtime payload。

## 3. Locale 只有一个 persisted truth

唯一持久语言真值：

```text
qB app/preferences.locale
```

WeiG 不保存第二份 `weigg-language`，也不通过 browser `languagechange` 建立反向写入 owner。

两个 UI入口可以存在：

```text
WeiG Interface -> Language
qB Settings -> Advanced -> Locale
```

但它们共享同一个 Settings draft/value/options/save transaction。

普通 locale save：

```text
user edits locale
-> Settings draft
-> exact writable provenance check
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> verified prefs snapshot
-> canonical presentation locale refresh
-> rerender existing canonical DOM
```

Write失败时不切视觉语言；write成功但 verification reread失败时不能把未确认 draft提升为 rendered truth。

下一阶段可以重构 `W.I18n` 内部实现，但不能产生第二 persisted locale owner；任何 `setLocale`/browser-only language state都只能是 verified `app/preferences.locale` 的 presentation projection。

## 4. 返回原生 WebUI 的 locale/root handoff

关闭 Alternative WebUI 时，root 与 translator owner会切换。该 bounded transaction继续由 `W.SessionController`负责：

```text
plan current prefs + pending
-> if required, write/verify temporary locale while Alternative root active
-> disable alternative_webui_enabled
-> after built-in root active, write/verify final target locale
-> normal final verification reread
```

约束：

```text
最终 persisted truth仍只有 app/preferences.locale
不保存 previousLocale
不做 exit restore
用户显式目标 locale必须保持 final target
temporary locale只是 transaction中间值
任一阶段失败都不能把未验证 draft提升为最终 truth
```

删除或精简 Alternative WebUI 自己的 translation assets **不得影响返回 built-in qB WebUI 后的内置语言资源**；built-in root 与 Alternative root 必须分别验证。

## 5. Locale options source truth

真实 qB：

```text
private/views/preferences.html
-> qB WebApplication replaces ${LANGUAGE_OPTIONS}
-> running runtime locale code + localized language name
```

Virtual/historical exact profile使用 source-SHA-bound frozen locale facts。历史 alias/normalization只在 canonical locale source layer处理，禁止 Settings caller写 patch-version分支。

当前 admitted latest surface为61项是 operational fact，不提升为永久常量。

## 6. qB-owned copy 与 WeiG-owned copy 边界

长期原则：

> qB upstream 已拥有且可以证明 exact source/context 的语义，WeiG 不重新拥有其译文；WeiG 自己新增的语义，不能伪装成 qB 官方翻译。

qB-owned examples：

```text
Settings tabs / preference labels
Torrent status/filter captions
Transfer rate mode labels
Torrent Detail tabs / groups / field labels / table columns
Torrent Detail file-priority options / Tracker/Peer context-menu labels
```

WeiG-owned examples：

```text
WeiG Interface / Theme / Starfield / Motion
WeiG diagnostics / compatibility notices
WeiG-specific layout/help/feedback
About / Brand / project identity
Private / PT where qB has no equivalent source/context
```

Presentation modules只消费 canonical translation API，不维护手写 `中文 -> 英文` 或多语言副本。

Approved target进一步收紧为：

```text
qB-owned wording
-> exact qB source text + CONTEXT
-> official translation route

WeiG-owned wording
-> small WeiG-owned dictionary only
```

现有 `i18n.js` 中如果某条文案其实存在 exact qB source/context，应在迁移时改走 qB-owned route并删除 WeiG duplicate；只有真正 WeiG-specific 的文案才继续由 WeiG 自己维护。

## 7. WebAPI 与 qB native translation 的真实边界

### 7.1 WebAPI 不提供通用 translation dictionary

WebAPI可以提供：

```text
app/version
app/webapiVersion
app/preferences.locale
app/preferences current values
```

但当前正式设计不能假设存在：

```text
/api/v2/app/translations
/api/v2/app/translate
/api/v2/app/qm
```

也不能假设浏览器 JS 可以直接读取 qB executable 内部 Qt resource。Translation不是 `app/preferences` 的延伸能力。

### 7.2 qB native translation 是 server-side document translation

qB official WebUI使用：

```text
QBT_TR(Source text)QBT_TR[CONTEXT=ContextName]
```

qB WebApplication在把 HTML/JS 文档发给浏览器之前解析 marker，使用当前 locale 的 Qt translator替换为译文；译文不存在时回退 source text。

因此 native-first 的正确含义是：

```text
exact qB source/context
-> literal QBT_TR marker in a translatable served document
-> exact source-proven WebApplication translator behavior
-> official translation
```

不是“JS通过 WebAPI 下载翻译表”。

### 7.3 Alternative WebUI root limitation

当前 qB source family中，Alternative WebUI启用后 WebApplication root会切到 Alternative WebUI root；translator asset route也与 active root/source behavior绑定。不能假设 Alternative WebUI 缺少自己的 QM时会自动 fallback到 built-in `:/www/translations`。

所以在当前 upstream条件下，Universal Portable若要求：

```text
all supported qB releases
+ offline
+ qB-owned wording official/native-first
```

就不能简单把所有 Alternative-WebUI translation runtime asset全部删掉。

未来若 qB upstream新增“Alternative root missing locale QM -> built-in translation fallback”，只能把它作为 **new source-proven capability** 使用；由于 WeiG support floor仍是 qB 4.1.0，未来新 qB 的 fallback也不能自动让历史 qB所需资产从 Universal Portable全局消失。

## 8. qB native-first translator families

Alternative WebUI 是否真正能执行 document translation必须按 exact sourceSha证明，不能只看 `.qm` 是否存在。

Source-derived translator families当前长期 hard boundaries：

```text
4.1.0 -> 4.1.3   qApp/native translator family
4.1.4            dedicated translator, strict/fail-closed family
4.1.5 -> 4.4.5   dedicated native document translation
4.5.0 -> 4.6.4   Alternative WebUI document translation disabled
4.6.5+            dedicated native document translation restored
```

因此 `4.5.0 -> 4.6.4` 必须保留 exact official-TS compatibility bridge；不能因为安装了 recovery QM就宣称 native path成立。

Current routing concept：

```text
exact profile + native-capable
-> qB native registry / QBT_TR / official QM

exact profile + source-proven Alternative-WebUI gap
-> official-TS compatibility bridge

route unresolved
-> fail closed / source fallback behavior
```

Bridge是 transport，不是第二 translation owner。

## 9. Approved target: runtime translation slimming

下一阶段不是“抛弃 official translation”，而是把 full build/source knowledge编译成最小 runtime translation assets。

### 9.1 Native-capable releases: minimal official QM

Build-time先对正式 `webui/**` 做 exact qB-owned translation-ref inventory：

```text
all qB-owned QBT_TR source/context actually referenced by WeiG
+ dynamic source refs that runtime can prove/use
-> unique required ref set
```

然后从 official TS / deterministic recovery evidence只生成这些 refs需要的 QM messages，而不是把完整 qB WebUI translation body复制进每个 `webui_<locale>.qm`。

当前 qB QTranslator filename contract按 locale加载独立 `webui_<locale>.qm` 时，**支持全部 locale意味着文件数量仍大致按 locale 数量存在**；不能为了“只有一个文件”伪造 native translator contract。优化重点先是：

```text
full QM -> minimal QM content
```

而不是虚构一个 qB不会加载的单文件格式。

每个 minimal QM必须仍然来自 official source/context + official translation evidence；缺失 translation按 qB原生 fallback语义处理，不由 WeiG手写补成“官方翻译”。

### 9.2 4.5.0 -> 4.6.4 gap: compact official bridge

这一 family不能依赖 document QBT_TR translation。下一阶段必须退休当前 per-release full Settings translation shard bridge，改为 **只覆盖 WeiG实际引用的 qB-owned refs** 的 compact bridge。

优先设计：

```text
exact gap release/source identity
+ verified locale
+ qB-owned ref key (source/context or canonical ref id)
-> official translated text
```

Build-time对相同 translation sets做内容去重；runtime asset优先一个 compact bridge/少量 bounded shards，而不是每个 exact release一个巨型 `qb-settings/<sourceSha>.json`。

文件数和大小约束：

```text
prefer one compact bridge asset when under project size budget
split only when required by qB static-file limit / project 5 MiB target
sharding must be deterministic and content-addressable/bounded
runtime loads only the current exact profile + locale path/data it needs
```

不能用“最近版本译文”“相同英文大概一样”等猜测跨 source hard boundary。

### 9.3 WeiG-owned i18n保持极小

WeiG-owned dictionary只允许保存 upstream不存在的 WeiG-specific copy。它可以是一个小 JS/JSON owner，但：

```text
不得复制 qB-owned translation surface
不得拥有第二 persisted locale
不得覆盖 exact qB official text with a hand-written alternate translation
```

## 10. Approved target: materialized distribution cleanup

当前 source `webui/**` 本身较轻；大目录主要由 build/materialization生成。下一阶段要修改的是 **compiler/materializer + runtime consumer contract**，不是把 source/CI evidence粗暴删除。

正式目标：

```text
REMOVE from end-user runtime when no remaining consumer:
- private/data/qb-settings/
- qb-settings-native.txt
- full/unfiltered qB WebUI QM payloads
- duplicated all-release/all-locale translation sets

KEEP:
- app/preferences WebAPI runtime reads/writes
- W.SettingsSchema small canonical semantics
- exact Preference write provenance needed for fail-closed
- qB-owned source/context refs needed by actual product surfaces
- minimal official QM for native-capable route
- compact official-TS bridge for proven native-gap route
- small WeiG-owned i18n only for WeiG semantics
```

`qb-release-profiles` 当前约束不同：它承担 exact release/source/action/parameter/field/Preference provenance。**本次首轮不以删除 `qb-release-profiles` 为目标。** 等 Settings/translation runtime收口完成并有 exact package metrics后，再由用户决定是否单独做 profile runtime-IR dedupe；任何 profile优化都必须保持 exact source identity、bounded inheritance与dangerous-write fail closed。

## 11. Implementation sequence / atomic cutover requirements

下一阶段必须按以下顺序执行，不能边删资产边补 fallback：

```text
A. fresh source/runtime audit
B. define new runtime contracts + tests first
C. switch Settings current-value/presence path to WebAPI-owned truth
D. cut qB Settings translation/UI runtime dependence
E. inventory qB-owned refs and generate minimal official translation assets
F. replace 4.5.0-4.6.4 full shard bridge with compact exact bridge
G. retire obsolete materialized assets + old loaders atomically
H. verify package/runtime across representative qB families/locales
I. only then update current-fact docs / VERSION as required
```

Owner cutover要求：

```text
new owner proven
+ all callers switched
+ tests updated
+ old qb-settings/native-registry runtime loader retired
+ no dual translation/settings runtime path
```

禁止长期保留“新 WebAPI Settings + 旧 qb-settings fallback”双 active；如果过渡必须在同一 coherent change内完成并退休旧 owner。

## 12. Acceptance criteria for the convergence

产品层至少必须证明：

```text
1. Settings values/presence来自真实 app/preferences，而不是 historical runtime shard。
2. unknown returned Preference可见但未证明setter/type时只读；危险write仍HTTP前fail closed。
3. runtime package不再包含 private/data/qb-settings/。
4. qb-settings-native.txt只有在完整caller audit证明仍必要时才保留；否则退休。
5. qB-owned wording native-capable release优先走exact QBT_TR/source-context官方路线。
6. 4.5.0-4.6.4 gap继续得到exact official translation bridge，不退化为手写WeiG翻译。
7. WeiG-owned i18n不复制qB-owned wording。
8. locale唯一persisted truth仍是 app/preferences.locale；切换语言write+verification语义不退化。
9. 返回built-in qB WebUI后各语言仍由built-in root正常工作。
10. Universal Portable仍可离线复制到受支持qB直接使用，不依赖tools/simulator/GitHub。
11. qB static hard limit 10 MiB/file继续满足；project target优先保持 <=5 MiB/file。
12. materialized runtime总size与重复度相对当前checkpoint显著下降，并输出可审计size report。
```

验证覆盖至少包括 translator family代表点：

```text
4.1.0-4.1.3 family representative
4.1.4 strict family
4.1.5-4.4.5 native family representative
4.5.0-4.6.4 gap representative(s)
4.6.5+ native family representative
current latest stable
```

并至少覆盖：English + 简体中文 + 一个非中文非英文 locale；如 source facts显示 alias/locale-route风险，再增加对应locale。

Release-level manual matrices、promotion/main/tag/Release仍需要用户另行明确授权，不能因为本阶段产品CI绿色自动执行。

## 13. Torrent Detail shared interaction

Torrent Detail 原版语义当前已经收口到 shared owners，不再按 tab 维护第二套 UI/action/state。

Source/runtime链：

```text
W.ReleaseProfile.torrentDetailUi
-> W.QbUiEvidence exact projection
-> generic app Detail runtime
-> W.SharedColumns / W.ColumnInteraction
-> W.CapabilityRegistry / W.ReleaseProfile.actionDescriptor
-> W.QBClient transport
```

### 13.1 Tabs / General / qB-owned copy

Detail tab order/existence、General group/field labels、table column labels、file-priority option labels与 Tracker/Peer context-menu labels都来自 exact qB source/context并通过 canonical qB-owned translation path渲染。

禁止手写 `概览/普通/Peers/用户` 等语言映射；没有 exact source/context时不能把 WeiG自己的翻译伪装成 qB官方文案。

### 13.2 Shared columns / first toolbar rail

Detail Columns live-apply同一 state：

```text
checkbox change
-> W.SharedColumns.commit(...)
-> ctx.apply(true)
-> canonical detail rebuild/projection
```

Resize/reorder：

```text
resize handle -> resize only
pointermove -> live width/grid-template only
pointerup -> commit/persist once
header body drag -> reorder
normal touch scroll -> not reorder
long-press -> intentional mobile reorder
```

Columns entry必须加入当前 surface已有的 first toolbar row；zero-selection source actions也复用同一 rail。不得为 Columns另占一整行或写绝对定位补丁。

Header与body消费同一个 resolved column definition和grid template；`.shared-table__viewport`是单一 horizontal scroll owner。禁止 MutationObserver、scrollLeft repair、第二 column state或第二 viewport。

### 13.3 Tracker URL / Peer flag

Tracker Detail exact URL是业务值：presentation只允许单行 ellipsis + tooltip/title，不允许 `normalizeTracker()`改变 path/query。

Peer country flag复用 shared ISO alpha-2 `U.countryFlag()`/canonical equivalent，消费 exact `country_code`；禁止 country-name -> flag 静态表。

### 13.4 Generic row actions / context menu

Tracker/Peer永久 inline Edit/Delete/`×`操作已退休。Row action presentation来自 source-generated context menu；真实 support由 exact source action/capability + QBClient决定。

```text
context menu item
-> source availability
-> ReleaseProfile.actionDescriptor
-> endpoint agreement
-> required/optional parameter contract + options
-> generic parameter binding
-> QBClient request
```

不能绑定 required parameter、source action不成立或 endpoint不一致时，必须在 HTTP 前 fail closed。Runtime不得按已知 endpoint名字重新写一套 Tracker/Peer分支。

## 14. Editability / fail-closed

Exact stable Preference只有同时满足：

```text
setPreferences action proven
setter exists
write type understood
getter/setter type agrees
descriptor writable == true
```

才可编辑。危险 mutation若依赖多个 upstream actions/parameters，必须 all-required proven，UI gate与 `W.QBClient` transport preflight双层 fail closed。

删除 runtime Settings translation/data shard不能降低此标准。

## 15. Mobile / responsive

Mobile使用同一 Settings DOM/state/save flow与同一 Detail column/action state；只允许 adaptive placement/geometry，不建立第二 locale、draft、columns、context-menu capability或 translation owner。
