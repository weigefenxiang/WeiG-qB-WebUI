## 1. Settings 当前 owner 与 A 阶段状态

当前业务值的唯一 truth仍是 `GET /api/v2/app/preferences`。A 的 formal runtime atomic cutover 已完成实现，正式链路现在是：

```text
exact source-native Preferences IR
-> bounded settings-compat.json envelope
-> W.CapabilityRegistry lazy integrity + catalog/exact-release identity gate
-> W.SettingsSchema exact source adapter
-> exact tabs / sections / order / controls / attributes / options / units / dependencies
∩ current GET /api/v2/app/preferences
-> W.SettingsRenderer generic canonical rows
```

危险写入固定为：

```text
user edit
-> certified exact/equivalent release
-> exact source setPreferences action proven
-> current app/preferences contains the Preference key
-> exact descriptor proves setter + writable + type agreement
-> source projection.safeWrite == true
-> source dependency gates satisfied
-> outgoing raw value matches proven write type
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> verified value becomes truth
```

`W.SettingsSchema.writableDraft()` 在 save-time 再执行同一门禁；UI editable 状态与最终 HTTP write gate不能只依赖其中一层。Unknown/unproven/composite inverse unknown路径保持只读/fail closed。

Source value projection直接使用 exact evidence：`identity / scale / switch-map / unproven`。`switch-map` 若只有read map而没有source-proven inverse必须只读。唯一窄例外仍是 #1856 已证明的 direct-string write：exact writable string descriptor + native text/select/password/textarea + source direct identity setter，可记录 `writeIdentity:true + safeWrite:true`；numeric/structured/composite不会继承该例外。

旧的 qB-owned manual runtime truth已经退休：`SURFACES / SECTION_ORDER / SECTION_TITLES / META / FAMILY_RULES / add()` 不再参与正式 Settings projection。`tools/qb-compact-runtime.mjs` 也不再从旧 descriptor/nativeTabs 重建第二份 Settings truth；它只验证和包装 source-native payload。

当前 A 实现仍需最终 product SHA 的 automated validation。只有 ordinary CI、Pages Source及受影响 Virtual qB/browser lane全部通过后，A 才能进入 `🟠 IMPLEMENTED — WAITING HUMAN REVIEW`；用户人工复核之前不得宣告 `✅ VERIFIED DONE`，也不得自动进入 B。

### 1.1 Runtime payload / identity

`settings-compat.json` 是单一 Settings domain入口，使用 bounded compressed transport；canonical semantic identity不是压缩流本身，而是解压后的 source-native IR SHA + Frozen catalog identity。当前 accepted payload必须保持 #1856 的 **311540 bytes** / SHA256 `2784279c685ffc3df3cd4bb5bcdcb3838e50940ccdc2cb83d32e7a3cf04b326f`，并与65个 exact `qbVersion + sourceSha`逐项一致。mixed/stale bytes、catalog mismatch、release-set mismatch任一发生都fail closed。

## 2. Settings layout / compound controls

Settings顶层布局只有一个 owner：canonical SettingsGrid + `W.SettingsRenderer`。Source-native schema决定 SettingRow是否存在、属于哪个tab/section、source order、control semantic、attributes/options/unit/dependency与是否 writable；presentation只投影这些 facts。

旧 Listening port + Random 与 Schedule From/To compound helpers已从正式renderer退休。原因不是“compound永远禁止”，而是当前 #1856 exact source IR没有独立证明这些synthetic组合应作为一个canonical row owner。当前安全行为是每个 source-proven Preference各自使用canonical row/control；未来若 exact source/admission能够证明一个稳定compound composition，可以由source contract显式表达，再由generic renderer消费，不能恢复patch-version rule或手工key list。

测试绑定稳定 semantic owner：`data-setting-key` / canonical control role / exact source order。Browser test不得继续期待 synthetic `schedule_range` 等旧DOM，也不能通过增加timeout、删除断言或恢复旧owner来让测试变绿。

移动端继续只负责presentation：短行保持同一行，说明文字过长时把同一个canonical control移到下一行；responsive逻辑不得改变 Preference存在性、可写性、依赖或raw/UI语义。

## 3. Native Options identity

WeiG外层不应把 qB native Preferences surface重新命名成一套独立“Settings”产品语义。qB-owned native surface identity必须来自对应 exact release upstream source；例如 toolbar/title/source里是 `Options` 时，显示文本由 official qB translation解析。

固定八 native-tab whitelist已从 compact tooling退休；当前按 exact `qbOwnedUi` 的 `settings.tab.*` source facts动态提取 native tab集合/顺序。历史已知 change point只作为 evidence，不应再变成固定 allowlist或未来版本 if/else。

## 4. Preferences independent census

A source layer现在有独立于 semantic extractor 的 census：

```text
raw Preferences source
-> independent tab inventory
-> independent read/write app/preferences references
-> independent source-bound control bindings
-> account against semantic manifest + explicit reviewed exclusions
```

Full-stable Preferences source contract要求每个 admitted release的 `tabs / preferences / bindings` census均 complete；出现 `unaccounted / overlap / escaped / duplicate` 直接 FAIL。Raw helper/client-only controls可以保留为 diagnostics，但不能假装成 app/preferences completeness blocker。

因此“Preferences census 尚未实现”已不是 TODO；A当前 blocker是**正式 runtime cutover**。Mapping ratio仍可保留为 parser健康度信号，但不能代替 census，也不能因为 ratio达到某阈值就忽略新语法。

## 5. Locale / qB-owned copy

唯一 persisted language truth是 `qB app/preferences.locale`。qB-owned wording不维护第二手写翻译表，统一走 `W.I18n`：exact `{source, context}` + exact-release official translation facts；只有 source-proven Alternative WebUI hard gap才使用 compact official-TS bridge。官方目标 locale缺失时允许回退 **upstream English source**，不允许回退 WeiG手写“官方中文”。

当前 runtime仍使用 Settings-focused `qb-settings-native.txt` + minimal official QM。C阶段若把它泛化为 domain-neutral qB-owned copy artifact，必须一次切换 generator、runtime loader、callers、tests、distribution contract并删除旧 artifact；不得保留 `qb-settings-native.txt` 和新文件两套 active registry。

`4.5.0 -> 4.6.4` document-translation hard gap继续保留。完整 TS/recovery/source evidence只在 tools/CI，最终 runtime只携带实际引用的 compact registry与 minimal QM。

Locale bootstrap正确链路：

```text
browser/session locale intent
-> canonical bootstrap decision
-> qB app/preferences.locale persisted truth
-> reread/observed locale
-> W.I18n presentation
```

`W.I18n` 只负责 presentation，不得偷偷成为第二 persisted language owner。出现 `zh-CN browser -> qB locale en` 时，不能用前端强制中文显示掩盖；必须检查 bootstrap初始化顺序、session/reset、simulator Preferences truth与真实 qB write/reread contract。

## 8. Shared interaction

Settings/Detail复用 canonical `W.Components` 与 shared Input/Button/Dialog/Select；Detail tables复用 `W.SharedColumns / W.ColumnInteraction`。Desktop/Mobile只是同一 state 的 adaptive presentation，不建立第二控件、action、language、scroll或polling owner。

Torrent/Detail虚拟滚动交互继续由 canonical `W.VirtualList`拥有。滚动或 scrollbar drag期间可以继续获取 polling数据，但 DOM replacement必须延后，只保留 latest pending snapshot并在 bounded idle后一次提交。

## 9. Validation

A阶段内部使用与当前 product cutover直接相关的 source parser/unit/change-point/focused browser tests；A完整收口后最多一次65-release offline/Virtual Settings matrix。Independent census已经是 source gate基础，不应重复造第二 census；下一步重点是让 formal runtime真正消费 source-native IR/projection并删除旧 owner。
