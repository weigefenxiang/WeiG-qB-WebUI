# 005. 统一交互、Settings 与 Locale 系统

Status: **current Settings / Locale / qB-owned copy / shared interaction contract**

## 1. Settings 当前 owner 与 A 阶段目标

当前业务值的唯一 truth始终是 `GET /api/v2/app/preferences`。正式写入链固定为：

```text
user edit
-> current Preference exists
-> exact descriptor proves writable/type
-> certified setPreferences write provenance
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> verified value becomes truth
```

Unknown/unproven values只读，危险 write fail closed。

当前 runtime 仍由 `W.SettingsSchema + private/data/settings-compat.json` 投影 Settings；这条链已经 source-drive native tab presence/order，但 `settings-schema.js` 仍手工维护大量 qB-owned section/control/unit/enum/family truth，因此 **A 尚未完成**。

A 的目标不是再加一套 renderer，而是把 exact-source Preferences native IR原子接入 canonical Settings owner：

```text
exact qB Preferences source
+ exact preferenceDescriptors / app/preferences keys
-> native tabs / sections / order / source-context copy
-> control semantic / attributes / options / unit / dependency
-> getter / setter / readType / writeType agreement
-> compact Settings contract
∩ runtime app/preferences
-> W.SettingsSchema / W.SettingsRenderer generic projection
```

新 source-native contract proven 后，必须同批删除被替代的 qB-owned `SURFACES/SECTION_ORDER/SECTION_TITLES/META/FAMILY_RULES/add()` 等手工 truth；禁止 “source schema + legacy schema” 双 active。WeiG 自己的 layout tokens、canonical components 与 presentation rules可以保留，但不能重新定义 qB native semantics。

## 2. Settings layout / compound controls

Settings 顶层布局只有一个 owner：canonical SettingsGrid + `W.SettingsRenderer`。Source/schema 决定 SettingRow 是否存在、属于哪个 section、是否 writable；presentation 只能投影这些 facts。

一个 SettingRow 内允许把语义紧密关联的控件组合在一起，例如：

```text
Listen port + Random
schedule From + To
```

但 **compound control 只说明 row 内部有多个控件，不代表整个 row 必须 full-span**。顶层 row 默认仍占一个标准 grid cell；只有独立 source/layout contract 明确证明需要时才跨两列。

测试必须优先绑定稳定 semantic owner（例如 `data-setting-key` / canonical control role），同时考虑 compound row 的真实 DOM 层级。若 browser test 找不到 input，先核对 current renderer 输出和 readiness，再判断是 selector stale、surface 未 ready，还是产品确实没渲染；禁止只加 timeout、删断言或恢复旧 DOM 来让测试变绿。

## 3. Native Options identity

WeiG 外层不应把 qB native Preferences surface重新命名成一套独立“Settings”产品语义。qB-owned native surface identity必须来自对应 exact release upstream source；例如 toolbar/title/source里是 `Options` 时，显示文本由 official qB translation解析。

历史 tab presence/order必须 source-driven。已知 change points包括：

```text
4.2.x: no Behavior / no RSS tab
4.3.x: RSS tab admitted
4.6+:   Behavior tab admitted
```

这些只是已知事实，不是未来版本 hard-coded if/else；future native tab必须通过 generic source inventory admission进入，而不是修改固定八 tab列表。

## 4. Locale / qB-owned copy

唯一 persisted language truth是 `qB app/preferences.locale`。qB-owned wording不维护第二手写翻译表，统一走 `W.I18n`：exact `{source, context}` + exact-release official translation facts；只有 source-proven Alternative WebUI hard gap才使用 compact official-TS bridge。官方目标 locale缺失时允许回退 **upstream English source**，不允许回退 WeiG 手写“官方中文”。

当前 runtime仍使用 Settings-focused `qb-settings-native.txt` + minimal official QM。C 阶段若把它泛化为 domain-neutral qB-owned copy artifact，必须一次切换 generator、runtime loader、callers、tests、distribution contract并删除旧 artifact；不得保留 `qb-settings-native.txt` 和新文件两套 active registry。

`4.5.0 -> 4.6.4` 的 document-translation hard gap继续保留。完整 TS/recovery/source evidence只在 tools/CI，最终 runtime只携带实际引用的 compact registry与 minimal QM。

Locale bootstrap 的正确链路是：

```text
browser/session locale intent
-> canonical bootstrap decision
-> qB app/preferences.locale persisted truth
-> reread/observed locale
-> W.I18n presentation
```

`W.I18n` 只负责 presentation，不得偷偷成为第二 persisted language owner。出现 `zh-CN browser -> qB locale en` 时，不能用前端强制中文显示来掩盖；必须检查 bootstrap 初始化顺序、session/reset、simulator Preferences truth 与真实 qB write/reread contract。

## 5. qB-owned copy coverage

C 阶段要求所有正式 qB-owned runtime text都能追到 `{source, context}`，至少包括：

```text
Options tabs / sections / controls / options / units
Torrent Status / Categories / Tags / Trackers
RSS Downloader/rule fields/actions where upstream owns wording
Torrent Detail tabs/labels/menu actions
```

WeiG-owned Path、Private/PT、WeiG WebUI、About、WeiG diagnostics继续用 WeiG i18n。不能为了“统一翻译”把 WeiG extension伪装成 qB source string，也不能把 qB native text重新放入 WeiG EN/ZH dictionary。

## 6. Self-contained runtime

```text
capabilities.json
torrent-compat.json
detail-compat.json
settings-compat.json
rss-compat.json
source-actions.json
qb-settings-native.txt          # current artifact until an atomic C cutover replaces it
translations/webui_*.qm
```

`release-profile.js`、`qb-releases.json`、`qb-release-profiles/`、旧 per-release Settings/translation shards 已退休，不得回流。完整 Preferences native source catalog/IR属于 tools/CI/admission input；只有最终 compact runtime projection进入 `webui/**`。

## 7. Shared interaction

Settings/Detail复用 canonical `W.Components` 与 shared Input/Button/Dialog/Select；Detail tables复用 `W.SharedColumns / W.ColumnInteraction`。Desktop/Mobile只是同一 state 的 adaptive presentation，不建立第二控件、action、language、scroll或polling owner。

Torrent/Detail 的虚拟滚动交互继续由 canonical `W.VirtualList` 拥有。滚动或 scrollbar drag 期间可以继续获取 polling 数据，但 DOM replacement 必须延后，只保留 latest pending snapshot并在 bounded idle 后一次提交。

## 8. Validation

A 阶段内部使用 source parser/unit/change-point/focused browser tests；A 完整收口后最多一次 65-release offline/Virtual Settings matrix。必须额外证明 upstream Preferences inventory被全部 mapped 或 explicit excluded；coverage ratio只能是开发信号，不能代替 `unaccounted=0` 的 completion gate。

C 阶段应对所有 admitted release/runtime qB-owned `{source,context}` route做解析检查：official translation存在则 exact resolve；允许 hard gap时回 upstream English；不得落入 WeiG 手写 qB copy。

Pages build/deploy 成功不自动证明 locale/settings live acceptance；required live lane 的 timeout/assertion failure仍然是 FAIL。Promotion/main/tag/Release另需用户授权。
