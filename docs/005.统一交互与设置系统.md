# 005. 统一交互、Settings 与 Locale 系统

Status: **current Settings / Locale / qB-owned copy / shared interaction contract**

本文件维护 Settings、Locale、qB-owned translation 与 shared interaction 的当前长期契约。`webui/**` 是正式产品；source/LKG/CI 负责证明与编译，不把完整历史翻译数据库塞给最终用户。

## 1. Canonical controls 与 owner

Settings 与详情工具复用 `W.Components`、canonical Input/Button/Dialog/Feedback、shared section/grid/row layout；表格语义一致时复用 `W.SharedColumns / W.ColumnInteraction`。不为 qB4/qB5、Desktop/Mobile、某个 tab 或某个语言建立第二套控件/状态系统。

Preference routing由 `W.SettingsSchema` 唯一负责：

```text
exact descriptor
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

当前实例 Preference presence/current value 的唯一运行时事实来自：

```text
GET /api/v2/app/preferences
```

写入仍要求 exact source provenance：

```text
Preference returned by app/preferences
!= proven writable

user edit
-> W.SettingsSchema writable/type proof
-> W.ReleaseProfile exact setter/action provenance
-> W.QBClient.setPreferences()
-> W.QBClient.getPreferences() verification reread
-> only verified value becomes truth
```

未知 scalar/array/object在没有 exact setter/type proof 时只读。Runtime slimming不得降低 dangerous-write fail-closed 标准。

## 2. Locale 只有一个 persisted truth

唯一持久语言真值：

```text
qB app/preferences.locale
```

WeiG不保存第二份 `weigg-language`。WeiG Interface -> Language 与 qB Settings -> Advanced -> Locale 可以同时存在，但共享同一个 Settings draft/value/options/save transaction。

普通 locale save：

```text
user edits locale
-> exact writable provenance
-> setPreferences
-> getPreferences verification reread
-> verified prefs snapshot
-> W.I18n.applyLocale(verified locale)
```

Write失败或 verification reread失败时，不把未确认 draft提升为 rendered truth。

关闭 Alternative WebUI 返回 built-in WebUI 的 root/locale handoff仍由 `W.SessionController` 的 bounded transaction负责；最终 persisted truth始终只有 `app/preferences.locale`，不保存 previousLocale，不做 exit restore。

## 3. Locale options source truth

真实 qB：

```text
private/views/preferences.html
-> qB WebApplication replaces ${LANGUAGE_OPTIONS}
-> running locale code + localized language label
```

Virtual/historical profile使用 exact source-SHA-bound frozen locale facts。Alias/normalization只在 canonical locale source/I18n layer处理，Settings caller不得写 patch-version分支。

## 4. qB-owned copy 与 WeiG-owned copy

长期边界：

> qB upstream 已拥有且能证明 exact source/context 的语义，WeiG不重新拥有其译文；WeiG新增语义不能伪装成 qB官方翻译。

qB-owned包括 Settings labels/tabs、Torrent status/filter、Transfer rate mode、Torrent Detail tabs/groups/fields/columns/options/context actions等。WeiG-owned包括 Theme/Starfield/Motion、WeiG diagnostics/compat notices、brand/help/layout等。

Presentation modules只消费 canonical `W.I18n.qbSetting/qbText/loadQbOwnedText`，不维护手写 qB 中文/英文副本。

## 5. Current runtime copy architecture（0.3.86）

本轮 runtime-convergence 已完成 atomic cutover。Current chain：

```text
exact qB source + certified Settings/source LKG + deterministic official recovery evidence
-> buildNativeSettingsBundle compiler
-> deduplicated source/context refs
-> deduplicated preference/UI binding sets
-> deduplicated exact compact bridge sets
-> private/data/qb-settings-native.txt
-> W.I18n single qB-owned resolver
```

旧 runtime path 已退休：

```text
private/data/qb-settings/<sourceSha>.json
old full qb-settings-native registry body/format
W.I18n loadSettingsData/loadNativeSettingsData dual loader
release-profile settingsTranslationPath/settingsNativeLocales/settingsTranslationLocales copies
```

完整 Settings/source LKG、official TS/recovery bodies继续保留在 `tools/**`、CI/artifacts/source pipeline，仅作为 build-time proof。

`qb-release-profiles` 继续承担 exact source/action/parameter/field/Preference provenance；本轮不做 profile runtime-IR dedupe。

## 6. Native translation 与 minimal official QM

qB原生翻译仍是 server-side document translation：

```text
QBT_TR(Source)QBT_TR[CONTEXT=Context]
-> qB WebApplication
-> active translator
-> translated document sent to browser
```

不存在可依赖的通用 WebAPI translation dictionary。

Compiler只把 **WeiG实际引用且需要 active Alternative-WebUI root QM 的 source/context** 投影进 `translations/webui_<locale>.qm`：

```text
full deterministic recovery union
-> filter by actual qB-owned runtime refs
-> only active-root native translator families/locales
-> minimal official QM
```

`4.1.0 -> 4.1.3` 使用 application-installed translator，不因为“native”就强塞 Alternative-root QM。English source copy不生成无意义 QM。未引用的 recovery-only messages不进入最终 runtime。

每个 minimal QM仍来自 official source/context + official translation evidence；缺失 translation保持 qB source fallback语义，不由 WeiG手写补译。

## 7. Exact compact bridge

Source-derived translator hard boundaries保持：

```text
4.1.0 -> 4.1.3   qApp/native translator family
4.1.4            dedicated strict family
4.1.5 -> 4.4.5   dedicated native document translation
4.5.0 -> 4.6.4   Alternative WebUI document translation disabled
4.6.5+            dedicated native document translation restored
```

因此 `4.5.0 -> 4.6.4` 以及任何 exact source证明确实不能安全使用 native route 的 locale，继续走 compact bridge：

```text
exact sourceSha/qB version
+ verified locale
+ canonical ref id(source/context)
-> exact official TS text
```

Bridge只包含 WeiG实际引用且译文不同于 source 的 refs；相同 binding/translation content按 hash去重。Bridge与 native route都由同一个 `W.I18n` owner解析，不存在 I18nV2/第二 translation owner。

## 8. Universal Portable / materialized payload

正式产品仍要求：

```text
one materialized WeiG-qB-WebUI folder
+ offline
+ copy to supported qB host
+ set Alternative WebUI path
= works
```

最终用户不需要 Node、tools、Simulator、GitHub或在线下载当前 locale。

Materialized runtime现在保留：

```text
private/data/qb-releases.json
private/data/qb-release-profiles/
private/data/qb-settings-native.txt
translations/webui_<locale>.qm   # minimal, referenced-only
VERSION / GIT_SHA
```

并明确不再生成：

```text
private/data/qb-settings/
old full native-registry body/format (the filename is reused by compact IR)
full/unfiltered recovery QM payloads
```

Distribution manifest输出 core runtime、release profiles、translation assets、redundant bytes、total uncompressed、ZIP bytes、max file等审计指标；单文件继续低于 qB 10 MiB hard limit，并以项目 5 MiB target fail closed。

## 9. Torrent Detail shared interaction

Torrent Detail仍沿用既有 shared owners：

```text
W.ReleaseProfile.torrentDetailUi
-> W.QbUiEvidence
-> generic app Detail runtime
-> W.SharedColumns / W.ColumnInteraction
-> W.CapabilityRegistry / actionDescriptor
-> W.QBClient
```

Tabs/General/table labels/options/context actions中的 qB-owned wording继续通过本文件定义的 canonical qB-owned resolver；列 visibility/order/width、resize/reorder、single horizontal viewport、Tracker exact URL、Peer ISO flag与 generic row actions 的既有 contract不变。
