# 005. 统一交互与设置系统

> 当前 Settings / capability / interaction contract。详细 semantic ownership 以 `DESIGN.md` 为准。

## 1. Canonical controls

Settings 复用统一组件：

```text
W.Components.selectControl()
switch-control
field-input setting-input
canonical Dialog / Feedback
shared section/grid/row layout
```

不为 qB4/qB5、Desktop/Mobile 或某个 tab 建第二套控件系统。

## 2. 六个 qB Settings surfaces

Canonical surfaces：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

## 3. Exact Preference provenance

每个 admitted official stable profile 从 qB upstream getter/setter source 生成 descriptor：

```text
getter/read type/kind/confidence
setter/write type/kind/confidence
getter/setter agreement
writable
enum fallback provenance
```

Setter-only key 不得逃出 `app/preferences` surface。

### Locale / language source facts

`locale` 仍属于同一个 `W.SettingsSchema` Preference surface，不建立第二套 Settings owner。

语言选项只允许来自 qBittorrent 官方 source facts：

```text
running qB injects ${LANGUAGE_OPTIONS}
-> exact runtime locale options

historical / Virtual qB
-> exact release profile webuiLocales
-> source-derived frozen locale facts
```

禁止在 `capabilities.json`、`settings.js` 或 `SettingsSchema` 中维护 qB4/qB5 语言版本表。WeiG Language 与 qB `locale` 的同步必须继续经过 exact setter provenance 与 `QBClient.setPreferences()`；WeiG 的 `auto` 只能解析为当前 qB 实际支持的 locale，不能把 `auto` 写入 qB。

通用 Preference 描述文案在另行处理前保持现有 `qBittorrent preference.` 不变。

## 4. Editability

Exact stable profile 只有同时满足以下条件才可编辑：

```text
setPreferences action proven
setter exists
write type understood
getter/setter type agrees
descriptor writable == true
```

否则可见但 read-only，或按 capability policy隐藏。

Boolean/Enum/Input/Structured control 都消费同一事实；`onDraft` 拒绝 non-writable，保存时 `writableDraft()` 再过滤。

## 5. Unknown / future Preferences

未来 stable 新 key 不静默丢失：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

未知 scalar 在没有 exact setter provenance 时只读；未知 array/object 可见但只读，以结构化 JSON 展示。

禁止猜 unit / enum / range / startup default，也禁止 blind write。

## 6. 与 simulator Endpoint/Transport Contract 的边界

```text
W.SettingsSchema + Preference descriptors
-> key/type/getter/setter/editability

simulator Endpoint Contract
-> historical request/response/status/mutation semantics

simulator Transport Contract
-> auth/header/proxy transport semantics
```

这些职责不能合并成第二套 Settings owner。

同时：

```text
CapabilityRegistry 不决定 Preference writable
SettingsSchema 不维护 endpoint historical response policy
QBClient 不维护产品版本策略
simulator router 不重新解释 Settings UI schema
```

## 7. Owner cutover discipline

未来如果 Settings/Preference owner 真正被替换，必须 atomic cutover：

```text
new owner + callers + contracts + DESIGN
-> remove superseded owner/helpers/tests
```

禁止新旧 Settings router/renderer 长期双活。

## 8. 保存流程

```text
user interaction
-> canonical control
-> SettingsState.draft
-> writableDraft()
-> validateBeforeSave()
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> canonical feedback
```

写成功但 verification read 失败时必须明确显示“已写入但无法确认”，不能伪装完全验证成功。

## 9. Mobile / acceptance

Mobile 使用同一 Settings DOM/state/controls/save flow。

Contracts 至少覆盖：

```text
exact routing
future family routing
missing/getter-only/type-mismatch read-only
source-proven writable scalar
structured unknown read-only
writableDraft() defense-in-depth
canonical control reuse
```

Pages/Chrome 使用 source-derived exact profiles验证六个 Settings surfaces；发布前真实 qB 证明由 G-FM 提供。
