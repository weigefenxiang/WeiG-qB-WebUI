# 005. 统一交互与设置系统

> 当前 Settings / capability / interaction contract。详细 semantic ownership 以 `DESIGN.md` 为准。本文中的“Locale 单一 owner cutover”是下一次产品改动的已确认实施方案；在产品代码完成原子切换前，不把计划描述成已上线行为。

## 1. Canonical controls

Settings 复用统一组件：

```text
W.Components.selectControl()
switch-control
field-input setting-input
canonical Dialog / Feedback
shared section/grid/row layout
```

不为 qB4/qB5、Desktop/Mobile 或某个 tab 建第二套控件系统。

## 2. 六个 qB Settings surfaces

Canonical surfaces：

```text
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
```

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

## 3. Exact Preference provenance

每个 admitted official stable profile 从 qB upstream getter/setter source 生成 descriptor：

```text
getter/read type/kind/confidence
setter/write type/kind/confidence
getter/setter agreement
writable
enum fallback provenance
```

Setter-only key 不得逃出 `app/preferences` surface。

### 3.1 Locale / language 复盘结论

当前实现仍存在两个独立语言状态：

```text
WeiG weigg-language / W.I18n
        -> weigg:languagechange
        -> QBLocaleBridge
        -> qB preferences.locale

qB Settings locale
        -> SettingsState.draft.locale
        -> setPreferences + verification reread
        -X-> W.I18n active locale
```

因此从 qB Settings 的 `Locale` 选择其他语言并保存后，qB preference 可以写入并回读，但 WeiG 页面不会因此切换语言。这个问题不得通过再增加一层“双向同步”修补。

下一次产品改动必须进行 owner cutover：**`qBittorrent preferences.locale` 成为唯一持久语言 owner**。WeiG 不再保存第二份 `weigg-language`。

目标链路：

```text
qB app/preferences.locale
-> SettingsState authoritative value
-> shared locale adapter
-> W.I18n active locale
-> WeiG UI + About + qB Settings presentation
```

`Advanced -> Locale` 和 `WeiG WebUI -> Interface -> Language` 可以保留两个显示入口，但它们必须绑定**同一个 `draft.locale`、同一组 options、同一个 `QBClient.setPreferences()` 保存流程**。不允许一个写 localStorage、另一个写 qB。

保存 Locale 时：

```text
user changes either Locale control
-> SettingsState.draft.locale
-> SettingsSchema writable provenance
-> QBClient.setPreferences({locale})
-> QBClient.getPreferences() verification reread
-> verified locale becomes W.I18n active locale
-> repaint the existing shared Desktop/Mobile DOM
```

如果 qB write 或 verification 失败，不能先把 WeiG UI 假装切到目标语言。

### 3.2 Locale options 的 source truth

`locale` 仍属于同一个 `W.SettingsSchema` Preference surface，不建立第二套 Settings owner。

语言选项只允许来自 qBittorrent 官方 source facts：

```text
running qB
-> private/views/preferences.html
-> qB WebApplication injects ${LANGUAGE_OPTIONS}
-> exact runtime locale codes + localized language names

Virtual qB / historical release
-> exact release profile webuiLocales
-> source-derived, source-SHA-bound frozen locale facts
```

禁止在 `capabilities.json`、`settings.js`、`W.SettingsSchema` 或 UI 组件里维护手写 qB4/qB5 语言版本表。

当前版本实际支持多少 Locale，两个语言选择入口就显示多少；例如连接 qB 5.2.3 时，两处都使用 5.2.3 的完整 61 项。旧 qB release 仍使用该 exact release 的真实 Locale 集合，不能给旧版本暴露它实际上不支持的值。

### 3.3 WeiG translation coverage 以 qB 5.2.3 为基线

WeiG 自己的可翻译界面覆盖集合使用最新 admitted stable qB 5.2.3 的 WebUI locale superset，共 **61** 个 locale code：

```text
ar, az@latin, be, bg, bs, ca, cs, da, de, el,
en, en_AU, en_GB, eo, es, et, eu, fa, fi, fr,
gl, he, hi_IN, hr, hu, hy, id, is, it, ja,
ka, kk, ko, lt, ltg, lv_LV, mn_MN, ms_MY, nb, ne_NP,
nl, oc, pl, pt_BR, pt_PT, ro, ru, sk, sl, sq,
sr, sr@latin, sv, th, tr, uk, uz@Latn, vi, zh_CN, zh_HK, zh_TW
```

旧 release 的历史代码（例如 `de_DE`、`ja_JP`、旧 `zh` 等）通过 locale identity/alias normalization 映射到同一语言身份；映射依据 locale code / script / region 与冻结 source facts，不写 `if (qB version >= ...)` 分支。

### 3.4 qB 官方翻译与 WeiG 自有翻译边界

不能把“使用 qB 自带语言”理解成 Alternate WebUI 可以自动翻译任意 WeiG 自定义字符串。qB 5.2.3 的 WebApplication 会从内置 `webui_*.qm` 生成 `${LANGUAGE_OPTIONS}`；但启用 Alternate WebUI 后，qB translator 的 WebUI translation path 指向 Alternate WebUI root 下的 `translations/webui_<locale>`。

因此翻译 owner 分两类：

```text
qB-owned labels / phrases
-> 从 qB 5.2.3 官方 webui_*.ts / official WebUI source 生成
-> 不人工编造译文

WeiG-only UI / About / WeiG-specific behavior
-> WeiG 自己的最小 translation namespace
-> 覆盖同一 61-locale superset
```

同一句话只允许一个 owner。能直接对应 qB 官方 WebUI 的文字，不在 WeiG 字典里复制一份人工翻译。

通用 Preference 描述文案在另行处理前保持现有 **`qBittorrent preference.`** 不变。

### 3.5 旧 i18n 层的原子清理计划

当前仓库不是 `private/scripts/i18n/*` 目录，而是 `private/scripts/` 下若干 `i18n*.js` 文件。下一次产品实现必须先做完整 caller audit，然后一次性迁移并删除被替代层，禁止兼容 wrapper 长期双活。

已确认的 cutover 原则：

```text
i18n-interface.js
-> 先把 qb-locale-bridge.js 改为 index.html 显式加载
-> 迁走仍有 caller 的文字
-> 删除旧 InterfaceText owner

i18n-time.js
-> Logs 等实际 caller 迁到 canonical W.I18n
-> 删除旧 RuntimeI18n owner

i18n-transfer.js
-> 若完整 tree audit 仍确认无 caller，直接删除

i18n-alternative-webui.js
-> 若完整 tree audit 确认无 caller，直接删除

i18n.js
-> 保留 W.I18n 作为统一 presentation API，移除独立 weigg-language state 与固定五语言表
-> 不再同时维护 EN/ZH/JA/KO 手写 qB-owned 文案
```

`settings.js` 中当前 `text(en, cn)`、`transfer.js` 中当前 `label(en, cn)` 等动态双语分支也必须在同一次 cutover 中迁走；否则即使静态 DOM 支持 61 种语言，动态生成内容仍会退回英文。

`WeiG WebUI` 自有设置和 `About` 不删除，它们属于 WeiG-owned presentation，并补齐 5.2.3 的 61-locale coverage。

## 4. Editability

Exact stable profile 只有同时满足以下条件才可编辑：

```text
setPreferences action proven
setter exists
write type understood
getter/setter type agrees
descriptor writable == true
```

否则可见但 read-only，或按 capability policy 隐藏。

Boolean/Enum/Input/Structured control 都消费同一事实；`onDraft` 拒绝 non-writable，保存时 `writableDraft()` 再过滤。

## 5. Unknown / future Preferences

未来 stable 新 key 不静默丢失：

```text
exact schema
-> semantic family
-> canonical surface
-> Advanced / Upstream fallback
```

未知 scalar 在没有 exact setter provenance 时只读；未知 array/object 可见但只读，以结构化 JSON 展示。

禁止猜 unit / enum / range / startup default，也禁止 blind write。

## 6. 与 simulator Endpoint/Transport Contract 的边界

```text
W.SettingsSchema + Preference descriptors
-> key/type/getter/setter/editability

simulator Endpoint Contract
-> historical request/response/status/mutation semantics

simulator Transport Contract
-> auth/header/proxy transport semantics
```

这些职责不能合并成第二套 Settings owner。

同时：

```text
CapabilityRegistry 不决定 Preference writable
SettingsSchema 不维护 endpoint historical response policy
QBClient 不维护产品版本策略
simulator router 不重新解释 Settings UI schema
```

## 7. Owner cutover discipline

Settings/Locale owner 被替换时必须 atomic cutover：

```text
new canonical owner + callers + contracts + DESIGN
-> remove superseded owner/helpers/tests
```

禁止新旧 Settings/i18n router/renderer/locale state 长期双活。`DESIGN.md` 只在产品代码真正完成 cutover 的同一提交中更新为 Current Owner；本 docs 方案本身不提前宣称 owner 已经切换。

## 8. 保存流程

普通 qB Preference：

```text
user interaction
-> canonical control
-> SettingsState.draft
-> writableDraft()
-> validateBeforeSave()
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> canonical feedback
```

Locale 在 verification reread 成功后额外驱动同一个 `W.I18n` presentation state；不再触发第二次 qB write。

写成功但 verification read 失败时必须明确显示“已写入但无法确认”，不能伪装完全验证成功。

## 9. Mobile / acceptance

Mobile 使用同一 Settings DOM/state/controls/save flow，不建立第二套语言状态。

Locale cutover contracts 至少覆盖：

```text
qB Locale save -> verified reread -> WeiG UI language changes
WeiG Language and qB Locale share the same draft/value/options
qB 5.2.3 = 61 locale options
all 61 locales have required qB-derived + WeiG/About presentation coverage
historical locale aliases map without qB-version branching
no weigg-language persistent state
no fixed five-language supported list
no duplicate setPreferences after locale save
superseded i18n files/owners are removed, not hidden or wrapped
qBittorrent preference. remains unchanged
Desktop/Mobile consume the same active locale
```

Pages/Chrome 使用 source-derived exact profiles 验证 Settings/Locale presentation；发布前真实 qB 证明仍由 G-FM 提供。
