# 005. 统一交互与设置系统

> 当前 Settings / capability / interaction contract。详细 semantic ownership 以 `DESIGN.md` 为准。

## 1. Canonical controls

Settings 继续复用统一组件：

- `W.Components.selectControl()`；
- `switch-control`；
- `field-input setting-input`；
- `settings-section / settings-grid / setting-row`；
- canonical Dialog / Feedback。

不为 qB4/qB5、Desktop/Mobile 或某个 Settings tab 建第二套控件系统。

## 2. 六个 qB Settings surfaces

Canonical qB surfaces 为：

1. Downloads
2. Connection
3. Speed
4. BitTorrent
5. Web UI
6. Advanced

Preference routing 由 `W.SettingsSchema` 唯一负责：

```text
exact schema -> semantic family -> Advanced / Upstream
```

Speed 独占 global/alternate rate limit、scheduler 与 rate-limit behavior；Advanced 不重复这些 key。

## 3. Exact stable Preference provenance

每个官方 stable release 从 qB upstream `AppController::preferencesAction()` 与 `setPreferencesAction()` 生成 descriptor。Descriptor 分开记录：

- getter 是否存在；
- read type / getter kind / confidence；
- setter 是否存在；
- write type / setter kind / confidence；
- getter/setter agreement；
- writable；
- enum upstream fallback token（仅作为 fallback provenance，不冒充 startup default）。

Setter-only key 不得逃出 `app/preferences` surface。

## 4. Editability contract

对 exact stable profile，一个 Preference 只有同时满足以下条件才可编辑：

- upstream setter 存在；
- write type 已解析；
- getter/setter 类型不冲突；
- descriptor `writable === true`。

否则保持可见但 read-only。

所有控件种类必须消费同一事实：

- Boolean switch：disabled；
- Enum canonical Select：disabled；
- Number/Text/Path input：readonly；
- Structured Array/Object：readonly JSON textarea。

`settings.js` 的 `onDraft` 入口拒绝 non-writable key；保存时 `SettingsSchema.writableDraft()` 再过滤一次。UI 状态不能成为唯一安全边界。

## 5. Unknown / future Preferences

未来 stable 新增 key 不允许静默丢失：

- 能通过 family rule 分类的进入对应 surface/section；
- 其余进入 Advanced / Upstream；
- scalar 可以按实际/read type 正确展示，但没有 exact setter provenance 时只读；
- array/object 始终先只读，直到建立专用 structured editor contract；
- 不猜 unit / enum / range / default。

## 6. Capability 与 Settings 的关系

`W.ReleaseProfile` 提供 exact stable source facts；`W.CapabilityRegistry` 负责 user-visible feature availability；`W.SettingsSchema` 独立负责 Preference semantics。

这三者不可互相复制：

- CapabilityRegistry 不决定 Preference writable；
- SettingsSchema 不维护 Torrent feature availability；
- QBClient 不维护产品版本策略。

## 7. 保存流程

```text
user interaction
 -> canonical control
 -> SettingsState.draft
 -> writableDraft()
 -> validateBeforeSave()
 -> QBClient.setPreferences()
 -> QBClient.getPreferences() verification read
 -> canonical feedback
```

Alternative WebUI disable/path 等高风险现有确认逻辑保留。写成功但 verification read 失败时必须显示“已写入但无法确认”，不能伪装成完全验证成功。

## 8. Mobile

Mobile 使用同一 Settings DOM/state/controls。短描述保持左右布局；长描述可让同一 control 自适应到下一行。不得创建 Mobile-only draft/store、第二套 Select 或第二套 save flow。

## 9. Acceptance

Contracts 必须覆盖：

- exact route ownership；
- future family routing；
- missing descriptor fail closed；
- getter-only read-only；
- type mismatch read-only；
- source-proven future scalar writable；
- structured read-only；
- `writableDraft()` defense-in-depth；
- canonical control reuse。

Pages Real Chrome 还会在 qB 4.1.0 floor session 中逐个进入六个 qB Settings surfaces，验证 deployed runtime 使用 canonical renderer。
