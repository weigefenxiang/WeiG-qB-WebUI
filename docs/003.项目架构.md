# 003. 项目架构

> 当前架构说明。`DESIGN.md` 是 semantic ownership 的最高当前文档；本文件描述模块边界与数据流。

## 1. 总体边界

WeiG qB WebUI 仍是 qBittorrent Alternative WebUI。产品运行时通过 canonical `W.QBClient` 调用 qB WebAPI；Virtual qB Lab 只在产品 client 后方模拟 qB WebAPI，不替换产品业务模块。

正式支持 qBittorrent **4.1.0 → 最新官方 stable**。支持矩阵不是手写 patch 表，而是从上游 stable tag/source 自动生成。

## 2. 上游事实层

### Build-time owners

- `tools/qb-source-parsers.mjs`：`app/preferences` getter/setter 与类型 provenance；
- `tools/qb-torrent-surface-parsers.mjs`：Torrent filter 与 `torrents/info` 参数 surface；
- `tools/qb-release-catalog.mjs`：将每个 official stable 组装为 exact release profile；
- `tools/qb-catalog-quality.mjs` / evolution contracts：校验 catalog 完整性和演化质量。

### Runtime owner

`W.ReleaseProfile / scripts/release-profile.js` 根据已检测到的 qB exact version 选择对应 profile，并提供：

- Preference descriptor；
- API action presence；
- Torrent filter surface；
- `torrents/info` parameter presence；
- start/resume、stop/pause exact action resolution；
- qB4 paused/resumed ↔ canonical stopped/running boundary mapping。

Catalog 缺失或 exact version 不在 catalog 时只能 conservative fallback；不得伪造 setter/source provenance，也不得把未知 release 标为 certified。

## 3. 产品运行时 owner map

```text
Exact stable source facts              W.ReleaseProfile
HTTP transport / endpoint invocation   W.QBClient
User-visible capability policy         W.CapabilityRegistry
Settings semantics                     W.SettingsSchema
Settings presentation/write workflow   W.SettingsRenderer / settings.js
Torrent status/filter semantics        W.TorrentSemantics
Torrent filter DOM                     W.TorrentFilterView
Torrent query/page/sort state           W.LibraryController / W.AppState
Selection/actions                      W.Selection / ActionRegistry
Torrent row/card DOM                   W.Components
Torrent field registry                 W.TorrentFieldRegistry
Transfer runtime/history               W.TransferRuntime
Theme                                  W.Theme
Feedback                               W.Feedback
Responsive placement                   W.MobileAdaptive
```

一个 semantic purpose 只能有一个 Current Owner。Presentation caller 不得重新建立版本表、状态 regex、轮询器或业务 state。

## 4. Torrent 查询链

```text
ReleaseProfile.torrentFilters()
  -> TorrentSemantics.statusFilters()
  -> TorrentFilterView render
  -> LibraryController.setFilter()
  -> QBClient.getTorrents()
  -> ReleaseProfile.upstreamTorrentFilter()
  -> api/v2/torrents/info
```

`app.js` 与 `selection.js` 都使用 `W.TorrentSemantics.matchesStatus()`；全选匹配与页面筛选因此共享同一语义。完成度 100% 不自动等于做种。

## 5. Capability 链

`W.CapabilityRegistry + data/capabilities.json` 负责展示策略，`W.ReleaseProfile` 提供 source truth。

对配置了 `upstream.action / torrentFilter / torrentInfoParameter` 的 feature，exact source truth 优先；没有该 upstream surface 时普通 UI **隐藏**。Unknown capability id fail closed。

Version range 仍可用于没有 exact source predicate 的能力和 requirement 文案，但 caller 不得自行 hard-code patch 分支。

## 6. Settings 链

```text
app/preferences JSON
  + ReleaseProfile.preferenceDescriptors
  -> SettingsSchema route/type/editability
  -> SettingsRenderer canonical controls
  -> writableDraft()
  -> QBClient.setPreferences()
  -> getPreferences() verification read
```

对于 exact stable profile，setter provenance 决定可写性。Getter-only、setter unresolved、type mismatch、missing descriptor 均 read-only；arrays/objects 仍 read-only。所有 Select/Switch/Input 使用同一 `editable` 事实，保存前再次过滤。

## 7. Desktop / Mobile

Desktop 与 Mobile 只改变 placement/geometry，不改变 semantic owners。Sidebar/Drawer 使用同一 filter/facet state；Selection toolbar、Transfer history、Settings state、Header Search 都是同一实例/状态链，禁止镜像 store。

## 8. Virtual qB Lab

Virtual Lab 的职责是提供 deterministic qB WebAPI backend：

```text
product W.QBClient
  -> Service Worker protocol adapter
  -> QBProtocolRouter
  -> QBSimulatorEngine / Scheduler / Policy
  -> IndexedDB world
```

Pages build 将同一 generated release catalog 同时发布到 metadata 与 `__source/private/data/qb-releases.json`。Lab 不修改 formal `webui/**` 的业务 API 形状。

## 9. Artifact / evidence

Release candidate 的 full upstream audit 生成 exact `qb-releases.json` artifact，release packaging 下载该 artifact 并放入 `private/data/qb-releases.json`。Pages build 也注入相同 catalog shape。

CI、Pages LIVE、候选包与 Release 全部绑定 exact Git SHA。VERSION 是产品版本，不替代 SHA evidence identity。
