# 003. 项目架构

Status: **current architecture / Current Owner boundaries**

`webui/**` 是唯一正式产品。浏览器 runtime 的 release-profile layer 已退休；source catalog 是离线 source truth / admission / validation input，不是 runtime owner。

## 1. 总体分层

```text
qB WebAPI
-> W.QBClient                    # transport + detected qB/WebAPI identity
-> W.CapabilityRegistry          # runtime release resolution + lazy domain loader
   <- capabilities.json          # control plane only
   <- torrent-compat.json
   <- detail-compat.json
   <- settings-compat.json
   <- rss-compat.json
   <- source-actions.json
-> canonical semantic owners
-> UI / presentation

current qB-owned copy runtime
   qb-settings-native.txt + minimal official QM
   -> W.I18n

qB official source / Frozen admitted release catalog
-> source extractors / independent inventories / CI
-> compact domain compilers
-> exact-release compact contracts + qB-owned copy evidence
-> formal browser consumes only bounded/lazy runtime artifacts
```

`capabilities.json` 只负责 release identity、high-level gates 与 `compatFiles` index，不承载所有 UI/version history。领域事实各自归对应 compact contract；full 65-release catalog 只存在于 tools/CI/simulator/admission 层。

## 2. Current Owner map

```text
HTTP transport / detected identity         W.QBClient
Runtime release/capability/source facts    W.CapabilityRegistry
Settings current runtime semantics         W.SettingsSchema + settings-compat.json
Settings presentation/layout               W.SettingsRenderer + canonical SettingsGrid
Preferences native-source admission        tools/qb-preferences-* (evidence today; target of A cutover)
RSS Downloader native surface              rss-compat.json -> RSSRules generic manifest consumer
Persisted language truth                   qB app/preferences.locale
qB-owned/WeiG copy                         W.I18n
Torrent status/filter semantics            W.TorrentSemantics
Torrent field/column provenance            W.TorrentFieldRegistry
Selection/torrent actions                  W.Selection / ActionRegistry
Main/detail virtual projection             W.VirtualList
Detail source schema/descriptors           W.CapabilityRegistry
Detail source projection                   W.QbUiEvidence
Detail generic dispatch                    app.js descriptor consumer
Detail user columns                        W.SharedColumns
Detail resize/reorder lifecycle            W.ColumnInteraction
Transfer runtime/history                   W.TransferRuntime
Responsive placement                       W.MobileAdaptive / W.SpatialRuntime
```

一个 semantic purpose只能有一个 Current Owner。A 阶段的 new Preferences compact IR 当前仍是 source/admission evidence，不得因为“已经生成”就被视为第二 active Settings owner。正式 cutover必须 new owner proven + callers switched + contracts/tests/docs更新 + superseded runtime truth删除，同一 coherent change完成；禁止 runtime alias、repair layer、第二 polling/state/scroll/layout/language owner。

## 3. Compact domain contract

正式 runtime domain 当前包括：

```text
capabilities.json
  releases / WebAPI milestones / high-level features / compatFiles

torrent-compat.json
  Torrent filters/states/fields/columns
  B target: native sidebar facet inventory/order/semantics

detail-compat.json
  Torrent Detail tabs/layout/tables/menus/control facts

settings-compat.json
  current Preference getter/setter/type + native tab facts
  A target: exact native sections/order/control/options/unit/dependencies/source refs

rss-compat.json
  exact RSS Downloader native-surface fields/copy/path/control semantics

source-actions.json
  exact action existence + required/optional parameter provenance

qB-owned copy artifact
  exact {source, context} -> official locale route
```

所有 domain 最终必须从同一 Frozen admitted catalog 编译，并携带可比较的 catalog/release-set identity，例如 support floor、latest admitted stable、release count、release-set hash/source-catalog hash。若任一 domain 停在不同 release set，CI/runtime contract必须 fail closed，不能混合“capabilities 已 5.2.x、settings 还在旧 catalog”的 bytes。

## 4. Compatibility / writes

`W.CapabilityRegistry` 从 compact source facts解析 Torrent filters/info fields/table columns/Detail UI/RSS UI/source actions。UI key不是 API proof；unknown upstream shape fail closed。Dangerous write必须具备 certified identity + exact action/parameter provenance，并由 `W.QBClient` transport；不能用 patch/major version猜 endpoint。

Settings write additionally要求 exact Preference setter/type agreement并在 POST 后 reread verification。A cutover后，native control semantics也必须来自 source-derived manifest；未知 enum/unit/dependency 不能由前端猜。

## 5. Settings source-to-runtime boundary

当前 source/admission 链已经存在：

```text
exact qB Preferences source + preferenceDescriptors
-> tools/qb-preferences-surface-source.mjs
-> source-native manifest
-> tools/qb-preferences-compact.mjs
-> keyed compact Preferences IR
```

当前正式 Settings runtime仍是：

```text
settings-compat.json
-> W.SettingsSchema
-> W.SettingsRenderer
```

A 的工作不是长期并行两套 schema，而是把 source-native IR 的已证明 facts原子接入 canonical Settings compact contract/runtime，然后删除被替代的手工 qB-owned `SURFACES/SECTION_ORDER/SECTION_TITLES/META/FAMILY_RULES/add()` truth。WeiG-owned layout/presentation token可以继续存在，但不能重新定义 qB native semantics。

## 6. Torrent Sidebar / Detail / VirtualList

B 的目标链：

```text
exact upstream native status/filter/facet inventory
-> torrent compact contract
-> W.CapabilityRegistry / W.TorrentSemantics
-> generic facet state + generic projection
-> append WeiG Path extension last
```

当前 `spatial.js` 固定 category/tag/tracker/savePath 是未完成状态，不是长期架构。未来 qB 增加同类 native facet时，应由 source admission进入 manifest；UI不能再加第 N 个 hard-coded button/branch。

E/Detail 继续固定为：

```text
W.CapabilityRegistry.torrentDetailUi()
-> W.QbUiEvidence
-> generic app Detail runtime
-> W.SharedColumns / W.ColumnInteraction / existing W.VirtualList
-> W.QBClient
```

General只消费 source-generated layout；Files/Trackers/Peers/Web Seeds共用 generic renderer/action chain；禁止 per-surface第二 schema、第二 scroll owner或 endpoint-name业务分支。

`W.VirtualList` 是 Torrent 主列表和需要虚拟投影的 Detail surface 的 canonical virtual/scroll owner。原生横/纵向滚动或 scrollbar drag 期间，网络 polling 可以继续，但新 snapshot 不得替换正在交互的 DOM；只保留 latest pending snapshot，bounded idle 后一次提交。禁止第二轮 polling、scroll repair 或 MutationObserver 同步。

## 7. Completeness / anti-omission architecture

仅有 semantic extractor不足以证明“没有漏”。每个准备声明阶段完成的 source-driven domain必须有独立 inventory/census 路径：

```text
raw exact upstream source
  ├─ semantic extractor -> compact product facts
  └─ independent inventory/census -> upstream exposed inventory

inventory = mapped + explicit reviewed exclusions
unaccounted = 0
duplicate = 0
```

inventory pass应尽量避免复用 semantic extractor 的同一 parser assumption。若 upstream 改成未知语法，正确结果是 admission fail/PENDING_REVIEW，而不是 extractor返回少几个元素后仍然绿色。

## 8. Build/runtime boundary

65 stable source catalog、full translation recovery、upstream source parser属于 tools/CI/simulator。raw `webui/` 只携带浏览器真正消费的 compact contracts/copy/QM，因此可直接作为 Alternative WebUI root。Historical `main=0.3.71` simulator preview 可在 `branch==='main'` 的 simulator-only build 路径临时物化旧 profile runtime；不得回流到 dev formal product。

历史上用于 connector 传输的 `.weigg-bootstrap/**` 和一次性 `dev-bootstrap-*.yml` 不属于任何正式 architecture owner；它们必须在最终产品 tree 中消失，不能被后续 AI 当成 runtime/build subsystem继续维护。

## 9. Validation

Source audit、phase-end 65-release offline/Virtual matrix、browser/Pages、real-qB、Candidate/Release 是不同 evidence 层。阶段内部只跑 focused/change-point；一个阶段完整收口后最多一次该领域的 65-release offline/Virtual full matrix。最终 real-qB heavy matrix只属于全部 A–F 完成、final dev exact SHA冻结后的 release-grade gate。

`SKIPPED != PASS`；exact-SHA evidence不可跨提交偷用。Workflow 内部 source-contract PASS不能替代该产品 checkpoint 的 applicable UI/browser 与 exact-SHA Pages materialization/build/deploy/live evidence。
