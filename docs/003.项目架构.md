# 003. WeiG qB WebUI 项目架构

Status: **Architecture authority for v0.2.2+**  
Repository: `weigefenxiang/WeiG-qB-WebUI`

> 本文负责“代码放在哪里、谁依赖谁、每一层允许做什么”。视觉规则看根目录 `DESIGN.md`；产品/兼容硬规则看 `001.项目总方案.md`；当前兼容状态看 `002.兼容与实现状态.md`。

## 1. 架构目标

项目坚持：

```text
qB API 差异留在 Client/Capability
业务状态留在 Controller/State
DOM Primitive 留在 Components
布局/视觉留在 CSS + Spatial Composition
翻译留在 i18n/Settings translation
大列表统一 VirtualList/DataGrid
安装器与运行时分离
```

核心约束：

```text
UI/Spatial/Component
        × 不直接 fetch /api/v2/*
        × 不直接写 qB 版本特例
        × 不自己发明翻译分支
```

## 3. Runtime 启动链

qBittorrent Alternate WebUI 运行链：

```text
qBittorrent HTTP server
↓
public/login.html          未认证入口
↓ authentication
private/index.html         已认证 App Shell
↓
i18n.js
↓
core.js
↓
settings-schema.js
settings-translations.js
↓
qb-client.js
↓
components.js
↓
app.js
↓
ux-v021.js                过渡 i18n/导航桥
↓
spatial-v022.js           Spatial composition
```

`components.js` 负责加载带 `?v=0.2.2` 的 `v022.css` 与 `spatial-v022.js`，使 4.1.9 稳定入口不需要因每个视觉迭代反复重写，同时让新 Spatial 资源带版本 cache bust。

## 4. Layer 0 — qB Static Entry

### `webui/public/login.html`

职责：

- qB 未登录页面；
- POST `api/v2/auth/login`；
- 浏览器语言检测；
- Login UI；
- 不加载 authenticated App 业务。

禁止：

- Torrent 业务；
- Settings；
- 大型依赖；
- 跨站 CDN。

### `webui/private/index.html`

职责：

- App Shell；
- semantic DOM anchors / IDs；
- Topbar / Sidebar / Workspace / Status Dock / Dialog shell；
- script bootstrap 顺序。

禁止：

- 直接实现 API 业务；
- 大量页面级 inline logic；
- 版本特例。

## 5. Layer 1 — Core

### `core.js`

职责：

```text
Config
Router / Navigation helpers
formatters
Tracker normalization
VirtualList
DataGrid
shared utility
```

核心权威：

- `normalizeTracker()`：Tracker 隐私脱敏；
- `VirtualList`：大列表 DOM 窗口化；
- `DataGrid`：列 schema/width/order/persistence；
- global UI config：fontSize / density / pageSize / PT rules。

禁止：

- 页面 DOM composition；
- 直接 qB Feature UI；
- locale-specific UI branch。

## 6. Layer 2 — Internationalization

### `i18n.js`

职责：

- English canonical dictionary；
- Locale overlay；
- `navigator.languages` 自动解析；
- 手动 language setting；
- English fallback；
- `data-i18n*` 应用。

正式维护语言：

```text
en       English / canonical
zh-CN    简体中文 / maintained translation
```

其他 overlay 可以保留，但缺失 key 必须 English fallback。

### `settings-translations.js`

职责：

- qB Preference label/description 翻译；
- English canonical → zh-CN；
- qB 官方术语优先。

禁止：

- API 调用；
- 业务条件；
- 控件创建。

## 7. Layer 3 — Settings Metadata

### `settings-schema.js`

输入：qB Preference key/type。

输出 metadata：

```text
canonical English title
description
kind
known / fallback
search metadata
```

职责：把 `/app/preferences` 从 raw JSON key/value 变成产品可理解的设置模型。

未知新 key：humanized English fallback，不能让 Settings 崩溃。

## 8. Layer 4 — qB Compatibility Client

### `qb-client.js`

这是 **唯一允许直接访问 qB `/api/v2/*` 的业务层**。

职责：

```text
request/auth behavior
app/version
app/webapiVersion
Capability Profile
4.x / 5.x endpoint bridge
Torrent API
Transfer API
Preferences
RSS
Search
Logs
Tracker/Peer/File actions
```

关键兼容：

```text
4.x resume/pause ↔ 5.x start/stop
4.x paused       ↔ 5.x stopped
```

规则：

- Feature 不关心 endpoint 名称差异；
- UI 只查询 `client.capabilities.*`；
- 已知 404/405 差异可在这里 fallback；
- 版本字符串采用分段比较，不使用 `parseFloat`。

## 9. Layer 5 — Canonical Components

### `components.js`

职责：

```text
Torrent Row
Mobile Torrent Card
Status Pill
Progress
KV field
Section Heading
Preference Field / Setting Card
```

Setting Card 只表达 canonical DOM 结构，不拥有 Settings 数据源。

v0.2.2 中同时作为 Spatial 资源 bootstrap：

```text
css/v022.css?v=0.2.2
scripts/spatial-v022.js?v=0.2.2
```

禁止：

- 直接 API；
- qB version switch；
- Feature-local style constants。

## 10. Layer 6 — Application Controller

### `app.js`

当前职责：

```text
application state
Torrent page/filter state
catalog
selection
polling
route handling
Torrent actions
Detail tabs
Settings render/save
Search/RSS/Logs orchestration
```

数据流：

```text
QBClient
↓
app state
↓
Components / VirtualList / DataGrid
```

### 当前架构债务

`app.js` 目前仍是较大的 Controller 文件。**禁止继续无边界膨胀。**

后续拆分方向：

```text
features/torrents.js
features/detail.js
features/settings.js
features/search.js
features/rss.js
features/logs.js
state/app-state.js
polling/refresh-engine.js
```

拆分时必须保持 QBClient / Component / Spatial 边界，不允许把 API 差异搬到 Feature。

## 11. Layer 7 — Transitional UX Bridge

### `ux-v021.js`

性质：**过渡层，不是长期业务层。**

当前职责：

- 将旧 `app.js` 的部分中文动态文案映射到 canonical i18n；
- Topbar/Mobile route sync；
- contextual search bridge；
- Settings language card；
- capability entry visibility。

规则：

- 不新增 qB API；
- 不新增新的长期业务状态；
- 新功能优先进入 canonical Feature / i18n 模块；
- 随着 `app.js` 动态文案全部迁移到 semantic i18n key，逐步删除此 bridge。

## 12. Layer 8 — Spatial Composition

### `spatial-v022.js`

职责：**重排表现，不拥有业务 state。**

当前实现：

```text
Tracker / SavePath / Category / Tags
    从 Sidebar DOM anchor
    → Filter Shelf Floating Popover

Connection metadata
    从 Sidebar
    → Status Dock Popover

Settings cards
    → visual polish hooks/tooltips
```

重要：移动原 DOM 节点而不是复制业务数据，因此 app.js 现有事件、ID、filter state 继续是 canonical source。

禁止：

- 自己调用 qB API；
- 自己维护第二份 tracker/category state；
- 重复实现 filter logic。

## 13. CSS 架构

### `app.css`

基础权威：

```text
Design tokens
Typography
Base theme
Core layout
DataGrid
VirtualList
Mobile card
Primitive base styles
```

### `v021.css`

v0.2.1 导航/i18n/Settings 基线覆盖。

性质：兼容层；后续稳定后应逐步吸收到 canonical CSS，而不是无限增加版本层。

### `v022.css`

v0.2.2 Spatial 权威：

```text
six-level surfaces
Topbar chrome
Search/Input interaction depth
Desktop no-scroll state Sidebar
Filter Shelf / Facet Popover
Connection Dock Popover
Stats material
Settings Title→Description→Control
2-column Settings
Light spatial equivalents
Mobile spatial behavior
```

### CSS 演进规则

`v021.css` / `v022.css` 是迭代期间的显式迁移层。稳定到 1.0 前必须计划一次 CSS consolidation：将仍有效规则合并回 token/base/component 文件，删除过时覆盖，避免形成 `v023/v024/v025` 无限链。

## 14. Data / DOM Boundary

Torrent 页：

```text
qB limit/offset
↓
page models / catalog models
↓
VirtualList
↓
viewport + overscan DOM
```

硬规则：

```text
Data count != DOM count
```

同一原则适用于 Files / Peers / Trackers / Logs / Search Results。

## 15. Tracker Data Boundary

Raw value：仅 API 操作内部必要时使用。

UI/filter value：

```text
raw announce
↓ normalizeTracker()
remove query / fragment secrets
↓
safe display/filter key
```

Spatial Filter Shelf 只消费 safe/canonical nav state，不重新读取 raw credential。

## 16. Settings Data Boundary

```text
QBClient.getPreferences()
↓ raw qB object
SettingsSchema.describe(key)
↓ metadata
SettingsTranslations / I18n
↓ localized metadata
Components.preferenceField()
↓ canonical Setting Card
app prefsDraft
↓
QBClient.setPreferences()
```

Spatial CSS 只改变卡片排列，不改变 key/value semantics。

## 17. Navigation Boundary

```text
Router / app route state
↓
Topbar + Mobile Bottom Nav
↓
Workspace Feature
```

Torrent Sidebar/Filter Shelf 只改变 Torrent dataset filter，不改变应用 Route。

Back：

```text
Internal route history
→ browser history
→ home fallback
```

## 18. Installer Architecture

### `install.sh`

职责：

- Linux/qB config detection；
- Docker container list；
- `/config` bind mount mapping；
- explicit `--container` / `--config-root`；
- backup；
- deploy；
- verification；
- optional configuration；
- rollback。

多实例禁止自动选第一个。

### `install.ps1`

Windows 对等职责。

Installer 不属于 WebUI runtime，不得把宿主机探测逻辑带入浏览器代码。

## 19. Test Architecture

### `tests/smoke.mjs`

静态守门：

```text
required files
canonical IDs
English canonical markup
page sizes
compatibility tokens
i18n/schema/translations
VirtualList/DataGrid
Spatial CSS/controller
no external runtime assets
installer safety
```

GitHub CI 还负责 JS/Shell/PowerShell syntax。

Static PASS 不能代替 Lab A / Lab B 实机回归。

## 20. 依赖方向

允许：

```text
Spatial → DOM anchors / Components presentation
App → QBClient / Core / Components
Components → Core / SettingsSchema / i18n
SettingsSchema → metadata only
QBClient → HTTP
```

禁止：

```text
QBClient → UI
Core → Feature UI
Component → fetch API
Spatial → QBClient
Translation → API
Installer → browser runtime
```

## 21. 新功能放置决策

新增功能前按顺序判断：

```text
API 差异？          → qb-client.js
通用模型/算法？     → core.js
qB Preference 描述？→ settings-schema / settings-translations
可复用 UI？         → components.js + canonical CSS
业务流程？          → Feature Controller（当前 app.js，后续拆分）
纯布局重排？        → Spatial Composition
翻译？              → i18n / settings-translations
部署？              → installers
```

## 22. Reuse Gate

新增 helper/component/style 前必须搜索已有能力：

```text
Reuse
↓
Extend
↓
New
```

尤其禁止第二套：

```text
Button
Tooltip
Dialog
Switch
DataGrid
VirtualList
Router
Tracker normalizer
Capability detector
Settings field
```

## 23. 架构演进优先级

在不影响 4.1.9 稳定性的前提下：

1. 将 `app.js` 逐步拆为 Feature modules；
2. 将旧中文动态文案全部迁入 canonical i18n，最终删除 `ux-v021.js` bridge；
3. v0.x 视觉稳定后合并 `v021.css` / `v022.css` 到 canonical token/component CSS；
4. 保持 Spatial 层只做 composition，不复制业务 state；
5. 每次拆分同时跑 Lab A 4.1.9.1 与 Lab B 5.2.0 回归。

## 24. 架构一句话

> **QBClient 隔离 qB 版本差异，Core 提供通用能力，App/Feature 管业务状态，Components 管可复用 DOM，i18n 管 English→中文，Spatial 只做高级布局重排，VirtualList 控 DOM，Installer 与浏览器 Runtime 完全分离。**
