# 003. WeiG qB WebUI 项目架构

Status: **v0.3.7 architecture authority / Responsive UI System 3.3**  
Target revision: **Clean Settings + Verified Session 3.4**  
Repository: `weigefenxiang/WeiG-qB-WebUI`

> 本文定义运行时层次、模块边界与 ownership。视觉/交互规则以根目录 `DESIGN.md` 为最高 authority；产品总方案见 `001.项目总方案.md`；兼容与测试见 `002` / `006`。

## 1. 总体数据流

```text
qB WebAPI
  ↓
QBClient + capability normalization
  ↓
Application / Session state
  ↓
PreferenceSchema / semantic registries
  ↓
Canonical component factories
  ↓
Canonical layout owners
  ↓
Responsive presentation
```

核心边界：presentation 只决定如何显示，不复制后端业务。**Data count != DOM count**。

## 2. Design authority

项目 UI 设计文档遵循 `VoltAgent/awesome-design-md` 的结构方法：

```text
Visual Theme & Atmosphere
Color Palette & Roles
Typography Rules

```

所有页面先扩展根 `DESIGN.md` 已定义的 token / primitive / owner；不允许 feature 自己建立第二套视觉系统。

## 3. Business / Presentation 分层

```text
QBClient
  ✓ endpoint / HTTP contract
  ✓ qB 4.x / 5.x compatibility
  ✓ logout endpoint / protected session probe
  × no layout

Application state
  ✓ torrents / prefs / drafts / polling
  ✓ qB preference save semantics
  × no CSS geometry

PreferenceSchema
  ✓ label / description / type / unit / enum / capability
  ✓ explicit span / layout semantics
  × no DOM mutation

ControlRegistry
  ✓ semantic control choice
  × no qB save business

SettingsRenderer
  ✓ source-generated SettingsSection/Grid/Row/Fact DOM
  × no observer repair

SessionController
  ✓ logout state machine
  × no button geometry

SessionGate
  ✓ private-shell re-entry / BFCache protection
  × no qB preference business
```

## 4. ASSET-NAMING-001 — 稳定语义文件名

运行时第一方文件按职责命名，不按引入它的版本命名。

Canonical target：

```text
webui/private/css/
  app.css
  ui.css
  layout.css
  settings.css
  brand.css
  logs.css

webui/private/scripts/
  core.js
  components.js
  i18n.js
  ui.js
  layout.js
  settings.js
  brand.js
  header.js
  session.js
  logs.js
  app.js
  bootstrap.js
```

原则：

```text
版本变化 != 新文件 owner
缓存变化 != 新文件名
Git 历史 = 旧实现档案
当前运行目录 = 只保留当前 canonical 实现
```

禁止最终 runtime 中存在：

```text
*-vNNN.css
*-vNNN.js
vNNN.css
vNNN.js
旧名字 alias / shim / import-only wrapper
old + new 同时加载
```

`settings-brand-v037.css/js` 不直接改名成永久 `settings-brand.css/js`，因为其混合职责本身需要拆除：

```text
Settings CSS/DOM          -> settings.css / settings.js
Brand presentation/motion -> brand.css / brand.js
Header utilities          -> header.js + shared ui.css
Session/logout            -> session.js
shared UI primitives      -> ui.css / ui.js
responsive shell          -> layout.css / layout.js
```

已有 `app.css / app.js / core.js / components.js / i18n.js` 这类稳定语义名继续保留并按实际 owner 收敛。

Cache identity：

```text
stable semantic path + exact Git SHA
```

`VERSION` 只描述产品版本；tag/Release 描述分发；Git SHA 描述 exact code/cache identity。

## 5. Settings architecture 3.4 — Clean Cut

Canonical pipeline：

```text
qB preference / WeiG preference
        ↓
PreferenceSchema
        ↓
ControlRegistry
        ↓
SettingsRenderer
        ↓
SettingRow
├─ SettingCopy
└─ SettingControlSlot
        ↓
SettingsGrid
        ↓
SettingsSectionPanel
        ↓
SettingsViewportLayout
```

### 5.1 Source renderer is final renderer

3.4 不再把 legacy Settings DOM 当作可长期兼容输入。源 renderer 必须一次生成正确最终结构：

```text
SettingsSectionPanel
├─ SectionHeader
└─ SettingsGrid
   ├─ SettingRow
   ├─ SettingRow
   └─ ...
```

Target row：

```text
SettingRow
├─ SettingCopy
│  ├─ SettingTitleLine
│  └─ Description
└─ SettingControlSlot
```

迁移完成后 Settings 范围内删除，而不是继续兼容：

```text
.settings-control
.settings-row--canonical
.setting-row-grid
.settings-section--rows
.settings-grid-canonical
SETTINGS-FORM-RAIL-*
```

### 5.2 Settings legacy bridge removal

以下当前/历史机制不得成为 3.4 最终架构：

```text
patchFactories()
normalizeSettings()
normalizeSection()
consolidateWeiGGrid()
Settings MutationObserver 搬行
语言卡片 MutationObserver 注入
时区卡片 MutationObserver 注入
依赖 CSS load order 让新规则压旧规则
Settings setTimeout repair
版本化 loader 为了把新 Settings 层叠到旧 Settings 上
```

迁移完成后对应代码应删除；不留“备用兼容路径”。

### 5.3 API compatibility remains

UI clean cut ≠ 删除 qB 兼容：

```text
qB 4.1.9.1 / WebAPI 2.2.1
...
qB current 5.x
```

继续由 `QBClient` capability normalization 保持。

## 6. Settings geometry ownership

Wide desktop：

```text
SettingsGrid = repeat(2,minmax(0,1fr))
```

Narrow/mobile：

```text
SettingsGrid = minmax(0,1fr)
```

每个 ordinary SettingRow：

```text
SettingRow
  grid-template-columns: minmax(0,1fr) auto

SettingCopy
  width: 100%
  justify-self: start
  text-align: left

SettingControlSlot
  justify-self: end
```

SectionHeader 和 SettingCopy 使用同一个 section inset。控件使用同一个右 inset。

### 6.1 禁止水平居中

普通 Settings 文字禁止：

```text
text-align:center
justify-self:center
justify-content:center 作为横向布局
固定宽居中 FormRail
```

`align-items:center` 只能用于纵向对齐控件/row，不得改变文字左轴。

### 6.2 Span

```text
default span = 1
```

`span=full` 仅用于 multiline/composite/list/table/large editor，由 schema 明确声明。禁止 key-name heuristic。

最后一个奇数 ordinary row 留在左 cell。


### 9.1 HeaderUtilityAction

## 10. Verified Session architecture

```text
HeaderUtilityAction(Logout)
        ↓
SessionController.logout()
        ↓
QBClient.logout()
        ↓
POST auth/logout
        ↓
QBClient.probeSession()
        ↓
verified invalid ?
```

### 10.1 QBClient

Canonical methods：

```text
logout()
probeSession()
```

调用方不应散落 `request('auth/logout', ...)` 字符串。

### 10.2 SessionController

状态：

```text
idle
→ logging-out
→ verifying
→ logged-out | auth-bypass | failed
```

`auth/logout` HTTP success 不是最终 success。只有 protected probe 证明 session 不可用，才进入 `logged-out`。

### 10.3 Logout commit

verified invalid 后：

```text
stop polling
prevent new authenticated jobs
clear volatile torrents / prefs / private view state
set sessionStorage logout guard
lock private shell
location.replace(public root)
```

Theme / Language / Timezone 等 display preference 可保留。

## 11. SessionGate / Back / BFCache

浏览器历史不是认证边界，但不能展示陈旧 private snapshot。

```text
private page pageshow
  ├─ event.persisted == true
  └─ logout guard exists
        ↓
SessionGate locks shell
        ↓
reload / server probe
```

登录成功必须 clear logout guard。

## 12. Authentication bypass semantics

qB 4.1.9.1 与当前 qB 都会在以下情况自动创建 session：

```text
localhost client + local auth disabled
或
client IP 命中 auth subnet whitelist
```

因此：

```text
POST logout success
protected probe still 200
→ SessionController state = auth-bypass
→ 不允许显示“已登出”
→ UI 解释当前 qB Web UI 策略会自动重新认证该客户端
```

只有修改 qB server auth policy 才能实现 durable logout。

## 16. Runtime lineage / zombie-code policy

历史实现只由 Git history 和 docs 描述，不再通过版本号文件长期留在 runtime tree。

当前已确认的版本化 runtime 文件全部进入 inventory：

```text
brand-v031.css
logs-v032.css / logs-v032.js
mobile-v036.css
ui-system-v037.css / ui-polish-v037.css
settings-brand-v037.css / settings-brand-v037.js
v021.css / v022.css / v030.css / v036.css / v037.css
以及 scripts 下所有第一方 *-vNNN.js / vNNN.js
```

处理方式不是“统一改名后全部保留”，而是：

```text
读取旧文件唯一职责
→ 把仍有效能力迁到 stable semantic owner
→ 去重重复实现
→ 更新 loader/reference
→ 删除旧版本文件
```

明确 zombie-code 候选：

```text
SETTINGS-FORM-RAIL-* CSS
legacy settings-row--canonical/settings-control geometry
Settings normalization observer/adapter code
Language Settings injector
Timezone Settings injector
Settings-specific CSS-order compatibility logic
纯版本叠层 loader/order 逻辑
已被 semantic owner 覆盖的旧 CSS/JS
```

## 17. Systemic failure modes

```text
1. 同语义多 DOM shape。
2. 同区域多 layout owner。
3. 多代 CSS + !important 同时控制同一 SettingRow。
4. 版本号 runtime 文件让团队习惯“新建下一代文件”而不是替换 owner。
5. 源 renderer 生成旧 DOM，再由 observer 修 DOM。
6. Language / Time zone 由历史 observer 后插入。
7. 测试只验外层两列，没验文字绝对左轴。
8. migration bridge 永久化。
9. mixed settings-brand owner 混合 Settings / Brand / Header / Session 四种职责。
10. Logout 以 redirect 代替 server invalidation verification。
11. Back/BFCache 未纳入 auth state machine。
12. qB authentication bypass 被误判为 logout failure 或 logout success。
```

固定处理顺序：

```text
owner
→ stable semantic filename
→ schema/state boundary
→ source component/renderer
→ migrate unique behavior
→ delete obsolete/versioned owner
→ layout
→ regression contract
```

禁止从截图直接开始补 CSS，也禁止遇到冲突就再创建 `v038.*`。

## 18. Automated ownership gates

普通 dev：

```text
npm/static/syntax
qB 4.1.9.1 + 5.2.0 representative compatibility
```

UI/Auth 变更 focused gate：

```text
one Linux Chromium job
same run covers qB 4.1.9.1 + 5.2.0 fixtures
```

Static asset gate：

```text
no active first-party *-vNNN.css / *-vNNN.js
no active first-party vNNN.css / vNNN.js
no loader reference to removed versioned files
no duplicate old/new semantic asset pair
```

Settings gate：

```text
same source owners across all tabs
no legacy Settings DOM class names in editable rows
no Settings observer required for geometry
wide two-column / narrow one-column
ordinary span=1
copy left-axis absolute alignment
control right-axis absolute alignment
computed text-align != center
explicit full-span allowlist only
Advanced final row reachable
```

Auth gate：

```text
logout through SessionController → QBClient.logout
protected probe confirms invalid session
private shell locks before navigation
Back/BFCache cannot restore private content
login clears logout guard
auth-bypass fixture cannot produce false success
```

完整 stable-tag + Linux/Windows + multi-viewport 仍只属于 main Release candidate。

## 19. Live and Release boundary

真实 exact-SHA qB 4.1.9.1 + 5.2.x LIVE 是 promotion gate。Settings clean cut、stable semantic assets 与 verified logout 都必须在真实 qB 上验证。任何新 SHA 后，旧 LIVE PASS 不继承。
