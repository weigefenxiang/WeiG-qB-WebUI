# 003. WeiG qB WebUI 项目架构

Status: **Current Semantic Ownership**  
Repository: `weigefenxiang/WeiG-qB-WebUI`

> `DESIGN.md` 是总 authority；本文定义 Current Owner、数据流和模块边界。

## 1. 总体数据流

```text
qB WebAPI
→ QBClient detect / endpoint adapter / unit normalization
→ business state owner
→ semantic lifecycle
→ canonical component/presentation owner
→ layout/theme
```

Capability UI 单独遵循：

```text
QBClient.detect() -> qbVersion + webApiVersion
→ W.CapabilityRegistry + data/capabilities.json
→ supported / disabled / degraded
→ badge / Tooltip / canonical Capability Dialog
```

Transient feedback 单独遵循：

```text
business Promise/result
→ W.toast(message, kind, options)
→ W.Feedback / scripts/feedback.js
→ one feedback record/card
→ duration:0 activity rail or finite lifetime rail
→ same-record real-result update
→ leaving -> right exit -> remove
```

Torrent progress 单独遵循：

```text
torrent object already being rendered
→ W.Components.progressVisual(torrent)
→ real percent + semantic state/activity
→ W.Components.progressTrack / progressCell
→ css/progress.css
```

## 3. QBClient vs CapabilityRegistry

`QBClient` 保留技术职责：

```text
request transport
qB/WebAPI detection
endpoint availability facts
unit normalization
```

它不是版本 badge / disabled state / user explanation 的 Owner。

`CapabilityRegistry` 保留 UI policy：

```text
semantic ranges
qB-facing badge
visible disabled state
Tooltip reason
shared Capability Dialog
```

Capability evaluation 只消费已检测的 qB/WebAPI versions，不创建请求或 polling。

## 4. Current hard rules

### ROUTE-OWNER-001
`app.js` 唯一提交 App route presentation。

### RATE-UNIT-001
Canonical rate = B/s；ALT KiB/s 只在 QBClient boundary normalize。

### LAYOUT-OWNER-001
`css/layout.css` 唯一拥有 non-Settings shell/Torrent/Footer geometry。

### EXACT-HEAD-001
CI/LIVE/Release 绑定 exact Git SHA；新提交使旧证据失效。

### CONTROL-SKIN-001
Select behavior only `W.Components.selectControl()`；shared primitive skin only `css/ui.css`。

### DIALOG-SCROLL-001
Dialog shell 不做通用 scroll owner；真实溢出区域内部滚动。

### NATIVE-THEME-001
Native controls 跟随 resolved Light/Dark theme。

### CAPABILITY-OWNER-001
User-facing qB/WebAPI compatibility policy 只有 `W.CapabilityRegistry + capabilities.json` 一个 Owner。

### CAPABILITY-RANGE-001
版本条件使用 semantic range，不靠精确 patch 列表。

### OWNER-RETIRE-001
旧 owner/caller/shim/test expectation 同批退出，Git history 是 archive。

### CURRENT-ONLY-001
当前树不保存 WeiG 旧 release runtime/tests/deploy compatibility copies。

### FILE-NAMING-001
First-party files 使用稳定职责名，不编码 WeiG release 或特定 qB 版本。

### FEEDBACK-OWNER
Transient feedback 只有 `W.Feedback / scripts/feedback.js` 一个 Current Owner；业务唯一入口是 `W.toast(...)`。

### FEEDBACK-TRUTH
Timer 只控制展示寿命；processing 使用 `duration:0`，必须由真实 Promise/result 更新成 success/warning/error。

### FEEDBACK-ACTIVITY
`duration:0` 使用同一卡片上的 indeterminate activity rail，只表达“仍在处理”，不表达业务百分比；真实结果完成后同一 rail 切换为 finite lifetime。

### FEEDBACK-RETIRE
旧 `core.js` Toast owner、旧 `.toast-region/.toast` CSS、旧 `danger` Toast caller 与相应测试假设同批退出，不保留 alias/shim。

### TORRENT-PROGRESS-OWNER
Torrent progress 只有 `W.Components.progressVisual/progressTrack/progressCell + css/progress.css` 一条 canonical presentation chain；Mobile 复用同一 projection/rail。

### TORRENT-PROGRESS-TRUTH
Progress fill width 只来自真实 `torrent.progress`；decorative sheen 不得改变 width 或伪造完成度。

### TORRENT-PROGRESS-STATE
Torrent state 只从当前已渲染 torrent object 本地映射为 download/seed/complete/paused/checking/queued/stalled/error/idle；不增加 API/polling，不从 DOM 反推业务状态。

### TORRENT-PROGRESS-MOTION
只有真实 active download/seed/checking 使用轻量 flow/sheen；complete/paused/queued/stalled/error 静止，System/WeiG Reduced Motion 都关闭装饰运动但保持真实 width/state/color。

## 7. Connection boundary

```text
getTransferInfo connection_status
→ app emits weigg:status-state
→ W.MobileAdaptive paints status + Tooltip/Dialog explanation
→ css/layout.css paints one marker
```

`W.PolishRuntime` 不解析 Connection 文本、不监听 status lifecycle、不画第二圆/扩散环。Connection help 读取现有 qB/WebAPI/DHT/Peers 信息，0 new requests。

## 8. Feedback boundary

`W.Feedback` 是 presentation owner，不拥有 qB state。它不创建 `QBClient`、API request、polling、port scan 或 feature-specific state store。

Add Torrent、Settings save/readback、RSS add/reload 等真实异步动作可创建一个 persistent processing card。Processing 使用 indeterminate activity rail；真实业务结果落定后在同一个 record/card 上 `update(...)`，并切成 finite lifetime rail。Selection command 只声明 `Command sent / 命令已发送`，不能把 HTTP acceptance 描述为长任务已经完成。

Desktop 与 Mobile 共享同一 queue：Desktop 右下角 newest-bottom；Mobile top safe-area newest-top。有限时长自动退出严格 FIFO；`duration:0` processing 不阻塞后续有限时长反馈。

## 9. Capability ranges

Range operators：`eq / gt / gte / lt / lte`；compound：`all / any / not`。

`qBittorrent 5.0.0+` Private exact metadata 与 `WebAPI 2.3.0+` Tags 都是当前 upstream capability facts。WebAPI 门槛在 UI 上优先转换为已知 qB-facing badge，例如 Tags `4.2+`。

任意 patch 版本按 range 比较；测试中的 `4.9.2 / 4.9.3` 是 synthetic boundary strings，不是 release claim。

## 10. Stable repository / tests

禁止 version-labelled first-party runtime/tests/docs aliases。Current tests 验证 current product contract only。

真实 qB 4.1.9.1 + 5.2.x LIVE 与 maintainer 明确授权前不晋级 `main`。

## 11. Theme ownership boundary

Theme preference 与 resolved visual theme 是两个不同概念：

```text
W.Config.theme = system | time | light | dark
        ↓
W.Theme / scripts/theme.js
        ↓
resolved = light | dark
        ↓
html[data-theme]
        ↓
semantic surface/control tokens
```

Current Owner：`W.Theme / scripts/theme.js`。`W.Config` 只保存 preference；Header 与 Settings 都只是 presentation caller，并复用 `W.Components.selectControl()`。`app.js` 不再拥有二态 toggle。

### THEME-OWNER
Theme mode validation、resolved Light/Dark、system listener、Smart Auto boundary timer、`theme-color` metadata 和 `weigg:themechange` 只有 `W.Theme` 一个 Current Owner。

### THEME-MODE
Canonical preferences 只有 `system / time / light / dark`。`system` 跟随浏览器/OS；`time` 使用浏览器设备当地时间；`light/dark` 为固定模式。

### THEME-RESOLUTION
CSS 与 native control 只消费 resolved `light / dark`，禁止让 CSS 解释 `system/time`，禁止从可见 DOM 反推 saved preference。

### THEME-SYSTEM
System mode 只使用一个 `prefers-color-scheme` change listener，实时切换，无刷新、无 API、无 polling。

### THEME-TIME
Smart Auto：20:00–次日08:00 Dark，其余 Light。只调度下一个 08:00/20:00 boundary timer；页面恢复可见或 pageshow 时校准。禁止 minute polling。

### THEME-SURFACE
Light 的 canonical surface ladder 是 white canvas -> white/very-light-blue surface -> cool hairline -> blue/violet elevation。各 feature CSS 通过 semantic variables 消费，不得新增 `light-fix.css` 或末尾 selector patch layer。

### THEME-DARK-STABILITY
本次 Light migration 不重新设计 Dark palette。Dark token 是稳定 baseline；共享 component formula 通过不同 semantic token 同时覆盖 Light/Dark。

### THEME-MOTION
Theme truth 不依赖动画。System `prefers-reduced-motion` 与 WeiG `data-motion=reduced` 下，明暗切换、mode 生命周期和 boundary timer 仍正确，装饰 transition/animation 必须可关闭。

### THEME-RETIRE
新 owner 生效后，旧 `core.js` Theme resolution、`app.js::toggleTheme()`、直接 `#theme-btn.onclick`、重复 Theme enum/state 和 Light CSS correction layer 必须退出 runtime。
