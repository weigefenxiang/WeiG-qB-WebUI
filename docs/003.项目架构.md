# 003. 项目架构

> 本文件记录长期有效的模块边界与兼容架构，不维护历史 Phase 状态。`webui/**` 是唯一正式产品；Current Owner 最终以 `DESIGN.md` 为准。

## 1. 总体分层

正式产品链：

```text
qB official stable source
-> source extractors / admitted release facts
-> W.ReleaseProfile
-> canonical compatibility owners
-> W.QBClient
-> real qB WebAPI / WebApplication
-> UI / presentation
```

辅助验证链：

```text
same formal webui/**
-> W.QBClient
-> Virtual qB transport / simulator
-> browser / Pages acceptance
```

Virtual qB、fixtures 和 Pages 只能模拟/验证产品，不能反向定义正式产品语义。

## 2. Current Owner 规则

```text
Exact stable source facts              W.ReleaseProfile
HTTP transport / endpoint invocation   W.QBClient
User-visible capability strategy       W.CapabilityRegistry
Settings Preference semantics          W.SettingsSchema
Persisted language truth               qB app/preferences.locale
WeiG translation/presentation runtime  W.I18n
Torrent status/filter semantics        W.TorrentSemantics
Torrent field/column provenance        W.TorrentFieldRegistry
Torrent query/page/sort state          W.LibraryController / W.AppState
Selection/actions                      W.Selection / ActionRegistry
Torrent row/card DOM                   W.Components
DataGrid layout/resize/persistence     W.DataGrid
Transfer runtime/history               W.TransferRuntime
Responsive placement                   W.MobileAdaptive / W.SpatialRuntime
Settings presentation                  W.SettingsRenderer
Logs runtime                           W.Logs
RSS query/presentation                 W.RSS + canonical UI caller
```

一个 semantic purpose 只能有一个 Current Owner。

`W.I18n` 仍是当前 presentation API，但 qB-owned Settings wording 已不是“浏览器自有翻译库”模式：当前 0.3.72 延续 native-first QBT_TR/QM，只有 source-proven Alternative WebUI 翻译洞才使用 exact official-TS compatibility shard。详见 `docs/012.qB原生翻译与国际化复盘.md`。

正式 owner 切换必须 atomic cutover：

```text
new owner
+ all callers
+ tests/contracts
+ DESIGN/docs
+ remove old owner
```

禁止：

```text
dormant duplicate owner
runtime bridge / monkey patch
MutationObserver 修复业务架构
第二业务状态
重复 polling
presentation 保存自己的 compatibility truth
```

## 3. Source Truth 层

Build-time source facts主要来自：

```text
tools/qb-release-tags.mjs
tools/qb-release-catalog.mjs
tools/qb-stable-admission.mjs
tools/qb-source-parsers.mjs
tools/qb-torrent-surface-parsers.mjs
tools/qb-torrent-fields-parser.mjs
tools/qb-detail-surface-parsers.mjs
tools/qb-action-surface-parsers.mjs
tools/qb-preference-semantics.mjs
tools/qb-catalog-evolution.mjs
tools/qb-webapi-evolution*.mjs
```

每个 admitted stable profile 可以提供：

```text
qB version / WebAPI version / source SHA
API actions
required/optional action parameters
Torrent request/response fields
Torrent states / filters
Details response fields
Preference getter/setter/type provenance
WebUI locale surface facts
release evolution facts
```

这些 facts 进入 `W.ReleaseProfile` 后，再由正式 runtime owners 消费。UI caller 不应维护 patch-version table。

Translation bodies 不属于 release compatibility catalog 的主职责。qB-owned translation source/context 与 translator behavior 由 source evidence 证明；正式产品优先复用 qB WebApplication 的原生 translator。只有上游 Alternative WebUI 无法执行 QBT_TR 的 exact family 才允许窄化 compatibility transport。

## 4. Capability model

统一 modes：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

`UNKNOWN` 只表示无法证明。对危险 write/action，`UNKNOWN` 必须在 QBClient 发出 HTTP 前被阻断。

不能因为版本更高就自动继承最新 capability；不能因为 major 改变就整体拒绝。

## 5. Read / Write / Action / Field 分离

不同语义必须独立证明，禁止用一个粗粒度 boolean 同时控制多个动作。

例如：

```text
Tags:
read/facet/filter != list != assign != create != delete

Category:
read/filter != list != create/delete != assign

Tracker:
read != add != remove != edit != reannounce

Settings:
read endpoint != write endpoint != per-Preference writable

Details:
properties/files/trackers/peers/webseeds reads independent
file priority / peer ban / tracker writes independent
```

## 6. Torrent field architecture

Torrent field chain：

```text
W.ReleaseProfile exact torrentInfoFields
-> W.TorrentFieldRegistry
   canonical field ID / metadata
   provenance mode
   effective availability
   saved preference merge
-> W.DataGrid layout/resize/persistence
-> W.Components rendering
-> Desktop/Mobile Columns + Sort
```

Saved preference 与 effective availability 分离。字段存在不自动证明 server-side sort/filter 语义。

## 7. Settings architecture

Settings 写能力是双层证明：

```text
W.ReleaseProfile proves app/setPreferences action
AND
W.SettingsSchema proves Preference setter/type/editability
-> W.QBClient.setPreferences
-> verification reread
```

任何一层 unknown/unproven 都不能进入 write payload。

Locale 是同一 Settings transaction 的 Preference，不建立第二套语言保存 owner。

## 8. Language / translation architecture

### 8.1 Persisted locale

```text
qB preferences.locale
-> shared app.preferences / SettingsState.prefs
-> W.I18n.applyLocale()
```

Locale options 优先来自 running qB 的 `${LANGUAGE_OPTIONS}`；Virtual/historical 使用 source-SHA-bound frozen locale facts。

### 8.2 qB-owned wording：当前 0.3.72 native-first

当前正式链：

```text
exact qB Preferences source/context
-> source-SHA-bound translator behavior
-> QBT_TR registry
-> qB native translator / official minimal QM when supported
-> W.I18n.qbSetting() presentation consumption
```

对 `4.5.0 -> 4.6.4` 这类 source-proven Alternative WebUI QBT_TR gap：

```text
exact qB official TS
-> private/data/qb-settings/<sourceSha>.json
-> only the exact routed profile/locale consumes the bridge
```

因此：

```text
qb-releases.json                      compatibility/source facts only
private/data/qb-settings-native.txt   native QBT_TR registry
settingsTranslationPath               narrow compatibility pointer only
```

`settingsTranslationPath` 不是待一刀切删除的历史债；只要支持范围仍包含 upstream 无法执行 Alternative WebUI document translation 的 exact stable，它就可能作为受 source evidence 约束的 compatibility pointer 存在。禁止把它扩回全版本翻译 owner。

65-stable translator behavior audit 与 QM provisioning 已完成；不要再把它们描述为“迁移前待办”。

### 8.3 WeiG-owned wording

只有 qB upstream 没有对应语义的 WeiG feature text 才由 `W.I18n` 自己拥有翻译。

完整决策与当前实现见 `docs/012.qB原生翻译与国际化复盘.md`。

## 9. Action parameter architecture

对于 Tracker、Torrent Creator、Files、Peers 等 action：

```text
exact release/source action
+ exact required/optional parameter facts
-> capability owner
-> canonical form generation
-> QBClient transport guard
```

如果 action 存在但参数 contract 无法证明，最终 write 状态仍应是 `UNKNOWN`/unavailable，而不是猜参数。

## 10. Virtual qB / Pages 架构

Virtual qB 与 Pages 使用同一份正式 `webui/**`，仅替换后端 transport/environment。

Pages artifact 必须绑定 source exact SHA：

```text
Virtual qB Pages Source
-> relevance classifier
-> Virtual qB Pages build for relevant dev exact SHA
-> virtual-qb-pages-site-<SHA>
-> deploy + live verify
-> main promotion reuses the same exact dev artifact
```

日常 docs-only commit 可以让 current dev HEAD 仅因明确 Pages-irrelevant history 领先 materialized Pages SHA；runtime installer 与 dev deploy gate会验证中间 diff。正式 release evidence 仍要求 final dev exact SHA 自己有同 SHA Pages evidence。

main promotion path不重新 build site。若 exact artifact 不存在，必须 fail closed。

当前 native-first translation 路径下，Pages 在 validation build 中模拟 qB server-side QBT_TR replacement；这种 emulator/fixture 只属于 validation infrastructure，不能成为正式产品的第二 translation owner，也不能为 `4.5.0 -> 4.6.4` 伪造上游不存在的 native capability。

## 11. Real-qB 架构

全版本真实 qB 验证不建立第二 compatibility owner：每个 runtime job都使用正式 `webui/**` 与同一套 capability-driven harness。

版本 expectation 来自 Frozen LKG / exact release profile；真实 qB runtime 负责验证 source facts 与产品语义在真实服务器上成立。

当前 release-grade real-qB evidence 分为两个互补 owner：

```text
Real qB Current Stable Locale Matrix
-> final dev exact SHA 上显式 workflow_dispatch
-> current admitted stable 的全部 exact locale
-> 每个 locale write/read/reload/restore
-> exact-SHA aggregate

Real qB Full Frozen Matrix
-> final dev exact SHA 上显式 workflow_dispatch
-> 全部 Frozen admitted stable runtime
-> Exhaustive exact-version semantics
-> exact-SHA aggregate
```

当前 operational surface 是 qB 5.2.3 的 61 locales 与 Frozen 65 stable runtimes；数量由 exact LKG 派生，不作为架构常量。

发布前 `candidate + Pages + manual Locale + manual G-FM` 必须绑定同一 final exact SHA，并由中央 `tests/release-compat-evidence.mjs` 再验证。普通 push 的 skipped Locale run、Fast G-FM utility 或旧 SHA evidence 均不能冒充 release-grade evidence。

Full Frozen Matrix 是 final/release-stage 重型验证，不是日常开发反馈环；普通 dev push 与中间 checkpoint 不运行它。

## 12. 架构变更纪律

涉及以下内容时必须同步检查 docs/tests/workflows：

```text
Current Owner 变化
source fact schema 变化
capability mode 变化
endpoint/action parameter 变化
Locale/translation owner 变化
Pages exact-SHA choreography 变化
candidate/promotion/release evidence 变化
```

删除一个 workflow、owner 或 contract 时，必须搜索所有引用并同批退役，避免出现“文件删了但测试仍要求其存在”的悬空依赖。
