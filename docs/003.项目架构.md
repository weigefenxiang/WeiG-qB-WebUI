# 003. WeiG qB WebUI 项目架构

Status: **v0.3.7 architecture authority / Responsive UI System 3.3**  
Repository: `weigefenxiang/WeiG-qB-WebUI`

> 本文定义运行时层次、模块边界与 ownership。视觉/交互规则以根目录 `DESIGN.md` 为最高 authority；产品总方案见 `001.项目总方案.md`；兼容与测试见 `002` / `006`。

## 1. 总体数据流

```text
qB WebAPI
  ↓
QBClient + capability normalization
  ↓
Application state / preference drafts
  ↓
PreferenceSchema / semantic registries
  ↓
Canonical component factories
  ↓
Canonical layout owners
  ↓
Responsive presentation
```

核心边界：presentation 只决定如何显示，不复制后端业务。

## 2. Business / Presentation 分层

```text
QBClient
  ✓ API contract
  ✓ compatibility bridge
  ✓ endpoint / field / capability normalization
  × no layout

Preference state / draft
  ✓ qB preference values
  ✓ save semantics
  ✓ setPreferences ownership
  × no CSS geometry

PreferenceSchemaV037
  ✓ field title/description/type/unit/enum/capability
  ✓ explicit layout metadata: span/layout/control semantic
  × no DOM mutation

Canonical components
  ✓ controls and SettingRow structure

Layout owners
  ✓ SettingsGrid / Shell / DataGrid / Dialog geometry
  × no qB WebAPI duplication
```

## 3. Settings architecture 3.3

Canonical pipeline：

```text
QB preference / WeiG preference
        ↓
PreferenceSchema
        ↓
SettingRowFactory
        ↓
SettingRow
├─ SettingCopy
└─ SettingControlSlot
        ↓
SettingsGrid
        ↓
SettingsSectionPanel
        ↓
SettingsViewportLayout
```

### 3.1 SettingRowFactory

所有 ordinary editable setting 最终必须进入同一个 factory/adapter，而不是让不同历史模块直接输出不同 DOM。

Factory 接收概念输入：

```text
key
label
description
control
help
span       default 1
layout     default inline
capability
```

输出唯一结构：

```text
SettingRow
├─ SettingCopy
│  ├─ SettingTitleLine
│  └─ Description
└─ SettingControlSlot
```

历史 `settings-control` flat DOM 只能作为 migration input。迁移完成后，不允许继续维护两套 row CSS。

### 3.2 SettingsGrid

```text
wide desktop  -> two outer columns
narrow/mobile -> one outer column
```

每个 ordinary SettingRow 默认只占一个 outer cell。最后一个奇数 row 保留左 cell，不拉伸。

`span=full` 只能由 schema 明确声明给 multiline/composite/data editor。禁止通过 key/label 字符串匹配推断。

### 3.3 SettingControlSlot

`SettingControlSlot` 是统一右对齐 owner：

```text
Switch
NumberInput
PortInput
Select
TextInput
RateControl
DurationControl
TimeZoneControl
```

它负责 alignment/width tier，不负责业务值转换。

## 4. ControlRegistry

Canonical mapping：

```text
boolean       -> Switch
number        -> NumberInput
port          -> PortInput
select/enum   -> Select/Listbox
text          -> TextInput
path/url      -> TextInput semantic variant
rate          -> RateControl
duration      -> DurationControl
timezone      -> TimeZoneControl
readonly      -> read-only/Fact semantics
```

已验证 enum 应优先显示 canonical Select，而不是让用户面对无说明的数字 code。

## 5. Settings migration bridge

当前 `settings-brand-v037.js` 的 normalize/MutationObserver 只能作为迁移桥。

长期 architecture 禁止：

```text
observer 反复搬 SettingRow
setTimeout 周期性修 layout
等待另一个 observer 先补 class
页面渲染后再猜 owner
```

目标是源 renderer 一次生成正确 DOM；normalize 只兼容尚未迁移的历史模块，并最终可删除。

## 6. CSS ownership

Settings geometry 只有一个 owner：

```text
settings-brand-v037.css (or future canonical successor)
→ SettingsSectionPanel
→ SettingsGrid
→ SettingRow
→ SettingControlSlot
```

历史 `SETTINGS-FORM-RAIL-*` 规则不得影响 migrated SettingsGrid。

禁止两个高 specificity / `!important` 系统同时控制同一个 row 的 width/grid-template/alignment。

## 7. Header architecture

Topbar actions 分两类：

```text
Primary action
└─ Add Torrent

HeaderUtilityBar
├─ GitHub external action
├─ Blog external action
├─ Refresh runtime action
└─ Theme runtime action
```

### HeaderUtilityAction

一个 presentation owner 同时支持：

```text
action="external" -> <a>
action="runtime"  -> <button>
```

两者共享：

```text
icon-btn geometry
Tooltip
focus-visible
hover/active
accessible label
```

外链 registry：

```text
github -> https://github.com/weigefenxiang/WeiG-qB-WebUI
blog   -> https://www.weigshare.com/
```

不允许 feature-local `.github-btn` / `.blog-btn`。

## 10. Responsive ownership

手机不是独立业务应用。

```text
Desktop / Tablet / Phone
        ↓
shared model + shared components
        ↓
adaptive layout only
```

每个 active long page 只有一个 primary scroll owner。Settings 为 `settings-content`。

Phone topbar 空间不足时 GitHub/Blog 外链移动到 ContextDrawer `Links`；action registry 不变。

## 11. Compatibility architecture

`QBClient` 继续是唯一 qB WebAPI compatibility boundary：

```text
4.x resume/pause ↔ semantic start/stop ↔ 5.x start/stop
field presence    ↔ capability
legacy/modern API vocabulary bridge
```

Settings UI 迁移不得改变任何 preference key 或 write contract。

## 12. Systemic failure modes

已确认需要长期防止：

```text
1. 同语义多 DOM shape
2. 同区域多 layout owner
3. key-name heuristic 代替 schema
4. MutationObserver 成为主渲染器
5. !important 层叠互相覆盖
6. 测试只验“有两列”而不验每个 row alignment
7. Header 新入口各自创建视觉模板
```

处理顺序固定：

```text
owner
→ schema
→ component
→ layout
→ regression contract
```

禁止直接从最后一步补 screenshot-specific CSS。

## 13. Automated ownership gates

普通 dev：

```text
npm/static/syntax
qB 4.1.9.1 + 5.2.0 representative compatibility
```

UI 变更：

```text
one Linux Chromium focused gate
same run covers qB 4.1.9.1 + 5.2.0
```

Focused Settings contract 必须逐 tab 验证：

```text
same Settings owners
wide two-column / narrow one-column
ordinary span=1
copy left aligned
control right aligned
no centered ordinary setting title
explicit full-span allowlist only
Advanced final row reachable
```

完整 stable-tag + Linux/Windows + multi-viewport 只属于 main Release candidate。

## 14. Live and Release boundary

真实 exact-SHA qB 4.1.9.1 + 5.2.x LIVE 仍是 promotion gate。任何 UI/docs/code 变化产生新 SHA 后，旧 LIVE PASS 不继承。
