`webui/**` 是唯一正式产品。浏览器 runtime 的 release-profile layer 已退休；source catalog是离线 source truth / admission / validation input，不是 runtime owner。

## 1. 总体分层

```text
qB WebAPI
-> W.QBClient                    # transport + detected qB/WebAPI identity
-> W.CapabilityRegistry          # runtime release resolution + lazy domain loader
   <- capabilities.json          # control plane only
   <- torrent-compat.json
   <- detail-compat.json
   <- settings-compat.json
   <- rss-compat.json
   <- source-actions.json
-> canonical semantic owners
-> UI / presentation

current qB-owned copy runtime
   qb-settings-native.txt + minimal official QM
   -> W.I18n

qB official source / Frozen admitted release catalog
-> semantic source extractors
-> independent inventory/census
-> common catalog identity
-> compact domain compilers
-> exact-release compact contracts + qB-owned copy evidence
-> formal browser consumes only bounded/lazy runtime artifacts
```

`capabilities.json` 只负责 release identity、high-level gates 与 `compatFiles` index，不承载所有 UI/version history。领域事实各自归对应 compact contract；full 65-release catalog只存在于 tools/CI/simulator/admission层。

### 1.1 Product-first architecture discipline

Source/tooling层存在的目的，是让正式 `webui/**` canonical owner可以安全、可证明地运行；它本身不是交付目标。开发顺序默认是：

```text
formal product blocker
-> webui owner/caller cutover
-> only if blocked: patch exact source/tooling/test gap
-> return immediately to product cutover
```

已经具备的 source foundation不能长期停在 evidence层。只要足以支撑当前 product owner切换，就应优先完成 `webui/**` integration/retirement，而不是继续横向扩 parser/census/test surface。新增 infrastructure必须有明确 product consumer或具体 validation responsibility。

## 3. Compact domain contract

正式 runtime domain当前包括：

```text
capabilities.json
  releases / WebAPI milestones / high-level features / compatFiles

torrent-compat.json
  Torrent filters/states/fields/columns
  B target: native sidebar facet inventory/order/semantics

detail-compat.json
  Torrent Detail tabs/layout/tables/menus/control facts

settings-compat.json
  bounded exact-source Preferences transport envelope
  A1 target: tabs/fieldsets/nested structure/rows/clusters/controls/helper actions/adornments/behavior predicates/source refs
  plus descriptors + value projection; display adornment is not the same contract as numeric scale

rss-compat.json
  exact RSS Downloader native-surface fields/copy/path/control semantics

source-actions.json
  exact action existence + required/optional parameter provenance

qB-owned copy artifact
  exact {source, context} -> official locale route
```

`tools/qb-catalog-identity.mjs` 现在是 common Frozen catalog identity helper。`tools/qb-compact-runtime.mjs` 已把同一 identity注入 capabilities/torrent/detail/actions/settings outputs；Preferences keyed native IR也携带该 identity。**这只是 foundation，不是 F 完成**：RSS尚未纳入同一 compiler/identity closure，browser/distribution也尚未对全部 domains执行 mixed/stale identity拒绝。

最终所有 domain与 qB-owned copy必须从同一个 Frozen admitted catalog编译并携带可比较的 catalog/release-set identity。若任一 domain停在不同 release set，CI/runtime contract必须 fail closed，不能混合“capabilities已更新、settings/rss仍是旧 catalog”的 bytes。

## 4. Compatibility / writes

`W.CapabilityRegistry` 从 compact source facts解析 Torrent filters/info fields/table columns/Detail UI/RSS UI/source actions。UI key不是 API proof；unknown upstream shape fail closed。Dangerous write必须具备 certified identity + exact action/parameter provenance，并由 `W.QBClient` transport；不能用 patch/major version猜 endpoint。

Settings write additionally要求 current runtime key、exact Preference setter/type agreement与source raw/UI `projection`共同成立。`identity / scale / switch-map / unproven` + `safeWrite`直接来自exact source；其中 exact writable string control若 source明确 direct identity setter，可附加 `writeIdentity:true`。只有 certified identity + source action + current key + descriptor + `projection.safeWrite` + dependencies + raw type 全部成立才允许进入HTTP；未知路径 read-only/fail closed。

## 5. Settings source-to-runtime boundary — A1 contract

A-base已经建立唯一Settings runtime owner和安全write gate；A1不推翻这条链，而是把 source truth从 preference-centric row 扩展为 **qB Control Graph**。人工复核证明仅有tabs/sections/basic controls不足以还原真实Options。

```text
exact qB Preferences HTML + inline source behavior + preferenceDescriptors
  ├─ independent Preference inventory/census
  ├─ value projection / setter provenance
  └─ A1 generic structural parser
       tab / fieldset / nested fieldset
       row / cluster / source order
       source label / local label / note
       preference control
       helper control / source-owned action button
       adornment prefix/suffix/unit
       bounded behavior predicate graph
           truthy / falsy / equals / notEquals / allOf / anyOf
       |
       v
     compact exact-release Control Graph IR
       | bounded transport + Frozen identity + raw payload hash
       v
settings-compat.json
  -> W.CapabilityRegistry lazy decode / integrity / exact-release identity gate
  -> W.SettingsSchema graph adapter
       graph facts ∩ current GET app/preferences
  -> W.SettingsRenderer generic structural templates
  -> existing writeSafe() gate
  -> W.QBClient app/setPreferences + verified reread
```

`settings-compat.json`仍是domain入口，不是第二source truth。A1不得在browser里执行upstream arbitrary JS；build-time parser只能把已证明的source behavior降级为小型可审计predicate/action IR。未知行为read-only/disabled/fail closed。

Generic structural templates可以表达 `single row / inline multi-control / control+helper button / gated sentinel value / nested gated fieldset / time range / adornment`，但模板选择必须来自graph shape。禁止 `if(key==='listen_port')`、Proxy手工key list、patch-version layout table或第二Settings renderer。

Display adornment与value projection分属不同source fact：`KiB/%/MiB/ms/sec/min`等后缀可独立来自HTML adjacency；API raw↔display scale/inverse仍只由value-projection source证明。不得因为单位存在就猜scale。

About/product identity 的A1-0 cutover由 `tools/product-identity.mjs -> webui/private/product-identity.json -> W.SettingsRenderer About` 单一路径负责；`weigg-install.json`只保留部署metadata，不再承担产品VERSION authority。source-direct与materialized runtime读取同一generated identity，`tools/build-webui-dist.mjs`在打包时再次校验其与canonical VERSION一致。

A1必须先做structural census/accounting，至少证明Listening Port、Connection Limits、I2P、Scheduler、Proxy、Advanced adornments在exact source与IR间没有silent drop，再接renderer。

E/Detail继续固定为：

```text
W.CapabilityRegistry.torrentDetailUi()
-> W.QbUiEvidence
-> generic app Detail runtime
-> W.SharedColumns / W.ColumnInteraction / existing W.VirtualList

```

General只消费 source-generated layout；Files/Trackers/Peers/Web Seeds共用 generic renderer/action chain；禁止 per-surface第二 schema、第二 scroll owner或 endpoint-name业务分支。

`W.VirtualList` 是 Torrent主列表和需要虚拟投影的 Detail surface 的 canonical virtual/scroll owner。原生横/纵向滚动或 scrollbar drag期间，网络 polling可以继续，但新 snapshot不得替换正在交互的 DOM；只保留 latest pending snapshot，bounded idle后一次提交。禁止第二轮 polling、scroll repair或 MutationObserver同步。

## 7. Completeness / anti-omission architecture

仅有 semantic extractor不足以证明“没有漏”。每个准备声明阶段完成的 source-driven domain必须有独立 inventory/census路径：

```text
raw exact upstream source
  ├─ semantic extractor -> compact product facts
  └─ independent inventory/census -> upstream exposed inventory

inventory = mapped + explicit reviewed exclusions
unaccounted = 0
duplicate = 0
```

Preferences字段级source layer已经实现独立census并在full-stable contract检查tabs/preferences/bindings；A1还必须补**结构级accounting**，独立核对source-owned helper controls/actions/adornments/compositions/behavior nodes，避免semantic extractor与runtime一起漏掉同一结构。B/C/D/E/F仍需各自census/coverage closure。

Inventory应尽量避免复用 semantic extractor的同一 parser assumption。若 upstream改成未知语法，正确结果是 admission fail/PENDING_REVIEW，而不是 extractor返回少几个元素后仍然绿色。

## 8. Build/runtime boundary

65 stable source catalog、full translation recovery、upstream source parser属于 tools/CI/simulator。raw `webui/` 只携带浏览器真正消费的 compact contracts/copy/QM，因此可直接作为 Alternative WebUI root。Historical `main=0.3.71` simulator preview可在 `branch==='main'` 的 simulator-only build路径临时物化旧 profile runtime；不得回流到 dev formal product。

历史上用于 connector传输的 `.weigg-bootstrap/**` 和一次性 `dev-bootstrap-*.yml` 不属于任何正式 architecture owner；它们必须在最终产品 tree中消失，不能被后续 AI当成 runtime/build subsystem继续维护。

## 9. Validation

Source audit、phase-end 65-release offline/Virtual matrix、browser/Pages、real-qB、Candidate/Release是不同 evidence层。阶段内部只跑与当前 product change直接相关的 focused/change-point；一个阶段完整收口后最多一次该领域的65-release offline/Virtual full matrix。最终 real-qB heavy matrix只属于全部 A–F完成、final dev exact SHA冻结后的 release-grade gate。

`SKIPPED != PASS`；exact-SHA evidence不可跨提交偷用。Workflow内部 source-contract PASS不能替代该产品 checkpoint 的 applicable UI/browser 与 exact-SHA Pages materialization/build/deploy/live evidence。
