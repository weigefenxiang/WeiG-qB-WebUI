# 003. WeiG qB WebUI 项目架构

Status: **Architecture authority for v0.3.5+**  
Repository: `weigefenxiang/WeiG-qB-WebUI`

> 本文负责“文件放在哪里、谁依赖谁、每层允许做什么”。视觉/交互看 `DESIGN.md`；产品硬规则看 `001.项目总方案.md`；兼容状态看 `002.兼容与实现状态.md`；UI/缓存专项契约看 `004.UI与缓存契约.md`。

## 1. 架构目标

```text
qB API/version differences → QBClient + Capability + normalization
Torrent/business state     → Application Controller
DOM primitives             → Components/Core
Large-list mechanics       → VirtualList/DataGrid
Settings semantics         → SettingsSchema/Translations + settings compatibility runtime
Navigation/i18n bridge     → UX layer
Feature enhancements       → versioned runtime modules
Visual material            → canonical CSS layers
Build/cache identity       → HTML build SHA + installer/release stamping
Browser compatibility gate → deterministic qB fixtures + Chromium
Install/backup/rollback    → Installer + install metadata
```

语言契约：**English 是 canonical source language；简体中文是正式维护语言**。Feature runtime 通过 i18n/translation layer 获取展示文本，不直接按 locale 分支。

硬约束：

```text
UI / Runtime / Components
  × 不直接散落 qB 主版本特例
  × 不伪造不存在的 backend data/write API
  × 不把大型数据变成大型隐藏 DOM
  × 不为已有语义再造第二套 Card/Grid/Modal
  × 不自行维护 ?v=0.x.y 静态资源版本

QBClient
  ✓ 唯一 API contract / compatibility / normalization boundary

HTML + deploy layer
  ✓ 唯一 build Git SHA 来源
```

## 3. Runtime 依赖

`private/index.html` 是 canonical runtime bootstrap，直接资源统一使用：

```text
?v=__WEIGG_GIT_SHA__
```

安装器/Release 打包时占位符被替换为实际 40 位 Git SHA。

`components.js` 负责 lazy runtime asset helper：

```text
<meta name="weigg-build-sha" content="<SHA>">
          ↓
currentBuildToken()
          ↓
buildAssetUrl(path)
          ↓
path?v=<SHA>
```

所以旧层仍可保持稳定文件名：

```text
spatial-v022.js  → Filter Shelf / Connection Dock / spatial composition
v030.js          → stable scroll / Transfer Dock / session graph / selection
v030.css         → compact empty state / Transfer surfaces / selection feedback
logs-v032.js     → cross-version Logs stream / filters / adaptive panel
settings-v034.js → Alternative WebUI compatibility/safety save bridge
```

文件名中的历史版本不再等于 cache identity。**真正的资源身份只有部署 Git SHA。**

## 4. Components ownership

`components.js` 是可复用 DOM primitive 层。

Settings：

```text
W.Components.preferenceField()
  → editable qB preference SettingCard

W.Components.readonlySettingField()
  → readonly WeiG/deployment SettingCard

settings-control
  → WeiG interface preference
```

统一视觉：

```text
settings-row setting-card
Title
Description
Control / readonly input
```

普通 desktop 2 列，wide desktop 三卡视觉列，mobile 1 列。任何 feature runtime 可以增加业务行为，但不能复制上述 layout CSS。

## 5. `qb-client.js`

唯一 qB WebAPI 兼容边界。

### 5.1 语义桥

```text
4.x resume ↔ 5.x start
4.x pause  ↔ 5.x stop
4.x paused ↔ 5.x stopped
```

### 5.2 Logs contract

```text
qB >= 4.1.0 → logs=true
legacy log milliseconds → seconds
modern log seconds      → seconds
```

### 5.3 Preferences contract

Alternative WebUI 不按主版本硬编码，读取实际 `app/preferences`：

```text
alternative_webui_enabled
alternative_webui_path
```

存在即显示；缺失即 Unsupported；写入统一走 `QBClient.setPreferences()`。

## 6. `settings-v034.js` 在 v0.3.5 的职责

文件名为历史兼容保留，但**不再拥有视觉组件**。

允许职责：

```text
读取 Alternative WebUI 两个 Preferences
用 canonical preferenceField() 渲染 enabled/path
用 readonlySettingField() 渲染 Host/VERSION/Git SHA/Container/Installed At
隐藏 Advanced generic 重复项
复用顶部 Save qB Settings
路径风险确认
已知 Docker Host path 误填阻止
关闭 Alternative WebUI 强确认
关闭成功后返回 /
读取 weigg-install.json
```

禁止职责：

```text
第二套 Settings Grid
第二套 Setting Card
alt-webui-v034__head/control/meta/info
feature-local Settings CSS
```

Docker 路径 contract：

```text
Host: /root/qbittorrent3/config/weigg-qb-webui
  ↓ mounted as /config
qB:   /config/weigg-qb-webui
```

Host path 不能直接写入 qB 的 `alternative_webui_path`。

## 8. Build / cache identity

### 8.1 Source payload

源码保留：

```text
webui/GIT_SHA = __WEIGG_GIT_SHA__
private/index.html build meta = __WEIGG_GIT_SHA__
local CSS/JS query = __WEIGG_GIT_SHA__
weigg-install.json.gitSha = __WEIGG_GIT_SHA__
```

### 8.2 Linux installer

`install.sh`：

```text
main install → GitHub commits API 解析 main SHA
Release      → archive 内 GIT_SHA
        ↓
inject_build_sha()
        ↓
写 GIT_SHA
写 weigg-install.json.gitSha
```

Release 缺少有效 40 位 SHA 时拒绝把它当作 SHA-addressed payload。

### 8.3 Windows installer

`install.ps1` 采用相同 contract：`Resolve-MainSha` / `Inject-BuildSha` / `GIT_SHA` / `gitSha`。

### 8.4 GitHub Release

`release.yml` 在打包前使用 `${GITHUB_SHA}` 替换 source placeholder，然后生成 ZIP + SHA256SUMS。

### 8.5 HTML no-store

`public/login.html` 与 `private/index.html` 都声明 no-store/no-cache meta。生产环境还要检查 qB/反代/CDN 最终 HTTP Header，因为前端仓库不能强制覆盖 Cloudflare/Nginx 的缓存策略。

## 9. 安装身份

部署目录：

```text
VERSION
GIT_SHA
private/weigg-install.json
```

Linux Docker metadata 示例：

```json
{
  "version": "0.3.5",
  "gitSha": "<40-character SHA>",
  "container": "qbittorrent3",
  "qbPath": "/config/weigg-qb-webui",
  "hostPath": "/root/qbittorrent3/config/weigg-qb-webui",
  "installedAt": "...",
  "installer": "linux"
}
```

qB WebAPI 无法推导 Docker Host path；只能由部署层元数据提供。

## 13. Installer / security boundary

普通 install/update：

- 不修改 WebUI 用户名/密码；
- 多 qB container 时不猜目标；
- 先备份再原子替换；
- rollback 可恢复上一份；
- qB path 与 Host path 明确分开；
- `VERSION` 是产品版本；
- `GIT_SHA` 是确切部署源码身份。
