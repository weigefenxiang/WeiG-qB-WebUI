# 003. 项目架构

> 本文件记录长期有效的模块边界与兼容架构，不维护历史 Phase 状态。`webui/**` 是唯一正式产品；Current Owner 最终以 `DESIGN.md` 为准。

## 1. 总体分层

正式产品链：

```text
qB official stable source
-> source extractors / admitted release facts
-> W.ReleaseProfile
-> canonical compatibility owners
-> W.QBClient
-> real qB WebAPI
-> UI / presentation
```

辅助验证链：

```text
same formal webui/**
-> W.QBClient
-> Virtual qB transport / simulator
-> browser / Pages acceptance
```

Virtual qB、fixtures 和 Pages 只能模拟/验证产品，不能反向定义正式产品语义。

## 2. Current Owner 规则

```text
Exact stable source facts              W.ReleaseProfile
HTTP transport / endpoint invocation   W.QBClient
User-visible capability strategy       W.CapabilityRegistry
Settings Preference semantics          W.SettingsSchema
Torrent status/filter semantics        W.TorrentSemantics
Torrent field/column provenance        W.TorrentFieldRegistry
Torrent query/page/sort state          W.LibraryController / W.AppState
Selection/actions                      W.Selection / ActionRegistry
Torrent row/card DOM                   W.Components
DataGrid layout/resize/persistence     W.DataGrid
Transfer runtime/history               W.TransferRuntime
Responsive placement                   W.MobileAdaptive / W.SpatialRuntime
Settings presentation                  W.SettingsRenderer
Logs runtime                           W.Logs
RSS query/presentation                 W.RSS + canonical UI caller
```

一个 semantic purpose 只能有一个 Current Owner。

正式 owner 切换必须 atomic cutover：

```text
new owner
+ all callers
+ tests/contracts
+ DESIGN.md
+ remove old owner
```

禁止：

```text
dormant duplicate owner
runtime bridge / monkey patch
MutationObserver 修复业务架构
第二业务状态
重复 polling
presentation 保存自己的 compatibility truth
```

## 3. Source Truth 层

Build-time source facts主要来自：

```text
tools/qb-release-tags.mjs
tools/qb-release-catalog.mjs
tools/qb-stable-admission.mjs
tools/qb-source-parsers.mjs
tools/qb-torrent-surface-parsers.mjs
tools/qb-torrent-fields-parser.mjs
tools/qb-detail-surface-parsers.mjs
tools/qb-action-surface-parsers.mjs
tools/qb-preference-semantics.mjs
tools/qb-catalog-evolution.mjs
tools/qb-webapi-evolution*.mjs
```

每个 admitted stable profile 可以提供：

```text
qB version / WebAPI version / source SHA
API actions
required/optional action parameters
Torrent request/response fields
Torrent states / filters
Details response fields
Preference getter/setter/type provenance
release evolution facts
```

这些 facts 进入 `W.ReleaseProfile` 后，再由正式 runtime owners 消费。UI caller 不应维护 patch-version table。

## 4. Capability model

统一 modes：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

`UNKNOWN` 只表示无法证明。对危险 write/action，`UNKNOWN` 必须在 QBClient 发出 HTTP 前被阻断。

不能因为版本更高就自动继承最新 capability；不能因为 major 改变就整体拒绝。

## 5. Read / Write / Action / Field 分离

不同语义必须独立证明，禁止用一个粗粒度 boolean 同时控制多个动作。

例如：

```text
Tags:
read/facet/filter != list != assign != create != delete

Category:
read/filter != list != create/delete != assign

Tracker:
read != add != remove != edit != reannounce

Settings:
read endpoint != write endpoint != per-Preference writable

Details:
properties/files/trackers/peers/webseeds reads independent
file priority / peer ban / tracker writes independent
```

## 6. Torrent field architecture

Torrent field chain：

```text
W.ReleaseProfile exact torrentInfoFields
-> W.TorrentFieldRegistry
   canonical field ID / metadata
   provenance mode
   effective availability
   saved preference merge
-> W.DataGrid layout/resize/persistence
-> W.Components rendering
-> Desktop/Mobile Columns + Sort
```

Saved preference 与 effective availability 分离。字段存在不自动证明 server-side sort/filter 语义。

## 7. Settings architecture

Settings 写能力是双层证明：

```text
W.ReleaseProfile proves app/setPreferences action
AND
W.SettingsSchema proves Preference setter/type/editability
-> W.QBClient.setPreferences
-> verification reread
```

任何一层 unknown/unproven 都不能进入 write payload。

## 8. Action parameter architecture

对于 Tracker、Torrent Creator、Files、Peers 等 action：

```text
exact release/source action
+ exact required/optional parameter facts
-> capability owner
-> canonical form generation
-> QBClient transport guard
```

如果 action 存在但参数 contract 无法证明，最终 write 状态仍应是 `UNKNOWN`/unavailable，而不是猜参数。

## 9. Virtual qB / Pages 架构

Virtual qB 与 Pages 使用同一份正式 `webui/**`，仅替换后端 transport/environment。

Pages artifact 必须绑定 source exact SHA：

```text
Virtual qB Pages Source
-> Virtual qB Pages build for dev exact SHA
-> virtual-qb-pages-site-<SHA>
-> deploy + live verify
-> main promotion reuses the same exact dev artifact
```

main promotion path不重新 build site。若 exact artifact 不存在，必须 fail closed。

## 10. Real-qB 架构

全版本真实 qB 验证不建立第二 compatibility owner：每个 runtime job都使用正式 `webui/**` 与同一套 capability-driven harness。

版本 expectation 来自 Frozen LKG / exact release profile；真实 qB runtime 负责验证 source facts 与产品语义在真实服务器上成立。

## 11. 架构变更纪律

涉及以下内容时必须同步检查 docs/tests/workflows：

```text
Current Owner 变化
source fact schema 变化
capability mode 变化
endpoint/action parameter 变化
Pages exact-SHA choreography 变化
candidate/promotion/release evidence 变化
```

删除一个 workflow、owner 或 contract 时，必须搜索所有引用并同批退役，避免出现“文件删了但测试仍要求其存在”的悬空依赖。
