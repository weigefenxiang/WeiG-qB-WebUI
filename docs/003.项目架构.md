# 003. WeiG qB WebUI 项目架构

Status: **Architecture authority for v0.3.3+**  
Repository: `weigefenxiang/WeiG-qB-WebUI`

> 本文负责“文件放在哪里、谁依赖谁、每层允许做什么”。视觉/交互看 `DESIGN.md`；产品硬规则看 `001.项目总方案.md`；兼容状态看 `002.兼容与实现状态.md`。

## 1. 架构目标

```text
qB API/version differences → QBClient + Capability + normalization
Torrent/business state     → Application Controller
DOM primitives             → Components/Core
Large-list mechanics       → VirtualList/DataGrid
Settings semantics         → SettingsSchema/Translations
Navigation/i18n bridge     → UX layer
Feature enhancements       → versioned runtime modules
Visual material            → CSS layers
Browser compatibility gate → deterministic qB fixtures + Chromium
Install/backup/rollback    → Installer
```

硬约束：

```text
UI / Runtime / Components
  × 不直接散落 qB 主版本特例
  × 不伪造不存在的 backend data/write API
  × 不把大型数据变成大型隐藏 DOM

QBClient
  ✓ 唯一 API contract / compatibility / normalization boundary
```

## 3. Runtime 依赖

`index.html` 直接加载 canonical base assets，并加载 `logs-v032.css/js` 作为 v0.3.2 的独立 Logs enhancement。v0.3.3 是验证层版本，没有修改这些 runtime bytes，因此它们继续使用 `?v=0.3.2` 作为内容 revision；只有实际 runtime asset 内容改变时才推进对应 cache-bust。

长期仍遵循：成熟的 versioned runtime 能力稳定后回收进 canonical modules，避免无限增长。

旧运行时层继续保留职责：

```text
spatial-v022.js  → Filter Shelf / Connection Dock / spatial composition
v030.js          → stable scroll / Transfer Dock / session graph / selection
v030.css         → compact empty state / Transfer surfaces / selection feedback
```

English 是 canonical source language；简体中文是正式维护语言，feature runtime 不建立 locale 分支业务逻辑。

## 4. `qb-client.js`

唯一 qB WebAPI 兼容边界。

### 4.1 语义桥

```text
4.x resume ↔ 5.x start
4.x pause  ↔ 5.x stop
4.x paused ↔ 5.x stopped
```

### 4.2 Logs contract

Capability：

```text
qB >= 4.1.0 → logs=true
```

Transport normalization：

```text
log timestamp milliseconds → seconds
log timestamp seconds      → seconds
```

Feature 层不再判断 qB 日志 timestamp 单位。

`logs(lastId)` 和 `peerLogs(lastId)` 保留 `last_known_id` 语义，供增量 UI 使用。

## 5. `logs-v032.js`

这是 Logs feature enhancement，而不是第二个 Torrent Controller。

Ownership：

```text
own QBClient instance for route-local log stream
main-log item buffer (max 5000)
lastId
severity filter
log search query
follow-latest state
log VirtualList instance
Auto / Compact / Max local UI preference
route-local poll timer
```

不拥有：

```text
Torrent catalog
Torrent filter/page/selection
qB global settings
connection credentials
```

### Data flow

```text
enter #/logs
   ↓
QBClient.detect()
   ↓
logs(-1)
   ↓
normalized rows
   ↓
VirtualList
   ↓
logs(lastId) only while route active
```

后台 tab 自动降低刷新频率；离开 Logs 路由停止该 poll timer。

## 6. `logs-v032.css`

实现 canonical Logs DataPage/DataPanel：

```text
Header
Toolbar
Panel
  Head
  Virtual viewport
  Empty state
  Status
```

Auto mode 使用 `minmax(0,1fr)` 占据剩余 workspace；Compact/Max 是用户显式模式。普通桌面路径不再依赖 `max-height:62vh`。

## 7. VirtualList ownership

主 Torrent VirtualList 仍由 Application Controller 管理；Logs v0.3.2 持有独立 `state.virtual`。

```text
Torrent virtual state != Logs virtual state
Data count != DOM count
```

主 Torrent VirtualList 的既有 container state contract 不变：`__weiggVirtualScrollTop` 继续保存轮询之间的用户 viewport，并保留 detached-spacer scroll guard。

这避免日志页覆盖主列表的 feature-local VirtualList reference，并为后续 app Controller 拆分提供明确方向。

## 8. v0.3 既有能力不得退化

v0.3.2 是在 v0.3.1 stable baseline 上增量增加 Logs，不替换既有能力：

```text
Transfer Graph ring buffer: MAX 900 samples
Global DL / UL limit
Alternative Speed mode
Compact Empty State
Rendered-row multi-select
Stable Torrent VirtualList viewport
```

因此 Logs 自己的 5000-row bounded buffer 与 Transfer Graph `MAX 900` 是两个独立的数据生命周期。

## 9. Canonical DataPanel 演进

v0.3.2 先用 Logs 验证统一模板。后续迁移顺序建议：

```text
Search results
RSS lists
Files
Peers
Trackers
```

迁移时复用设计 token、toolbar、Panel、VirtualList 和 responsive contracts；不要为每页重新发明固定高度容器。

## 10. Tests

### 10.1 API-contract fixtures

`tests/log-compat-v032.mjs` 守门：

```text
4.1.9 logs capability
4.6 logs capability
5.2 logs capability
millisecond → second normalization
second timestamp preservation
last_known_id incremental request
```

### 10.2 Browser fixture gate

`tests/browser-logs-v033.mjs` 使用真实 Chromium/Playwright 加载实际 `webui/private` runtime，并由本地 fixture server 模拟两种 qB WebAPI contract：

```text
qB 4.1.9.1 / API 2.2.1  → millisecond Logs
qB 5.2.0   / API 2.15.1 → second Logs
```

浏览器矩阵：

```text
390 × 844
1366 × 768
1920 × 1080
```

验证：

```text
normalized timestamp range
no horizontal overflow
adaptive panel geometry
Auto / Compact / Max
search
severity filter
incremental last_known_id polling
Follow latest OFF viewport stability
browser console/page errors
```

CI 的 `browser` job 必须在 `smoke` 成功后运行。Browser fixture PASS 是比静态 fixture 更高一层的确定性验证，但仍不等于真实远端 qB server certification。

## 11. Installer / security boundary

普通安装仍不修改 WebUI credentials。产品 `VERSION` 每次集成变化都推进；runtime cache-bust 只有在对应 runtime bytes 改变时推进，防止无意义的全量缓存失效，同时保证真实资源更新一定得到新 revision。
