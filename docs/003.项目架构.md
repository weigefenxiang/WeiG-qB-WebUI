# 003. 项目架构

Status: **current architecture / Current Owner boundaries**

本文件只记录长期有效的模块边界、Current Owner 与数据流，不维护 WeiG 版本历史。`webui/**` 是唯一正式产品；Current Owner 的最终 UI/design authority 仍以 `DESIGN.md` 为准。

## 1. 总体分层

正式产品链：

```text
qB official stable source
-> source extractors / admitted release facts
-> W.ReleaseProfile
-> canonical compatibility owners
-> W.QBClient
-> real qB WebAPI / WebApplication
-> UI / presentation
```

辅助验证链：

```text
same formal webui/**
-> W.QBClient
-> Virtual qB / simulator transport
-> browser / Pages / real-qB acceptance
```

Virtual qB、fixtures、Pages 与 tests 只能验证产品，不能反向定义产品语义。

一个 semantic purpose只能有一个 Current Owner。

正式 owner cutover必须同一 coherent change完成：

```text
new owner proven
-> all callers switch
-> contracts/tests update
-> DESIGN/docs update when public contract changes
-> old owner/helper/state/event/polling path retires
```

禁止 runtime alias、monkey patch、MutationObserver repair、post-render repair、第二业务状态或重复 polling。

## 3. Source Truth 层

Build-time source facts主要来自 `tools/qb-*` extractors、release catalog/admission、detail/action/preference/translation source parsers。

每个 admitted exact stable profile可以提供：

```text
qB version / WebAPI version / source SHA
API actions + parameters
Torrent states / filters / info fields
main Torrent native columns
Torrent Detail tabs / property labels / table columns
detail row source relation / derived dependencies
Preference getter/setter/type provenance
translator behavior / locale surface
release evolution facts
```

这些 facts进入 `W.ReleaseProfile` 后由 runtime owners消费。UI caller不得维护 patch-version truth table。

Unknown upstream shape必须 fail closed。Parser允许适配历史 source shape，但 relation必须由 exact source证明，不能按 UI key或字段名字“看起来相同”来猜。

## 4. Main Torrent table architecture

```text
W.ReleaseProfile exact torrentInfoFields + torrentTableColumns
-> W.TorrentFieldRegistry
   canonical field metadata/provenance
   effective availability
   saved preference merge
-> W.DataGrid
   header geometry/resize/reorder
-> W.Components row/card rendering
```

约束：

```text
source schema/default != user override
saved preference != current availability
field presence != server sort proof
pointermove != persistence
```

`W.VirtualList` 是主列表唯一 virtual/scroll projection owner。主列表横向滚动期间的 polling snapshot coalescing也必须留在这个 owner 内；不能通过 app-level第二滚动状态、DOM repair或 scrollLeft transform同步实现。

## 5. Torrent Detail architecture

### 5.1 Source schema

```text
exact qB properties markup / detail scripts
-> extractTorrentDetailUi()
-> W.ReleaseProfile.torrentDetailUi
-> canonical detail projection / W.QbUiEvidence
```

`torrentDetailUi` 可包含：

```text
tabs + source/context
property groups/fields + dataProperties
Files / Trackers / Peers / Web Seeds columns
column captions/source-context
dataProperties / source relation / derived dependency
```

UI row key不是 API field proof。比如 Tracker `peers` 只有 source证明后才能投影到 `num_peers`。

### 5.2 Shared table user state

```text
source detail columns
-> W.SharedColumns visibility/order/width override
-> W.ColumnInteraction pointer/touch lifecycle
-> shared detail table DOM
```

`W.SharedColumns` 不拥有第二 source schema；`W.ColumnInteraction` 不拥有第二 column state。

Detail header/body必须消费同一 column definition、width、padding/alignment projection。列设置、resize、reorder、持久化都应复用公共 owner；不得每个 Detail tab复制一套列系统。

### 5.3 Detail product convergence

当前架构已经提供 source-driven tabs/labels/columns、General property layout、shared column state等基础，但用户要求的“完全向 qB 原版语义收口”的产品改造尚未完成。具体七项只维护在 `docs/014`，避免这里变成第二 TODO。

未来实施时必须继续沿上述 owner扩展，而不是建立新的 DetailTabsV2、TrackerTableV2、PeerMenuV2 或手写翻译/字段映射层。

## 6. Settings / Locale / translation architecture

Settings写能力必须双层证明：

```text
W.ReleaseProfile proves setPreferences/action surface
AND
W.SettingsSchema proves specific Preference setter/type/editability
-> W.QBClient.setPreferences()
-> verification reread
```

Persisted locale只有：

```text
qB app/preferences.locale
```

qB-owned wording统一由 `W.I18n` 消费 exact source/context 与 source-bound translator route：

```text
native QBT_TR / qB translator
-> official QM where source-proven
-> exact official-TS bridge only for proven Alternative WebUI gap
```

完整 translation recovery bodies属于 build-time materialization，不是 browser release catalog 的业务数据。

`4.5.0 -> 4.6.4` Alternative WebUI不执行 document translation，是 source-proven hard boundary；不能因 QM存在就假设 native path可用。

## 7. Capability model

统一状态：

```text
NATIVE
NORMALIZED / ADAPTER
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

Read / write / action / field / parameter必须分离证明。例如：

```text
Tracker: read != add != remove != edit != reannounce
Tags: read/facet != list != assign != create/delete
Settings: endpoint read/write != per-Preference writable
Details: properties/files/trackers/peers/webseeds independent
```

Dangerous write 的 `UNKNOWN` 必须在 transport前阻断。由多个 upstream actions共同完成的 UI mutation必须 all-required proven，不允许部分 action成功形成 half-write。

## 8. Validation infrastructure boundary

```text
Source audit      -> exact upstream structural facts
Virtual qB        -> deterministic multi-profile product validation
Browser/Pages     -> hosted UI/runtime materialization behavior
Real qB           -> real daemon/runtime evidence
Candidate         -> release-grade source/product/browser/package chain
```

任何一层绿色都不能自动替代另一层。`SKIPPED != PASS`；旧 SHA evidence不证明新 SHA。
