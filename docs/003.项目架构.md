# 003. 项目架构

> 当前模块边界与产品兼容架构。最高优先级由 `001` / `010` 定义：`webui/**` 是唯一正式产品，正式 support floor 为 qB 4.1.0，当前与未来 official stable 自动适配是 P0；Virtual qB 是辅助验证层。

## 1. 总体边界

WeiG qB WebUI 是 qBittorrent Alternative WebUI。

正式产品主链：

```text
qB upstream official stable source
-> Source Extractors / exact qb-releases.json
-> W.ReleaseProfile
-> canonical product compatibility owners
-> W.QBClient / real qB WebAPI
-> UI / presentation
```

辅助验证链：

```text
same formal webui/**
-> W.QBClient
-> Native Service Worker
-> Virtual qB protocol/runtime
```

Simulator 只能模拟真实 qB 后端，不能替代产品 compatibility layer，也不能要求 `webui/**` 依赖 simulator-only API。

## 2. 产品 Compatibility Current Owners

```text
Exact stable source facts              W.ReleaseProfile
HTTP transport / endpoint invocation   W.QBClient
User-visible capability strategy       W.CapabilityRegistry
Settings semantics                     W.SettingsSchema
Torrent status/filter semantics        W.TorrentSemantics
Torrent filter presentation            W.TorrentFilterView

Responsive placement                   W.MobileAdaptive / W.SpatialRuntime
```

一个 semantic purpose 只能有一个 Current Owner。UI/presentation 不复制 qB/WebAPI 版本表。

## 3. Compatibility Layer 职责

产品 compatibility 把真实 qB 的历史和未来差异归一化成 WeiG canonical semantics。

负责：

- endpoint/action 名称映射；
- 参数重命名/格式差异；
- response/status/result normalization；
- state/filter canonicalization；
- exact source action/field/filter/parameter capability；
- 可靠的旧 API 组合/emulation；
- 基于 canonical data 的本地 derivation；
- read/write capability 分离；
- unsupported dangerous write 在 HTTP 前 fail closed。

原则：

```text
presentation
-> canonical product owner
-> source-proven adapter/normalization/derivation
-> real qB
```

而不是：

```text
presentation -> if qB4 ... else if qB5 ...
```

## 4. Capability resolution

长期统一状态：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

解析优先级：

```text
native
-> normalized / adapter
-> reliable local derivation
-> read-only when applicable
-> unavailable
```

未知 future semantics 不自动继承危险写能力；但也不能因为 major=6/7 就整体拒绝。

## 5. Read / Write 分离

禁止粗粒度：

```text
tags = true/false
```

应拆成：

```text
tags.read
tags.facet/filter
tags.assign
tags.create
tags.delete
```

同理：

```text
Category read/filter != mutation
Tracker read/add/remove/edit/reannounce 彼此独立
```

Phase B 已证明 qB4.1.0 的 `category/tags` 字段可以支持 read/facet/filter，而 native taxonomy/mutation 不存在时只关闭相应写能力。

## 6. Filters / Facets / Actions

Filters：

```text
native upstream filter
-> normalized alias
-> reliable local derivation from source-proven fields/states
-> unavailable
```

Facets：

```text
Tracker / Path / Category / Tags
```

Category/Tags facet 的产品可见性由 `categoryFacet/tagFacet` 决定，不由 native taxonomy endpoint 决定。

Actions：

```text
canonical WeiG action
-> W.ReleaseProfile exact source action resolution
-> W.QBClient
```

缺少 source/adapter 证据时不渲染危险动作，QBClient 再做 fail-closed。

```text

```

Runtime 由 `W.ReleaseProfile` 消费这些 facts。

## 8. Full Stable Product Matrix

Phase C 已把每个 official stable `>=4.1.0` 升级为正式 product target。

当前：

```text
65 / 65 stable profiles PASS
qB 4.1.0 -> 5.2.3
```

正式矩阵执行：

```text
W.ReleaseProfile
W.CapabilityRegistry
W.TorrentSemantics
W.SettingsSchema
W.QBClient
```

验证 Filters、Facets、Torrent actions、当前 columns prerequisites、Settings provenance、Search/RSS/Logs gating。

代表版本测试只负责快速反馈，不能替代 formal full-stable matrix。

## 9. Phase D — Future Stable Discovery / Automation

当前下一阶段：

```text
new official stable discovered
-> exact source profile
-> upstream added/removed diff
-> Full Stable Product Compatibility Matrix
-> product gap => CI fail
-> compatible => green
```

目标不是预先写：

```text
if major == 6
if version >= 6.0
```

而是让 future stable/new major 自动进入同一事实链和产品验证链。

Phase D 还应增加 architecture guard，扫描 `webui/private/scripts/**`，阻止 scattered qB version-if 回归；版本知识只允许存在于集中 resolver/adapter/exception owner。

## 10. qB4.0.x / WebAPI v1

当前：

```text
Legacy WebAPI v1 Adapter = FUTURE OPTIONAL
```

不进入当前 CI/full-stable matrix，也不占当前 Phase。

未来如果明确支持，只通过集中 Transport/Adapter 映射到 canonical semantics，禁止 presentation/module 内双路维护 v1/v2。

## 11. Fields / Columns / Settings / Other Surfaces

Phase E 计划建立字段 provenance：

```text

normalized
derived
unavailable
```

当前 17 个正式 columns prerequisites 已经通过 65 stable matrix，因此这是未来扩展/架构硬化，不是当前 blocker。

Phase F 继续细化：

```text
Settings
Search
RSS
Logs
Torrent Details
Files
Peers

```

Settings 保留现有 source-proven getter/setter/type + fail-closed 架构，不推倒重写。

## 12. Virtual qB — auxiliary only

```text
formal W.QBClient
-> Service Worker transport adapter
-> simulator Transport Contract
-> protocol router + Endpoint Contract
-> QBSimulatorEngine / services
-> IndexedDB world
```

Endpoint/Transport Contract 是 simulator 内部 historical semantics owner，不代表产品 compatibility 已完成。

Virtual qB / browser fixtures 是强辅助证据，但不能替代真实 qB binary/server LIVE。

## 13. Validation hierarchy

```text
source truth / evolution facts
-> direct product contracts
-> Full Stable Product Compatibility Matrix
-> representative Virtual qB / Hosted Chrome
-> representative real qB binary/server
-> promotion-time frozen evidence
```

普通 dev push、candidate 和重型 upstream evolution audit 的触发分层见 `006.发布与晋级流程.md`。

## 14. Development discipline

- 正式开发 `dev`；未经明确授权不动 `main`；
- 写前/ref update 前 fresh-read exact dev；
- ref 更新只允许 `force:false` fast-forward；
- 每个大阶段完成后 STOP、复盘、更新 docs；
- 正式 `webui/**` 变化按版本规则 bump 产品 VERSION；
- simulator/docs/tests/workflow-only 变化不 bump；
- red test 先确认真实产品/upstream truth，再修正确 owner；
- 禁止为了 stale fixture/test 变绿回退正确产品行为。
