# 003. 项目架构

> 当前模块边界与 Current Owner。`DESIGN.md` 只登记已经落地的 ownership authority；本文件描述同一套当前架构、兼容 truth hierarchy 与 Phase D 收口规则。

## 1. 总体边界

WeiG qB WebUI 是 qBittorrent Alternative WebUI。正式产品通过 canonical `W.QBClient` 调用 qB WebAPI；Virtual qB Lab 只在产品 HTTP/WebAPI 边界以下模拟 qB，不替换产品业务 owner。

正式 WebAPI v2 支持范围：**qBittorrent 4.1.0 -> 最新官方 stable**。当前 source-derived stable matrix 已验证到 qB 5.2.3；当前 audited semantic ceiling 是 **WebAPI 2.15.1**。qB 4.0.x 属于旧 WebAPI v1；未来如需要，必须以独立 Legacy WebAPI v1 Adapter 接入，不在 v2 router 中维护双协议分支。

## 2. Current structural truth owners

Build-time：

- `tools/qb-source-parsers.mjs`：Preference getter/setter/type provenance；
- `tools/qb-torrent-surface-parsers.mjs`：Torrent filter 与 `torrents/info` 参数；
- `tools/qb-release-catalog.mjs`：official stable exact release profile；
- catalog quality/evolution contracts：source evidence 与演化完整性。

Runtime：

`W.ReleaseProfile` 绑定 exact stable profile，并提供 Preference descriptor、API action presence、Torrent filter/info parameter surface、qB4/qB5 action/filter mapping。

Exact version 不在 catalog 时只能 conservative fallback；不得伪造 source provenance 或 certified 状态。

## 4. Virtual protocol current architecture

```text
product W.QBClient
-> Native Service Worker / transport adapter
-> Transport Contract for HTTP/transport evolution
-> upstream-gates for structural endpoint existence
-> protocol router + Endpoint Contract for same-endpoint semantics
-> QBSimulatorEngine / Scheduler / Policy / services
-> IndexedDB world
```

职责必须保持正交：

```text
source catalog / upstream-gates
  -> endpoint/preference/filter/parameter exists?

Endpoint Contract
  -> this existing endpoint behaves how for this WebAPI revision?

Transport Contract
  -> HTTP authentication/header/proxy transport behaves how?

router / auxiliary-router
  -> parse request, dispatch, invoke core, construct Response

core/world owners
  -> deterministic state mutation and domain projection
```

## 5. Endpoint Contract — Current Owner

稳定职责文件：

```text
simulator/protocol/endpoint-contracts.js
```

公共接口：

```text
resolveEndpointContract(profile, path)
```

它负责已审计 same-endpoint semantic evolution，例如：

- required/renamed parameters；
- single vs multi/all selectors；
- response field presence/shape；
- HTTP status/no-op behavior tied to endpoint semantics；
- mutation semantics；
- conditional projection flags。

它不负责：

- structural endpoint existence；
- route dispatch；
- generic HTTP transport/auth/proxy rules；
- world mutation implementation；
- Preference schema；
- Torrent filter taxonomy；
- UI capability。

B1 dormant interface 与 B2 atomic caller cutover 均已完成。Phase D 已继续迁移多个历史边界，包括 `sync/maindata` lifecycle、tracker/editTracker、parseMetadata、add result/status、login/missing endpoint response、peer host_name 等。

未知/unclassified semantic revision 必须 fail closed；未来版本不得因为“更高”而自动继承 2.15.1 最后已知行为。

## 6. Transport Contract — Current Owner

稳定职责文件：

```text
simulator/protocol/transport-contract.js
```

Transport Contract 专门拥有 WebAPI/qB patch 的 HTTP transport evolution，当前至少包括：

- WebAPI 2.15.0 Basic Auth acceptance；
- qB 5.2.2 `X-Forwarded-Host` 只有 reverse-proxy support enabled 时才可信。

这些边界由 Service Worker/transport adapter 消费；router/core 不得自己保存 transport version policy。

同一个 WebAPI revision 内的 qB patch-level 行为变化必须用 exact qB version/evidence 表达，不能强行塞成 WebAPI revision boundary。

## 7. Structural owners remain orthogonal

Endpoint/Transport Contract 上线不替代这些 owner：

- `apiActions/upstream-gates`：endpoint existence；
- Preference source pipeline：getter/setter/type/provenance；
- Torrent surface parser/catalog：filters + `torrents/info` parameters；
- `W.SettingsSchema`：产品 Settings semantics；
- `W.TorrentSemantics`：产品 Torrent status/filter semantics。

禁止因为一个 contract 能“判断版本”就吸收其它层的 truth。

## 8. OWNER-CUTOVER migration rule

新 owner 不允许和旧 owner 长期双活。

### B1 — Dormant validation — COMPLETE

```text
new contract exists
-> direct isolated contracts
-> production path remains single-owner
```

### B2 — Atomic cutover — COMPLETE

```text
all affected callers -> canonical contract
+ remove superseded version branches
+ remove obsolete helpers/fallback path
+ repo-wide ownership guards
+ DESIGN.md registers Current Owner
```

禁止 shim、runtime alias、feature flag、old/new fallback bridge。

Phase D 扩展已有 owner 时继续沿用同一纪律：先 evidence/classification，再完整 lifecycle，一次切 owner，不制造第二套 truth。

## 10. Phase D architecture

Phase D 只消费 ledger 中已证明的 `MISSING`：

```text
upstream evidence
-> classify owner
-> implement one canonical behavior
-> direct/runtime/ownership tests
-> ledger transition
-> exact-SHA CI + full upstream + Pages live
```

不能用“相邻版本已经有 contract”推断本条也覆盖；不能在 audit 中边发现边把随机 `apiAtLeast()` 塞回 caller。

已经完成的代表性 cutover：

- `sync/maindata.categories/free_space_on_disk/use_subcategories`；
- tracker timing/status 5/6；
- `editTracker` 204；
- `parseMetadata` ordered array；
- missing endpoint text + login 204/401；
- `torrents/add` structured result + 200/202/409；
- Basic Auth；
- peer `host_name`；
- X-Forwarded-Host reverse proxy gate；
- qB 5.2.1 C++ API result-buffer lifetime -> `NOT_APPLICABLE`。

## 11. Future-proof strategy

### Future stable discovery

```text
new official tag
-> exact source profile
-> WebAPI revision/spine comparison
-> supplement/evolution audit
```

### Future semantic revision

如果 revision 高于 audited ceiling 或出现未分类 delta：

```text
fail closed
-> collect upstream evidence
-> add ledger classification
-> establish canonical owner
-> only then restore PASS
```

Endpoint Contract/Transport Contract 的公共调用边界应隐藏内部数据来源，未来可从 audited table 升级为 generated semantic truth，而 caller 无需改变。

## 12. Settings / Torrent / Capability boundaries

- Preferences：继续归 `W.SettingsSchema + exact Preference descriptors`；Endpoint Contract 不复制 getter/setter/type truth。
- Torrent filter/info parameters：继续归 source-derived Torrent catalog + `W.TorrentSemantics`。
- UI capability：继续归 `W.ReleaseProfile + W.CapabilityRegistry`。
- `W.QBClient`：正式产品真实 qB transport，不维护 Virtual Lab historical semantic policy。

## 13. Desktop / Mobile

Desktop/Mobile 只改变 placement/geometry，不改变 semantic owners。Sidebar/Drawer、Selection、Transfer、Settings、Search 均共享同一业务状态链。

## 14. Artifact / evidence

Pages 与 Release candidate 使用同 shape source-derived `qb-releases.json`。CI、Pages LIVE、candidate、artifact 全部绑定 exact Git SHA；VERSION 是产品版本，不代替 SHA identity。

Formal Pages 以 triggering source SHA、exact checkout、`WEIGG_PAGES_SOURCE_SHA`、`WEIGG_EXPECTED_SIMULATOR_SHA`、deployed metadata 为 source identity；workflow UI 的 `main head_sha` 不能替代这些证据。

## 15. Development discipline

- `dev` 是正式开发分支，未经明确授权不动 `main`；
- 写前/ref update 前 fresh-read exact `dev`；
- ref 只允许 `force:false` fast-forward；
- 大阶段完成后停下复盘，由用户拍板；
- production truth 与 stale tests 冲突时先读 runtime/upstream evidence，不能为让测试绿而回退正确语义；
- docs/tests/workflow-only 改动不升级产品 VERSION；只有正式 `webui/**` 产品内容变化才升级。
