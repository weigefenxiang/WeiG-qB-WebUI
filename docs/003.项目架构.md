# 003. 项目架构

> 当前模块边界与正式产品兼容架构。`webui/**` 是唯一正式产品；support floor 为 qBittorrent 4.1.0；Current Owner 最终以 `DESIGN.md` 为准。

## 1. 总体边界

正式产品链：

```text
qB upstream official stable source
-> Source Extractors / generated exact stable facts
-> W.ReleaseProfile
-> canonical product compatibility owners
-> W.QBClient / real qB WebAPI
-> UI / presentation
```

辅助验证链：

```text
same formal webui/**
-> W.QBClient
-> Native Service Worker / Virtual qB transport
-> simulator Endpoint/Transport Contract
-> IndexedDB world
```

Virtual qB 只能模拟真实 qB 后端；不能反过来定义正式产品语义。

### Formal Product Compatibility

Runtime owners消费 machine-readable facts，输出 canonical WeiG semantics。Presentation 不保存 qB patch/major version table，也不 self-probe feature availability。

### Virtual qB

Simulator / Pages 是辅助 evidence。若 Simulator/test 与 exact source/upstream product truth 冲突，先确认 source truth；正确产品行为优先，修 stale simulator/test。

## 4. Capability model

统一 modes：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

优先级：

```text
native
-> normalized / adapter
-> reliable old-API composition
-> reliable local derivation
-> read-only when applicable
-> unavailable
```

future `UNKNOWN` 只关闭无法证明的具体 capability，尤其危险写操作；不能按 major/version 整体拒绝，也不能自动继承 latest semantics。

## 5. Read / Write / Action / Field 分离

禁止粗粒度 boolean 把不同语义绑死。典型拆分：

```text
Tags:
read/facet/filter != list != assign != create != delete

Category:
read/filter != list != create/delete != assign

Tracker:
read != add != remove != edit != reannounce

Settings:
read endpoint != write endpoint != per-Preference writable

Details:
properties/files/trackers/peers/webseeds read independent
file priority / peer ban / tracker writes independent
```

## 8. Phase F surface provenance contract

### 8.1 Endpoint/action provenance

每个 touched surface 必须能回答：

```text
read action exists?
write action exists?
required/optional parameters?
response fields available?
future profile exact or UNKNOWN?
```

Certified exact profile：按 source facts判定 `NATIVE/UNAVAILABLE`。

Future/unadmitted profile：无法证明具体 action/parameter 时为 `UNKNOWN`；尤其 write 不得发 HTTP。

### 8.2 Settings two-level write proof

```text
app/setPreferences source action writable
AND
W.SettingsSchema descriptor proves setterPresent + writeType + typeAgreement + writable
```

两层都真才进入 payload。Getter-only、missing setter、unknown endpoint、type mismatch、structured-unproven 都不能 blind write。

Settings 已有的 schema/renderer/UI primitives 保持 Current Owner，不推倒重写。

### 8.3 Search / RSS / Logs

Route availability 与子 action必须分开。

RSS historical correction：upstream qB 4.1.0 已声明 core RSS actions，因此不能继续用 `WebAPI >=2.1.0` 作为最终 availability truth。

Search core actions 从 qB 4.1.4 起 source-proven；Logs main/peers 从 qB 4.1.0 起 source-proven。

### 8.4 Details

目标：

```text
properties/files/trackers/peers/webseeds
-> exact read capability

filePrio/removeTracker/editTracker/banPeer/...
-> separate write/action capability

response field
-> exact field availability
```

禁止：

```text
unsupported/error -> []
```

必须区分：

```text
UNAVAILABLE/UNKNOWN
real empty
runtime/HTTP error
```

### 8.5 Action parameter provenance

QBClient form 必须优先由 `W.ReleaseProfile.actionDescriptor()` / `apiActionParameters` 组装，避免 version-threshold form guessing。

`editTracker` 是 Phase F 的代表案例：旧 stable 与 5.2.x 参数契约不同，必须按 exact source parameters 发送。

## 12. Source parser boundary

Phase F pre-start audit 已证明现有 catalog 具有本阶段首批所需：

```text
apiActions
apiActionParameters
preferenceDescriptors
torrentPropertiesFields
torrentTrackerFields
torrentFileFields
torrentWebSeedFields
```

所以第一版不改 source parser/discovery/evolution。若实施中 exact facts 缺失，不能在 runtime 猜；必须停下补 source truth，并升级到 heavy source/evolution audit。

## 13. Proof boundary

Repo-wide ownership/absence/uniqueness：

```text
target exact SHA
-> complete relevant tree
-> complete tracked blob/file contents
```

Search/snippet 只能 discovery。

Git identity/hash proof必须读 canonical Git index/blob bytes，不能用 Windows CRLF working-tree bytes。

## 14. Validation hierarchy

```text

```
