# 003. 项目架构

> 当前模块边界与产品兼容架构。最高优先级由 `001` / `010` 定义：`webui/**` 是唯一正式产品，正式 support floor 为 qB 4.1.0，当前与未来 official stable 自动适配是 P0；Virtual qB 是辅助验证层。

## 1. 总体边界

WeiG qB WebUI 是 qBittorrent Alternative WebUI。

正式产品主链：

```text
qB upstream official stable source
-> Source Extractors / generated exact stable facts
-> W.ReleaseProfile
-> canonical product compatibility owners
-> W.QBClient / real qB WebAPI
-> UI / presentation
```

辅助验证链：

```text
same formal webui/**
-> W.QBClient
-> Native Service Worker
-> Virtual qB protocol/runtime
```

Simulator 只能模拟真实 qB 后端，不能替代 product compatibility layer，也不能要求 `webui/**` 依赖 simulator-only API。

## 2. 产品 Compatibility Current Owners

Current Owner 最终以 `DESIGN.md` 为准；当前 compatibility 主链包括：

```text
Exact stable source facts              W.ReleaseProfile
HTTP transport / endpoint invocation   W.QBClient
User-visible capability strategy       W.CapabilityRegistry
Settings semantics                     W.SettingsSchema
Torrent status/filter semantics        W.TorrentSemantics
Torrent filter presentation            W.TorrentFilterView
Torrent field registry                 W.TorrentFieldRegistry
Torrent query/page/sort state          W.LibraryController / W.AppState
Selection/actions                      W.Selection / ActionRegistry
Torrent row/card DOM                   W.Components
Transfer runtime/history               W.TransferRuntime
Search/RSS/Logs business owners        existing canonical feature modules
Responsive placement                   W.MobileAdaptive / W.SpatialRuntime
```

一个 semantic purpose 只能有一个 Current Owner。新增 planned/dormant owner 不得提前登记为 Current Owner；正式切换必须 atomic cutover，删除 superseded runtime path。UI/presentation 不复制 qB/WebAPI 版本表。

## 3. Compatibility Layer 职责

产品 compatibility 把真实 qB 的历史和未来差异归一化成 WeiG canonical semantics。

负责：

- endpoint/action 名称映射；
- 参数重命名/格式差异；
- response/status/result normalization；
- state/filter canonicalization；
- exact source action/field/filter/parameter capability；
- 可靠的旧 API composition/emulation；
- 基于 canonical bulk data 的可靠 local derivation；
- read/write capability 分离；
- unsupported / unknown dangerous write 在 HTTP 前 fail closed。

原则：

```text
presentation
-> canonical product owner
-> source-proven adapter/normalization/composition/derivation
-> real qB
```

而不是：

```text
presentation -> if qB4 ... else if qB5 ... else qB6 ...
```

## 4. Capability resolution

长期统一状态：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

解析优先级：

```text
native
-> normalized / adapter
-> reliable old-API composition
-> reliable local derivation
-> read-only when applicable
-> unavailable
```

future `UNKNOWN` 只关闭无法证明的具体 capability，尤其危险写操作；不能因为 major/version 变大就整体拒绝，也不能因为版本更高就自动继承当前 latest semantics。

## 5. Read / Write 分离

禁止粗粒度：

```text
tags = true/false
```

应拆成：

```text
tags.read
tags.facet/filter
tags.list
tags.assign
tags.create
tags.delete
```

同理：

```text
Category read/filter != mutation
Tracker read/add/remove/edit/reannounce 彼此独立
Settings getter-only != editable
```

Phase B 已证明 qB4.1.0 的 `category/tags` 字段可以支持 read/facet/filter，而 native taxonomy/mutation 不存在时只关闭相应写能力。

## 6. Filters / Facets / Actions

Filters：

```text
native upstream filter
-> normalized alias
-> reliable local derivation from source-proven fields/states
-> unavailable
```

Facets：

```text
Tracker / Path / Category / Tags
```

Category/Tags facet 的产品可见性由 read/facet capability 决定，不由 native taxonomy endpoint 粗粒度决定。

Actions：

```text
canonical WeiG action
-> W.ReleaseProfile exact source action resolution
-> W.QBClient
```

缺少 source/adapter evidence 时不渲染危险动作，QBClient 再 fail closed。

## 9. Phase D — Incremental Future Stable Admission / Last Known Good — DONE

Phase D 新增 build/release-side ownership，不新增第二套 runtime compatibility owner。

LKG ownership：

```text
tests/fixtures/qb-release-catalog.lkg.json   frozen complete historical facts
tools/data/qb-stable-lkg.json               LKG identity/hash/admission manifest
tools/qb-stable-admission.mjs               discovery + admission transition owner
tools/qb-release-catalog.mjs --base-catalog new-stable-only source extraction
tools/qb-product-capability-diff.mjs         formal product capability diff
```

Future stable admission：

```text
verify LKG
-> lightweight remote stable-tag comparison
-> no new stable: stop
-> new stable: source checkout only then
-> source-extract only fresh profiles
-> preserve all frozen profile contents
-> audit floor + new refs
-> product gate floor + previous LKG + new profiles
-> repository contracts / architecture guard
-> upstream/product diff
-> all PASS
-> fresh dev ref check
-> safe fast-forward catalog + manifest only
```

失败时：

```text
PENDING_REVIEW
candidate rejected
LKG unchanged
```

这属于 release/admission 策略，不是 runtime fallback bridge。

历史全量 product regression 只在通用 product compatibility owner / matrix contract 变化时运行，直接读取 frozen LKG，不重新 source-extract old profiles。

Stable discovery / source parser / evolution tooling 变化进入 heavy full-history audit；普通 docs/UI/CSS/installer/test-only 不应触发该 audit。

### Architecture guard

`tests/compat-architecture-contract.mjs` 的 scope 是：

```text
webui/private/scripts/**
```

它在目标 exact checkout 上递归读取全部 `.js` 完整文件，而不是用 code search/snippet 证明 absence。`release-profile.js` 是集中版本知识 owner；已有 legacy branches 用 reviewed blob SHA 冻结，改变时必须显式迁移/复核。

### Repo-wide proof discipline

任何 repo-wide ownership / absence / uniqueness 结论必须：

```text
target exact SHA
-> complete relevant tree identity
-> complete blob/file contents where semantic inspection is required
```

Code search/snippet 只能用于 discovery，旧 SHA、截断结果、局部片段和推测不能充当 repo-wide final proof。

## 11. Phase E — Torrent Fields / Columns provenance — APPROVED / IN PROGRESS

Approved start base：

```text
d300b52475a4b3f2349bbfe148400596e1911ee9
```

启动前复盘确认：DESIGN 当前已经把 `W.TorrentFieldRegistry` 记为 Torrent field registry/preferences 的 Current Owner，但 exact runtime 的 field metadata 仍重叠存在于：

```text
ui.js         -> 17-field FIELDS + W.TorrentFieldRegistry + mobile preference
core.js       -> W.DataGrid.defaults 的重叠 field metadata
components.js -> common field renderer branches
```

Phase E 禁止新增第四套表。目标是 formal owner convergence：

```text
W.ReleaseProfile exact torrentInfoFields
-> W.TorrentFieldRegistry single semantic field/provenance owner
-> NATIVE / NORMALIZED / DERIVED / UNAVAILABLE / UNKNOWN
-> W.DataGrid layout/persistence only
-> W.Components DOM/special visual renderer only
-> Desktop/Mobile Columns + Sort consume same effective registry
```

必要时允许 `READ_ONLY`，但本 Phase 不为凑状态枚举而制造无语义状态。

Current Owner 切换规则：

```text
planned torrent-fields.js may exist dormant/test-only
-> no runtime caller and no DESIGN Current Owner claim before cutover
-> formal cutover must atomically move all callers
-> retire superseded ui.js/core.js field ownership paths
-> update DESIGN.md in the same product commit
```

Field availability 与 saved preference 分离：某字段在当前 release `UNAVAILABLE/UNKNOWN` 时，不破坏性删除用户保存配置；未来 capability 恢复后可重新生效。Desktop/Mobile 共享同一 semantic field state，只允许 presentation 差异。

DERIVED 只能来自已有 canonical bulk data，不允许新增 per-torrent compatibility request、额外 polling 或 presentation probe。Field 存在不自动等于 server-side sort 可用；Sort provenance 独立证明。

当前正式 17 个 fields 在 frozen 65 stable 的 source facts 中全部存在，因此正式 Phase E matrix 预期全部解析为 `NATIVE`；`NORMALIZED / DERIVED / UNAVAILABLE / UNKNOWN` 由 synthetic contracts 验证通用规则，不得冒充真实 historical qB facts。

Phase E 产品实现修改 `webui/**` 后必须 bump patch VERSION 到 `0.3.59`。

## 13. Virtual qB — auxiliary only

```text

-> Service Worker transport adapter

```

Endpoint/Transport Contract 是 simulator 内部 historical semantics owner，不代表产品 compatibility 已完成。

Virtual qB / browser fixtures 是强辅助证据，但不能替代正式 product compatibility 或真实 qB binary/server LIVE。

## 14. Validation hierarchy

```text
source truth / evolution facts
-> direct product contracts
-> frozen/all-stable Product Compatibility Matrix
-> representative Virtual qB / Hosted Chrome
-> representative real qB binary/server
-> promotion-time frozen evidence
```

Phase E 属于通用 compatibility owner 变化：正式实现必须跑 frozen LKG historical product regression，并让 full-stable matrix 真正加载 runtime `W.TorrentFieldRegistry` provenance owner。只有 source parser/catalog/evolution tooling 变化才触发 heavy upstream evolution audit。

不同风险层的触发规则见 `006.发布与晋级流程.md`。

## 15. Development discipline

- 正式开发 `dev`；未经明确授权不动 `main`；
- 写前/ref update 前 fresh-read exact dev；
- ref 更新只允许 `force:false` safe fast-forward；
- repo-wide proof 绑定目标 exact SHA 完整 tree/blob/file；
- 每个大阶段完成后 STOP、复盘、更新 canonical docs；
- 正式 `webui/**` 变化按版本规则 bump 产品 VERSION；
- simulator/docs/tests/workflow/tools-only 变化不 bump；
- red test 先读完整失败日志并确认真实产品/upstream/source truth，再修正确 owner/test/evidence；
- 禁止为了 stale fixture/test 变绿回退正确产品行为或增加 workaround architecture。
