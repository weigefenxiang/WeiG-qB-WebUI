# 003. WeiG qB WebUI 项目架构

Status: **v0.3.7 Semantic Ownership 3.6**  
Repository: `weigefenxiang/WeiG-qB-WebUI`

> 本文定义运行时层次、数据流、模块边界与 ownership。视觉/交互总规则以根目录 `DESIGN.md` 为最高 authority；兼容、测试、发布边界分别见 `002`、`004`、`005`、`006`。

## 1. 总体数据流

```text
qB WebAPI
  ↓
QBClient + capability normalization
  ↓
Canonical business/data owner
  ├─ AppState / query/catalog
  ├─ SettingsState
  ├─ Selection
  ├─ TorrentSemantics
  ├─ TransferRuntime
  └─ SessionController
  ↓
source renderer / semantic events
  ↓
canonical components + layout owners
  ↓
responsive/polish presentation
```

核心边界：

```text
business owner produces state
presentation owner consumes state
DOM mutation is not an event bus
Data count != DOM count
```

## 2. Owner map

```text
QBClient                     endpoint / HTTP / qB 4.x-5.x capability
AppState                     torrent query/catalog/paging/poll lifecycle
SettingsRenderer/State       Settings source DOM + save flow
ControlRegistry              semantic Settings control choice
TorrentSemantics             Private/PT classification and compatibility evidence
Selection                    selected hashes + selection interaction
Selection.actions            one Torrent ActionRegistry
TransferRuntime              transfer samples + maindata telemetry snapshot
Transfer                     stats dialog + rate editor + status capsule
TorrentFieldRegistry         desktop/mobile field registry
LayoutRuntime                DataGrid/dialog geometry
MobileAdaptive               responsive shell presentation
SpatialRuntime               facet shelf/connection dock presentation
UiSystem                     shared adaptive UI behavior
PolishRuntime                status/tooltip visual polish only
Brand/AmbientMark            brand asset and motion
SessionController/Gate       logout/auth/BFCache state machine
```

同一语义不得出现第二个 Set、第二个 action list、第二个 Transfer dialog、第二个 telemetry client 或第二个 Settings renderer。

## 3. API ownership boundary

`QBClient` 是 endpoint/兼容 adapter，不意味着任何模块都能自行创建 client 并轮询。

允许持有 qB API 生命周期的业务 owner：

```text
app.js                 torrent/app polling
settings.js            settings read/save lifecycle
selection.js           command dispatch / all-matching scan
transfer.js            transfer telemetry + rate APIs
session.js             auth/session state machine
```

Presentation-only 模块禁止拥有独立 qB client/poll：

```text
responsive.js
spatial.js
layout.js
polish.js
ux.js
```

如果 Presentation 需要新数据，先把数据纳入正确 business owner 的 snapshot/event，再消费；不能“为了显示一个数字”另开一条 API 定时器。

## 4. Explicit runtime lifecycle

v0.3.7 最终 runtime 不使用 `MutationObserver` 做 ownership/repair。跨模块同步通过明确事件：

```text
app.js
  weigg:library-state     query/catalog/list state completed
  weigg:status-state      connection/status updated
  weigg:route-state       route/view changed

settings.js
  weigg:settings-render   canonical Settings DOM completed

transfer.js
  weigg:transfer          transfer sample captured
  weigg:maindata          normalized server telemetry refreshed

shared
  weigg:languagechange
  weigg:configchange
```

消费者只重算自己的 presentation，不重新接管源 DOM。

禁止：

```text
observe body → 找到后来出现的节点 → 重包/搬行
observe Select → 自动升级
observe Settings → 修布局
observe DataGrid → 抢 resize owner
observe status text → 推断 business lifecycle
CSS-order observer
```

## 6. Settings architecture — Clean Cut

Canonical pipeline：

```text
qB/WeiG preference
  ↓
PreferenceSchema
  ↓
ControlRegistry
  ↓
SettingsRenderer
  ↓
SettingsSection
  ↓
SettingsGrid
  ↓
SettingRow
  ├─ SettingCopy
  └─ SettingControlSlot
```

源 renderer 一次生成最终 DOM；`weigg:settings-render` 表示这一次渲染完成。

Wide：

```text
SettingsGrid = repeat(2,minmax(0,1fr))
```

Narrow：一列。

Ordinary row：

```text
span = 1
SettingCopy left axis
SettingControlSlot right axis
```

只有 multiline/composite/list/table/large editor 可以由 schema 明确 `span=full`。

迁移完成后不保留：

```text
.settings-control old geometry
settings-row--canonical bridge
centered FormRail
Settings MutationObserver
language/timezone post-render injector
native Select upgrade requirement
CSS-order/setTimeout repair
```

## 7. Canonical Select ownership

Visible Select 由源 owner 明确调用：

```text
W.Components.selectControl(options)
```

Settings、Transfer、Selection、mobile sort、page-size 等都应直接创建 canonical Select；不扫描 DOM 去寻找 native `<select>` 再升级。

Native/static placeholder 只有在文档 bootstrap 明确需要时可存在，并且不得同时作为第二个 live presentation owner。

## 8. Selection architecture

`W.Selection` 唯一拥有：

```text
selected Set
range anchor
select page / invert page
select all matching / invert all matching
Ctrl/Cmd toggle
Shift range
Ctrl/Cmd+A
Escape clear
checkbox state
Toolbar enable state
```

普通交互：

```text
row/card non-interactive click -> selectOnly
Ctrl/Cmd click                 -> toggle
Shift click                    -> range
title/detail button            -> open detail only
checkbox                       -> toggle
right-click                    -> canonical ActionRegistry
mobile long press              -> canonical ActionRegistry
mobile More / top More         -> same ActionRegistry
```

移动 checkbox/select hit-area 至少 44×44 CSS px。

`app.js` 不得再有 `selected:new Set()`；任何入口不得建立自己的 action list。

## 9. Private / PT compatibility architecture

`W.TorrentSemantics` 输出：

```text
PRIVATE_PT
PRIVATE
PT
PUBLIC
UNKNOWN
```

### 9.1 Explicit Private metadata

如果 qB 返回 `private` / `is_private` / 等价 authoritative field，直接使用。

### 9.2 Metadata pending

`has_metadata=false` 或 `metaDL` / `forcedMetaDL`：

```text
Private state = UNKNOWN
```

不能因为 DHT/PeX/LSD 信息暂时不可用就判 Public。

### 9.3 qB 4.1.9.1

上游 `release-4.1.9.1` 的 `TorrentsController::getStickyTrackers()` 明确生成：

```text
** [DHT] **
** [PeX] **
** [LSD] **
```

源码只在 `torrent->isPrivate()` 为 true 时，把同一条本地化 `privateMsg` 写进三个 row 的 `msg`。Public torrent 即便全局关闭 DHT/PeX/LSD，`status` 会 disabled，但 `msg` 仍为空。

因此 fallback：

```text
三个 pseudo row 都存在
+ 三个 msg 都非空
+ 三个 msg 完全相同
=> Private

三个 msg 都为空
=> Public

缺失/混合
=> Unknown
```

不硬编码英文 `This torrent is private`，也不把 `status=0` 当 Private 证据。

### 9.4 PT

`ptTrackers` 只按 hostname 补充 PT 识别：

```text
Private = qB authoritative semantics
PT      = user-configured tracker-domain semantics
```

两者可以组合成 `PRIVATE_PT`。

## 10. TransferRuntime telemetry architecture

`W.TransferRuntime` 是 Transfer telemetry 唯一 owner。

```text
existing QBClient.getTransferInfo()
  ↓ wrap once
sample history (max 900)
  ↓
weigg:transfer

one bounded sync/maindata lifecycle
  ↓
server_state normalization
DHT / peers / free space
  ↓
TransferRuntime.snapshot()
  ↓
weigg:maindata
```

关键规则：

1. 不创建第二个 `getTransferInfo()` polling loop。
2. maindata 使用一个 owner、一个 rid、一个并发折叠 promise、一个有界周期。
3. Responsive 的 Storage 只读 snapshot/event，不创建 QBClient。
4. Stats dialog 可以触发 owner 的显式 refresh，但不再自己建立平行 metadata owner。
5. ALT mode 不建立常驻第二轮询；在 init/open/visibility/用户动作处显式同步。

Stats 信息顺序：

```text
Session downloaded | Session uploaded | DHT / Peers
Global upload       | Global download | Free space
```

Rate editor：

```text
[NORMAL | ALT] [unit]
Upload | Download
```

## 11. StatusDock / shell geometry

`css/layout.css` 唯一拥有 desktop statusbar shell 几何：

```text
grid-template-areas:
"torrent storage transfer connection message"
```

Transfer/Storage/Connection 使用明确 `grid-area`，不依赖 append 顺序和 CSS auto placement。

`polish.css` 只能做 tone、tooltip、pulse 等视觉，不定义 shell grid。

## 12. Responsive architecture

`W.MobileAdaptive` 可以：

```text
安装 page scroll contract
移动 toolbar 到 mobile command bar
fit text/meta
同步 facet summary
调整 VirtualList row height
paint Storage snapshot
```

它不可以：

```text
new QBClient()
getMainData()
setInterval API polling
重建 Selection/Transfer/Settings state
DOM MutationObserver reclaim
```

Phone 是同一业务 runtime 的 adaptive presentation。

## 13. Layout / Spatial / Polish / UX boundaries

### LayoutRuntime

DataGrid resize、dialog normalization。由 source lifecycle 显式调用/同步；不观察 body 等节点出现。

### SpatialRuntime

Facet shelf / connection dock。只消费 library state；不观察 nav 去猜变化。

### PolishRuntime

状态 tone、connection visual、tooltip 等 final polish；不拥有 Statusbar geometry，不装饰 ActionRegistry DOM 来补业务语义。

### UX

翻译/搜索上下文同步；不修 Settings，不通过全 body observer 重新翻译每次 DOM 变动。Canonical owner 完成状态后通过 semantic event 同步。

## 14. Session architecture

```text
Header Logout
→ SessionController.logout()
→ QBClient.logout()
→ POST auth/logout
→ QBClient.probeSession()
```

只有 protected probe 证明会话无效，才 commit logout：

```text
stop private work
clear volatile state
set logout guard
lock shell
location.replace(public root)
```

qB localhost/subnet auth bypass 若让 probe 仍成功：状态为 `auth-bypass`，不是 logged-out。

Back/BFCache `pageshow.persisted` 或 logout guard 存在时 fail-closed。

## 15. Brand / About

Header Brand mark/name 是两个 Home target，但复用同一 `Brand` / `AmbientMark` owner。About 使用 `BrandIdentity + FactRow`，不复制 logo/motion engine，也不把 metadata 当 editable SettingRow。

## 16. Progress ownership

`css/progress.css` 唯一负责 Torrent progress transition/flow/sweep。100% 停止装饰运动，Reduced Motion 同时尊重系统偏好和 WeiG 设置。

## 17. Zombie-code policy

历史实现由 Git history 保存。发现旧模块时：

```text
inventory unique capability
→ migrate useful capability into canonical owner
→ remove duplicate implementation
→ remove loader/alias
→ delete obsolete file
```

绝不因为“还有一点功能”永久保留整个旧 owner。

## 18. Systemic failure modes

```text
1. 同语义多个 DOM/state owner。
2. Presentation 自己开 QBClient/timer 获取显示数据。
3. Source DOM 后由 Observer 修复。
4. versioned runtime 鼓励叠新层而不是替换 owner。
5. Native Select + custom Select 双 owner。
6. Selection title/row/checkbox 点击语义互相抢事件。
7. ActionRegistry 在右键/More/long-press 分叉。
8. qB4 用 DHT disabled status 误判 Private。
9. metadata pending 被错误判 Public。
10. Transfer/info 与 maindata 各自有独立轮询 owner。
11. statusbar 依赖 DOM 顺序 auto-flow。
12. Polish 接管 shell geometry 或业务 tone。
```

固定修复顺序：

```text
owner
→ upstream/API evidence
→ data/schema boundary
→ source component
→ semantic lifecycle
→ layout
→ remove old owner
→ static/browser regression
```

## 20. LIVE and Release boundary

真实 exact-SHA qB 4.1.9.1 + 5.2.x LIVE 是 promotion gate。任何 code/test/doc commit 都产生新 exact candidate；旧 SHA 的 CI/LIVE PASS 不继承。

`main` 只在 exact candidate 通过 CI + real LIVE 且用户明确授权后晋级。
