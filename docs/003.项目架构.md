# 003. 项目架构

> 当前模块边界 + 已批准的下一阶段目标架构。`DESIGN.md` 只登记已经落地的 Current Owner；本文件可以同时描述 Approved Target Owner，但必须明确状态。

## 1. 总体边界

WeiG qB WebUI 是 qBittorrent Alternative WebUI。正式产品通过 canonical `W.QBClient` 调用 qB WebAPI；Virtual qB Lab 只在产品 HTTP/WebAPI 边界以下模拟 qB，不替换产品业务 owner。

正式 WebAPI v2 支持范围：**qBittorrent 4.1.0 -> 最新官方 stable**。qB 4.0.x 属于旧 WebAPI v1；未来如需要，必须以独立 Legacy WebAPI v1 Adapter 接入，不在 v2 router 中维护双协议分支。

## 2. Current structural truth owners

Build-time：

- `tools/qb-source-parsers.mjs`：Preference getter/setter/type provenance；
- `tools/qb-torrent-surface-parsers.mjs`：Torrent filter 与 `torrents/info` 参数；
- `tools/qb-release-catalog.mjs`：official stable exact release profile；
- catalog quality/evolution contracts：source evidence 与演化完整性。

Runtime：

`W.ReleaseProfile` 绑定 exact stable profile，并提供 Preference descriptor、API action presence、Torrent filter/info parameter surface、qB4/qB5 action/filter mapping。

Exact version 不在 catalog 时只能 conservative fallback；不得伪造 source provenance 或 certified 状态。

## 3. Current product owner map

```text
Exact stable source facts              W.ReleaseProfile
HTTP transport / endpoint invocation   W.QBClient
User-visible capability policy         W.CapabilityRegistry
Settings semantics                     W.SettingsSchema
Settings presentation/write workflow   settings.js + canonical controls
Torrent status/filter semantics        W.TorrentSemantics
Torrent filter DOM                     W.TorrentFilterView

Torrent row/card DOM                   W.Components
Transfer runtime/history               W.TransferRuntime
Theme                                  W.Theme

```

一个 semantic purpose 只能有一个 Current Owner；presentation/caller 不得复制版本表、状态 regex、轮询器或业务 state。

## 4. Virtual protocol current state

```text
product W.QBClient
-> Native Service Worker
-> simulator/protocol/router.js + auxiliary-router.js
-> QBSimulatorEngine / Scheduler / Policy / services
-> IndexedDB world
```

当前 endpoint existence 已可由 exact profile `apiActions` + `upstream-gates.js` fail closed；但“同 endpoint 在不同 WebAPI revision 的行为差异”仍有一部分散落在 router/core caller 的 `apiAtLeast()` / version branches 中。

这是当前主要待收口的 ownership gap。

## 5. Approved Target Owner — Endpoint Contract

目标新增稳定职责文件：

```text
simulator/protocol/endpoint-contracts.js
```

公共接口保持窄而稳定：

```text
resolveEndpointContract(profile, path)
```

责任划分：

```text
apiActions / upstream-gates
  -> endpoint exists?

Endpoint Contract
  -> endpoint behaves how for this WebAPI revision?

router / auxiliary-router
  -> parse request, execute resolved contract, form HTTP response

core/world owners
  -> state mutation / deterministic domain behavior
```

Endpoint Contract 只返回 semantic facts，例如：

- required/renamed parameters；
- single vs multi/all selector；
- response field presence/shape；
- status-code behavior；
- no-op/mutation semantics；
- conditional projection flags。

它**不**负责 route dispatch、HTTP Response construction、world mutation、Preferences schema、Torrent filter taxonomy 或 UI capability。

## 6. Future-proof interface

Router 永远只依赖 `resolveEndpointContract(profile, path)`，不依赖内部 truth 存储方式。

第一阶段内部可以是 audited canonical table；未来可以替换为：

```text
upstream changelog parser
+ source semantic parser
+ generated semantic catalog
```

调用方接口不变。未知 semantic revision 不得静默继承；未来 audit 必须 fail closed。

## 7. OWNER-CUTOVER migration rule

新 owner 不允许和旧 owner长期双活。

### B1 — Dormant validation

```text
endpoint-contracts.js exists
-> direct isolated contracts
-> no production caller switches yet
```

此时旧 runtime path 仍是唯一 active owner。

### B2 — Atomic cutover

一旦 direct contract 通过，下一变更必须：

```text
all affected callers -> Endpoint Contract
+ remove superseded apiAtLeast/version branches
+ remove obsolete helpers/files/tests/docs
+ repo-wide zero-reference audit
+ DESIGN.md register new Current Owner
```

禁止 shim、runtime alias、feature flag、old/new fallback bridge。

职责正交的 `apiActions/upstream-gates`、Preference parser、Torrent surface parser 继续存在，不因新 owner 被误删。

## 8. Full WebAPI Evolution Audit architecture

Audit 按 WebAPI chronology 从 2.0.x 到 latest stable，逐条分类：

```text
NEW_ENDPOINT / REMOVED_ENDPOINT
PREFERENCE / TORRENT_SURFACE
PARAMETER_CHANGE / RESPONSE_CHANGE
STATUS_CHANGE / MUTATION_CHANGE
TRANSPORT_CHANGE / NOT_APPLICABLE
```

先生成完整 classification ledger，再集中修 `MISSING`。不得在 audit 中边发现边把 version if 随机塞回 router。

未来计划工具：

```text
tools/qb-webapi-evolution-audit.mjs
```

它消费 upstream changelog/stable catalog/Endpoint Contract/source-derived catalogs，输出 `SOURCE_DERIVED / CONTRACT_COVERED / NOT_APPLICABLE / MISSING / UNCLASSIFIED`。`UNCLASSIFIED` 最终必须成为 hard failure。

## 9. Settings / Torrent / Capability boundaries

- Preferences：继续归 `W.SettingsSchema + exact Preference descriptors`；Endpoint Contract 不复制 getter/setter/type truth。
- Torrent filter/info parameters：继续归 source-derived Torrent catalog + `W.TorrentSemantics`。
- UI capability：继续归 `W.ReleaseProfile + W.CapabilityRegistry`。
- QBClient：只负责真实 qB transport，不维护 simulator historical semantic policy。

## 10. Desktop / Mobile

Desktop/Mobile 只改变 placement/geometry，不改变 semantic owners。Sidebar/Drawer、Selection、Transfer、Settings、Search 均共享同一业务状态链。

## 11. Artifact / evidence

Pages 与 Release candidate 使用同 shape source-derived `qb-releases.json`。CI、Pages LIVE、candidate、artifact 全部绑定 exact Git SHA；VERSION 是产品版本，不代替 SHA identity。
