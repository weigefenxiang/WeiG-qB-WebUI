# 003. 项目架构

> 当前模块边界与产品兼容架构。最高优先级由 `001` / `010` 定义：`webui/**` 是唯一正式产品，support floor 为 qB 4.1.0；当前与未来 official stable 自动适配是 P0；Virtual qB 是辅助验证层。

## 1. 总体边界

正式产品主链：

```text
qB upstream official stable source
-> Source Extractors / generated exact stable facts
-> W.ReleaseProfile
-> canonical product compatibility owners
-> W.QBClient / real qB WebAPI
-> UI / presentation
```

辅助验证链：

```text
same formal webui/**
-> W.QBClient
-> Native Service Worker
-> Virtual qB protocol/runtime
```

Simulator 只能模拟真实 qB 后端，不能替代 product compatibility layer，也不能要求 `webui/**` 依赖 simulator-only API。

## 4. Capability resolution

长期统一状态：

```text
NATIVE
NORMALIZED
DERIVED
READ_ONLY
UNAVAILABLE
UNKNOWN
```

优先级：

```text
native
-> normalized / adapter
-> reliable old-API composition
-> reliable local derivation
-> read-only when applicable
-> unavailable
```

future `UNKNOWN` 只关闭无法证明的具体 capability，尤其危险写操作；不能按 major/version 整体拒绝，也不能假定高版本继承当前 latest semantics。

## 5. Read / Write 分离

禁止粗粒度：

```text
tags = true/false
```

应拆成：

```text
tags.read
tags.facet/filter
tags.list
tags.assign
tags.create
tags.delete
```

同理：

```text
Category read/filter != mutation
Tracker read/add/remove/edit/reannounce independent
Settings getter-only != editable
```

Phase B/C 已证明 qB4.1.0 的 `category/tags` bulk fields 可支持 read/facet/filter，而 native taxonomy/mutation 不存在时只关闭相应写能力。

## 6. Filters / Facets / Actions

Filters：

```text
native upstream filter
-> normalized alias
-> reliable local derivation from source-proven fields/states
-> unavailable
```

Facets：

```text
Tracker / Path / Category / Tags
```

Category/Tags facet 可见性由 read/facet capability 决定，不由 taxonomy endpoint 粗粒度决定。

Actions：

```text
canonical WeiG action
-> W.ReleaseProfile exact source action resolution
-> W.QBClient
```

缺少 source/adapter evidence 时 UI 不暴露危险动作，QBClient 再 fail closed。

### 7.2 Field provenance

```text

NORMALIZED  trustworthy central alias/source mapping
```

当前 frozen 65 stable 的 17 fields 由 runtime owner 实际解析为全部 `NATIVE`；非-native modes 通过 synthetic contracts 验证机制，不冒充 historical facts。

### 7.3 Saved preference / effective availability

```text

```

```text

```

Desktop/Mobile 共用 semantic state，只允许 presentation geometry 差异。

Field presence 不证明 server-side sort semantics；Sort provenance 独立。

## 10. Architecture guard / proof boundary

Repo-wide ownership/absence/uniqueness proof 固定要求：

```text
target exact SHA
-> complete relevant tree identity
-> complete blob/file contents for semantic inspection
```

`tests/compat-architecture-contract.mjs` 扫描 `webui/private/scripts/**` tracked `.js`；Git identity/proof 读取 canonical Git index/blob bytes，避免 Windows checkout 的 LF/CRLF transformation 影响 blob identity。

Code search/snippet 只用于 discovery；旧 SHA、截断结果、局部片段、working-tree transformed bytes 和推测不能作为 repo-wide final proof。

## 14. Development discipline

- 正式开发 `dev`；未经明确授权不动 `main`；
- 写前/ref update 前 fresh-read exact dev；
- candidate 只以 fresh base 为唯一 parent；
- ref 更新只允许 `force:false` safe fast-forward；
- `webui/**` 变化才 bump VERSION；docs/tests/tools/workflow-only 不 bump；
- red gate 先读完整日志、找 root cause，再修正确 owner/test/evidence；
- 禁止为了 stale fixture/test 回退正确产品行为或增加 workaround architecture；
- 每个大 Phase 完成后 STOP、更新 canonical docs、等待下一阶段确认。
