## 6. 验证与证据规则

- CI红灯必须先读完整日志，先区分真实产品回归与 stale test/fixture/docs/simulator gate；owner优先级是 upstream/source/canonical runtime truth > stale expectation。
- readiness必须等待真正影响断言的 semantic owner + visible state收敛，并 bounded fail closed；`releaseIdentity()`、capability flag、DOM attached、`document.readyState`任一单独都可能只是中间态。
- product/runtime completion以最近一次真正改变产品的 final exact SHA及其适用 gate为准。历史 checkpoint不能跨实现改动复用。
- ordinary CI 必须与 exact-SHA Pages materialization/build/deploy/live evidence共同闭环；正式 UI变化还需要适用 browser semantic evidence。
- Pages build/deploy SUCCESS但 required live verify FAILURE => Pages整体未闭环。
- Workflow内部 final-tree验证是重要证据，但不能自动替代新 product commit的 external push/dispatch evidence。
- qB-owned文字必须 source-proven；dangerous Settings write必须 exact source proof + Preference writable proof + reread verification。
- heavy/manual Current Stable Locale Matrix、Real qB Full Frozen Matrix、promotion/main/tag/Release不得自动触发。
- `SKIPPED != PASS`。
