## 5. 本轮复盘：需要避免的坑

### 5.1 先用真实 materialization证明，不要只信 focused contract

本轮 focused contracts最初都绿，但真实 Pages materialization把 `qb-settings-native.txt` 做成约29.34 MB，超过 qB 10 MiB static-file hard limit。最终通过 bridge leaf-value 全局去重降到3,829,474 B。

教训：runtime slimming/packaging任务必须看真实 materialized bytes、manifest与qB静态文件边界，不能只看“结构上已去重”。

### 5.2 不要为了过 gate 恢复旧 owner或放宽 assertion

本轮出现过 stale docs/CI/Pages assertions。正确处理是先确认 canonical runtime truth，再同步 stale gate；不能恢复 `qb-settings/`、双 loader、旧 translation route字段，也不能把5/10 MiB限制调大来掩盖体积问题。

### 5.3 docs authority必须同步，不要让旧概述误导下一位 AI

`docs/014` 是唯一 mutable handoff/TODO authority；`docs/002` 是 current facts；`docs/001` 只保存高层 current project state。阶段完成后要把长期事实写回 owner docs，并清掉旧的“下一阶段/尚未实现”描述，否则下一位 AI 会把已完成内容重新当 TODO。

### 5.4 Exact-SHA evidence不能跨提交偷用

旧 SHA的CI/Pages PASS不证明新 SHA。Docs-only change也要按 classifier和Pages representability判断 current SHA的适用 evidence；不要因为改的是文档就宣称旧 final SHA自动等价于当前 HEAD。

### 5.5 GitHub connector大文件写入要做 blob identity硬校验

本轮 `i18n.js` 大文件通过长 base64参数直接写入时发生过工具层截断，错误 blob没有挂到 branch。最终用独立 verify workflow生成并核对 exact Git blob SHA，再组正式 commit。

教训：大 UTF-8文件不得凭“看起来相同”落库；必须用 canonical Git blob hash/runner验证字节身份。临时验证设施不能进入正式 dev历史，验证分支/ref用完必须恢复。

### 5.6 不要把 translator family数量当最终 runtime route数量

`2908 native / 616 mandatory bridge`描述的是 source-proven translator family hard-boundary层；最终 runtime还可能因为exact historical TS/QM wording差异把某些 native-capable route降为 exact bridge。不要为了追某个统计数字删 bridge或弱化 exact historical wording。
