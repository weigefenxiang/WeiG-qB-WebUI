## 6. 累计复盘：需要避免的坑

### 6.1 用户现场失败与实际 UI 问题优先于“旧 gate 绿了”

用户指出的真实交互问题必须先验证 runtime/页面行为，再看 contract 是否 stale。旧 test 与已确认 source/runtime truth 冲突时更新 test，不恢复错误实现。

### 6.2 Detail toolbar/context 只能有一个 action owner

Toolbar、blank-area context menu、row context menu可以有不同 presentation entry，但 action truth必须汇聚到同一 source/provenance executor。Copy 是 local browser action时不要伪造 WebAPI endpoint；Rename/Priority 属于 transport write时必须 exact provenance后才允许出现。

### 6.3 Sticky header 必须解决真实视觉穿透，不做 scroll repair

表格 row 穿透 header 是 surface opacity/stacking 问题，不是 scrollLeft 同步问题。正确修复是 semantic opaque sticky surface；不要引入 transform、MutationObserver 或第二 scroll owner。

### 6.4 General native-like layout不能变成第二 schema

General 三组 label/value 排列只是 source-generated `propertyLayout` 的 presentation。Desktop/Mobile可改变列数，但 source order、field binding与 qB-owned copy不能复制到第二手写 registry。

### 6.5 Source-proven local action与 transport action要分开

Local Copy使用 clipboard；qB mutation进入 `W.QBClient`。不要为了“统一”把本地 action伪装成 HTTP，也不要因为表格已有字段就猜测 qB write能力。

### 6.6 Exact Pages/materialization验证不能省略

Focused contracts全绿不等于 materialized hosted runtime正确。涉及 `webui/**` 的正式产品 change必须看 exact Pages build/deploy/live verification；0.3.88 已完成这一闭环。

### 6.7 不要为 stale contract改坏正确 runtime

0.3.88 首轮 CI 的 workspace assertion落后于新 canonical selection-context signature。正确做法是确认 current plan/runtime truth后同步 test；禁止恢复旧签名、重复 action owner或放宽 source/write safety。
