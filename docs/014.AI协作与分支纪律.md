## 3. 0.3.102 本轮完成内容

### 3.1 Locale bootstrap product root cause

历史 Pages run `35037003377` 中，zh-CN browser session 期望 qB persisted locale 为 `zh_CN`，实际保持 `en`。根因不是 `W.I18n` 显示层，而是 bootstrap 在 Settings compatibility/write proof 尚未加载时就调用 `SettingsSchema.isWritable('locale', ...)`；fail-closed 结果被误当作“locale 不可写”，并把 bootstrap 错误标记为已完成。

0.3.102 在 `webui/private/scripts/session.js` 修正 owner 边界：只有当 browser locale 与当前 qB locale 不同、确实需要判断写权限时，才 lazy-load Settings compatibility proof，再执行 source-proven `locale` writable check。写入后仍必须 reread `app/preferences` 确认 persisted truth；失败不得用 DOM/localStorage/W.I18n 伪装成功。

### 3.2 Browser feedback stale selector

历史 ordinary CI run `35036992447` 的 `browser-feedback.mjs` 仍寻找旧 standalone：

```text
[data-setting-key="listen_port"] input
```

当前 canonical renderer 已将 Listen port + Random 合并到一个 compound SettingRow。测试已改为 current semantic DOM：

```text
[data-setting-key="listen_port_compound"] input[type="number"]
```

没有为了旧 selector 恢复退休 DOM，也没有删除 Settings write + reread 断言。

### 3.3 Pages preferences-anchor stale row model

旧 `tests/pages-live-preferences.mjs` 默认“一 upstream Preference = 一 `data-setting-key` DOM row”。这与 current Settings layout owner 冲突：Speed 的四个 source Preferences：

```text
schedule_from_hour
schedule_from_min
schedule_to_hour
schedule_to_min
```

由一个 canonical `schedule_range` compound row 表示。

修复过程保持 source truth：

1. 先从 `SettingsSchema.group()` 得到 upstream routed source keys。
2. 显式 `await SettingsSchema.loadCompatibility()`，确保测试与 renderer 消费同一 Settings layout contract。
3. 按 `SettingsSchema.layout('speed.scheduleRange')` 计算 source Preference -> canonical row projection。
4. 继续逐项验证四个 source Preferences 存在于 `app/preferences`、被 `schedule_range` 的 semantic metadata 表示，并由 compound controls 实际承载。
5. Anchor 测试本身不切换 Settings route，因此 compound row readiness 只要求 DOM `attached`，不虚构“当前视图必须 visible”的额外产品要求。

最终 exact Pages run `35042417653` 的 `verify preferences-anchor`、`verify locale-bootstrap`、全部 10 个 preference shards、core/services/release-profile/mobile 等 required live lanes 均 SUCCESS，整个 run SUCCESS。

### 3.4 Ordinary browser readiness closure

final tests-only checkpoint 前，ordinary CI 曾暴露 `browser-sidebar-capability-visual.mjs` 的固定 100ms readiness flake：qB5 动态列表已经开始生成 `title` metadata，而 canonical `PolishRuntime` 的 event + `requestAnimationFrame` scrub 尚未完成，导致最终“只允许四个 Header Tooltip opt-in、全局 `[title]/[data-tooltip]` 必须为零”的断言过早执行。

没有删除或放宽最终断言。测试仅把固定 `waitForTimeout(100)` 改为等待真正的 semantic readiness：
