## 1. 第一原则：永远先 dev

用户明确要求：**不要跳过 dev，直接改 main。**

任何修改，包括“只是文档”“只是 workflow”“只是测试修复”，都先进入：

```text
dev
```

禁止：

```text
直接在 main update_file/create_file/delete_file
直接在 main 创建 commit
直接 cherry-pick 到 main
直接 update_ref main 作为日常修改方式
force push main
为了省 CI 时间把 fix 只放 main
```

正确流程：

```text
修改 dev
-> 验证 dev
-> 修复仍然在 dev
-> 冻结 final dev exact SHA
-> 建立同 SHA evidence
-> formal promotion
-> main fast-forward 到 validated dev SHA
```

即使某一刻 `main == dev`，下一次改动仍然从 dev 开始。

## 4. 但不要误判为“v0.3.71 已可发布”

`ba8ee498...` **没有同 SHA 的 Real qB Full Frozen Matrix (G-FM) 65/65 run**。

本轮曾直接把 main fast-forward 到 `ba8ee498...`，main Pages 也成功，但这没有经过 `Promote validated dev to main` workflow 对 G-FM 的强制检查。

因此永久记住：

```text
candidate PASS != G-FM PASS
main == dev != formal promotion gate complete
main Pages PASS != tag/release permission
```

而本轮 docs/test commit 会继续推进 dev，所以 future release 应从新的 final dev SHA 重建完整 evidence，不应给旧 `ba8ee498...` 直接补 tag。

## 6. Installer / supply-chain 当前事实

### Stable Release identity

Linux/Windows installer：

```text
resolve Release metadata
-> exact tag
-> tag commit SHA
-> tag-pinned asset URL
-> SHA256SUMS
-> package VERSION == tag version
-> package GIT_SHA == tag commit
```

不要放宽这条链。

### Dev distribution

Linux/Windows Dev 只消费 Pages exact-SHA materialized distribution：

```text
current dev SHA
== downloads/dev/GIT_SHA
== package GIT_SHA
```

禁止 raw-source fallback。

## 8. Pages 当前架构与坑

唯一部署 owner：

```text
Virtual qB Pages Source
-> workflow_dispatch
-> Virtual qB Pages
```

不要恢复 default-branch `workflow_run` deployment trigger。

Concurrency：

```text
virtual-qb-pages-dispatch
cancel-in-progress: false
```

deploy 前必须 fresh-head gate。

旧 run 如果 branch 已前进，应在 deploy 前 fail closed，而不是让旧 deploy 覆盖新 SHA。

Live catalog 等待：

```text
catalogError || (catalogReady && !catalogBusy)
```

不要在 `catalogReady` 第一次变 true 时立刻要求 busy=false。

### 8.1 应用语言不是浏览器 locale

WeiG 的持久化语言 truth owner 是：

```text
qB app/preferences.locale
```

`browser.newContext({locale:'zh-CN'})` 只改变浏览器 locale，不保证当前 qB preference 已经是 `zh_CN`，也不能作为“页面必须输出中文”的测试依据。

2026-09-12 docs-only Pages 验收曾出现：

```text
actual: Page 1 / 100 · 50 per page
stale assertion: 必须匹配中文 “第 1 / 100 页 · 每页 50”
```

产品 pager 语义是正确的；错误在 acceptance 把浏览器 locale 当成应用 persisted locale。

正确测试规则：读取实际 `W.I18n.getLocale()` / qB preference，再验证对应语言的 pager；不要通过 retry 把这个确定性前置假设跑成偶然绿色，也不要为了测试修改产品语言 ownership。

## 9. Candidate mock 的历史坑

曾出现生产 installer 正确、candidate mock 错误：真实 GitHub commit API 的 pretty JSON 中 `sha` 是独立行，而 mock 返回单行 `{"sha":"..."}`，导致 parser 报：

```text
Release v0.3.71 did not resolve to a valid commit SHA.
```

正确修法是让 mock 模拟真实 API shape；**不要修改生产 identity parser 去迁就错误 mock**。
