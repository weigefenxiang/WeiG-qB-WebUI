## 8. CI / Validation Health

当前 validation policy：

```text
< 3 min      正常
3–5 min      记录耗时，判断是否天然可分片
> 5 min      必须输出 progress/timing；可独立任务优先 matrix/shard
> 10 min     天然可分片全量任务原则上不得继续单 runner
> 30 min     无合理原因和持续进度 => 停止并查根因/换验证设计
```

默认 independent full-version work：

```text
bounded shards
-> max-parallel: 16
-> 65 releases通常约16 shards × 4–5 releases
-> per-shard artifact
-> strict same-SHA aggregate
```

#1856 从 push 到完成约3m44s，16个 Preferences shard全部 SUCCESS，说明当前 source gate 已回到预算内。未来若某任务再次超过3–5分钟，先判断能否安全16-way分片；若不能分片则要求阶段进度与耗时。超过30分钟不得“再等等”，必须定位 parser/checkout/hydration/browser/runtime根因或选择更合适的验证方案。

Aggregate 必须来自同一 exact SHA + 同一 Frozen expected set/catalog identity，并证明：

```text
executed == expected
missing == []
duplicate == []
unexpected == []
FAIL == 0
BLOCKED == 0
```

`SKIPPED != PASS`。旧 SHA、cancelled/superseded run、其它 SHA shard都不能证明 current exact SHA。
