## 2. 第一原则：所有开发都先 dev

```text
dev   唯一 normal development / fix / docs / validation 入口
main  validated promotion result
```

禁止：

```text
直接在 main update/create/delete file
直接在 main 创建日常 commit
日常 cherry-pick/merge 到 main
force push dev/main
为了省 CI 时间把 fix 只放 main
未经用户批准触发 Candidate
未经用户批准 promotion / tag / GitHub Release
```

正确流程：

```text
fresh-read dev
-> 在 dev 完成 coherent change
-> normal validation
-> 红灯只修 root cause
-> 用户明确决定是否进入最终验证/发布
```

即使某时 `main == dev`，下一次修改仍从 `dev` 开始。

## 4. 0.3.78 当前产品事实

正式 DataGrid继续消费 exact qB source-derived：

```text

```

exact native schema拥有 column keys/source order/defaultVisible/defaultWidth/dataProperties；用户 visibility/order/width只是 override。

Columns dialog仍由 `app.js -> openColumns()` 负责 checkbox、↑/↓、Desktop dialog drag 与 Android 360ms long-press drag。Header reorder和Columns dialog只是同一 state owner的不同入口，禁止第二 layout owner、MutationObserver或post-render repair。

### 4.2 Transfer

Transfer仍复用同一 `transfer/info` poll与 `W.TransferRuntime` bounded history。

Desktop Statusbar与Mobile Drawer compact capsule显示 realtime rates：

```text
↓ <dl_info_speed>   ↑ <up_info_speed>
```

完整 Transfer dialog chart-bottom仍保留 realtime + session totals 语义对。

Display smoothing默认10s；可选 `Raw / 3 / 5 / 10 / 15 / 20 / 30 s`。当前window使用absolute-time bucket增量聚合：active bucket可变化，completed bucket完成后冻结；正常poll不再反复重算已完成历史桶。它只是bounded derived display cache，不是第二history owner。

### 4.3 Native WebUI return locale

唯一 persisted language truth：

```text
qB app/preferences.locale
```

`W.SessionController` 的 temporary-locale/root/final-locale handoff只用于切换 qB WebUI root后重新加载正确 translator；最终 persisted truth仍只有目标 locale。禁止恢复 `previousLocale`、exit restore或第二语言 state。

### 4.4 Tracker URL

Torrent Details的Tracker display/edit直接使用 qB `torrents/trackers` API exact `url`；不得再用 `normalizeTracker()` 截断或泛化详情URL。Facet/domain分类用途与详情 exact URL owner必须区分。

## 7. 写入与 ref 操作纪律

每轮正式 mutation batch：

```text
fresh-read dev exact HEAD
-> 读取相关 exact files/tree
-> 准备 coherent exact diff
-> validate
-> 再 fresh-read dev 做 race check
-> safe fast-forward force:false
```

如果 dev 已移动，停止旧 ref update并基于新 HEAD重建。旧 SHA不能作为新 SHA proof。

### 7.1 Mutation API 绝不能当 probe

这一条必须比以前更严格执行：

```text
不要用 create_branch 测权限/参数
不要用 create_file/update_file 测branch是否存在
不要用 create_tree 测tree schema
不要用 create_commit 测commit schema
不要创建no-op VERSION commit
不要为了拿schema/错误信息制造blob/tree/commit
```

即使一个对象没有挂到ref，Git database mutation仍然不是“只读探测”。先用 `list_resources` / read-only fetch/search读取tool schema；如果写工具参数不确定，停止并先确认，不要试写。

本轮曾发生 mutation-probe / placeholder 类错误，产生过 orphan Git objects，并短暂产生后立即删除的占位文件。最终 current tree没有保留该占位文件，`main`/tag/Release均未受影响；但这些操作本身就是需要避免的反例。下一位AI不要追、merge、rebase这些orphan objects，也不要自行“清理”历史。

## 9. 红灯处理纪律

遇到 CI/Pages 红灯：

```text
读完整失败 job/log
-> 分类 product bug / source misunderstanding / stale test/docs / workflow / infrastructure / identity
-> 修 root cause
```

优先级：

```text
qB upstream/source truth
-> canonical runtime truth
-> real runtime evidence
-> tests/fixtures/docs/simulator expectation
```

禁止：

```text
删正确 assertion只为绿灯
FAIL改SKIP
扩大skip
吞runtime/source error
把正确产品恢复成旧DOM/旧owner
same-SHA rerun确定性bug
```

只有明确 transient runner/CDN/GitHub infrastructure fault才适合同SHA rerun。

## 10. Pages / Dev installer 注意事项

Dev installer只消费 materialized Pages distribution，并验证 embedded identity；禁止 raw-source fallback。

Pages Source必须同时考虑：

```text
current push diff
published materialized payload SHA -> current dev history
```

如果中间存在 Pages-relevant产品变化，后续docs-only push不能让旧payload永久停留。`pages-source.yml` 的materialization relevance matcher只有一个 canonical owner；不要复制第二份匹配表。

Docs-only/public-payload-irrelevant follow-up可以由classifier证明无需重新materialize，但不能把旧SHA Pages evidence变成新SHA release-grade evidence。
