## 4. 已确认的 source/runtime facts

### 4.1 Settings

Canonical QBClient已有：

```text
GET  /api/v2/app/preferences
POST /api/v2/app/setPreferences
```

因此当前实例 Preference keys/values可以直接从 qB读取。

但：

```text
GET返回某key
!=
证明该key可安全POST写回
```

现有 exact Preference getter/setter/type/writable provenance必须保留；unknown scalar/structured value不能因为 runtime减肥而 blind write。

### 4.2 Translation不是 WebAPI

当前不能假设存在：

```text
/api/v2/app/translations
/api/v2/app/translate
/api/v2/app/qm
```

qB原生 WebUI翻译是 WebApplication server-side document translation：

```text
QBT_TR(Source)QBT_TR[CONTEXT=...]
-> qB WebApplication
-> Qt translator for current locale
-> translated HTML/JS sent to browser
```

WebAPI只可以告诉我们 `preferences.locale`，不能直接把 qB executable 内置的完整 translation dictionary/QM暴露给浏览器。

### 4.3 Alternative WebUI translation root

当前 qB source behavior不能假设 Alternative WebUI会自动借用 built-in `:/www/translations`。

启用 Alternative WebUI后 active WebUI root切到用户配置目录；对应 translator load/path behavior按该 active root/source family处理。Alternative root缺少需要的 QM时，不能把“built-in qB明明有同语言QM”当作自动 fallback能力。

关闭 Alternative WebUI返回 built-in WebUI后，则 root回到 qB自身资源；删除/精简 WeiG自己的 translation assets不应破坏 built-in WebUI 自己的语言资源。

### 4.4 Translator hard boundary

现行 source-derived families继续保留：

```text
4.1.0 -> 4.1.3   qApp/native translator family
4.1.4            dedicated translator, strict/fail-closed family
4.1.5 -> 4.4.5   dedicated native document translation
4.5.0 -> 4.6.4   Alternative WebUI document translation disabled
4.6.5+            dedicated native document translation restored
```

所以不能通过“全部改 QBT_TR + 删除所有 bridge”解决 4.5.0-4.6.4。

## 5. 用户批准的最终架构方向

总体目标：

```text
qB WebAPI        -> runtime facts/current settings values
qB source facts  -> exact capability/write provenance
qB QBT_TR/QM     -> qB-owned official copy when native-capable
compact TS bridge-> only proven native-gap releases
WeiG tiny i18n   -> WeiG-owned wording only
```

### 5.1 Settings

正式 target：

```text
app/preferences actual keys/values
-> W.SettingsSchema canonical grouping/control semantics
-> exact W.ReleaseProfile Preference descriptor provenance
-> SettingsRenderer
```

最终用户 runtime不再携带：

```text
private/data/qb-settings/<sourceSha>.json
```

Full Settings/source LKG仍保留在 tools/CI/artifacts作为 build-time evidence。

`qb-settings-native.txt` 先做完整 caller audit；若新 translation/runtime path不再需要它，则同一 atomic cutover退休。禁止先删再靠 fallback补洞。

### 5.2 qB-owned translation

凡 qB upstream已有 exact source/context 的词，优先使用：

```text
QBT_TR(Source)QBT_TR[CONTEXT=...]
```

并从 official TS/recovery evidence生成 **只包含 WeiG 实际使用 refs** 的 minimal QM，而不是完整复制 qB原生 WebUI全部翻译。

注意：当前 qB按 locale filename加载 `webui_<locale>.qm` 的 source contract下，Universal Portable支持全部locale仍可能需要一个locale一个小 QM；不能为了减少“文件数”虚构单文件 native-QTranslator格式。第一目标是大幅减少每个QM内容和总字节数。

### 5.3 4.5.0-4.6.4 compact bridge

这些 release不能依赖 native document translation。

把当前 per-release full `qb-settings/<sourceSha>.json` bridge改成：

```text
exact gap source identity
+ locale
+ only WeiG-used qB-owned refs
-> official translated text
```

相同 translation set内容去重。优先一个 compact bridge asset；只有超过 qB/project file-size budget才做 deterministic bounded shards。

Bridge仍由 canonical `W.I18n`/qB-owned resolver消费，不建立 I18nV2/第二translation owner。

### 5.4 WeiG-owned wording

WeiG自己的 Theme/Starfield/diagnostics/brand/help等，qB没有 official source/context，继续由一个很小的 WeiG-owned dictionary负责。

现有 `i18n.js` 中其实属于 qB-owned 的重复 EN/ZH 文案应逐步迁到 qB-owned source/context route并删除 duplicate；不能为了省QM把它们重新变成 WeiG手写翻译。

### 5.5 Universal Portable必须保留

官方产品继续要求：

```text
one materialized WeiG-qB-WebUI folder
+ offline
+ copy to supported qB host
+ set Alternative WebUI path
= works
```

不能要求最终用户安装 tools、运行 Node、连接 GitHub或在线下载当前 locale才能正常使用。

Targeted installer可以以后作为附加优化，但不能成为唯一产品形态。
