## 1. 第一原则：永远先 dev

用户明确要求：**不要跳过 dev，直接改 main。**

任何修改，包括“只是文档”“只是 workflow”“只是测试修复”，都先进入：

```text
dev
```

禁止：

```text
直接在 main update_file/create_file/delete_file
直接在 main 创建 commit
直接 cherry-pick 到 main
直接 update_ref main 作为日常修改方式
force push main
为了省 CI 时间把 fix 只放 main
```

正确流程：

```text
修改 dev
-> 验证 dev
-> 修复仍然在 dev
-> 完成所有计划修改
-> 冻结 final dev exact SHA
-> 建立同 SHA release-grade evidence
-> formal promotion
-> main fast-forward 到 validated dev SHA
```

即使某一刻 `main == dev`，下一次改动仍然从 dev 开始。

## 4. 当前 0.3.72 已完成的 release evidence 架构

本轮已经完成以下正式治理收口：

### 4.1 Full Frozen Matrix 不再随 dev push 自动运行

`.github/workflows/real-qb-full.yml` 当前是：

```text
name: Real qB Full Frozen Matrix
workflow_dispatch only
manual Exhaustive 65/65
fail-fast: false
max-parallel: 16
```

普通 dev push 不允许启动 65 个真实 qB jobs。

Fast capability planner / aggregate 可以保留为离线 contract、调试工具，但**不是正式 release evidence**。

### 4.2 Promotion / Release 统一要求 exact-SHA compatibility evidence

正式 promotion 与 Release 都必须为同一 exact SHA 解析：

```text
release-candidate-<SHA>
candidate-deployment-<SHA>
real-qb-full-aggregate-<SHA>
real-qb-current-locale-aggregate-<SHA>
```

Full 与 Locale release-grade evidence 必须来自：

```text
successful workflow_dispatch run
same exact WeiG SHA
```

普通 push 的 skipped Locale run、旧 SHA aggregate、Fast aggregate 都不能替代。

### 4.3 Central verifier

中央 owner：

```text
tests/release-compat-evidence.mjs
```

它会 fail closed 验证：

```text
WeiG exact SHA / VERSION
Frozen catalog digest
G-FM 65 expected / 65 executed / 65 PASS
FAIL=0 / BLOCKED=0
no missing/duplicate/unexpected qB versions
requested qB == runtime-reported qB
runtime image immutable digest identity
Locale exact SHA
Locale target == current admitted stable
all current-stable locales PASS
no Locale failures
```

离线 behavioral contract：

```text
tests/release-compat-evidence-contract.mjs
```

已进入 `npm test`，证明正确合成 `65/65 + 61/61` 可以通过，同时以下错误会被拒绝：

```text
wrong G-FM SHA
wrong qB runtime identity
mutable image tag
incomplete Locale evidence
wrong Locale SHA
```

这个测试不启动真实 qB，只保护发布 gate 逻辑。

## 5. 最重要的新成本纪律：不要频繁跑 Full Matrix

用户明确要求：**Real qB Full Frozen Matrix 不要频繁跑，只在最后一次验证 / 准备发布时跑。**

永久执行方式：

```text
日常 dev push                -> 不跑 Full
普通修复 / workflow / tests -> 不跑 Full
docs-only                    -> 不跑 Full
中间 checkpoint              -> 不跑 Full
final dev SHA 未冻结         -> 不跑 Full
最终验证 / 准备发布          -> 手动 workflow_dispatch 跑一次
```

只有以下例外可考虑额外手工全量：

```text
Frozen LKG 扩展，需要全区间重新认证
real-qB harness/runtime resolver 重大变化
compatibility owner 重大变化且明确要求重新认证
用户明确要求重新确认完整支持区间
```

开发期间先靠：

```text
normal CI
source/product contracts
focused real-qB acceptance
behavioral fail-closed tests
```

把问题收敛。

如果 Full 跑完以后又产生任何将进入最终发布历史的新 commit，旧 Full aggregate 只证明旧 SHA。真正发布时对新的 final exact SHA 重新跑最后一次即可；不要为了每个中间 SHA 都补 65/65。

## 6. 发布前必须完成：同一个 final exact SHA

只有用户明确进入最终验证 / 准备发布阶段，才先冻结一个 **final dev exact SHA**。

同一个 SHA 必须具备：

```text
normal CI PASS
CI candidate PASS
Dev Pages exact-SHA artifact/live verify PASS
manual Current Stable Locale Matrix PASS
manual Real qB Full Frozen Matrix 65/65 PASS
central release-compat-evidence verifier PASS
Promote validated dev to main PASS
main == dev == final exact SHA
main Pages exact reuse/live identity PASS
```

当前 operational expectation：

```text
G-FM: 65/65
Locale: qB 5.2.3 current surface 61/61
```

61 是当前 LKG 派生事实，不是永久硬编码产品常量。

之后才允许：

```text
create tag v0.3.72
let Release workflow publish
```

Release 会再次独立解析 candidate + G-FM + Locale exact-SHA evidence，不能只依赖“Promotion 已经绿过”。

Release 正式 assets：

```text
WeiG-qB-WebUI.zip
weigg-install.sh
weigg-install.ps1
SHA256SUMS
```

Release 复用 exact dev candidate artifact，不重新 build 产品。

## 7. Installer / supply-chain 当前事实

### Stable Release identity

Linux/Windows installer：

```text
resolve Release metadata
-> exact tag
-> tag commit SHA
-> tag-pinned asset URL
-> SHA256SUMS
-> package VERSION == tag version
-> package GIT_SHA == tag commit
```

不要放宽这条链。

### Dev distribution

Linux/Windows Dev 只消费 Pages materialized distribution。payload 自身 identity：

```text
downloads/dev/GIT_SHA
== package GIT_SHA
```

日常 `current dev HEAD` 可以只因为明确的 Pages-irrelevant commit 暂时领先 published Pages SHA。只有 intervening diff 全部属于明确允许的 Pages-irrelevant 集合时才允许复用最后一个 verified payload。

任何未知/runtime path 都 fail closed，等待新的 Pages build。

禁止 raw-source fallback。

## 9. Pages 当前架构与坑

唯一部署 owner：

```text
Virtual qB Pages Source
-> relevance classifier
-> workflow_dispatch
-> Virtual qB Pages
```

不要恢复 default-branch `workflow_run` deployment trigger。

### 9.1 Pages relevance

每个 dev/main push 进入轻量 `Virtual qB Pages Source`，由完整 Git history 做 relevance classifier。

不要为了省 runner 在这个安全入口改用容易因 changed-file 上限造成错误判定的 GitHub 原生 `paths` / `paths-ignore`。

仓库有中文文件名，diff 继续使用：

```text
git diff --name-only -z
read -d ''
```

未知路径默认 Pages-relevant。

纯 docs push 的目标是低成本，不是 0 runner：

```text
CI classifier -> SUCCESS
heavy smoke   -> SKIPPED where classifier permits
Pages Source  -> lightweight classification
Pages deploy  -> only when relevant/manual
Full Matrix   -> no run
```

### 9.2 应用语言不是浏览器 locale

WeiG 的持久化语言 truth owner：

```text
qB app/preferences.locale
```

Playwright/browser locale 不是应用持久语言 truth。

测试界面语言必须读取实际 `W.I18n.getLocale()` / qB preference，再验证对应输出；不要因为浏览器 locale 是 `zh-CN` 就假定产品已经切到中文。


## 11. 当前推荐下一步

每次接手：

```text
1. fresh-read dev/main HEAD、VERSION、latest Release/tag。
2. fresh-read latest normal CI / Pages / manual Locale / manual G-FM 状态。
3. 不移动 main。
4. 继续开发仍然只改 dev。
5. 普通开发只跑与改动风险匹配的轻量/常规验证，不运行 Full Frozen Matrix。
6. 所有计划修改完成后，再决定是否进入“最终验证/准备发布”。
7. 进入发布阶段时 freeze final dev exact SHA。
8. 为同一 SHA 建 candidate + explicit Pages + manual Locale evidence。
9. 最后对同一 SHA 手动跑一次 Real qB Full Frozen Matrix 65/65。
10. 全部同 SHA evidence PASS 后使用 formal promotion workflow 晋级 main。
11. main Pages exact reuse PASS 后才创建 v0.3.72 tag。
12. Release workflow 再次验证 candidate + G-FM + Locale 后发布现有 bytes。
```

在用户没有明确要求发布前，**不要提前跑 Full 65/65，也不要移动 main/tag/Release。**
