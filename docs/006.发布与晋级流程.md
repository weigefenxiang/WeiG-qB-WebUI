# 006. 发布与晋级流程

Status: **current CI / candidate / promotion / release authority**

本文档描述长期有效的执行流程、exact-SHA 门禁与当前 operational 边界，不维护历史 Phase checkpoint。所有数字型 matrix 规模、某次 SHA/run 只作为当前事实，不提升为永久架构常量。

## 1. 正式 workflow

仓库正式 GitHub Actions workflow：

```text
CI
Promote validated dev to main
Real qB Full Frozen Matrix
Real qB Current Stable Locale Matrix
Release
Virtual qB Pages
Virtual qB Pages Source
```

新增、删除、重命名或改变 workflow 职责属于显式架构变更，必须同步检查 `.github/workflows/**`、tests/contracts、package scripts、permissions、concurrency 与 docs 引用。

## 2. 分支职责：所有工作先进入 dev

```text
dev   唯一开发 / 修复 / docs / validation 入口
main  稳定晋级结果，只接收 validated dev safe fast-forward
```

产品、installer、workflow、test、fixture、docs、CI 修复都先进入 dev。未经用户明确授权禁止直接修改 main、promotion、tag 或 GitHub Release；禁止 force push。即使 main 与 dev 暂时相等，下一次修改仍从 dev 开始。

main 只能从已经完成正式门禁的 final dev exact SHA 做 safe fast-forward，`force:false`；禁止 merge commit、cherry-pick rebuild、main-only fix 或重新构造 release identity。

## 3. CI 按风险分层

`.github/workflows/ci.yml` 的职责：

```text
ordinary dev push             -> classify + normal/smoke as applicable
explicit UI validation        -> UI/browser lane
candidate validation          -> complete source/product/browser/package/deployment chain
```

Candidate 可通过：

```text
workflow_dispatch: validation_mode=candidate
```

或由 final coherent commit message 明确包含 `[candidate]` 触发现有 push gate。`[candidate]` 只能附着在真实、必要、可审计的最终改动（例如 docs authority finalization）；禁止为了触发 Actions 造无意义空提交或假代码改动。

普通 docs/tests/tooling-neutral maintenance 不应自动启动 real-qB Full Frozen Matrix 或 current-stable 全 Locale matrix。

任何新 commit 都产生新的 exact-SHA evidence identity。旧 candidate、browser、Pages、Locale、G-FM artifact不能自动证明新 SHA。

## 4. Release candidate

准备正式候选时，先完成计划内代码/workflow/tests/docs，再冻结 final dev exact SHA。Candidate 至少覆盖：

```text
smoke
representative fixture compatibility
exact stable source catalog generation
all admitted stable upstream source audit
locale/source enrichment shards
merged exact source + recovery evidence
Settings/source certified LKG
full stable PRODUCT compatibility
Linux hosted Chrome candidate
Windows hosted Chrome candidate
release candidate package
candidate deployment / official-qB rehearsal acceptance
```

当前 source/recovery pipeline 的关键 artifact 包括：

```text
qb-release-catalog-base-<SHA>
qb-release-enriched-<SHA>-<shard>
qb-release-catalog-<SHA>
qb-settings-translation-lkg-<SHA>
release-candidate-<SHA>
candidate-deployment-<SHA>
```

Release candidate artifact 必须至少包含：

```text
WeiG-qB-WebUI.zip
weigg-install.sh
weigg-install.ps1
SHA256SUMS
CANDIDATE_SHA
```

checksums、VERSION、CANDIDATE_SHA、ZIP 内 `GIT_SHA` 必须与 target exact SHA一致。

Candidate CI 的 `Full qB Release compatibility audit` 是 source/product/evidence aggregate，**不等于** Real qB Full Frozen Matrix；两者不能互相冒充。

## 5. Candidate deployment acceptance

Candidate deployment 必须在 official qB runtime 上验证真实安装/运行，不允许只用 fixture/Virtual qB。

当前 representative official-qB acceptance 至少覆盖 floor-era 与 latest stable 代表，包括现有 harness 使用的 qB 4.6.7 与 5.2.3；具体代表版本可以随 source/evidence policy 调整，不提升为永久硬编码。

至少证明：

```text
candidate package exact identity
checksum / VERSION / GIT_SHA
installer syntax and lifecycle
real app/preferences
canonical Settings
locale write/read/reload semantics where exercised
source-proven product actions
promotion/release rehearsal invariants
no unexpected remote writes
```

生产 identity/security gate 不得因为 candidate harness/mock 不完整而放松。错误 mock 应修测试桩，不应修改正确生产 parser 来迁就。

## 6. Virtual qB Pages exact-SHA 规则

Pages 两层 owner：

```text
Virtual qB Pages Source
-> ref-bound workflow_dispatch
-> Virtual qB Pages
```

`Virtual qB Pages` 是 build/deploy/live-verify owner；禁止恢复 default-branch `workflow_run` duplicate deployment path。

### 6.1 Dev Pages

```text
resolve target dev ref/SHA
-> source/materialization evidence as required
-> exact-SHA site artifact
-> fresh-head stale-deploy gate
-> deploy
-> live browser verify
```

Pages source/build必须消费 frozen/hash-bound source/LKG facts，不应在普通 deployment 上重新 clone/re-parse 全部 qB history。

### 6.2 Docs-only / public-payload-irrelevant nuance

Dev installer 与 Pages stale classifier允许在 GitHub compare **明确证明只有 public-payload-irrelevant diff** 时复用最近已验证 materialized payload。这是日常 Dev distribution 的成本优化，不是 release evidence继承。

因此：

```text
old materialized product SHA may represent unchanged runtime bytes
!=
new docs SHA has exact-final-SHA release-grade Pages evidence
```

准备 promotion/release 时，最终 dev exact SHA 必须拥有正式 gate 所要求的 exact Pages identity；不能因为 docs-only classifier允许复用旧 payload，就把旧 SHA Pages artifact写成新 SHA release evidence。

### 6.3 Main Pages

Promotion 后 main 不应重新 full-build另一份产品；应复用同一个已验证 final dev artifact/bytes，并验证 main/dev/build metadata/live deployment identity一致。若 required exact artifact不存在，必须 fail closed。

## 7. Current Stable Locale Matrix

`.github/workflows/real-qb-locale.yml` 是 focused real-qB language acceptance，不是第二套 Full Frozen Matrix。

Release-grade Locale evidence必须来自 final dev exact SHA 的显式 manual dispatch。矩阵身份由 target exact-SHA locale LKG派生：

```text
latestAdmittedStable
-> exact current stable profile/source identity
-> exact localeSet
-> one exact-SHA per-locale acceptance
-> aggregate
```

当前 operational surface 是 qB 5.2.3 的 61 locales；数量随 Frozen LKG演进，不是长期常量。

每个 locale至少证明 running qB identity、locale确实存在于 native surface、`app/setPreferences(locale)` 成功、verified reread命中目标、native locale surface仍可用，并安全恢复测试前状态。Aggregate必须拒绝 missing/duplicate/unexpected，且全部 PASS。

普通 push 的 skipped/conditional Locale run不能作为 release-grade evidence。

## 8. Real qB Full Frozen Matrix（G-FM）

`.github/workflows/real-qb-full.yml` 是发布前重型真实 qB gate，只在 final/release-stage显式运行，不是日常 CI。

expected versions必须从 target exact-SHA Frozen LKG派生。当前 operational surface 是 65 stable runtimes，但数量不是长期硬编码。

每个 runtime必须验证：

```text
same WeiG exact SHA
requested qB == runtime self-report
ReleaseProfile/exact source identity consistent
runtime image/source-build immutable identity
capability/product acceptance PASS
```

Aggregate必须证明 expected == executed，`FAIL=0`、`BLOCKED=0`，无 missing/duplicate/unexpected version。

手工启动必须有 branch/ref、exact candidate SHA和显式确认词等 fail-closed guard，防止误触错误 SHA 或无谓展开整套 matrix。

如果 G-FM完成后又产生任何进入 release history 的新 commit，旧 aggregate只证明旧 SHA；正式发布必须重新对新的 final SHA取得证据。

## 9. Exact-SHA promotion gate

正式 authority：

```text
Promote validated dev to main
```

Promotion 前必须证明同一个 final dev SHA 至少拥有：

```text
current dev HEAD == candidate SHA
normal CI success
candidate full chain success
release-candidate exact artifact
candidate-deployment exact evidence
Dev Pages exact required evidence
manual Current Stable Locale aggregate all PASS
manual G-FM aggregate all PASS
central release-compat-evidence verifier PASS
main is ancestor and safe fast-forward is possible
```

最终只能：

```text
<current main> -> <validated final dev exact SHA>
```

并显式 `force:false`。

Candidate PASS、Pages PASS、main==dev 或 Actions 顶层绿色状态任一单项都不能替代 formal promotion permission。

未经用户明确授权，不执行 promotion。

## 10. Tag / Release

Formal promotion成功、main Pages exact reuse/live identity确认后，才允许创建：

```text
v<VERSION>
```

必须满足：

```text
tag SHA == current main SHA == validated final dev SHA
```

Release坚持 `build once / validate once / promote same bytes`：复用已验证 candidate artifact，不在 main/tag 后重新构建另一份 ZIP。

Release workflow应重新验证：

```text
tag/version/main SHA identity
candidate run/artifacts
candidate deployment evidence
manual G-FM aggregate
manual Locale aggregate
central release-compat-evidence
CANDIDATE_SHA
SHA256SUMS
installer bytes
ZIP embedded GIT_SHA / VERSION
generated catalog/LKG identity as applicable
```

已发布 tag/Release/assets是 immutable historical identity；禁止覆盖、移动或删除后重打。

未经用户明确授权，不创建 tag 或 GitHub Release。

## 11. 推荐正式顺序

```text
1. all planned changes -> dev
2. sync current docs/tests/workflows; no heavy G-FM yet
3. freeze final dev exact SHA
4. normal CI PASS
5. CI candidate PASS on same SHA
6. Dev Pages exact required evidence PASS on same SHA
7. manual Current Stable Locale Matrix PASS on same SHA
8. manual Real qB Full Frozen Matrix PASS on same SHA
9. central release-compat-evidence PASS
10. user explicitly authorizes promotion/release
11. Promote validated dev -> main safe fast-forward
12. main Pages exact reuse/live verify
13. tag v<VERSION> on exact main SHA
14. Release reuses validated candidate bytes
15. verify final assets/digests/identities
```

Candidate、Pages、Locale、G-FM在 final SHA冻结后可按 workflow能力并行；但 G-FM应尽量放在开发彻底停止后的最后重型验证阶段，避免新 commit使昂贵证据失效。

## 12. Docs-only 规则

Docs-only coherent change：

```text
must go to dev
must not bump Product VERSION
must not direct-sync main
may trigger candidate when it is the real final authority/handoff commit
must not be used as excuse for empty/no-op trigger commits
```

如果 docs-only final commit触发 candidate并成功，它证明的是该 docs SHA 的 candidate chain；旧 product SHA的 Pages/runtime证据仍只能按各自 exact-SHA/public-payload规则使用。

## 13. Red gate discipline

红灯先分类：

```text
product bug
source/profile misunderstanding
stale test/fixture/simulator/docs
workflow choreography bug
runtime infrastructure problem
artifact/evidence identity problem
promotion/ref race
```

处理规则：

```text
读完整失败日志
确定性 bug 修 root cause
source/canonical runtime truth优先
不降低 assertion/provenance/exact-SHA gate
不把 FAIL 改 SKIP
不吞 runtime/source error
只对明确 transient runner/CDN/infrastructure fault做 same-SHA rerun
```
