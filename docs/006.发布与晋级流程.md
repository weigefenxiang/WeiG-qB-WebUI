## 2. Validation tiers

### Tier 1 — normal dev / docs / tests / tooling-neutral

普通 `dev` push：

```text
smoke
-> npm test
-> JavaScript / installer / script syntax
```

Docs-only Phase F start checkpoint 只应触发 normal smoke；不应人为触发 candidate/browser/full upstream audit。

### Tier 2 — general product/UI compatibility change

正式 `webui/**` compatibility 修改至少：

```text
smoke
-> direct product contracts
-> frozen LKG product regression when formal compatibility owner changes
-> relevant browser / Virtual qB evidence
```

Frozen regression：

```text
verify frozen LKG identity
-> architecture guard
-> Full Stable PRODUCT Compatibility Matrix on 65 frozen profiles
```

它不重新 checkout/source-extract verified historical qB。

### Tier 2.5 — future stable incremental admission

```text
verify frozen LKG
-> lightweight official stable tag comparison
-> no new stable: immediate exit
```

有新 stable 才：

```text
checkout upstream
-> source-extract only new stable profiles onto frozen prefix
-> reject historical mutation
-> source audit floor + new refs
-> focused product gate
-> repository contracts
-> upstream + product diff
-> PASS
-> fresh dev race check
-> safe fast-forward catalog + manifest only
```

失败：

```text
PENDING_REVIEW
candidate rejected
LKG unchanged
```

### Tier 3 — source/discovery/evolution changes

独立 heavy `Full qB stable WebAPI evolution audit` 只用于真正改变：

```text
stable tag discovery
source parsers
source-derived actions/parameters/fields/filters/preferences
evolution tooling / ledger
```

明确不因 runtime compatibility owner、ordinary UI、docs、tests、VERSION-only、installer自动触发。

Phase F pre-start audit判断：**首批实现现有 catalog facts 足够，不计划改 parser/discovery/evolution，因此不应人为触发 Tier 3。** 若实施中必须改 source extraction，立即升级风险等级并跑 Tier 3。

## 5. Phase F product validation contract

### 5.1 Settings

必须证明：

```text
read endpoint source action exists
write endpoint source action exists
per-Preference setter/type agreement exists
```

写入条件：

```text
endpoint writable
AND
preference writable
```

Unknown endpoint、getter-only、missing setter、type mismatch、unproven structured editor => no unsafe payload。

### 5.2 RSS historical correction

Exact upstream qB 4.1.0 已有 core RSS actions；因此 Phase F candidate 必须包含回归证明：

```text
qB 4.1.0 RSS core route/read/actions = source-proven
```

旧 Virtual qB/Pages expectation 如果要求 4.1.0 `rss/items` 404，必须修 evidence；禁止为了旧 test 保留错误产品隐藏。

### 5.3 Search / Logs

```text
Search core: source-proven from qB 4.1.4
Logs main/peers: source-proven from qB 4.1.0
```

Final product gate 应读取 exact source actions，不再只验证 WebAPI/qB version threshold。

### 5.4 Details / action parameters

必须分别验证：

```text
Properties / Files / Trackers / Peers / WebSeeds reads
File priority / Tracker mutations / Peer Ban writes
response fields used by UI
action parameter form generation
```

代表性 parameter evolution：`editTracker` old vs 5.2.x contract；QBClient 必须按 exact action parameters 生成 form，unknown contract HTTP 前 fail closed。

禁止把 unsupported/error catch 成 fake empty list。
