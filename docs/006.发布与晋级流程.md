# 006. 发布与晋级流程

Status: **current product validation / promotion / release contract**

本文件以 `webui/**` 产品兼容为中心。Virtual qB / source audit 是开发证据的一部分，但不能替代真实 qB compatibility evidence。

## 1. Version discipline

只有正式 `webui/**` 产品内容变化才 bump patch VERSION。

一旦 `webui/**` 变化，以下四处同一最终 tree 同步：

```text
VERSION
webui/VERSION
package.json.version
package-lock.json root package version
```

仅 simulator/tests/tools/workflow/docs/DESIGN/installer/CI 变化时保持产品 VERSION。

Exact Git SHA 始终是 code/cache/test/Pages/LIVE/candidate/artifact evidence identity；新 SHA 不继承旧 SHA 证据。

## 2. Phase E normal dev validation

当前产品主阶段是 Real qB Product Compatibility。

每个 `webui/**` compatibility batch 至少经过：

```text
upstream/source evidence
-> direct product compatibility contracts
-> normal CI
-> Upstream Compatibility Audit
-> relevant Virtual qB stable-profile browser tests
-> representative real-qB evidence when available/practical
```

目标不是只证明 simulator 正确，而是证明正式 `webui/**` 能正确处理真实 qB4/qB5 差异。

## 3. Product compatibility contracts

新增/修改产品兼容逻辑必须直接测试产品 owner，例如：

```text
legacy qB input/request/response
-> W.QBClient / ReleaseProfile / TorrentSemantics / SettingsSchema
-> canonical WeiG result

modern qB input/request/response
-> same product owner
-> same canonical WeiG semantics
```

测试应覆盖：

- qB4/qB5 endpoint/action naming；
- parameter differences；
- response normalization；
- status/error behavior；
- feature capability；
- emulation path；
- unavailable path；
- UI final state where relevant。

## 4. Upstream compatibility evidence

当前 WebAPI v2 source-derived stable matrix：

```text
qBittorrent 4.1.0 -> latest official stable
```

当前 tested latest 为 qB 5.2.3 / WebAPI 2.15.1，stable profile 数量由 tooling 动态发现。

Source audit 验证：

- endpoint existence；
- Preference getter/setter/type provenance；
- Torrent filter/info parameter surface；
- WebAPI evolution evidence。

它证明“上游是什么”，但不自动证明 `webui/**` 已正确适配。

## 5. Virtual qB Pages — auxiliary product acceptance

Virtual qB Pages 的正确定位：

```text
same formal webui/**
-> Virtual qB historical profiles
-> Hosted Chrome real UI flows
```

它适合：

- 快速覆盖多 stable profile；
- 验证产品 normalization；
- 验证 filters/facets/columns/settings/search/rss/logs 的 capability presentation；
- 验证历史 response/status shape。

它不能替代真实 qB binary/server LIVE。

Workflow `head_sha` 可能显示 default branch main；source identity 仍以 triggering source SHA、exact checkout、`WEIGG_PAGES_SOURCE_SHA`、`WEIGG_EXPECTED_SIMULATOR_SHA`、deployed metadata 为准。

## 6. Representative real-qB validation during development

Phase E 不再把所有真实 qB 验证都推迟到 promotion 最后一天。

对于高风险产品兼容批次，应该尽早增加 representative real-qB evidence，例如：

```text
legacy supported qB4
modern qB4
qB5 generation
latest stable qB5
```

具体 patch 不在文档硬编码，可由当前 available runner/container/operator environment 决定；但每次证据必须记录 exact qB version + WebAPI version + WeiG SHA。

如果某项兼容逻辑只能在 simulator 中证明、尚无真实 qB evidence，汇报时必须明确标注，而不是写成“真实 qB 已兼容”。

## 7. qB4.0.x / WebAPI v1

当前自动 stable source/evolution matrix 从 qB 4.1.0 开始。

如果 Phase E 扩展到全部 qB4 stable，应先建立：

```text
Legacy WebAPI v1 Adapter
```

并单独定义 real-qB v1 validation。不得把 v1 compatibility 混进 v2 UI caller。

## 8. Promotion-time frozen real-qB LIVE

准备晋级 `main` 时，冻结 final dev SHA，执行真实 qB4/qB5 LIVE。

统一脚本当前包括：

```text
tests/live.sh
tests/live-api.sh
```

如果 Phase E 增加新的 product-critical flow，应同步扩展 real LIVE coverage。

LIVE 后 tree 变化，旧 evidence 作废。

## 9. Promote dev to main

必须满足：

- exact validated dev SHA；
- normal CI/upstream/product compatibility evidence；
- relevant Virtual Pages；
- required real-qB LIVE/operator confirmation；
- 用户/maintainer 显式授权；
- safe fast-forward。

只允许：

```text
main -> exact validated dev SHA
```

禁止 merge commit/force overwrite 未知 main-only commit。

## 10. Main-only candidate / Release

main 指向 validated SHA 后运行 full candidate：

```text
full stable-tag source audit
Linux Hosted Chrome representative matrix
Windows Hosted Chrome representative matrix
real-qB evidence requirements
exact-SHA candidate artifact
```

Artifact 必须携带 source-derived `qb-releases.json` 并绑定 candidate SHA/checksum。

Tag/Release 只发布同一 candidate artifact，不重新 build 一个不同产物。

## 11. Canonical chain

```text
Phase E dev batch
-> product compatibility implementation in webui/**
-> product contracts
-> CI/upstream
-> Virtual qB auxiliary matrix
-> representative real-qB when relevant
-> batch checkpoint

when promoting
-> freeze dev SHA
-> final real-qB LIVE
-> explicit authorization
-> safe fast-forward main
-> full candidate
-> artifact
-> tag/release same SHA
```

## 12. Red gate discipline

看到红灯先判定：

```text
real product bug?
upstream misunderstanding?
stale product test?
stale simulator test?
fixture/source profile problem?
```

Real upstream/real-qB truth 优先。禁止为了旧 simulator/test expectation 回退正确产品兼容行为。

## 13. SAFE-REF

正式开发使用 `dev`；未经授权不动 `main`。

每次写入：

```text
fresh-read dev
-> build candidate
-> compare expected paths
-> validate
-> fresh-read dev again
-> force:false fast-forward
-> final SHA validation
```
