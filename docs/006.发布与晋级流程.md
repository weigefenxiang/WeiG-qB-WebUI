# 006. 发布与晋级流程

Status: **current release contract**

当前仓库只维护现行开发/发布链。历史 WeiG 版本的 runtime、tests、deploy scripts 不保留兼容副本；历史恢复使用 Git commits / tags / Releases。qBittorrent / WebAPI 的当前兼容版本门槛继续作为产品事实保留。

## Version discipline

每一个**正式 dev tree 改动**都必须先递增 patch VERSION。范围包括 code、`webui/**`、tests、fixtures、workflow、docs、DESIGN、installer、CI/gate 修复等；不得再因为“只改测试/文档/CI”而沿用旧 VERSION。

Canonical version sources 必须在同一个最终 tree 中完全一致：

```text
VERSION
webui/VERSION
package.json -> version
```

例如当前正式状态 `0.3.25` 的下一次 dev tree 改动是 `0.3.26`。禁止只更新其中一处造成版本漂移。

VERSION 是人类可读的正式开发状态标识；**exact Git SHA 仍然是 code/cache/test/LIVE/candidate/artifact 的唯一证据身份**。任何新 commit 都产生新的 exact SHA，旧 SHA 的 CI / LIVE / candidate / artifact 证据一律作废，不得仅凭版本字符串继承。

Browser/test fixture 需要产品版本时读取 canonical `VERSION`，禁止硬编码 `0.3.x`。

## 1. Dev validation

普通 `dev` push：

```text
dev push
  -> npm test
  -> JavaScript / Shell / PowerShell syntax
  -> Upstream Compatibility Audit
       qB 4.1.9.1
       qB 5.2.0
```

Gate ownership 使用稳定职责边界：

```text
runtime-contract.mjs          global runtime invariants only
feature *-contract.mjs        feature semantic/Current Owner rules
syntax-contract.mjs           all runtime/test JavaScript syntax
browser-*.mjs                 real interaction + final semantic/visible state
workflow if                   candidate source admission
```

禁止让总 gate 重复拥有 Theme/Feedback/Capability/Torrent 等专属实现形状；禁止为了同一条件再增加只做重复判断的 guard job。Private/PT semantics 属于 Torrent contract，不保留第二个 standalone semantics gate。

UI/响应式修改使用 `[ui]` focused gate：

```text
dev commit contains [ui]
  -> smoke/static contracts
  -> Linux Chromium
       browser-runtime.mjs
       browser-theme.mjs
       browser-feedback.mjs
       browser-feature-parity.mjs
       browser-torrent-workspace.mjs
       browser-adaptive-ui.mjs
```

当前测试文件只用稳定职责名；禁止 `*-vNNN.mjs`、`live-vNNN.sh`、`live-qbNN.sh`。

## 2. Upstream compatibility

普通 dev 代表性 audit：

```text
release-4.1.9.1
release-5.2.0
node tests/upstream-release-audit.mjs upstream-qb --refs=release-4.1.9.1,release-5.2.0
```

qB/WebAPI 版本号是当前兼容事实。例如 Private/PT 的 `qBittorrent 5.0.0+`、Tags 的 `WebAPI 2.3.0+` 必须继续保留。

## 3. Exact-SHA LIVE gate

晋级 `main` 前，current final `dev` SHA 必须真实验证：

```text
Legacy LIVE: qBittorrent 4.1.9.1
Modern LIVE: qBittorrent 5.2.x
```

部署脚本永久使用：

```text
tests/live.sh
```

它接收 exact SHA + target path，从 candidate `webui/VERSION` 读取实际产品版本；不硬编码 WeiG release version，不创建 version-named staging/backup path。

无本地仓库：

```sh
SHA=<40-char-current-dev-sha>
curl -fL "https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/${SHA}/tests/live.sh" -o /tmp/weigg-live.sh
sh /tmp/weigg-live.sh --sha "$SHA" --target /path/to/weigg-qb-webui
```

Modern qB API regression 使用 `tests/live-api.sh`。脚本正文可以验证 qB 5.2.0/WebAPI capability；文件名不编码版本。

任何 code/test/docs/workflow 变化都同时产生新 VERSION 和新 SHA。无论版本字符串如何，旧 LIVE-PASS 都不得继承给新 SHA。

## 4. Promote dev to main

`.github/workflows/promote.yml` 需要：

```text
candidate_sha = exact current dev HEAD
live_gate     = LIVE-PASS
confirmation  = PROMOTE-VALIDATED-DEV
```

必须验证 current dev、safe fast-forward、exact-SHA successful CI、exact-SHA upstream audit、operator LIVE confirmation。

通过后只允许：

```text
main -> exact validated dev SHA
```

禁止 merge commit / force-overwrite 未知 main-only commit。

## 5. Main-only Release candidate

`main` 指向已验证 exact SHA 后手动运行：

```text
workflow_dispatch
validation_mode=candidate
```

完整候选：

```text
main exact SHA
  -> smoke
  -> release-compat.mjs
  -> upstream-release-audit.mjs (all stable 4.x/5.x from 4.1.9.1)
  -> Linux browser matrix
  -> Windows browser matrix
  -> package exact-SHA release candidate
  -> release-candidate-<SHA>
```

Candidate source eligibility 由各 candidate job 的 workflow `if` 直接拥有，不再创建重复 qualification guard job。

Artifact：`WeiG-qB-WebUI.zip + SHA256SUMS + CANDIDATE_SHA`。

## 6. Tag Release

`v*` tag 启动 publish-only Release workflow。必须验证 tag SHA=current main、successful exact main candidate、candidate artifact、dev upstream audit、CANDIDATE_SHA、SHA256SUMS、ZIP GIT_SHA。

Tag 阶段禁止重新测试、重新 build 或重新 package source。

## 7. Canonical release chain

```text
formal dev change
→ patch VERSION +1 in all three canonical sources
→ dev exact SHA
→ current contracts/syntax
→ qB 4.1.9.1 + 5.2.0 representative audit
→ focused Chromium when UI-affecting
→ exact-SHA qB4 + qB5 LIVE
→ explicit maintainer authorization
→ fast-forward main same SHA
→ main-only full stable-tag + Linux + Windows candidate
→ reusable artifact
→ tag same SHA
→ verify + publish same artifact
```

旧 SHA 曾 green 不能为新 SHA 提供发布豁免。任何新 SHA 都必须取得自己的 CI/LIVE/candidate 证据。
