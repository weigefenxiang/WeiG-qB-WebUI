### 2.3 dev -> main — pure fast-forward only

只有 final dev candidate 全绿后才允许 promotion。

Promotion 前必须验证：

```text
candidate_sha == current dev HEAD
successful full candidate run exists for candidate_sha
release-candidate-<candidate_sha> artifact exists and is not expired
main is an ancestor of candidate_sha / safe fast-forward is possible
```

Promotion 结果必须是：

```text
dev  -> candidate_sha
main -> candidate_sha
```

禁止：

```text
merge commit
cherry-pick rebuild
force push
main-only product mutation
```

### 2.4 main 不重复重型 candidate

如果 `main` 只是 fast-forward 到已经完整验证的 dev exact SHA，则：

```text
main tree == validated dev tree
main SHA  == validated dev SHA
```

因此本次发布不再在 main 重跑：

```text
Linux browser
Windows browser
Full qB all-stable source/product audit
release candidate package build
```

原因：这些证据已经绑定 exact SHA；分支 ref 从 `dev` 移到 `main` 不改变 Git object 或产品 bytes。

可以保留轻量 ref/integrity check，但**发布的 ZIP 必须复用 dev candidate 已经验证过的同一个 artifact，禁止 main 再构建一份新的 ZIP。**

## 14. Red gate discipline

红灯分类：

```text
real product bug
upstream/source misunderstanding
owner/caller migration gap
stale implementation-shape test
stale browser/simulator fixture
cross-platform proof bug
profile/evidence problem
source parser problem
CI trigger problem
release artifact identity problem
promotion/ref race problem
```

完整失败日志优先。Correct upstream/source/canonical runtime truth > stale fixture/test。禁止为了变绿回退正确产品行为、放宽正确 gate、恢复旧 owner或加 compat hack。
