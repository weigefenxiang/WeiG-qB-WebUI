## 1. Version discipline

只有正式 `webui/**` 产品内容变化才 bump patch VERSION。

一旦 `webui/**` 变化，以下四处在同一最终 tree 同步：

```text
VERSION
webui/VERSION
package.json.version
package-lock.json root/package version
```

仅 simulator/tests/tools/workflow/docs/DESIGN/installer/CI 变化时保持产品 VERSION。

当前：

```text
VERSION 0.3.59
Phase E final validated SHA:
6443cc35f570e8f1ed7a7e078aa15efa1618ce25
```

Exact Git SHA 始终是 code/cache/test/Pages/LIVE/candidate/artifact evidence identity；任何新 SHA 不自动继承旧 SHA 的 runtime/candidate/LIVE evidence。Docs-only SHA 不要求重跑 runtime Pages 或重型 compatibility evidence，除非 workflow/gate 明确需要。

## 2. Validation tiers

### Tier 1 — normal dev / docs / tests / tooling-neutral

普通 `dev` push：

```text
smoke
-> npm test
-> JavaScript / installer / script syntax
```

`docs/**`、README、纯文档更新不触发 Full qB stable WebAPI evolution audit，也不触发 candidate browser/full-stable jobs。

### Tier 2 — general product/UI compatibility change

正式 `webui/**` compatibility 修改至少：

```text
smoke
-> direct product compatibility contracts
-> relevant browser / Virtual qB evidence
```

通用 compatibility owner / formal product matrix 改变时，必须使用 frozen LKG 做历史 product regression：

```text
verify frozen LKG identity
-> architecture guard
-> Full Stable PRODUCT Compatibility Matrix on frozen profiles
```

该 regression 不 checkout qB upstream，不重新 source-extract verified historical profiles。

正式 candidate：

```text
exact generated catalog
-> all-stable source audit
-> Full Stable PRODUCT Compatibility Matrix
-> Linux Hosted Chrome browser
-> Windows Hosted Chrome browser
-> exact-SHA candidate package
```

### Tier 2.5 — future stable incremental admission

Future Stable Watch 首先只比较 official stable tag names：

```text
verify frozen LKG
-> fetch remote release-* tag names only
-> compare with admitted stable prefix
```

无新 stable：

```text
exit immediately
no upstream source checkout
no historical product replay
no source extraction
no repository write
```

有新 stable：

```text
checkout upstream source only then
-> source-extract only new stable profiles onto frozen LKG
-> reject retroactive history drift / frozen profile mutation
-> source audit support floor + newly discovered refs
-> product gate: floor + previous admitted stable + new profiles
-> repository contracts / architecture guard
-> upstream + formal product capability diff
-> all gates PASS
-> fresh-check dev exact SHA
-> safe fast-forward catalog + manifest admission only
```

任一 parser/source/product/write-semantics/admission gate 失败：

```text
PENDING_REVIEW
candidate rejected
Last Known Good unchanged
```

仅新增 verified stable profile、且通用 runtime compatibility code 未变时，不要求重跑全部 frozen historical product matrix，也不得重新 source-extract 历史 profiles。

### Tier 3 — upstream source / discovery / WebAPI evolution

`Full qB stable WebAPI evolution audit` 只用于真正影响 source/discovery/evolution facts 的变化，例如：

```text
qB stable tag discovery logic
WebAPI revision history
source parsers
source-derived API/actions/parameters/fields/filters/preferences
release-to-release evolution tooling / ledger
```

当前 trigger source of truth 是 `.github/workflows/upstream-compat.yml`。

明确不因为以下内容自动跑重型 audit：

```text
docs/**
README
ordinary UI / CSS / images / translations
runtime compatibility owner changes alone
ordinary tests
VERSION-only
installers
unrelated tooling
```

普通 CI 已运行 `npm test`，重型 upstream audit 不重复整套 npm test。

## 3. Product compatibility contracts

新增/修改兼容逻辑必须直接测试正式 product owner：

```text
historical/source facts
-> canonical product owner
-> canonical WeiG result

future/source facts
-> same owner
-> same canonical semantics or honest fail-closed mode
```

测试重点：

- endpoint/action naming 和 parameters；
- response normalization；
- native / normalized / adapter / composition / derived / read-only / unavailable / unknown；
- read/write capability 分离；
- dangerous unsupported/unknown write 在 HTTP 前 fail closed；
- user-visible final state where relevant；
- 不制造 N->N request amplification。

## 7. Cross-platform exact proof

Repo-wide/identity proof 不依赖 working-tree line-ending transformation。

需要 Git blob identity/hash 时：

```text
exact checkout/index
-> canonical tracked path/blob identity
-> canonical Git blob bytes
```

这样 Linux/Windows 均证明同一 repository blob，避免 Windows CRLF checkout 产生 false drift。

Semantic repo-wide inspection 同样要求 target exact SHA + complete relevant tree/blob/file；code search/snippet 只能 discovery。

## 9. Browser fixture discipline

历史 browser fixture 不手写第二份 qB field history。需要 exact release profile 时从 frozen LKG 选取对应 profile。

Critical browser test 必须执行真实 user action并验证 semantic transition + final visible/computed state；不能只断言元素存在或实现字符串。

Stale geometry test 应修正为真实可点击区域，不通过 `force:true`、关闭 pointer checks 或产品 hack 绕过。

## 12. Promote dev to main

未经用户明确授权，禁止修改 `main`、晋级、发布或执行任何可能改变 main 的操作。

授权后仍需：

```text
exact validated dev SHA
relevant source/product/browser evidence
required real-qB LIVE/operator confirmation
fresh main/dev ref checks
safe fast-forward only
```

只允许：

```text
main -> exact validated dev SHA
```

禁止 force、未知 main-only commit overwrite 或为了发布重建不同 artifact。

Tag/Release 应复用同一 exact candidate artifact/checksum。

## 13. SAFE-REF

每次正式写入：

```text
fresh-read dev exact HEAD
-> candidate only parent = that SHA
-> compare exact expected paths
-> validate
-> fresh-read dev immediately before ref update
-> if moved: candidate invalid, rebuild
-> force:false safe fast-forward
-> validate final exact SHA
```

## 14. Red gate discipline

看到红灯先读完整失败日志并区分：

```text
real product bug
upstream/source misunderstanding
owner/caller migration gap
stale implementation-shape test
stale browser/simulator fixture
cross-platform proof bug
profile/evidence problem
source parser problem
CI trigger problem
```

Real upstream/source/canonical runtime truth 优先。正确 gate 抓到真实遗漏时修真正问题；stale evidence/test 则修 test。禁止为了变绿回退正确产品行为、放宽正确 gate、恢复旧 owner 或增加 compat hack。
