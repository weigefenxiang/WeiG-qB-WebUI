## 3. 从 0.3.74 checkpoint 到 0.3.75 已完成什么

### 3.1 Deterministic full native-QM recovery

0.3.74 checkpoint 中尚未闭合的 recovery 架构已经完成：

```text
exact official TS evidence
-> per-release/per-locale recovery votes
-> shard sidecars
-> deterministic merge
-> certified recovery union
-> native QM materialization
```

Canonical winner：

```text
largest occurrence count
-> newest exact stable supporting the candidate
-> lexical/codepoint translation order
```

因此 merge 不依赖 shard完成顺序，必须 associative/order-independent；malformed/conflicting evidence fail closed。

Full recovery translation bodies只能用于 build-time QM recovery，不能重新进入 browser profile JSON。

### 3.2 Settings/source LKG v2

LKG已升级为 v2，冻结 exact source facts 与 recovery identity，包括：

```text
qbVersion
sourceSha
torrentTableColumns
source/bridge facts
recovery union hash
```

Candidate CI已被改造为：

```text
source shard -> .json + .recovery.json
merge -> exact catalog + deterministic recovery sidecar
LKG -> exact-SHA certified artifact
candidate packer -> explicitly consumes the certified LKG
```

不能恢复 packer“没有 LKG也继续”的 permissive fallback。

### 3.3 Native bundle / catalog materialization

Native-capable release使用 certified recovery union生成 qB-native QM；qApp-native保持原生 translator。Runtime release profiles只保留 bounded compatibility facts，build-only recovery/translation bodies剥离。

`4.5.0 -> 4.6.4` Alternative WebUI document translation gap仍走 exact official-TS bridge。Recovery QM完整并不改变这个 source-proven hard boundary。

### 3.4 Legacy dynamicTable comment parser incident

Candidate source shard真实暴露 qB 4.1.0 parser bug：

```text
//Don't round up
```

旧 scanner没有 comment state，把 apostrophe当单引号 string开头，最后报 `TorrentsTable Class: unterminated block`。

修复后的 scanner区分：

```text
code / line-comment / block-comment / string
```

Regression同时锁住 comment里的 quote和 brace。教训：解析 legacy JS block时不能只做 string+brace scanner，也不能用跨 statement宽 regex猜语义。

## 4. 产品侧写能力收口

### 4.1 File Priority

Torrent Details File Priority的 UI与 transport现在共享 exact `torrentscontroller.h:filePrioAction` provenance。

```text
EXACT/EQUIVALENT + action proven -> writable
INHERITED/FALLBACK/unproven       -> fail closed before HTTP
```

Unsupported不是“点了再404”；必须 zero request。

### 4.2 Transfer global / alternative limits

0.3.75新增 composite write capability：

Normal/global Apply全部需要：

```text
setDownloadLimitAction
setUploadLimitAction
toggleSpeedLimitsModeAction
```

Alternative Apply全部需要：

```text
setPreferencesAction
toggleSpeedLimitsModeAction
```

`W.CapabilityRegistry` 的 `allActions` 使用 strict `every()`；Transfer UI按当前 mode动态 decorate，真正 `applyLimits()`前再次 `supports()` preflight，防止部分 action存在时发生 half-write。

这是对现有 Current Owner的 source-expression扩展，不是 owner替换：

```text
source facts    -> W.ReleaseProfile
UI capability   -> W.CapabilityRegistry
transport       -> W.QBClient
```

因此本轮没有为了 `allActions` 新建第二 capability owner，也没有必要把 `DESIGN.md`/`docs/003` 改成另一套 ownership图。

qB upstream核验：4.1.0与5.2.3都存在本次所需 actions；正式 product仍按每个 exact release source facts判断，不能把这个核验偷换成 version-only写策略。

## 6. 本次 docs finalization 的用途

本次只更新 current authority/复盘 docs，不修改 `webui/**`，所以 Product VERSION保持 0.3.75。

建议 coherent commit message：

```text
docs: sync 0.3.75 handoff [candidate]
```

`[candidate]` 不是为了制造空提交，而是让**真实需要的 final docs authority commit**本身成为新的 exact-SHA candidate identity。Push后 CI会按现有规则运行完整 candidate chain。

Candidate结果必须从 Actions真实读取：成功才写 SUCCESS；失败就读具体 job log修 root cause。本文不能预写“candidate已通过”，否则新 commit会形成自证循环。

## 7. Candidate之后仍未自动完成的 release-grade evidence

即使 docs final SHA的 candidate全部成功，以下仍是独立 gate：

```text
Dev Pages exact-final-SHA required evidence
manual Current Stable Locale Matrix all PASS
manual Real qB Full Frozen Matrix all PASS
central release-compat-evidence verifier
formal promotion
main Pages exact reuse/live identity
tag / GitHub Release
```

Docs-only/public-payload-irrelevant classifier可能允许 Dev runtime继续复用 `b92ae7c8...` 的 materialized payload；这不等于 docs final SHA已经拥有 formal release-grade exact Pages evidence。

当前 GitHub connector如果没有新建 workflow_dispatch能力，不得用空 commit、main写入或其它绕过制造这些手工 gate。把它们准确标记为 pending/not run，交给具备 dispatch入口的下一位 AI/用户执行。

用户本轮没有授权 promotion/main/tag/Release，任何 AI都不得提前执行。

## 8. 必须避开的坑

```text
1. 不动 main/tag/Release/promotion，除非用户明确授权。
2. 不 force push；dev ref更新只 safe fast-forward force:false。
3. 每批写入前和 ref update前都 fresh-read dev，防 race。
4. docs/tests/tools/workflow-only change不 bump Product VERSION。
5. old SHA evidence不能证明 new SHA；skipped不能写成 green/PASS。
6. Full recovery translation bodies只能 build/QM，不进 browser profiles。

10. 一个 UI write依赖多个 upstream actions时必须 all-required source-proven，不能 anyActions/部分成功。
```
