# 005. v0.3.7 统一交互与设置系统

Status: **Semantic Feature Parity + Observer-Free Ownership 3.6**

本文记录 v0.3.7 当前统一 UI/runtime contract，以及本问题链为什么必须作为一条系统性修复一次完成。

> **Restore capability, not legacy ownership.**

## 1. 本轮问题链

表面症状包括：

```text
Transfer 的 Peers/DHT/限速信息不稳定
Global upload/download 排列与 dialog geometry 不统一
Torrent 选择区域和标题点击冲突
qB 4.1.9.1 Private/PT 识别不足
statusbar cluster 依赖 DOM 顺序
多个 runtime 通过 Observer 或独立 API lifecycle 做事后同步
```

实际根因是 ownership 分叉：数据 owner、DOM owner、layout owner 与 presentation consumer 没完全分离。

本轮目标不是增加一层 patch，而是：

```text
同一能力只保留一个 semantic owner
source 产生 final DOM
explicit event 替代 DOM observation
presentation 不持有 business/API poll
兼容证据由上游源码/API contract 证明
```

## 3. Observer-free runtime lifecycle

本轮把 first-party runtime `MutationObserver` 作为架构机制彻底退出。

Canonical events：

```text
app.js
  weigg:library-state
  weigg:status-state
  weigg:route-state

settings.js
  weigg:settings-render

transfer.js
  weigg:transfer
  weigg:maindata
```

典型替换：

```text
旧：Layout observe body → DataGrid 出现 → 安装 resize
新：App renderHead 完成 → explicit LayoutRuntime.installGridResize

旧：Responsive observe nav/count → 猜 filter/count 变化
新：App library-state → Responsive sync

旧：Polish observe action dialog → 给按钮补 tone
新：ActionRegistry source renderer 直接写 dataset.actionTone

旧：UX observe whole body → 每次 DOM 变更重翻译
新：canonical owner render/state event → refresh translation
```

## 4. Presentation 不再拥有 API lifecycle

审计中发现 `responsive.js` 虽然已经不再 observer 修 DOM，但仍自己：

```text
new W.QBClient()
getMainData()
30s timer
```

只为了显示 Storage/free-space。

这仍然是 ownership 分叉，因此本轮继续收口：

```text
W.TransferRuntime
  owns one sync/maindata lifecycle
  owns rid + in-flight collapse
  normalizes dhtNodes / peers / freeSpace
  emits weigg:maindata

W.MobileAdaptive
  reads TransferRuntime.snapshot()
  consumes weigg:maindata
  paints Storage only
```

Presentation 层从此不因为“缺一个显示字段”再开自己的 qB polling。

## 5. Transfer — one runtime snapshot

### 5.1 Speed samples

`W.TransferRuntime` 包装现有 `QBClient.getTransferInfo()` 一次：

```text
App existing poll
→ getTransferInfo()
→ TransferRuntime capture sample
→ weigg:transfer
```

不新建第二个 speed poll。

样本最多保留 900 个。

### 5.2 Telemetry metadata

同一个 runtime owner 维护：

```text
sync/maindata
→ dhtNodes
→ peers
→ freeSpace
→ snapshot()
→ weigg:maindata
```

生命周期：

```text
one rid
one metadata in-flight promise
one bounded 30s timer
visibility refresh
```

Stats panel 需要最新 metadata 时调用同一个 owner 的 explicit refresh，而不是再创建另一套 maindata owner。

### 5.3 Stats panel

Canonical 顺序：

```text
Session downloaded | Session uploaded | DHT / Peers
Global upload       | Global download | Free space
```

Chart：

```text
1 min
5 min
15 min
```

如果 `transfer/info` 没有 peer count，maindata snapshot 仍能补齐。

### 5.4 Rate editor

```text
[NORMAL | ALT] [KiB/s | MiB/s | GiB/s]
Upload limit | Download limit
0 = Unlimited
```

上传在左，下载在右。

NORMAL：

```text
transfer/uploadLimit
transfer/downloadLimit
```

ALT：

```text
preferences.alt_up_limit
preferences.alt_dl_limit
```

Apply 后同步 qB Alternative Speed Limits mode。

Limit dialog 是 compact editor，不复用 Stats panel 的大几何。

## 6. Statusbar — named placement

旧问题：Transfer/Storage/Connection 的位置部分依赖哪个脚本先 append、哪个 CSS 最后覆盖。

现在 desktop shell 由 `layout.css` 明确：

```text
grid-template-areas:
"torrent storage transfer connection message"
```

各 cluster 直接声明 `grid-area`。

`polish.css` 不再定义 statusbar grid，只允许视觉 tone/pulse/tooltip。

## 7. Selection — one state, standard file-list semantics

`W.Selection` 仍是唯一 selected Set。

普通点击合同：

```text
row/card 非交互空白区域  -> select only
Ctrl/Cmd click             -> toggle
Shift click                -> range
checkbox                   -> toggle
torrent title/details      -> open detail only
```

这样标题的“进入详情”和行的“选择”不再抢同一个 click owner。

统一动作入口：

```text
Top More
Desktop right-click
Mobile long-press
Mobile More
```

全部使用同一个 `ActionRegistry`。

移动端 checkbox/select hit target 至少 44×44 CSS px；视觉 checkbox 可以较小，但可点击 label 区域不能小。

## 8. Select — source canonicalization

本轮不保留“页面先生成旧 Select，再 observer 自动升级”的模式。

Visible custom Select 由业务/source owner直接调用：

```text
W.Components.selectControl()
```

已覆盖：

```text
Settings enum/timezone/etc
Selection action control
Transfer chart window/unit
mobile sort/filter
file priority
page-size runtime control
```

Settings 不再提供 native fallback。

## 9. Private / PT — qB5 authoritative + qB4 source-backed

### 9.1 Classification

```text
PRIVATE_PT
PRIVATE
PT
PUBLIC
UNKNOWN
```

### 9.2 qB5 / explicit metadata

存在 `private` / equivalent field 时直接使用。

### 9.3 Magnet metadata pending

```text
has_metadata=false
state=metaDL / forcedMetaDL
```

必须返回 `UNKNOWN`，不能提前标 Public。

### 9.4 qB 4.1.9.1 upstream evidence

我们核对了上游 `release-4.1.9.1` 的 `src/webui/api/torrentscontroller.cpp`。

其 `getStickyTrackers()` 为每个 Torrent 生成：

```text
** [DHT] **
** [PeX] **
** [LSD] **
```

上游源码逻辑：

```text
privateMsg = localized "This torrent is private"
isTorrentPrivate = torrent->isPrivate()

DHT.msg = private ? privateMsg : ""
PeX.msg = private ? privateMsg : ""
LSD.msg = private ? privateMsg : ""
```

而 status 还会受全局 DHT/PeX/LSD 开关影响。

所以最终算法不是比较英文，也不是看 status：

```text
3 sticky rows present
+ all msg non-empty
+ all msg equal
=> Private

all 3 msg empty
=> Public

otherwise
=> Unknown
```

这个算法兼容 qB 自己的本地化文案，并避免把“Public + 用户关闭 DHT”误判成 Private。

### 9.5 PT tracker rules

WeiG 的 PT domain rules 只负责 supplemental PT classification：

```text
Private source = qB semantic evidence
PT source      = configured tracker hostname rules
```

## 18. CI / exact-HEAD rule

本问题链固定流程：

```text
1. temp branch 一次完成代码 + tests + docs
2. cumulative diff audit
3. ownership/static pre-audit
4. 用 final temp tree 创建 dev 的单一 [ui] commit
5. exact dev HEAD 只跑一次统一 dev CI
6. CI 红 -> 读完整失败 → 集中修一批 → 新 exact HEAD 再完整验证
7. 全绿才称为 LIVE candidate
```

禁止“改一点 → 跑一次 CI → 再改一点”。

## 19. Release boundary

本问题链完成后也只得到 **dev exact-SHA LIVE candidate**：

```text
main untouched
Release untouched
```

下一步必须把同一个 exact SHA 部署到真实：

```text
qB 4.1.9.1
qB 5.2.0
```

真实 LIVE 全部通过后仍要用户明确授权，才能进入 main/Release 流程。
