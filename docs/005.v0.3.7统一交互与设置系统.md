# 005. v0.3.7 统一交互与设置系统

Status: **Clean Settings + Semantic Feature Parity 3.5**

本文记录 v0.3.7 当前已经收敛后的统一 UI / runtime contract。目标不是保留某个历史版本的实现，而是保证：**用户能力不丢失，同时每一种能力只保留一个 semantic owner。**

> Restore capability, not legacy ownership.

## 1. 全局硬规则

```text
one semantic purpose -> one canonical owner
stable semantic runtime filename
no old + new parallel runtime
no hidden versioned loader
no post-render repair as permanent architecture
qB 4.1.9.1 compatibility remains in QBClient
Reduced Motion is mandatory
exact Git SHA is code/cache identity
```

当前 runtime 不通过 `vNNN.js/css` 保存历史实现；历史只存在于 Git history。

## 2. Canonical owner map

```text
Settings DOM / save flow      -> W.SettingsRenderer / W.SettingsState
Settings controls             -> W.ControlRegistry + W.Components
Torrent selection/state       -> W.Selection
Torrent action registry       -> W.Selection.actions (ActionRegistry)
Transfer sample stream        -> W.TransferRuntime
Transfer panel + rate editor  -> W.Transfer
Torrent field registry        -> W.TorrentFieldRegistry
Adaptive UI behavior          -> W.UiSystem
Responsive viewport           -> W.MobileAdaptive
DataGrid/dialog normalization -> W.LayoutRuntime
Status/tooltip/action polish  -> W.PolishRuntime
Facet shelf/connection dock   -> W.SpatialRuntime
Brand/logo/favicon/motion     -> W.Brand + W.AmbientMark
Torrent progress motion       -> css/progress.css
Session/logout/BFCache        -> W.SessionController / SessionGate
qB compatibility              -> W.QBClient
```

任何入口不得为了方便再创建第二个 Set、第二个 action list、第二个 Transfer dialog 或第二个 Brand renderer。

## 3. Settings — Clean Cut

普通可编辑设置直接由 source renderer 输出最终结构：

```text
SettingsSection
└─ SettingsGrid
   └─ SettingRow
      ├─ SettingCopy
      └─ SettingControlSlot
```

Wide desktop：

```text
SettingsGrid = repeat(2,minmax(0,1fr))
```

Narrow/mobile：

```text
SettingsGrid = one column
```

普通 row：

```text
span = 1
copy = left aligned
control = right aligned
```

禁止恢复：

```text
.settings-control
.settings-row--canonical
.settings-group repair
centered FormRail
key-name full-span heuristic
Settings MutationObserver 搬行/包装
Settings setTimeout repair
CSS-order compatibility layer
```

Language / Time zone 是 WeiG Settings 的正常源数据项，不由历史 observer 后插入。

## 4. Selection — 一个状态模型

`W.Selection` 是 Torrent selection 的唯一 runtime state owner。

它负责：

```text
single selected Set
select current page
invert current page
select all matching filters
invert all matching filters
clear selection
Ctrl/Cmd toggle
Shift range selection
Ctrl/Cmd+A current-page selection
Escape clear
selection count
row/checkbox selected state
Start/Pause/More/Delete enable state
```

`app.js` 只能消费 `W.Selection`；不得重新创建 `selected: new Set()` 或第二套 toolbar selection state。

“选择全部筛选结果”按 conceptual dataset 工作，不按当前 VirtualList 已挂载 DOM 工作：

```text
current query/filter contract
        ↓
QBClient paged scan
        ↓
matching hashes
        ↓
W.Selection
```

因此分页 50 条时仍可选中 80、800 或更多匹配 Torrent。

## 5. Torrent ActionRegistry — 所有入口同一份动作

`W.Selection.actions` 是 Torrent actions 的唯一 registry。

统一入口：

```text
Top toolbar More
Desktop right click
Mobile long press
Mobile row More
```

这些入口不得分别维护 action list。

当前 registry 包括：

```text
Start
Pause / Stop
Force start
Recheck
Reannounce
Sequential download
First / last piece priority
Automatic torrent management
Queue top / bottom
Rename
Location
Category
Tags (when supported)
Download / upload limit
View details (single selection)
Delete
```

批量请求按 hash chunk 执行；qB endpoint 差异仍由 `QBClient` 处理。

## 6. Query / scroll boundary

以下变化代表新的 conceptual result set：

```text
filter
tracker
save path
category
tag
search query
sort
page
page size
```

因此 Torrent list 主滚动位置 reset 到 0，并按交互语义清除失效 selection。

从 Torrent detail 返回原列表不是新的 query。`Navigation` 保存进入详情前的 route/hash 与 `scrollTop`，返回时恢复原 conceptual list position。

结论：

```text
query change -> reset scroll
detail back  -> restore scroll
```

## 7. Empty result contract

零匹配结果时 `.torrent-panel.is-empty` 成为明确状态。DataGrid head/list/pager 退出主视觉，empty state 成为当前内容；不保留一个看似仍可滚动的空数据区域。

## 8. Transfer — 一个 sample stream，两个明确入口

### 8.1 Runtime sample owner

`W.TransferRuntime` 包装现有 `QBClient.getTransferInfo()` 数据流，保存有限样本并派发：

```text
weigg:transfer
```

Transfer chart 不得新建第二套 `getTransferInfo()` polling loop。

### 8.2 Status capsule

StatusDock 中只有一个 `#transfer-capsule`，提供两个明确 affordance：

```text
DL / UL live values -> realtime Transfer panel
↕                  -> global rate editor
```

ALT active 时 capsule 使用 alternative-rate semantic tone。

### 8.3 Realtime Transfer panel

Canonical panel：

```text
Session downloaded
Session uploaded
Global DL limit
Global UL limit
DHT / Peers
Free space
Transfer chart
  1 min
  5 min
  15 min
```

Canvas chart 直接消费 `W.TransferRuntime.samples()`。

### 8.4 NORMAL / ALT rate editor

同一个 `W.Transfer` owner 同时编辑：

```text
NORMAL
  transfer/downloadLimit
  transfer/uploadLimit

ALT
  preferences.alt_dl_limit
  preferences.alt_up_limit
```

Apply 后按用户选择同步 qB Alternative Speed Limits mode。

不得在 `ui.js`、`polish.js` 或其它 feature 再建立 Transfer dialog/capsule。

## 9. Transfer modal geometry / scroll ownership

Desktop：

```text
dialog outer overflow = hidden
header fixed in dialog grid
body normal content owner
footer/actions fixed in dialog grid
```

普通桌面高度不允许整个 modal 自己出现多余 scrollbar。只有 narrow/mobile 或 very short viewport 才允许 `.dialog__body` 成为纵向 scroll owner。

## 10. Torrent progress motion

`css/progress.css` 是 Torrent progress 的唯一 motion owner。业务数据仍只决定 progress percentage -> width；视觉层增加 width transition、flow stripes 与 shine sweep。

100% 完成后停止装饰动画。

必须同时支持：

```text
@media(prefers-reduced-motion:reduce)
html[data-motion="reduced"]
```

Reduced Motion 下 flow/sweep 禁用，width transition 接近即时。

## 11. Semantic bootstrap contract

把文件从 `*-vNNN.js` 改成 semantic filename 不代表迁移完成。任何 active behavior module 必须满足二选一：

```text
A. self-start on DOMContentLoaded
or
B. explicitly started by one canonical bootstrap owner
```

当前 `Selection`、`Transfer`、`LayoutRuntime`、`PolishRuntime`、`SpatialRuntime` 均建立明确启动链。

禁止：

```text
export .init but nobody calls it
rely on script order to accidentally activate behavior
keep old bootstrap only to start renamed module
```

## 12. Hidden loader / zombie policy

Semantic runtime 不得动态请求已删除的版本资产。本轮明确删除的 zombie pattern 包括：

```text
advanced-v036.js loader
mobile-v036.css loader
ui-polish-v037.css loader
brand-v031.css loader
Spatial legacy Settings observer/repair
Polish duplicate Transfer owner
UI duplicate Transfer owner
app.js duplicate Selection/action owner
```

如果一个旧文件只剩“防止旧 loader 再加载它”的 alias，正确处理顺序是：

```text
delete loader
→ delete alias
```

而不是永久保留 alias。

## 13. Brand ownership

Logo、Header Brand、About BrandIdentity、favicon 与 AmbientMark 均归 canonical Brand 系统。`spatial.js` 不再加载旧 Brand CSS，也不再直接重建/绘制第二个 Header Brand。

```text
W.Brand
├─ normalizeHeader
├─ createIdentity
├─ cloneMark
├─ ensureFavicon
└─ iconUrl

W.AmbientMark
└─ shared motion engine
```

## 15. Static ownership gate

`tests/runtime-contract.mjs` 除了检查 semantic runtime filenames，还必须阻止：

```text
hidden *-vNNN.js/css loader
second Selection Set in app.js
second Transfer owner in ui.js/polish.js
orphan/non-starting LayoutRuntime / PolishRuntime
Spatial hidden brand/settings repair layer
removed AdvancedSettings alias
missing progress motion owner
```

Static gate 的作用是提前阻止“页面暂时能跑，但 architecture 已经重新分叉”的提交。

## 16. CI / exact-HEAD rule

本问题链不采用“改一点跑一次 CI”。流程固定为：

```text
1. temp branch 完成同链全部代码修改
2. tests + docs 同步
3. cumulative diff audit
4. static/syntax pre-audit
5. 用 final tree 创建 dev 的单个 [ui] commit
6. 记录 exact dev HEAD SHA
7. 只验证该 SHA 的 smoke + focused Chromium
8. CI 红 -> 集中修复 -> 新 exact SHA 重新完整验证
9. 全绿后才汇报 candidate 状态
```

旧 SHA 的绿灯不能证明新代码；任何 code/test/doc commit 都产生新的 exact candidate。

## 17. Release boundary

本轮只负责 dev feature-parity candidate：

```text
main untouched
Release untouched
```

只有进入单独 Release 流程后，才允许将经过要求验证的 exact SHA 晋级 main，并执行 full stable-tag / Linux / Windows / multi-viewport candidate audit。
