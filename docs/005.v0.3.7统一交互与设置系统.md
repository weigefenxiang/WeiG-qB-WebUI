# 005. v0.3.7 统一交互与设置系统

Status: **Semantic Feature Parity + Single Ownership 3.7**

本文记录 v0.3.7 当前统一 UI/runtime contract，以及本问题链为什么必须作为一条系统性修复一次完成。

> **Restore capability, not legacy ownership.**

## 1. 本轮用户可见问题

本问题链同时覆盖手机与网页端：

```text
qB4 Private/PT 大库加载非常慢
第 1 / ? 页长时间不结束
RSS -> Settings 后 RSS 仍显示 active
Torrent filter -> Settings 后 Torrent sidebar 仍留在设置页
Desktop Torrent 数据 panel 没有填满 workspace 剩余高度
Transfer 1 min 时间窗口过短且不能扩展
Transfer MiB/s 在 modal 内点击没有可靠反应
ALT rate unit 与 NORMAL unit 语义混淆
旧 Route/Spatial/UX/布局层有重叠 ownership 风险
```

这些不是独立“小 CSS bug”。共同根因是：

```text
capability compatibility 与性能预算脱节
route state 有多个 writer
page total 与首屏渲染耦合
fixed height 与 flex shell 双 owner
modal top layer 与 body portal 交互冲突
API unit conversion 泄漏到 UI owner
```

因此按一条问题链整体收口，而不是加版本文件、Observer、兼容覆盖层。

## 3. Route Frame — 从多个 writer 收回 app.js

`app.js` 现在一次提交：

```text
active view
Top nav active state
Mobile nav active state
sidebar/tool-route scope
Back button state
drawer close
weigg:route-state
```

`ux.js` 删除 route binding/active class writer；`spatial.js` 删除 route shell writer。

因此：

```text
RSS -> Settings
=> RSS active 立即退出
=> Settings active
=> Torrent sidebar 不再残留

Torrent 下载中/做种/... -> Settings
=> library filter state 可以保留
=> 但整个 library sidebar shell 不进入 Settings route
```

这解决“视觉已经到设置页，但左侧还是 Torrent 页面”的半路由状态。

## 4. qB4 Private / PT — capability degradation，而不是逐种子模拟

上一版为了兼容 qB4，曾尝试通过每个 Torrent 的 tracker/sticky discovery 信息推断 Private。

在少量 Torrent 上可工作，但 collection filter 会形成：

```text
N torrents
→ N metadata/tracker enrich requests
→ concurrency queue
→ page/filter waits for enrichment
```

这违反大库性能目标。

最终 clean cut：

```text
qB 5.0.0+
  authoritative collection `private` metadata
  Private/PT filter enabled

qB 4.x
  Private/PT entry still visible
  small 5+ capability marker
  click -> neutral capability dialog
  no filter switch
  no tracker scan
  no per-torrent privacy queue/cache
```

普通用户提示只包括：

```text
requires qBittorrent 5.0.0+
current version
consider upgrading if the feature is needed
back up configuration/tasks/important data before upgrade
```

不向用户解释内部 WebAPI、逐种子请求或性能实现细节。

这形成长期规则：**旧版本难以低成本正确实现的新功能，默认做 capability degradation，而不是为了“版本全支持”牺牲性能。**

## 5. Progressive paging — 当前页不等待总页数

旧状态把 `catalogReady` 和精确 total pages 绑定，导致大库长期：

```text
第 1 / ? 页
```

新流程：

```text
GET current page with pageSize + 1
→ first page renders immediately
→ extra item only tells hasNext

background catalog
→ independently accumulates exact total
→ once ready, page label becomes 第 X / Y 页
```

Catalog 未完成时：

```text
[small CSS ring] 第 1 页 · 每页 50
```

不再显示 `?`。

Catalog error 也不阻塞当前 page；只把 loading ring 变成轻量 error indicator。

## 6. Desktop Torrent panel — flex-fill 单 Owner

旧 `app.css` 包含：

```text
height:min(62vh,660px)
mobile calc(100svh - 360px)
mobile calc(100svh - 390px)
```

与此同时 layout 又试图用 flex shell 管剩余高度，形成双 owner。

最终：

```text
css/layout.css
  owns workspace height
  owns #list-view flex column
  owns .torrent-panel flex-fill
  owns #torrent-list flex:1
```

旧固定高度从 `app.css` 删除。

Desktop 上 Torrent panel 现在跟随 workspace 剩余空间延伸，和左侧工作区高度关系稳定；手机继续使用同一个 primary-scroll/flex contract。

`spatial.css` 不再拥有 `.app-shell.is-tool-route` geometry。

## 7. Select — 同一 primitive 的 floating / native 两种 presentation

过去 modal 内继续使用 body-level FloatingLayer，会遇到 browser top layer：trigger 在 dialog 内，menu portal 在 body 常规 stacking context。

这类问题不再用 z-index 继续堆。

`W.Components.selectControl()` 现在明确支持：

```text
Default
  canonical floating trigger/menu

native:true
  canonical wrapper + one native <select>
```

不是两套工具：同一个 owner、同一个 options/value/onChange contract，只是 presentation mode 不同。

Transfer modal 的：

```text
Chart time window
Rate unit
```

都使用 `native:true`，让 browser 负责 top-layer-safe dropdown interaction。

## 8. Transfer history — 12h 但不增加网络负担

原来 raw samples：

```text
MAX = 900
1 / 5 / 15 min
```

新设计保留 raw detail，同时新增 bounded minute buckets：

```text
RAW_MAX = 900
BUCKET_MAX = 720
1 bucket / minute
```

可选窗口：

```text
1 min
5 min
15 min
30 min
1 h
3 h
6 h
12 h
```

短窗口使用 raw samples；长窗口使用 minute aggregation。

关键性能合同：

```text
no extra transfer polling
no new server-side storage
no persistent speed-history localStorage
no unbounded arrays
```

History 只在当前页面内存里，浏览器刷新后清空。

## 9. Transfer rate unit — UI 统一 B/s，QBClient 处理 API 差异

这里发现了一个容易长期复发的系统性问题：qB NORMAL 与 ALT 使用不同 API unit。

```text
NORMAL transfer limits = B/s
ALT preferences limits  = KiB/s
```

旧 UI 直接把 `prefs.alt_*_limit` 当 B/s 使用，存在 1024 倍语义风险。

最终边界：

```text
W.Transfer
  always B/s

W.QBClient.getAltSpeedLimits()
  KiB/s -> B/s

W.QBClient.setAltSpeedLimits()
  B/s -> KiB/s
```

Unit conversion 不再泄漏到 Transfer UI。

## 10. Rate editor UI

最终结构：

```text
[NORMAL | ALT] [Auto / KiB/s / MiB/s / GiB/s]

Upload limit | Download limit

0 = Unlimited
```

上传在左，下载在右。

输入：

```text
input.step = any
```

显示采用紧凑有效数字，而不是固定两位小数。这样把较小速率切到 GiB/s 时仍能看到实际非零值，不会被 `0.00` 伪装成 0。

`Auto` 由当前值选择合适 display unit；显式单位用于查看/输入，最终都转换回 canonical B/s。

## 11. Transfer Status / Stats

Status capsule 仍是一个 owner：

```text
↓ rate ↑ rate -> Stats
↕             -> Rate editor
```

Desktop statusbar 由 `layout.css` named grid 固定：

```text
"torrent storage transfer connection message"
```

Stats 顺序：

```text
Session downloaded | Session uploaded | DHT / Peers
Global upload       | Global download | Free space
```

DHT/Peers/free-space 来自同一个 `TransferRuntime` maindata snapshot；Responsive 不另开 QBClient。

## 12. Selection / Torrent card

`W.Selection` 继续是唯一 selected Set。

```text
row/card non-interactive click -> select only
title                         -> detail only
checkbox                      -> toggle
Ctrl/Cmd                      -> toggle
Shift                         -> range
right click                   -> ActionRegistry
mobile long press             -> same ActionRegistry
More                          -> same ActionRegistry
```

移动选择 hit-area >=44×44 CSS px。

## 13. Settings / Responsive / Spatial / Polish / UX

Settings：source-final `SettingsGrid/SettingRow`，不恢复 native fallback/Observer。

Responsive：可以 fit text、移动 toolbar、同步 mobile filter、调整 row height；不持有 API lifecycle。

Spatial：facet shelf / connection dock presentation only，不再接管 Route Frame。

Polish：final tone/tooltip only，不接管 statusbar/Transfer/Route geometry。

UX：消费 semantic lifecycle 做语言/上下文同步，不再 bind route active state。

## 14. 系统性问题总结

本轮确认了以下高频错误模式：

```text
A. 为兼容旧版本新增 per-item 网络扫描，功能正确但大库不可用。
B. 为拿 total/page count 阻塞首屏。
C. 同一 route active state 被多个脚本写。
D. fixed vh 和 flex shell 同时拥有高度。
E. browser top layer 问题用更多 z-index/portal patch 处理。
F. API 单位差异由 UI feature 各自换算。
G. 时间范围扩大直接等于 raw history 无限扩大。
H. Browser test 只检查 DOM 存在，没有实际操作 control。
I. post-render Observer/CSS override 代替 source-owner 修复。
J. 新实现上线后旧 Current Owner 没真正退出 runtime。
```

固定处理方式：

```text
identify Current Owner
→ inspect API/capability/performance budget
→ normalize data/unit at adapter boundary
→ source-final component
→ explicit lifecycle
→ single geometry owner
→ delete old owner
→ static owner gate
→ real interaction browser gate
```

## 15. 写入硬规则

本轮新增/确认：

```text
OWNER-001
一个功能一个 Current Owner；canonical replacement 完成后旧 owner 必须退出 runtime。

COMPAT-DEGRADE-001
缺少能力且正确模拟代价高时，用中立 minimum-version degradation。

PERF-COMPAT-001
默认禁止 O(N) / N-per-item 网络兼容工作；必要时需开发者明确确认性能预算。

PROGRESSIVE-DATA-001
当前页/首屏 usefulness 不等待全量 total/enrichment。

ROUTE-OWNER-001
app.js 唯一提交 Route Frame state。

SELECT-TOPLAYER-001
Modal/top-layer 下 canonical Select 可使用 native presentation，不再叠 portal workaround。

RATE-UNIT-001
WeiG rate business unit = B/s；QBClient 独占 API-unit conversion。

TIMESERIES-001
扩展时间窗必须 bounded + aggregated，不能提高 API polling frequency。

LAYOUT-OWNER-001
layout.css 独占 route/status/Torrent viewport geometry。

INTERACTION-TEST-001
关键控件必须用真实 click/selectOption/input/apply 验证，不能只 assert DOM。

EXACT-HEAD-001
任何 code/test/doc change 都生成新的 candidate SHA。
```

## 18. CI / exact-HEAD workflow

本问题链固定：

```text
1. temp branch 一次完成 code + tests + docs
2. cumulative diff audit
3. static/ownership pre-audit
4. 把 final temp tree squash 成 base dev 的一个直接子 commit
5. fast-forward dev 到这个 single final commit
6. 对 exact dev HEAD 跑统一 dev gates
7. CI 红 -> 读完整失败链 -> 集中修一批 -> 新 exact HEAD 再验证
8. 全绿才称为 LIVE candidate
```

不做“改一点就跑一次 CI”。

## 19. LIVE / Release boundary

当前问题链完成也只产生 **dev exact-SHA LIVE candidate**。

```text
main remains v0.3.6 until LIVE passes
Release untouched
```

下一步仍必须把同一个 exact SHA 部署真实：

```text

```

真实 LIVE 全部通过后，还要用户明确授权，才能进入 main/Release。
