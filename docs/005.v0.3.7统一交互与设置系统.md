## 2. Preference unit contract

A numeric field may show a unit only when the qBittorrent API/source semantics are verified. The schema owns:

```text
apiUnit
displayUnit
scale
special value meanings
```

Examples:

```text
dl_limit                 API B/s   -> display KiB/s
up_limit                 API B/s   -> display KiB/s
alt_dl_limit             API B/s   -> display KiB/s
alt_up_limit             API B/s   -> display KiB/s
socket_receive_buffer    API B     -> display KiB
torrent_file_size_limit  API B     -> display MiB
web_ui_ban_duration      API s     -> display s
listen/web-ui/proxy port           -> display port
```

The display layer must round-trip to the original API representation exactly.

## 3. Translation contract

English remains canonical. For non-English Advanced settings:

1. If a verified qBittorrent translation exists, use it as the visible label.
2. If no verified translation is bundled, keep the visible English label.
3. Provide a SettingHelp surface containing the WeiG translation/explanation.
4. Translation records and provenance live outside business logic in `webui/private/translations/settings-official-v037.js`.
5. The help surface clearly distinguishes `qBittorrent official` from `WeiG explanation`.
6. SettingHelp uses the same body-level FloatingLayer portal as other floating controls.

Special values such as `0 = System default`, `0 = Disabled`, `0 = Permanent lease`, and verified `-1` meanings are shown only for fields whose semantics are known.

## 4. Selection contract

Selection is conceptual state, not DOM state.

```text
Current page
Invert current page
All matching query
Invert all matching query
Clear
```

Paging does not clear selection. A meaningful filter/search/facet change does clear it to prevent destructive actions from applying to a different query.

Current-page selection is based on the current page data model, not the number of mounted VirtualList rows. Large actions resolve hashes and dispatch in bounded chunks instead of building one unbounded request.

## 5. Torrent action contract

All action-oriented interaction routes open the same action model:

```text
Toolbar More
Mobile card More
Desktop right-click
Mobile long-press
```

The existing desktop row detail affordance remains a Detail navigation control rather than being silently repurposed. Long press is cancelled when pointer movement indicates scrolling. Buttons, checkboxes and links never start the long-press timer.

## 6. DataGrid resize contract

During column drag:

```text
pointermove
 -> requestAnimationFrame
 -> CSS grid template update
```

Forbidden during pointermove:

```text
VirtualList.render()
DOM row reconstruction
API requests
persistent storage writes
```

On pointerup, the final width is persisted and one reconciliation render is allowed.

## 7. Adaptive dialog contract

Dialogs use three tracks:

```text
Header
Body
Footer
```

Only Body may scroll, and only when content is taller than the available dynamic viewport. A desktop Add Torrent dialog with enough space must not show a scrollbar.

## 8. Mobile shell contract

Phone layout uses the dynamic viewport:

```text
Topbar                  auto
Workspace               minmax(0, 1fr)
Bottom navigation       auto + safe area
```

The former fixed mobile status row is removed from the layout. Status/system metadata moves into the hamburger drawer on phones. Therefore Torrent, Settings, Search, RSS, Logs and Detail all extend to the top edge of Bottom Navigation.

Bottom Navigation uses a horizontal icon + label arrangement and must stay on one line.

## 9. Mobile Settings navigation

Desktop keeps the Settings category rail.

On phones, Settings categories move into the hamburger drawer directly after Torrent filters:

```text
WeiG WebUI
Downloads
Connection
Speed
BitTorrent
Web UI
Advanced
About
```

This prevents category navigation from consuming the Settings workspace height.
