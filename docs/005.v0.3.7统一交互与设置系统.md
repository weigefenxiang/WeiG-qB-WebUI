# 005. v0.3.7 统一交互与设置系统

Status: **Semantic Feature Parity + Single Ownership 3.7**

本文记录 v0.3.7 当前统一 UI/runtime contract，以及本问题链为什么必须作为一条系统性修复一次完成。

> **Restore capability, not legacy ownership.**

## 1. 本问题链覆盖的用户可见问题

本轮问题同时覆盖网页与手机：

```text
qB4 Private/PT 大库兼容曾触发高成本逐种子扫描
第 1 / ? 页长时间不结束
RSS -> Settings 后 route presentation 不原子
Desktop Torrent panel 没有稳定填满 workspace
Transfer modal 的 Select 在 top layer 中交互不可靠
NORMAL / ALT rate unit 语义曾混淆
Rate dialog 曾在权威限速加载前开放，快速切单位可把空值捕获为 0
Private/PT capability dialog 在手机/部分网页视口出现无意义滚动条
暗黑模式下 1 min / Auto · KiB/s native Select 退回过亮 browser-default 外观
Select behavior 已统一但 visual skin 仍曾由 Transfer feature 局部拥有
Selection 仍残留已删除 qB4 Private resolveMany 的不可达兼容 caller
```

这些不是独立“小 CSS bug”。共同根因是：

```text
capability compatibility 与性能预算脱节
route state 有多个 writer/interceptor
page total 与首屏渲染耦合
fixed height 与 flex shell 双 owner
modal top layer 与 body portal 交互冲突
API unit conversion 泄漏到 UI owner
shared primitive behavior 与 visual skin ownership 分裂
generic dialog overflow 与 feature-local repair 双 owner
canonical 删除后 dormant caller 没一起退出 runtime
async editable surface 在 authoritative data ready 前开放
```

因此按一条问题链整体收口，而不是加版本文件、Observer、兼容覆盖层或 feature-local 暗黑补丁。

## 3. Route Frame — 从多个 writer 收回 app.js

`app.js` 一次提交：

```text
active view
Top nav active state
Mobile nav active state
sidebar/tool-route scope
Back button state
drawer close
weigg:route-state
```

`ux.js` 不写 route active；`spatial.js` 不写 route shell；`settings.js` 只拥有 Settings 内容/Tab/保存，不再通过 capture-phase `hashchange + stopImmediatePropagation()` 抢 Route Frame。

因此：

```text
RSS -> Settings
=> RSS active 立即退出
=> Settings active
=> Torrent sidebar 不再残留
```

## 4. qB4 Private / PT — capability degradation，而不是逐种子模拟

高成本旧方案会形成：

```text
N torrents
→ N metadata/tracker enrich requests
→ concurrency queue
→ page/filter waits for enrichment
```

最终 clean cut：

```text
qB 5.0.0+
  authoritative collection `private` metadata
  Private/PT filter enabled

qB 4.x
  Private/PT entry still visible
  small 5+ capability marker
  click -> neutral capability dialog
  no filter switch
  no tracker scan
  no per-torrent privacy queue/cache
```

普通用户提示只包括最低版本、当前版本、如需功能建议升级、升级前备份；不暴露内部 API/性能实现。

`W.Selection.selectAllMatching()` 也删除了 `TorrentSemantics.resolveMany` 的旧不可达 caller，避免已退出的兼容路径以后被误复活。

## 5. Capability Dialog — 使用 canonical Dialog Surface

原问题不是 Private/PT 自己“设计丑”，而是 generic dialog scroll ownership 错了：

```text
旧 app.css mobile
  dialog { overflow:auto }

Transfer
  再局部 overflow:hidden / body scroll
```

于是 generic shell 和 feature CSS 同时拥有 scroll behavior。

现在统一：

```text
css/ui.css
  dialog.dialog outer shell -> overflow:hidden
  head                     -> intrinsic
  body/form/action-list    -> only scroll on real overflow
  actions                  -> intrinsic

feature CSS
  only geometry variables
```

Private/PT capability dialog 只声明：

```text
--dialog-width:470px
--dialog-max-width:470px
```

不再使用 `width:...!important` 对抗 shared primitive。

Acceptance：

```text
Desktop qB4 capability dialog
  outer scrollbar = none
  body scrollbar  = none

Mobile qB4 capability dialog
  outer scrollbar = none
  body scrollbar  = none
```

如果未来 dialog 内容真的超过 viewport，只有 canonical internal body/form/action-list 才允许滚动。

## 6. Select — behavior 与 visual skin 都有唯一 Owner

`W.Components.selectControl()` 仍是唯一 behavior/presentation owner：

```text
floating mode
native:true mode
```

本轮进一步把 visual ownership 收口：

```text
css/ui.css
  floating Select skin
  native Select skin
  default / hover / focus / disabled
  native option / optgroup surface
  light/dark color-scheme
```

Feature CSS 只能给 geometry：

```text
--ui-select-h
--ui-select-width
```

`transfer.css` 已删除 `.ui-select__native` 皮肤，不再单独设计 `1 min` 或 `Auto · KiB/s`。

## 7. Dark native Select — 一个主题合同

暗黑模式不允许 native `<select>` 回退成突兀白色 browser-default island。

Canonical theme：

```text
html[data-theme=dark]
  --ui-native-scheme: dark
  control surface  -> shared elevated token
  border           -> shared control border token
  text             -> shared primary text
  option surface   -> shared floating token

html[data-theme=light]
  --ui-native-scheme: light
  same semantic roles resolve to light tokens
```

Transfer Stats 的 `1 min` 和 Rate dialog 的 `Auto · KiB/s` 现在必须得到同一 computed background/text/border/option theme；这不是两份 CSS。

设计方法参考 `VoltAgent/awesome-design-md` 的 design-system discipline：使用明确 tokens、surface hierarchy、hairline boundary、reusable components 和 restrained accents；WeiG 保留自己的 Nebula Spatial Console palette，不复制其它产品颜色。

## 8. Progressive paging — 当前页不等待总页数

```text
GET current page with pageSize + 1
→ first page renders immediately
→ extra item only tells hasNext

background catalog
→ independently accumulates exact total
→ once ready, page label becomes 第 X / Y 页
```

Catalog 未完成时：

```text
[small CSS ring] 第 1 页 · 每页 50
```

不再显示 `?`。

## 9. Desktop Torrent panel — flex-fill 单 Owner

最终：

```text
css/layout.css
  owns workspace height
  owns #list-view flex column
  owns .torrent-panel flex-fill
  owns #torrent-list flex:1
```

旧 `62vh/660px` 与手机 `calc(100svh - Npx)` fixed height 不再和 flex shell 双重拥有 viewport。

## 10. Transfer history — 12h 但不增加网络负担

```text
RAW_MAX = 900
BUCKET_MAX = 720
1 bucket / minute
```

可选窗口：

```text
1 min / 5 min / 15 min / 30 min / 1 h / 3 h / 6 h / 12 h
```

短窗口使用 raw samples；长窗口使用 minute aggregation。

```text
no extra transfer polling
no new server-side storage
no persistent speed-history localStorage
no unbounded arrays
```

## 11. Transfer rate unit — UI 统一 B/s，QBClient 处理 API 差异

```text
NORMAL transfer limits = B/s
ALT preferences limits = KiB/s
```

最终边界：

```text
W.Transfer
  always B/s

W.QBClient.getAltSpeedLimits()
  KiB/s -> B/s

W.QBClient.setAltSpeedLimits()
  B/s -> KiB/s
```

Unit conversion 不再泄漏到 Transfer UI。

## 12. Rate editor — authoritative load before interaction

结构：

```text
[NORMAL | ALT] [Auto / KiB/s / MiB/s / GiB/s]
Upload limit | Download limit
0 = Unlimited
```

输入 `step=any`；显示采用紧凑有效数字，避免小值切 GiB/s 被显示成 0。

本轮此前 Chromium 抓到的真实 race：

```text
old
showModal()
→ async loadLimits()
→ user can change unit while inputs are empty
→ captureLimits() stores 0

new
await loadLimits()
→ paint authoritative state
→ showModal()
```

所以 visible/editable 第一帧必须已经是 qB 权威值。

`W.Selection` 是唯一 selected Set。

```text
row/card non-interactive click -> select only
title                         -> detail only
checkbox                      -> toggle
Ctrl/Cmd                      -> toggle
Shift                         -> range
right click                   -> ActionRegistry
mobile long press             -> same ActionRegistry
More                          -> same ActionRegistry
```

移动选择 hit-area >=44×44 CSS px。

## 15. Settings / Responsive / Spatial / Polish / UX

Settings：source-final `SettingsGrid/SettingRow`；不恢复 route interceptor/native fallback/Observer。

Responsive：可以 fit text、移动 toolbar、同步 mobile filter、调整 row height；不持有 API lifecycle。

Spatial：facet shelf / connection dock presentation only，不接管 Route Frame。

Polish：final tone/tooltip only，不接管 statusbar/Transfer/Route/Dialog/Select skin。

UX：消费 semantic lifecycle 做语言/上下文同步，不 bind route active state。

## 16. 系统性问题总结

本轮确认的高频错误模式：

```text
A. 为兼容旧版本新增 per-item 网络扫描，功能正确但大库不可用。
B. 为拿 total/page count 阻塞首屏。
C. 同一 route active state 被多个脚本写或拦截。
D. fixed vh 和 flex shell 同时拥有高度。
E. browser top layer 问题用更多 z-index/portal patch 处理。
F. API 单位差异由 UI feature 各自换算。
G. 时间范围扩大直接等于 raw history 无限扩大。
H. Browser test 只检查 DOM 存在，没有实际操作 control。
I. post-render Observer/CSS override 代替 source-owner 修复。
J. 新实现上线后旧 Current Owner 没真正退出 runtime。
K. shared Dialog 外壳由 app.css 控 scroll，feature 再局部反向修复。
L. Select behavior 已 canonical，但 native visual skin 由 Transfer feature 单独拥有。
M. canonical resolver 删除了，但 Selection 留下永远 false 的 caller。
N. editable dialog 在 authoritative async state ready 前就开放。
```

固定处理方式：

```text
identify Current Owner
→ inspect API/capability/performance budget
→ normalize data/unit at adapter boundary
→ source-final component
→ shared primitive skin
→ explicit lifecycle
→ single geometry owner
→ delete old owner + dormant callers
→ static owner gate
→ real interaction browser gate
```

## 17. 写入硬规则

```text
OWNER-001
一个功能一个 Current Owner；canonical replacement 完成后旧 owner 必须退出 runtime。

OWNER-RETIRE-001
旧 owner/API 退出包括所有不可达 caller、shim、no-op hook；Git history 才是 archive。

CONTROL-SKIN-001
shared control visual skin 由 css/ui.css 独占；feature CSS 只提供 geometry variables。

DIALOG-SCROLL-001
Dialog outer shell 不做 generic scroll owner；短弹窗无滚动条，真实溢出只在内部区域滚动。

NATIVE-THEME-001
native Select 显式跟随 resolved light/dark color-scheme，control/option 共用 shared theme tokens。

COMPAT-DEGRADE-001
缺少能力且正确模拟代价高时，用中立 minimum-version degradation。

PERF-COMPAT-001
默认禁止 O(N) / N-per-item 网络兼容工作；必要时需开发者明确确认性能预算。

PROGRESSIVE-DATA-001
当前页/首屏 usefulness 不等待全量 total/enrichment。

ROUTE-OWNER-001
app.js 唯一提交 Route Frame state。

SELECT-TOPLAYER-001
Modal/top-layer 下 canonical Select 可使用 native presentation，不叠 portal workaround。

RATE-UNIT-001
WeiG rate business unit = B/s；QBClient 独占 API-unit conversion。

TIMESERIES-001
扩展时间窗必须 bounded + aggregated，不能提高 API polling frequency。

LAYOUT-OWNER-001
layout.css 独占 route/status/Torrent viewport geometry。

INTERACTION-TEST-001
关键控件必须用真实 click/selectOption/input/apply 验证，不能只 assert DOM。

EXACT-HEAD-001
任何 code/test/doc change 都生成新的 candidate SHA。
```

## 20. CI / exact-HEAD workflow

本问题链固定：

```text
1. 已确定范围一次完成 code + tests + docs
2. cumulative diff audit
3. static/ownership pre-audit
4. final [ui] exact dev HEAD 才触发统一 dev gates
5. CI 红 -> 读完整失败链 -> 集中修一批 -> 新 exact HEAD 再验证
6. 全绿才称为 LIVE candidate
```

不做“改一点就跑一次 CI”。

## 21. LIVE / Release boundary
