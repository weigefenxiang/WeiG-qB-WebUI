# 005. v0.3.7 统一交互与设置系统

Status: **Responsive UI System 3.3 contract**

本文件记录 v0.3.7 的统一 UI contract，重点解决本次真实页面截图暴露的 Settings 对齐、span、DOM ownership 与 Header utility 入口问题。

## 1. 设计方法

所有设计继续参考 `VoltAgent/awesome-design-md` 的方法论：

```text

```

## 2. 本次截图的直接问题

### Downloads

当前页面虽然已经出现两列，但 ordinary rows 没有形成统一的“copy 左 / control 右”结构：部分标题/描述视觉居中，部分 Switch 位于 cell 中部；某些 path-like 字段又突然跨两列。

### Connection

`代理类型`、`使用随机监听端口`、`使用 UPnP / NAT-PMP 端口映射` 等 row 的 title/control alignment 与上方普通数字 row 不一致；`代理主机`、`代理用户名` 等因为 key/text heuristic 被当作 full-span，导致桌面网格节奏被打断。

### 其它 tabs

Speed / BitTorrent / Web UI / Advanced 使用相同历史 renderer/样式链，因此同类问题会重复出现。不能逐 tab 补 CSS。

## 3. 系统性根因

### 3.1 两种 SettingRow DOM 共存

当前至少存在：

```text
A. preferenceField
   SettingRow
   ├─ .settings-row__copy
   └─ control

B. legacy settings-control
   strong
   small
   control
```

新 SettingsGrid CSS 能稳定处理 A，却必须为 B 再写另一套 selector。结果就是同一个 grid 中出现不同 alignment。

### 3.2 两套 Settings geometry owner 共存

历史 `ui-polish-v037.css` 仍存在 centered FormRail / fixed label-control rail 的几何规则，而新的 `settings-brand-v037.css` 又定义 SettingsGrid + row right alignment。

两个系统都使用高 specificity/`!important` 时，最终视觉由 selector 命中顺序决定，而不是组件语义决定。

### 3.3 full-span 使用 key-name heuristic

当前 `classifySpan()` 会根据 `path/url/domain/address/tracker/directory/location/save/host/username/password/rule` 等字符串自动判 full。

这正是代理主机、用户名、保存路径等普通字段突然只剩“一列整行”的根因。

### 3.4 Post-render normalize 承担了过多核心职责

MutationObserver 当前同时负责发现 row、包装、搬运、合并 grid、处理异步注入。它适合作为迁移桥，不适合作为长期 renderer。

### 3.5 Gate 验证粒度不足

此前 focused gate 已能证明“两列存在”和部分 control right alignment，但没有逐行验证：

```text
title text-align
control slot axis
ordinary row span
forbidden full-span heuristic
每一个 Settings tab 的一致性
```

因此结构 bug 能通过粗粒度 contract。

## 5. SettingRow 统一结构

普通 editable setting 统一：

```text
SettingRow
├─ SettingCopy
│  ├─ SettingTitleLine
│  │  ├─ Title
│  │  └─ optional Help
│  └─ Description
└─ SettingControlSlot
   └─ control
```

视觉：

```text
┌──────────────────────────────────────────────┐
│ 标题 / 说明                         [控件] │
└──────────────────────────────────────────────┘
```

硬规则：

```text
Title              left
Description        left
ControlSlot        right
ordinary row       inline
ordinary row span  1
```

不再允许普通 row 中标题居中、Switch 居中或 input 使用另一根对齐轴。

字段数量为奇数时，最后一个 ordinary row 留在左 cell，右 cell 为空；不会自动拉满整行。

## 7. full-span 新规则

默认所有 ordinary field：

```text
span=1
```

只有真正的大编辑器允许：

```text
span=full
layout=stacked/composite
```

例如：

```text
multiline textarea
tracker/source list
certificate/key textarea
large rules editor
composite multi-control editor
table/list/data editor
```

明确禁止：

```text
path
url
host
address
username
password
```

因为名字看起来“可能很长”就 full-span。

普通 path/url input 使用较宽 control tier，但仍待在一个 SettingsGrid cell。

## 8. ControlRegistry 与 width tiers

```text
boolean       Switch
number        NumberInput
port          PortInput
enum          Select/Listbox
text          TextInput
path/url      TextInput (wide tier)
rate          RateControl
duration      DurationControl
timezone      TimeZoneControl
```

Width policy：

```text
Switch            intrinsic
Number / Port     compact
Select            content-fit, capped
Text              medium
Path / URL        wide tier, still half-grid by default
Multiline/complex explicit full SettingBlock
```

同一个 control type 在 Downloads/Connection/Speed/BitTorrent/Web UI/Advanced 不得有 page-local width。

已验证 enum 应使用 canonical Select，不应继续向用户展示无法理解的 raw code。

## 9. CSS ownership cleanup

迁移完成后的 Settings geometry 只允许：

```text
SettingsSectionPanel
→ SettingsGrid
→ SettingRow
→ SettingControlSlot
```

旧 centered FormRail：

```text
--settings-rail-w
--settings-label-w
--settings-control-w
SETTINGS-FORM-RAIL-*
```

不得继续影响 migrated row。

不要通过增加更强的 `!important` 来“赢过”旧规则；应删除/隔离旧 owner。

## 10. Renderer migration

短期：

```text
legacy renderer
→ SettingRowAdapter
→ canonical SettingRow
```

长期：

```text
PreferenceSchema
→ SettingRowFactory
→ canonical DOM immediately
```

`normalizeSection()` / MutationObserver 只保留为未迁移模块的兼容桥，不能继续承担永久 layout repair。

## 15. 总实施方案

```text
A. Docs lock System 3.3 contract

B. Settings structure
   - introduce canonical SettingControlSlot
   - adapt every legacy settings-control row
   - ordinary rows become one DOM shape

C. Span semantics
   - remove classifySpan key-name heuristic
   - PreferenceSchema default span=1
   - explicit full only for real multiline/composite editors

D. Geometry cleanup
   - remove/disable legacy FormRail geometry for migrated rows
   - one SettingsGrid owner

E. All qB tabs
   Downloads -> Connection -> Speed -> BitTorrent -> Web UI -> Advanced
   presentation only; WebAPI/save unchanged

F. Header utilities
   - generic HeaderUtilityAction
   - GitHub + Blog external links
   - reuse Refresh/Theme icon-btn visual contract

G. Regression
   - static no-duplicate-owner contract
   - one focused Linux Chromium [ui]
   - qB 4.1.9.1 + 5.2.0 in same run

H. New exact-SHA LIVE
   - legacy 4.1.9.1
   - modern 5.2.x

I. Release only when requested
   - promote same SHA to main
   - full stable-tag audit
   - Linux + Windows + multi-viewport candidate
   - tag/release same artifact
```
