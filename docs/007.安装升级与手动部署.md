# 007. 安装、升级、Dev Distribution 与 Windows 配置安全

Status: **current install / update / rollback / deployment authority**

本文件统一维护 Stable/Dev 安装来源、Linux/Docker/Windows 部署、Pages materialized distribution、Windows qB config mutation与 backup retention。

## 1. 当前安装来源

当前正式支持基线：qBittorrent `4.1.0 -> 5.2.3` admitted stable；qB 4.0.x/WebAPI v1不在正式 scope。Repository/Product VERSION 当前为 `0.3.86`；已发布 Release 与开发 VERSION 是不同事实，安装器不得把 dev 当 Stable fallback。

Stable installer必须：

```text
resolve exact Release/tag
-> validate tag vX.Y.Z
-> resolve tag commit SHA
-> pin exact assets
-> verify SHA256SUMS
-> verify package VERSION == tag version
-> verify package GIT_SHA == tag commit SHA
```

任何 identity/checksum mismatch fail closed。

Dev只消费 Virtual qB Pages发布的 exact-SHA materialized distribution，禁止 raw-source archive fallback：

```text
Pages downloads/dev/GIT_SHA
== package GIT_SHA
== manifest gitSha
```

HEAD领先 materialized SHA时，只能在 canonical Pages relevance classifier证明全部 intervening changes为 Pages-irrelevant后复用旧 payload；未知、截断或任一 Pages-relevant change都必须等待新 exact materialization。

## 2. Linux / NAS / Docker

Stable bootstrap：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh
sh weigg-install.sh --configure
```

Dev：

```sh
sh weigg-install.sh --dev --configure
```

默认 Linux root：`~/.local/share/weigg-qb-webui`。Docker Alternative WebUI Root Folder必须使用容器内路径；例如 host `/root/qbittorrent/config/weigg-qb-webui` 映射到 container `/config/weigg-qb-webui` 时，qB填写后者。

多个 qB容器/配置候选存在时不得猜，可使用 `--list-containers`、`--container=<name>`、`--config-root=<host path>`。

## 3. Windows Stable / Dev

Stable：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

Dev必须从 materialized Pages payload获取同步 bootstrap：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure
```

指定目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -o "D:\WeiG-qB-WebUI" -configure
```

Portable/custom profile或多个候选时使用 `-qbconfig "<exact qBittorrent.ini path>"`。Installer不得静默猜 config。

## 4. Windows qB config mutation safety

外部修改 qB config必须 fail closed。写前检查：

```text
qBittorrent.exe not running
no non-empty qBittorrent_new.ini/recovery file
config non-empty and structurally plausible
unambiguous config target
exactly one [Preferences]
managed WebUI keys unique and owned by [Preferences]
```

Mutation chain：

```text
strict decode + byte round-trip
-> byte-identical safety backup
-> mutate in memory
-> temp write
-> strict reread
-> encoding/BOM/newline/invariant verification
-> recheck target unchanged
-> atomic replacement
-> post-replace reread/verification
-> safe rollback when applicable
```

必须保留 UTF-8 BOM/no-BOM、UTF-16 LE/BE BOM。禁止 whole-file `Get-Content -Raw` + `Set-Content -Encoding UTF8` 式转码。遇到非空 recovery/new config必须停止；未知 mojibake不得自动逆转码。

## 5. Materialized WebUI runtime contract（0.3.86）

Dev/Release materialized WebUI必须至少包含：

```text
private/data/qb-releases.json
private/data/qb-release-profiles/
private/data/qb-settings-native.txt
translations/webui_*.qm          # referenced-only minimal official QM assets
VERSION
GIT_SHA
```

并且必须**不包含**已退休 runtime assets：

```text
private/data/qb-settings/
old full native-registry body/format
```

`qb-settings-native.txt` 当前内容是 source-derived、exact-source-bound 的 compact qB-owned wording IR；它包含去重后的 source/context refs、binding sets和必要 exact bridge sets。`translations/webui_*.qm` 只包含正式产品实际引用、且 active Alternative-WebUI translator需要的 official messages；完整 TS/recovery/source evidence不进入用户包。

Installer的 `Assert-MaterializedWebUI` / `assert_materialized_webui` 继续验证该兼容文件名存在且非空；materializer/tests负责证明它是新 compact IR，并证明旧 per-release `qb-settings/` 不再生成。禁止用 dummy file 掩盖 stale package。

Distribution `manifest.json` 必须提供可审计 size report：

```text
coreRuntimeBytes
releaseProfileBytes / releaseProfileFiles
translationBytes / translationFiles
redundantBytes            # retired Settings assets应为0
totalUncompressedBytes
zipBytes
maxFileBytes / maxFile
```

同时报告 binding/bridge dedupe数量。单个 runtime file必须低于 qB 10 MiB hard limit；项目 materializer当前以 `<5 MiB/file` target fail closed。

## 6. Universal Portable

正式产品仍是一个可复制目录：

```text
one materialized WeiG-qB-WebUI folder
+ offline
+ copy to supported qB host
+ set Alternative WebUI Root Folder
= works
```

最终用户不需要 tools、Node、Simulator、GitHub或在线下载语言包。Installer只是部署入口，不是产品运行依赖。

## 7. Backup / rollback retention

Shell与Windows installer最多保留最新3个 installer-owned timestamp backup。顺序固定：

```text
complete new backup
-> write state/last-backup
-> prune older installer-owned backups
```

Pruning ownership必须同时满足目录名严格 `YYYYMMDD-HHMMSS`、`had-webui` marker、`dest-path` marker。不得删除普通文件、用户目录、非 timestamp目录或缺 marker目录。

Rollback：

```sh
sh weigg-install.sh --rollback
```

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -rollback
```

## 8. 常用参数

| 用途 | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| 最新正式版 | 默认 | 默认 |
| 指定 Release | `--version X.Y.Z` | `-version X.Y.Z` |
| 开发版 | `--dev` | `-dev` |
| 指定目录 | `-o /path` / `--output /path` | `-o D:\path` / `-output D:\path` |
| 自动配置 qB | `--configure` | `-configure` |
| 回滚 | `--rollback` | `-rollback` |
| 指定 Docker 容器 | `--container=NAME` | — |
| 指定 Docker config root | `--config-root=/path` | — |
| 指定 Windows qB config | — | `-qbconfig PATH` |

指定版本不存在时直接失败，不能 fallback到 latest/dev。

## 9. Release publisher

手动 Stable至少验证 `SHA256SUMS / VERSION / GIT_SHA`。正式 Release只消费已经验证的 exact dev candidate artifact，不在 main/tag后重新 build另一个 ZIP；完整 release gate见 `docs/006.发布与晋级流程.md`。
