# 007. 安装、升级与手动部署

Status: **stable distribution guide + explicit dev channel**

默认稳定安装以 GitHub Release 为事实源；`dev` 是显式开发频道。历史 WeiG 版本通过对应 Release/tag 恢复，当前仓库不保留 version-named deployment scripts 或 legacy runtime fallback。

## 1. 安装频道

### Release

Release 页面提供 `WeiG-qB-WebUI.zip + SHA256SUMS`。安装必须验证 ZIP、checksum、有效 `GIT_SHA` 与 Alternate WebUI entry points；失败时 fail closed，不回退 branch archive。

### dev

Installer 解析 current `dev` exact SHA，再部署该 SHA 的 `webui/` 并写入 exact `GIT_SHA`。

```text
dev != stable Release
dev != automatic fallback
```

普通 dev 安装只代表开发频道体验，不代表该 SHA 已进入 candidate/release。

## 2. Linux / Docker / NAS

Release：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o /tmp/weigg-qb-install.sh && sh /tmp/weigg-qb-install.sh --configure
```

dev：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/dev/installers/install.sh -o /tmp/weigg-qb-install.sh && sh /tmp/weigg-qb-install.sh --channel=dev --configure
```

Docker 中 qBittorrent 必须使用 container-visible path，例如 `/config/weigg-qb-webui`，不能把 host path 填进 qB。

## 3. Windows

Release：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile $env:TEMP\weigg-qb-install.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Channel Release -Configure
```

dev：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/dev/installers/install.ps1 -OutFile $env:TEMP\weigg-qb-install.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Channel Dev -Configure
```

## 4. 手动安装

Release 下载并校验 `WeiG-qB-WebUI.zip + SHA256SUMS` 后解压。Alternate WebUI root 至少包含：

```text
public/index.html
public/login.html
private/index.html
VERSION
GIT_SHA
```

qBittorrent：Tools / Options / Preferences -> Web UI -> Use alternative WebUI -> Files location / Root Folder。

## 5. Exact-SHA LIVE deployment

真实 qB LIVE 是 **main promotion / Release 前**的验证工具，不是每个 dev SHA 的默认步骤。普通 dev 使用 CI / Upstream / relevant Virtual qB Pages；准备晋级时冻结 final dev exact SHA，再执行真实 qB4/qB5 LIVE。

统一稳定文件名：

```text
tests/live.sh
tests/live-api.sh
```

脚本从 exact SHA 自身读取版本，不创建 version-labelled runtime script。任何新 commit 都产生新的 validation identity；LIVE 后 tree 变化则旧 evidence 作废。

## 6. 更新 / 回滚

Release：

```sh
sh /tmp/weigg-qb-install.sh --update
```

dev：

```sh
sh /tmp/weigg-qb-install.sh --update --channel=dev
```

需要立即恢复 qB built-in WebUI 时，关闭 **Use alternative WebUI**。

Installer rollback 使用当前 canonical installer flow；旧 deployment tool 不因新 owner 迁移而作为备用长期保留。

## 7. Deployment identity

安装后检查：

```text
VERSION
GIT_SHA
private/weigg-install.json
```

真实域名、凭据、container 名与机器专属路径不得写入公开源码。

## 8. Compatibility

当前 WebAPI v2 minimum supported target：**qBittorrent 4.1.0**；上界为 latest official stable，动态发现，不硬编码 patch/数量。

qB 4.0.x 属于旧 WebAPI v1，当前 installer/product 不声明主线支持。未来若实现 Legacy WebAPI v1 Adapter，必须作为明确、独立、可验证的 architecture extension；不得把 v1 作为 v2 请求失败后的 silent fallback。

Source-bound feature availability 以 exact release profile 为 authority；普通 unsupported UI 隐藏，不以 stale disabled badge 代替真实 capability。

## 9. Current-only deployment rule

新 deployment/runtime tool 若真正替代旧 tool，必须遵守 `OWNER-CUTOVER`：先 isolated validation，再 atomic cutover 并删除 superseded old file/caller/test。发布包中不得同时携带 old/new 两套 active implementation。
