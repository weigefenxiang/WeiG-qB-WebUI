# 007. 安装、升级与手动部署

这是一份安装来源与部署规则 authority。普通用户优先使用最新正式 Release；只有明确测试开发版时才使用 `dev`。

当前产品支持基线：

```text
qBittorrent 4.1.0 -> 5.2.3 admitted stable
qB 4.0.x / WebAPI v1: not supported
```

当前发布事实（2026-09-12）：

```text
latest published Release: v0.3.61
repository VERSION: 0.3.71
v0.3.71 tag/Release: not published
```

因此“main 仓库代码 VERSION=0.3.71”不等于“用户稳定版已经是 v0.3.71”。Stable installer 的 Release channel 仍解析 GitHub Release identity。

## 1. 安装来源

### 1.1 最新正式 Release

普通用户推荐。

正式 Release assets 当前设计为：

```text
WeiG-qB-WebUI.zip
weigg-install.sh
weigg-install.ps1
SHA256SUMS
```

稳定安装器会：

```text
resolve /releases/latest or /releases/tags/<tag>
-> validate tag vX.Y.Z
-> resolve tag commit SHA
-> pin assets to /releases/download/<exact tag>
-> verify SHA256SUMS
-> verify package VERSION == tag version
-> verify package GIT_SHA == tag commit SHA
```

任何 identity/checksum 不一致都 fail closed。

### 1.2 指定 Release

Linux：

```sh
sh weigg-install.sh --version 0.3.61 --configure
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -version 0.3.61 -configure
```

指定版本不存在时直接失败，不 fallback 到 latest/dev。

### 1.3 Dev

Dev 不是 Release fallback。Linux/Windows Dev 都只消费 Virtual qB Pages 发布的 **materialized Pages distribution**。该 payload 本身仍绑定一个 40 位 exact Git SHA，但日常 `dev` HEAD 可以只因为明确的 Pages-irrelevant commit（例如 docs/Markdown）暂时领先这个 materialized SHA。

Dev payload identity：

```text
Pages downloads/dev/GIT_SHA
== package embedded GIT_SHA
```

当：

```text
current dev HEAD != Pages downloads/dev/GIT_SHA
```

installer 必须比较：

```text
Pages published SHA ... current dev HEAD
```

只有中间**全部**变化属于明确 Pages-irrelevant 集合时才允许复用最后一个 verified payload。任何未知路径、`webui/**`、Virtual qB/simulator、installer、tool/runtime data 等 Pages-relevant 变化都会 fail closed，让用户等待新的 Pages build；仍然不允许 raw-source fallback。

正式 candidate / promotion / release 的 final dev exact SHA 仍必须建立同 SHA Pages evidence。若 final freeze 最后只是 docs-only commit，可显式 `workflow_dispatch` Virtual qB Pages；日常 docs push 不因此自动 rebuild/deploy Pages。

## 3. Linux / NAS

Stable bootstrap：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh
sh weigg-install.sh --configure
```

默认安装目录：

```text
~/.local/share/weigg-qb-webui
```

Dev：

```sh
sh weigg-install.sh --dev --configure
```

当前 Linux `--dev` 不再下载 GitHub raw archive。它会解析 current dev HEAD 与 Pages 已发布 materialized SHA，只消费 Pages：

```text
https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/
```

并要求 checksum + materialized runtime data 一致；若 HEAD 领先，只允许经过 GitHub compare 验证的 Pages-irrelevant 差异。

## 4. Docker

Stable：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh
sh weigg-install.sh --configure
```

qB 在容器里时，Alternative WebUI `Root Folder` 必须是**容器内路径**。

示例：

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

则：

```text
宿主机 WebUI: /root/qbittorrent/config/weigg-qb-webui
qB Root Folder: /config/weigg-qb-webui
```

多个候选容器/路径存在时安装器不得随便猜。

Dev 同样使用 materialized Pages payload：

```sh
sh weigg-install.sh --container=qbittorrent --dev --configure
```

## 5. Windows PowerShell

### 5.1 Stable

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

默认目录：

```text
%LOCALAPPDATA%\WeiG-qB-WebUI
```

指定目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -o "D:\WeiG-qB-WebUI" -configure
```

### 5.2 Dev：Pages bootstrap 为 authority

推荐：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure
```

指定目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure -o "D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
```

历史上旧 `main/installers/install.ps1 -dev` 曾走 raw-source archive，这是事故来源。**当前 installer 已改为 Pages materialized Dev distribution，并对 current dev HEAD 与 published Pages SHA 之间的差异做 Pages relevance 验证**；Dev bootstrap authority 仍推荐 `downloads/dev/install.ps1`，因为它与 materialized distribution 同步发布。

不要从旧 Release、缓存文件或历史脚本复制 `-dev` 逻辑。

### 5.3 Windows `-configure` 当前安全边界

当前 installer 已完成 fail-closed hardening。写 qB config 前会检查：

```text
qBittorrent.exe 是否仍在运行
是否存在非空 qBittorrent_new.ini / recovery file
config 是否为空/过小/不像合法 INI
是否存在多个 config candidate
是否恰好一个 [Preferences]
managed WebUI keys 是否唯一且位于 [Preferences]
```

写入链：

```text
strict decode + byte round-trip
-> byte-identical safety backup
-> temp write
-> strict reread + encoding/BOM/invariant verify
-> recheck target unchanged
-> atomic replace
-> post-replace byte/text verify
-> failure-safe rollback when safe
```

支持保留：

```text
UTF-8 BOM
UTF-8 no BOM
UTF-16 LE BOM
UTF-16 BE BOM
```

不要重新引入：

```powershell
Get-Content $cfg -Raw
Set-Content -Encoding UTF8 $cfg
```

这种 whole-file transcode 曾真实污染中文/日文路径和 Tags。

虽然 installer 会拒绝运行中的 qB，人工操作仍建议先完全退出 qBittorrent。

自定义/portable profile 不明确时使用：

```powershell
-qbconfig "<exact config path>"
```

不要让脚本猜多个候选。

## 6. 手动安装 Stable

手动下载：

```text
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest
```

必须至少验证：

```text
SHA256SUMS
VERSION
GIT_SHA
```

仅比较 VERSION 不足以证明 build identity。

Release asset 解压根至少：

```text
public/
private/
VERSION
GIT_SHA
```

qB Alternative WebUI `文件位置` 指向这个根目录。

## 7. 更新与回滚

重新运行同一来源就是更新。

Linux stable：

```sh
sh weigg-install.sh --configure
```

Windows stable：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

Dev 应重新下载 Pages bootstrap，避免 bootstrap 与 materialized payload 脱节。

回滚：

```sh
sh weigg-install.sh --rollback
```

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -rollback
```

若用户已经发生 Unicode mojibake，应从**已知正常备份**恢复 proven-corrupted keys；不要盲目自动逆转码。

## 8. 常见问题

### 页面仍是旧内容

先 `Ctrl + F5`，再核对安装目录的 40 位 `GIT_SHA`。

### Dev source-proven 错误

优先检查：

```text
installed/package GIT_SHA == Pages downloads/dev/GIT_SHA
current dev HEAD == Pages GIT_SHA
OR current dev HEAD only contains verified Pages-irrelevant changes after Pages GIT_SHA
private/data/qb-releases.json 非空
private/data/qb-release-profiles/ 存在
private/data/qb-settings-native.txt 存在
translations/webui_*.qm 存在
```

不要放宽 dangerous-write source guard。

### Release checksum / identity 失败

不要绕过；调查 Release tag、commit、asset 与 checksum identity。

### `Release vX.Y.Z did not resolve to a valid commit SHA`

真实 GitHub commits API 返回 pretty JSON。candidate mock 也必须模拟真实 API shape；不要为了错误测试桩放宽生产 installer parser/identity gate。
