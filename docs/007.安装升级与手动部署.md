# 007. 安装、升级与手动部署 / Installation, Upgrade & Manual Deployment

状态 / Status：**稳定 Release 优先 + 显式 dev + exact SHA 身份 / stable Release first + explicit dev + exact-SHA identity**

本文是 WeiG qB WebUI 的详细部署说明。README 负责快速安装；本页负责 Release、指定版本、dev、Docker、多容器、手动部署、回滚和发布身份等高级场景。

This is the detailed deployment guide for WeiG qB WebUI. The README covers quick installation; this document covers Releases, exact versions, dev builds, Docker, multiple containers, manual deployment, rollback, and deployment identity.

## 1. 安装来源 / Installation Sources

### 最新正式版 / Latest stable Release

普通用户默认使用最新 GitHub Release。安装器会下载 `WeiG-qB-WebUI.zip` 和 `SHA256SUMS`，验证 SHA-256 后才部署；校验失败时直接停止，不回退到 `dev` 或分支 ZIP。

The default for normal users is the latest GitHub Release. The installer downloads `WeiG-qB-WebUI.zip` and `SHA256SUMS`, verifies SHA-256, and only then deploys the package. Verification failure is fatal; it never falls back to `dev` or a branch archive.

### 指定正式版本 / Specific Release

可以显式安装某个已发布版本，例如 `0.3.60`。指定版本不存在、缺少 Release 文件、checksum 不匹配，都会直接报错，不会自动换成 latest 或 dev。

You can explicitly install a published version such as `0.3.60`. A missing Release, missing asset, or checksum mismatch fails closed and never silently switches to latest or dev.

### 开发版 / dev

`--dev / -dev` 只用于测试当前 `dev` 分支。安装器会先解析 `dev` 的 exact 40-character Git SHA，再部署该 SHA，并写入 `GIT_SHA`。

`--dev / -dev` is only for testing the current `dev` branch. The installer first resolves `dev` to an exact 40-character Git SHA, deploys that SHA, and records it in `GIT_SHA`.

```text
dev != stable Release
dev != automatic fallback
```

普通 dev 安装只表示开发频道体验，不表示该 SHA 已经通过最终 candidate 或可以发布。

A normal dev install only represents the development channel. It does not mean that SHA has passed final candidate validation or is release-ready.

## 2. Linux / NAS

默认安装最新正式 Release：

Install the latest stable Release by default:

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh && sh weigg-install.sh --configure
```

默认 WebUI 安装目录：`~/.local/share/weigg-qb-webui`。安装脚本保存在当前目录为 `./weigg-install.sh`。

The default WebUI directory is `~/.local/share/weigg-qb-webui`. The installer script remains in the current directory as `./weigg-install.sh`.

指定版本 / Specific version:

```sh
sh weigg-install.sh --version 0.3.60 --configure
```

开发版 / dev:

```sh
sh weigg-install.sh --dev --configure
```

自定义安装目录 / Custom install directory:

```sh
sh weigg-install.sh -o /opt/weigg-qb-webui --configure
```

也可以写成 / Equivalent long form:

```sh
sh weigg-install.sh --output /opt/weigg-qb-webui --configure
```

## 4. Docker：先理解宿主机与容器 / Docker: Host vs Container

Docker 中最容易出错的是路径。**宿主机路径**是文件实际保存在 Linux/NAS 的位置；**容器内路径**是 qBittorrent 进程在容器里能看到的位置。

Paths are the most common Docker mistake. The **host path** is where files physically live on Linux/NAS; the **container path** is what the qBittorrent process can see inside the container.

例如 / Example:

```text
宿主机 / Host:      /root/qbittorrent/config
                         ↓ mapped to
容器内 / Container: /config
```

Docker Compose 常见写法 / Typical Docker Compose mapping:

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

如果 WebUI 文件实际位于：

If the WebUI is physically stored at:

```text
/root/qbittorrent/config/weigg-qb-webui
```

那么 qBittorrent 应使用：

qBittorrent should use:

```text
/config/weigg-qb-webui
```

不要把 `/root/qbittorrent/config/weigg-qb-webui` 直接填到容器里的 qBittorrent，因为容器通常看不到宿主机路径。

Do not enter `/root/qbittorrent/config/weigg-qb-webui` directly in a containerized qBittorrent instance; the container normally cannot see that host path.

## 5. Docker 一键安装 / Docker One-click Installation

### 只有一个 qBittorrent 容器 / One qBittorrent container

直接运行普通一键命令。安装器会尝试识别正在运行的 qBittorrent 容器和 `/config` 映射，并在 `--configure` 下自动设置 Alternate WebUI。

Use the normal one-click command. The installer tries to detect the running qBittorrent container and its `/config` mapping, then configures the Alternate WebUI automatically when `--configure` is used.

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh && sh weigg-install.sh --configure
```

### 查看容器 / List containers

```sh
sh weigg-install.sh --list-containers
```

也可以使用 / Or use:

```sh
docker ps
```

### 指定容器 / Select a container

```sh
sh weigg-install.sh --container=qbittorrent --configure
```

也支持分开的参数形式 / Separate argument form is also supported:

```sh
sh weigg-install.sh --container qbittorrent --configure
```

### 多个 qBittorrent 容器 / Multiple qBittorrent containers

如果同时存在 `qbittorrent` 和 `qbittorrent-test`，请明确指定目标；安装器不会在多个候选之间静默猜测。

If both `qbittorrent` and `qbittorrent-test` exist, select the target explicitly. The installer will not silently guess between multiple candidates.

```sh
sh weigg-install.sh --container=qbittorrent --configure
sh weigg-install.sh --container=qbittorrent-test --configure
```

### 已知宿主机 `/config` 目录 / Known host `/config` directory

```sh
sh weigg-install.sh --config-root=/root/qbittorrent/config --configure
```

群晖示例 / Synology example:

```sh
sh weigg-install.sh --config-root=/volume1/docker/qbittorrent --configure
```

其他 NAS 示例 / Another NAS example:

```sh
sh weigg-install.sh --config-root=/share/Container/qbittorrent --configure
```

这些只是示例，请替换成自己的真实目录。

These are examples only; replace them with your real path.

### 指定容器内 WebUI 路径 / Choose the container-visible WebUI path

```sh
sh weigg-install.sh --container=qbittorrent -o /config/weigg-qb-webui --configure
```

安装器会根据 `/config` 映射换算宿主机实际安装位置。

The installer converts the `/config/...` container path into the corresponding host install location.

## 7. `--configure / -configure` 做什么 / What `--configure / -configure` Does

该参数在安装完成后尝试自动查找 qBittorrent 配置，先备份原配置，再启用 Alternate WebUI 并写入 WebUI 路径。

After installation, this option tries to locate the qBittorrent configuration, backs it up first, then enables the Alternate WebUI and writes the WebUI path.

核心设置对应：

The core settings correspond to:

```text
WebUI\AlternativeUIEnabled=true
WebUI\RootFolder=<WebUI path>
```

如果自动配置无法安全识别 qBittorrent 配置，安装仍可完成；之后按上一节手动启用即可。

If the installer cannot safely identify the qBittorrent configuration, the WebUI can still be installed; enable it manually using the previous section.

## 8. 手动 Release 安装 / Manual Release Installation

推荐使用安装器，因为安装器会自动做 checksum、目录验证、版本和 Git SHA 检查。确实需要手动安装时，Release 包至少应包含：

The installer is recommended because it automatically verifies checksums, layout, version, and Git SHA. For a manual Release deployment, the package should at minimum contain:

```text
WeiG-qB-WebUI/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

Linux 使用 `curl` / Linux with `curl`:

```sh
curl -fL https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip -o WeiG-qB-WebUI.zip
curl -fL https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/SHA256SUMS -o SHA256SUMS
sha256sum -c SHA256SUMS
unzip WeiG-qB-WebUI.zip
```

Linux 使用 `wget` / Linux with `wget`:

```sh
wget https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip -O WeiG-qB-WebUI.zip
wget https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/SHA256SUMS -O SHA256SUMS
sha256sum -c SHA256SUMS
unzip WeiG-qB-WebUI.zip
```

Windows PowerShell:

```powershell
Invoke-WebRequest https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip -OutFile .\WeiG-qB-WebUI.zip
Expand-Archive .\WeiG-qB-WebUI.zip .\WeiG-qB-WebUI -Force
```

Windows 手动方式如果要达到与安装器相同的完整性保证，还应另外下载 `SHA256SUMS` 并验证 ZIP 的 SHA-256。

To obtain the same integrity guarantee as the installer on Windows, also download `SHA256SUMS` and verify the ZIP SHA-256.

## 9. 更新 / Update

推荐做法是**重新运行安装命令**。默认仍安装最新稳定 Release；指定版本继续使用 `--version / -version`；开发版继续使用 `--dev / -dev`。

The recommended update method is to **run the installer again**. The default remains the latest stable Release; use `--version / -version` for an exact Release and `--dev / -dev` for the development branch.

Linux 最新版 / Linux latest:

```sh
sh weigg-install.sh --configure
```

Linux dev:

```sh
sh weigg-install.sh --dev --configure
```

Windows 最新版 / Windows latest:

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

Windows dev:

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -dev -configure
```

Linux 仍兼容旧 `--update`，Windows 仍兼容旧 `-Mode Update`，但它们不再是 README 的主推荐入口。

Linux still accepts the legacy `--update`, and Windows still accepts legacy `-Mode Update`, but they are no longer the primary documented workflow.

## 10. 回滚 / Rollback

安装器会在覆盖现有 WebUI 或 qBittorrent 配置前保存备份，并记录最近一次安装目录。

Before replacing an existing WebUI or qBittorrent configuration, the installer stores a backup and remembers the last install directory.

Linux:

```sh
sh weigg-install.sh --rollback
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -rollback
```

如果只想立即恢复 qBittorrent 内置 WebUI，也可以手动关闭 **Use alternative WebUI / 使用备选 WebUI**。

To immediately return to qBittorrent's built-in WebUI without restoring files, disable **Use alternative WebUI / 使用备选 WebUI** manually.

## 11. 安装身份 / Deployment Identity

安装完成后，以下文件共同用于识别部署身份：

After installation, these files identify the deployed build:

```text
VERSION
GIT_SHA
private/weigg-install.json
```

正式 Release 的 ZIP 内 `VERSION`、`GIT_SHA`、Release tag 和 checksum 必须相互一致。

For a formal Release, `VERSION`, `GIT_SHA`, the Release tag, and the checksum must agree with each other.

`dev` 安装必须记录解析到的 exact Git SHA；不能只写 `dev` 作为身份。

A `dev` deployment must record the resolved exact Git SHA; the word `dev` alone is not a sufficient build identity.

## 12. Exact-SHA 验证与发布 / Exact-SHA Validation and Release

真实 qB LIVE 验证是发布准备工具，不是每一个 dev commit 的默认安装步骤。准备发布时应先冻结 final dev exact SHA，再对同一个 SHA 完成需要的 CI/LIVE/candidate 验证。

Real qB LIVE validation is a release-preparation tool, not a default installation step for every dev commit. Before release, freeze the final dev exact SHA and run the required CI/LIVE/candidate validation against that same SHA.

```text
Any new commit = new validation identity
```

如果验证后 tree/SHA 发生变化，旧证据不能自动继承到新 SHA。

If the tree/SHA changes after validation, the old evidence does not automatically transfer to the new SHA.

稳定 LIVE 脚本 / Stable LIVE scripts:

```text
tests/live.sh
tests/live-api.sh
```

## 13. 兼容范围 / Compatibility

当前正式产品线支持 qBittorrent **4.1.x → 5.2.x**；已验证的 Release profile 以 exact qBittorrent version 为准。

The current formal product line supports qBittorrent **4.1.x → 5.2.x**; validated Release profiles are tracked by exact qBittorrent version.

当前 WebAPI v2 下限为 **qBittorrent 4.1.0**。qBittorrent 4.0.x 属于旧 WebAPI v1，当前产品不声明主线支持。

The current WebAPI v2 floor is **qBittorrent 4.1.0**. qBittorrent 4.0.x belongs to the older WebAPI v1 and is not part of the supported mainline product.

功能可用性以 exact release profile / capability 为准；不支持的功能应隐藏或明确处理，不通过 silent fallback 假装成功。

Feature availability follows exact release profiles and capabilities. Unsupported features should be hidden or handled explicitly, not silently emulated through fallback behavior.

## 14. 当前部署实现规则 / Current-only Deployment Rule

新的 deployment/runtime tool 如果真正替代旧实现，必须遵守 `OWNER-CUTOVER`：先独立验证，再原子切换，并删除被替代的 active implementation/caller/test。正式发布包不得同时携带两套互相竞争的 active deployment implementation。

When a new deployment/runtime tool truly replaces an older implementation, follow `OWNER-CUTOVER`: validate it in isolation, perform an atomic cutover, and remove the superseded active implementation/caller/test. A formal Release must not ship two competing active deployment implementations.

真实域名、凭据、私有容器名与机器专属路径不得写入公开源码。

Real domains, credentials, private container names, and machine-specific private paths must not be committed to public source code.
