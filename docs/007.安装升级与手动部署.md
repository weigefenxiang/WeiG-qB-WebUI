# 007. 安装、升级与手动部署

这是一份面向新手的完整安装说明。**普通用户优先使用最新正式 Release**；只有明确需要测试开发版时才使用 `dev`。

支持范围：**qBittorrent 4.1.x → 5.2.x**。

> 如果你只想最快安装：直接找到下面对应的 **Linux / NAS、Docker 或 Windows PowerShell**，复制主命令即可。主命令下面的详细说明和案例默认折叠，需要时再展开。

## 1. 先看懂常用参数

Linux / Docker / NAS 使用 `install.sh`，Windows 使用 `install.ps1`。两边参数尽量保持同名；PowerShell 参数本身不区分大小写，文档统一使用小写。

| 用途 | Linux / Docker / NAS | Windows PowerShell | 说明 |
|---|---|---|---|
| 最新正式版 | 默认，无需参数 | 默认，无需参数 | 推荐普通用户使用 |
| 指定正式版本 | `--version 0.3.60` | `-version 0.3.60` | 只安装指定 Release |
| 开发版 | `--dev` | `-dev` | 当前 `dev` 的 exact Git SHA |
| 指定安装目录 | `-o /path` 或 `--output /path` | `-o D:\path` 或 `-output D:\path` | `o` = output |
| 自动配置 qBittorrent | `--configure` | `-configure` | 自动启用 Alternate WebUI 并填写路径 |
| 回滚 | `--rollback` | `-rollback` | 恢复上一次安装及 qB 配置 |
| 查看帮助 | `--help` | `-help` | 显示脚本完整帮助 |
| 指定 Docker 容器 | `--container=NAME` | — | 多个 qB 容器时使用 |
| 列出 Docker 容器 | `--list-containers` | — | 查看检测到的 qB 容器 |
| 指定 Docker `/config` 宿主机目录 | `--config-root=/path` | — | 已知宿主机映射目录时使用 |

### 参数最重要的几条规则

- **什么参数都不加**：安装最新正式 Release。
- `--version / -version`：安装指定版本，例如 `0.3.60`。如果这个版本不存在，会直接报错，**不会自动退回 latest 或 dev**。
- `--dev / -dev`：只用于测试开发版，和 `--version / -version` **不能同时使用**。
- `--configure / -configure`：安装后自动修改 qBittorrent 配置；修改前会先备份。
- `--rollback / -rollback`：恢复上一次安装目录和对应的 qBittorrent 配置。
- Linux 的旧参数 `--channel=release|dev`、`--dir=...`，Windows 的 `-Channel`、`-Destination`、`-Mode` 仍为旧用户保留兼容，但**新文档不推荐继续使用**。

## 2. 我应该选哪一种安装来源？

### 最新正式版：推荐

适合绝大多数用户。安装器会从 GitHub Release 下载：

```text
WeiG-qB-WebUI.zip
SHA256SUMS
```

并验证 SHA-256。校验失败时会停止安装，不会偷偷改用 `dev`。

### 指定正式版本

适合需要固定版本、回到旧版本、测试指定 Release 的用户。例如：

```text
0.3.60
```

输入时可以写 `0.3.60`，脚本会对应到 Release tag `v0.3.60`。

### dev 开发版

`dev` 会先解析当前 `dev` 分支的 **40 位 exact Git SHA**，再下载那个精确提交的内容。它不是正式稳定版，也不会作为 Release 下载失败时的备用方案。

## 3. Linux / NAS

最常用的一键安装命令：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh && sh weigg-install.sh --configure
```

这条命令会把安装脚本保存为当前目录下的 `weigg-install.sh`，然后安装最新正式 Release，并尝试自动配置 qBittorrent。

<details>
<summary><b>点击展开：Linux / NAS 路径说明、参数用法和更多案例</b></summary>

### 默认安装到哪里？

普通 Linux 用户默认安装到：

```text
~/.local/share/weigg-qb-webui
```

例如用户名是 `alex`，通常就是：

```text
/home/alex/.local/share/weigg-qb-webui
```

如果使用 `root` 用户运行，通常就是：

```text
/root/.local/share/weigg-qb-webui
```

安装脚本本身则在你执行命令的当前目录：

```text
./weigg-install.sh
```

### 案例 1：安装最新正式版并自动配置 qBittorrent

```sh
sh weigg-install.sh --configure
```

适合大多数用户。

### 案例 2：只安装文件，不自动修改 qBittorrent 配置

```sh
sh weigg-install.sh
```

安装完成后，脚本会告诉你 WebUI 路径。然后手动进入 qBittorrent：

**工具 → 选项... → WebUI**

1. 勾选 **使用备选 WebUI**。
2. 在 **文件位置：** 填写 WebUI 路径。
3. 点击 **确定**。

### 案例 3：安装指定正式版本

```sh
sh weigg-install.sh --version 0.3.60 --configure
```

只会尝试安装 `v0.3.60`，不存在就报错。

### 案例 4：安装到 `/opt/weigg-qb-webui`

```sh
sh weigg-install.sh -o /opt/weigg-qb-webui --configure
```

也可以写：

```sh
sh weigg-install.sh --output /opt/weigg-qb-webui --configure
```

### 案例 5：指定版本 + 指定目录

```sh
sh weigg-install.sh --version 0.3.60 -o /opt/weigg-qb-webui --configure
```

### 案例 6：测试当前 dev

```sh
sh weigg-install.sh --dev --configure
```

`dev` 会固定到运行时解析出的 exact Git SHA。

### 案例 7：升级最新正式版

直接重新运行原来的命令即可：

```sh
sh weigg-install.sh --configure
```

如果你之前固定在某个版本，例如 `0.3.60`，想升级到另一个指定版本：

```sh
sh weigg-install.sh --version 0.3.61 --configure
```

想从固定版本切回最新正式版，就去掉 `--version`。

### 案例 8：回滚

```sh
sh weigg-install.sh --rollback
```

安装器会读取上一次保存的备份，恢复之前的 WebUI 和 qBittorrent 配置。没有显式指定 `-o` 时，也会记住上一次使用的安装目录。

### 案例 9：查看完整帮助

```sh
sh weigg-install.sh --help
```

### 下载工具不一样怎么办？

Linux 安装器会自动寻找可用工具，包括常见的：

```text
curl
wget
BusyBox wget
Python 3
```

解压会尝试：

```text
unzip
BusyBox unzip
Python 3 zipfile
bsdtar
```

Release 的 SHA-256 校验会寻找可用的 `sha256sum`、BusyBox、`shasum`、OpenSSL 或 Python 3。**找不到可用的 SHA-256 工具时，Release 安装会拒绝继续，而不是跳过校验。**

</details>

## 4. Docker

如果你的 qBittorrent 运行在 Docker 中，先试最简单的一键命令：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh && sh weigg-install.sh --configure
```

如果机器上只有一个正在运行的 qBittorrent 容器，并且它有正常的 `/config` 映射，安装器会尝试自动识别。

<details>
<summary><b>点击展开：Docker 新手说明、多容器、NAS 路径和完整案例</b></summary>

### 先理解“宿主机”和“容器”

假设你的 qBittorrent Docker 配置是：

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

含义是：

```text
宿主机：/root/qbittorrent/config
   ↓ 映射到
容器内：/config
```

冒号左边是**宿主机路径**，右边是**容器内路径**。

如果 WeiG qB WebUI 最终保存在宿主机：

```text
/root/qbittorrent/config/weigg-qb-webui
```

qBittorrent 的 **文件位置：** 应填写：

```text
/config/weigg-qb-webui
```

而不是：

```text
/root/qbittorrent/config/weigg-qb-webui
```

因为 qBittorrent 进程运行在容器里，它看到的是 `/config/...`。

### Docker 默认安装位置

当安装器检测到：

```text
容器 /config -> 宿主机 /root/qbittorrent/config
```

且你没有使用 `-o` 指定路径时，默认会换算为：

```text
宿主机安装路径：/root/qbittorrent/config/weigg-qb-webui
qBittorrent 路径：/config/weigg-qb-webui
```

脚本会输出类似：

```text
Host install path: /root/qbittorrent/config/weigg-qb-webui
qBittorrent Root Folder: /config/weigg-qb-webui
```

### 案例 1：只有一个 qBittorrent 容器

直接运行：

```sh
sh weigg-install.sh --configure
```

安装器会尝试：

1. 找到正在运行的 qBittorrent 容器；
2. 找到它的 `/config` 映射；
3. 把 WebUI 安装到宿主机对应目录；
4. 把 qBittorrent 的 WebUI 路径设置为容器内路径。

### 案例 2：不知道容器叫什么

先运行：

```sh
sh weigg-install.sh --list-containers
```

脚本会列出检测到的 qBittorrent 容器及 `/config` 映射。

也可以自己看：

```sh
docker ps
```

### 案例 3：明确指定容器

假设容器名是：

```text
qbittorrent
```

运行：

```sh
sh weigg-install.sh --container=qbittorrent --configure
```

也支持分开的写法：

```sh
sh weigg-install.sh --container qbittorrent --configure
```

### 案例 4：机器上有多个 qBittorrent 容器

例如：

```text
qbittorrent
qbittorrent-test
qbittorrent-old
```

先列出：

```sh
sh weigg-install.sh --list-containers
```

给正式容器安装：

```sh
sh weigg-install.sh --container=qbittorrent --configure
```

给测试容器安装：

```sh
sh weigg-install.sh --container=qbittorrent-test --configure
```

**多个 qBittorrent 容器时，安装器不会随便猜一个，会要求你明确指定。**

### 案例 5：我知道宿主机的 qBittorrent `/config` 目录

例如你的真实目录是：

```text
/root/qbittorrent/config
```

直接指定：

```sh
sh weigg-install.sh --config-root=/root/qbittorrent/config --configure
```

也可以写：

```sh
sh weigg-install.sh --config-root /root/qbittorrent/config --configure
```

### 案例 6：群晖 Synology

假设 `/config` 的宿主机目录是：

```text
/volume1/docker/qbittorrent
```

运行：

```sh
sh weigg-install.sh --config-root=/volume1/docker/qbittorrent --configure
```

### 案例 7：其他 NAS

例如：

```text
/share/Container/qbittorrent
```

运行：

```sh
sh weigg-install.sh --config-root=/share/Container/qbittorrent --configure
```

上面的 NAS 路径只是示例，必须换成你自己实际映射到容器 `/config` 的目录。

### 案例 8：指定容器里的 WebUI 路径

```sh
sh weigg-install.sh --container=qbittorrent -o /config/weigg-qb-webui --configure
```

如果容器的 `/config` 映射到：

```text
/root/qbittorrent/config
```

安装器会自动换算：

```text
/config/weigg-qb-webui
        ↓
/root/qbittorrent/config/weigg-qb-webui
```

### 案例 9：指定宿主机 WebUI 路径

如果你已经知道宿主机 `/config` 是：

```text
/root/qbittorrent/config
```

也可以组合：

```sh
sh weigg-install.sh --config-root=/root/qbittorrent/config -o /root/qbittorrent/config/weigg-qb-webui --configure
```

安装器会把对应的 qBittorrent 容器路径换算为：

```text
/config/weigg-qb-webui
```

### 案例 10：指定正式版本

```sh
sh weigg-install.sh --container=qbittorrent --version 0.3.60 --configure
```

### 案例 11：测试 dev

```sh
sh weigg-install.sh --container=qbittorrent --dev --configure
```

### 案例 12：Docker 回滚

```sh
sh weigg-install.sh --rollback
```

如果上一次安装器保存了 Docker WebUI 目录与 qBittorrent 配置备份，会恢复上一次状态。

### Docker 最常见的错误：填错路径

如果 qBittorrent 中填的是：

```text
/root/qbittorrent/config/weigg-qb-webui
```

但 qBittorrent 实际运行在容器里，通常会找不到文件。

应该填写容器看到的路径，例如：

```text
/config/weigg-qb-webui
```

### 容器没有 `/config` 映射怎么办？

自动检测依赖 qBittorrent 容器暴露可用的 `/config` 挂载。如果容器没有可用 `/config` 映射，安装器不会凭空猜路径。请先确认 Docker Compose / docker run 的 volume 配置。

</details>

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1; powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

这条命令会把 `weigg-install.ps1` 保存到当前 PowerShell 目录，然后安装最新正式 Release，并尝试自动配置 qBittorrent。

以下写法在 PowerShell 中等价：

```text
-configure
-Configure
```

Windows 可能因为当前 PowerShell 执行策略而阻止本地脚本运行。这里的 `-ExecutionPolicy Bypass` 只用于这次启动的 PowerShell 进程，不等于永久修改整个系统的执行策略。

不想运行脚本，也可以手动下载 Release ZIP。

最新正式版：

```text
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest
```

需要的文件：

```text
WeiG-qB-WebUI.zip
SHA256SUMS
```

<details>
<summary><b>点击展开：手动下载、校验、解压和 qBittorrent 设置</b></summary>

### Linux：使用 curl 下载

```sh
curl -fL https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip -o WeiG-qB-WebUI.zip
curl -fL https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/SHA256SUMS -o SHA256SUMS
sha256sum -c SHA256SUMS
unzip WeiG-qB-WebUI.zip
```

### Linux：使用 wget 下载

```sh
wget https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip -O WeiG-qB-WebUI.zip
wget https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/SHA256SUMS -O SHA256SUMS
sha256sum -c SHA256SUMS
unzip WeiG-qB-WebUI.zip
```

### Windows：手动下载并解压

```powershell
Invoke-WebRequest https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip -OutFile .\WeiG-qB-WebUI.zip
Expand-Archive .\WeiG-qB-WebUI.zip .\WeiG-qB-WebUI -Force
```

如果要手动核对 SHA-256：

```powershell
Get-FileHash .\WeiG-qB-WebUI.zip -Algorithm SHA256
```

然后与 `SHA256SUMS` 中 `WeiG-qB-WebUI.zip` 对应的哈希比较。

### 解压后应该看到什么？

正式 Release 的 WebUI 根目录中应至少能看到：

```text
WeiG-qB-WebUI/
├── public/
├── private/
├── VERSION
└── GIT_SHA
```

其中入口文件包括：

```text
public/index.html
public/login.html
private/index.html
```

### 手动启用 qBittorrent Alternate WebUI

打开 qBittorrent：

**工具 → 选项... → WebUI**

当前简体中文官方用语：

```text
使用备选 WebUI
文件位置：
```

勾选 **使用备选 WebUI**，然后把 **文件位置：** 指向 `WeiG-qB-WebUI` 根目录。

普通 Windows 示例：

```text
D:\WeiG-qB-WebUI
```

普通 Linux 示例：

```text
/opt/WeiG-qB-WebUI
```

Docker 示例：

```text
/config/weigg-qb-webui
```

## 7. 更新与回滚怎么理解？

### 更新

安装器不是“只能安装一次”。**重新运行安装命令就是更新**。

最新正式版用户：

```sh
sh weigg-install.sh --configure
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

如果 latest 已经变成新版本，安装器会重新下载新的正式 Release。

### 回滚

Linux：

```sh
sh weigg-install.sh --rollback
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -rollback
```

安装器在修改前会创建备份。回滚用于恢复最近一次安装前的 WebUI 文件和 qBittorrent 配置。

### 只想马上恢复 qBittorrent 原版 WebUI

即使不运行 rollback，也可以直接进入：

**工具 → 选项... → WebUI**

取消勾选：

```text
使用备选 WebUI
```

qBittorrent 就会重新使用内置 WebUI。

## 8. 常见问题

<details>
<summary><b>点击展开：白屏、404、路径错误、Docker、多容器、配置失败</b></summary>

### 安装成功，但页面还是旧的

浏览器可能缓存了旧 JS/CSS。先尝试：

```text
Ctrl + F5
```

也可以使用无痕窗口测试。

### 页面 404 / WebUI 无法打开

优先检查 qBittorrent 的 **文件位置：**。

这个目录里面应该直接看到：

```text
public
private
VERSION
GIT_SHA
```

如果还要再进入一层 `WeiG-qB-WebUI` 才能看到这些内容，说明路径多一层或少一层。

### Docker 明明安装成功，qBittorrent 还是找不到

最常见原因是把**宿主机路径**填进了 qBittorrent。

例如错误：

```text
/root/qbittorrent/config/weigg-qb-webui
```

容器内通常应该是：

```text
/config/weigg-qb-webui
```

### 提示找到多个 qBittorrent Docker 容器

先列出：

```sh
sh weigg-install.sh --list-containers
```

然后明确指定：

```sh
sh weigg-install.sh --container=qbittorrent --configure
```

### `--configure` 没有自动配置成功

安装文件本身仍可能已经成功。可以按照“手动启用 qBittorrent Alternate WebUI”一节自行填写路径。

### Release checksum 校验失败

不要绕过。重新下载并重试。如果 Release 的 ZIP 和 `SHA256SUMS` 不匹配，安装器会 fail closed，这是预期的安全行为。

### 指定版本不存在

例如：

```sh
sh weigg-install.sh --version 9.9.9
```

如果 GitHub 没有对应 Release，脚本会报错，并且**不会改装 latest 或 dev**。

</details>

## 9. 安装后如何确认自己装的是哪一版？

安装目录中可检查：

```text
VERSION
GIT_SHA
private/weigg-install.json
```

含义：

- `VERSION`：WeiG qB WebUI 版本号；
- `GIT_SHA`：这份 WebUI 对应的 exact Git commit；
- `private/weigg-install.json`：安装器记录的来源、SHA、安装路径、Docker 信息等部署元数据。

Release 和 dev 都应有可追踪的 exact SHA 身份，避免“看起来是同一个版本，但实际上文件不是同一份”的情况。

## 10. 兼容范围

当前主线支持：

```text
qBittorrent 4.1.x → 5.2.x
```

WebAPI v2 的最低主线目标为 **qBittorrent 4.1.0**。

qBittorrent 4.0.x 属于旧 WebAPI v1，不在当前主线支持声明中。

## 11. 给高级用户 / 维护者

<details>
<summary><b>点击展开：exact SHA、Release 身份和旧参数兼容</b></summary>

### exact SHA

`dev` 安装不是简单下载一个会不断变化的分支 ZIP。安装器会先解析 `dev` 当前的 40 位 Git SHA，再部署这个精确提交，并写入 `GIT_SHA`。

### Release

正式 Release 必须包含：

```text
WeiG-qB-WebUI.zip
SHA256SUMS
```

安装器会验证 checksum、`VERSION` 和有效的 `GIT_SHA`。指定版本不允许自动 fallback。

### 旧参数兼容

Linux 仍兼容：

```text
--channel=release
--channel=dev
--dir=/path
--update
```

Windows 仍兼容：

```text
-Channel Release
-Channel Dev
-Destination PATH
-Mode Install
-Mode Update
-Mode Rollback
```

这些是为了已有用户和旧自动化脚本继续工作。**新部署请优先使用本文顶部的新参数。**

### 公开仓库注意事项

真实域名、登录凭据、服务器专属路径、容器中的敏感信息不要写入公开源码。

</details>
