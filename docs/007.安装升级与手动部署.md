# 007. 安装、升级与手动部署

Status: **current installation / upgrade / Dev distribution / Windows config authority**

本文件维护安装、升级、Dev distribution、Windows qB config 与回滚的当前长期契约。发布流程见 `docs/006`，当前产品事实见 `docs/002`，当前未完成事项只见 `docs/014`。

## 1. 产品形态

WeiG WebUI 正式产品是 materialized `WeiG-qB-WebUI/` 目录，而不是仓库 source tree 本身。

Universal Portable 必须满足：

```text
one materialized WeiG-qB-WebUI folder
+ offline
+ copy to supported qB host
+ point qB Alternative WebUI root to the folder
= works
```

最终用户正常运行不得依赖 Node、tools、simulator、GitHub 或在线下载当前语言资产。

## 2. Stable installer

Stable installer 只消费 immutable GitHub Release identity：

```text
release tag
-> WeiG-qB-WebUI.zip
-> SHA256SUMS
-> embedded VERSION / GIT_SHA
```

禁止 stable installer 回退到 raw source、moving branch 或未验证 artifact。已发布 tag/Release/assets 不覆盖、不移动、不复用。

## 3. Dev installer

Dev installer 只消费 Dev Pages 暴露的 exact-SHA materialized distribution，不允许 raw-source fallback。

Canonical chain：

```text
current dev
-> Virtual qB Pages Source
-> exact-ref Virtual qB Pages materialization
-> downloads/dev/GIT_SHA + manifest.json + WeiG-qB-WebUI.zip
-> Dev installer
```

如果 current dev push 本身 Pages-irrelevant，Source workflow仍必须比较已发布 `downloads/dev/GIT_SHA -> current dev` 之间所有变化，只有能证明 materialized public payload不变时才允许复用旧 payload。Unknown compare必须 fail closed。

## 4. Materialized runtime contract（0.3.86）

当前 materialized product runtime至少包含：

```text
qb-releases.json
qb-release-profiles/
qb-settings-native.txt
translations/webui_*.qm
VERSION
GIT_SHA
manifest.json
```

其中：

```text
qb-settings-native.txt
= compact qB-owned source/context/binding/bridge runtime IR
= compatibility filename only; not the retired full native-registry format

translations/webui_*.qm
= minimal official QMs containing only runtime-required refs for source-proven active-root native routes
```

必须不存在：

```text
private/data/qb-settings/
retired per-release Settings translation shards
old full/unfiltered native-registry body
full/unfiltered recovery QM runtime payloads
```

完整 Settings/source LKG、official TS/recovery evidence与 source extractors仍保留在 tools/CI/artifacts，不属于 end-user runtime。

Materializer必须 fail closed：

```text
any single static file >= qB 10 MiB hard limit -> fail
any generated runtime file >= project 5 MiB target -> fail
missing compact registry / release profile / required QM -> fail
retired Settings runtime asset reappears -> fail
```

## 6. Linux / manual install

手动安装必须使用完整 materialized product folder，不是只复制 `index.html` 或仓库 raw `webui/` source。

典型流程：

```text
stop/prepare qB if config mutation required
backup existing Alternative WebUI folder/config
extract/copy complete WeiG-qB-WebUI folder
verify VERSION / GIT_SHA when applicable
point qB WebUI\AlternativeUIEnabled + RootFolder to materialized folder
start/reload qB
verify WebUI loads
```

具体 qB config path、service command、container mount由用户环境决定；installer不得假造统一主机路径。

## 7. Windows qB config mutation safety

任何 installer 对 qB config 的外部修改必须是 byte-safe transaction：

```text
read raw bytes
-> strict decode
-> preserve encoding/BOM/newline behavior
-> parse target [Preferences] keys
-> byte-identical backup
-> write temp file
-> invariant reread
-> confirm target original unchanged
-> safe replace
-> post-write verify
-> rollback on failure
```

禁止用 PowerShell whole-file `Get-Content/Set-Content` 默认编码路径直接重写 qB config。

### 7.1 Running qB

若 qB仍运行且可能写 config，installer必须先阻止 unsafe concurrent mutation；不能假设“刚读完文件”后 qB不会覆盖。

### 7.2 Recovery / invalid file

如果 primary config无效而存在 source-proven/reliable recovery file，只能按明确策略恢复；不能静默用空/default config覆盖用户配置。

### 7.3 Target unchanged check

在 temp file写好后、replace之前必须确认原目标文件仍与最初读取 identity一致；若外部进程已修改，必须 abort而不是覆盖新内容。

## 8. Backup retention

Installer-owned backup必须 bounded。当前规则：最多保留3份，并且顺序必须是：

```text
create + verify new backup
-> update last-backup pointer/metadata
-> only then prune oldest installer-owned backups beyond limit
```

不能先 prune再更新 latest pointer；失败时不能让唯一可恢复 backup被删掉。

用户自己创建的备份不属于 installer retention owner，不得按文件名相似就删除。

## 9. Upgrade

升级必须区分 product folder 与 qB user config：

```text
replace materialized WeiG product bytes
!=
delete/reset qB user preferences
```

升级默认保留用户 qB config、Torrent数据与非 installer-owned文件。若需要迁移 WeiG 自有持久化 state，应由对应 canonical owner提供向后兼容或明确 migration，installer不得猜。

旧 product folder可用临时目录/atomic-ish replace策略减少半安装状态；失败时应恢复上一份已知可用 product folder，而不是留下缺文件目录。

## 10. Rollback

Rollback对象至少可能包括：

```text
previous materialized WeiG folder
previous qB config bytes
installer metadata
```

恢复必须与实际失败阶段对应。若 product copy失败但 config尚未改，不应多余改 config；若 config replace失败，应恢复 byte-identical backup并验证。

## 11. Dev / Stable identity separation

Dev 与 Stable 不能混用 identity：

```text
Dev -> current validated Pages materialized exact-SHA payload
Stable -> immutable Release/tag/checksum payload
```

Dev installer不能因为 Pages暂时不可用就偷偷下载 raw dev source；Stable installer不能因为发现更新的 dev就越过 Release渠道。
