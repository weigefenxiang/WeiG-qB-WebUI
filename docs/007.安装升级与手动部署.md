# 007. 安装、升级与手动部署

Status: **stable distribution guide + explicit dev channel**

默认稳定安装以 GitHub Release 为事实源；`dev` 是显式开发频道。历史 WeiG 版本通过对应 Release/tag 恢复，当前仓库不保留 version-named deployment scripts。

## 1. 安装频道

### Release

```text
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest
WeiG-qB-WebUI.zip
SHA256SUMS
```

Release 安装必须验证 ZIP、SHA256SUMS、有效 `GIT_SHA` 和完整 Alternate WebUI entry points。失败时 fail closed，不回退 branch archive。

### dev

Installer 先解析 current `dev` exact SHA，再下载该 SHA source archive，只部署 `webui/`，并写入 exact `GIT_SHA`。

```text
dev != stable Release
dev != automatic fallback
```

普通 dev 安装/更新只是开发频道体验，不等于该 SHA 已进入 release candidate 流程。

## 2. Linux / Docker / NAS

Release：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o /tmp/weigg-qb-install.sh && sh /tmp/weigg-qb-install.sh --configure
```

dev：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/dev/installers/install.sh -o /tmp/weigg-qb-install.sh && sh /tmp/weigg-qb-install.sh --channel=dev --configure
```

多 container：

```sh
sh /tmp/weigg-qb-install.sh --list-containers
sh /tmp/weigg-qb-install.sh --container=<qb-container> --configure
```

Docker 中 qBittorrent 必须使用 container-visible path，例如 `/config/weigg-qb-webui`，不能把 Host path 填进 qB。

## 3. Windows

Release：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile $env:TEMP\weigg-qb-install.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Channel Release -Configure
```

dev：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/dev/installers/install.ps1 -OutFile $env:TEMP\weigg-qb-install.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Channel Dev -Configure
```

## 4. 手动安装

Release 页面下载 `WeiG-qB-WebUI.zip + SHA256SUMS`，校验后解压。Alternate WebUI root 必须包含：

```text
public/index.html
public/login.html
private/index.html
VERSION
GIT_SHA
```

qBittorrent：Tools / Options / Preferences -> Web UI -> Use alternative WebUI -> Files location / Root Folder。

## 5. Exact-SHA LIVE deployment

真实 qB LIVE deployment 是 **main promotion / Release 前**的验证工具，不是普通 dev 每个 SHA 的默认交付步骤。普通 dev 先使用 normal CI / Upstream / relevant Virtual qB Pages 验证；当 maintainer 决定晋级 `main` 时，再冻结 final dev exact SHA 并执行 qB4/qB5 Real LIVE。

真实验证统一使用稳定文件名：

```text
tests/live.sh
```

无本地仓库时：

```sh
SHA=<40-char-current-dev-sha>
curl -fL "https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/${SHA}/tests/live.sh" -o /tmp/weigg-live.sh
sh /tmp/weigg-live.sh --sha "$SHA" --target /path/to/weigg-qb-webui
```

`live.sh` 从目标 exact SHA 自身 `webui/VERSION` 读取产品版本，不硬编码 v0.3.x。运行时 staging 使用 `.new-live-*`，rollback backup 使用 `.before-live-YYYYMMDD-HHMMSS`；成功切换后统一按修改时间只保留最近 **3** 份 sibling rollback backups，并把历史 `.before-*` / `.ui-backup-*` 命名一起纳入清理。因此旧的 `before-v036-*`、`before-v037-*`、`before-live-*`、`ui-backup-*` 不会继续无限堆积。

真实 modern qB API regression 使用：

```text
tests/live-api.sh
```

qBittorrent 5.0.0+、5.2.x、WebAPI 2.3.0+ 等信息可以存在于脚本测试逻辑和 UI capability copy 中，因为这些是当前兼容事实，不是文件版本身份。

任何新 commit 都产生新的 exact validation identity。若 LIVE 后 tree 又变化，则旧 LIVE 不能继承；只有仍准备晋级 `main` 的最终 SHA 才继续称为 candidate。

## 6. 更新 / 回滚

Release：

```sh
sh /tmp/weigg-qb-install.sh --update
```

dev：

```sh
sh /tmp/weigg-qb-install.sh --update --channel=dev
```

立即回到 qB built-in WebUI：关闭 **Use alternative WebUI**。

Linux rollback：

```sh
sh /tmp/weigg-qb-install.sh --rollback
```

Windows rollback：

```powershell
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Mode Rollback
```

## 7. Deployment identity

安装后检查：

```text
VERSION
GIT_SHA
private/weigg-install.json
```

真实部署域名、凭据、container 名和机器专属路径不得写入公开源码。

## 8. Compatibility

Minimum supported target: **qBittorrent 4.1.9.1**。

Private/PT 在缺少 authoritative metadata 的实例保持 `5.0.0+ / 此功能需要 qBittorrent 5.0.0+` capability notice；Tags 以 **WebAPI 2.3.0+** 为 capability threshold。这些版本提示必须保留。
