# 007. 安装、升级、Dev Distribution 与 Windows 配置安全

Status: **current install / update / rollback / deployment authority**

本文件统一维护 Stable/Dev 安装来源、Linux/Docker/Windows 部署、Pages materialized distribution、Windows qB config mutation与 backup retention。Windows Dev 与历史编码事故不再拆成单独复盘文件。

## 1. 当前安装来源

当前产品支持基线：

```text
qBittorrent 4.1.0 -> 5.2.3 admitted stable
qB 4.0.x / WebAPI v1: not supported
```

当前发布事实：

```text
latest published Release: v0.3.61
repository/product VERSION: 0.3.83
v0.3.83 tag/Release: not published
```

因此开发仓库 VERSION不等于正式 Release。

### Stable

普通用户优先使用最新 GitHub Release。Stable installer必须：

```text
resolve exact Release/tag
-> validate tag vX.Y.Z
-> resolve tag commit SHA
-> pin assets to exact tag
-> verify SHA256SUMS
-> verify package VERSION == tag version
-> verify package GIT_SHA == tag commit SHA
```

Identity/checksum不一致必须 fail closed，不 fallback到 latest/dev。

### Dev

Dev不是 Stable fallback。Linux/Windows Dev只消费 Virtual qB Pages发布的 **materialized distribution**，禁止 raw-source archive fallback。

Canonical identity：

```text
Pages downloads/dev/GIT_SHA
== downloaded package GIT_SHA
== package manifest gitSha
```

Current `dev` HEAD可以因明确的 repository-only/Pages-irrelevant commit领先 materialized SHA，但只有 canonical classifier能证明这种 representability。

## 2. Dev public-payload classifier

当前问题定义是：

> 哪些 repository changes 会改变公开 materialized Dev payload？

Pages Source、Pages stale-deploy gate和 installer必须使用同一 canonical relevance语义，不能各自维护第二份例外名单。

当：

```text
current dev HEAD == materialized SHA
```

可直接消费。

当 HEAD领先：

```text
materialized SHA -> current dev HEAD
-> GitHub compare
-> all changes proven Pages-irrelevant
   -> may reuse last verified payload
-> any Pages-relevant / unknown / invalid / truncated state
   -> fail closed and wait for new exact Pages materialization
```

不得把“docs-only通常安全”简化成 permissive fallback；判断必须由当前 canonical matcher/workflow证明。

正式 candidate/promotion/release的 final dev SHA仍必须满足 `docs/006` 的 exact evidence gate；Dev stale-safe representability不能替代 release evidence。

## 3. Linux / NAS / Docker

Stable bootstrap：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh
sh weigg-install.sh --configure
```

Dev：

```sh
sh weigg-install.sh --dev --configure
```

默认 Linux install root：

```text
~/.local/share/weigg-qb-webui
```

Docker Alternative WebUI `Root Folder`必须使用**容器内路径**。例如：

```text
host:      /root/qbittorrent/config/weigg-qb-webui
container: /config/weigg-qb-webui
```

则 qBittorrent中填写 `/config/weigg-qb-webui`。

多个 qB容器/配置候选存在时 installer不得猜，可使用：

```text
--list-containers
--container=<name>
--config-root=<host path>
```

## 4. Windows Dev / Stable

Stable：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

Dev推荐直接获取与 materialized payload同步发布的 bootstrap：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure
```

指定目录示例：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -o "D:\WeiG-qB-WebUI" -configure
```

如果只更新 WebUI文件、不希望修改 qB配置，省略 `-configure`。Portable/custom profile或多个候选时使用：

```powershell
-qbconfig "<exact qBittorrent.ini path>"
```

Installer不得在多个 config候选之间静默猜测。

## 5. Windows qB config mutation safety

外部修改 `qBittorrent.ini` 必须 fail closed。写入前至少检查：

```text
qBittorrent.exe not running
no non-empty qBittorrent_new.ini / recovery file
config non-empty and structurally plausible
unambiguous config target
exactly one [Preferences]
managed WebUI keys unique and owned by [Preferences]
```

Mutation chain：

```text
strict decode + byte round-trip
-> byte-identical safety backup
-> mutate in memory
-> temp write
-> strict reread
-> encoding/BOM/newline/invariant verification
-> recheck target unchanged
-> safe/atomic replacement
-> post-replace reread/verification
-> rollback only when safe
```

必须保留现有 encoding/BOM：

```text
UTF-8 BOM
UTF-8 no BOM
UTF-16 LE BOM
UTF-16 BE BOM
```

禁止重新引入：

```powershell
Get-Content $cfg -Raw
Set-Content -Encoding UTF8 $cfg
```

这类 whole-file transcode会破坏中文/日文路径、Tags等 Unicode内容。

遇到非空 recovery/new config文件必须停止，不得先删除它再继续写正式 config。

已有 mojibake恢复应以 known-good backup中同 key值为权威；禁止对未知乱码自动逆转码。

## 6. Materialized Dev payload 必需内容

Dev distribution至少应包含并保持 identity一致：

```text
private/data/qb-releases.json
private/data/qb-release-profiles/
private/data/qb-settings-native.txt
private/data/qb-settings/<sourceSha>.json where source-proven bridge is required
translations/webui_*.qm
VERSION
GIT_SHA
manifest.json
```

缺失这些 build-time materialized facts时，真实 qB可能表现为 source proof/settings/translation failure。正确做法是核对 materialized identity并等待正确 Pages build，不是放宽 runtime source guard。

## 7. Backup / rollback retention

Windows 与 shell installer只保留最新 **3** 个 installer-owned timestamp backup。

成功安装/备份时顺序固定：

```text
complete new backup
-> write state/last-backup rollback pointer
-> prune older installer-owned backups
```

Pruning ownership必须同时满足：

```text
directory name exactly matches YYYYMMDD-HHMMSS
AND had-webui marker exists
AND dest-path marker exists
```

按 timestamp newest-first只删除第4个及更旧的 owned backup。

禁止删除：

```text
ordinary files
user-created directories
non-timestamp directories
timestamp-looking directories missing either ownership marker
```

禁止在写入新的 `last-backup` pointer之前 prune，否则可能破坏 rollback identity。

Rollback入口：

```sh
sh weigg-install.sh --rollback
```

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -rollback
```

## 8. 常用参数

| 用途 | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| 最新正式版 | 默认 | 默认 |
| 指定 Release | `--version X.Y.Z` | `-version X.Y.Z` |
| 开发版 | `--dev` | `-dev` |
| 指定目录 | `-o /path` / `--output /path` | `-o D:\path` / `-output D:\path` |
| 自动配置 qB | `--configure` | `-configure` |
| 回滚 | `--rollback` | `-rollback` |
| 指定 Docker 容器 | `--container=NAME` | — |
| 指定 Docker config root | `--config-root=/path` | — |
| 指定 Windows qB config | — | `-qbconfig PATH` |

指定版本不存在时直接失败，不能 fallback到 latest/dev。

## 9. 手动安装 / Release publisher

手动 Stable至少验证：

```text
SHA256SUMS
VERSION
GIT_SHA
```

Alternative WebUI root至少包含：

```text
public/
private/
VERSION
GIT_SHA
```

正式 Release只消费已经验证的 exact dev candidate artifact，不在 main/tag后重新 build另一个 ZIP。完整 release gate见 `docs/006.发布与晋级流程.md`。
