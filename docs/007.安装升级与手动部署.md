# 007. 安装、升级与手动部署

**语言**：[English](../README.md) · **简中** · [繁中](../translations/README.zh-TW.md) · [日本語](../translations/README.ja.md) · [한국어](../translations/README.ko.md) · [Deutsch](../translations/README.de.md) · [Français](../translations/README.fr.md) · [Español](../translations/README.es.md) · [Português](../translations/README.pt.md) · [Русский](../translations/README.ru.md)

这是一份安装来源与部署规则 authority。普通用户优先使用最新正式 Release；只有明确测试开发版时才使用 `dev`。

当前产品支持基线：

```text
qBittorrent 4.1.0 -> 5.2.3 admitted stable
qB 4.0.x / WebAPI v1: not supported
```

> **Windows Dev 特别规则：不要使用 `main/installers/install.ps1 -dev`。** 当前 Dev 必须使用 Pages `downloads/dev/install.ps1`，因为 Dev runtime 需要 exact-SHA materialized catalog/profile/QM/translation assets。完整说明见 `docs/008.Windows开发版安装.md`。

## 1. 安装来源

### 1.1 最新正式 Release

普通用户推荐。Release 至少包含：

```text
WeiG-qB-WebUI.zip
SHA256SUMS
```

安装器必须验证 checksum、`VERSION`、`GIT_SHA`；失败时 fail closed，不得自动退回 dev。

### 1.2 指定 Release

Linux：

```sh
sh weigg-install.sh --version 0.3.61 --configure
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -version 0.3.61 -configure
```

指定版本不存在时直接失败，不 fallback 到 latest 或 dev。

### 1.3 Dev

Dev 不是 Release fallback。Dev 必须绑定当前 `dev` 40 位 exact Git SHA，并部署该 SHA 对应的 materialized payload。

Linux/Docker Dev 可以继续由当前脚本按 exact SHA 规则处理；Windows Dev 入口单独见第 5 节。

## 2. 常用参数

| 用途 | Linux / Docker / NAS | Windows PowerShell |
|---|---|---|
| 最新正式版 | 默认 | 默认 |
| 指定正式版本 | `--version X.Y.Z` | `-version X.Y.Z` |
| 开发版 | `--dev` | `-dev` |
| 指定目录 | `-o /path` / `--output /path` | `-o D:\path` / `-output D:\path` |
| 自动配置 qB | `--configure` | `-configure` |
| 回滚 | `--rollback` | `-rollback` |
| 帮助 | `--help` | `-help` |
| 指定 Docker 容器 | `--container=NAME` | — |
| 列 Docker 容器 | `--list-containers` | — |
| 指定 Docker config root | `--config-root=/path` | — |

旧参数为了兼容历史自动化仍可能存在，但新文档优先使用上表。

## 3. Linux / NAS

稳定版一键：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh && sh weigg-install.sh --configure
```

默认安装到：

```text
~/.local/share/weigg-qb-webui
```

只装文件、不改 qB：

```sh
sh weigg-install.sh
```

指定目录：

```sh
sh weigg-install.sh -o /opt/weigg-qb-webui --configure
```

Dev：

```sh
sh weigg-install.sh --dev --configure
```

回滚：

```sh
sh weigg-install.sh --rollback
```

安装器应支持常见下载/解压/hash 工具组合；找不到可验证 SHA-256 的工具时，Release 安装必须拒绝继续。

## 4. Docker

最简单的一键仍是：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o weigg-install.sh && sh weigg-install.sh --configure
```

关键原则：qB 运行在容器里时，qB 的 Alternative WebUI `文件位置` 必须是**容器看到的路径**。

例如：

```yaml
volumes:
  - /root/qbittorrent/config:/config
```

则：

```text
宿主机 WebUI: /root/qbittorrent/config/weigg-qb-webui
qB Root Folder: /config/weigg-qb-webui
```

不要把宿主机 `/root/...` 路径直接填进容器内 qB。

多个 qB 容器时先：

```sh
sh weigg-install.sh --list-containers
```

再明确指定：

```sh
sh weigg-install.sh --container=qbittorrent --configure
```

已知宿主机 `/config` 映射目录时：

```sh
sh weigg-install.sh --config-root=/root/qbittorrent/config --configure
```

Dev：

```sh
sh weigg-install.sh --container=qbittorrent --dev --configure
```

多个候选容器/路径存在时安装器不得随便猜。

## 5. Windows PowerShell

### 5.1 稳定版

稳定版 bootstrap 来自 `main`：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

默认安装目录：

```text
%LOCALAPPDATA%\WeiG-qB-WebUI
```

指定 D 盘目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -o "D:\WeiG-qB-WebUI" -configure
```

### 5.2 Dev：必须使用 Pages bootstrap

正确：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure
```

本轮真实环境指定目录示例：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure -o "D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
```

禁止把下面这种命令当作 Dev authority：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -dev ...
```

原因：旧 main installer 的 Dev 路径曾直接部署 raw source，而当前 Dev 运行时依赖构建期 materialized：

```text
compact qb-releases index
exact release profile shards
qb-settings-native.txt
official minimal webui_*.qm
source-proven Settings bridge shards
```

Pages Dev 安装器验证：

```text
current dev HEAD == downloads/dev/GIT_SHA == package GIT_SHA
```

不一致时应让用户等待 Pages 追上 exact SHA，而不是 raw-source fallback。

### 5.3 Windows `-configure` 安全注意

2026-09-11 真实事故证明，旧 PowerShell 5.1 whole-file text rewrite 曾把 qB `qBittorrent.ini` 的 UTF-8 no-BOM 中文/日文转成 mojibake。

当前 dev 已修 encoding-preserving read/write 并有 Windows PowerShell 5.1 regression；但以下 installer hardening 仍在待办：

```text
qB running -> fail closed
non-empty qBittorrent_new.ini -> fail closed
zero/invalid config -> fail closed
temp write -> strict verify -> atomic replace
portable/custom/multi-config ambiguity -> do not guess
```

在这些 guardrails 完成前，测试 Dev `-configure` 时**先完全退出 qBittorrent**。

只读确认：

```powershell
[bool](Get-Process qbittorrent -ErrorAction SilentlyContinue)
Test-Path "$env:APPDATA\qBittorrent\qBittorrent_new.ini"
```

理想结果：

```text
False
False
```

完整事故复盘见 `docs/013.Windows配置编码事故复盘.md`。

## 6. 手动安装

不运行脚本时，可以手动下载最新 Release：

```text
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest
```

Windows 示例：

```powershell
Invoke-WebRequest https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip -OutFile .\WeiG-qB-WebUI.zip
Get-FileHash .\WeiG-qB-WebUI.zip -Algorithm SHA256
Expand-Archive .\WeiG-qB-WebUI.zip .\WeiG-qB-WebUI -Force
```

必须与 `SHA256SUMS` 对应哈希比较。

解压根应至少包含：

```text
public/
private/
VERSION
GIT_SHA
```

qB Alternative WebUI 中的 `文件位置` 指向这个根目录，而不是它的父目录或再下一层。

## 7. 更新与回滚

重新运行同一安装来源就是更新。

Linux stable：

```sh
sh weigg-install.sh --configure
```

Windows stable：

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure
```

Windows Dev 应重新下载 Pages Dev bootstrap，再执行 `-dev`，确保 bootstrap 与 materialized payload 同步。

回滚：

```sh
sh weigg-install.sh --rollback
```

```powershell
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -rollback
```

回滚不能替代配置备份审计。若用户已经发生 Unicode mojibake，应从**已知正常备份**恢复对应 key；不要盲目做自动逆转码。

## 8. 常见问题

### 页面仍是旧内容

先：

```text
Ctrl + F5
```

并核对安装目录的 `GIT_SHA`。

### Source-proven 错误

优先检查：

```text
GIT_SHA 是否为 current dev exact SHA
private/data/qb-releases.json 是否为非空 compact index
private/data/qb-release-profiles/ 是否存在
active qB sourceSha profile shard 是否存在
```

不要通过放宽 source guard 让危险 action 发 HTTP。

### Windows 中文路径乱码

如果已有 torrent 的“更改保存位置”路径正常，而“默认保存路径”乱码，优先检查全局 `qBittorrent.ini`：

```text
General\Locale
Session\DefaultSavePath
Session\TempPath
SavePathHistory
Session\Tags
```

本轮真实环境最终正常基线：

```text
General\Locale=zh_CN
Session\DefaultSavePath=D:\\clash\\u\\下载
Session\TempPath=D:\\clash\\其他文件\\下载临时文件夹
```

### Release checksum 失败

不要绕过。重新下载并调查 Release asset / checksum identity。

## 9. 安装后身份确认

安装目录：

```text
VERSION
GIT_SHA
private/weigg-install.json
```

`VERSION` 不是足够的 build identity。尤其 dev 可能多个 commit 都暂时保持同一 VERSION；调试时必须看 40 位 `GIT_SHA`。

Materialized Dev 还应确认：

```powershell
$root="D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
Get-Content "$root\GIT_SHA"
Get-Item "$root\private\data\qb-releases.json" | Select-Object Length
(Get-ChildItem "$root\private\data\qb-release-profiles" -Filter '*.json').Count
Test-Path "$root\private\data\qb-settings-native.txt"
Test-Path "$root\translations\webui_zh_CN.qm"
```
