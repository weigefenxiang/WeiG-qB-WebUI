# 007. 安装、升级与手动部署

Status: **stable distribution guide**

本文件面向普通用户。稳定安装只以 GitHub Release 为事实源；`dev` / `main` 用于开发与预发布，不是稳定下载包。

## 1. 稳定下载入口

```text
Latest Release
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest

WebUI ZIP
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/WeiG-qB-WebUI.zip

SHA256 checksum
https://github.com/weigefenxiang/WeiG-qB-WebUI/releases/latest/download/SHA256SUMS
```

如果 `releases/latest` 还不存在，说明当前还没有正式稳定版。不要把 `dev`、`main` 或 GitHub Actions 临时 artifact 当成普通用户稳定版。

Linux/Windows bootstrap installer 也遵循同一规则：**Release 不存在就失败，不会回退 main**。

## 2. 平台选择

| 环境 | 推荐方式 |
|---|---|
| Linux 原生 qBittorrent | `install.sh` |
| Docker / Docker Compose | `install.sh` 自动识别 `/config` mount |
| Synology / Unraid / TrueNAS SCALE 等 Docker/NAS | 宿主机运行 `install.sh`，或手动安装 |
| Windows | `install.ps1` |
| macOS / FreeBSD / 其它系统 | 手动安装 Release ZIP |
| 特殊容器/只读系统 | 手动安装到持久可写目录 |

一键安装器只是 bootstrap。稳定 WebUI payload 最终只来自 Release ZIP，并校验 `SHA256SUMS` 与 exact `GIT_SHA`。

## 3. Linux / Docker / NAS 一键安装

最简单：

```sh
curl -fsSL https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.sh -o /tmp/weigg-qb-install.sh && sh /tmp/weigg-qb-install.sh --configure
```

`--configure` 会在能够安全识别 qBittorrent 配置时启用 Alternate WebUI，并写入 qBittorrent 进程可见的 WebUI Root Folder。安装前会备份原 WebUI 和可识别的 qB 配置。

稳定安装器要求系统存在：

```text
unzip
sha256sum
curl 或 wget
```

如果 Release ZIP、`SHA256SUMS`、有效 `GIT_SHA` 或 Alternate WebUI 必需入口缺失，安装器会拒绝继续。

只安装文件、不自动修改 qB 配置：

```sh
sh /tmp/weigg-qb-install.sh
```

### 3.1 Docker 自动识别

当宿主机存在一个正在运行的 qBittorrent Docker container，并且有：

```text
/config -> host path
```

安装器会选择类似：

```text
Host install path:
<host-config>/weigg-qb-webui

qBittorrent Root Folder:
/config/weigg-qb-webui
```

qBittorrent 设置里要填 **容器内路径**，不是宿主机路径。

### 3.2 多个 qBittorrent 容器

安装器不会猜。先查看：

```sh
sh /tmp/weigg-qb-install.sh --list-containers
```

指定容器：

```sh
sh /tmp/weigg-qb-install.sh --container=<qb-container> --configure
```

或指定宿主机 `/config` 根目录：

```sh
sh /tmp/weigg-qb-install.sh --config-root=/srv/qbittorrent/config --configure
```

### 3.3 自定义安装目录

原生 Linux：

```sh
sh /tmp/weigg-qb-install.sh --dir=/opt/weigg-qb-webui
```

Docker 中也可以直接给 qB-visible path：

```sh
sh /tmp/weigg-qb-install.sh --container=<qb-container> --dir=/config/weigg-qb-webui --configure
```

安装器会在能够确定 `/config` host mount 时映射到宿主机真实目录。

## 4. Windows PowerShell 一键安装

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile $env:TEMP\weigg-qb-install.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Configure
```

Windows installer 会下载 Release ZIP 与 `SHA256SUMS`，使用 `Get-FileHash -Algorithm SHA256` 验证后才安装；Release 或 checksum 不存在时直接失败。

默认安装位置由安装器选择用户可写目录。自定义目录：

```powershell
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Destination "D:\Apps\WeiG-qB-WebUI" -Configure
```

只安装文件、不修改 qB 配置：

```powershell
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1
```

## 5. qBittorrent 中手动启用

无论哪个系统，最终都使用 qBittorrent 标准 Alternate WebUI 设置：

```text
Tools / Options / Preferences
-> Web UI
-> Use alternative Web UI
-> Files location / Root Folder
```

填写的是 **qBittorrent 进程能够看到的 WeiG WebUI 根目录**。

目录至少应包含：

```text
public/index.html
public/login.html
private/index.html
VERSION
GIT_SHA
```

Docker 通用示例：

```text
宿主机：/srv/qbittorrent/config/weigg-qb-webui
容器内：/config/weigg-qb-webui
```

qBittorrent 中填写：

```text
/config/weigg-qb-webui
```

## 6. 通用手动安装

适用于 Linux、Windows、macOS、FreeBSD、NAS 或任何无法使用自动脚本的环境。

### 6.1 下载同一个 Release 的文件

```text
WeiG-qB-WebUI.zip
SHA256SUMS
```

### 6.2 校验 SHA256

Linux：

```sh
sha256sum -c SHA256SUMS
```

Windows PowerShell：

```powershell
Get-FileHash .\WeiG-qB-WebUI.zip -Algorithm SHA256
Get-Content .\SHA256SUMS
```

两边 SHA256 必须一致。

### 6.3 解压并检查身份

Release ZIP 内目录：

```text
WeiG-qB-WebUI/
```

复制到持久可写位置后检查：

```text
VERSION  -> 产品版本
GIT_SHA  -> 精确发布 commit
```

稳定 Release 的 `GIT_SHA` 必须是 40 位 Git SHA。

同时检查三个 qB Alternate WebUI 入口：

```text
public/index.html
public/login.html
private/index.html
```

## 7. 更新

Linux / Docker / NAS：

```sh
sh /tmp/weigg-qb-install.sh --update
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Mode Update
```

更新仍然安装最新稳定 Release，不以 `dev` 或 `main` 为更新源。没有稳定 Release 时更新失败，不会切换到 branch archive。

## 8. 回滚

Linux：

```sh
sh /tmp/weigg-qb-install.sh --rollback
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File $env:TEMP\weigg-qb-install.ps1 -Mode Rollback
```

回滚恢复上一份 WebUI；如果安装器曾修改 qB 配置，也会尽可能恢复对应备份。

## 9. 稳定部署 contract

```text
下载 Release ZIP
-> 下载 SHA256SUMS
-> 强制校验 SHA256
-> 解压到 staging
-> 检查 public/index.html + public/login.html + private/index.html
-> 检查 exact GIT_SHA
-> 写部署 metadata
-> 备份旧版本
-> 原子替换
-> 输出安装路径与 qB-visible path
```

部署 metadata 位于：

```text
private/weigg-install.json
```

它可以记录版本、Git SHA、安装路径、qB-visible path、container（如适用）和安装时间。真实部署域名、凭据、维护者容器名和机器专属路径不得写进公开源码。

## 10. Release 尚未发布时

项目开发期可能存在：

```text
dev candidate
GitHub Actions release-candidate artifact
main source
```

这些都不是普通用户稳定分发入口。首次稳定 Release 前，维护者可以使用 exact-SHA live helper 做真实环境验证；普通用户文档始终以 `releases/latest` 为准。

当前 bootstrap installer 已进入稳定 fail-closed 模式：`releases/latest` 不存在时明确报错，不再把 `main` 当作稳定 payload。

## 11. 常见问题

### 页面 404 / Unauthorized

确认 Root Folder 指向 WebUI 根目录，而不是 `private/` 或 `public/` 子目录，并确认三个入口文件均存在。

### Docker 宿主机有文件，但 qB 看不到

通常是把宿主机路径填进了 qB。检查：

```sh
docker inspect <qb-container>
```

qBittorrent 中必须使用容器内可见路径。

### 多容器时安装器拒绝继续

这是安全行为。使用：

```sh
--list-containers
--container=<qb-container>
```

明确目标。

### 安装器提示没有 stable Release

这表示项目当前没有可供普通用户安装的正式 Release，或者 GitHub Release asset 暂时不可访问。安装器不会自动退回 `main`。维护者测试候选版本应使用 exact-SHA candidate/live helper，而不是修改稳定安装器来源。

### 更新后浏览器仍像旧版

先检查安装目录中的 `GIT_SHA`。WebUI 静态资源使用 exact SHA 作为 cache identity；确认 qB 指向正确目录后再强制刷新浏览器。

### 想固定旧版本

进入对应 GitHub Release 页面下载该版本的 ZIP 和 SHA256SUMS，手动安装。不要用 branch archive 模拟固定稳定版本。
