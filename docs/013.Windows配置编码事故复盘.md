# 013. Windows 配置编码事故复盘

Status: **2026-09-11 incident postmortem / current handoff authority for the Windows corruption incident**

本文记录 2026-09-11 在真实 Windows qBittorrent 4.6.7 环境中发现的 WeiG qB WebUI 开发版安装、runtime catalog、qB-owned Settings 翻译与 qBittorrent 配置编码问题。本文只描述已经被源码、CI 或真实用户环境证明的事实，并明确尚未完成的项目工作。

`main`、tag、GitHub Release 在本轮排障中均不得修改；全部开发工作只进入 `dev`。

## 2. 事故症状

本轮实际上暴露了三条不同故障链，不能混为一个问题：

### 2.1 Dev raw-source 安装导致 runtime facts 缺失

用户最初使用：

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/weigefenxiang/WeiG-qB-WebUI/main/installers/install.ps1 -OutFile .\weigg-install.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install.ps1 -configure -o D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI -dev
```

旧 `main/installers/install.ps1` 的 Dev 路径直接下载 GitHub source archive；raw `webui/**` 不包含 candidate/Pages 在构建期 materialize 的完整 runtime catalog、exact release profile、Settings native registry、official QM 和 exact translation bridge data。

典型症状：

```text
This API action is not source-proven for the current qBittorrent release.
This qBittorrent version returned no settings in this group.
qB-owned Settings labels fall back to English.
```

因此 Windows Dev 不能再通过 `main` 安装器 + `-dev` 获取 raw source。

正确 Dev 入口是 Pages 与 exact-SHA materialized payload 同时发布的安装器：

```powershell
Invoke-WebRequest https://weigefenxiang.github.io/WeiG-qB-WebUI/downloads/dev/install.ps1 -OutFile .\weigg-install-dev.ps1
powershell -ExecutionPolicy Bypass -File .\weigg-install-dev.ps1 -dev -configure -o "D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI"
```

安装器必须验证：

```text
current dev SHA
== downloads/dev/GIT_SHA
== package embedded GIT_SHA
```

不允许 raw-source fallback。

### 2.2 单体 runtime catalog 对真实 qB 静态服务器过大

早期 materialized `private/data/qb-releases.json` 携带 65 个 full profile 后接近 9.5 MiB。Pages/普通静态服务器可以读取，但真实 qB Alternative WebUI 静态文件链存在约 10 MiB 级实用边界，导致真实 qB 上 catalog load 失败或不稳定。

旧 `release-profile.js` 又会把 catalog load failure 吞成空 catalog/fallback，最终错误表现为“source-proven 不足”，掩盖了真正的静态资源加载问题。

已改为 runtime sharding：

```text
private/data/qb-releases.json                    # tiny index
private/data/qb-release-profiles/<sourceSha>.json # active profile shard
```

在 `c1823a4f7a721b34eab7db1855f30844ca43b43e` 构建的 materialized artifact 中曾验证：

```text
runtime release index: ~14.6 KiB
stable profile shards: 65
qB 4.6.7 exact profile shard: ~183 KiB
qB 4.6.7 Settings bridge shard: < 1 MiB
minimal official QM files: 96
webui_zh_CN.qm: present
```

运行时只加载 index + 当前 exact/inherited profile shard；catalog/profile HTTP error 不再静默退化为空 catalog。

### 2.3 Windows PowerShell 5.1 配置转码污染

旧 Windows 安装器在 `-configure` 时使用默认文本读取/写入方式处理整个 `qBittorrent.ini`。Windows PowerShell 5.1 对 UTF-8 no-BOM 文本的默认解码可能走系统 ANSI/GBK，再以 UTF-8 写回，从而造成经典 UTF-8 -> GBK mojibake。

真实损坏例：

```text
下载            -> 涓嬭浇
其他文件        -> 鍏朵粬鏂囦欢
电影            -> 鐢靛奖
moka酱          -> moka閰?
小西まりえ      -> 灏忚タ...
永野いち夏      -> 姘搁噹...
```

污染不只影响：

```text
Session\DefaultSavePath
Session\TempPath
```

还污染过：

```text
SavePathHistory
Session\Tags
```

因此“只修默认下载路径”不足以证明配置已清理干净。

## 3. 已实现的 Windows 编码修复

`dev/installers/install.ps1` 已加入 encoding-preserving config I/O：

```text
Read-QBConfigText
Write-QBConfigText
Configure-QBWebUI
```

当前逻辑能够识别并保留：

```text
UTF-8 BOM
UTF-8 no BOM (strict UTF-8)
UTF-16 LE BOM
UTF-16 BE BOM
system default only as fallback
```

并执行 byte round-trip safety check；无法无损往返时拒绝重写。

已有 Windows PowerShell 5.1 regression `tests/windows-config-encoding.ps1`，真实使用 `powershell.exe` 执行，覆盖中文路径与 BOM/no-BOM：

```text
D:\clash\u\下载
D:\clash\其他文件\下载临时文件夹
D:\软件\下载工具\qbittorrent\WeiG-qB-WebUI
```

该 regression 在 candidate 的 Windows browser job 中已通过。

## 4. 本地恢复过程与教训

历史备份证明 `20260911-172729` 是已知正常配置；后续多份备份出现一代或二代 mojibake。恢复策略坚持：

```text
known-good backup source
-> restore only proven-corrupted keys when possible
-> strict UTF-8 read
-> temp file validation
-> atomic replace
-> post-start reread verification
```

最终从 `20260911-172729/qBittorrent.conf` 恢复：

```text
General\Locale
Session\DefaultSavePath
Session\TempPath
SavePathHistory
Session\Tags
```

并确认整份当前 INI 的已知 mojibake pattern count 为 0。

本轮排障中还出现一次人为恢复脚本事故：用户将多段 PowerShell 分开执行，导致上下文变量不完整，正式 `qBittorrent.ini` 一度被写成 0 字节。随后从完整备份恢复。这个事故不是 qB 或 WeiG 产品 runtime 自动造成，但形成永久脚本规则：

```text
不要给用户依赖跨段变量状态的修复脚本
优先使用 & { ... } 单一 PowerShell script block
先写 temp
验证 temp 完整性/关键值/size
最后 atomic replace
任何异常都保留原文件与 safety backup
```

不要尝试对未知 mojibake 自动“逆转码”；如果有已知正常备份，应以备份中的同 key 值为权威。

## 5. qB 4.6.7 配置事实

本轮查阅 qB 4.6.7 官方源码确认：

```text
Locale owner: Preferences/General/Locale
runtime SettingsStorage: loads QSettings data into memory and writes through *_new file
current default save key after migration: BitTorrent/Session/DefaultSavePath
current temp path key: BitTorrent/Session/TempPath
old Preferences/Downloads/SavePath is migration source, not current owner
```

qB 启动时如果发现非空 `qBittorrent_new.ini`，会把它作为未完成写入恢复来源。因此任何外部配置修改器都必须把 `qBittorrent_new.ini` 视为冲突/恢复状态，而不是忽略它。

## 6. Release profile / future version 策略

当前 release resolution 不是 `exact || fallback`，而是：

```text
EXACT       exact admitted official stable
EQUIVALENT  canonical suffix equivalence, e.g. 5.2.3-r1 -> 5.2.3
INHERITED   same major.minor nearest lower certified profile when safe
FALLBACK    no safe source-backed relation
```

目标例：

```text
5.2.4   -> temporarily inherit 5.2.3
5.2.3.1 -> inherit 5.2.3
```

但 inheritance 不等于“nearest wins”。不能跨 source-proven hard boundary 盲继承，例如 translator behavior 的 `4.6.4 -> 4.6.5` 边界。危险写操作仍要求 action/parameter/Preference provenance 证明；不能因为继承 profile 就放松 fail-closed。

运行时应保留：

```text
detectedVersion
resolvedFrom
resolutionMode = EXACT | EQUIVALENT | INHERITED | FALLBACK
```

## 9. 尚未完成，下一位维护者必须继续

### 9.1 Windows installer safety hardening

编码保留已经完成，但以下保护尚未进入 installer：

```text
1. -configure 时检测 qBittorrent.exe 正在运行 -> fail closed
2. 同配置目录存在非空 qBittorrent_new.ini -> fail closed
3. config 为 0 字节/异常小/无法解析 -> fail closed
4. Configure-QBWebUI 改为 temp write -> strict reread verify -> atomic replace
5. 原正式 INI 始终保留 safety backup；失败自动回滚
6. 配置发现需要继续审计 portable/custom-profile/多 config 歧义；不允许随便猜错文件
7. tests/windows-config-encoding.ps1 扩展上述 negative/fail-closed cases
```

注意：用户本机已证明实际使用 `%APPDATA%\qBittorrent\qBittorrent.ini`，不是 portable profile；但产品安装器仍应正确处理其它用户的 portable/custom profile 情况。

### 9.2 Fix candidate deployment acceptance

当前 deterministic failure 是：


需要检查 `tests/candidate-deployment.sh`、真实 qB public static path、candidate package 的 SHA exposure 方式，以及测试是不是对 qB public root 做了错误假设。不能降低 exact-SHA identity gate。

修复后必须至少让真实 qB：

```text

```

完成 candidate deployment + browser locale/settings chain acceptance。

### 9.3 Fix Pages live acceptance race

`tests/pages-live-acceptance.mjs` 当前 `waitForCatalog()` 在 `catalogReady` 变 true 后立即断言 `catalogBusy === false`。5000-torrent catalog 场景中二者存在短暂交叠。

修复原则：等待稳定条件：

```text
catalogReady === true && catalogBusy === false
```

给合理 timeout；不要通过删掉 busy 断言或修改 product state lifecycle 掩盖测试 race。
