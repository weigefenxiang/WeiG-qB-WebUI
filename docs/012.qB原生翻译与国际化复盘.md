# 012. qB 原生翻译与国际化复盘

Status: **accepted direction / implementation not yet cut over**

本文记录 2026-09-11 对 Locale / qB 官方翻译 / Alternative WebUI 翻译机制的重新复盘。它用于约束下一次产品改动，避免继续扩大临时 JSON translation projection。

`DESIGN.md` 仍是 Current Owner 最终 authority；本文明确区分“当前已经上线的事实”和“下一次产品切换目标”。

## 1. 已确认的产品原则

### 1.1 Locale 持久真值已经完成单 owner cutover

当前 `dev` 已经完成：

```text
qB app/preferences.locale
-> W.SettingsState / shared app.preferences
-> W.I18n.applyLocale(verified locale)
-> shared Desktop/Mobile presentation
```

`qBittorrent preferences.locale` 是唯一持久语言 owner。WeiG 不再保存第二份 `weigg-language`。

两个 UI 入口可以同时存在：

```text
WeiG WebUI -> Interface -> Language
qB Settings -> Advanced -> Locale
```

但它们必须编辑同一个 `draft.locale`、同一组选项、同一个 `QBClient.setPreferences()` 事务。

Locale 保存必须遵守：

```text
draft.locale
-> SettingsSchema writable provenance
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> verified prefs.locale
-> W.I18n.applyLocale()
```

不得在 qB 回读确认前先切换视觉语言。

## 2. qB 官方 WebUI 的真实翻译机制

重新核对 qB upstream `src/webui/webapplication.cpp` 后，确认不能把“官方译文存在”和“Alternative WebUI 自动拿到内置译文”混为一件事。

### 2.1 Built-in WebUI

现代 qB 的语言选项来自内置 Qt resource：

```text
:/www/translations/webui_*.qm
```

qB 根据这些 `webui_*.qm` 生成 `${LANGUAGE_OPTIONS}`。因此官方 WebUI 的翻译资源本来就在 qB 构建产物里。

### 2.2 QBT_TR 是 qB 的服务器端翻译抽象

qB WebApplication 在向浏览器发送可翻译 HTML/JS 时处理：

```text
QBT_TR(Source text)QBT_TR[CONTEXT=SomeContext]
```

并在服务器端把它替换成当前 Locale 的译文。浏览器收到的已经是替换后的文字。

因此，对于 qB upstream 已经拥有的语义，WeiG 的长期目标不是再建立一份浏览器 translation database，而是尽可能复用：

```text
official source/context
-> QBT_TR
-> qB translator
-> official translation
```

### 2.3 历史实现并不完全相同

已直接核实的两个端点：

**qB 4.1.0**：`translateDocument()` 对 `QBT_TR` 使用 `qApp->translate(context, source)`；它利用 qB 应用侧已经安装的 translator。

**qB 4.6.4 与 qB 5.2.3**：WebApplication 在 `configure()` 中从 active WebUI root 加载：

```text
<active WebUI root>/translations/webui_<locale>
```

随后 `translateDocument()` 使用该 `m_translator` 处理 `QBT_TR`。

因此不要写未经源码证明的类似结论：

```text
"所有 4.1.0+ 都以完全相同方式加载 Alternative WebUI .qm"
"某个猜测版本才开始支持 Alternative WebUI 翻译"
```

下一次实现前必须对 admitted 4.1.0 -> 5.2.3 release tags 做**轻量 translator-behavior audit**，定位真实实现边界，而不是猜 patch 版本。

### 2.4 不假设存在“翻译 WebAPI”

当前复盘没有发现一个受支持的 WebAPI action 可以让 Alternative WebUI 请求：

```text
translate(context, source) -> localized string
```

因此不能设计成浏览器运行时逐句调用 WebAPI 获取官方译文。

正确复用点是 qB WebApplication 的 `QBT_TR`/translator 机制；对于要求 Alternative WebUI 自己提供 `.qm` 的 release，需要解决官方 QM provisioning，而不是发明 translation API。

## 3. 第三方 WebUI 的经验怎么用

第三方项目并不只有一种 i18n 方式。

现代 SPA 可以完全自己拥有前端 i18n。例如 `CzBiX/qb-web` 明确包含：

```text
src/locale/en.ts
src/locale/zh-CN.ts
src/locale/zh-TW.ts
src/locale/ru.ts
src/plugins/i18n.ts
```

这证明“第三方自己翻译”是一条可行技术路线，但**不是 WeiG 对 qB-owned 文案的首选路线**。它会重新拥有 qB 已经翻译过的语义，增加措辞漂移和维护成本。

WeiG 应优先复用 qB 官方机制；第三方 SPA 的组件、API、UI 架构可以参考，但不要机械复制它们的 translation ownership。

## 4. Current 0.3.69 的真实状态

当前 `dev` 产品版本为 `0.3.69`。Locale owner cutover 已经完成，但 qB-owned Settings 文案仍处于**过渡 transport**：

```text
candidate upstream source
-> exact Preferences control relation / QBT_TR source/context
-> exact official qB TS translation
-> candidate enriched catalog
-> packaging strips translation bodies from qb-releases.json
-> private/data/qb-settings/<sourceSha>.json
-> W.I18n.qbSetting()
```

浏览器只加载当前 exact release 的一个 shard，不再下载 65 个 release 的全部翻译。

这套实现有两个重要性质：

1. 译文本身仍来自 qB 官方 TS，并非 WeiG 人工翻译；
2. 它仍然是浏览器侧的 duplicate translation projection，因此只是过渡方案，不是长期 owner。

当前 candidate 已证明该过渡方案可以通过完整 65-release source/product audit、Linux/Windows browser、release candidate packaging 和 deployment acceptance。它可以作为回退点，但不应继续扩展成永久 translation catalog。

## 5. 最终目标架构

目标 owner 图：

```text
Persisted locale
    qB preferences.locale

Allowed locale set
    running qB ${LANGUAGE_OPTIONS}
    + source-SHA-bound frozen locale facts for simulator/history

qB-owned wording
    qB official source/context
    -> QBT_TR
    -> qB native translator / official QM

WeiG-only wording
    W.I18n minimal WeiG namespace

Compatibility facts
    qb-releases.json / W.ReleaseProfile
    (NO translation bodies, NO translation ownership)
```

长期硬规则：

> 凡 qB upstream 已拥有的语义，WeiG 不重新拥有其译文；凡 WeiG 自己新增的语义，不能伪装成 qB 官方翻译。

## 6. `qb-releases.json` 的长期职责

`qb-releases.json` 需要继续存在，是因为它承担 admitted stable 的 WebAPI/Preference/field/action/capability compatibility facts。

它**不需要、也不应该为了翻译**携带：

```text
settingsUi translation bodies
all-release translation sets
all-locale translation payload
```

当前 0.3.69 的 `settingsTranslationPath` 是过渡指针。完成原生 QBT_TR/QM cutover 后，应与 `qb-settings/<sourceSha>.json` runtime projection 同批退休。

不要因为翻译架构调整而删除仍被正式 compatibility owners 使用的 release/source facts。

## 7. 下一次产品实现前必须完成的 source audit

不要立即删除 JSON bridge。先完成以下证明：

### 7.1 Translator behavior matrix

对 admitted 4.1.0 -> 5.2.3 的每个 official stable，只提取少量结构事实：

```text
QBT_TR parser exists?
translation call path = qApp translator / dedicated WebUI translator / other?
Alternative WebUI translator resource path?
active-root webui_<locale>.qm required?
missing translation fallback behavior?
which served file types are translateDocument() processed?
```

这比重新读取每个 release × 每个 locale × 全部 TS message 轻得多。

### 7.2 WeiG qB-owned string inventory

扫描正式 `webui/**`，把文字分成：

```text
A. qB-owned: exact upstream source/context 可以证明
B. WeiG-only: upstream 没有该语义
C. uncertain: 暂不能证明 owner
```

A 才迁到 `QBT_TR`；B 留在 `W.I18n`；C fail closed 到当前可信文案，不猜“像 qB 官方”的翻译。

### 7.3 QM provisioning strategy

需要根据 translator matrix 决定，不提前拍脑袋：

- 4.1.0 这类 `qApp->translate()` 路径是否无需额外 Alternative WebUI QM；
- active-root translator release 是否必须在 WeiG root 提供 `translations/webui_<locale>.qm`；
- 是否可安全复用一套 official QM，还是需要按 source/context compatibility 分组；
- 历史 Locale code (`de_DE`, `ja_JP`, `ko_KR`, `zh` 等) 对 QM 文件 identity 的影响；
- Qt `lrelease` 生成方式、构建依赖、包体大小和 10 MiB 单静态文件限制。

任何 `.qm` 都只能来自 qB 官方 translation source 的机械编译/复制，不人工修改 qB-owned 译文。

## 8. 建议的产品 cutover 顺序

完成 audit 后，一次 coherent 产品变更：

```text
1. add/prove native qB translation provisioning
2. migrate proven qB-owned UI strings to QBT_TR(source/context)
3. keep preferences.locale verification semantics unchanged
4. keep W.I18n only for WeiG-owned text + locale presentation helpers
5. remove W.I18n.qbSetting() browser translation database path
6. remove qb-settings/<sourceSha>.json runtime projection
7. remove settingsTranslationPath from runtime release profiles
8. stop packing translation payload into runtime compatibility artifacts
9. retain only source/context validation tooling needed for CI evidence
10. update browser/Pages/real-qB acceptance
```

Owner retirement必须与 caller migration 同批发生，不能新旧两套 qB translation runtime 长期双活。

## 9. Pages / Virtual qB 的特殊问题

GitHub Pages 并不经过真正 qB WebApplication，因此它不会天然执行服务器端 `QBT_TR` replacement。

产品迁到 QBT_TR 后，Virtual qB Pages 仍需要**validation-only translation emulation**，否则页面会直接显示 `QBT_TR(...)` marker。

正确边界：

```text
formal product webui/** contains QBT_TR
real qB performs production translation

Virtual qB/Pages build may preprocess the same formal source
using frozen/source-derived official translation fixtures
ONLY for simulator/browser evidence
```

这种 validation fixture 不能重新进入正式 product runtime，也不能成为第二 translation owner。

Pages 仍禁止在每次部署时 clone/parse 整个 qB upstream history；应复用冻结的 source-derived evidence。

## 10. Candidate 性能复盘

前一轮约 20 分钟的 enrichment 主要来自：

```text
65 releases
× many locales
× historical TS blobs
× repeated git show / partial-clone blob fetch
```

不是 WeiG 主 WebUI 文件本身太大。

原始 enriched runtime catalog 一度达到约 29.6 MB，超过 qB Alternative WebUI 单静态文件 10 MiB 限制；0.3.69 用 per-release shard 解决了当前 candidate packaging 红灯。

但原生 QBT_TR cutover 后，正常 candidate 不应继续为了正式 runtime 生成全历史 translation payload。重型翻译 source scan只应在：

```text
new official stable admission
translator/source parser change
explicit translation evidence refresh
```

等需要时运行。

如果仍需重建历史 evidence，应优先 blob-SHA dedupe / `git cat-file --batch` / frozen artifacts，再考虑有限并发；不要单纯用高并发掩盖重复 I/O。

## 11. 必须避免的坑

1. 不恢复 `weigg-language` 或第二 persisted locale owner。
2. 不在 `languagechange` 里反向再写一次 qB。
3. 不在 verification reread 成功前视觉切语言。
4. 两个 Locale 控件不得维护不同 draft/options/save path。
5. 不把 qB-owned 中文/日文/德文重新手写进 WeiG dictionary。
6. 不假设 WebAPI 有逐句 translation endpoint。
7. 不假设所有 4.1.0+ release 的 Alternative WebUI translator 实现完全相同。
8. 不写 `if (qbVersion === '4.x.y')` 翻译补丁；历史差异应来自 source facts。
9. 不把所有 TS translation bodies重新塞回 `qb-releases.json`。
10. 不因为翻译解耦而删除 compatibility catalog 的 API/Preference/field/action facts。
11. 不让 Pages 的 translation emulation 进入正式产品 runtime。
12. 不为使旧测试变绿而恢复已经证明错误的架构；修 stale contract。
13. 不在 docs-only/tests-only/tools-only 变更中机械 bump 产品 VERSION。
14. 不主动运行 candidate / Real qB Full Frozen Matrix / promotion / main / tag / Release；这些是明确授权边界。
15. 任何 `webui/**` 产品修改都按仓库规则同步 patch VERSION 五处。
