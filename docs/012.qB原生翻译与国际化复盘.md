本文在 2026-09-13 复盘 Locale、qB 官方翻译、Alternative WebUI `QBT_TR`、QM provisioning、qB-owned wording、Virtual qB/Pages 与 Windows Dev installer。`DESIGN.md` 仍是 Current Owner 最终 authority；本文解释“为什么这样做、现在做到哪里、还有什么不能误判成完成”。

## 1. 最终产品原则

### 1.1 Locale 只有一个持久 owner

```text
qB app/preferences.locale
-> W.SettingsState / shared app.preferences
-> QBClient.setPreferences()
-> QBClient.getPreferences() verification reread
-> verified prefs.locale
-> W.I18n.applyLocale()
```

`qBittorrent preferences.locale` 是唯一持久语言真值。WeiG 不保存第二份语言设置，也不会在 qB 回读确认之前先切换视觉语言。

两个 UI 入口可以同时存在：

```text
WeiG WebUI -> Interface -> Language
qB Settings -> Advanced -> Locale
```

但它们编辑同一个 `draft.locale`、同一组选项和同一个保存事务。

### 1.2 qB-owned 与 WeiG-owned 文案必须分开

长期硬规则：

> 凡 qB upstream 已拥有且可以证明 exact source/context 的语义，WeiG 不重新拥有其译文；凡 WeiG 自己新增的语义，不能伪装成 qB 官方翻译。

因此：

```text
qB-owned wording
    qB official source/context
    -> QBT_TR
    -> qB translator
    -> official QM / official TS-derived compatibility transport

WeiG-only wording
    W.I18n minimal WeiG namespace
```

浏览器侧 JSON 不作为 qB-owned 翻译主体。

## 2. qB 官方 WebUI 的真实翻译机制

qB WebApplication 可在发送文本资源时处理：

```text
QBT_TR(Source text)QBT_TR[CONTEXT=SomeContext]
```

服务器端根据当前 Locale 用 Qt translator 替换 marker。对于 dedicated WebUI translator 的版本，Alternative WebUI 所需语言资源位于 active WebUI root：

```text
translations/webui_<locale>.qm
```

因此“qB 有官方译文”与“Alternative WebUI 一定能执行 `QBT_TR`”是两回事：除了 QM 是否存在，还必须证明 `sendFile()` 会让 Alternative WebUI 进入 `translateDocument()`。

当前没有依赖假想的 WebAPI `translate(context, source)`；正式复用点是 qB 自己的 `QBT_TR`/Qt translator。

## 5. Exact translation overlay / LKG / native bundle

`tools/qb-settings-translation-overlay.mjs` 当前同时收集：

```text

Preferences toolbar source

```

并把 qB-owned refs 与 Settings refs 一起送入 official TS extraction。Enriched profile 构建期含：

```text

```

production exact-clone path如果拿到了完整 toolbar/filters source 却解析不到 qB-owned refs，会 fail closed；focused unit fixtures 只给 Preferences source 时仍允许按其测试边界运行。

`tools/qb-settings-translation-lkg.mjs` 会保留 qB-owned UI refs 与 binding count；旧的 Settings-only LKG 对当前 runtime 不再充分，必须通过 source regeneration 更新，不能静默复用。

`tools/qb-settings-native-bundle.mjs` 的 `refsForProfile()` 把：

```text
Settings preference refs
+
qB-owned shared UI refs
```

放入同一 translator-family routing、canonical minimal official QM union 与 registry。

Registry v2：

```text
@@WEIGG_PROFILE <sourceSha> <preference key> ...
@@WEIGG_UI      <sourceSha> <semantic key> <refId>
@@WEIGG_TEXT    <refId> + QBT_TR(source/context)
```

这仍是一套 qB translation pipeline，不是第二翻译系统。

## 6. Preference source parser 修复

qB Settings markup 不只用 `<label for=...>`；某些控件通过 `aria-labelledby` 关联官方 label。

`tools/qb-settings-translation-source.mjs` 当前会：

```text
index label by for
index label by id
scan input/select/textarea aria-labelledby
resolve referenced QBT_TR label
```

这关闭了 file log age/max size 等字段退回 humanized English 的问题。不要重新把 UI control relation 简化回仅 `for=`。

## 7. Native-first runtime 路由

正式优先级：

```text
1. exact profile + locale native-capable
   -> private/data/qb-settings-native.txt
   -> qB server QBT_TR output
   -> official minimal QM when required

2. exact profile + locale explicitly bridge-routed
   -> private/data/qb-settings/<sourceSha>.json
   -> exact official qB TS-derived preferences + ui

3. neither route proven
   -> fail closed / source fallback behavior
```

`qb-settings/<sourceSha>.json` 是 source-proven gap transport，不是主翻译 owner。

Runtime `qb-releases.json` 不携带 all-release translation bodies；build-only qB-owned/Settings translation facts在 packaging 后退出 runtime profile，exact bridge shard只保留 gap 所需数据。

## 14. Promotion/release gate remains separate

当前不能把历史 candidate、当前 Pages 或 installer success 当作 final release permission。真正准备发布时先停止继续开发，冻结新的 final dev exact SHA，再对同一个 SHA 建立：

```text
normal CI PASS
CI candidate PASS
Dev Pages exact-SHA build/deploy/live verify PASS
manual Real qB Current Stable Locale Matrix all-locale PASS
manual Real qB Full Frozen Matrix 65/65 PASS
central tests/release-compat-evidence.mjs PASS
formal promotion PASS
```

普通 push 的 skipped Locale run、旧 SHA aggregate 或 Fast G-FM utility 不能替代。

**本轮用户明确要求继续在 `dev` 开发，暂不晋级 `main`、不 tag、不 Release。**
