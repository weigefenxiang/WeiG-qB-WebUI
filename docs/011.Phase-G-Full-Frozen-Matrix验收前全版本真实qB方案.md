# 011. Phase G Full Frozen Matrix — 验收前全版本真实 qB 方案

Status: **PLANNED / execute only after G1–G3 are stable / before G4 acceptance evidence**

> 本方案不是日常开发矩阵，也不是新的兼容性 owner。它是 Phase G 最终验收前的一次全支持区间真实 qB 运行门禁：把 Frozen LKG 中 qBittorrent 4.1.0 -> 5.2.3 的全部 65 个 stable profile，逐版本映射到真实 qB runtime，并使用同一份正式 `webui/**` 与同一套 capability-driven real-qB harness 取得 exact-SHA evidence。

## 1. Phase G 中的位置

固定执行顺序：

```text
G1 Representative real-qB matrix
-> G2 Real WebAPI semantic flows
-> G3 Deployment / operator hardening
-> G-FM Full Frozen Matrix (this plan)
-> G4 Promotion-time frozen evidence / Phase G acceptance
```

因此：

```text
现在：只保留 4 个代表版本快速迭代
G1-G3 稳定后：实现并运行 G-FM
G-FM 全部完成后：才允许进入 G4 最终验收证据整理
```

G-FM PASS 不自动触发 `dev -> main`、tag、release 或 version bump。

## 2. 目标范围

Authority：

```text
tools/data/qb-stable-lkg.json
-> tests/fixtures/qb-release-catalog.lkg.json
-> 65 exact stable profiles
-> support floor qB 4.1.0
-> latest admitted stable qB 5.2.3
```

执行时必须从 Frozen LKG / Frozen catalog 动态生成版本列表，禁止在 workflow 里长期维护第二份手写 65-version table。

若 Phase G 收尾前已有新的 official stable 被 Phase D 正式 admission 到新的 Frozen LKG，则 G-FM 使用届时 fresh-verified Frozen LKG；不得偷偷修改历史 Frozen evidence。

## 3. GitHub Actions 调度模型

目标模型：

```text
1 workflow run
65 independent matrix jobs
1 qB stable version per job
max-parallel: 16
fail-fast: false
```

语义：

```text
最多 16 个版本同时运行
-> 任意 job 先结束
-> GitHub 从剩余队列动态补下一个版本
-> 不固定把版本平均绑定到 16 个 shard
-> 不限制某个“并发槽位”最终累计承接多少版本
-> 直到全部 65 个独立 jobs 结束
```

禁止改成固定 `16 shards x 4~5 versions` 作为默认方案，因为固定 shard 会产生慢 shard 尾部拖延，并降低单版本失败隔离与 evidence 可读性。

## 4. Workflow 触发策略

G-FM 不是每次 push 的高成本 gate。

计划触发：

```text
workflow_dispatch                     required
Phase G final candidate / pre-acceptance checkpoint
optional exact-SHA reusable_call      only if later needed
```

日常仍使用 Representative Matrix：

```text
qB 4.1.0
qB 4.6.7
qB 5.0.0
qB 5.2.3
```

G-FM workflow / scripts / evidence modules 自身发生变化时，必须重新跑 G-FM 或在 G4 前对最终 exact SHA 完整重跑；不能用旧 SHA 的 65/65 结果替代新 candidate。

## 5. Runtime identity resolver

65 个 profile 都必须映射到可审计的真实 qB runtime。不能因为某个历史 Docker tag 不存在就跳过该 stable。

Resolver 优先级：

```text
1. official qBittorrent historical container/image with immutable digest
2. verified historical runtime wrapper + qB self-reported version + immutable digest
3. deterministic source build from exact official qB tag/commit
4. unresolved runtime => BLOCKED/FAIL, not compatibility PASS
```

每个版本至少记录：

```text
qB version
WebAPI version
official tag / source commit identity
runtime image identity + digest, or source-build identity
platform / architecture
WeiG exact SHA
```

第三方 historical wrapper 只能作为 runtime packaging evidence，不得冒充 qB official image。

## 6. 每版本测试模型

每个 matrix job 运行同一套 capability-driven harness，不建立 patch-version compatibility table。

基础真实语义：

```text
auth/session/login/logout
app version / WebAPI identity
transfer / torrent list
Settings read + approved no-op write + reread
Logs
RSS lifecycle
Categories lifecycle
Tags lifecycle where source-supported
isolated test torrent add / state transition / details / cleanup
Search lifecycle where source-supported and runtime prerequisite exists
other G2 scenarios already certified for final harness
```

所有 endpoint / action / parameter expectation 来自 exact Frozen release profile/source provenance。

禁止：

```text
if qB major == 4 / 5 then guess API
manual compatibility mode
404 probing as capability owner
fake empty result
silently weakening assertions for one historical version
```

## 7. Safe-write 与隔离

全部真实 qB job 必须在隔离环境运行：

```text
no user production qB
no user torrents
no public inbound service
no credential reuse
unique temporary torrent/category/tag/RSS/search objects
approved safe Settings no-op keys only
finally cleanup required
```

历史 qB runtime 默认不得暴露公网；优先 internal/isolated Docker network + runner-only access。

Cleanup 失败必须进入 evidence，不能因为主语义 PASS 而忽略。

## 8. PASS / FAIL / SKIP / BLOCKED

版本级最终状态只允许：

```text
PASS
FAIL
BLOCKED
```

Scenario 级允许 `SKIP`，但必须有明确原因：

```text
source profile 证明该版本不具备该 capability
or
明确的可选 runtime prerequisite 不存在，并被 evidence 标记
```

以下不能记为 SKIP：

```text
找不到该 qB 版本 runtime
容器启动失败
版本/WebAPI identity 不匹配且无法解释
harness crash
cleanup 未执行
network/runtime infrastructure failure after retry policy exhausted
```

这些必须使版本 job 为 `FAIL` 或 `BLOCKED`，防止 65/65 被“跳过”伪造成 PASS。

## 9. Evidence contract

每一个 stable version 独立产生 evidence artifact；即使 65 jobs 属于同一个 workflow run，也不得只保存一个总日志。

至少记录：

```text
phase = G-FM
weig_sha
webui_version
test_time
qB_version
WebAPI_version
qB_binary_or_source_identity
runtime_image_digest
platform / architecture / deployment_mode
scenario
capability_expected
source_provenance
HTTP semantic result (redacted)
cleanup_result
PASS / FAIL / SKIP
known_issue
```

禁止记录：

```text
password
session cookie/token
API credential
private torrent content
sensitive public address
```

Artifact naming 必须能直接从 `WeiG SHA + qB version` 定位。

## 10. Aggregate gate

65 个 jobs 必须 `fail-fast: false`，即使前面已有失败，也继续得到完整支持区间地图。

最终 aggregator 必须输出：

```text
expected stable count
executed stable count
PASS count
FAIL count
BLOCKED count
per-version result
per-version evidence artifact identity/digest
missing versions
unexpected duplicate versions
Frozen LKG/catalog identity
WeiG exact SHA
```

G-FM 通过条件：

```text
executed == expected Frozen profile count
missing == 0
duplicate == 0
FAIL == 0
BLOCKED == 0
all version identities match expected exact profiles
all required cleanup PASS
all evidence artifacts present
```

任何一个版本未实际执行，都不能写 `65/65 real-qB PASS`。

## 11. Failure handling

单版本出现失败：

```text
capture exact evidence
-> classify runtime packaging / harness contract / source misunderstanding / product bug
-> do not weaken Frozen/source gate
-> if harness/runtime issue: fix test infrastructure only
-> if real product bug: fix canonical `webui/**` owner
-> rerun affected direct/representative gates
-> rerun final G-FM on the new exact SHA
```

最终 G4 只接受最后 exact SHA 的完整 G-FM evidence。

## 12. DoD

G-FM 完成定义：

```text
Frozen LKG dynamically enumerated
all admitted stable versions have auditable real runtime identity
one independent matrix job per stable version
max-parallel = 16
fail-fast = false
dynamic queue refill, no fixed shard ownership
all required real-qB semantics executed
safe writes isolated and cleaned
per-version evidence complete
aggregate evidence complete
0 missing / 0 duplicate / 0 FAIL / 0 BLOCKED
final exact SHA 65/65 PASS
```

只有满足以上条件，Phase G 才进入 `G4 — Promotion-time frozen evidence` 与最终验收整理。
